# テストケース: 構造体テンプレート

この文書は、機能仕様書 [07-templates.md](../../spec/07-templates.md) の受け入れ基準 (159 項目) を確認するテストケースを定める。書式と種別の決め方は [00-test-strategy.md](../00-test-strategy.md) に従う。

- テストケースの数: 136 件 (自動: 単体 43、自動: 結合 25、自動: UI 47、自動: 性能 10、自動: 国際化 1、自動: アクセシビリティ 2、自動: ファジング 3、半自動 2、手動 3)
- 手動・半自動のテストケースの所要時間の合計: 約 17 分 (うちスモーク (優先度「高」) は 3 分)
- テンプレート言語のテストは、主にゴールデンファイルのテストで行う。テストケースごとにフィクスチャのフォルダ `tests/fixtures/templates/<テストケース ID>/` を作り、テンプレート (`template.hxt` または `.ksy`)、データ (`data.bin`。テストデータ ID を使う場合は省く)、期待する結果ツリー (`expected.json`。TPL-25 の JSON 形式) を置く。テストコードは、テンプレートをデータに適用し、結果ツリーを JSON でエクスポートして `expected.json` と比べる (`display` の地域設定に依存する値は en-US で比べる)。手順に書いたテンプレートとデータは、そのフィクスチャの内容である。
- エラーのテストは、エラーのコード・行・列・データの位置と、部分結果の JSON を照合する。
- サンドボックスのテストは、検索パスの外のファイル・ネットワーク・プロセスなどへの到達を試みるテンプレートを実行し、拒否されることと、実際にアクセスが起きないこと (ファイル・ネットワークの監視) を確認する。
- テンプレートのパーサと評価器、`.ksy` の読み込みは、SharpFuzz でファジングする (自動: ファジング)。
- 小さなデータは、テストデータ ID を付けずに手順の中に Hex で書く。

### TC-TPL-02-01 数値リテラルと演算子の優先順位

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | TPL-02 の受け入れ基準 1、2 |

| 環境 | 標準 (Hex ビューの基数の設定を 16 進にした状態と 10 進にした状態の両方で行う) |

**前提**: アプリの設定「接頭辞のない数値の解釈」を 16 進にしてある (手順の後半で 10 進に変える)。

**手順**:

1. `local auto v1 = 0x10 + 1Fh + 0b1 [[show]];`、`local auto v2 = 10 [[show]];`、`local auto v3 = 0o17 + 1_000 [[show]];`、`local auto v4 = 2 + 3 * 4 << 1 [[show]];`、`local auto v5 = 1 | 2 ^ 3 & 4 [[show]];`、`local auto v6 = !0 && 0 || 1 ? 7 : 8 [[show]];` を含むテンプレートを、空のデータに適用する。

3. 仕様 7 の表の優先順位のすべての隣り合う組 (13 組) について、`a 演算子1 b 演算子2 c` の値を、括弧を付けた期待値と比べる式を FsCheck で無作為な a・b・c (0〜1,000) で 500 回評価する。

**期待結果**:

- 手順 1 と手順 2 のどちらでも、v1 = 48、v2 = 10、v3 = 1,015、v4 = 28、v5 = 3、v6 = 7 になる。
- 手順 3 のすべての式が、仕様 7 の優先順位で括弧を付けた値と一致する。

# テストケース: UI と設定

機能仕様書 [09-ui-and-settings.md](../../spec/09-ui-and-settings.md) (UI-01〜UI-58、受け入れ基準 216 項目) のテストケース。書式と種別の決め方は [00-test-strategy.md](../00-test-strategy.md) に従う。

| 種別 | 件数 |
| --- | --- |
| 自動: 単体 | 10 |
| 自動: 結合 | 12 |
| 自動: UI | 126 |
| 自動: 性能 | 5 |
| 自動: 国際化 | 20 |
| 自動: アクセシビリティ | 4 |
| 自動: 配布 | 17 |
| 半自動 | 5 |
| 手動 | 8 |
| 合計 | 207 |

- 手動・半自動の 13 件の所要時間の目安の合計は 48 分。うち優先度「高」(スモークテスト) のものはない。
- 自動テストは、前提に特に書かない限り、新しいテスト用の設定フォルダ (`--test-profile`) で起動する (00-test-strategy.md 6.5)。「同じ設定フォルダで起動する」と書いた場合は、直前の手順と同じフォルダを指定する。
- 表示言語の指定は `--ui-lang <言語タグ>` (08 の AUTO-37) で行う。設定 `ui.language` は変えない。
- 「テスト用のビルド」は、異常を再現する仕組み (`--test-hooks`、00-test-strategy.md 7.2) とテスト用のメニュー (8.4) を含むビルドを指す。
- 入力の配列 (ドイツ語、フランス語 AZERTY)、Windows のアプリモード・コントラストテーマ・文字の大きさ・地域設定・言語の優先順位は、自動テストの中で切り替え、テストの後に元に戻す。
- 手動・半自動のテストケースの前提は、手動テスト支援ツールの「準備」(00-test-strategy.md 8.2) で作る。

## UI-01 メインウィンドウの構成

### TC-UI-01-01 初回起動時に表示される領域

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | UI-01 の受け入れ基準 1 |
| 種別 | 自動: UI |
| 優先度 | 高 |
| フェーズ | 0 |
| テストデータ | なし |
| 環境 | 標準 |

**前提**: 新しいテスト用の設定フォルダで、ファイルを指定せずに起動する。

**手順**:

1. メインウィンドウの UI オートメーションの要素を `AutomationId` で取得する。
2. タイトルバー、タブ列、エディタ領域、ステータスバー、ツールバー、左パネル、右パネル、下パネルの各要素の表示状態と位置を記録する。

**期待結果**:

- タイトルバー、タブ列、エディタ領域、ステータスバーが表示され、上から順に並んでいる。
- エディタ領域にスタートページが表示されている。
- ツールバー、左パネル、右パネル、下パネルは表示されていない。

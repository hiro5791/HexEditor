# テストケース: 編集、選択、クリップボード、Undo、データ演算、パッチ

この文書は、機能仕様書 [03-editing.md](../../spec/03-editing.md) の受け入れ基準を確認するテストケースを定める。書式と種別の決め方は [00-test-strategy.md](../00-test-strategy.md)、共通のテストデータは [test-data.md](../test-data.md) に従う。

テストケースは 163 件 (自動: 単体 28 件、自動: 結合 12 件、自動: UI 96 件、自動: 性能 16 件、半自動 1 件、手動 10 件)。手動・半自動のテストケースの所要時間の目安は合計 40 分 (うち優先度「高」のスモークテストは 3 分)。

## このファイルの共通事項

- 「TD-xxx を開いた状態」は、テスト用の設定フォルダ (`--test-profile`) を新しく作り、そのファイルを起動引数で開いた状態を指す。手動・半自動のテストでは、手動テスト支援ツールの「準備」(00-test-strategy.md 8.2) で作る。
- 自動: UI のテストは、操作する要素を `AutomationId` で探す。「オフセット 0x10 のバイトをクリックする」は、Hex ビューが UI オートメーションに公開するバイトの要素 (UI-50) を探してクリックすることを指す。ドキュメントの内容は、バイトの要素の値を読んで確認する。大きな範囲は「名前を付けて保存」で一時フォルダに書き出したファイルを読んで確認する。
- 自動: 単体 のテストは、`HexEditor.Core` のデータエンジンをメモリ上のデータソースで作り、UI を使わずにコマンドを実行する。
- 「基準モデル」は、同じ操作をバイト配列 (`List<byte>`) に適用する単純な実装を指す (00-test-strategy.md 6.3)。
- 時間は、コマンドを実行してから完了の通知 (テスト用の完了イベント、またはステータスバーの値の変化) までを測る。性能のテストは 11 回測り、1 回目をウォームアップとして除いた 10 回の最大値を目標と比べる。
- メモリ使用量はプロセスのプライベートバイトで測る。「メモリ使用量がほぼ増えない」「増えない」は、操作の前後の差が 50 MB 以下であることとする。
- 「60 fps を保つ」の判定は [テスト方針](../00-test-strategy.md) の 7.2 に従う (フレームの間隔の 99 パーセンタイルが 16.7 ms 以下、かつ最大が 50 ms 以下)。
- 「遅いデータソース」などの異常を再現する仕組み (00-test-strategy.md 7.2) は、`--test-hooks` の設定ファイルで有効にする。
- 物理ディスクのテストは、CI で TD-VHDX-MBR を接続し、その物理ディスクを開いて行う (00-test-strategy.md 6.4)。編集はドキュメント上だけで行い、ディスクには書き込まない。
- キー入力は、特に書かない限り `SendInput` で仮想キーを送る。IME を通さない Unicode 文字の入力は `KEYEVENTF_UNICODE` で送る。
- 環境の「日本語 IME」「中国語 (ピンイン) IME」などは、CI ランナーにその言語の入力方式 (Windows 標準の Microsoft IME など) を追加し、テストの開始時にその入力方式に切り替えた状態を指す。

### TC-EDIT-01-01 Shift+クリックでアンカーが変わらない

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | EDIT-01 の受け入れ基準 2 |
| 種別 | 自動: UI |
| 優先度 | 高 |
| フェーズ | 0 |
| テストデータ | TD-SEQ-1M |
| 環境 | 標準 |

**前提**: TD-SEQ-1M を開いた状態。1 行 16 バイトの表示。

**手順**:

1. Hex 列のオフセット 0x10 のバイトをクリックする。
2. Shift を押しながら、オフセット 0x30 のバイトをクリックする。
3. ステータスバーの選択範囲の表示を読む。
4. Shift を押しながら、オフセット 0x20 のバイトをクリックする。
5. ステータスバーの選択範囲の表示を読む。
6. Shift を押しながら、オフセット 0x08 のバイトをクリックする。
7. ステータスバーの選択範囲の表示を読む。

**期待結果**:

- 手順 3: 開始 0x10、終了 (このバイトを含む) 0x30、長さ 0x21。
- 手順 5: 開始 0x10、終了 0x20、長さ 0x11 (アンカーが 0x10 のまま)。
- 手順 7: 開始 0x08、終了 0x10、長さ 0x9 (アンカーより前を Shift+クリックしても、アンカー 0x10 を含む範囲になる)。

### TC-EDIT-01-05 100 GB のファイルでドラッグして自動スクロールする

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | EDIT-01 の受け入れ基準 1 |
| 種別 | 自動: 性能 |
| 優先度 | 中 |
| フェーズ | 1 |
| テストデータ | TD-SPARSE-100G |
| 環境 | 標準 |

**前提**: TD-SPARSE-100G を開いた状態。1 行のバイト数を 4,096 (指定) にしてある (自動スクロールの最大速度 1 秒あたり 1,000,000 行で、約 30 秒で末尾に届くようにするため)。ETW でフレームの記録を始めている。

**手順**:

1. Hex 列のオフセット 0 のバイトでマウスのボタンを押す。
2. ボタンを押したまま、ポインタを Hex ビューの表示領域の下端から 300 px 下へ動かし、そのまま保つ。
3. ステータスバーの選択範囲の長さを 1 秒ごとに読み、長さが 100 GiB − 1 GiB 以上になるまで待つ (上限 10 分)。
4. ボタンを離す。
5. フレームの記録を止めて、フレームの表示間隔を集計する。

**期待結果**:

- 手順 3 の間、選択範囲の長さが増え続け、10 分以内に 100 GiB − 1 GiB 以上になる。
- 手順 4 の後、選択範囲の開始は 0 で、終了はポインタの下のバイトになっている。
- 手順 2〜4 の間、60 fps を保つ (このファイルの共通事項の判定方法)。

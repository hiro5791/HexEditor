# テストケース: データエンジン、データソース、開く・保存

この文書は、機能仕様書 [01-engine-and-sources.md](../../spec/01-engine-and-sources.md) (ENG) の受け入れ基準を確認するテストケースを定める。書式と用語は [00-test-strategy.md](../00-test-strategy.md) に従う。

- テストケースの数: 合計 164 件 (自動: 単体 12、自動: 結合 67、自動: UI 58、自動: 性能 19、自動: 国際化 1、自動: 配布 4、手動 3)
- 手動・半自動の所要時間の合計 (目安): 12 分
- 共通のテストデータは [test-data.md](../test-data.md)、このファイルで新しく定義したテストデータは末尾の「このファイルで使うテストデータ」を参照する。

このファイルの「環境」欄では、標準環境 (00-test-strategy の 5.1) のほかに次の書き方を使う。

| 書き方 | 意味 |
| --- | --- |
| 管理者 (CI) | CI のランナーの管理者権限のまま、アプリを管理者として実行する |
| 一般ユーザー (CI) | CI のランナー上で、昇格していないトークン (制限付きトークン) でアプリを起動する。ランナーの UAC は「確認なしで昇格する」設定にしておき、補助プロセス (ENG-28) の起動は確認なしで通る |

## ENG-01 データソースの抽象化 (IByteSource)

### TC-ENG-01-01 能力のフラグによる編集・保存の無効化

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | ENG-01 の受け入れ基準 1 |
| 種別 | 自動: 単体 |
| 優先度 | 高 |
| フェーズ | 0 |
| テストデータ | なし |
| 環境 | 標準 |

**前提**: 能力のフラグを任意に指定できるテスト用のデータソース (長さ 4,096 バイト、内容は TD-BYTES-256 の 16 回繰り返し) を用意する。

**手順**:

1. `CanResize` = 偽、`CanWrite` = 真のデータソースでドキュメントを作り、挿入・削除・切り取り・挿入貼り付けのコマンドの実行可否を問い合わせる。
2. 同じドキュメントにオフセット 0x10 への 1 バイトの挿入を API で直接要求する。
3. `CanResize` = 真、`CanWrite` = 偽のデータソースでドキュメントを作り、オフセット 0 の 1 バイトを上書きしてから、保存コマンドの実行可否を問い合わせる。
4. `CanResize` = 真、`CanWrite` = 真のデータソースで、手順 1 と 3 の問い合わせを行う。

**期待結果**:

- 手順 1 で、挿入・削除・切り取り・挿入貼り付けがすべて実行不可になる。
- 手順 2 の要求が拒否され、ドキュメントの長さが 4,096 のまま変わらない。
- 手順 3 で、保存が実行不可になる。
- 手順 4 で、挿入・削除・保存がすべて実行可能になる。

### TC-ENG-01-02 一部が読めないデータソースの読み込み結果

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | ENG-01 の受け入れ基準 2 |
| 種別 | 自動: 単体 |
| 優先度 | 中 |
| フェーズ | 0 |
| テストデータ | TD-SEQ-1M |
| 環境 | 標準 |

**前提**: TD-SEQ-1M を元データとし、範囲 [0x1000, 0x2000) を I/O エラー、範囲 [0x3000, 0x3200) を「アクセス不可」として返すテスト用のデータソースを用意する。

**手順**:

1. 位置 0x0、長さ 0x4000 の読み込みを 1 回要求する。
2. 位置 0x1800、長さ 0x100 (全体が読めない範囲) の読み込みを要求する。
3. 位置 0xFFF00、長さ 0x200 (末尾を 0x100 バイト越える) の読み込みを要求する。

**期待結果**:

- 手順 1 で例外が発生せず、[0x0, 0x1000)・[0x2000, 0x3000)・[0x3200, 0x4000) のバイトが TD-SEQ-1M と一致し、読めなかった範囲として [0x1000, 0x2000) (理由: I/O エラー) と [0x3000, 0x3200) (理由: アクセス不可) の 2 つが返る。
- 手順 2 で例外が発生せず、読めたバイトが 0 個、読めなかった範囲が [0x1800, 0x1900) の 1 つになる。
- 手順 3 で [0xFFF00, 0x100000) の 0x100 バイトだけが返り、末尾を越えた部分はバイトとしても読めない範囲としても返らない。

## ENG-02 ピースツリー

### TC-ENG-02-01 100 GB のファイルへの 1 バイト挿入の時間

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | ENG-02 の受け入れ基準 1 |
| 種別 | 自動: 性能 |
| 優先度 | 中 |
| フェーズ | 0 |
| テストデータ | TD-SPARSE-100G |
| 環境 | 標準 |

**前提**: TD-SPARSE-100G を開き、事前に固定の種で無作為な位置へ 10,000 回の 1 バイト上書きを行ってピースを増やしておく。

**手順**:

1. オフセット 0 に 1 バイト `AA` を挿入する時間を計る。
2. オフセット 2^31 − 1、2^32、50 GiB (中央) にそれぞれ 1 バイト挿入する時間を計る。
3. 末尾 (長さと同じオフセット) に 1 バイト挿入する時間を計る。
4. 各挿入の後に、挿入位置の前後 16 バイトを読む。

**期待結果**:

- 各挿入が 100 ms 以内に終わる (20 回の計測の最大値で判定する)。
- 手順 4 で、挿入したバイトが `AA` で、その後ろが挿入前の内容 (目印) を 1 バイトずらしたものになっている。

### TC-ENG-02-02 10 GB の範囲の削除と複製の時間

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | ENG-02 の受け入れ基準 2 |
| 種別 | 自動: 性能 |
| 優先度 | 中 |
| フェーズ | 0 |
| テストデータ | TD-SPARSE-100G |
| 環境 | 標準 |

**前提**: TD-SPARSE-100G を開く。

**手順**:

1. 範囲 [10 GiB, 20 GiB) を削除する時間を計る。
2. 操作前の状態に戻し、範囲 [2^32 − 1 GiB, 2^32 + 9 GiB) (10 GiB) を、データをコピーしない範囲の複製としてオフセット 60 GiB に挿入する時間を計る。
3. 手順 1 の後、オフセット 10 GiB の 16 バイトを読む。

**期待結果**:

- 手順 3 の内容が、元のオフセット 20 GiB の目印と一致する。
- 手順 4 の内容が、元のオフセット 2^32 の目印 (`@0000000100000000`) と一致する。
- 長さが手順 1 の後は 90 GiB、手順 2 の後は 110 GiB になる。

### TC-ENG-02-03 無作為な操作列と単純な配列の比較

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | ENG-02 の受け入れ基準 3 |
| 種別 | 自動: 単体 |
| 優先度 | 高 |
| フェーズ | 0 |
| テストデータ | TD-SEQ-1M、TD-EMPTY |
| 環境 | 標準 |

**前提**: FsCheck で、挿入 (1〜4,096 バイト)・削除・上書き・範囲の複製・塗りつぶしの操作列を作る生成器を用意する。位置は 0、末尾、末尾 − 1、ピースの境界の前後を高い確率で選ぶ。

**手順**:

1. TD-SEQ-1M を元データとし、合計 100 万回の操作 (1 回の操作列あたり 1,000 回 × 1,000 列) をピースツリーとバイト配列の基準モデルの両方に適用する。

**期待結果**:

- すべての操作列で、ピースツリーの内容と長さが基準モデルと一致する。
- 変更された範囲の列挙が、基準モデルで元データと違う位置 (またはずれた位置) をすべて含む。

## ENG-03 生成ピース (塗りつぶし・乱数)

### TC-ENG-03-01 1 TB の範囲の塗りつぶし

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | ENG-03 の受け入れ基準 1 |
| 種別 | 自動: 性能 |
| 優先度 | 中 |
| フェーズ | 0 |
| テストデータ | TD-SPARSE-2T |
| 環境 | 標準 |

**前提**: TD-SPARSE-2T を開き、エンジンのメモリ使用量を記録する。

**手順**:

1. 範囲 [0, 1 TiB) をパターン `DE AD BE EF` で塗りつぶす時間を計る。
2. 塗りつぶしの後のエンジンのメモリ使用量を記録する。
3. オフセット 0、2^31 − 2、2^32 + 1、2^40 − 8 の各位置から 8 バイトを読む (いずれも塗りつぶしの範囲内)。
4. オフセット 2^40 (塗りつぶしの直後) から 17 バイトを読む。

**期待結果**:

- 塗りつぶしが 100 ms 以内に終わる。
- メモリ使用量の増加が 1 MiB 以下。
- 手順 3 の内容が、各位置の位相に応じたパターン (例: オフセット 2^31 − 2 は `BE EF DE AD BE EF DE AD`) になる。
- 手順 4 の内容が、塗りつぶし前のオフセット 2^40 の目印と一致する。

### TC-ENG-03-02 塗りつぶしの途中への挿入でパターンが崩れない

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | ENG-03 の受け入れ基準 2 |
| 種別 | 自動: 単体 |
| 優先度 | 中 |
| フェーズ | 0 |
| テストデータ | TD-ZERO-1M |
| 環境 | 標準 |

**前提**: TD-ZERO-1M を開き、範囲 [0x100, 0x10100) をパターン `01 02 03` (3 バイト) で塗りつぶす。

**手順**:

1. オフセット 0x1001 (パターンの位相 2 の位置) に 1 バイト `FF` を挿入する。
2. 範囲 [0xFF0, 0x1010) を読む。
3. 範囲 [0x100, 0x10101) の全体を読み、`FF` を取り除いた列を作る。
4. パターンの長さ 1 と 4,096 で同じ検査を行う。

**期待結果**:

- 手順 2 で、0x1000 の前後のパターンが位相を保って並び、0x1001 に `FF` がある。
- 手順 3 の列が、`01 02 03` を 0x10000 バイト分くり返した列と一致する。
- 手順 4 でも同じ結果になる。パターンの長さ 0 と 4,097 での塗りつぶしは拒否される。

## ENG-04 追加バッファと一時ファイルへの退避

### TC-ENG-04-01 2 GiB の貼り付けでメモリの上限を超えない

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | ENG-04 の受け入れ基準 1、2 |
| 種別 | 自動: 結合 |
| 優先度 | 中 |
| フェーズ | 0 |
| テストデータ | TD-SEQ-1M |
| 環境 | 標準 |

**前提**: 既定の設定 (エンジンのメモリ上限 1 GiB、追加データをメモリに置く上限 256 MiB) で TD-SEQ-1M を開く。貼り付け元として、固定の種の乱数で 2 GiB のデータを作り、SHA-256 を記録する。

**手順**:

**期待結果**:

- 手順 2 の最大値が 1 GiB を超えない。設定フォルダの `recovery/<ドキュメント ID>/add.bin` が作られている。
- 手順 3 の値が、貼り付け元の SHA-256 と一致する。
- 手順 4 の検索結果が 0x80000 + 2 GiB − 16 の 1 件。
- 手順 5 の SHA-256 が一致する。

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | ENG-30 の受け入れ基準 1 |
| 種別 | 自動: 結合 |
| 優先度 | 中 |
| フェーズ | 2 |
| テストデータ | TD-VHDX-MBR |
| 環境 | 管理者 (CI)、仮想ディスク |

**前提**: TD-VHDX-MBR を接続し、NTFS のボリュームにドライブ文字を割り当てる (開いているファイルはない)。アプリで物理ディスクを開き、読み取り専用を解除する。補助プロセスまたは同じプロセスのデバイス制御の呼び出しを記録する。

**手順**:

1. ボリュームの範囲内で、ファイルシステムが使っていない位置 (パーティションの開始 + 32 MiB) の 512 バイトを `C3` で上書きする。
2. Ctrl+S を押す。
3. 確認ダイアログの本文とボタン、既定のボタンを取得し、「ディスクに書き込む」を押す。
4. 保存の完了後、テストコードが物理ディスクの同じ位置を直接読む。
5. デバイス制御の呼び出しの記録を取得する。

**期待結果**:

- 手順 3 の本文に、ディスクの番号・モデル名・サイズ、書き込む量 (1 か所、512 バイト)、影響するボリューム (ドライブ文字) とロックすること、データが壊れる可能性と元に戻せない場合がある警告が含まれる。ボタンが「ディスクに書き込む」「キャンセル」で、既定が「キャンセル」。
- 手順 4 の内容が `C3` × 512。
- 手順 5 の順序が `FSCTL_LOCK_VOLUME` → 書き込み → `Flush` → ロックの解除。

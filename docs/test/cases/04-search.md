# テストケース: 検索・置換

この文書は、機能仕様書 [04-search.md](../../spec/04-search.md) の受け入れ基準を確認するテストケースを定める。書式と種別の決め方は [00-test-strategy.md](../00-test-strategy.md)、共通のテストデータは [test-data.md](../test-data.md) に従う。

テストケースは 108 件 (自動: 単体 25 件、自動: 結合 11 件、自動: UI 60 件、自動: 性能 10 件、手動 2 件)。手動・半自動のテストケースの所要時間の目安は合計 6 分。優先度「高」の手動・半自動のテストケースはない (検索のスモークテストはすべて自動)。

## このファイルの共通事項

- 「TD-xxx を開いた状態」は、テスト用の設定フォルダ (`--test-profile`) を新しく作り、そのファイルを起動引数で開いた状態を指す。手動テストでは、手動テスト支援ツールの「準備」(00-test-strategy.md 8.2) で作る。
- 自動: UI のテストは、操作する要素を `AutomationId` で探す。検索バーの検索欄・種類・オプション、結果一覧の行、処理センターの項目もすべて `AutomationId` で探す。選択範囲・カーソル位置はステータスバーの表示と、Hex ビューが UI オートメーションに公開する値 (UI-50) で読む。
- 自動: 単体 のテストは、`HexEditor.Core` の検索エンジンを、メモリ上のデータソースから作ったデータエンジンのスナップショットに対して実行する。「一致の一覧」は、すべて検索と同じ処理で得た (開始オフセット, 長さ) の列を指す。
- 「基準の実装」は、データ全体を 1 つのバイト配列に読み、先頭から 1 バイトずつ照合する単純な検索を指す。
- 「読み込みを数えるデータソース」は、読み込みの呼び出しごとにオフセットと長さを記録するテスト用のデータソースを指す。読み込みのバイト数はその合計とする。
- 時間は、検索を始めてから完了の通知 (テスト用の完了イベント、または検索バー・結果一覧の表示の変化) までを測る。性能のテストは 3 回測り、最も遅い値を目標と比べる。
- 「データが OS のキャッシュにない状態」は、計測の前にテスト用のファイルを `FILE_FLAG_NO_BUFFERING` で開き直し、システムのファイルキャッシュを空にする (`SetSystemFileCacheSize` によるキャッシュの破棄。管理者権限で行う) ことで作る。
- メモリ使用量はプロセスのプライベートバイトで測る。
- 「60 fps を保つ」の判定は [テスト方針](../00-test-strategy.md) の 7.2 に従う (フレームの間隔の 99 パーセンタイルが 16.7 ms 以下、かつ最大が 50 ms 以下)。
- 「遅いデータソース」などの異常を再現する仕組み (00-test-strategy.md 7.2) は、`--test-hooks` の設定ファイルで有効にする。「遅延 2 ms/MiB」は、1 MiB 読むごとに 2 ms の遅延を入れる設定を指す。
- 物理ディスクのテストは、CI で TD-VHDX-MBR を接続し、その物理ディスクを開いて行う (00-test-strategy.md 6.4)。
- 仕様書の「4 MB」「1 MB」「1 GB」などの大きさは、このファイルでは 2 の累乗 (MiB・GiB) として扱う。

## FIND-01 チャンク単位の検索と境界の重なり

### TC-FIND-01-01 チャンクの境界をまたぐ一致を 1 回だけ報告する

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | FIND-01 の受け入れ基準 1、2 |
| 種別 | 自動: 単体 |
| 優先度 | 高 |
| フェーズ | 0 |
| テストデータ | TD-FIND-CHUNK-16M |
| 環境 | 標準 |

**前提**: TD-FIND-CHUNK-16M をデータソースにしたスナップショット。チャンクサイズは既定 (4 MiB)。

**手順**:

1. 16 バイトのパターン P (`5A A5 01 23 45 67 89 AB CD EF FE DC BA 98 76 54`) をすべて検索し、一致の一覧を得る。
2. 先頭から次を検索を繰り返し、移動した位置を順に記録する。
3. 末尾から前を検索を繰り返し、移動した位置を順に記録する。
4. 並列数を 1、2、8 にして、手順 1 を繰り返す。

**期待結果**:

- 手順 1: 一致は 0x3FFFF8、0x7FFFF0、0x800000、0xBFFFFF、0xFFFFF0 の 5 件で、同じ開始位置の重複はない。
- 手順 2: 上の 5 か所に順に移動し、その後は一致がない (折り返しなしの場合)。
- 手順 3: 上の 5 か所を逆順にたどる。
- 手順 4: どの並列数でも手順 1 と同じ 5 件。

### TC-FIND-01-02 チャンクサイズを変えても結果が同じ

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | FIND-01 の受け入れ基準 5 |
| 種別 | 自動: 単体 |
| 優先度 | 中 |
| フェーズ | 0 |
| テストデータ | TD-FIND-CHUNK-16M、TD-RANDOM-16M |
| 環境 | 標準 |

**前提**: チャンクサイズを 256 KiB、4 MiB、64 MiB に設定した 3 つの検索エンジンを用意する。

**手順**:

1. TD-FIND-CHUNK-16M で P をすべて検索し、3 つの設定の結果を比べる。
2. TD-RANDOM-16M で、Hex `00 00`、ワイルドカード `?F ?? 0?`、テキスト (大文字・小文字を区別しない、ASCII) `ab`、正規表現 (バイト列) `\x00[\x80-\xFF]{2}` をすべて検索し、3 つの設定の結果を比べる。正規表現 (バイト列) は FIND-19 (フェーズ 1) で実装するため、フェーズ 0 では正規表現を除く 3 つで比べ、FIND-19 の実装時に正規表現を加える。
3. FsCheck で、長さ 0〜2 MiB の無作為なデータ、長さ 1〜64 のリテラルのパターン (データの一部を切り出したものを半分以上含める)、チャンクサイズ 256 KiB〜2 MiB の無作為な値を 500 通り作り、すべて検索の結果を基準の実装と比べる。

**期待結果**:

- 手順 1・2: 3 つの設定の結果 (開始位置と長さの列) がそれぞれ一致する。
- 手順 3: すべての場合で基準の実装と一致する。

### TC-FIND-01-04 10 GiB のファイルの末尾にあるリテラルの検索速度

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | FIND-01 の受け入れ基準 4 |
| 種別 | 自動: 性能 |
| 優先度 | 中 |
| フェーズ | 0 |
| テストデータ | TD-FIND-RANDOM-10G |
| 環境 | 性能テスト用の固定の計測機 (NVMe SSD、読み込み 2 GiB/s 以上)。管理者として実行 |

**前提**: TD-FIND-RANDOM-10G を NVMe SSD に置いて開いた状態。データが OS のキャッシュにない状態にしてある。

**手順**:

1. 検索バーで種類「Hex」に `48 45 58 45 4E 44 21 21` を入力し、Enter を押して時間を測る。
2. 選択範囲を読む。
3. キャッシュを空にして、手順 1〜2 を 3 回行う。
4. 同じ条件 (キャッシュを空にした状態) で、ストレージの読み込み速度 (同じファイルを先頭から 4 MiB 単位で順に読む時間から求める。FIND-01 の「読み込み速度」) を測る。

**期待結果**:

- 3 回とも、選択は 10,737,418,232 (末尾 − 8) から長さ 8。
- 検索の速度 (10 GiB ÷ 時間。3 回のうち最も遅い値) が、手順 4 の読み込み速度の 80% 以上。
- この計測機では、3 回とも 10 秒以内に終わる。

### TC-FIND-01-05 検索の種類ごとの速度

| 項目 | 内容 |
| --- | --- |
| 確認する基準 | FIND-01 の受け入れ基準 4 |
| 種別 | 自動: 性能 |
| 優先度 | 低 |
| フェーズ | 2 |
| テストデータ | TD-FIND-RANDOM-10G |
| 環境 | TC-FIND-01-04 と同じ計測機 |

**前提**: TD-FIND-RANDOM-10G を開いた状態。データが OS のキャッシュにない状態にしてある。

**手順**:

1. 次の検索で、それぞれキャッシュを空にしてから、ファイル全体の次を検索 (一致は末尾だけ、または一致なし) の時間を測る。
   - テキスト (大文字・小文字を区別しない、ASCII) `hexend!!`
   - 整数 (64 bit、リトルエンディアン) `0x2121444E45584548`
   - 浮動小数点 (double、絶対誤差 `1e-300`) `1.5e300`
   - 正規表現 (バイト列、後戻りしない方式) `HEX[A-Z]{3}!!`
2. 各検索の速度 (10 GiB ÷ 時間) を求める。
3. TC-FIND-01-04 の手順 4 と同じ方法で、読み込み速度 R を測る。

**期待結果**:

- 大文字・小文字を区別しないテキストは、500 MiB/s と 0.8 × R のうち小さい方以上。
- 整数・浮動小数点は、300 MiB/s と 0.8 × R のうち小さい方以上。
- 正規表現は、100 MiB/s と 0.8 × R のうち小さい方以上。
- 前回の夜間の計測から 20% 以上遅くなった場合は警告として記録する。

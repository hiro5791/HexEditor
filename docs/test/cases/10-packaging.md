# テストケース: 配布形態と自動更新

機能仕様書 [10-packaging.md](../../spec/10-packaging.md) (PKG-01〜PKG-31、受け入れ基準 101 項目) のテストケース。書式と種別の決め方は [00-test-strategy.md](../00-test-strategy.md) に従う。

| 種別 | 件数 |
| --- | --- |
| 自動: 単体 | 5 |
| 自動: 結合 | 18 |
| 自動: UI | 1 |
| 自動: 性能 | 2 |
| 自動: 配布 | 63 |
| 手動 | 17 |
| 合計 | 106 |

- 手動の 17 件の所要時間の目安の合計は 69 分。うち優先度「高」(スモークテスト) は 3 件、14 分 (Windows 10 でのポータブル版とインストーラ版、ARM64 の実機)。
- 「自動: 配布」のテストは GitHub Actions の Windows ランナー (x64 は `windows-latest`、ARM64 は `windows-11-arm`) で行う。インストーラ版のテストは、ランナーの既定のアカウント (管理者) で、昇格を求めずに `Setup.exe` を実行する。一般ユーザーのアカウントでしか確かめられないこと (UAC の確認画面が出ないこと) は、そのためのアカウントを作るまで確かめない (TC-PKG-07-01 の一部)。
- 「自動: 配布」のテストの実行場所: `ci.yml` の毎晩と手動の実行で、配布物を調べるもの (`artifacts`)、ポータブル版 (`portable`)、3 種類の配布形態を入れて起動するもの (`distribution`。x64 と ARM64)、MSIX 版 (`msix`)、UI テストの突き合わせ (`ui-distro`、`same-results`) を行い、`release.yml` の `verify` でインストーラ版 (`Test-Installer.ps1`) を、`publish` でできたリリース (`Test-Release.ps1`) を確かめる。アプリを操作するテストは、テスト用のビルド (`build/publish.ps1 -TestHooks`) をテスト用の命令の通り道 (00-test-strategy.md 7.2) で操作し、`--test-profile` を使わずに各配布形態の本来の保存先を使う。
- まだない機能に依存する手順は、テストのスクリプトが「Skipped」または「Not checked」として理由をジョブの概要に出す。どの手順かは各テストケースの備考に書く。
- MSIX 版の自動テストは、テスト用の証明書をその場で作ってパッケージに署名し、そのランナーの中だけで信頼してインストールする (PKG-24 の仕様 1 の手順 7 と同じ方法)。この証明書とパッケージは公開しない。Microsoft Store からのインストール・更新と、UAC の確認画面・SmartScreen の警告が出る操作は手動にする。
- 更新のテスト (PKG-08 の一部、PKG-17〜PKG-22) は、更新のテスト用の配布元 TD-PKG-UPDATE-FEED と、テスト用のビルド (00-test-strategy.md 7.2) を使い、設定 `test.update.source` (PKG-17 の仕様 8) に TD-PKG-UPDATE-FEED のリポジトリの URL を書いて更新の確認先を差し替える。この文書の「更新のテスト用のビルド」はこの状態のテスト用のビルドを指す。「版 0.9.0」などの版は TD-PKG-UPDATE-FEED のリリースを指す。
- ワークフローのテスト (PKG-01 の一部、PKG-16、PKG-23〜PKG-29) は、本リポジトリを複製したテスト用のリポジトリで、ワークフローを実際に動かして確認する。このうち、できたリリースを調べるもの (TC-PKG-01-01、TC-PKG-24-01、TC-PKG-24-02、TC-PKG-24-04、TC-PKG-25-01、TC-PKG-25-04、TC-PKG-26-01、TC-PKG-26-02) は、本リポジトリのリリースのたびに `release.yml` でも確かめる。わざと壊した変更・フォーク・ブランチ保護の設定が要るもの (TC-PKG-16-02、TC-PKG-23-02、TC-PKG-23-03、TC-PKG-24-03) は、本リポジトリで行うと `main` を壊す・リリースや Issue を作るため、テスト用のリポジトリでだけ行う (スクリプトの部分は `tests/HexEditor.Platform.Tests` でも確かめる)。
- ネットワークの記録は、ETW の TCP/IP と DNS のイベントを、HexEditor のプロセスとその子プロセスについて集めたものを指す。
- 手動のテストケースの前提は、手動テスト支援ツールの「準備」(00-test-strategy.md 8.2) と、`tools/sandbox/` の Windows Sandbox の設定 (8.5) で作る。

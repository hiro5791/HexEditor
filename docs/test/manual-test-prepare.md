# 手動テストの準備の手順

手動テスト支援ツール (`tools/ManualTestRunner`、テスト方針 8 章) が、テストケースごとの「準備の手順」に表示する内容です。
ツールはこのファイルを読みます。テストケースの文 (前提・手順・期待結果) は `cases/*.md` のものをそのまま表示し、ここには「どう用意するか」だけを書きます。

書き方 (ツールが読む形):

- `### 機材: 名前` … この PC のほかに要る物・ソフト・環境。これを 1 つでも使うテストケースは「機材が必要」になり、ツールの「機材が必要なテストを除く」で一覧から外れる。
- `### 環境: 名前` … この PC だけで用意できる設定や操作。「機材が必要」には数えない。
- `### TD-…` … 準備ボタンで作れないテストデータの用意のしかた。
- `### TC-…` … テストケースごとの準備。表の項目は次のとおり。どれも省略できる。
  - 起動: `開発版` (既定)、`開発版 (管理者)`、`ポータブル版`、`ポータブル版 (管理者)`、`インストーラ版`、`なし` (HexEditor を起動しない)
  - 引数: HexEditor に渡す引数。`{TD-…}` は作ったテストデータのパス、`{設定フォルダ}` はテスト用の設定フォルダ。`なし` ならファイルを開かない。省略すると、最初のテストデータを開く
  - 必要なもの: 上の「機材」「環境」の名前を「、」で区切って書く
  - 設定: テスト用の設定フォルダの settings.json に書く項目 (JSON)
  - フック: `--test-hooks` の設定 (JSON。開発版だけ)。TD-VIEW-HOOK-READERR などのフックのテストデータは、ツールがこの設定を自分で作る
  - コピー先: `デスクトップ` なら、最初のテストデータをデスクトップにも置く
  - コマンド (管理者): 準備のときに、管理者の PowerShell で実行するコマンド (リポジトリのフォルダで実行する)
  - 表の後の行は、そのテストケースだけの補足の手順。「準備の前に」を含む行があれば、ツールは補足を準備の前の段階 (「済んだ」を押す) にする。ほかは手順を行うときに読むこととして出す。

ツールは、この内容から「いま行うこと」の段階を作る (`PrepGuide`)。自動でできる段階 (仮想ディスク・ポータブル版・インストーラ版・準備) は「準備」ボタン 1 つで続けて行い、手で行う段階で止まる。順は、機材 → 準備ボタンで作れないテストデータ → 仮想ディスク → ポータブル版 → インストーラ版 → 準備の前に行う設定 → 準備 → 準備の後に行うこと (ナレーター・TestTarget) → 手順。管理者として実行・一般ユーザーの権限・ハイコントラストなど、手順を行いながら気をつけることは段階にせず、最後の段階に書く。「ないとき: 「対象外」を押し、コメントに「…」と書く。」の行があれば、その段階に飛ばすボタン (コメントを書いて対象外・保留にする) を付ける。

## 1. 機材

### 機材: USB メモリ
用意するもの: USB メモリ 1 本 (FAT32 か exFAT で初期化したもの。中身は読むだけ)。
1. USB メモリを PC に挿す。
2. エクスプローラーで、USB メモリのドライブ文字を確かめる (テストケースでは E: と書いてある。違う文字なら読み替える)。
確かめ方: エクスプローラーの「PC」に USB メモリが出ている。
ないとき: 「対象外」を押し、コメントに「USB メモリなし」と書く。

### 機材: 消えてよい USB メモリ
用意するもの: 中身が消えてもよい USB メモリ 1 本 (容量はテストケースの「環境」を見る)。大切なデータが入ったものは使わない。
1. ほかの USB ディスクと外付けディスクをすべて抜き、このテストに使う USB メモリだけを挿す。
2. PowerShell (管理者でなくてよい) で `Get-Disk | Format-Table Number,FriendlyName,BusType,Size` を実行する。
3. BusType が USB の行が USB メモリ。FriendlyName と Size が手元の USB メモリと合うことを確かめ、ディスク番号を紙に書く (以下 N)。
4. システムのディスク (BusType が NVMe か SATA、通常は 0 番) は絶対に選ばない。
5. HexEditor のダイアログに出るディスク番号・名前・容量が、書いたものと同じかをもう一度見る。少しでも迷ったら「キャンセル」を押し、このテストは「保留」にする。
6. テストが終わったら、「ディスクの管理」で USB メモリを初期化し直す。
ないとき: 「対象外」を押し、コメントに「消えてよい USB メモリなし」と書く。

### 機材: 書き込み禁止スイッチ付きの USB メモリ
用意するもの: 書き込み禁止のスイッチが付いた USB メモリ。
1. スイッチをオフ (書き込める状態) にして挿し、テストケースの前提のとおりにファイルを置く。ポータブル版の zip は、ツールの「ポータブル版を作る」で作ったものを使う (下の「ポータブル版」を参照)。
2. いったん抜き、スイッチをオン (書き込み禁止) にして挿し直す。
ないとき: 「対象外」を押し、コメントに「書き込み禁止スイッチ付きの USB メモリなし」と書く。

### 機材: HPA を設定した SATA ディスク
用意するもの: HPA (隠し領域) を設定した SATA の HDD か SSD と、それを内蔵 SATA ポートにつないだ PC。普通は用意できない。
ないとき: 「対象外」を押し、コメントに「HPA を設定したディスクなし」と書く。

### 機材: ATA パススルー非対応の USB 変換アダプタ
用意するもの: ATA パススルーに対応しない USB 変換アダプタでつないだ SATA ディスク (または USB メモリ)。
ないとき: 「対象外」を押し、コメントに「機材なし」と書く。

### 機材: スピーカーかヘッドホン
用意するもの: 音を聞けるスピーカーかヘッドホン。
1. タスクバーの音量のアイコンで、ミュートになっていないことと、音量が 0 でないことを確かめる。
ないとき: 「対象外」を押し、コメントに「音を聞けないため」と書く。

### 機材: モニター 2 台
用意するもの: 表示倍率を変えられる 2 台目のモニター (テストケースの「環境」の倍率にする)。
1. Windows の「設定 > システム > ディスプレイ」で、2 台のモニターの「拡大/縮小」をテストケースの「環境」の値にする。
2. テストが終わったら、倍率を元に戻す。
ないとき: 「対象外」を押し、コメントに「モニターが 1 台のため」と書く。

### 機材: 高精度タッチパッド
用意するもの: 高精度タッチパッドを持つノート PC (「設定 > Bluetooth とデバイス > タッチパッド」に「お使いの PC には高精度タッチパッドがあります」と出るもの)。
ないとき: 「対象外」を押し、コメントに「高精度タッチパッドなし」と書く。

### 機材: プリンタ
用意するもの: 白黒で印刷できる実機のプリンタ。
1. Windows の「設定 > Bluetooth とデバイス > プリンターとスキャナー」にプリンタが登録されていることを確かめる。
2. 電源を入れ、用紙を入れておく。
ないとき: 「対象外」を押し、コメントに「プリンタなし」と書く。

### 機材: Microsoft Word
用意するもの: Microsoft Word がインストールされていること (スタートメニューに Word がある)。
ないとき: 「対象外」を押し、コメントに「Word なし」と書く。

### 機材: Microsoft Excel
用意するもの: Microsoft Excel がインストールされていること (スタートメニューに Excel がある)。
ないとき: 「対象外」を押し、コメントに「Excel なし」と書く。

### 機材: 他の Hex エディタ
用意するもの: テストケースの名前にある Hex エディタ (HxD、010 Editor、Hex Editor Neo、WinHex、Hex Workshop、Frhed、Visual Studio のどれか) がインストールされていること。
ないとき: 「対象外」を押し、コメントに「(エディタの名前) なし」と書く。

### 機材: NVDA
用意するもの: スクリーンリーダー NVDA (最新の安定版) がインストールされていること。
ないとき: 「対象外」を押し、コメントに「NVDA なし」と書く。

### 機材: FTK Imager
用意するもの: FTK Imager 4.7 がインストールされていること。
ないとき: 「対象外」を押し、コメントに「FTK Imager なし」と書く。

### 機材: QEMU
用意するもの: QEMU (`qemu-system-x86_64`) がインストールされていること (PowerShell で `qemu-system-x86_64 --version` が動く)。
ないとき: 「対象外」を押し、コメントに「QEMU なし」と書く。

### 機材: SSH サーバー
用意するもの: SSH / SFTP で接続できるサーバー (NAS、Linux の PC、WSL の OpenSSH など) と、パスワードでログインできるユーザー。
ないとき: 「対象外」を押し、コメントに「SSH サーバーなし」と書く。

### 機材: Windows 10 の仮想マシン
用意するもの: Windows 10 の仮想マシン (テストケースの「環境」の版。1809 か 22H2) と、テストケースの前提の状態のスナップショット。
1. この PC でツールの「ポータブル版を作る」を押して zip を作る (zip の場所は準備の結果に出る)。
2. zip とテストデータ (準備ボタンで作ったもの。場所は準備の結果に出る) を仮想マシンにコピーする。
ないとき: 「対象外」を押し、コメントに「Windows 10 の仮想マシンなし」と書く。

### 機材: Windows 11 x64 の仮想マシン
用意するもの: 証明書の操作をしていない Windows 11 x64 の仮想マシンと、HexEditor が入っていない状態のスナップショット。
ないとき: 「対象外」を押し、コメントに「仮想マシンなし」と書く。

### 機材: Windows 11 ARM64 の PC
用意するもの: Windows 11 の ARM64 の実機 (Snapdragon の PC など)。
ないとき: 「対象外」を押し、コメントに「ARM64 の PC なし」と書く。

### 機材: Windows 11 Pro
用意するもの: Windows 11 Pro 以上の PC (BitLocker、動的ディスクのストライプ、Windows Sandbox が使える版)。この PC は Home なので使えない。
ないとき: 「対象外」を押し、コメントに「Home のため」と書く。

### 機材: Mac
用意するもの: Mac と、中身が消えてよい USB メモリ。
ないとき: 「対象外」を押し、コメントに「Mac なし」と書く。

### 機材: 追加の入力方式
用意するもの: テストケースの「環境」にある入力方式 (トルコ語 Q、中国語のピンイン、韓国語、タイ語、ベトナム語など) を Windows に追加すること。
1. 「設定 > 時刻と言語 > 言語と地域」で言語を追加し、その言語の「言語のオプション」でキーボードを追加する。
2. テストが終わったら、追加したキーボードと言語を削除する。
ないとき (追加したくないとき): 「対象外」を押し、コメントに「入力方式を追加しないため」と書く。

### 機材: 公開・署名のあと
用意するもの: Microsoft Store・winget への公開、コード署名、GitHub Pages の公開の設定のどれか (テストケースの前提を見る)。まだ行っていない。
ないとき: 「保留」を押し、コメントにテストケースの前提にある条件 (「Store に公開されたあと」など) を書く。

## 2. この PC で行う設定 (機材は要らない)

### 環境: 仮想ディスク
テスト用の仮想ディスク (TD-VHDX-MBR・TD-VHDX-GPT・TD-VHDX-CLONE) を使う。Windows の設定は変えない。
1. 「準備」を押す (仮想ディスクも作る)。
2. 「このアプリがデバイスに変更を加えることを許可しますか?」と出たら「はい」を押す。
3. 終わると、ボタンの下に 3 つのディスクの番号が出る (HexEditor では「Msft Virtual Disk」と表示される。64 MiB が 2 つ、512 MiB が 1 つ)。
4. PC を再起動すると接続が外れる。そのときは、もう一度「準備」を押す (作ってあるファイルをそのまま接続し直す)。
5. すべての手動テストが終わったら「仮想ディスクを外す」を押す (接続を外してファイルを消す)。

### 環境: 管理者として実行
準備ボタンが HexEditor を管理者として起動する。
1. 「このアプリがデバイスに変更を加えることを許可しますか?」と出たら「はい」を押す。
2. HexEditor のタイトルバーに「管理者」と出ていることを確かめる。

### 環境: 一般ユーザーの権限
準備ボタンは HexEditor を一般の権限で起動する (このツールを管理者として起動していなければ、そうなる)。
1. HexEditor のタイトルバーに「管理者」と出ていないことを確かめる。

### 環境: ポータブル版
準備ボタンは、ツールが作ったポータブル版 (`%LOCALAPPDATA%\HexEditorManualTests\portable\HexEditor\HexEditor.exe`) を起動する。
1. まだ作っていなければ、「準備」を押すと作る (数分かかります)。ボタンの下に進み具合が出る。
2. ソースを新しくしたときは、「ポータブル版を作り直す」を押す。

### 環境: インストーラ版
準備ボタンは、インストールしたインストーラ版 (`%LOCALAPPDATA%\HexEditor\current\HexEditor.exe`) を起動する。
1. まだインストールしていなければ、「準備」を押すと作ってインストールする (数分かかります)。作り終わるとインストーラが動き、この PC のユーザーにインストールされる。
2. すべての手動テストが終わったら、「設定 > アプリ > インストールされているアプリ」で HexEditor をアンインストールする。

### 環境: ナレーター
Windows のナレーター (スクリーンリーダー) を使う。
1. 準備の後、HexEditor のウィンドウをクリックしてから、Ctrl + Windows + Enter でナレーターを起動する。
2. 終わったら、もう一度 Ctrl + Windows + Enter でナレーターを止める。

### 環境: ハイコントラスト
スクリーンショットの代わりに、画面を直接見て確かめる。
1. 「設定 > アクセシビリティ > コントラスト テーマ」で、テストケースの「環境」にあるテーマ (水生・砂漠・夕暮れ・夜空。「黒」は夜空、「白」は砂漠に当たる) を選び、「適用」を押す。
2. HexEditor の画面を見て、期待結果と比べる。ほかのテーマでも同じことを行う。
3. 終わったら、コントラスト テーマを「なし」に戻す。

### 環境: ライトとダークのテーマ
スクリーンショットの代わりに、画面を直接見て確かめる。
1. HexEditor の「設定」(Ctrl+,) の「外観」で、テーマを「ライト」「ダーク」に順に切り替えて見比べる。
2. 終わったら、テーマを「システムの設定」に戻す (テスト用の設定フォルダなので、戻さなくても普段の設定は変わらない)。

### 環境: グレースケール
色を使わずに区別できるかを、画面を白黒にして確かめる。
1. 「設定 > アクセシビリティ > カラー フィルター」で「カラー フィルター」をオンにし、「グレースケール」を選ぶ (Windows + Ctrl + C でも切り替わる)。
2. 終わったら、カラー フィルターをオフに戻す。

### 環境: 表示倍率 200%
1. 「設定 > システム > ディスプレイ」の「拡大/縮小」を、テストケースの「環境」の値 (100% と 200% など) に順に変えて見る。
2. 終わったら、元の倍率に戻す。

### 環境: 日本語 IME
1. タスクバーの入力インジケーターが「あ」(日本語 IME) になっていることを確かめる。「A」なら半角/全角キーで切り替える。

### 環境: 実際のキーボード
画面キーボードやリモートデスクトップではなく、この PC のキーボードで入力する。

### 環境: 半自動の目視
このテストケースは「ツールが撮ったスクリーンショット」を見る前提で書かれているが、このツールはスクリーンショットを撮らない。代わりに、準備ボタンで起動した HexEditor を前提の状態にして、画面を直接見て確かめる。
1. 前提に別のテストケース (TC-…) の状態が書いてあれば、下の「参照するテストケース」の手順のとおりに操作して、その状態にする。
2. テーマや倍率ごとに見るものは、上の「ハイコントラスト」などの手順で切り替える。

### 環境: この PC の SATA ディスク
1. PowerShell で `Get-PhysicalDisk | Format-Table DeviceId,FriendlyName,BusType,Size` を実行する。
2. BusType が SATA のディスクがあれば、その DeviceId をディスク番号として控える (以下 N)。読み取るだけで、書き換えない。
ないとき (SATA のディスクがない): 「対象外」を押し、コメントに「SATA のディスクなし」と書く。

### 環境: この PC の NVMe SSD
1. PowerShell で `Get-PhysicalDisk | Format-Table DeviceId,FriendlyName,BusType,SerialNumber` を実行し、BusType が NVMe のディスクの番号とシリアル番号を控える。読み取るだけで、書き換えない。
ないとき (NVMe のディスクがない): 「対象外」を押し、コメントに「NVMe SSD なし」と書く。

### 環境: TestTarget
準備ボタンが、管理者の PowerShell のウィンドウで `dotnet run --project tools/TestTarget -c Release` を実行する。
1. 「このアプリがデバイスに変更を加えることを許可しますか?」と出たら「はい」を押す。
2. 開いた PowerShell のウィンドウに `VALUE 0x...` の行が出たら、そのアドレスを控える。`READY` が出たら、そのウィンドウは開いたままにする。
3. テストが終わったら、その PowerShell のウィンドウを閉じる。

## 3. 準備ボタンで作れないテストデータ

### TD-VHDX-MBR
「仮想ディスクを作る」で作る (上の「仮想ディスク」を参照)。HexEditor では 64 MiB の「Msft Virtual Disk」で、ボリュームのラベルは HEXVHD。

### TD-VHDX-GPT
「仮想ディスクを作る」で作る (上の「仮想ディスク」を参照)。HexEditor では 64 MiB の「Msft Virtual Disk」で、パーティションが 2 つ (NTFS と FAT32) ある。

### TD-FOR-BITLOCKER
BitLocker で暗号化した VHDX で、Windows 11 Pro でないと作れない (保管のテストデータ)。この PC では用意できないので、「対象外」にし、コメントに「Home のため」と書く。

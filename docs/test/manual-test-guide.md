# 手動テストの手引き (最終確認用)

この文書は、最後の手動テストを行う人のための手引きです。
使う道具は「手動テスト支援ツール」(`tools/ManualTestRunner`) です。

**手動テストは、ツールの画面だけで行えます。** テストケースを選ぶと、ツールの「準備の手順」の欄に、準備ボタンが自動で行うこと・テストケースの前提・あなたが行うこと (機材や設定の用意のしかた、ないときの扱い) が出ます。この文書は、ツールを最初に起動するまでのことと、全体の流れの補足です。

- テストケースは `docs/test/cases/*.md`、準備の手順は `docs/test/manual-test-prepare.md` にあり、ツールが直接読みます。
- 準備の手順を直すときは `manual-test-prepare.md` を直します (書き方はそのファイルの先頭)。すべての手動・半自動のテストケースに準備の手順があることを、CI が検査します。

## 1. 件数と所要時間

手動と半自動のテストケースは、全部で 114 件です (手動 91 件、半自動 23 件)。所要時間の目安の合計は約 418 分です。

| まとまり | 件数 | 目安 |
| --- | --- | --- |
| この PC だけでできる | 42 件 | 約 133 分 |
| 機材が必要 (USB メモリ、プリンタ、スピーカー、別の PC、Word・Excel、公開・署名のあとなど) | 72 件 | 約 285 分 |

ツールの「機材が必要なテストを除く」は、最初からオンです。オンのあいだは、この PC だけでできる 42 件だけが一覧に出ます。
除いたものは、「報告を書き出す」で報告の「機材が必要なため今回は実施しない」の節に書かれ、合格・不合格の件数には数えられません。
機材がそろったら、チェックを外すと一覧に出ます。

何を「機材」とするかは、`manual-test-prepare.md` の「1. 機材」の一覧です。
ツールのボタンで作る仮想ディスクと、この PC のディスク (NVMe・SATA) は、機材に数えません。

## 2. ツールのビルドと起動

PowerShell をリポジトリのルート (`f:\dev\HexEditor`) で開き、次を順に実行します。

```powershell
git switch main
git pull
dotnet build src/HexEditor.App/HexEditor.App.csproj -p:Platform=x64
dotnet build tools/ManualTestRunner -p:Platform=x64
```

1 つ目のビルドは、テストする HexEditor 本体 (開発版) を作ります。
2 つ目のビルドが、手動テスト支援ツールです。ツールを開いたままだとビルドに失敗するので、先にツールを閉じます。

ツールを起動します (エクスプローラーでダブルクリックしてもかまいません)。

```powershell
& "tools\ManualTestRunner\bin\x64\Debug\net10.0-windows10.0.26100.0\win-x64\ManualTestRunner.exe"
```

ここから先は、ツールの画面だけで進められます。

- ツールは、開発版の HexEditor (`src\HexEditor.App\bin\x64\Debug` の下の `HexEditor.exe`) を自分で探します。
- ポータブル版・インストーラ版が要るテストケースでは、ツールに「ポータブル版を作る」「インストーラ版を作ってインストールする」のボタンが出ます。押すと、ツールが `build/publish.ps1` で作ります (数分かかります)。
- 仮想ディスクが要るテストケースでは、「仮想ディスクを作る (管理者の確認が出ます)」と「仮想ディスクを外す」のボタンが出ます。押すと Windows の確認が出るので「はい」を押します。終わると、ディスクの番号が出ます。Windows の設定は変えません。
- ツールのウィンドウは、既定で「常に手前に表示」になります。邪魔なときはチェックを外します。
- 結果は `%LOCALAPPDATA%\HexEditorManualTests` に自動で保存されます。途中で閉じても、次回は続きから再開できます。

## 3. テストケースを選ぶ

1. 「テストの選び方」を「リリース前 (すべての手動・半自動)」にする。一度選べば、次に起動したときも同じ選び方になる。
2. 「フェーズ (以下)」がいちばん大きい数になっていることを確かめる (既定でいちばん大きい数になる)。
3. 「機能 ID」の欄は空にする。
4. 「機材が必要なテストを除く」をオンのままにする (横に、除いた件数が出る)。

一部だけ行うときは、「機能 ID」の欄に `ENG-28` や `TC-UI-` のように入れて絞ります。
「未実施のもの」を選ぶと、まだ結果を付けていないものだけが出ます。
「前回不合格・保留のもの」を選ぶと、やり直しが必要なものだけが出ます。

## 4. 1 件ごとの進め方

1. 一覧からテストケースを選ぶ。
2. 「準備の手順」を上から読む。機材が要るときは、いちばん上に太字で出る。なければ「対象外」(公開・署名のあとのものは「保留」) を押して次へ。
3. 「準備」ボタンを押す。準備の手順の「1.」が、行ったこと (✔) に変わる。できなかったこと (✖) があれば、その行に理由と次にすることが出る。
4. 準備の手順の「3. あなたが行うこと」を行う。
5. 「手順」を 1 つずつ行い、チェックを付ける。
6. 「期待結果」と見比べて、「合格」「不合格」「保留」「対象外」のどれかを押す。
7. 不合格のときは、コメントに気づいたことを書く。HexEditor のウィンドウの画像と環境の情報は自動で付きます。

| 結果 | 使うとき |
| --- | --- |
| 合格 | 期待結果のとおりだった |
| 不合格 | 期待結果と違った。コメントに何が違ったかを書く |
| 保留 | 今はできないが、あとで行う。コメントに理由と、できるようになる条件を書く |
| 対象外 | 機材や環境がなく、行わない。コメントに「機材なし」などと書く |

補足:

- 半自動のテストケースは「ツールが撮ったスクリーンショット」を見る前提で書かれていますが、ツールはスクリーンショットを撮りません。準備の手順の「半自動の目視」のとおり、HexEditor の画面を直接見て確かめます。
- 前提に別のテストケース (TC-…) の状態が書いてあるときは、準備の手順の「4. 参照するテストケース」に、そのテストケースの前提と手順が出ます。
- 「すべてコピー」を押すと、テストケースの内容 (準備の手順を含む) をまとめてコピーできます。どの文字も選んでコピーできます。

## 5. 壊れてもよい機材だけを使う (破壊を伴うテスト)

TC-FOR-24-04 (クローン)、TC-FOR-25-03 (セクタの復元)、TC-FOR-30-05 (ディスク全体の消去) は、USB メモリの中身を消したり書き換えたりします。
ツールの準備の手順の「消えてよい USB メモリ」に、ディスクの番号の確かめ方が出ます。そのとおりに行い、少しでも迷ったら「キャンセル」を押して「保留」にします。

## 6. 結果を書き出して Claude に送る

1. ツールで、「テストの選び方」を「リリース前 (すべての手動・半自動)」、「フェーズ」をいちばん大きい数、「機能 ID」を空にする。書き出しは、いま一覧に出ているもの (と、機材が必要なため除いたもの) が対象です。
2. 「報告を書き出す」を押す。
3. ダイアログに、書き出した場所と、後片付け (仮想ディスクを外す、ポータブル版の `HexEditor.Elevated.exe` の名前を戻す、インストーラ版のアンインストール) が出る。仮想ディスクが残っていれば、ダイアログの「仮想ディスクを外す」で外せる。
4. `report-日時.md` と `report-日時.json` を Claude に渡す (チャットに貼るか、パスを伝える)。不合格のスクリーンショットは、同じフォルダの `screenshots` にあります。

不合格のものは、Claude が GitHub の Issue の下書きにします。送信は、あなたが確かめてから行います。
最初からやり直したいときは「新しく始める」を押します。前回の結果は `run-日時.json` に残ります。

## 7. 注意

- HexEditor のウィンドウを、別のアプリの上に無理に出さないでください。テストの間は、ツールの「常に手前に表示」を使います。
- クリップボードを使うテストでは、他のアプリのコピーしたものが消えます。終わってから他の作業をしてください。
- TC-FOR-02-01 は Windows の USB 書き込み保護の設定を変えます。手順の最後で必ず無効に戻します。
- 手順のとおりにできないとき (ボタンの名前が違うなど) は、「不合格」にして、コメントに見たものをそのまま書きます。
- `%TEMP%\HexEditor\dev-no-activate` というファイルがあると、ツールと HexEditor が前面に出ません (開発中の確認用)。あるときは、ツールの一覧の下に注意が出ます。

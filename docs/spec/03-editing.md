# 機能仕様書: 編集、選択、クリップボード、Undo、データ演算、パッチ

この文書は、選択、入力と編集、元に戻す / やり直し、クリップボード、塗りつぶし、データ演算、テキスト変換、暗号化・圧縮、パッチ、変換を通した編集の振る舞いを定める。書式・用語・入力式・ショートカットは [00-overview.md](00-overview.md) に従う。

対象とするロードマップの項目:

| フェーズ | ID |
| --- | --- |
| フェーズ 0 | F0-04 (選択)、F0-05 (編集)、F0-06 (Undo / Redo)、F0-07 (クリップボード) |
| フェーズ 1 | F1-11 (選択範囲の指定)、F1-14 (塗りつぶし・挿入)、F1-15 (Copy As)、F1-16 (貼り付けの自動判別)、F1-23 (読み取り専用モード) |
| フェーズ 2 | F2-05 (データ演算)、F2-12 (マルチ選択)、F2-13 (文字コード変換)、F2-15 (矩形選択) |
| フェーズ 4 | F4-02 (分岐する Undo 履歴)、F4-03 (パッチ)、F4-04 (暗号化・圧縮) |

ロードマップにない機能は、調査 ([../research/feature-survey.md](../research/feature-survey.md) の 2.3、2.4 章) で見つかったものを「追加 (フェーズ N 提案)」として載せる。

## この文書で使う用語

[00-overview.md](00-overview.md) の 3 章の用語に加えて、次の用語を使う。

| 用語 | 意味 |
| --- | --- |
| 固定長ドキュメント | 長さを変えられないデータソースのドキュメント。物理ディスク、論理ボリューム、プロセスメモリ (`IByteSource` の「サイズ変更できるか」が偽のもの) |
| アンカー | 範囲選択の起点。選択範囲はアンカーとカーソルの間になる |
| 末尾位置 | オフセット = ドキュメントの長さの位置。最後のバイトの次。カーソルは末尾位置に置ける (追加入力のため) |
| 主カーソル | マルチカーソルのうち、画面のスクロールとステータスバーの表示に使うカーソル。最後に追加したカーソル |
| 編集グループ | 1 回の元に戻す / やり直しで一緒に戻る編集のまとまり |
| 選択の要素 | 選択範囲を構成する 1 つの連続範囲。単一選択では 1 つ、マルチ選択では複数 |
| 長さが変わる編集 | 挿入・削除・長さの違う置き換え。固定長ドキュメントでは実行できない |
| 追加データ | 編集で新しく作られたバイト列。データエンジン (ENG) の追加バッファに入り、一定量を超えると一時ファイルに退避される |

共通の約束:

1. この文書の編集操作はすべて元に戻せる (EDIT-19)。1 つのコマンドは 1 つの編集グループになる。
2. 長時間処理になる編集操作は、結果を追加データとして作り終えてから 1 回でドキュメントに反映する。途中でキャンセルまたは失敗した場合、ドキュメントは変わらない。
3. 読み取り専用のドキュメントでは、データを変えるコマンドを実行しない (EDIT-16)。
4. 固定長ドキュメントでは、長さが変わる編集を実行しない。メニューでは無効にし、ショートカットで呼ばれた場合は InfoBar で理由を示す。
5. 選択範囲がない状態で選択範囲を対象とするコマンドを呼んだ場合、ダイアログの対象範囲の欄にカーソル位置から 1 バイトを入れて開く (ダイアログのないコマンドは無効にする)。

## 1. 選択

### EDIT-01 マウスによる選択

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-04 |
| 呼び出し | マウスのクリック、ドラッグ、Shift+クリック、ダブルクリック、トリプルクリック |

**概要**: マウスでカーソルを置き、範囲を選択する。Hex 列・テキスト列・オフセット列のどこからでも選択でき、選択はバイト単位で両方の列に同時に表示する。

**仕様**:

1. 左クリック: クリックしたバイトにカーソルを置き、選択を解除する。アンカーをその位置にする。Hex 列では、クリックした文字が上位ニブルか下位ニブルかによってカーソルのニブル位置を決める。
2. ドラッグ: 押した位置をアンカーにし、ポインタの位置までを選択する。選択範囲はアンカーのバイトとポインタのバイトの両方を含む。
3. ドラッグ開始の判定: ポインタが 4 px (表示倍率 100% 換算) 以上動いた時点でドラッグとする。それ未満で離した場合はクリックとして扱う。
4. Shift+クリック: アンカーを変えずに、クリックした位置までを選択する。選択範囲はアンカーのバイトとクリックしたバイトの両方を含む (クリックしたバイトがアンカーより前の場合も同じ)。
5. ダブルクリック: Hex 列では、クリックしたバイトを含むグループ (表示設定のグループ化単位。1 / 2 / 4 / 8 / 16 バイト) を選択する。テキスト列では、クリック位置を含む「印字可能文字の連続」を選択する。印字可能文字の判定は現在の文字コードで行う。連続が 64 KiB を超える場合は、クリック位置から前後 32 KiB までにする。
6. トリプルクリック: クリックした行 (表示上の 1 行) 全体を選択する。
7. オフセット列のクリックは行全体を選択し、オフセット列でのドラッグは行単位で選択する。
8. 列をまたぐドラッグ: Hex 列で押してテキスト列まで動かした場合も、ポインタの真下のバイトを基準に選択する。どちらの列で押したかで、操作後に入力を受け付ける列 (アクティブな列) を決める。
9. 自動スクロール: ドラッグ中にポインタが表示領域の上下の外に出た場合、外に出た距離に応じた速さでスクロールする (VIEW-28 の 7)。距離 0〜50 px では距離に比例して 1 秒あたり 1〜20 行。50 px を超えると距離に比例して速くし、150 px で 1 秒あたり表示行数の 10 倍 (最低 20 行) に達する。50 px を超えた状態を保つと、さらに 1 秒ごとに速度を 2 倍にする (指を戻せば距離による速度に戻る)。最大速度は 1 秒あたり 1,000,000 行とする。移動するバイト量は 1 行のバイト数に比例する (1 行 16 バイトでは 1 秒あたり約 15 MiB で、100 GiB の端まで約 1.9 時間。1 行 4,096 バイトでは 1 秒あたり約 3.8 GiB で、100 GiB の端まで約 30 秒)。
10. 右クリック: 選択範囲の中を右クリックした場合は選択を保ったまま右クリックメニューを開く。選択範囲の外を右クリックした場合はその位置にカーソルを移し、選択を解除してから開く。
11. 末尾位置 (最後のバイトの次) は、最終行の最後のバイトの右側をクリックしたときに選べる。
12. 選択範囲が変わったら、ステータスバーの選択範囲の表示 (開始・終了・長さ) を更新する (表示の仕様は 09 / 02)。

**画面**: 選択範囲は Hex 列とテキスト列の両方を `ThemeResource` の選択色で塗る。アクティブでない列の選択は薄い色で塗る。ハイコントラストテーマではシステムの `Highlight` 色を使う。

**巨大ファイル・長時間処理**: 選択範囲はアンカーとカーソルの 2 つの `long` で持ち、範囲の大きさに関係なく一定時間で処理する。選択範囲の描画は見えている行だけ行う。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 100 GB のファイルで、1 行 4,096 バイトの表示にして先頭からドラッグして自動スクロールし、末尾近くまで選択できる (最大速度で約 30 秒)。その間 UI が 60 fps を保つ。
- [ ] Shift+クリックでアンカーが変わらないことを、2 回続けて Shift+クリックして確認できる。
- [ ] Hex 列で 2 バイトグループ表示のとき、ダブルクリックで 2 バイトが選択される。
- [ ] テキスト列で `Hello` の上をダブルクリックすると、前後の非印字文字を含まずに 5 バイトが選択される。
- [ ] 選択範囲の中を右クリックしても選択が解除されない。

### EDIT-02 キーボードによる選択

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-04 |
| 呼び出し | Shift+カーソル移動キー (Shift+矢印、Shift+PageUp / PageDown、Shift+Home / End、Ctrl+Shift+Home / End。00-overview.md 8.3) |

**概要**: カーソル移動キー (02 で定めるもの) に Shift を加えると、アンカーからカーソルまでを選択する。

**仕様**:

1. 選択がない状態で Shift+移動キーを押すと、移動前のカーソル位置をアンカーにして選択を始める。
2. 選択がある状態で Shift+移動キーを押すと、アンカーを変えずにカーソルだけを移動する。
3. Shift を押さない移動キーを押すと、選択を解除してカーソルを移動する。←・→ は、選択がある場合に限り、選択範囲の先頭 / 末尾にカーソルを移すだけにする (テキストエディタと同じ)。
4. 選択はバイト単位。Hex 列でカーソルが下位ニブルにある状態で Shift+→ を押すと、そのバイトを含めて選択し、カーソルを次のバイトの上位ニブルに置く。
5. 移動量は 02 のカーソル移動と同じ。Shift+Ctrl+← / → はグループ単位 (02 の定義) で選択を広げる。
6. Ctrl+Shift+Home / End はドキュメントの先頭 / 末尾位置までを選択する。
7. 選択範囲が変わるたびに、スクリーンリーダーに「選択 開始 0x…、長さ N バイト」を通知する。通知は最後の変化から 500 ms 後に 1 回にまとめる (キーリピート中に読み上げが溜まらないようにする)。

**画面**: EDIT-01 と同じ。

**巨大ファイル・長時間処理**: EDIT-01 と同じ。Ctrl+Shift+End は 100 GB のファイルでも 100 ms 以内に完了する。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] カーソルを 0x10 に置いて Shift+→ を 4 回押すと、0x10〜0x13 の 4 バイトが選択される。
- [ ] その状態で Shift+← を 2 回押すと 0x10〜0x11 の 2 バイトになる (アンカーが 0x10 のまま)。
- [ ] 100 GB のファイルで Ctrl+Shift+End を押すと 100 ms 以内に全体が選択される。
- [ ] ナレーターで、選択範囲の変化がキーを離してから 1 回だけ読み上げられる。

### EDIT-03 すべて選択と選択の解除

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-04 |
| 呼び出し | 編集 > すべて選択 (Ctrl+A)、編集 > 選択の解除 (Esc。エディタの有効範囲。00-overview.md 8.3)、コマンドパレット「すべて選択」「選択の解除」、右クリックメニュー |

**概要**: ドキュメント全体を選択する。または選択を解除する。

**仕様**:

1. すべて選択は、オフセット 0 から末尾位置の直前までを選択する。カーソルは末尾位置、アンカーは 0 に置く。表示位置 (スクロール) は変えない。
2. 長さ 0 のドキュメントでは何もしない。
3. マルチ選択・矩形選択・マルチカーソルの状態ですべて選択を実行すると、単一の選択に戻してから全体を選択する。
4. 選択の解除は、選択を解除してカーソルを現在の位置に残す。マルチカーソル・マルチ選択の場合は主カーソルだけを残す。
5. エディタにフォーカスがある状態で Esc を押すと選択の解除を行う (00-overview.md 8.3 のエディタの有効範囲)。検索バーにフォーカスがある場合の Esc は検索バーの割り当て (00-overview.md 8.4) が優先する。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: 一定時間で完了する。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 100 GB のファイルで Ctrl+A を押すと 100 ms 以内にステータスバーの長さが全体の長さになる。
- [ ] Ctrl+A の後もスクロール位置が変わらない。
- [ ] マルチ選択の状態で Esc を押すと主カーソルだけが残る。

### EDIT-04 範囲を選択

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-11 |
| 呼び出し | 編集 > 範囲を選択 (Ctrl+E)、コマンドパレット「範囲を選択」、ステータスバーの選択範囲の表示をクリック |

**概要**: 開始・終了・長さを入力して範囲を選択する。

**仕様**:

1. ダイアログには「開始」「終了」「長さ」の 3 つの入力欄を置く。入力欄は 00-overview.md 6 章の入力式を受け付ける。
2. 「終了」は選択に含まれる最後のバイトのオフセット (このバイトを含む) とし、入力式の `sel.last` に当たる (`sel.end` は直後の位置で含まないため、これとは 1 違う。00-overview.md 6.2)。ラベルは「終了 (このバイトを含む)」と書く。
3. 3 つのうち最後に編集した 2 つから残りの 1 つを計算して表示する。計算された欄は斜体で示し、編集できる。「長さ = 終了 − 開始 + 1」。
4. 開いたときの初期値: 選択がある場合はその開始・終了・長さ。選択がない場合は開始 = カーソル位置、長さ = 空 (入力待ち)。
5. 選択モードを選べる: 「新しい選択」(既定) / 「現在の選択に追加」(マルチ選択。EDIT-07) / 「現在の選択を広げる」(既存の範囲と入力した範囲を両方含む最小の範囲)。また「矩形として選択」チェックボックス (既定オフ) をオンにすると、開始のバイトと終了のバイトを対角とする矩形選択 (EDIT-06) を、現在の 1 行のバイト数で作る (開始の列が終了の列より右の場合は、左右の列を入れ替えた矩形にする)。オンのときの選択モードは「新しい選択」だけにする。これがキーボードで大きな矩形を作る方法になる。「現在の選択に追加」と「矩形として選択」は、マルチ選択 (EDIT-07) と矩形選択 (EDIT-06) を実装するフェーズ 2 でダイアログに加える (それまでは出さない)。
6. 「選択後に開始位置へ移動」チェックボックス (既定オン)。オンなら選択範囲の開始が見えるようにスクロールする。
7. 確定すると、指定範囲を選択し、アンカーを開始、カーソルを終了の次に置く。
8. 長さ 0 は許可しない (確定ボタンを無効にする)。
9. 入力欄の横に解釈結果 (10 進と 16 進) を表示する (00-overview.md 9 章)。
10. 入力履歴: 各欄は直近 20 件の入力を候補として出す。候補は欄の右の「履歴」ボタンか Alt+↓ で開き、選ぶと欄に入れる。確定したときに入力した欄 (計算で求めた欄を除く) の文字列を履歴に加え、アプリの状態 (09 の UI-23 の `state.json`) に保存する。

**画面**: 小さなダイアログ (ContentDialog)。3 つの入力欄、選択モードのラジオボタン、チェックボックス、「選択」ボタンと「キャンセル」ボタン。

**巨大ファイル・長時間処理**: 該当なし (一定時間で完了する)。

**エラー**:

| 状況 | 表示 |
| --- | --- |
| 開始がドキュメントの長さ以上 | 入力欄を赤枠にし「開始がファイルの末尾を超えています (長さ 0x…)」。確定ボタンを無効にする |
| 終了がドキュメントの末尾を超える | 赤枠と説明に加えて「末尾までにする」ボタンを出す |
| 開始 > 終了、長さが負 | 赤枠と「終了が開始より前です」 |
| 式の構文エラー、存在しないブックマーク名 | 赤枠と、エラーの位置と理由 |

**受け入れ基準**:

- [ ] 開始 `0x100`、長さ `0x20` を入力すると終了に `0x11F` が表示され、確定で 0x100〜0x11F が選択される。
- [ ] 開始 `end-0x10`、終了 `end-1` で最後の 16 バイトが選択される。
- [ ] 末尾を超える終了を入れると確定ボタンが無効になり、「末尾までにする」で修正できる。
- [ ] 地域設定をドイツ語にしても `1.5K` が 1536 と解釈される。

### EDIT-05 選択範囲をずらす・広げる

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 編集 > 選択 > 「選択範囲を次へずらす」「選択範囲を前へずらす」「選択範囲を N バイトずらす…」「選択範囲を広げる / 狭める…」「アンカーとカーソルを入れ替える」。ショートカットはすべて既定なし。コマンドパレットから実行できる |

**概要**: 選択範囲の長さを保ったまま前後にずらす。固定長レコードを 1 件ずつ順に見るときに使う。

**仕様**:

1. 「次へずらす」: 選択範囲を、その長さ分だけ後ろへ移す (開始 += 長さ)。「前へずらす」は前へ移す。
2. 「N バイトずらす…」: ずらす量 (入力式。負の値で前へ) を入力する。入力した量は記憶し、次回から「次へずらす」「前へずらす」の移動量として使う設定 (「ずらす量: 選択範囲の長さ / 最後に指定した量」、既定は選択範囲の長さ) を持つ。
3. ずらした先が先頭より前、または末尾を超える場合は、ずらさずに InfoBar で「これ以上ずらせません」と示す。
4. 「広げる / 狭める…」: 開始側と終了側をそれぞれ何バイト動かすか (入力式、負の値で狭める) を指定する。
5. 「アンカーとカーソルを入れ替える」: 選択範囲は変えず、カーソルを反対側の端に移す。表示もその端へスクロールする。
6. マルチ選択に対して「ずらす」を実行すると、すべての要素を同じ量だけずらす。1 つでも範囲外に出る場合は何もしない。
7. ずらした後は、選択範囲の開始が見えるようにスクロールする。データインスペクタ (05) は新しい選択範囲の開始で再評価する。

**画面**: 「N バイトずらす」「広げる / 狭める」は入力欄 1〜2 個の小さなダイアログ。

**巨大ファイル・長時間処理**: 該当なし。マルチ選択の要素数に比例するが、要素数の上限 (EDIT-07) 内で 100 ms 以内。

**エラー**: 範囲外になる場合は上記 3 のとおり。

**受け入れ基準**:

- [ ] 0x00〜0x1F を選択して「次へずらす」を 3 回実行すると 0x60〜0x7F が選択される。
- [ ] 末尾の 32 バイトを選択して「次へずらす」を実行すると、選択は変わらず InfoBar が出る。
- [ ] 「アンカーとカーソルを入れ替える」で、選択範囲が変わらずにカーソルだけ反対側に移る。

### EDIT-06 矩形選択

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-15 |
| 呼び出し | Alt+ドラッグ、Alt+Shift+矢印、範囲を選択 (Ctrl+E、EDIT-04) の「矩形として選択」、コマンドパレット「矩形選択を開始」 |

**概要**: 表示上の行と列で囲まれた長方形の範囲を選択する。固定長レコードの同じフィールドだけを選ぶときに使う。

**仕様**:

1. 矩形選択は「開始行・終了行・開始列・終了列」で表す。列は行の先頭からのバイト位置 (0 〜 1 行のバイト数 − 1)。
2. Alt+ドラッグ: 押した位置と現在の位置を対角とする長方形を選択する。Alt+Shift+矢印: アンカーを対角の一方にして、カーソルを動かして長方形を広げる。キーボードだけで行数の多い矩形を作る場合は、範囲を選択 (Ctrl+E) で開始と終了を入力し、「矩形として選択」をオンにする (EDIT-04)。
3. 選択されるのは、各行の開始列から終了列までのバイト。最終行で終了列のバイトが存在しない場合 (ファイル末尾) は、存在する分だけを選択する。
4. ステータスバーには「矩形 R 行 × C バイト (計 N バイト)」と表示する。
5. 1 行のバイト数を変更した場合や、オフセットの開始位置を変えた場合、矩形選択は同じバイトを指すマルチ選択 (行ごとに 1 要素) に変換する。変換で要素数が上限 (EDIT-07) を超える場合は選択を解除し、InfoBar で知らせる。
6. 矩形選択でできる操作: コピー (EDIT-22)、形式を選択してコピー (EDIT-25)、切り取り・削除・貼り付け・挿入 (EDIT-17)、塗りつぶし (EDIT-29)、データ演算 (EDIT-31〜36)、ハッシュ (06)、マルチ選択への変換。
7. 「マルチ選択に変換」コマンド (既定なし) で、行ごとに 1 要素のマルチ選択に変換する。

**画面**: 長方形の領域を Hex 列・テキスト列の両方で選択色で塗る。

**巨大ファイル・長時間処理**: 矩形選択自体は 4 つの数値で持ち、行数に関係なく一定時間で作れる。100 GB のファイル全体の行にわたる矩形も選択できる。行ごとの処理が必要な操作は EDIT-17 の上限に従う。

**エラー**: マルチ選択への変換で上限を超えた場合は InfoBar 「矩形の行数 (N 行) がマルチ選択の上限 (M) を超えるため変換できません」。

**受け入れ基準**:

- [ ] 16 バイト / 行の表示で、0x04 から Alt+ドラッグで 3 行下の列 7 まで選択すると、0x04〜0x07、0x14〜0x17、0x24〜0x27、0x34〜0x37 の 16 バイトが選択される。
- [ ] その状態でコピーすると 16 バイトが行順に連結されてクリップボードに入る。
- [ ] 1 行のバイト数を 8 に変えると、同じ 16 バイトを指す 4 要素のマルチ選択に変わる。
- [ ] 100 GB のファイル全体にわたる矩形選択を作ってもメモリ使用量が増えない (矩形は Alt+ドラッグの自動スクロール、または範囲を選択 (Ctrl+E) の「矩形として選択」で作る)。

### EDIT-07 マルチ選択

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-12 |
| 呼び出し | Ctrl+ドラッグ / Ctrl+Shift+クリック (範囲をマルチ選択に追加。00-overview.md 8.3)、範囲を選択 (Ctrl+E) の「現在の選択に追加」、検索結果一覧の「選択に変換」(04)、編集 > 選択 > 「選択を反転」「重なった要素を結合」「要素を個別に処理」、コマンドパレット |

**概要**: 離れた複数の範囲を同時に選択し、コピー・削除・塗りつぶし・データ演算などを一度に行う。

**仕様**:

1. マルチ選択は、重ならない要素 (開始, 長さ) をオフセット順に並べた集合とする。要素を追加したときに既存の要素と重なる、または隣接する場合は 1 つに結合する。
2. Ctrl+ドラッグで新しい要素を追加する。既に選択されている範囲の中で Ctrl+クリックすると、その要素を取り除く。
3. 要素数の上限は既定 1,000,000 (設定で 1,000〜10,000,000)。上限を超える追加は行わず、InfoBar で知らせる。
4. 「選択を反転」: ドキュメント全体のうち、現在選択されていない範囲を選択する。
5. ステータスバーには「N 個の範囲、計 M バイト」と表示する。主要素 (最後に追加した要素) の開始・終了 (このバイトを含む) も表示する。
6. 「次の要素へ」「前の要素へ」(既定なし) で、主要素を切り替えてその位置へスクロールする。
7. マルチ選択に対する操作の扱い:

   | 操作 | 振る舞い |
   | --- | --- |
   | コピー | 要素をオフセット順に連結する。形式を選択してコピー (EDIT-25) では「要素ごとに分ける」を選べる |
   | 切り取り・削除 | すべての要素を削除する。1 つの編集グループ |
   | 貼り付け | クリップボードの内容が同じ数の要素を持つ (マルチ選択からコピーした) 場合は、各要素に対応する部分を貼る。それ以外は同じ内容を各要素に貼る |
   | 入力 | 各要素の先頭にカーソルを置いたマルチカーソル (EDIT-08) として扱う |
   | 塗りつぶし・データ演算・文字コード変換 | 各要素に個別に適用する。1 つの編集グループ |
   | 検索 | 「選択範囲内を検索」は要素ごとに検索する (04) |
   | ハッシュ | 要素を連結したデータに対して計算する (06) |

8. 長さが変わる編集を複数要素に行った場合、後ろの要素の位置はずれた分だけ自動で調整する (編集はオフセットの大きい要素から順に行う)。
9. 要素は追加したときに常に結合し (仕様 1)、操作は常に要素ごとに行う (仕様 7) ため、「呼び出し」の「重なった要素を結合」「要素を個別に処理」はコマンドとしては設けない (常にその動作になる)。

**画面**: 各要素を選択色で塗る。主要素は枠線を太くする (色だけで区別しない)。

**巨大ファイル・長時間処理**: 要素は平衡木で持ち、追加・削除・位置の検索は O(log 要素数)。描画は見えている要素だけ。要素数に比例する操作 (削除、反転、塗りつぶし) は、要素数が 10,000 を超える場合に長時間処理として実行する。データエンジンへの操作は要素数ぶんのピース操作になり、データ量には比例しない。

**エラー**: 上限超過は InfoBar。長さが変わる操作を固定長ドキュメントで行おうとした場合は共通の約束 4 に従う。

**受け入れ基準**:

- [ ] Ctrl+ドラッグで 3 つの範囲を選び、Delete で 3 つとも削除され、Ctrl+Z 1 回で 3 つとも戻る。
- [ ] 重なる範囲を Ctrl+ドラッグで追加すると 1 つの要素に結合される。
- [ ] すべて検索で 100,000 件見つけた結果を選択に変換し、00 で塗りつぶしても UI が固まらず、進捗が表示される。
- [ ] 「選択を反転」を 2 回実行すると元の選択に戻る。

### EDIT-08 マルチカーソル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-12 (マルチカーソルはこの項目に含めて実装する) |
| 呼び出し | Alt+クリック (カーソルを追加)、Ctrl+Alt+↑ / ↓ (カーソルを上 / 下の行に追加)、Esc (主カーソルだけに戻す)、コマンドパレット「選択範囲の各要素にカーソルを置く」 |

**概要**: 複数の位置にカーソルを置き、同じ入力を同時に行う。

**仕様**:

1. Alt+クリックで、クリックした位置にカーソルを追加する。既にカーソルがある位置を Alt+クリックするとそのカーソルを取り除く (最後の 1 つは取り除かない)。
2. Ctrl+Alt+↑ / ↓ は、主カーソルと同じ列の上 / 下の行にカーソルを追加する。
3. カーソル数の上限は 10,000。超える追加は行わず InfoBar で知らせる。
4. 入力 (Hex 列・テキスト列)、Delete、Backspace、貼り付け、移動キー、Shift+移動キー (各カーソルが自分の選択範囲を持つ) はすべてのカーソルに同時に適用する。
5. 挿入モードで入力した場合、後ろのカーソルの位置は入力したバイト数だけずれる。
6. すべてのカーソルへの 1 回の入力は 1 つの編集として記録し、入力のまとめ (EDIT-19) の規則に従って編集グループにする。
7. 2 つのカーソルが同じ位置に重なった場合は 1 つにまとめる。
8. ステータスバーには「N 個のカーソル」と主カーソルの位置を表示する。

**画面**: 主カーソルは通常のカーソル、それ以外は細いカーソルで表示する。

**巨大ファイル・長時間処理**: カーソル数の上限 10,000 で、1 回の入力が 50 ms 以内に画面に反映されること。

**エラー**: いずれかのカーソルが入力できない位置 (固定長ドキュメントの末尾位置など) にある場合は、そのカーソルへの入力だけを行わず、InfoBar で「N 個のカーソルで入力できませんでした」と示す。

**受け入れ基準**:

- [ ] Ctrl+Alt+↓ を 3 回押して 4 行に縦にカーソルを並べ、Hex 列で `FF` と入力すると 4 か所が FF になる。
- [ ] 上記の入力が Ctrl+Z 1 回で戻る。
- [ ] 挿入モードで 2 つのカーソルから入力したとき、2 つめのカーソルの位置が正しくずれる。

### EDIT-09 選択範囲の保存と読み込み

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 編集 > 選択 > 「選択範囲を保存…」「保存した選択範囲を読み込む…」「選択範囲をエクスポート…」「選択範囲をインポート…」。ショートカットは既定なし |

**概要**: 現在の選択 (単一・マルチ・矩形) に名前を付けて保存し、後で選択し直す。ファイルへのエクスポートもできる。

**仕様**:

1. 保存先はドキュメントに付随するデータ (00-overview.md 10 章) の「選択セット」。名前は 1〜100 文字、ドキュメント内で一意。同じ名前で保存すると確認の上で上書きする。
2. 選択セットは要素 (開始, 長さ) の一覧として保存する。矩形選択は矩形として (行・列とその時点の 1 行のバイト数を含めて) 保存する。
3. 読み込むときは「置き換える」(既定) / 「現在の選択に追加」を選べる。
4. ドキュメントの長さより後ろを指す要素は、読み込み時に切り詰めるか除外し、InfoBar で件数を知らせる。
5. 編集でデータがずれても、保存済みの選択セットのオフセットは自動では調整しない (ブックマーク (05) と異なる)。この違いを読み込みダイアログに注記する。
6. エクスポート形式: CSV (1 行目は見出し `start,length`、2 行目から 1 要素 1 行。値は常に `0x` 付きの 16 進 (英字は大文字、先頭の 0 は詰めない) で書く。例: `0x10,0x4`)、JSON (`{"name": "...", "ranges": [{"start": 256, "length": 16}]}`)。インポートは同じ 2 形式と、1 行に「開始 長さ」または「開始-終了」(終了はそのバイトを含む) を書いたテキストを受け付ける。インポートでは、CSV とテキストの値は `0x` 付きの 16 進と 10 進のどちらも受け付ける (`0x` のない値は 10 進)。エラーの行番号は見出しの行を 1 行目として数える。
7. 選択セットは 1 ドキュメントあたり 100 個まで。

**画面**: 「保存」は名前入力ダイアログ。「読み込む」は選択セットの一覧 (名前、要素数、合計バイト数、保存日時) と削除・名前変更ボタンを持つダイアログ。

**巨大ファイル・長時間処理**: 要素数 1,000,000 の選択セットの保存・読み込みは長時間処理として行う (進捗とキャンセル)。

**エラー**: ファイルの書式エラーは「N 行目: 開始が数値ではありません」のように行番号を示し、読み込まない。

**受け入れ基準**:

- [ ] 3 要素のマルチ選択を保存し、選択を解除してから読み込むと同じ 3 要素が選択される。
- [ ] アプリを再起動した後も選択セットが残っている。
- [ ] CSV にエクスポートしてインポートすると同じ選択になる。

### EDIT-10 上書きモードと挿入モード

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-05 |
| 呼び出し | Insert (切り替え)、編集 > 上書き / 挿入の切り替え、ステータスバーのモード表示をクリック、コマンドパレット「上書き / 挿入の切り替え」 |

**概要**: 入力したバイトで既存のバイトを置き換えるか、カーソル位置に挿入するかを切り替える。

**仕様**:

1. モードはタブ (ドキュメント) ごとに持つ。新しく開いたドキュメントのモードは設定「既定の入力モード」(既定は上書き) に従う。
2. 固定長ドキュメントは常に上書きモード。Insert を押すと InfoBar で「このドキュメントは長さを変えられないため、挿入モードにできません」と示す。
3. モードはステータスバーに「上書き」「挿入」の文字で表示する。カーソルの形も変える (上書き: ブロック、挿入: 縦線)。色だけで区別しない。
4. 末尾位置での入力は、どちらのモードでも追加 (ドキュメントを長くする) になる。固定長ドキュメントでは末尾位置での入力はできない。
5. モードが影響する操作: Hex 列・テキスト列の入力 (EDIT-11、EDIT-12)、Backspace (EDIT-13)、貼り付け (Ctrl+V。EDIT-23)。上書き貼り付け (Ctrl+B) はモードに関係なく上書きする。
6. モードの切り替えは編集履歴に記録しない。
7. 切り替え時にスクリーンリーダーへ「挿入モード」「上書きモード」を通知する。

**画面**: ステータスバーのモード表示 (ボタン)。カーソルの形。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 固定長ドキュメントでの切り替えは上記 2。

**受け入れ基準**:

- [ ] Insert を押すとステータスバーとカーソルの形が変わる。
- [ ] 物理ディスクを開いたタブでは Insert を押しても上書きモードのまま InfoBar が出る。
- [ ] 2 つのタブでモードを別々に保てる。

### EDIT-11 Hex 列での入力

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-05 |
| 呼び出し | Hex 列にフォーカスがある状態で 0〜9、A〜F (大文字・小文字) を入力 |

**概要**: Hex 列ではニブル (4 bit) 単位で値を入力する。

**仕様**:

1. 上書きモード: カーソルが上位ニブルにあるとき、入力した桁でそのバイトの上位ニブルを置き換え、カーソルを下位ニブルに移す。下位ニブルにあるときは下位ニブルを置き換え、カーソルを次のバイトの上位ニブルに移す。
2. 挿入モード: カーソルが上位ニブルにあるとき、新しいバイト (値 = 入力した桁 × 16) をカーソル位置に挿入し、カーソルをそのバイトの下位ニブルに移す。続けて入力した桁で下位ニブルを置き換え、次のバイトの上位ニブルに移す。下位ニブルにカーソルがある状態 (矢印キーで移動した場合) で入力した場合は、上書きモードと同じく下位ニブルを置き換える。
3. 選択範囲がある状態で入力した場合: 挿入モードでは選択範囲を削除してから入力を始める。上書きモードでは選択範囲の先頭から上書きを始め、選択を解除する (選択範囲を削除しない)。上書きモードで選択範囲を削除せずに入力することは設定「上書きモードで選択範囲に入力したとき: 先頭から上書き (既定) / 選択範囲を 00 にしてから上書き」で変えられる。
4. 16 進数字以外のキーは無視する。音は鳴らさない。
5. 全角の `０`〜`９`、`Ａ`〜`Ｆ`、`ａ`〜`ｆ` は半角に変換して受け付ける (IME がオンのまま Hex 列に入力した場合のため)。IME の変換中の文字列は確定してから 1 文字ずつ処理する。Hex 列にフォーカスが移ったときは IME を自動的にオフにしない (利用者の IME 状態を変えない)。
6. セルの表示形式 (02) が Hex 以外の場合の入力:

   | 表示形式 | 入力 |
   | --- | --- |
   | 10 進 (000〜255) | 3 桁の 10 進数字で 1 バイト。3 桁目で確定して次のバイトへ。255 を超える場合は入力した桁を受け付けず、セルを赤枠で 1 秒示す |
   | 8 進 (000〜377) | 3 桁の 8 進数字で 1 バイト。8 と 9 は無視する |
   | 2 進 (8 桁) | 0 と 1 の 8 桁で 1 バイト。1 桁ごとに該当するビットを置き換える |
   | 多バイトの数値 (int16 / float など) | セルでの直接入力はできない。Enter でそのセルの値を編集するポップアップを開く (データインスペクタ (05) と同じ入力規則) |

7. 入力したバイトは「変更されたバイト」として強調表示する (02)。
8. 入力ごとに、スクリーンリーダーへ「オフセット 0x…、値 0x…」を通知する (設定でオフにできる。09 の UI-51 の「読み上げの詳しさ」を「読み上げない」にする)。

**画面**: カーソルは現在のニブルの 1 文字を反転表示する。

**巨大ファイル・長時間処理**: 1 回の入力はデータエンジンの 1 バイトの置き換えまたは挿入で、ファイルサイズに関係なく 50 ms 以内に画面に反映する。

**エラー**: 読み取り専用 (EDIT-16)、固定長ドキュメントの末尾位置での入力 (共通の約束 4)。

**受け入れ基準**:

- [ ] 上書きモードで `4` `1` と入力するとカーソル位置のバイトが 0x41 になり、カーソルが次のバイトの上位ニブルに移る。
- [ ] 挿入モードで `7` を入力した直後、ファイル長が 1 増え、新しいバイトの値が 0x70 になっている。続けて `F` で 0x7F になる。
- [ ] `G` や `-` を押してもデータが変わらない。
- [ ] 日本語 IME をオンにしたまま `ａｂ` と入力・確定すると 0xAB になる。
- [ ] 100 GB のファイルの中央で挿入モードの入力をしても 50 ms 以内に表示が変わる。

### EDIT-12 テキスト列での入力

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-05 |
| 呼び出し | テキスト列にフォーカスがある状態で文字を入力 (キーボード、IME、デッドキー、絵文字パネル Win+.) |

**概要**: テキスト列では、入力した文字を現在の文字コード (02 / 09 の表示文字コード) でバイト列に変換して書き込む。

**仕様**:

1. 文字入力は TSF (Windows.UI.Text.Core の `CoreTextEditContext`) で受け取る。キーダウンイベントから文字を作らない (デッドキー・IME・絵文字パネルを正しく扱うため)。
2. IME の変換中の文字列は、カーソル位置に重ねて下線付きで表示するだけで、確定するまでデータを変えない (00-overview.md 5.4)。変換候補ウィンドウはカーソル位置の近くに出す。
3. 確定した文字列を現在の文字コードで変換し、得られたバイト列を、上書きモードでは上書き、挿入モードでは挿入する。上書きモードでは、変換後のバイト数だけ既存のバイトを置き換える (文字境界は考慮しない。例: UTF-8 で `あ` を入力すると、元の文字に関係なく 3 バイトを置き換える)。
4. 現在の文字コードで表せない文字が含まれる場合は、何も書き込まず、InfoBar で「『…』は Shift_JIS で表せません」と示す。最善の近似文字への置き換え (best fit) は行わない。
5. UTF-16 / UTF-32 では、BOM を付けずにその文字のコード単位だけを書き込む。エンディアンは文字コードの指定 (LE / BE) に従う。サロゲートペアの文字は 4 バイトで書く。
6. 結合文字 (タイ語の母音記号、ベトナム語の声調記号など) は、確定した単位で書き込む。テキスト列の表示は、書き込んだ後に文字コードで再解釈して表示する。
7. Enter キーの扱い: 設定「テキスト列での Enter: 何もしない (既定) / CR LF / LF / CR を書き込む」。Tab キーは列の切り替え (00-overview.md 8 章) に使うため、タブ文字は書き込まない。タブ文字は「形式を選択して貼り付け」や塗りつぶしで入れる。
8. 選択範囲がある状態での入力は EDIT-11 の 3 と同じ。
9. カーソルはバイト単位で動く。多バイト文字の途中のバイトにカーソルがある状態でも入力できる。
10. マルチカーソルでの IME 入力は、確定した文字列を全カーソルに書き込む。変換中の表示は主カーソルの位置だけに出す。

**画面**: IME の変換中文字列の表示 (下線)。表せない文字の InfoBar。

**巨大ファイル・長時間処理**: EDIT-11 と同じ。1 回の確定で書き込むバイト数は、IME の確定文字列の長さで、上限は設けない (通常は数百バイト以下)。

**エラー**: 表せない文字 (上記 4)、読み取り専用、固定長ドキュメントでの挿入。

**受け入れ基準**:

- [ ] 文字コード UTF-8、挿入モードで日本語 IME から `日本` と入力・確定すると `E6 97 A5 E6 9C AC` が挿入される。変換中はファイル長が変わらない。
- [ ] 文字コード Shift_JIS、上書きモードで `日` を確定すると `93 FA` の 2 バイトが上書きされる。
- [ ] 文字コード ASCII で `é` を入力すると何も書き込まれず InfoBar が出る。
- [ ] フランス語配列のデッドキー (`^` → `e`) で `ê` が 1 文字として書き込まれる。
- [ ] 文字コード UTF-16 LE で絵文字 (U+1F600) を入力すると `3D D8 00 DE` が書き込まれる。
- [ ] 文字コード UTF-8、挿入モードで、中国語 (ピンイン)、韓国語、タイ語、ベトナム語の入力方式から入力すると、変換中はファイル長が変わらず、確定した文字列を UTF-8 にしたバイト列がそのまま挿入される。例: ピンインの `中文` で `E4 B8 AD E6 96 87`、韓国語の `한` で `ED 95 9C`、タイ語の `ดี` で `E0 B8 94 E0 B8 B5` (テキスト列では 1 文字として表示)、ベトナム語 (Telex) の `Việt` に続く空白で、入力方式が NFC で確定した場合は `56 69 E1 BB 87 74 20` (正規化はせず、確定した単位のまま書く。仕様 6)。

### EDIT-13 削除

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-05 |
| 呼び出し | Delete、Backspace、編集 > 削除、右クリックメニュー「削除」、コマンドパレット「削除」 |

**概要**: 選択範囲、またはカーソル位置のバイトを削除する。

**仕様**:

1. 選択範囲がある場合: Delete と Backspace はどちらも選択範囲を削除する (ドキュメントが短くなる)。カーソルは削除した範囲の先頭に置く。
2. 選択範囲がない場合の Delete: カーソル位置の 1 バイトを削除する。末尾位置では何もしない。Hex 列でカーソルが下位ニブルにある場合も、そのバイト全体を削除する。
3. 選択範囲がない場合の Backspace:
   - 挿入モード: カーソルの直前の 1 バイトを削除し、カーソルを 1 バイト戻す。Hex 列で、挿入モードで上位ニブルだけ入力した直後 (下位ニブルにカーソルがある) の場合は、その入力中のバイトを削除する。
   - 上書きモード: データを変えずにカーソルを 1 つ前に戻す (Hex 列ではニブル単位、テキスト列ではバイト単位)。設定「上書きモードの Backspace: カーソルを戻す (既定) / 直前のバイトを 00 にして戻る」。
4. 上書きモードでも Delete は削除 (長さが変わる) を行う。設定「上書きモードでは Delete で長さを変えない」をオンにすると、上書きモードの Delete は選択範囲 (またはカーソル位置のバイト) を 00 で塗りつぶす。
5. 固定長ドキュメントでは、Delete と Backspace による削除は行わない。InfoBar で「このドキュメントは長さを変えられません」と示し、「00 で塗りつぶす」ボタンを付ける。
6. 削除したバイト数をスクリーンリーダーに通知する。
7. 連続した Delete / Backspace は、入力のまとめ (EDIT-19) の規則で 1 つの編集グループにまとめる。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: 削除はデータエンジンのピース操作で、削除するバイト数に関係なく 100 ms 以内 (00-overview.md 11.1)。50 GB の選択範囲の削除も同じ。

**エラー**: 読み取り専用、固定長ドキュメント (上記 5)。

**受け入れ基準**:

- [ ] 50 GB を選択して Delete を押すと 100 ms 以内に完了し、Ctrl+Z で 100 ms 以内に戻る。
- [ ] 挿入モードで Backspace を押すと直前のバイトが削除される。上書きモードではデータが変わらずカーソルが戻る。
- [ ] 物理ディスクのタブで Delete を押すとデータが変わらず InfoBar が出て、「00 で塗りつぶす」で塗りつぶせる。

- [ ] 位置 0x10 にバイト数 `1T`、内容 `00` を挿入すると 100 ms 以内に完了し、ファイル長が 1 TiB 増える。メモリ使用量はほぼ増えない。

### EDIT-15 ファイルサイズの変更と切り詰め

### EDIT-16 読み取り専用モードと編集の保護

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-23 |
| 呼び出し | 編集 > 読み取り専用 (チェック項目)、ステータスバーの鍵アイコンをクリック、コマンドパレット「読み取り専用の切り替え」。ショートカットは既定なし |

**概要**: ドキュメント単位でデータを変える操作を禁止する。読み取り専用モードの切り替えと編集の保護はこの項目が主担当である (00-overview.md 1.1)。どの場合に読み取り専用で開くか・書き込めないデータソースの扱いは ENG-14、書き込み保護モードによる強制は FOR-01 で定める。

**仕様**:

1. 読み取り専用はタブ (ドキュメント) ごとの状態。読み取り専用で開く条件 (「読み取り専用で開く」の指定、書き込み権限がない、読み取り専用属性、共有違反、ディスク・ボリューム・プロセスメモリの既定、書き戻す先のないデータソースなど) は ENG-14 に従う。書き込み保護モード (FOR-01) が有効な間は、すべてのドキュメントを読み取り専用として扱う (FOR-01 でドキュメント単位の例外を設定したドキュメントを除く)。
2. 読み取り専用のとき、データを変えるコマンド (入力、削除、貼り付け、切り取り、置換、塗りつぶし、データ演算、変換、パッチの適用、ファイルサイズの変更、スクリプトからの書き込み、元に戻す / やり直し、保存) はメニューで無効にする。コピー、検索、選択、ブックマーク、比較などデータを変えない操作はそのまま使える。再読み込み・変更を破棄して再読み込み (ENG-18) と外部変更による再読み込み (ENG-19) は、データソースに書かずにその今の内容に戻す操作のため、読み取り専用でも使える (他のアプリが書き換えたファイルを表示し直せる)。外部変更とのマージ (ENG-19) は自分の変更を適用し直す編集のため、読み取り専用では使えない。
3. 読み取り専用のときにキー入力・貼り付けなどデータを変える操作をした場合、データを変えずに InfoBar 「このドキュメントは読み取り専用です」を出す。InfoBar には「編集を許可する」ボタンを付ける。InfoBar が表示中の間は、同じ通知を重ねて出さない。
4. 「編集を許可する」/ 読み取り専用の解除:
   - 利用者の選択で読み取り専用にしていた場合は、そのまま解除する。
   - 権限・属性・共有違反が原因の場合、ディスク・ボリューム・プロセスメモリの場合は、ENG-14 の解除の処理 (書き込みで開き直す、確認ダイアログ) に従う。失敗した場合は理由を示して読み取り専用のままにする。
   - 書き戻す先のないデータソース (ENG-14) と、書き込み保護モード (FOR-01) が有効な場合は解除できない (ボタンを出さない)。
5. 編集中 (未保存の変更がある状態) に読み取り専用にした場合、未保存の変更は保持し、保存と追加の編集だけを禁止する。
6. ステータスバーに鍵アイコンと「読み取り専用」の文字を表示する。タブの見出しにも鍵アイコンを付ける。

**画面**: ステータスバーの表示、タブのアイコン、InfoBar。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 開き直しの失敗 (上記 4)。

**受け入れ基準**:

- [ ] 読み取り専用のタブで Hex 列に入力するとデータが変わらず InfoBar が 1 つだけ出る。
- [ ] 読み取り専用のタブでコピーと検索ができる。
- [ ] 読み取り専用属性のファイルを開いて「編集を許可する」を選ぶと確認ダイアログが出て、承認すると編集できる。
- [ ] 書き込み保護モードでは「編集を許可する」ボタンが出ない。

### EDIT-17 矩形範囲の編集

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-15 |
| 呼び出し | 矩形選択中のコピー・切り取り・貼り付け・Delete・入力・バイトの挿入 (EDIT-14)、コマンドパレット「矩形挿入」 |

2. コピー: クリップボードには、行を連結したバイナリと、行ごとに改行で区切った Hex テキストを入れる。さらに「矩形の情報」(行数・各行のバイト数) をアプリ独自形式で入れる。

**巨大ファイル・長時間処理**: 長さが変わる操作は行数ぶんのピース操作 (O(行数 × log ピース数)) になるため、10,000 行を超える場合は長時間処理として実行する。上書きする操作のうち塗りつぶしは行数ぶんの塗りつぶしピースで表す。データ演算は選択バイト数に比例する長時間処理 (EDIT-31)。

**エラー**: 行数の上限を超えた場合は実行せず「矩形が N 行あり、上限 M 行を超えています。上書きの操作は使えます」と示す。

**受け入れ基準**:

- [ ] 4 行 × 2 バイトの矩形を削除すると 8 バイト減り、Ctrl+Z 1 回で戻る。
- [ ] 4 行 × 2 バイトの矩形をコピーし、別の位置で Ctrl+B を押すと、同じ形で 4 行に上書きされる。
- [ ] 2,000,000 行の矩形を Delete しようとすると実行されずメッセージが出る (矩形は Alt+ドラッグ、または範囲を選択 (Ctrl+E) の「矩形として選択」で作る。EDIT-06)。

### EDIT-18 選択範囲のドラッグ & ドロップ

7. 固定長ドキュメントでは移動・挿入はできず、Shift による上書きだけを受け付ける。
8. ドラッグ中は Esc で中止できる。

**画面**: ドラッグ中は挿入位置に縦線を表示し、ポインタに「移動」「コピー」「上書き」の表示を付ける。

**巨大ファイル・長時間処理**: 同じドキュメント内・他のタブへの移動とコピーはピースの参照で行い、データ量に関係なく 100 ms 以内。

**エラー**: 読み取り専用のドキュメントへのドロップは受け付けない (ポインタを禁止の形にする)。

**受け入れ基準**:

- [ ] 0x00〜0x0F を選択して 0x40 にドラッグすると、16 バイトが移動し、Ctrl+Z 1 回で元に戻る。
- [ ] Ctrl を押しながらドロップするとコピーになる。
- [ ] 10 GB の選択範囲を同じファイル内で移動しても 100 ms 以内に完了する。
- [ ] 選択範囲の内側にドロップしようとすると禁止の形のポインタになる。

## 3. 元に戻す / やり直し

### EDIT-19 元に戻す・やり直し

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-06 |
| 呼び出し | 編集 > 元に戻す (Ctrl+Z)、編集 > やり直し (Ctrl+Y / Ctrl+Shift+Z)、ツールバーのボタン、コマンドパレット「元に戻す」「やり直し」 |

**概要**: ドキュメントへのすべての編集を、回数の制限なく元に戻し、やり直す。メモリ使用量はファイルサイズに比例しない。

**仕様**:

1. 履歴はドキュメントごとに持つ。対象はデータを変えるすべての操作 (入力、削除、挿入、貼り付け、塗りつぶし、データ演算、変換、パッチの適用、ファイルサイズの変更、データインスペクタ・テンプレートからの値の書き換え、スクリプトによる編集)。
2. 次は履歴に記録しない: 選択・カーソル移動、表示設定、ブックマーク・色付け (05 で別の履歴を持つ)、上書き / 挿入の切り替え、読み取り専用の切り替え。
3. 履歴の各項目 (編集グループ) は、データエンジンのピースツリーの「その時点のルート」への参照と、元に戻した後に復元する選択範囲・カーソル位置を持つ (feature-survey.md 3.2 の永続データ構造)。元に戻す・やり直しは、ルートを差し替えるだけで行い、データ量に関係なく 100 ms 以内に完了する。
4. 回数の上限は設けない。
5. 入力のまとめ: 連続した入力 (Hex 列・テキスト列の文字入力、連続した Delete、連続した Backspace) は、次のいずれかが起きるまで 1 つの編集グループにまとめる。
   - 入力位置が直前の入力の続きでなくなった (カーソルの移動、クリック)
   - 入力の種類が変わった (文字入力から Delete へ、など)
   - 入力モードを切り替えた
   - 直前の入力から 2 秒以上たった (設定で 0〜10 秒。0 はまとめない)
   - 1 グループのバイト数が 4 KiB を超えた
   - 他のコマンドを実行した、または保存した
6. 1 つのコマンド (貼り付け、塗りつぶし、データ演算、マルチ選択への削除など) は、内部で多数のピース操作をしても 1 つの編集グループにする。
7. スクリプト (08) は API で編集グループの開始・終了を指定できる。指定しない場合はスクリプト 1 回の実行を 1 グループにする。
8. 新しい編集をしたとき、やり直しできる履歴 (元に戻した先の編集) は捨てる。分岐する履歴 (EDIT-21) を有効にしている場合は捨てずに枝として残す。
9. 保存と履歴:
   - 保存しても履歴は消さない。保存した時点を「保存点」として記録し、保存点の状態にいるときは「変更なし」と表示する。元に戻して保存点から離れると再び「変更あり」になる。
   - 設定「保存時に履歴を消す」(既定オフ) をオンにすると、保存のたびに履歴を消す。
   - 保存で元ファイルが置き換わった後も過去の状態に戻れるよう、データエンジンは保存前の元データのうち履歴から参照されている部分を保持する (具体的な方法は ENG で定める)。保持に必要な一時領域が足りない場合は、保存の前に確認ダイアログで「保存すると、保存より前の状態に戻せなくなります」と示し、「保存して履歴を消す」「キャンセル」を選ばせる。
   - 固定長ドキュメント (ディスク・プロセスメモリ) で保存 (書き込み) した後に元に戻すと、ドキュメントは「変更あり」になり、もう一度書き込むまで対象には反映しない。
10. 元に戻す・やり直しをすると、その編集グループの範囲を選択し、見える位置にスクロールする。
11. メニューの項目名には対象の操作名を入れる (例: 「元に戻す: 塗りつぶし」「やり直し: 入力」)。
12. ドキュメントを閉じると履歴は破棄する (分岐する履歴の保存 (EDIT-21) を除く)。異常終了からの復旧 (00-overview.md 11.3) では、復旧した時点の内容を新しい履歴の起点とし、復旧前の履歴は戻さない。

**画面**: ツールバーの「元に戻す」「やり直し」ボタン。ボタンのツールチップに操作名を表示する。

**巨大ファイル・長時間処理**:

1. 履歴の各項目はピースツリーのルート参照なので、1 項目のメモリはその編集で変わったピースの数に比例し、データ量には比例しない (100 GB の削除も数百バイト)。
2. 編集で作った追加データ (入力したバイト、演算結果など) は、メモリ上限 (00-overview.md 11.2、既定 1 GB) を超える分を一時ファイルに退避する。履歴から参照されている追加データは、履歴が残っている間は消さない。
3. 履歴のメタデータ (ピースツリーのノード) の合計が設定「履歴に使うメモリ」(既定 256 MB、メモリ上限の内数) を超えた場合は、古い項目のノードを一時ファイルに退避する。退避した項目への元に戻すは、読み戻しのため 1 秒程度かかってよい。
4. 一時ファイルの置き場所 (既定は `%TEMP%`。設定で変更可) の空き容量が 1 GB を下回った場合、InfoBar で「一時領域が不足しています。古い履歴を消して容量を空けますか」と示し、「古い履歴を消す」(最も古い項目から。消す量を選べる)、「一時フォルダを変更」ボタンを付ける。利用者が選ぶまで履歴は自動では消さない。空き容量がなくなり編集を記録できない場合は、その編集を実行せずにエラーにする。

**エラー**: 一時領域の不足 (上記)。元に戻す対象がない場合はコマンドを無効にする。

**受け入れ基準**:

- [ ] 100 GB のファイルで、10 GB の削除、1 TB の挿入、1 バイトの書き換えを行い、すべて元に戻し、すべてやり直せる。各操作は 100 ms 以内。
- [ ] 10,000 回の 1 バイト書き換えを行っても、メモリ使用量の増加が 100 MB 以下である。
- [ ] `ABCD` と続けて入力した後 Ctrl+Z を 1 回押すと 4 文字すべてが戻る。2 秒以上空けて入力した場合は 2 回に分かれる。
- [ ] 保存した後に Ctrl+Z を押すと「変更あり」になり、Ctrl+Y で「変更なし」に戻る。
- [ ] メニューに「元に戻す: 塗りつぶし」のように操作名が表示される。

### EDIT-20 履歴パネル

**概要**: 編集履歴を一覧で表示し、任意の時点へ一度に戻る・進む。

**仕様**:

1. 一覧の各行: 番号、操作名、対象範囲 (開始・長さ)、長さの変化 (+N / −N)、日時。保存点の行には「保存」の印を付ける。

- [ ] 5 回編集した後、1 番目の行をダブルクリックすると 1 番目の編集の直後の状態になり、Ctrl+Y で 2 番目の編集がやり直される。
- [ ] 保存点の行に印が付いている。

### EDIT-21 分岐する Undo 履歴

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-02 |
| 呼び出し | 履歴パネル (EDIT-20) の「木で表示」切り替え、設定「分岐する履歴を使う」(既定オフ。フェーズ 4 で既定をオンにするかは未決定)、コマンドパレット「履歴を保存」「履歴を読み込む」「履歴の節へ移動」 |

**概要**: 元に戻した後に新しい編集をしても、やり直しの履歴を捨てずに枝として残す。履歴を木で表示し、名前付け・固定・保存・読み込みができる。

**仕様**:

1. 元に戻した状態で新しい編集をすると、新しい枝を作る。それまでのやり直し履歴は別の枝として残る。
2. やり直し (Ctrl+Y) は、現在の枝 (最後に通った子) を進む。別の枝に移るには履歴パネルで目的の節をダブルクリックする。
3. 木の表示: 節は編集グループ。根は開いた時点の状態。保存点、名前付きの節、固定した節、現在の節を、アイコンと文字で区別する。木は縦方向に時系列で並べ、枝を横に分ける。
4. 名前付け: 節を右クリックして「名前を付ける」(1〜100 文字)。名前の付いた節は、コマンドパレット「履歴の節へ移動」で名前から選べる。
5. 固定 (ピン留め): 固定した節と、根からその節までの経路は、自動の整理 (下記 7) で消さない。
6. 節の削除: 現在の節とその祖先以外の節を、枝ごと削除できる。削除は元に戻せないため確認ダイアログを出す (「枝を削除」「キャンセル」)。
7. 自動の整理: 履歴の一時領域が不足したとき (EDIT-19 の巨大ファイルの項 4)、利用者の承認を得て、固定されておらず名前もない枝を古いものから削除する。
8. 履歴の保存: 履歴を `.hexhist` ファイル (zip 形式。中身は節の構造を表す JSON、各節の編集内容、追加データ) に書き出す。元ファイルの識別情報 (パス、長さ、更新日時、先頭・中央・末尾の各 1 MiB の SHA-256) を含める。全体の SHA-256 を含めるかを保存時に選べる (既定オフ。巨大ファイルでは時間がかかるため)。
9. 履歴の読み込み: 同じ元ファイルを開いた状態で読み込む。識別情報が一致しない場合は「元ファイルが変わっている可能性があります」と警告し、「読み込む」「キャンセル」を選ばせる。読み込んだ後は、保存時に現在だった節に移る。
10. 履歴は自動では保存しない。名前付きまたは固定した節がある状態でドキュメントを閉じるときは、確認ダイアログで「履歴を保存」「保存しないで閉じる」「キャンセル」を選ばせる。

**画面**: 履歴パネルの木の表示。節を選ぶと、その節での変更内容 (範囲、変更前後の先頭 16 バイト) をパネル下部に表示する。

**巨大ファイル・長時間処理**: 節の移動は一定時間。履歴の保存・読み込みは追加データの量に比例する長時間処理 (進捗とキャンセル)。書き出す推定サイズを保存前に表示する。

**エラー**: `.hexhist` の破損 (「履歴ファイルを読み込めません: 理由」)、識別情報の不一致 (上記 9)、書き出し先の容量不足 (保存前に確認)。

**受け入れ基準**:

- [ ] 編集 A、B を行い、B を元に戻して C を編集した後、履歴パネルで B の節を選ぶと B の状態になる。
- [ ] 名前を付けた節に、コマンドパレットから移動できる。
- [ ] 履歴を保存してアプリを再起動し、同じファイルを開いて読み込むと、同じ木が表示され、どの節にも移動できる。
- [ ] 別のファイルを開いた状態で読み込もうとすると警告が出る。

## 4. クリップボード

### EDIT-22 コピーと切り取り

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-07 |
| 呼び出し | 編集 > コピー (Ctrl+C)、編集 > 切り取り (Ctrl+X)、右クリックメニュー、コマンドパレット「コピー」「切り取り」、Ctrl+Insert (コピー)、Shift+Delete (切り取り) (00-overview.md 8.3) |

**概要**: 選択範囲のバイト列を、バイナリとテキストの両方の形式でクリップボードに入れる。切り取りはコピーした後に選択範囲を削除する。

**仕様**:

1. 選択範囲がない場合、コピー・切り取りは無効にする。
2. クリップボードに入れる形式:

   | 形式 | 内容 |
   | --- | --- |
   | アプリ独自形式 `HexEditor.Binary` | バイト列そのもの |
   | アプリ独自形式 `HexEditor.Meta` | JSON。アプリのインスタンス ID、コピーの通し番号、元ドキュメントの名前、開始オフセット、長さ、マルチ選択・矩形の構造 |
   | 他のエディタ互換の形式 | EDIT-27 で定める形式 |
   | テキスト (`CF_UNICODETEXT`) | アクティブな列が Hex 列なら Hex 文字列 (既定 `DE AD BE EF` の形。区切り・大文字小文字・改行を入れるバイト数は設定「コピーする Hex 文字列の書式」で変更可。既定は改行なし)。テキスト列なら現在の文字コードで解釈した文字列。解釈できないバイトと NUL は U+FFFD に置き換える |

3. 各形式のデータは遅延レンダリング (`DataPackage.SetDataProvider`) で作り、貼り付け先が要求したときに生成する。アプリの終了時には、上限以内の形式だけを実データにしてクリップボードに残す。
4. システムのクリップボードに入れる大きさの上限: 設定「クリップボードに入れる最大サイズ」(既定 64 MiB、範囲 1 MiB〜2 GiB)。バイナリ形式はバイト数、テキスト形式は生成後の文字数 × 2 バイトで判定する。
5. 選択範囲が上限を超える場合: システムのクリップボードには `HexEditor.Meta` と、テキスト形式として「[HexEditor: 12.3 GB のデータ。HexEditor 内でのみ貼り付けできます]」の 1 行だけを入れる。アプリ内では大きな範囲のアプリ内クリップボード (EDIT-24) で全データを貼り付けられる。InfoBar で「選択範囲 (12.3 GB) は大きすぎるため、他のアプリには渡せません。HexEditor 内では貼り付けられます」と示し、「ファイルに書き出す」ボタン (選択範囲の保存。11 の TOOL-16) を付ける。フェーズ 1 までは文だけを示し、ボタンは TOOL-16 (フェーズ 2) と同時に加えた。
6. テキスト形式だけが上限を超える場合 (バイナリは上限以内) は、テキスト形式を入れずにバイナリ形式だけを入れ、その旨を InfoBar で示す。
7. 切り取り: コピーが成功してから選択範囲を削除する (EDIT-13 と同じ)。固定長ドキュメントと読み取り専用のドキュメントでは切り取りを無効にする (コピーは使える)。
8. マルチ選択・矩形選択のコピーは EDIT-06、EDIT-07、EDIT-17 に従う。
9. クリップボードを開けない場合 (他のアプリが開いたままにしている) は、50 ms 間隔で最大 10 回試してから失敗にする。

**画面**: 該当なし (上限超過時の InfoBar のみ)。

**巨大ファイル・長時間処理**: コピー操作自体はピースの参照を記録するだけで、データ量に関係なく 100 ms 以内に完了する。システムのクリップボードへの実データの生成は貼り付け先が要求したときに行い、上限以内 (既定 64 MiB) のデータに限る。生成に 0.5 秒以上かかる場合は処理センターに進捗を表示する。

**エラー**: クリップボードを開けない (「クリップボードを使用できません。他のアプリが使用中の可能性があります」)。メモリ不足で生成できない場合は、そのテキスト形式を省いてバイナリ形式だけにする。

**受け入れ基準**:

- [ ] Hex 列で 4 バイトを選んでコピーし、メモ帳に貼り付けると `DE AD BE EF` の形のテキストになる。
- [ ] テキスト列から `Hello` の 5 バイトをコピーしてメモ帳に貼ると `Hello` になる。
- [ ] 10 GB を選択してコピーすると 100 ms 以内に完了し、InfoBar が出て、同じアプリの別タブに貼り付けられる。
- [ ] 1 MiB をコピーした直後にアプリを終了しても、メモ帳に貼り付けられる。
- [ ] 切り取りを Ctrl+Z で戻すと、データが戻り、クリップボードの内容は残っている。

### EDIT-23 貼り付けと上書き貼り付け

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-07 |
| 呼び出し | 編集 > 貼り付け (Ctrl+V)、編集 > 上書き貼り付け (Ctrl+B)、右クリックメニュー、コマンドパレット「貼り付け」「上書き貼り付け」「貼り付けて新しいタブで開く」、Shift+Insert (貼り付け) (00-overview.md 8.3) |

**概要**: クリップボードの内容をカーソル位置に貼り付ける。通常の貼り付けは現在の入力モードに従い、上書き貼り付けは常に上書きする。

**仕様**:

1. クリップボードから読む形式の優先順位: (1) システムのクリップボードの `HexEditor.Meta` がアプリ内クリップボード (EDIT-24) と一致する場合はアプリ内クリップボード、(2) `HexEditor.Binary`、(3) 他のエディタ互換の形式 (EDIT-27)、(4) エクスプローラーでコピーしたファイル (`CF_HDROP`。形式を選択して貼り付け (EDIT-26) のダイアログを「ファイルの内容」を選んだ状態で開く)、(5) テキスト。
2. テキストだけがある場合:
   - アクティブな列がテキスト列: テキストを現在の文字コードでバイト列に変換して貼る。表せない文字があれば EDIT-12 の 4 と同じく貼らずに InfoBar で示し、「形式を選択して貼り付け」ボタンを付ける。
   - アクティブな列が Hex 列: テキスト全体が Hex バイト列の入力 (00-overview.md 6.3。奇数桁は不可) として解釈できれば、そのバイト列を貼る。解釈できず、他の形式 (Base64、配列表記など。EDIT-26 の自動判別) に当てはまる場合は、形式を選択して貼り付けのダイアログをその形式を選んだ状態で開く (確認付きの自動判別。F1-16)。どの形式にも当てはまらない場合は、テキストとして現在の文字コードで変換して貼り、InfoBar で「Hex として解釈できないため、テキストとして貼り付けました」と「元に戻す」ボタンを示す。
   - 設定「Hex 列で自動判別したときに確認しない」(既定オフ) をオンにすると、最も確からしい形式でダイアログを出さずに貼る。
3. 通常の貼り付け (Ctrl+V): 挿入モードではカーソル位置に挿入し、上書きモードではカーソル位置から上書きする。選択範囲がある場合、挿入モードでは選択範囲を貼り付ける内容で置き換え (長さが変わりうる)、上書きモードでは選択範囲の先頭から上書きする。
4. 上書き貼り付け (Ctrl+B): モードに関係なく、カーソル位置 (選択範囲があればその先頭) から上書きする。
5. 上書きでドキュメントの末尾を超える場合: 可変長のドキュメントでは末尾を延ばす。固定長ドキュメントでは末尾までの分だけ書き、残りは書かない。書く前に ENG-07 の仕様 5 の確認ダイアログで確かめ、「末尾まで貼り付ける」を選んだら書いて、InfoBar で「末尾を超える N バイトは貼り付けませんでした」と示す。
6. 設定「上書き貼り付けで選択範囲の長さに合わせる」(既定オフ): オンの場合、選択範囲があれば、貼り付ける内容を選択範囲の長さで切り詰める (内容の方が短い場合は内容の長さだけ書く)。
7. 設定「貼り付け後に貼り付けた範囲を選択する」(既定オン)。オフの場合はカーソルを貼り付けた範囲の直後に置く。
8. 固定長ドキュメントでの通常の貼り付けは上書き貼り付けとして扱う。
9. 「貼り付けて新しいタブで開く」: クリップボードの内容 (EDIT-26 の解釈を含む) で新規ドキュメント (01 の新規作成) を作る。
10. 貼り付けたバイト数をスクリーンリーダーに通知する。

**画面**: 該当なし (InfoBar のみ)。

**巨大ファイル・長時間処理**: アプリ内クリップボード (EDIT-24) からの貼り付けはピースの参照で、データ量に関係なく 100 ms 以内。システムのクリップボードからの貼り付けはデータをコピーするため、4 MiB を超える場合は長時間処理として行う (進捗とキャンセル)。

**エラー**: クリップボードが空、または使える形式がない場合はコマンドを無効にする。読み取り専用 (EDIT-16)、固定長での末尾超過 (上記 5)。

**受け入れ基準**:

- [ ] 他のアプリでコピーした `0xDE, 0xAD` を Hex 列に Ctrl+V で貼ると DE AD の 2 バイトが貼られる。
- [ ] `SGVsbG8=` を Hex 列に Ctrl+V すると、Base64 が選ばれた状態で形式を選択して貼り付けのダイアログが開く。
- [ ] 挿入モードで Ctrl+B を押すとファイル長が変わらずに上書きされる (末尾を超えない場合)。
- [ ] 物理ディスクの末尾近くで末尾を超える長さを貼ると、末尾までだけ書かれて InfoBar が出る。
- [ ] テキスト列に `日本` を貼ると、文字コード UTF-8 では 6 バイト、Shift_JIS では 4 バイトになる。

### EDIT-24 大きな範囲のアプリ内クリップボード

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-07 |
| 呼び出し | コピー・切り取り・貼り付けの内部動作 (利用者が呼ぶコマンドはない) |

**概要**: アプリ内でのコピー・貼り付けは、データを複製せずにピースの参照で行う。数百 GB の範囲でも一瞬でコピー・貼り付けできる。

**仕様**:

1. コピー・切り取りのたびに、選択範囲を表すピースの列 (元ドキュメントのピースツリーの部分木の参照) をアプリ内クリップボードに記録する。同時にシステムのクリップボードに `HexEditor.Meta` (アプリのインスタンス ID とコピーの通し番号) を入れる。
2. 貼り付け時、システムのクリップボードの `HexEditor.Meta` がアプリ内クリップボードの通し番号と一致すれば、アプリ内クリップボードのピースを貼り付け先のピースツリーに挿入する。別のドキュメントへの貼り付けは、コピーした範囲全体を指す 1 つの参照 (外部参照のピース) として挿入し、データを複製しない。一致しない場合 (他のアプリがクリップボードを書き換えた) はアプリ内クリップボードを破棄し、システムのクリップボードから読む。
3. 参照先のデータの保護: アプリ内クリップボード (または貼り付けた先のドキュメント) が元ファイルの範囲を参照している間に参照元のドキュメントを閉じる場合は、その範囲のデータを一時ファイルにコピー (実体化) する。
   - 参照元のファイルを保存して置き換えても (01 の保存) 実体化は要らない。参照は保存前の版 (スナップショット) を指し、保存前の版の元データはデータエンジンが保持する (ENG-05 の仕様 5)。
   - 実体化が終わるまで (キャンセル・失敗した場合は、参照するものがなくなるまで)、参照元のドキュメントの元データと追加バッファは解放しない。貼り付けた先のドキュメントの内容は、実体化の有無に関係なく読める。
4. 参照元のファイルの外部での変更を検知した場合 (F1-18) は、変更前のデータを保証できないため、アプリ内クリップボードを破棄し、InfoBar で「コピー元のファイルが外部で変更されたため、クリップボードの内容を消去しました」と示す。
5. 実体化は長時間処理 (進捗とキャンセル)。ドキュメントを閉じる操作は、実体化の完了を待たずに画面上は閉じる。実体化をキャンセルした場合、または一時領域が足りない場合はアプリ内クリップボードを破棄し、InfoBar で知らせる。
6. 実体化が必要な量が 1 GB を超える場合は、閉じる前に確認ダイアログで「クリップボードの 12 GB を保持するため、一時領域に書き出します」と示し、「書き出して閉じる」「クリップボードを消して閉じる」「キャンセル」を選ばせる。
7. 物理ディスク・プロセスメモリからのコピーは、内容が変わりうるため、上限 (EDIT-22 の 4) 以内ならコピーした時点で実体化する。上限を超える場合はコピー時に確認ダイアログで「一時領域に N GB 書き出してコピーする」「キャンセル」を選ばせる。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: 参照の記録と貼り付けは O(ピース数) で、データ量に比例しない。実体化だけがデータ量に比例する長時間処理。

**エラー**: 実体化の失敗 (上記 5)。

**受け入れ基準**:

- [ ] 100 GB のファイル全体をコピーし、別の新規タブに貼り付けると 1 秒以内に完了し、メモリ使用量がほぼ増えない。
- [ ] コピー元のタブを閉じた後でも、貼り付けた内容が正しく読める (一時ファイルに実体化されている)。
- [ ] コピーした後にメモ帳で別のテキストをコピーすると、Ctrl+V はメモ帳のテキストを貼る。

### EDIT-25 形式を選択してコピー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-15 |
| 呼び出し | 編集 > 形式を選択してコピー… (Ctrl+Shift+C)、右クリックメニュー「形式を選択してコピー」(よく使う形式のサブメニュー付き)、コマンドパレット「形式を選択してコピー: <形式名>」(形式ごとのコマンド)、「前回の形式でコピー」(既定なし) |

**概要**: 選択範囲を、Hex 文字列、各プログラミング言語の配列、Base64 などのエンコード、HTML などの文書形式、画面表示どおりのテキスト、Intel HEX などのテキスト形式に変換してクリップボードに入れる。

**仕様**:

1. ダイアログで形式を選び、形式ごとの設定を変え、プレビューを見てから「コピー」を押す。プレビューには出力の先頭 4 KiB と、出力全体の推定サイズを表示する。
2. 前回選んだ形式と設定を記憶し、次回の初期値にする。「前回の形式でコピー」はダイアログを開かずにコピーする。

4. 共通の設定: 1 行のバイト数 (既定 16、1〜1024)、16 進の大文字・小文字 (既定 大文字)、変数名 (既定 `data`。その言語の識別子として正しくない場合は入力欄のエラー)。
5. 配列形式の要素の大きさ: 1 / 2 / 4 / 8 バイト (既定 1)、エンディアン (既定 ドキュメントの既定エンディアン)。選択範囲の長さが要素の大きさの倍数でない場合は、残りを 0 で埋めた要素として出力し、プレビューに「最後の要素は 0 で補いました」と注記する。

   | 数値列 | 10 進 / 8 進 / 2 進 | `222 173 190 239` / `336 255 276 357` / `11011110 10101101 10111110 11101111` |
   | 配列 | C | `unsigned char data[4] = { 0xDE, 0xAD, 0xBE, 0xEF };` (要素 2 バイト以上では `uint16_t` など) |
   | 配列 | C++ | `constexpr std::array<std::uint8_t, 4> data = { 0xDE, 0xAD, 0xBE, 0xEF };` |

   | 配列 | PureBasic | `DataSection`、`data:`、`Data.a $DE, $AD, $BE, $EF`、`EndDataSection` の 4 行 |
   | 配列 | アセンブリ | NASM `data: db 0xDE, 0xAD, 0xBE, 0xEF`、MASM `data db 0DEh, 0ADh, 0BEh, 0EFh`、GAS `data: .byte 0xDE, 0xAD, 0xBE, 0xEF` から選ぶ (要素 2 / 4 / 8 バイトでは `dw` / `dd` / `dq` など) |
   | エンコード | Base64 | `3q2+7w==`。標準 / URL 安全 (RFC 4648)、76 文字での改行の有無を選べる |
   | エンコード | Base32 | `32W353Y=` (RFC 4648)。Base32hex を選べる |

**画面**: ダイアログ。左に形式の一覧 (分類ごとのグループ、検索欄付き)、右上に形式ごとの設定、右下にプレビュー (等幅フォント、読み取り専用のテキスト欄)。下部に推定サイズ、「コピー」「ファイルに保存…」「閉じる」。

**受け入れ基準**:

- [ ] C、C#、Java、Python、Rust、Go の出力を各言語のコンパイラ / インタプリタに通すと構文エラーがなく、値が元のバイト列と一致する (自動テスト)。
- [ ] Base64、Base32、Ascii85、UUEncode、XXEncode、Quoted-Printable、Intel HEX、S-record、JSON の出力を EDIT-26 で貼り付けると元のバイト列に戻る (往復テスト)。
- [ ] 100 MiB を選んで C 配列を選ぶとコピーボタンが無効になり、「ファイルに保存」で書き出せる。
- [ ] HTML 形式でコピーして Word に貼ると、等幅のダンプが色付きで貼られる。

### EDIT-26 形式を選択して貼り付け

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-16 |
| 呼び出し | 編集 > 形式を選択して貼り付け… (Ctrl+Shift+V)、右クリックメニュー、コマンドパレット「形式を選択して貼り付け」、Hex 列への Ctrl+V で自動判別された場合 (EDIT-23 の 2) |

**概要**: クリップボードのテキストを、Hex 文字列・配列表記・Base64 などのどれとして解釈するかを自動で判別し、結果のバイト列を確認してから貼り付ける。

**仕様**:

1. ダイアログを開くと、クリップボードの内容を下表の各形式で解釈し、解釈できた形式を確からしさの順に一覧に出す。最も確からしい形式を選んだ状態にする。
2. 解釈を試みる形式:

   | 形式 | 判別の条件 |
   | --- | --- |
   | Hex 文字列 | 00-overview.md 6.3 の規則で全体が解釈でき、区切りで分けた各まとまりの桁数が偶数 (`222 173` のような 10 進の数値列を Hex と取り違えないため)。区切りには 6.3 のものに加えて `:` と `-` も使える (`DE:AD:BE:EF`) |
   | 配列表記 | `{ }` / `[ ]` / `( )` で囲まれた、または区切られた数値の並び (囲まれていない場合は、`0x` などの接頭辞か `db`・`Data.b` などの語句があるものだけ。接頭辞も語句もない 10 進の並びは 10 進の数値列として扱う)。数値を直接含む最後の括弧の組を値とする (`data[4] = { … }` の `{ … }`)。各数値は `0x`、`$`、`&H`、`h` 接尾辞、10 進のいずれかで、すべて 0〜255 (要素の大きさを 2 / 4 / 8 バイトに変えた場合はその範囲)。`byte[] data =`、`(byte)`、`db`、`Data.b` などの言語の語句と、`//`、`/* */`、`#`、`;` のコメントは無視する |
   | 10 進の数値列 | 空白・カンマ区切りの 0〜255 の整数のみ |
   | 8 進・2 進の数値列 | 空白・カンマ区切りの 8 進 (0〜377) の整数のみ、または 8 桁ちょうどの 2 進の数のみ (EDIT-25 の数値列の出力を戻すため) |
   | エスケープ文字列 | `\xHH`、8 進の `\NNN`、`\n` などの C のエスケープ、Python の bytes リテラル (`b` で始まる引用符付きの文字列) |
   | Base64 | 使われている文字が Base64 (標準または URL 安全) のみで、改行を除いた長さが 4 の倍数 (`=` がない場合は 4 で割った余りが 1 でない)。行の途中の空白は認めない (10 進の数値列などと取り違えないため)。最後の文字の余りのビットが 0 である (正しい出力の形) |
   | Base32 / Base32hex / Ascii85 / Z85 / UUEncode / XXEncode / Quoted-Printable / URL エンコード | 各形式の文字集合と構造 (`<~`、`begin 644` など) に一致する。Base32 と Base32hex は Base64 と同じく余りのビットが 0 であることも確かめる (例えば `DE AD BE EF` の Base32hex の `RQMRTRO=` は標準の Base32 の文字だけでできているが、余りのビットで区別できる)。Ascii85 は `<~` で始まるものだけを判別する |
   | Intel HEX / S-record | 空行を除く全行が `:` / `S` で始まり、レコードの構造が正しい |
   | JSON | EDIT-25 の JSON 形式 (`data` を持つオブジェクト)、または 0〜255 の数値の配列 |
   | 画面表示どおり | 各行がオフセット・Hex・テキストの形 (EDIT-25 の形式、または一般的なダンプの形)。オフセットとテキストの列を除き、Hex の部分だけを使う |
   | テキスト | 常に候補にする。文字コードを選べる (既定 現在の表示文字コード。UTF-8、UTF-16 LE / BE、その他 F1-06 のコードページ)。改行の変換 (そのまま / CRLF / LF) と、末尾に NUL を付けるかを選べる |
   | ファイルの内容 | エクスプローラーでファイルをコピーした場合。EDIT-30 と同じ |
   | バイナリ | クリップボードにバイナリ形式 (EDIT-22、EDIT-27) がある場合 |

3. 確からしさの順位: (0) バイナリとファイルの内容、(1) 構造のある形式 (Intel HEX、S-record、UUEncode、XXEncode、JSON、画面表示どおり)、(2) 配列表記とエスケープ文字列、8 桁の 2 進の数値列、(3) Hex 文字列、(4) Base64 など文字集合だけで判別する形式 (Ascii85、Base32、Base32hex、Base64、Z85、Quoted-Printable、URL エンコードの順)、(5) 10 進・8 進の数値列、(6) テキスト。例えば `1234` は Hex 文字列 (2 バイト)、Base64 (3 バイト)、テキスト (4 バイト) の候補になり、Hex 文字列を選んだ状態になる (10 進の数値列は 255 を超えるため候補にならない)。
4. 一覧で形式を選ぶと、プレビューに結果のバイト列 (先頭 256 バイトの Hex 表示) と長さを表示する。解釈できなかった形式は、一覧に「エラー: 3 行目 12 文字目」のように理由を付けて表示し、選べないようにする。
5. 貼り付け方を選べる: 「挿入」/「上書き」(既定は現在の入力モード。固定長ドキュメントでは上書きのみ)。Intel HEX / S-record では「カーソル位置に貼る」/「レコードのアドレスに書く」(アドレス − ベースアドレスのオフセットに上書き。データのない領域は書かない) を選べる。「カーソル位置に貼る」では、最小のアドレスのバイトをカーソル位置に置き、レコード間の隙間 (データのないアドレス) は詰めずにそのまま残して、塗りつぶしの値 (既定 `FF`、ダイアログで変更可。ENG-38 と同じ既定) で埋める。結果の長さは「最大のアドレス + 1 − 最小のアドレス」で、上限は 4 GiB (ENG-38 と同じ)。アドレスを持つほかの形式 (画面表示どおりのオフセットの列など) は、アドレスを使わずデータの部分だけを順に連結する。
6. 同じ判別結果の候補が複数ある場合、最後に使った形式を優先する (設定「前回の形式を優先する」、既定オン)。
7. 解釈するテキストの上限は 512 MiB。超える場合はダイアログを開かずに InfoBar で示す。

**画面**: ダイアログ。左に候補の形式の一覧 (確からしさ順、各形式の結果の長さ付き)、右上に形式ごとの設定、右下にプレビュー (元のテキストの先頭と、結果のバイト列)。下部に「挿入」「上書き」の選択、「貼り付け」「キャンセル」。

**巨大ファイル・長時間処理**: 判別はテキストの先頭 64 KiB で行い、選んだ形式での全体の変換は貼り付け時に行う。テキストが 4 MiB を超える場合、全体の変換は長時間処理になる。全体の変換の途中でエラーが見つかった場合は貼り付けず、エラーの位置を示す。

**エラー**: 変換時のエラー (「12,345 行目: 不正な文字 `G`」)。チェックサムの不一致 (Intel HEX / S-record では確認ダイアログで「チェックサムが一致しない行が N 行あります」と示し、「無視して貼り付ける」「キャンセル」を選ばせる)。

**受け入れ基準**:

- [ ] `{ 0xDE, 0xAD, 0xBE, 0xEF }` を貼ると配列表記が選ばれ、結果が DE AD BE EF になる。
- [ ] `3q2+7w==` を貼ると Base64 が選ばれ、DE AD BE EF になる。
- [ ] `00000010  DE AD BE EF  ....` の形のダンプを貼ると画面表示どおりが選ばれ、DE AD BE EF になる。
- [ ] EDIT-25 の全形式の出力を貼ると、正しい形式が最上位の候補になる (自動テスト)。
- [ ] 奇数桁の Hex 文字列では、Hex 文字列の候補がエラーになり選べない。
- [ ] Intel HEX を「レコードのアドレスに書く」で貼ると、各レコードのアドレスに書かれる。
- [ ] 隙間のある Intel HEX を「カーソル位置に貼る」で貼ると、隙間は詰められず塗りつぶしの値 (既定 `FF`) で埋まり、各レコードがカーソル位置からの相対位置 (アドレス − 最小のアドレス) に置かれる。

### EDIT-28 ユーザークリップボードとクリップボード履歴

| 項目 | 内容 |

### EDIT-29 塗りつぶし

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-14 |
| 呼び出し | 編集 > 塗りつぶし…、右クリックメニュー「塗りつぶし…」、コマンドパレット「塗りつぶし」。ショートカットは既定なし |

**概要**: 選択範囲 (または指定した範囲) を、バイト値・パターン・テキスト・乱数・カウンタ・ファイルの内容で塗りつぶす。

**仕様**:

1. 対象範囲: 「選択範囲」(既定。マルチ選択・矩形選択を含む) / 「範囲を指定」(開始と長さ、または開始と「終了 (このバイトを含む)」を入力式で指定。末尾を超える範囲は、可変長のドキュメントでは末尾を延ばし、固定長ドキュメントではエラー)。
2. 内容の種類:

   | 種類 | 指定するもの | 既定値・上限 |
   | --- | --- | --- |
   | バイト値 | 1 バイトの値 (入力式) | `00` |
   | Hex パターン | 00-overview.md 6.3 の Hex バイト列 | 1〜1 MiB |
   | テキスト | 文字列と文字コード (既定 現在の表示文字コード)。改行・タブはエスケープ (`\r` `\n` `\t`) で書ける | 1〜1 MiB (変換後) |
   | 乱数 | 値の範囲 (最小・最大。既定 0〜255)、シード (空欄なら毎回変わる) | 値の範囲が 0〜255 のときはデータエンジンの乱数の生成ピース (ENG-03 の SplitMix64) で表し、長さに関係なく一定時間で終わる。それ以外の範囲は擬似乱数 (xoshiro256**) で実データを作る。どちらもシードを指定すると同じ結果を再現できる |
   | 暗号論的乱数 | なし | `RandomNumberGenerator` (CNG の `BCryptGenRandom`) で生成する |
   | カウンタ | 開始値、増分 (負も可)、要素の大きさ (1 / 2 / 4 / 8 バイト)、エンディアン、符号の有無、あふれたときの扱い (ラップ / 飽和) | 開始 0、増分 1、1 バイト、ラップ |
   | ファイルの内容 | ファイルのパス、ファイル内の開始位置と長さ (既定 全体) | 長さの上限なし |
   | クリップボードの内容 | なし | EDIT-23 の形式の優先順位で読む |

3. 繰り返し: パターン・テキスト・ファイル・クリップボードの内容が対象範囲より短い場合は繰り返し、最後の繰り返しは途中で切る。「繰り返さない」を選ぶと 1 回だけ書いて残りは変えない。対象範囲より長い場合は対象範囲の長さで切る。
4. パターンの起点: 「範囲の先頭から」(既定) / 「オフセット 0 から数える」(位置 p のバイトはパターンの `p mod パターン長` 番目。レコード境界に揃えたい場合に使う)。マルチ選択では「要素ごとに先頭から」(既定) / 「要素をまたいで続ける」を選べる。
5. 塗りつぶしは対象範囲を上書きし、長さは変えない (範囲を指定して末尾を超える場合を除く)。挿入はバイトの挿入 (EDIT-14) で行う。
6. プレビュー: 対象範囲の先頭 64 バイトの変更前と変更後を並べて表示する。
7. 最後に使った種類と設定を記憶する。シードは記憶しない。

**画面**: ContentDialog。対象範囲の欄、内容の種類 (ラジオボタンまたはドロップダウン)、種類ごとの設定欄、プレビュー、「塗りつぶし」「キャンセル」。

**巨大ファイル・長時間処理**:

1. バイト値: データエンジンの塗りつぶしピース 1 つで表し、範囲の大きさに関係なく 100 ms 以内 (100 GB でも同じ)。
2. Hex パターン・テキストで長さ 4 KiB 以下のもの: 繰り返しピース (パターンと長さを持つピース) で表し、一定時間で完了する。データエンジンが繰り返しピースを持たない場合は、下記 3 と同じ扱いにする (ENG で決める)。
3. 範囲付きの乱数・暗号論的乱数・カウンタ (ラップで周期が 4 KiB 以下のものはパターンとして 2 で表す)・ファイル・長いパターン: 実データを追加データとして生成する (1 MiB を超えるものは一時ファイルに書き、キャンセル・失敗したら一時ファイルを消す)。データ量に比例する長時間処理 (進捗、残り時間、キャンセル)。生成速度の目標は 1 GB/s 以上 (暗号論的乱数は 300 MB/s 以上)。開始前に一時領域の空き容量を確認し、足りない場合は実行しない。
4. マルチ選択・矩形選択は要素ごとに上記を行う。要素数が 10,000 を超える場合は長時間処理。

**エラー**:

| 状況 | 表示 |
| --- | --- |
| パターンが空、Hex の奇数桁 | 入力欄のエラー。確定ボタンを無効にする |
| テキストが文字コードで表せない | 入力欄のエラー (表せない文字を示す) |
| ファイルを開けない | 「ファイルを開けません: 理由」 |
| 一時領域の不足 | 「塗りつぶしに一時領域が N GB 必要ですが、空きは M GB です」 |
| 固定長ドキュメントで末尾を超える範囲 | 入力欄のエラー |

**受け入れ基準**:

- [ ] 100 GB のファイル全体を `00` で塗りつぶすと 100 ms 以内に完了し、メモリ使用量がほぼ増えない。
- [ ] パターン `DE AD` で 5 バイトを塗りつぶすと `DE AD DE AD DE` になる。
- [ ] 「オフセット 0 から数える」で 0x03 から 3 バイトを `00 11 22 33` で塗ると `33 00 11` になる。
- [ ] カウンタ (開始 0xFE、増分 1、1 バイト、ラップ) で 4 バイトを塗ると `FE FF 00 01` になる。飽和では `FE FF FF FF` になる。
- [ ] 同じシードの乱数で 2 回塗りつぶすと同じ内容になる。
- [ ] 10 GB の暗号論的乱数の塗りつぶしを途中でキャンセルすると、データが変わっていない。

| --- | --- |
| ロードマップ | F2-05 |
| 呼び出し | データ > データ演算…、右クリックメニュー「データ演算」(演算の種類のサブメニュー付き)、コマンドパレット「データ演算: <演算名>」(演算ごとのコマンド)、「前回のデータ演算を繰り返す」。ショートカットは既定なし |

**概要**: 選択範囲を一定の大きさの要素の並びとみなし、各要素に演算を適用する。要素の大きさ、型、エンディアン、オペランドの増分、処理する要素と飛ばす要素を指定できる。

**仕様**:

1. 対象範囲: 選択範囲 (既定。マルチ選択・矩形選択を含む) / ドキュメント全体 / 範囲を指定 (入力式)。
2. 要素の型: 符号なし整数 / 符号付き整数 (2 の補数) / 浮動小数点 (IEEE 754。算術演算と最小値・最大値での制限だけで使える)。
3. 要素の大きさ: 整数は 1 / 2 / 4 / 8 バイト、浮動小数点は 4 / 8 バイト。既定は 1 バイト。
4. エンディアン: リトルエンディアン / ビッグエンディアン。既定はドキュメントのエンディアン (VIEW-11。データインスペクタも既定でこれに従う、INSP-02)。
5. オペランド: 演算に使う値。入力式 (00-overview.md 6 章) で指定する。浮動小数点の要素では小数 (`.` のみ) と指数表記 (`1e-3`) を受け付ける。オペランドの範囲は要素の型と大きさで表せる範囲 (表せない値は入力欄のエラー)。
6. オペランドの増分: 1 要素を処理するたびにオペランドに足す値 (既定 0)。例: 加算でオペランド 0、増分 1 にすると、i 番目の要素に i を足す。増分によるオペランドのあふれは、要素の大きさでラップする。
7. 処理と飛ばし (ストライド): 「N 要素を処理し、M 要素を飛ばす」を繰り返す (既定 N = 1、M = 0)。飛ばした要素は変えない。オペランドの増分は処理した要素についてだけ行う。
8. 端数: 対象範囲の長さが要素の大きさの倍数でない場合、最後の端数のバイトは変えない。プレビューとダイアログに「最後の N バイトは要素に満たないため変更しません」と表示する。
9. マルチ選択・矩形選択では要素 (範囲) ごとに先頭から要素を数える。オペランドの増分は「範囲ごとにやり直す」(既定) / 「範囲をまたいで続ける」を選べる。
10. プレビュー: 対象範囲の先頭 64 バイトについて、変更前と変更後を Hex で並べ、要素の値を 10 進でも表示する。変わるバイトに印を付ける。
11. 「前回のデータ演算を繰り返す」: 最後に実行した演算と設定を、現在の選択範囲に対して、ダイアログを開かずに実行する。
12. 実行結果は 1 つの編集グループ。演算の結果は長さを変えない (ビット単位の挿入と削除 (EDIT-37) を除く)。

**画面**: ダイアログ。上部に演算の種類 (分類ごとのドロップダウン: 算術、ビット演算、シフト・ローテート、並べ替え、制限、ビットの挿入・削除)、中央に共通の設定 (対象範囲、型、大きさ、エンディアン、オペランド、増分、処理と飛ばし) と演算ごとの設定、下部にプレビュー。「実行」「キャンセル」。

**巨大ファイル・長時間処理**:

1. 演算の結果は実データ (追加データ) として作る。対象範囲が 4 MiB 以下ならその場で実行し、それを超える場合は長時間処理 (進捗、処理速度、残り時間、キャンセル) として実行する。
2. 対象範囲を 1 MiB 単位で読み、SIMD (`Vector<T>`) で計算して追加データに書く。処理速度の目標は、ストレージの読み込みと一時ファイルの書き込みの遅い方の 80% 以上。
3. 開始前に一時領域の空き容量 (対象範囲と同じ大きさ) を確認し、足りない場合は実行しない。
4. 結果は作り終えてから 1 回でドキュメントに反映する。キャンセル・失敗時はドキュメントを変えない (共通の約束 2)。
5. 値が変わらない演算 (加算でオペランド 0、増分 0 など) は実行せず、「データは変わりません」と InfoBar で示す。

**エラー**:

| 状況 | 表示 |
| --- | --- |
| オペランドが範囲外、構文エラー | 入力欄のエラー。実行ボタンを無効にする |
| 0 での除算・剰余 | 入力欄のエラー (「0 では割れません」)。増分によって途中で 0 になる場合は、実行前のチェックで検出してエラーにする |
| 一時領域の不足 | 「演算に一時領域が N GB 必要ですが、空きは M GB です」 |
| 読み込み中の I/O エラー | 中止してドキュメントを変えない。エラーのオフセットを示す |

**受け入れ基準**:

- [ ] 要素 2 バイト・リトルエンディアンで `01 00 02 00` に 1 を足すと `02 00 03 00` になる。ビッグエンディアンでは `01 01 02 01` になる。
- [ ] 「1 要素を処理し 1 要素を飛ばす」で 4 バイトに XOR FF をすると、1 番目と 3 番目のバイトだけが変わる。
- [ ] オペランド 0、増分 1 の加算で `00 00 00 00` が `00 01 02 03` になる。
- [ ] 5 バイトに要素 2 バイトの演算をすると、最後の 1 バイトが変わらず、注記が表示される。
- [ ] 10 GB の範囲の XOR を途中でキャンセルするとデータが変わらず、実行すると Ctrl+Z 1 回で戻る。

### EDIT-32 算術演算

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-05 |
| 呼び出し | データ演算ダイアログの「算術」(EDIT-31 の呼び出しと同じ) |

**概要**: 各要素にオペランドを加算・減算・乗算・除算・剰余する。あふれたときの扱いをラップと飽和から選べる。

**仕様**:

1. 演算の種類:

   | 演算 | 結果 |
   | --- | --- |
   | 加算 | x + オペランド |
   | 減算 | x − オペランド |
   | 逆減算 | オペランド − x |
   | 乗算 | x × オペランド |
   | 除算 | x ÷ オペランド (整数は 0 方向への切り捨て) |
   | 逆除算 | オペランド ÷ x (x が 0 の要素は変えず、件数を結果に表示する) |
   | 剰余 | x mod オペランド (整数のみ。結果の符号は被除数と同じ。C# の `%` と同じ) |
   | 符号反転 | −x (オペランドなし) |
   | 絶対値 | \|x\| (符号付き整数・浮動小数点のみ。オペランドなし) |

2. あふれたときの扱い (整数のみ): 「ラップ」(既定。要素の大きさで切り捨てる) / 「飽和」(型の最小値・最大値に留める)。符号付き整数の飽和は、例えば 1 バイトで −128〜127。符号付きの最小値の符号反転・絶対値は、ラップでは最小値のまま、飽和では最大値にする。
3. 浮動小数点: IEEE 754 の規則で計算する (0 除算は ±∞ または NaN)。NaN と ∞ になった要素の数を完了時に表示する。
4. 完了時に、あふれた (ラップまたは飽和した) 要素の数を InfoBar で表示する。

**画面**: EDIT-31 のダイアログ内の、演算の選択とあふれの扱いのラジオボタン。

**巨大ファイル・長時間処理**: EDIT-31 と同じ。

**エラー**: EDIT-31 と同じ。

**受け入れ基準**:

- [ ] 符号なし 1 バイト、ラップで `FF` に 2 を足すと `01`、飽和では `FF` になる。
- [ ] 符号付き 1 バイト、飽和で `7F` に 1 を足すと `7F`、`80` から 1 を引くと `80` のまま。
- [ ] 符号付き 2 バイト (LE) の `F9 FF` (−7) を 2 で割ると `FD FF` (−3)、剰余 2 では `FF FF` (−1)。
- [ ] float (LE) の `00 00 80 3F` (1.0) に 0.5 を掛けると `00 00 00 3F` (0.5) になる。

### EDIT-33 ビット演算

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-05 |
| 呼び出し | データ演算ダイアログの「ビット演算」 |

**概要**: 各要素とオペランドの AND・OR・XOR・NOT などのビット演算を行う。XOR は複数バイトの鍵を繰り返し使える。

**仕様**:

1. 演算の種類: AND、OR、XOR、NOT (オペランドなし)、NAND、NOR、XNOR。
2. オペランドの指定方法: 「数値」(要素の大きさの値。EDIT-31 の 5) / 「バイト列の鍵」(Hex バイト列、テキスト (文字コード指定)、ファイル、クリップボードから。1 バイト〜16 MiB)。

4. 鍵の増分: バイト列の鍵を使う場合も、鍵を 1 周するごとに鍵の各バイトに増分を足す設定を持つ (既定 0)。
5. XOR を同じ設定で 2 回実行すると元に戻ることを、ダイアログの説明文に書く。

**画面**: EDIT-31 のダイアログ内の、演算の選択と鍵の入力欄。

**巨大ファイル・長時間処理**: EDIT-31 と同じ。

**エラー**: 鍵が空、Hex の奇数桁は入力欄のエラー。鍵のファイルが 16 MiB を超える場合は「鍵は 16 MiB までです」。

**受け入れ基準**:

- [ ] `00 FF 0F` に XOR 鍵 `AA 55` を適用すると `AA AA A5` になる。
- [ ] 同じ設定で XOR を 2 回実行すると元のデータに戻る。
- [ ] NOT で `0F` が `F0` になる。

### EDIT-34 シフトとローテート

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-05 |
| 呼び出し | データ演算ダイアログの「シフト・ローテート」 |

**概要**: 各要素のビットを左右にシフト・ローテートする。要素ごとに回転量を増やしていく段階的なローテートもできる。

**仕様**:

1. 演算の種類: 左シフト (論理)、右シフト (論理。空いたビットは 0)、右シフト (算術。空いたビットは符号ビット)、左ローテート、右ローテート。
2. ビット数: 1 〜 要素のビット数 − 1 (1 バイトなら 1〜7)。シフトでは要素のビット数以上も指定でき、その場合の結果は 0 (算術右シフトでは符号ビットで埋めた値) とする。
3. 段階的なローテート: 「回転量の増分」を指定すると、i 番目に処理する要素の回転量を `(ビット数 + i × 増分) mod 要素のビット数` にする。増分の既定は 0 (すべて同じ回転量)。
4. 「範囲全体を 1 つのビット列としてシフト」はこの演算ではなく、ビット単位の挿入と削除 (EDIT-37) で行う。

**画面**: EDIT-31 のダイアログ内の、演算の選択、ビット数、回転量の増分の欄。

**巨大ファイル・長時間処理**: EDIT-31 と同じ。

**エラー**: ビット数が範囲外の場合は入力欄のエラー。

**受け入れ基準**:

- [ ] 1 バイトの `81` を左ローテート 1 すると `03`、右ローテート 1 すると `C0` になる。
- [ ] 符号付き 1 バイトの `80` を算術右シフト 1 すると `C0`、論理右シフト 1 すると `40` になる。
- [ ] 回転量 1、増分 1 の左ローテートで `01 01 01` が `02 04 08` になる。

### EDIT-35 バイトスワップと反転

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-05 |
| 呼び出し | データ演算ダイアログの「並べ替え」、コマンドパレット「バイトスワップ (16 bit)」「バイトスワップ (32 bit)」「バイトスワップ (64 bit)」「バイト順を反転」 |

**概要**: 要素内のバイトの順序を入れ替える (エンディアンの変換)。範囲全体のバイト順やビット順を反転する。

**仕様**:

1. 演算の種類:

   | 演算 | 内容 | 例 |
   | --- | --- | --- |
   | バイトスワップ 16 / 32 / 64 bit | 2 / 4 / 8 バイトごとにバイト順を逆にする | 32 bit: `01 02 03 04` → `04 03 02 01` |

   | ビット順の反転 (各バイト) | 各バイトのビット 0〜7 を逆順にする | `01` → `80` |
   | ニブルの入れ替え (各バイト) | 上位と下位の 4 bit を入れ替える | `12` → `21` |

2. 要素単位の演算では、EDIT-31 の要素の大きさの指定は使わず、演算が決める大きさを使う。端数の扱いは EDIT-31 の 8 と同じ。処理と飛ばしは使える。
3. 範囲全体の反転では、マルチ選択は要素ごとに反転する。

**画面**: EDIT-31 のダイアログ内の演算の選択。

**巨大ファイル・長時間処理**: 要素単位の演算は EDIT-31 と同じ。範囲全体の反転は、範囲の末尾から 1 MiB 単位で読んで逆順に追加データへ書く長時間処理。

**エラー**: EDIT-31 と同じ。

**受け入れ基準**:

- [ ] 表の各例のとおりに変換される (自動テスト)。
- [ ] バイトスワップ 32 bit を 6 バイトに行うと、先頭 4 バイトだけが変わり、注記が表示される。
- [ ] 3 GB の範囲のバイト順の反転が長時間処理として実行でき、2 回行うと元に戻る。

### EDIT-37 ビット単位の挿入と削除

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | データ演算ダイアログの「ビットの挿入・削除」、コマンドパレット「ビットを挿入」「ビットを削除」 |

**概要**: データを 1 本のビット列とみなし、指定したビット位置に 0 または 1 のビットを挿入する、またはビットを削除して、後ろのビットを詰める。ビット単位でずれたデータを揃えるときに使う。

**仕様**:

1. 指定するもの: 位置 (バイトのオフセットと、そのバイト内のビット位置 0〜7。ビット 7 が最上位)、ビット数 (1〜2^31)、挿入の場合は埋める値 (0 / 1)、ビットの並び順 (最上位ビットから (既定) / 最下位ビットから)。
2. ずらす範囲: 「選択範囲の中だけ」(既定。長さは変わらない。はみ出したビットは捨て、空いたビットは 0 で埋める) / 「ドキュメントの末尾まで」(長さが変わる)。
3. 「ドキュメントの末尾まで」で挿入する場合、ドキュメントの長さは `ceil((元のビット数 + 挿入ビット数) / 8)` バイトになり、最後のバイトの余ったビットは 0 にする。削除する場合は `ceil((元のビット数 − 削除ビット数) / 8)` バイトになる。
4. ビット数が 8 の倍数のときは、通常のバイトの挿入・削除と同じ結果になる。その場合は、データエンジンのピース操作 (一定時間) で行う。
5. 固定長ドキュメントでは「選択範囲の中だけ」だけを使える。

**画面**: EDIT-31 のダイアログ内の、位置・ビット数・埋める値・ずらす範囲の欄。プレビューはビット単位 (2 進) で表示する。

**巨大ファイル・長時間処理**: 位置より後ろのデータをすべて書き直すため、ずらす範囲の大きさに比例する長時間処理になる。ずらす範囲が 1 GiB を超える場合は、実行前に確認ダイアログで「N GB のデータを書き直します (一時領域を N GB 使います)」と示し、「実行する」「キャンセル」を選ばせる。

**エラー**: EDIT-31 と同じ。

**受け入れ基準**:

- [ ] `FF 00` のオフセット 0、ビット 7 (先頭) に 0 を 1 ビット挿入し、ドキュメントの末尾までずらすと `7F 80 00` (3 バイト) になる。
- [ ] 上の結果の先頭から 1 ビット削除すると `FF 00 00` になる (長さは `ceil(23/8)` = 3 バイト)。
- [ ] 「選択範囲の中だけ」では長さが変わらない。
- [ ] 8 ビットの挿入は 100 GB のファイルでも 100 ms 以内に完了する。

## 7. テキスト変換

### EDIT-38 文字コード変換

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-13 |
| 呼び出し | データ > 文字コード変換…、右クリックメニュー、コマンドパレット「文字コード変換」。ショートカットは既定なし |

**概要**: 選択範囲のバイト列を、ある文字コードの文字列として解釈し、別の文字コードのバイト列に書き換える (例: Shift_JIS → UTF-8、ASCII ↔ EBCDIC)。

**仕様**:

1. 変換元と変換先の文字コードを選ぶ。選べる文字コードは表示文字コード (F1-06) と同じ一覧。既定の変換元は現在の表示文字コード、変換先は UTF-8。
2. 変換元で解釈できないバイト列の扱い: 「U+FFFD に置き換える」/「そのまま残す (変換しない。前後の文字だけ変換する)」/「最初の箇所でエラーにして中止する」(既定)。
3. 変換先で表せない文字の扱い: 「`?` に置き換える」/「指定した文字に置き換える」/「最初の箇所でエラーにして中止する」(既定)。最善の近似文字への置き換え (best fit) は使わない。
4. BOM: 変換元の先頭の BOM を取り除くか (既定 取り除く)、変換先に BOM を付けるか (既定 付けない) を選べる。
5. 改行の変換: そのまま (既定) / CRLF / LF / CR。
6. Unicode の正規化: しない (既定) / NFC / NFD / NFKC / NFKD。
7. 変換後の長さが変わる場合、選択範囲を変換結果で置き換える (長さが変わる編集)。固定長ドキュメントでは長さが変わる場合に実行しない (変換後の長さが同じなら実行できる)。
8. プレビュー: 変換前と変換後の先頭 256 バイトを Hex と文字で並べ、変換後の推定の長さを表示する。
9. マルチ選択では要素ごとに変換する。

**画面**: ContentDialog。変換元・変換先の文字コード (検索できるドロップダウン)、各種の扱い、プレビュー、「変換」「キャンセル」。

**巨大ファイル・長時間処理**: `Decoder` / `Encoder` を使い、1 MiB 単位で読みながら状態を引き継いで変換する (文字の途中でチャンクが切れても正しく変換する)。変換結果は追加データとして作る。4 MiB を超える場合は長時間処理。

**エラー**: 解釈できない・表せない箇所でのエラーは、最初の箇所のオフセットと文字を示し、「そのオフセットへ移動」ボタンを付ける。ドキュメントは変えない。

**受け入れ基準**:

- [ ] Shift_JIS の `93 FA 96 7B` (日本) を UTF-8 に変換すると `E6 97 A5 E6 9C AC` になる。
- [ ] ASCII の `41` (A) を EBCDIC (IBM037) に変換すると `C1` になる。
- [ ] 1 MiB の境界をまたぐ多バイト文字を含む 10 MiB の UTF-8 を UTF-16 LE に変換し、逆変換すると元に戻る。
- [ ] 変換先で表せない文字がある場合、既定ではエラーになりデータが変わらない。

### EDIT-40 暗号化と復号

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-04 |
| 呼び出し | データ > 暗号化…、データ > 復号…、コマンドパレット「暗号化」「復号」。ショートカットは既定なし |

**概要**: 選択範囲を、Windows の暗号 API (CNG) で暗号化・復号し、結果で置き換える。

**仕様**:

1. アルゴリズムとモード:

   | アルゴリズム | モード | 備考 |
   | --- | --- | --- |
   | AES-128 / 192 / 256 | ECB、CBC、CFB8、CFB128、CTR、GCM | CTR は ECB を使って実装する。GCM は認証付き |
   | ChaCha20-Poly1305 | — | 認証付き。OS が対応していない場合は一覧で無効にし、理由を表示する |
   | 3DES (TripleDES) | ECB、CBC | 互換のため。選ぶと「安全ではない方式です」と表示する |
   | DES | ECB、CBC | 同上 |
   | RC4 | — | 同上。CNG の RC4 を使う |

2. 鍵の指定: 「Hex で入力」(アルゴリズムの鍵長と一致する必要がある) / 「パスフレーズから作る」(PBKDF2-HMAC-SHA256。反復回数 既定 600,000、ソルト (Hex。空欄なら 16 バイトの乱数を生成して表示する)、鍵長はアルゴリズムで決まる)。
3. IV / ナンス: Hex で入力する。暗号化では「乱数で生成」ボタンを置く (CBC・CFB は 16 バイト、CTR は 16 バイトのカウンタ初期値、GCM・ChaCha20-Poly1305 は 12 バイト)。ECB では不要。
4. パディング (ECB・CBC のみ): PKCS#7 (既定)、ゼロ埋め、ANSI X9.23、ISO 10126、なし。「なし」で長さがブロック長の倍数でない場合はエラー。
5. 認証付き暗号 (GCM・ChaCha20-Poly1305): 追加認証データ (AAD。Hex、省略可) を指定できる。タグ (16 バイト) は暗号化では結果の末尾に付ける (既定) / 別の欄に表示するだけ、を選べる。復号ではタグを「選択範囲の末尾 16 バイト」(既定) / 「Hex で入力」から選ぶ。タグが一致しない場合は復号結果を書き込まない。
6. 結果の書き込み先: 「選択範囲を置き換える」(既定。長さが変わりうる) / 「新しいタブで開く」。固定長ドキュメントでは、長さが変わる場合は「新しいタブで開く」だけを使える。
7. 鍵・パスフレーズ・IV は、設定・履歴・復旧用データ・ログに保存しない。ダイアログを閉じたら、鍵のバイト列をメモリから消去する (`CryptographicOperations.ZeroMemory`)。アルゴリズム・モード・パディングの選択だけを記憶する。
8. 鍵の入力欄はパスワード入力欄 (`PasswordBox`) にし、「表示」ボタンで見えるようにできる。

**画面**: ContentDialog。アルゴリズム、モード、鍵 (方式の切り替え付き)、IV、パディング、AAD・タグ、書き込み先。下部に「暗号化」(または「復号」)「キャンセル」。

**巨大ファイル・長時間処理**:

1. ECB・CBC・CFB・CTR・RC4 は 1 MiB 単位のストリーム処理で、大きさの上限はない。4 MiB を超える場合は長時間処理。
2. GCM・ChaCha20-Poly1305 は .NET の API が一括処理のため、対象を 1 GiB までに制限する。超える場合はアルゴリズムの一覧に「1 GiB を超えるデータには使えません」と表示して選べないようにする。
3. 結果は追加データとして作り、完了後に 1 回でドキュメントに反映する。

**エラー**:

| 状況 | 表示 |
| --- | --- |
| 鍵長・IV 長が違う | 入力欄のエラー (「AES-256 の鍵は 32 バイトです (入力は 16 バイト)」) |
| 復号でパディングが正しくない | 「パディングが正しくありません。鍵・IV・モードが違う可能性があります」。「パディングなしで復号する」ボタンを付ける |
| 認証タグが一致しない | 「認証に失敗しました。鍵・ナンス・AAD・データのいずれかが違います」。データは変えない |

**受け入れ基準**:

- [ ] NIST SP 800-38A の AES-128 CBC のテストベクタで暗号化・復号の結果が一致する。
- [ ] AES-256 GCM で暗号化し、同じ鍵・ナンスで復号すると元に戻る。1 バイトでも改変すると認証エラーになりデータが変わらない。
- [ ] パスフレーズとソルトから作った鍵が、同じ条件の PBKDF2-HMAC-SHA256 の参照実装と一致する。
- [ ] ダイアログを閉じて再度開いたとき、鍵・IV の欄が空になっている。設定ファイルに鍵が含まれていない。
- [ ] 10 GB の範囲を AES-CBC で暗号化でき、進捗とキャンセルが使える。

### EDIT-41 圧縮と展開

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-04 |
| 呼び出し | データ > 圧縮…、データ > 展開…、データ > 圧縮データの範囲を選択、コマンドパレット「圧縮」「展開」「圧縮データの範囲を選択」。ショートカットは既定なし |

**概要**: 選択範囲を zlib・deflate・gzip・zstd・LZ4・LZMA・XZ・Brotli で圧縮・展開し、結果で置き換える、または新しいタブで開く。

**仕様**:

1. 形式:

   | 形式 | 実装 | 自動判別の手がかり |
   | --- | --- | --- |
   | deflate (raw) | `System.IO.Compression` | なし |
   | zlib | 同上 | 先頭 2 バイトが `78 01` / `78 5E` / `78 9C` / `78 DA` など (CMF・FLG のチェックが正しい) |
   | gzip | 同上 | `1F 8B` |
   | Brotli | `System.IO.Compression` | なし |
   | zstd | ライブラリは未決定 (ZstdSharp などを検討) | `28 B5 2F FD` |
   | LZ4 (フレーム / ブロック) | ライブラリは未決定 (K4os.Compression.LZ4 などを検討) | フレームは `04 22 4D 18` |
   | LZMA (`.lzma` 形式) / XZ | ライブラリは未決定 | XZ は `FD 37 7A 58 5A 00`。LZMA は先頭 1 バイトのプロパティが 0x5D など |

2. 圧縮: 形式と圧縮レベル (形式ごとの範囲。既定は各形式の標準) を選ぶ。gzip ではファイル名と更新日時をヘッダに入れるか選べる (既定 入れない)。
3. 展開: 形式は「自動判別」(既定) または指定。自動判別できない場合 (手がかりのない形式、または手がかりが一致しても展開に失敗した場合) は、「形式を自動判別できませんでした」と示して、同じダイアログで形式の選択を求める (選ぶまで展開しない)。
4. 展開は、圧縮データの終わりで止まる。選択範囲の後ろに余ったデータがある場合は「圧縮データは N バイトで終わり、残りの M バイトは変更しませんでした」と表示する。
5. 「圧縮データの範囲を選択」: カーソル位置から展開を試み、圧縮データとして読めた範囲 (先頭から終わりまで) を選択する。結果の大きさも表示する。データは変えない。
6. 書き込み先: 「選択範囲を置き換える」/ 「新しいタブで開く」(展開の既定)。圧縮の既定は「選択範囲を置き換える」。固定長ドキュメントでは「新しいタブで開く」だけを使える。
7. 展開後の大きさの上限: 設定「展開の確認を出す大きさ」(既定 4 GiB)。展開の途中で超えた場合は一時停止し、確認ダイアログで「展開後のデータが 4 GiB を超えました (圧縮前 N MB)」と示し、「続ける」「中止する」を選ばせる (圧縮爆弾への対策)。
8. 派生ドキュメント (EDIT-46) として開くと、展開したデータを編集して元の位置に再圧縮して書き戻せる。

**画面**: ContentDialog。形式、レベル、書き込み先、自動判別の結果の表示。

**巨大ファイル・長時間処理**: すべての形式をストリームで処理し (1 MiB 単位で読み、一時ファイルへ書く)、大きさの上限は設けない。4 MiB を超える場合は長時間処理。

**エラー**: 展開時のデータ破損 (「オフセット 0x… で圧縮データが壊れています」。それまでに展開できた分を新しいタブで開くかを選べる)、チェックサム (gzip の CRC-32、zlib の Adler-32、zstd の XXH64) の不一致 (警告し、結果を使うかを選べる)。

**受け入れ基準**:

- [ ] 各形式で圧縮してから展開すると元に戻る (自動テスト)。
- [ ] 他のツール (7-Zip、zstd コマンド、gzip) で作った各形式のデータのうち、自動判別の手がかりがある形式 (gzip、zlib、zstd、LZ4 フレーム、XZ、LZMA) は自動判別で展開できる。手がかりのない形式 (deflate (raw)、Brotli、LZ4 ブロック) は、自動判別できない旨を示して形式の選択を求め、選んだ形式で展開できる。
- [ ] 1 MiB の zip ファイル内のローカルファイルヘッダの直後で「圧縮データの範囲を選択」を実行すると、deflate の範囲が選択される。
- [ ] 展開後に 4 GiB を超える圧縮爆弾のテストデータで確認ダイアログが出て、中止するとデータが変わらない。

### EDIT-42 パッチの作成

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-03 |
| 呼び出し | データ > パッチ > パッチを作成…、比較 (06) の結果画面の「パッチを作成」、履歴パネル (EDIT-20、EDIT-21) の「この 2 時点からパッチを作成」、コマンドパレット「パッチを作成」。ショートカットは既定なし |

**概要**: 編集前と編集後の違いを、IPS・IPS32・BPS・UPS、またはこのアプリ独自の形式のパッチファイルに書き出す。パッチの作成・適用の操作はこの項目と EDIT-43 が主担当で、IPS / IPS32 のファイル形式と書き出しの規則は TOOL-12、コマンドラインからの適用は AUTO-43 で定める (00-overview.md 1.1)。

**仕様**:

1. 差分の取り方:
   - 「保存されている内容と現在の内容」(既定): データエンジンのピースツリーから変更箇所を求める (読み込み不要)。
   - 「2 つのファイル (タブ)」: 比較 (06) の結果を使う。
   - 「履歴の 2 時点」: 履歴パネルで選んだ 2 つの状態のピースツリーの違いを使う。
2. 形式:

   | 形式 | 扱える範囲 | 長さの変化 |
   | --- | --- | --- |
   | IPS | オフセット 0〜0xFFFFFF (16 MiB 未満)。レコードの分割・RLE などの書き出しの規則は TOOL-12 | 末尾の切り詰め (拡張の 3 バイト) のみ。途中の挿入・削除は、以降のバイトの上書きとして表す |
   | IPS32 | オフセット 0〜0xFFFFFFFF (4 GiB 未満)。形式は TOOL-12 | IPS と同じ |
   | UPS | 可変長整数のオフセット (上限なし)。変換前・変換後・パッチの CRC-32 を含む | 長さの変化を表せるが、途中の挿入・削除は以降の差分になる |
   | BPS | 上限なし。変換前・変換後・パッチの CRC-32 を含む。元データからのコピー命令で挿入・削除を効率よく表す | 表せる |
   | 独自形式 (`.hexpatch`) | 上限なし (64 bit のオフセット)。zip 形式で、命令の一覧 (JSON: 置き換え・挿入・削除と位置・長さ) と、データ (`data.bin`) を入れる。変換前のファイルの識別情報 (長さ、先頭・中央・末尾の各 1 MiB の SHA-256、任意で全体の SHA-256) を含める | 表せる (ピースの操作をそのまま記録する) |

3. IPS / IPS32 のレコードは TOOL-12 の書き出しの規則 (オフセット 0x454F46 の回避を含む) で作る。
4. 形式で表せない差分がある場合 (IPS で 16 MiB 以上のオフセットなど) は作成せず、エラーで理由と、使える形式を示す。形式の選択欄で「自動」を選んだ場合は TOOL-12 の 3 に従い、16 MiB 以上の変更があれば IPS32 を選ぶ。
5. 途中の挿入・削除を含む差分を IPS / IPS32 / UPS で作ると、以降のすべてのバイトが差分になる。推定サイズが変換後のデータの 50% を超える場合は「この形式では挿入・削除を効率よく表せません。BPS または独自形式を使ってください」と警告する。
6. 作成前に、レコード数・パッチの推定サイズを表示する。

**画面**: ContentDialog。差分の取り方、形式 (表せない形式は理由付きで無効)、出力ファイル、推定サイズ。

**巨大ファイル・長時間処理**: 「保存されている内容と現在の内容」の差分は、ピースツリーの変更箇所の列挙で O(ピース数)。パッチファイルへの書き出しは変更データの量に比例する長時間処理。BPS・UPS の CRC-32 は変換前・変換後の全体を読むため、ファイルサイズに比例する長時間処理 (進捗・キャンセル)。

**エラー**: 形式で表せない (上記 4)。書き出し先の容量不足 (開始前に確認)。

**受け入れ基準**:

- [ ] 3 か所を書き換えたファイルから IPS を作り、別ツール (Flips など) で元ファイルに適用すると、書き換え後と一致する。
- [ ] 途中に 100 バイトを挿入したファイルから BPS を作ると、パッチが 1 KiB 未満になる。
- [ ] 16 MiB を超えるオフセットの変更がある場合、IPS が無効になり理由が表示される。
- [ ] 独自形式で作ったパッチを EDIT-43 で適用すると、元の変更と一致する。

### EDIT-43 パッチの適用

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-03 |
| 呼び出し | データ > パッチ > パッチを適用…、コマンドパレット「パッチを適用」。ショートカットは既定なし |

**概要**: IPS・IPS32・UPS・BPS・独自形式のパッチを、開いているドキュメントに適用する。適用は通常の編集として行い、元に戻せる。IPS / IPS32 の読み込みの規則は TOOL-12、コマンドラインからの適用 (`hexed patch`) は AUTO-43 で定める。

**仕様**:

1. パッチファイルを選ぶと、ヘッダで形式を判別する (`PATCH` → IPS、`IPS32` → IPS32、`UPS1` → UPS、`BPS1` → BPS、zip 内の独自の目印 → 独自形式)。判別できない場合はエラー。
2. 適用前にダイアログで、形式、レコード数、変更するバイト数、適用後の長さ、変換前の確認の結果を表示する。
3. 変換前の確認:
   - UPS・BPS: 現在のドキュメントの CRC-32 と、パッチに記録された変換前の CRC-32 を比べる。
   - 独自形式: 長さと部分的な SHA-256 (全体の SHA-256 があればそれも) を比べる。
   - IPS・IPS32: 確認の手段がないため「確認できません」と表示する。
   - 一致しない場合は「このパッチは別のファイル用の可能性があります」と警告し、「適用する」「キャンセル」を選ばせる (既定のボタンは「キャンセル」)。
4. 適用はドキュメントへの 1 つの編集グループとして行う (ファイルには保存するまで書かない)。
5. UPS・BPS では、適用後の CRC-32 を確認し、一致しない場合は適用を取り消してエラーにする。
6. 固定長ドキュメントでは、長さが変わるパッチは適用しない。
7. 「逆適用」(UPS と独自形式のみ): 適用後の状態から適用前に戻す方向に適用する。

**画面**: ContentDialog。パッチの情報、確認の結果 (一致 / 不一致 / 確認できません を文字とアイコンで)、「適用」「キャンセル」。

**巨大ファイル・長時間処理**: レコードの適用はピース操作で、変更データの量に比例する。CRC-32 の計算はファイルサイズに比例する長時間処理 (進捗・キャンセル。「確認を省略して適用」ボタンを付ける)。

**エラー**: 形式の判別失敗、パッチの破損 (「レコード N が壊れています」)、範囲外のオフセット (固定長ドキュメントで末尾を超える場合)、適用後の CRC 不一致。

**受け入れ基準**:

- [ ] Flips で作った IPS と BPS のパッチを適用すると、期待するファイルと一致する。
- [ ] 違うファイルに BPS を適用しようとすると、CRC 不一致の警告が出る。
- [ ] パッチの適用を Ctrl+Z 1 回で取り消せる。

### EDIT-45 変換ビュー (XOR ビューなど)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | データ > 変換ビュー…、データ > 変換ビュー > XOR して表示…、ステータスバーの変換ビューの表示をクリック、コマンドパレット「変換ビューの設定」「XOR して表示」「変換ビューの解除」「この変換をデータに適用」。ショートカットは既定なし |

**概要**: データを変えずに、XOR などの変換をかけた結果を表示する。表示上で入力すると、逆変換してから元のデータに書き込む。XOR で隠されたデータを、復号せずにそのまま読み書きするときに使う。廃止した VIEW-44 (見かけ上の XOR 表示) の機能はこの項目に統合した (00-overview.md 1.1)。

**仕様**:

1. 変換は次の演算を最大 8 個まで順につなげて定義する: XOR (数値またはバイト列の鍵。EDIT-33 の鍵の指定と同じ)、加算・減算 (要素の大きさでラップ)、NOT、左右ローテート、バイトスワップ (16 / 32 / 64 bit)、ビット順の反転、ニブルの入れ替え。要素の大きさ・エンディアン・オペランドの増分は EDIT-31 と同じ。
2. XOR の鍵の入力: Hex バイト列 (00-overview.md 6.3。1〜256 バイト) または数値 (00-overview.md 6.1 の入力式。要素の大きさに収まる値)。バイト列の鍵は鍵の長さで繰り返し、オフセット *o* のバイトは `data[o] XOR key[(o − 鍵の起点) mod 鍵の長さ]` で表示する (*o* が鍵の起点より前のときも mod は 0 以上の値で計算する)。
3. 適用範囲: ドキュメント全体 (既定) / 範囲を指定。鍵の起点は「オフセット 0 から数える」(既定) / 「範囲の先頭から」/ 「オフセットを指定」(入力式)。
4. 「XOR して表示…」は、XOR 1 つだけの変換を、鍵と鍵の起点だけを入力するフライアウトで素早く設定するコマンドである。設定した結果は変換の定義ダイアログで設定したものと同じ扱いになる。
5. 変換は Hex 列・テキスト列・ミニマップ (VIEW-35)・バイトの画像表示 (VIEW-36) など、Hex ビューに付随する表示すべてに適用する。強調表示 (変更されたバイト、選択、検索結果、ブックマーク、テンプレート、色付けルール) の色の重ね順は VIEW-17 に従い、変換ビューによって変えない。
6. 変換ビューでの入力: 入力・貼り付け・塗りつぶし・データ演算で書き込む値は「表示上の値」とみなし、変換の逆変換 (つないだ演算を逆の順に、それぞれの逆演算で) をかけてから元のデータに書き込む。確認は出さないが、変換ビューであることは下記 9 の表示で常に示す。
7. 逆変換を持たない演算 (プラグインが追加する変換 (08 の `ITransformView`) で逆変換を実装していないもの、今後追加する演算で逆演算がないもの) を 1 つでも含む変換ビューは、読み取り専用として表示する。このときデータを変える操作は EDIT-16 と同じく実行せず、InfoBar で「この変換ビューは逆変換がないため編集できません。変換ビューを解除すると編集できます」と示す。1 の演算はすべて逆変換を持つ。
8. 挿入・削除は、要素の境界と鍵の位置がずれるため、変換ビューでは行わない (「変換ビューでは長さを変える編集はできません」と示す)。
9. 変換ビューが有効な間、Hex ビューの左上に「変換ビュー: XOR 5A」のような文字のバッジを表示し、ステータスバーにも同じ文字を表示する。エディタの枠を色と破線で示す (色だけで示さない)。
10. 変換ビューは表示の設定で、編集履歴には残さない。変換ビューを通した編集は通常の編集として履歴に残る。
11. 他の機能が読むデータ: 変換ビューが有効なタブでは、検索・置換 (04)、データインスペクタ (05)、ハッシュ・統計 (06)、構造体テンプレート (07) は、表示されている変換後のデータを対象にする。データインスペクタの扱い (既定で変換後のバイトを解釈し、ツールバーの「元のデータを解釈」で変換前に切り替えられる) は INSP-01 の 12 で定め、検索・ハッシュ・テンプレートも同じ規則 (アクティブなビューの表示どおりのデータを対象にし、その旨を表示する) に従う。変換ビューが無効 (元のデータの表示) では元のデータを対象にする。変換後のデータを対象にしている間は、各機能の画面 (検索バー、インスペクタ、ハッシュの結果、テンプレートの結果) に「変換ビュー: …」の表示を付け、結果の一覧・エクスポートにもその旨を記録する。置換で書き込む値は 6 と同じく逆変換してから書き込む。
12. コピーは変換後 (表示どおり) のデータを入れる。設定「変換ビューでのコピー: 表示どおり (既定) / 元のデータ」。
13. 「この変換をデータに適用…」: 変換ビューの変換を実際のデータに書き込む。データ演算 (EDIT-31〜35) のダイアログを同じ演算・鍵・範囲で開き、確定すると変換ビューを解除する。
14. 変換の定義に名前を付けて保存し、ほかのドキュメントで再利用できる。ドキュメントに付随するデータ (00-overview.md 10 章) に、適用中の変換を保存する。

**画面**: 変換の定義ダイアログ (演算の一覧、追加・削除・並べ替え、各演算の設定、表示のプレビュー)。「XOR して表示…」のフライアウト (鍵の入力欄、鍵の起点の入力欄)。Hex ビューの左上のバッジ。

**巨大ファイル・長時間処理**: 変換は表示する範囲 (見えている行) と、読み込んだブロックに対してだけ行い、ファイル全体は処理しない。表示の速度目標 (00-overview.md 11.1) を満たすこと。変換ビューでのデータ演算・塗りつぶしは EDIT-29、EDIT-31 と同じ長時間処理になる。

**エラー**: 鍵が空、奇数桁、256 バイト超の場合は入力欄に赤枠と説明文を出し、確定ボタンを無効にする。長さを変える編集 (上記 8)、逆変換のない変換ビューでの編集 (上記 7)。

**受け入れ基準**:

- [ ] 鍵 `FF` で XOR して表示すると `00` が `FF` と表示され、保存したファイルは変わらない。
- [ ] 鍵 `01 02` で、オフセット 0 と 1 にそれぞれ `01`、`02` が XOR されて表示される。
- [ ] 変換ビューの間、Hex ビューの左上とステータスバーに変換の内容が文字で表示される。
- [ ] XOR 鍵 `5A` の変換ビューで、元が `1B` のバイトが `41` (A) と表示される。
- [ ] そのビューのテキスト列で `B` を入力すると、元のデータに `18` (0x42 XOR 0x5A) が書き込まれる。
- [ ] 変換ビューを解除すると元のデータの表示に戻り、上記の編集が残っている。
- [ ] XOR 鍵 `5A` の変換ビューで `41` を検索すると元が `1B` の位置が見つかり、検索バーに変換ビューの表示が出る。変換ビューを解除すると同じ検索で見つからない。
- [ ] 「この変換をデータに適用…」で、データ演算の XOR が同じ鍵で開く。
- [ ] 100 GB のファイルで変換ビューを有効にしても、スクロールが 60 fps を保つ。

### EDIT-46 派生ドキュメント (展開・復号したデータの編集と書き戻し)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | 展開 (EDIT-41)・復号 (EDIT-40)・Base64 などのデコードで「新しいタブで開く」を選んだとき、派生ドキュメントのタブの「元に書き戻す」ボタン、コマンドパレット「元に書き戻す」。ショートカットは既定なし |

**概要**: 圧縮・暗号化・エンコードされた範囲を展開・復号した結果を別のタブで編集し、もう一度圧縮・暗号化・エンコードして元の範囲に書き戻す。長さが変わる変換を通して編集するときに使う。

**仕様**:

1. 派生ドキュメントは、元のドキュメントと範囲、適用した変換 (形式と設定) を記録した新しいタブとして開く。タブの見出しは「元のファイル名 [0x100-0x4FF 展開]」の形にする。
2. 派生ドキュメントは通常のドキュメントとして編集できる。
3. 「元に書き戻す」: 派生ドキュメントの内容に逆の変換 (圧縮・暗号化・エンコード) をかけ、元のドキュメントの記録した範囲を置き換える。長さが変わる場合、元のドキュメントが固定長なら書き戻さない。
4. 書き戻しは元のドキュメントへの 1 つの編集グループ。書き戻した後、派生ドキュメントの記録した範囲は新しい長さに更新する。
5. 元のドキュメントで、記録した範囲が別の編集で変わった場合、書き戻すときに確認ダイアログで「元の範囲は派生ドキュメントを開いた後に変更されています」と示し、「上書きして書き戻す」「キャンセル」を選ばせる。
6. 暗号化の書き戻しでは、鍵を改めて入力させる (鍵を保持しないため。EDIT-40 の 7)。IV・ナンスは、既定で開いたときと同じ値を使う。GCM・ChaCha20-Poly1305 では同じナンスを再利用すると安全でないため、新しいナンスを生成するかを選ばせ、既定を「新しいナンスを生成」にする (ナンスの保存位置はデータの形式に依存するため、利用者が書き込み先を確認する)。
7. 元のドキュメントを閉じると、派生ドキュメントは通常の新規ドキュメントになり、書き戻しはできなくなる (InfoBar で知らせる)。
8. 派生ドキュメントからさらに派生ドキュメントを開ける (入れ子は 8 段まで)。

**画面**: 派生ドキュメントのタブの上部に、元のドキュメントと範囲、変換の情報と「元に書き戻す」ボタンを持つ帯を表示する。

**巨大ファイル・長時間処理**: 展開・復号と、書き戻し時の圧縮・暗号化は、EDIT-40、EDIT-41 と同じストリーム処理の長時間処理。

**エラー**: 書き戻しの変換の失敗、元の範囲の変更 (上記 5)、固定長での長さの変化 (上記 3)。

**受け入れ基準**:

- [ ] PNG ファイルの IDAT チャンクの zlib データを派生ドキュメントで開き、1 バイト変えて書き戻すと、元のファイルの該当範囲が再圧縮されたデータに置き換わる。
- [ ] 書き戻しを元のドキュメントで Ctrl+Z 1 回で取り消せる。
- [ ] 元のドキュメントを閉じると、派生ドキュメントの「元に書き戻す」ボタンが無効になる。

## 1. Hex ビューの基本

### VIEW-01 Hex ビューコントロール

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-02 |
| 呼び出し | ドキュメントを開くと各タブ (UI) の中に表示される。コマンドとしての呼び出しはない |

**概要**: ドキュメントの内容を、オフセット列・Hex 列・テキスト列の 3 列で表示する自前描画のコントロール。見えている行だけを描画し、ファイルサイズに関係なく同じ速さで動く。

**仕様**:

1. 列の並びは左から「オフセット列」「Hex 列」「テキスト列」とする。各列の表示・非表示は VIEW-16、テキスト列の追加は VIEW-24 で定める。列と列の間は 2 文字幅の空白をあける。
2. 描画は、見えている行の数だけ用意した TextBlock を使い回して行う (ファイルの大きさに関係なく要素の数は一定)。XAML の `ScrollViewer` は使わない。Win2D は Windows App SDK 2.x で描画面が初期化されないため使わない (2026-10-07 確認)。VIEW-04 の性能目標を満たさない場合は Direct2D + DirectWrite の自前描画に置き換える。
3. フォントは等幅フォント 1 種類を使う。既定は Cascadia Mono、無い場合は Consolas。フォント名と大きさは設定 (UI) で変えられる。既定の大きさは 10 pt (100% 表示で 13.33 epx)。
4. 1 文字の幅 (セル幅) と行の高さは、選んだフォントの半角文字 `0` の送り幅と行の高さから求め、端数は物理ピクセルに合わせて切り上げる。行の高さは既定でフォントの高さ × 1.2。
5. 1 行に表示するバイト数を *b* (VIEW-08)、行の先頭のずれを *a* (VIEW-20、既定 0) とすると、行番号 *r* (0 始まり、`long`) の行は、オフセット `r × b − a` から始まる *b* バイトを表示する (最初の行は先頭の *a* バイト分を空白にする)。
6. 表示上の最終行は、ドキュメントの長さ *L* を含む行とする。データソースが長さを変えられる場合 (ENG)、末尾の次の位置 (オフセット *L*) もカーソルを置けるセルとして空欄で描く。このため *L* が *b* の倍数のときは、空の行が 1 行増える。
7. 長さ 0 のドキュメントでも 1 行を描き、オフセット 0 の空セルにカーソルを置く。
8. 各セルには、次の情報を重ねて描く。どの強調表示をどの順序で重ねるかは VIEW-17 の 5〜9 だけで定める。
   - バイト値の文字 (Hex 列は VIEW-10 の形式、テキスト列は VIEW-21 の文字コード)
   - 背景と文字色 (選択範囲、検索の一致、ブックマーク、注釈、テンプレート、色付けルール、差分、バイトテーマ、現在行、交互色など)
   - 下線・枠・模様 (カーソル、もう一方の列の対応位置、変更されたバイト、読み取れない範囲など)
9. Hex 表示部分 (オフセット列・Hex 列・テキスト列・列見出し) は、UI が右から左に書く言語 (アラビア語・ペルシア語) のときも左から右に描く (00-overview 5.4)。コントロールの `FlowDirection` を `LeftToRight` に固定する。
10. 色はすべてテーマのリソース (`ThemeResource`) から取り、ライト / ダーク / ハイコントラストの切り替えに即時に追従する (再起動不要)。ハイコントラストでは Windows のシステム色 (`WindowText`、`Window`、`Highlight`、`HighlightText`、`GrayText`、`HotTrack`) だけを使う。
11. 表示倍率 (DPI) が変わったとき (別のモニターへの移動を含む) は、セル幅と行の高さを計算し直して再描画する。カーソルのオフセットと、画面上で一番上に見えているオフセットは変えない。
12. ウィンドウの大きさが変わったときは、一番上に見えている行の先頭オフセットを保つ。1 行のバイト数が「自動」(VIEW-08) で変わる場合は、カーソルのある行が画面上の同じ高さに残るように一番上の行を決め直す。
13. コントロールにフォーカスがあるときだけカーソルを点滅表示する。点滅の間隔は Windows の設定 (`GetCaretBlinkTime`) に従い、点滅しない設定ならそれに従う。フォーカスがないときは、カーソル位置を枠線 (点滅なし) で示す。

**画面**: タブの内容領域いっぱいに配置する。右端に縦スクロールバー (VIEW-02)、必要なときだけ下端に横スクロールバー (VIEW-28)。ミニマップ (VIEW-35) を表示する場合は、縦スクロールバーの左に置く。上端に列見出し (VIEW-05)。

**巨大ファイル・長時間処理**: 描画に使うデータは表示中の行の範囲だけをデータエンジン (ENG) に要求する。行番号とオフセットはすべて `long` で計算し、`double` や `int` に変換しない (スクロールバーとの対応だけは VIEW-02 の方法で換算する)。

**エラー**: 読み込みに失敗した範囲は VIEW-03 の「読み取れない」表示にする。描画面の作成に失敗した場合 (GPU のリセットなど) は描画面を作り直して再描画し、3 回続けて失敗したらソフトウェア描画に切り替えて InfoBar で知らせる。

**受け入れ基準**:

- [ ] 100 GB のファイルを開き、先頭・中央・末尾の行が正しいオフセットとバイト値で表示される。
- [ ] 長さ 0 のファイルで 1 行と空セルのカーソルが表示され、例外が起きない。
- [ ] 長さが 1 行のバイト数の倍数のファイルで、末尾の次の位置に空の行が表示される (長さを変えられるデータソースの場合)。長さ固定のデータソースでは表示されない。
- [ ] UI をアラビア語にしても Hex 表示部分が左から右に表示される。
- [ ] ライト / ダーク / ハイコントラストを切り替えると、再起動せずに配色が変わる。
- [ ] 表示倍率の異なるモニター間でウィンドウを移動しても、カーソルのオフセットと一番上のオフセットが変わらない。

### VIEW-02 巨大ファイル用のスクロールバー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-02 |
| 呼び出し | 縦スクロールバーのマウス操作。キー操作は VIEW-25、ホイールは VIEW-28 |

**概要**: 何十億行あっても縦スクロールバーで全体を移動できるように、`long` の行位置とスクロールバーの値を縮尺で対応させる。

**仕様**:

1. 全行数を *R* (`long`)、画面に完全に収まる行数を *V* とし、一番上に表示する行の最大値を *M* = max(0, *R* − *V*) とする。
2. スクロールバーの内部値は 0〜*S* の整数とする。*S* = min(*M*, 1,000,000)。
   - *M* ≤ 1,000,000 のとき (おおむね 16 MB 以下のファイル): 内部値 = 一番上の行番号。つまみの 1 単位が 1 行に対応する。
   - *M* > 1,000,000 のとき: 一番上の行番号 = round(内部値 × *M* / *S*)。逆方向の換算は round(行番号 × *S* / *M*)。計算は 128 bit 整数 (`Int128`) で行い、桁あふれと丸め誤差の蓄積を避ける。
3. つまみをドラッグしたとき、つまみが最上端なら行 0、最下端なら行 *M* を必ず表示する。
4. スクロールバーの矢印ボタンは、縮尺に関係なく 1 回で 1 行動かす。押し続けると繰り返す。
5. つまみの外側 (トラック) のクリックは 1 画面 (*V* − 1 行、最低 1 行) 動かす。
6. 一番上の行が縮尺によって内部値と一致しない場合 (キー操作で 1 行ずつ動かしたときなど) は、つまみの位置を最も近い内部値に合わせるが、表示中の行は変えない。
7. つまみの最小の長さは 16 epx。つまみの長さは *V* / *R* に比例させ、最小値より短くなる場合は最小値にする。
8. つまみをドラッグしている間、つまみの横に「一番上の行の先頭アドレス」をツールチップで表示する (オフセットの書式は VIEW-19)。
9. スクロールバーの上に、ミニマップを表示していない場合でも、カーソル位置・選択範囲・検索結果・ブックマーク・差分の位置を細い印 (幅 4 epx) で表示できる。既定はカーソル位置と検索結果だけ表示。印の種類は VIEW-35 と同じ。
10. ドキュメントの長さが変わったとき (挿入・削除) は *R* と *M* を計算し直し、一番上の行の先頭オフセットが保たれるように行番号を決め直す。

**画面**: Hex ビューの右端。幅は Windows の標準スクロールバーと同じ。

**巨大ファイル・長時間処理**: 換算は定数時間。8 EB (2^63 − 1 バイト) まで扱えること。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 1 TB の仮想データソース (テスト用) で、つまみを最上端・中央・最下端に動かすと、それぞれ行 0、およそ中央、最終行が表示される。
- [ ] 長さ 2^63 − 1 の仮想データソースで、換算に桁あふれがなく、最終行の最終バイトまで表示できる。
- [ ] 1 MB のファイルでは、矢印ボタン 1 回で 1 行、つまみの 1 単位で 1 行動く。
- [ ] 100 GB のファイルで、矢印ボタン 1 回で 1 行だけ動く。
- [ ] つまみのドラッグ中に、一番上の行のアドレスがツールチップで表示される。

### VIEW-03 未読み込み・読み取れないバイトの仮表示

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-02 |
| 呼び出し | 自動 |

**概要**: 描画に必要なデータがまだ読み込まれていない場合は描画を待たずに仮の表示を出し、読み込み終わったら差し替える。読み取れない範囲 (I/O エラー、プロセスメモリの未割り当て領域など) は、それと分かる表示にする。

**仕様**:

1. 描画時に、表示範囲のデータがデータエンジンのキャッシュにない場合は、非同期の読み込みを要求し、その場では仮表示で描く。描画処理は I/O を待たない。
2. 仮表示 (読み込み中): Hex 列は各セルに `··` (U+00B7 を 2 つ)、テキスト列は空白を、`GrayText` 相当の色で描く。オフセット列は通常どおり描く。
3. 読み込み中の表示は、要求から 100 ms 未満で読み込みが終わった場合は出さない (前の描画内容を保ったまま、読み込み完了時に描き直す。スクロールやジャンプで行の先頭オフセットが変わり、その行に保てる前の内容がない場合は、オフセット列だけを描いてセルを空白にする)。100 ms を超えたら仮表示を出す。
4. 読み込みが終わったら、その範囲だけを描き直す。
5. 読み取れない範囲 (データソースが「読み取れない」と返した範囲): Hex 列は `??`、テキスト列は空白とし、背景に斜線の模様を付ける。色だけに頼らないため、模様は必ず付ける。
6. 読み取れないバイトにマウスを合わせると、ツールチップに理由 (例: 「読み取れません: デバイスの I/O エラー (0x0000045D)」「メモリが割り当てられていません」) を表示する。
7. 読み取れない範囲はスクリーンリーダーで「読み取れません」と読み上げる (VIEW-41 の 5、UI-51)。
8. 読み取れない範囲のセルにもカーソルを置ける。編集できるかどうかは EDIT で定める。

**画面**: Hex ビューのセル。

**巨大ファイル・長時間処理**: 読み込み要求は表示中の範囲だけに出す。スクロールで表示範囲から外れた要求は取り消す (キャンセルトークン)。ネットワークドライブや遅いディスクでも UI は止まらない。

**エラー**: 読み込みのエラーは上記 5〜6 で示す。InfoBar は出さない (同じ範囲を何度も描画するたびに通知が出るのを避ける)。ただし最初に読み取れない範囲が見つかったときだけ、ステータスバーに「読み取れない範囲があります」を 5 秒間表示する。

**受け入れ基準**:

- [ ] 読み込みに 2 秒かかるテスト用データソースで、スクロール中も 60 fps を保ち、読み込み中のセルに `··` が表示され、読み込み後に値に置き換わる。
- [ ] 読み込みが 100 ms 未満で終わる場合に仮表示がちらつかない。
- [ ] 読み取れない範囲に `??` と斜線模様が表示され、ツールチップで理由が分かる。
- [ ] ハイコントラストでも読み取れない範囲を見分けられる。

### VIEW-04 描画性能と仮想化

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-02 |
| 呼び出し | 自動 |

**概要**: スクロールとカーソル移動で 60 fps、キー入力から画面反映まで 50 ms 以内を保つための描画の決まりごと。

**仕様**:

1. 描画するのは画面に見えている行と、上下 1 行ずつの余分だけとする。
2. 1 フレームの描画に使うデータは、1 回の要求でデータエンジンから連続した範囲として受け取る (1 バイトずつ読まない)。
3. 毎フレームすべての行の文字列を組み立て直さない。描画は VIEW-01 の 2 のとおり行ごとの TextBlock を使い回し、行ごとに内容 (先頭オフセット・バイト値・セルの状態・選択範囲との重なり・操作中の列・配色) の要約値を持って、要約値が変わった行だけ文字列 (Run) を作り直す。Hex の 2 文字 (`00`〜`FF`) の文字列は事前に作って使い回す。VIEW-01 の 2 により Direct2D + DirectWrite の自前描画に置き換えた場合は、Hex 文字 (`0`〜`F`、`·`、`?`) とテキスト列で使う半角文字のグリフを、フォント・大きさ・色の組ごとに画像 (グリフアトラス) として持ち、全角・結合文字などのアトラスにない文字は DirectWrite で描いて、結果を最大 4,096 文字分キャッシュする (LRU)。
4. 1 行のバイト数が 4,096 で全セルが見えている場合のような描画量の多い場合も、1 フレームあたりの描画時間の目標は 8 ms (一般的な統合 GPU) とする。
5. カーソルの点滅やカーソル移動では、変化した行だけを描き直す。
6. 描画が 1 フレームに間に合わない場合は、背景・文字・強調の順で優先して描き、ツールチップなどの付加情報は次のフレームに回す。
7. 色付け (VIEW-17 の層) の判定は、表示中の範囲について 1 フレームにつき 1 回だけ行う。各層の提供元 (検索結果、ブックマーク、色付けルールなど) には「この範囲に重なる項目」を問い合わせ、全件を走査しない。
8. 性能の計測用に、描画時間と読み込み待ちの回数を記録する診断表示 (既定オフ、設定の「診断」から有効化) を用意する。

**画面**: 診断表示は Hex ビューの右上に半透明の小さな表で重ねる。

**巨大ファイル・長時間処理**: 描画の手間は表示中の行数と 1 行のバイト数にだけ比例し、ファイルサイズに依存しない。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 100 GB のファイルで PageDown を押し続けたとき、60 fps を保つ (OS のキャッシュに載っている範囲。判定は [テスト方針](../test/00-test-strategy.md) の 7.3: フレームの間隔の 99 パーセンタイルが 16.7 ms 以下、かつ最大が 50 ms 以下)。
- [ ] 矢印キーを押してから画面にカーソルの移動が反映されるまで 50 ms 以内。
- [ ] 1 行 4,096 バイト、表示倍率 100% のフル HD 画面で、スクロール中のフレーム時間が 16.7 ms を超えない。
- [ ] ブックマーク 100 万件を設定した状態でも、上記の性能を保つ。

### VIEW-05 列見出し (ルーラー)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | 表示 > 列の構成 > 列見出し。コマンドパレット「表示: 列見出しの表示切り替え」 |

**概要**: Hex 列とテキスト列の上に、行の中での位置 (0, 1, 2, …) を示す見出しを固定表示する。

**仕様**:

1. 見出しは Hex ビューの上端に固定し、縦スクロールしても動かない。横スクロールには追従する。
2. Hex 列の見出しには、各セルの行内での位置をオフセット列と同じ基数 (VIEW-19) で、セルの幅に合わせて表示する。例: 16 進で 1 行 16 バイトなら `00 01 02 … 0F`。グループ化 (VIEW-09) している場合は、グループの先頭の位置だけを表示する。
3. 基数が 10 進・8 進のときはその基数で表示する。セクタ表示のときは 16 進で表示する。
4. 行の先頭のずれ (VIEW-20) がある場合は、行の先頭のアドレスの下位桁に合わせた値を表示する (例: 行が `…08` から始まるなら `08 09 … 17`)。
5. テキスト列の見出しは、既定で行内の位置の最下位の 1 桁 (`0123456789ABCDEF`) を表示する。複数のテキスト列 (VIEW-24) ではそれぞれの見出しに文字コード名を表示し、位置の表示は省く。
6. カーソルのある列の見出しを強調する (VIEW-06)。
7. オフセット列の見出しには、オフセットの基数と表示形式の名前 (例: `Offset (h)`、`LBA`) を表示する。クリックすると基数を切り替えるメニュー (VIEW-19) を出す。
8. 既定は表示。

**画面**: Hex ビュー上端の 1 行。背景は通常の背景より一段階濃い色 (テーマのリソース)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 1 行 16 バイト・16 進で `00`〜`0F` が各セルの真上に表示される。
- [ ] グループ化 4 バイトで、`00 04 08 0C` だけが表示される。
- [ ] 縦スクロールしても見出しが動かず、横スクロールには追従する。

### VIEW-09 バイトのグループ化

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-05 |
| 呼び出し | 表示 > グループ化 (1 / 2 / 4 / 8 / 16 バイト)。コマンドパレット「表示: グループ化」 |

**仕様**:

2. グループ化 1 では、各バイトの間に 1 文字分の空白を入れる。グループ化 *g* (≥ 2) では、グループ内のバイトの間は空白なしで詰め、グループの間に 1 文字分の空白を入れる。

6. テキスト列はグループ化の影響を受けない。
7. ドキュメントの末尾で最後のグループが不完全な場合は、存在するバイトだけを描く。

### VIEW-10 セルの表示形式

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案。Hex 以外の形式。Hex はフェーズ 0) |
| 呼び出し | 表示 > 列の構成 > セルの表示形式。コマンドパレット「表示: セルの表示形式」 |

**概要**: Hex 列の各セルを、16 進以外 (10 進、8 進、2 進、整数、浮動小数点) で表示する。データは変えない。

**仕様**:

1. 選べる形式と、1 セルの単位 (バイト数)、セルの文字数:

   | 形式 | 単位 | 文字数 | 例 |
   | --- | --- | --- | --- |
   | Hex (既定) | 1 | 2 | `4F` |
   | 10 進 (符号なし) | 1 | 3 | `079` |
   | 10 進 (符号あり) | 1 | 4 | `-001`、`+079` |
   | 8 進 | 1 | 3 | `117` |
   | 2 進 | 1 | 8 | `01001111` |
   | 16 bit 整数 (Hex / 10 進符号なし / 10 進符号あり) | 2 | 4 / 5 / 6 | `4F2A`、`20266` |
   | 32 bit 整数 (同上) | 4 | 8 / 10 / 11 | |
   | 64 bit 整数 (同上) | 8 | 16 / 20 / 20 | |
   | float (IEEE 754 単精度) | 4 | 15 | `1.2345679E+08` |
   | double (IEEE 754 倍精度) | 8 | 25 | `1.2345678901234567E+08` |

   float / double の文字数は、最も長い表記 (符号、double の 3 桁の指数、非正規化数の印 `d`。例: `-1.4012985E-45d`、`-4.9406564584124654E-324d`) が入る幅。指数は 2 桁以上で表示する。

2. 10 進と 8 進は既定で桁をそろえるため左を 0 で埋める。設定で「空白で埋める」を選べる。
3. 2 バイト以上の単位では、単位を 1 つのセルとして表示し、値の解釈はエンディアン (VIEW-11) に従う。グループ化のバイト数は単位以上に自動で引き上げる。
4. float / double は指数表記 (有効桁 float 8 桁、double 17 桁、小数点は常に `.`。地域設定に依存しない)。NaN、+Inf、−Inf、非正規化数はそれぞれ `NaN`、`+Inf`、`-Inf` と、値の後に `d` を付けて表示する。
5. ドキュメントの末尾で単位に満たない端数のバイトは、Hex 形式で 1 バイトずつ表示し、背景に点線の枠を付ける。
6. カーソルは単位ごとに動く。Hex 以外の形式でのカーソルはセル全体を強調し、ニブル単位の位置は持たない。
7. Hex 以外の形式でセルに直接入力して編集できるかどうかは EDIT で定める (未決定の場合は読み取り専用表示とし、入力すると「この表示形式では直接編集できません。データインスペクタを使ってください」とステータスバーに出す)。
8. テキスト列は形式の影響を受けない。テキスト列のカーソルはバイト単位で動き、Hex 列の対応位置はそのバイトを含む単位のセルになる。

**画面**: 表示メニューのサブメニュー。現在の形式はステータスバー (VIEW-40) にも表示する。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 2 進形式でバイト `4F` が `01001111` と表示される。
- [ ] 32 bit 符号あり 10 進でリトルエンディアンの `FF FF FF FF` が `-1` と表示される。
- [ ] float 形式で `00 00 C0 7F` (LE) が `NaN` と表示される。
- [ ] 長さ 10 のファイルを 32 bit 形式で表示すると、最後の 2 バイトが Hex で点線の枠付きで表示される。
- [ ] 地域設定がフランス語でも float の小数点が `.` になる。

### VIEW-11 表示のエンディアンと見かけ上のバイトスワップ

| 項目 | 内容 |
| --- | --- |

**エラー**: 該当なし。

### VIEW-15 変更されたバイトの強調

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-05 |
| 呼び出し | 表示 > 列の構成 > 変更されたバイトを強調。コマンドパレット「表示: 変更されたバイトの強調」 |

**概要**: 保存されていない変更があるバイトを、色と下線の両方で示す。

**仕様**:

1. 既定はオン。
2. 「変更されたバイト」とは、データエンジン (ENG) のピースのうち、元データ以外 (追加データ・塗りつぶし) のピースに含まれるバイトとする。元と同じ値で上書きした場合も変更として示す。Undo で元データのピースに戻った場合は変更として示さない。
3. 上書きされたバイト: テーマの「変更」色 (既定は赤系) の文字と、1 px の実線の下線で示す。
4. 挿入されたバイト: テーマの「挿入」色 (既定は緑系) の文字と、2 本線の下線で示す。上書きと挿入の区別は ENG が提供する (提供できない場合は上書きと同じ表示にする)。
5. 削除された位置: 削除によって詰まった境界の左側のセルの右端に、縦の赤い線 (幅 2 px) を表示する。既定オフ (設定「削除位置を表示」)。
6. ハイコントラストでは色を変えず、下線 (実線 / 2 本線) だけで示す。色だけで区別しない (00-overview 11.5)。
7. Hex 列とテキスト列の両方に適用する。
8. 保存すると強調を消す (保存後の内容が新しい元データになるため)。設定「保存後も閉じるまで強調を残す」(既定オフ) をオンにすると、閉じるまで別の色 (テーマの「保存済みの変更」色、下線は点線) で残す。
9. スクリーンリーダーは、変更されたバイトを読み上げるときに「変更あり」または「挿入」を付ける (VIEW-41 の 5、UI-51)。

**画面**: Hex 列・テキスト列のセル。

**巨大ファイル・長時間処理**: 変更されたかどうかの判定は、表示中の範囲についてピースの境界を調べるだけで行い、ファイル全体の比較はしない。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 1 バイトを上書きすると、色付きの文字と実線の下線が表示される。
- [ ] Undo すると強調が消える。
- [ ] 挿入したバイトが 2 本線の下線で表示される。
- [ ] ハイコントラストで、変更されたバイトが下線で見分けられる。
- [ ] 保存すると強調が消える。

### VIEW-17 バイトテーマ (値による色分け) と色の重ね順

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 表示 > バイトテーマ (なし / 種類別 / グラデーション / 独自…)。コマンドパレット「表示: バイトテーマ」 |

**概要**: バイトの値に応じて文字色を変え、データの種類を見分けやすくする。あわせて、各機能が付ける色の重ね順を定める。

**仕様**:

1. 既定は「なし」。
2. 用意するテーマ:

   | テーマ | 内容 |
   | --- | --- |
   | なし | 通常の文字色 (ゼロのグレー表示 VIEW-13 は有効) |
   | 種類別 | `00`、`FF`、印字可能な ASCII (`20`〜`7E`)、空白類 (`09` `0A` `0D` `20`)、その他の制御文字 (`01`〜`1F`、`7F`)、`80`〜`FE` の 6 種類に色を分ける |
   | グラデーション | 値 0〜255 を連続した色の帯に対応させる (色覚の多様性に配慮した配色。例: cividis 系) |
   | 独自 | JSON ファイルで 256 個の値それぞれに文字色と背景色 (省略可) を指定する |

3. 独自テーマの JSON の形式:

   ```json
   {
     "name": "My theme",
     "light": {
       "00": "#808080",
       "FF": "#C00000",
       "20-7E": "#0050A0",
       "0A": { "text": "#000000", "background": "#FFE080" }
     },
     "dark": {
       "00": "#707070",
       "FF": "#FF6060",
       "20-7E": "#70B0FF",
       "0A": { "text": "#FFFFFF", "background": "#604000" }
     }
   }
   ```

   - キーは 2 桁の Hex 値、または `XX-YY` の範囲。後に書いたものが優先する。
   - 値は、文字色だけを指定する場合は色の文字列、背景色も指定する場合は `text` (文字色) と `background` (背景色) を持つオブジェクトとする。オブジェクトではどちらか一方を省略でき、省略した側は通常の色 (下の層の色) を使う。
   - 色は `#RRGGBB` または `#AARRGGBB`。`light` と `dark` を別に書く。片方しかない場合は両方に使う。
4. ハイコントラストではバイトテーマを無効にする (システム色だけを使う)。そのことを表示メニューの項目に「(ハイコントラストでは無効)」と表示する。
5. 色の重ね順: Hex ビューのセルに付くすべての強調表示の順序は、この表だけで定める (00-overview 1.1)。他の文書 (EDIT、FIND、INSP、ANA、TPL) は、自分の層の色・形だけを定め、順序はこの表に従う。順位の小さいものほど手前 (優先) とする。

   | 順位 | 層 | 主担当 | 背景 | 文字色 | 枠・線・模様 |
   | --- | --- | --- | --- | --- | --- |
   | 1 | カーソルと対応位置 | VIEW-06 | 上書きモードの帯 | — | 枠、挿入モードの縦棒 |
   | 2 | 選択範囲 (マルチ選択を含む) | EDIT-01〜EDIT-07 | ○ | ○ | — |
   | 3 | 注目している範囲の強調 (インスペクタの対象 INSP-18、逆アセンブルの現在の命令 ANA-23、追従構造体の範囲 TPL-26、テンプレートデバッガの現在位置 `$` TPL-32) | INSP-18 ほか各機能 | ○ (INSP-18 のみ) | — | 枠 (機能ごとに線の種類を変える) |
   | 4 | 現在の検索の一致 | FIND-12 | ○ | — | 枠 |
   | 5 | その他の検索の一致 | FIND-12 | ○ | — | — |
   | 6 | 変更されたバイト | VIEW-15 | — | ○ | 下線 (実線・2 本線・点線) |
   | 7 | ブックマーク | INSP-23 | ○ | — | ハイコントラストでは枠 |
   | 8 | 注釈 (ブックマーク・テンプレート以外の出どころ: YARA、すべて検索の結果、スクリプト・プラグイン) | INSP-32 | 出どころの設定による | — | 出どころの設定による (枠・下線) |
   | 9 | テンプレートの範囲の色分け | TPL-23 | ○ | — | ハイコントラストでは境目の線 |
   | 10 | 色付けルール (ルールどうしの優先順位は INSP-34) | INSP-33 | ○ | ○ | 枠 (実線・破線・点線) |
   | 11 | 差分 (比較 ANA、並列表示の「違いを強調」VIEW-39) | ANA-02〜ANA-04 | ○ | — | 差分の種類ごとの模様 |
   | 12 | バイトテーマ | この機能 | 独自テーマで指定した場合 | ○ | — |
   | 13 | ゼロのグレー表示 | VIEW-13 | — | ○ | — |
   | 14 | 現在行 | VIEW-06 | ○ | — | ハイコントラストでは上下の線 |
   | 15 | レコードの交互色 | VIEW-18 | ○ | — | ハイコントラストでは境界の線 |
   | 16 | 列の交互色 | VIEW-14 | ○ | — | ハイコントラストでは縦の点線 |
   | 17 | 通常の背景・文字色 | VIEW-01 | ○ | ○ | — |

6. 重ね方の規則:
   - 背景と文字色は、それぞれ「その種類を指定している最も手前の層」のものを使う。奥の層の背景は手前の層の背景に隠れる。
   - 枠・線・模様は、種類が違えば複数の層のものを同時に描く。同じ種類 (例: 枠どうし) が重なった場合は手前の層のものを描く。
   - 変更されたバイトの下線 (層 6) は、どの層が重なっても必ず描く (色だけで情報を伝えないため。00-overview 11.5)。
   - ブックマーク・注釈・テンプレート・色付けルールの背景 (層 7〜10) は、選択範囲・検索の一致 (層 2〜5) の下に隠れる場合も、セルの下端に高さ 2 px の帯として残す (選択中でも分かるように)。帯は変更されたバイトの下線のすぐ上に描く。
   - 同じ層の中での重なり (注釈どうし、色付けルールどうし、テンプレートの入れ子) の扱いは、それぞれの主担当 (INSP-32、INSP-34、TPL-23) で定める。
7. 読み込み中・読み取れないバイト (VIEW-03): 値がないため、値で決まる層 (層 10 のうち値・パターンの条件のもの、層 12、層 13) は適用しない。セルの文字は VIEW-03 の仮表示 (`··`、`??`) にし、読み取れない範囲の斜線の模様は、ほかの層の背景の上に必ず描く (層 1〜9 の枠・線もその上に描く)。
8. 区切り線 (VIEW-33)、インスペクタの配列モードの要素の境界線 (INSP-21) は、セルの境目に引く線で、この表の層とは重ならない。
9. 文字色と背景色のコントラスト比が 3:1 未満になる組み合わせでは、文字色を通常の文字色 (背景に対して 4.5:1 以上) に置き換える。背景は、そのセルの層 (選択範囲、ブックマーク、注釈、テンプレート、色付けルール、差分、バイトテーマ、現在行、レコード・列の交互色) の背景を重ねた結果の色で判断する。通常の文字色でも 4.5:1 に届かない背景では、黒か白のうち比の高い方にする。ハイコントラストでは置き換えない (システム色だけを使う)。

**画面**: 表示メニューのサブメニュー。独自テーマは「独自…」でファイルを選ぶ。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 独自テーマの JSON が不正な場合は、何行目のどのキーが不正かを InfoBar で示し、テーマを変えない。

**受け入れ基準**:

- [ ] 「種類別」で 00、FF、ASCII 文字、制御文字、80〜FE がそれぞれ違う色で表示される。
- [ ] 独自テーマの JSON を読み込むと、指定した色で表示される。不正な JSON では行番号付きのエラーが出る。
- [ ] ブックマークのあるバイトを選択しても、セル下端の帯でブックマークが分かる。
- [ ] 色付けルールが付いた変更済みのバイトで、変更の下線が必ず表示される。
- [ ] 読み取れない範囲にブックマークがあっても、斜線の模様が見える。
- [ ] ハイコントラストでバイトテーマが無効になる。
- [ ] 背景とのコントラストが低い組み合わせで、文字が読める色に置き換わる。

### VIEW-18 レコード表示

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-16 |
| 呼び出し | 表示 > レコード表示…。コマンドパレット「表示: レコード表示の設定」「表示: レコード表示の切り替え」「移動: 次のレコード」「移動: 前のレコード」(ショートカットは既定なし) |

**概要**: 固定長のレコードが並んだデータを、レコードごとに背景色を交互に変えて表示する。

**仕様**:

1. 設定項目:

   | 項目 | 既定値 | 範囲 |
   | --- | --- | --- |
   | レコード長 | 16 | 1〜2^31 − 1 バイト (入力式) |
   | 最初のレコードの開始オフセット | 0 | 0〜ドキュメントの長さ (入力式) |
   | 1 行を 1 レコードにする | オフ | レコード長が 4,096 以下のときだけ選べる |
   | オフセット列にレコード番号を表示 | オフ | |

2. 開始オフセットより前のバイトは、レコードの色を付けない (ヘッダとして扱う)。
3. レコード番号 *n* (0 始まり) は、開始オフセット + *n* × レコード長 から始まる。偶数番のレコードは通常の背景、奇数番のレコードは「レコードの交互色」で塗る。ハイコントラストでは塗らず、レコードの境界に実線を引く。
4. 「1 行を 1 レコードにする」をオンにすると、1 行のバイト数をレコード長にし、行の先頭のずれ (VIEW-20) を開始オフセットに合わせる。
5. 「オフセット列にレコード番号を表示」をオンにすると、オフセット列を `#レコード番号:レコード内の位置` の形式 (例: `#1024:0004`) で表示する。レコード番号は 10 進、レコード内の位置はオフセットの基数に従う。
6. 「次のレコード」「前のレコード」は、カーソルを同じレコード内の位置を保ったまま、次・前のレコードに移す。移動先がない場合は移動しない。
7. ステータスバー (VIEW-40) に、カーソルのあるレコード番号とレコード内の位置を表示する (レコード表示がオンのとき)。
8. 入力式の名前 `rec` (レコード長) と `recno` (カーソル位置のレコード番号、0 始まり) は、この機能の設定値から求める (定義は 00-overview 6.2)。開始オフセットより前にカーソルがある場合、`recno` は入力エラーにする。レコード表示がオフのときは、最後に設定したレコード長と開始オフセットを使う。
9. 挿入・削除でドキュメントの長さが変わっても、レコードの区切りは開始オフセットとレコード長から計算し直す (区切りはデータに追従しない)。

**画面**: 設定はフライアウトの入力欄 (モーダルにしない)。変更はその場で反映する。

**巨大ファイル・長時間処理**: レコードの区切りは計算で求め、レコードの一覧は作らない。

**エラー**: レコード長が 0 以下・範囲外の場合は入力欄に赤枠と説明文を出す。

**受け入れ基準**:

- [ ] レコード長 100、開始オフセット 0x40 で、0x40 以降が 100 バイトごとに交互の背景で表示される。0x40 より前は色が付かない。
- [ ] 「1 行を 1 レコードにする」で 1 行に 1 レコードが表示される。
- [ ] 「次のレコード」でカーソルがレコード長だけ進む。
- [ ] ハイコントラストでレコードの境界が線で示される。
- [ ] ステータスバーにレコード番号が表示される。

### VIEW-19 オフセットの基数と表示形式

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-05 |
| 呼び出し | 表示 > オフセットの基数 (16 進 / 10 進 / 8 進 / セクタ)。列見出し (VIEW-05) のオフセット列をクリック。コマンドパレット「表示: オフセットの基数」 |

**概要**: オフセット列とステータスバーなどのオフセット表記を、16 進・10 進・8 進・セクタ (LBA) で表示する。

**仕様**:

1. 既定は 16 進。
2. 各形式:

   | 形式 | 表記 | 例 |
   | --- | --- | --- |
   | 16 進 | 0 埋めの 16 進 | `00001F00` |
   | 10 進 | 0 埋めなし、右寄せ | `7936` (左を空白で埋めて右寄せ) |
   | 8 進 | 0 埋めの 8 進 | `00017400` |
   | セクタ | `セクタ番号 (10 進):セクタ内の位置 (16 進)` | `15:100` |

3. 桁数は、ドキュメントで表示しうる最大のアドレス (ベースアドレス + 長さ) を表せる桁数とし、16 進では最低 8 桁にする。ドキュメントを開いている間は、長さが増えて桁数が足りなくなったときだけ桁数を増やす (表示中に幅が揺れないようにする)。
4. オフセット列の 10 進表記には桁区切りを付けない (列の幅をそろえるため)。ステータスバーやツールチップの 10 進表記は地域設定の桁区切りを付ける。
5. 16 進のとき、桁区切り `:` を 4 桁ごとに入れる設定がある (既定オフ。例: `0000:1F00`)。
6. セクタ形式のセクタサイズは、ディスク・ボリュームではデータソースのセクタサイズ、ファイルでは 512 (00-overview 6.2 の `sector`)。ファイルのセクタサイズは表示設定で変えられる (512、1,024、2,048、4,096、任意)。
7. 基数の設定は、オフセット列、列見出し、ステータスバーのカーソル位置・選択範囲、ツールチップ、移動バーの解釈結果の表示に共通に使う。ただしツールチップは常に 16 進と 10 進を併記する。
8. 入力欄で接頭辞のない数値をどう解釈するかは 00-overview 6.1 の規則 (基数の設定に連動) に従う。

**画面**: 表示メニューのサブメニュー (ラジオ選択)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 10 進に切り替えると、オフセット列とステータスバーのカーソル位置が 10 進になる。
- [ ] セクタ形式で、オフセット 0x1F00 が `15:100` と表示される (セクタサイズ 512)。
- [ ] 100 GB のファイルで、オフセット列の桁数がスクロール位置によって変わらない。
- [ ] 10 進表示でも、移動バーに `0x1F00` と入力して移動できる。

### VIEW-20 ベースアドレス・行の先頭のずれ・基準点

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | 表示 > オフセットの基数 > ベースアドレスを設定… / 行の先頭をずらす… / カーソル位置を基準点にする / 基準点を解除。右クリックメニュー「ここを基準点にする」。コマンドパレット「表示: ベースアドレスの設定」ほか |

**概要**: オフセットに定数を足した「アドレス」で表示する。行の区切り位置をずらす。任意の位置を 0 とした相対オフセットで表示する。

**仕様**:

1. ベースアドレス: 0〜2^64 − 1 の値を入力式で指定する。既定は 0。表示上のアドレス = オフセット + ベースアドレス (00-overview 3 章)。アドレスの上限は 2^64 − 1 で、カーソルを置ける最大の位置 (VIEW-25 の 1 の最大値。長さを変えられるデータソースでは末尾の次の位置 *L*) のアドレスが 2^64 − 1 を超えるベースアドレスは確定できない。アドレスで指定する移動 (VIEW-29) も、この最大の位置のアドレスまで受け付ける。
2. プロセスメモリのドキュメントでは、ベースアドレスは仮想アドレスに自動で合わせ、変更できない (ENG)。
3. ベースアドレスを設定すると、オフセット列・ステータスバーはアドレスで表示する。ステータスバーにはベースアドレスを使っていることを示す `@` を付ける (例: `@00401F00`)。
4. 移動バー (VIEW-29) は、「アドレスで指定」と「オフセットで指定」を切り替えられる。ベースアドレスを設定しているときの既定は「アドレスで指定」。
5. 行の先頭のずれ: 0〜(1 行のバイト数 − 1) の値。既定は 0。設定「行の先頭をアドレスの区切りにそろえる」(既定オン) のときは、アドレスが 1 行のバイト数の倍数になる位置で行を区切るよう、ずれを自動で計算する (例: ベースアドレス 0x401004、1 行 16 バイトなら、最初の行は 4 バイト分空白)。
6. 基準点: 「カーソル位置を基準点にする」で、カーソルのオフセットを基準点 *p* として記録する。基準点があるとき、オフセット列とステータスバーに相対オフセット (オフセット − *p*、符号付き。例: `-00000010`、`+00000020`) を表示し、ステータスバーに `相対` と表示する。「基準点を解除」で元に戻す。
7. 基準点は挿入・削除に追従する (基準点より前で挿入・削除が起きたら位置をずらす)。基準点が削除された範囲に入った場合は、削除範囲の先頭に移す。
8. ベースアドレス、行の先頭のずれ、基準点はドキュメントごとの表示設定 (VIEW-42) として保存する。

**画面**: 入力はフライアウトの入力欄。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 範囲外の値は入力欄に赤枠と説明文を出す。

**受け入れ基準**:

- [ ] ベースアドレス 0x400000 で、オフセット 0 の行が `00400000` と表示される。
- [ ] ベースアドレス 0x401004 で、最初の行の先頭 4 バイトが空白になり、2 行目が `00401010` から始まる。
- [ ] 基準点を設定すると、基準点より前が `-`、後が `+` で表示される。
- [ ] 基準点より前に 16 バイト挿入すると、基準点が 16 バイト後ろにずれる。

### VIEW-21 テキスト列の文字コード

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-06 (フェーズ 0 では ASCII と ANSI だけ) |

2. 選べる文字コード:

4. 状態を持つ文字コード (ISO-2022 系、UTF-7、HZ、SO/SI で切り替える 2 バイトの EBCDIC (930、939 など)) は、任意の位置から正しく表示できないため、テキスト列では選べない。一覧には表示し、選べない理由を説明文で示す。これらは文字コード変換 (EDIT) では使える。
5. 1 バイトの文字コードでは、各バイトを 1 セルに 1 文字で表示する。
6. 表示しない文字 (既定では `.` で表示する): 制御文字 (`00`〜`1F`、`7F`、その文字コードで C1 制御文字に当たる `80`〜`9F`)、その文字コードで未定義のバイト、フォントと代替フォントのどちらにもない文字 (00-overview 5.4)。
7. 表示しない文字の記号は設定で選べる: `.` (既定)、空白、制御文字の図記号 (U+2400〜U+2421。例: `00` は `␀`)。

9. 文字コードを変えても、カーソルのオフセットと選択範囲は変わらない。
10. 右から左に書く文字 (アラビア文字、ヘブライ文字) も、セルの並びは左から右のまま、1 文字ずつセルに描く。双方向テキストの並べ替えは行わない。
11. テキスト列に入力するときの文字コードも、この設定に従う (入力の規則は EDIT)。

**巨大ファイル・長時間処理**: 該当なし (表示中の範囲だけを解読する)。

**エラー**: OS が提供しないコードページは一覧に出さない。

**受け入れ基準**:

- [ ] 文字コード 1252 で `E9` が `é`、437 で `82` が `é` と表示される。
- [ ] EBCDIC 037 で `C1` が `A` と表示される。
- [ ] ISO-2022-JP が一覧で選べず、理由が表示される。
- [ ] 文字コード一覧で `932` または `jis` と入力すると Shift_JIS に絞り込まれる。
- [ ] アラビア文字のバイト列が、左から右のセル順で 1 文字ずつ表示される。
- [ ] 制御文字の図記号を選ぶと、`00` が `␀` と表示される。

### VIEW-22 マルチバイト文字の表示規則

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-06 |
| 呼び出し | VIEW-21 で UTF-8 / UTF-16 / UTF-32 / CJK の文字コードを選んだとき自動 |

**概要**: 1 文字が複数バイトになる文字コードを、バイトのセルの並びを崩さずに表示する規則。

**仕様**:

1. テキスト列は常に 1 バイト = 1 セル (半角 1 文字分の幅) とする。マルチバイトの文字でもセルの数は変えない。
2. 複数バイトの文字は、その文字の先頭バイトのセルから、文字のバイト数分のセルの範囲 (以下「文字の範囲」) に描く。
   - 全角文字 (東アジアの文字幅が W / F の文字) は 2 セル分の幅で描く。文字の範囲が 2 セル以上あれば、先頭の 2 セルに描く。
   - 半角の文字は先頭の 1 セルに描く。
   - 文字の範囲の残りのセルは空白にする (設定で「続きの記号 `·` を薄く表示」を選べる。既定オフ)。
3. 文字の範囲が行末をまたぐ場合 (例: 3 バイトの UTF-8 が行末の 1 バイトから始まる): 文字は始まりの行の末尾のセルに描き、文字の幅がセルに収まらない場合は横方向に縮小して収める。次の行の先頭の続きのセルは空白 (または続きの記号) にする。
4. 解読を始める位置 (同期点) の決め方。表示する位置に関係なく、同じバイトは常に同じ文字として表示されるようにする:
   - UTF-8: 表示範囲の先頭から最大 3 バイト戻り、後続バイト (`80`〜`BF`) でない最初のバイトから解読する。
   - UTF-16: 「開始位置の偶奇」(既定: 偶数オフセットから) で決まる 2 バイトの区切りで解読する。上位サロゲートから始まる 4 バイトを 1 文字とする。
   - UTF-32: 4 バイトの区切り (開始位置はオフセットを 4 で割った余り 0〜3 から選べる。既定 0) で解読する。
   - 2 バイトの CJK 文字コード (Shift_JIS、GBK、Big5 など): 表示範囲の先頭から戻って、「その文字コードで 2 バイト目になりえないバイト」の直後を同期点とする。4 KiB 戻っても見つからない場合は、オフセットが 4,096 の倍数の位置を同期点とする。
   - GB18030: 上記に加えて 4 バイトの文字を扱う。
5. 不正なバイト列 (UTF-8 の不正なシーケンス、対になっていないサロゲート、未定義の 2 バイト目など): 各バイトを 1 セルずつ「不正」の記号 (既定 `.`。設定で `�` U+FFFD も選べる) で表示し、文字色をテーマの「不正な文字」色にする。不正なバイトの次のバイトから解読をやり直す。
6. 結合文字 (一般カテゴリ Mn / Me)、ゼロ幅の文字 (U+200B〜U+200F、U+2060〜U+2064、U+FEFF)、双方向制御文字 (U+202A〜U+202E、U+2066〜U+2069): 前の文字と合成せず、セルに単独で描く。結合文字は点線の円 (U+25CC) に付けて描く。ゼロ幅・双方向制御文字は表示しない文字の記号 (VIEW-21 の 7) で表示する。
7. 絵文字はモノクロのグリフで描く (カラー絵文字は使わない)。異体字セレクタ (U+FE00〜U+FE0F) は表示しない文字として扱う。
8. BOM (`EF BB BF`、`FF FE`、`FE FF`) はファイルの先頭にあっても特別扱いせず、U+FEFF として 6 の規則で表示する。
9. カーソルがテキスト列にあるとき、カーソルはバイト単位で動く。文字の範囲の途中のバイトにカーソルを置いた場合、その文字の範囲全体を薄く強調する。
10. 選択範囲が文字の範囲の途中で終わる場合も、選択はバイト単位のまま描く。

**画面**: テキスト列。

**巨大ファイル・長時間処理**: 同期点を探すための読み戻しは最大 4 KiB。表示のための解読は「表示中の範囲 + 4 KiB」以内で終わる。

**エラー**: 不正なバイト列は 5 の規則で示す。通知は出さない。

**受け入れ基準**:

- [ ] UTF-8 の `E3 81 82` が `あ` として先頭のセルから 2 セル幅で表示され、3 セル目は空白になる。
- [ ] スクロール位置を 1 行ずつ変えても、同じバイトの文字表示が変わらない (UTF-8、Shift_JIS、UTF-16 で確認)。
- [ ] UTF-16 の開始位置を奇数にすると、1 バイトずれた区切りで表示される。
- [ ] 不正な UTF-8 (`C3 28`) で `C3` が不正の記号と色で表示され、`28` は `(` と表示される。
- [ ] サロゲートペアの絵文字 (UTF-16 LE `3D D8 00 DE`) が 1 文字として表示される。
- [ ] 行末をまたぐ文字が、始まりの行に縮小して表示される。
- [ ] 結合文字が前の文字と合成されずに単独で表示される。

### VIEW-23 独自の文字表 (テーブルファイル)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 表示 > 文字コード > 文字表ファイルを読み込む…。コマンドパレット「表示: 文字表ファイルを読み込む」 |

**概要**: ゲームの ROM などで使われる独自の文字の対応表を読み込み、テキスト列の文字コードとして使う。

**仕様**:

1. 形式は、ROM の改造で広く使われる `.tbl` 形式 (1 行に `16進バイト列=文字列`) に対応する。
   - 例: `41=A`、`8140=` の後に全角空白 1 文字、`FF=<END>`。
   - 左辺は 1〜8 バイトの Hex。右辺は 1 文字以上の文字列。
   - `#` で始まる行と空行は無視する。
   - `/XX=文字列` (終端記号) と `*XX` (改行記号) の記法を受け付ける。終端記号は右辺の文字列で、改行記号は `↵` で表示する。
2. ファイルの文字コードは UTF-8 (BOM の有無どちらも可) と UTF-16 LE (BOM 付き) を受け付ける。
3. 解読は最長一致で行う。各位置で、表にある最も長いバイト列から順に照合する。どれにも一致しないバイトは `.` で表示する。
4. 右辺が複数の文字の場合 (例: `<END>`)、文字の範囲 (左辺のバイト数分のセル) に収まるよう縮小して描く。縮小しても読めない場合 (縮小率 50% 未満) は切り詰めて末尾に `…` を付け、ツールチップで全体を表示する。
5. 同期点は、表示範囲の先頭から 4 KiB 以内の、オフセットが 4,096 の倍数の位置とする。
6. 読み込んだ文字表は、文字コードの一覧の「独自」に名前 (ファイル名) で追加し、次回以降も選べる。設定フォルダにコピーして保存する。
7. テキスト列への入力やテキスト検索で文字表を使えるかどうかは EDIT、FIND で定める。

**画面**: ファイル選択ダイアログ。読み込み結果 (エントリ数、無視した行の数) を InfoBar で表示する。無視した行の数は不正な行 (下記のエラー) の数で、`#` で始まる行と空行は含めない。

**巨大ファイル・長時間処理**: 文字表のエントリ数の上限は 65,536。超える場合は読み込まない。

**エラー**: 不正な行 (`=` がない、左辺が Hex でない、奇数桁) は行番号付きで一覧にし、それ以外の行は読み込む。有効なエントリが 0 件、または上限を超える場合は読み込まず、理由を InfoBar で示す。

**受け入れ基準**:

- [ ] `41=A` と `4142=あ` を含む表で、`41 42` が `あ`、`41 43` が `A.` と表示される (最長一致)。
- [ ] 不正な行があっても他の行は読み込まれ、不正な行の行番号が表示される。InfoBar の無視した行の数は不正な行の数と同じになる (コメント行・空行は数えない)。
- [ ] 一度読み込んだ文字表を、再起動後に文字コードの一覧から選べる。

### VIEW-25 カーソル移動のキー操作

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-03 |
| 呼び出し | ←、→、↑、↓、Home、End、PageUp、PageDown、Ctrl+Home、Ctrl+End、Ctrl+← / Ctrl+→、Ctrl+↑ / Ctrl+↓ (00-overview 8.3)、マウスのクリック。移動メニューにはファイルの先頭・末尾 (VIEW-30) だけを出す |

**概要**: キーボードとマウスでカーソルを移動する規則。Shift を押しながらの移動 (選択範囲の拡張) は EDIT で定め、移動先の決め方はこの機能と同じとする。

**仕様**:

1. カーソルの位置はオフセット *c* と、Hex 列ではニブル (上位 / 下位) で表す。*c* の最大値 (以下「最大値」) は、長さを変えられるデータソースでは *L*、長さを変えられないデータソースでは *L* − 1 (*L* = 0 のときは 0)。*b* は 1 行のバイト数、*u* はセル形式の単位 (VIEW-10。Hex 形式とテキスト列では 1)、*V* は表示行数。
2. 各キーの動作:

   | キー | 動作 |
   | --- | --- |
   | ← | *c* − *u* へ。ニブルは上位にする。*c* = 0 のときは動かない |
   | → | *c* + *u* へ。ニブルは上位にする。最大値のときは動かない |
   | ↑ | *c* − *b* へ (同じ列の 1 行上)。最初の行では動かない |
   | ↓ | *c* + *b* へ (同じ列の 1 行下)。移動先が最大値を超える場合、最終行にいなければ最大値へ、最終行にいれば動かない |
   | Home | カーソルのある行の先頭のセルへ (行の先頭のずれ (VIEW-20) で最初の行が欠けている場合は、その行に存在する最初のバイト) |
   | End | カーソルのある行の最後のセルへ。最終行では最大値へ |
   | PageUp | *c* − *b* × max(1, *V* − 1) へ。0 を下回る場合は同じ列の最初の行へ、その行に同じ列がなければ 0 へ。表示も同じ行数だけ上にスクロールし、カーソルの画面上の高さを保つ |
   | PageDown | *c* + *b* × max(1, *V* − 1) へ。最大値を超える場合は最大値へ。表示も同じ行数だけ下にスクロールする |
   | Ctrl+Home | 0 へ (VIEW-30) |
   | Ctrl+End | 最大値へ (VIEW-30) |

3. 左右の動作は画面上の向きで決める。グループ内の逆順表示 (VIEW-11) では、画面上の右隣のセルへ移る。
4. 移動後のカーソルが画面の外にある場合は、VIEW-34 の規則でスクロールする。
5. 「Hex 列で ← / → をニブル単位で動かす」(VIEW-26) がオンのときは、Hex 列での ← / → は VIEW-26 の規則に従う。
6. マウスの左クリック:
   - Hex 列のセルでは、クリックした文字が 1 文字目なら上位ニブル、2 文字目なら下位ニブルにカーソルを置く。グループの間の空白をクリックした場合は、右側のバイトの上位ニブルに置く。
   - テキスト列では、クリックしたセルのバイトにカーソルを置く。
   - オフセット列では、その行の先頭のバイトにカーソルを置く (行全体の選択は EDIT)。
   - 最終行より下の空白部分では、最大値に置く。
   - カーソルを置いた列を操作中の列にする。
7. Alt+Shift+矢印 (矩形選択)、Ctrl+Alt+↑ / ↓ (カーソルの追加) は EDIT で定める。
8. 次のコマンドを用意する (既定のショートカットは 00-overview 8.3):
   - 「移動: 前のグループへ」「移動: 次のグループへ」(Ctrl+← / Ctrl+→): グループ化のバイト数 (VIEW-09) の境目へ移る。前のグループへは、グループの先頭にいないときはそのグループの先頭へ、先頭にいるときは前のグループの先頭へ移る。グループ化が 1 のときは ← / → と同じ。
   - 「表示: 1 行上にスクロール」「表示: 1 行下にスクロール」(Ctrl+↑ / Ctrl+↓): カーソルを動かさずに表示だけを 1 行動かす。
9. キーを押し続けたときの繰り返しは Windows のキーボード設定に従う。描画が追いつかない場合は途中のフレームを飛ばして最新の位置を描く (入力は捨てない)。
10. カーソルの位置はビュー (VIEW-37、VIEW-38) ごとに持つ。

**画面**: Hex ビュー。

**巨大ファイル・長時間処理**: 移動先の計算は定数時間。移動先のデータが未読み込みでもカーソルは即座に動かし、セルは VIEW-03 の仮表示にする。

**エラー**: 該当なし (範囲外への移動は端で止める)。

**受け入れ基準**:

- [ ] 1 行 16 バイト、長さ 100 のファイルで、オフセット 90 から ↓ を押すと 100 (末尾の次) に移り、100 から ↓ を押しても動かない。
- [ ] 長さを変えられないデータソースでは、Ctrl+End でオフセット *L* − 1 に移る。
- [ ] PageDown でカーソルの画面上の高さが変わらない (最終ページを除く)。
- [ ] Hex セルの 2 文字目をクリックすると下位ニブルにカーソルが置かれる。
- [ ] 32 bit 整数形式のとき、→ でカーソルが 4 バイト進む。
- [ ] 100 GB のファイルで Ctrl+End を押してから 50 ms 以内にカーソルが表示される (セルは仮表示でもよい)。

### VIEW-26 ニブル単位の移動

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-03 |
| 呼び出し | 設定「Hex 列で ← / → をニブル単位で動かす」(`view.cursor.nibbleArrowKeys`、既定オフ)。コマンドパレット「移動: 次のニブルへ」「移動: 前のニブルへ」(ショートカットは既定なし) |

**概要**: Hex 列でカーソルをバイト内の上位・下位のニブル単位で動かす。

**仕様**:

1. Hex 列でカーソルは上位ニブル (1 文字目) または下位ニブル (2 文字目) にある。
2. Hex 列での入力 (EDIT) では、上位ニブルに入力すると下位ニブルへ、下位ニブルに入力すると次のバイトの上位ニブルへ進む。
3. 「次のニブルへ」: 上位なら同じバイトの下位へ、下位なら次のバイトの上位へ。最大値の位置の下位ニブルでは動かない。
4. 「前のニブルへ」: 下位なら同じバイトの上位へ、上位なら前のバイトの下位へ。オフセット 0 の上位ニブルでは動かない。
5. 設定「Hex 列で ← / → をニブル単位で動かす」をオンにすると、Hex 列での ← / → は 3、4 の動作になる。オフのとき (既定) は VIEW-25 のとおりバイト単位で動き、ニブルは上位に戻す。
6. ↑ / ↓ / PageUp / PageDown ではニブルの位置を保つ。Home / End / Ctrl+Home / Ctrl+End では上位にする。
7. Hex 以外のセル形式 (VIEW-10) とテキスト列では、ニブルの位置を持たない。
8. ステータスバーのカーソル位置はバイト単位で表示する。設定「ニブルの位置を表示」(`view.statusBar.showNibble`、既定オフ) をオンにすると、下位ニブルにあるとき位置の後ろに `(下位)` を付ける。スクリーンリーダーは常に「下位」を読み上げる (VIEW-41 の 5、UI-51)。

**画面**: Hex 列のカーソル (VIEW-06 の 5)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 設定をオンにすると、→ を 2 回押して 1 バイト進む。
- [ ] 設定オフでは、下位ニブルから → を押すと次のバイトの上位ニブルに移る。
- [ ] 下位ニブルで ↓ を押すと、1 行下のバイトの下位ニブルに移る。

### VIEW-27 Hex 列とテキスト列の切り替え

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-03 |
| 呼び出し | Tab / Shift+Tab (順 / 逆。00-overview 8.3)。マウスで列をクリック。コマンドパレット「移動: Hex 列とテキスト列の切り替え」 |

**概要**: キー入力を受け付ける列 (操作中の列) を Hex 列とテキスト列の間で切り替える。

**仕様**:

2. カーソルのオフセットは変えない。Hex 列に移ったときニブルは上位にする。
3. 選択範囲は変えない。
4. Hex ビューの中では Tab をフォーカスの移動に使わない。キーボードで Hex ビューからフォーカスを外すには F6 / Shift+F6 (次 / 前の領域へ。00-overview 8.2) を使う。領域の移動の詳細は UI-52 で定める。
5. 操作中の列は、ステータスバー (VIEW-40) に `Hex` / `テキスト` で表示する。

**画面**: Hex ビュー。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] Tab を押すとカーソルがテキスト列に移り、オフセットは変わらない。
- [ ] テキスト列を非表示にしているとき、Tab を押しても何も起きない。
- [ ] テキスト列が 2 列あるとき、Tab で Hex → テキスト 1 → テキスト 2 → Hex と移り、Shift+Tab でその逆に移る。

### VIEW-28 スクロール (ホイール・横スクロール・タッチ)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-02 |
| 呼び出し | マウスホイール、Shift+ホイール、チルトホイール、タッチパッド、タッチ操作、スクロールバー |

**概要**: カーソルを動かさずに表示位置を変える操作の規則。

**仕様**:

1. ホイールの 1 ノッチ (120 単位) で、Windows の設定 (`SPI_GETWHEELSCROLLLINES`、既定 3 行) の行数だけ縦にスクロールする。設定が「1 画面ずつ」の場合は max(1, *V* − 1) 行。120 未満の細かい入力は蓄積して行に換算する。
2. 高精度タッチパッドとタッチ操作では、行の高さより細かい単位で滑らかにスクロールする。内部では「一番上の行番号 (`long`)」と「行内のずれ (ピクセル、0 以上 1 行の高さ未満)」を分けて持つ。指を離した後の慣性スクロールに対応する。
3. Shift+ホイール、チルトホイール、タッチパッドの左右の動きで横にスクロールする。ホイール 1 ノッチで 3 セル分。
4. Ctrl+ホイールはズーム (VIEW-43)。
5. 横スクロールバーは、Hex 表示部分の幅が表示領域より広いときだけ出す。オフセット列は横スクロールしても左端に固定する (設定「オフセット列を固定」、既定オン)。
6. スクロールではカーソルを動かさない。カーソルが画面外にある状態でカーソル移動や文字の入力をすると、まずカーソルが見える位置まで表示を戻す (VIEW-34)。
7. 範囲選択のドラッグ中 (EDIT) にマウスが表示領域の上端・下端の外に出たら、自動でスクロールする。速度は EDIT-01 の 9 で定める。
8. スクロールの位置はビューごとに持つ。同期スクロール (VIEW-37、VIEW-39) が有効な場合は、相手のビューにも移動を伝える。

**画面**: Hex ビューとスクロールバー。

**巨大ファイル・長時間処理**: スクロール量の計算は定数時間。速いスクロールで読み込みが追いつかない範囲は VIEW-03 の仮表示にする。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] ホイール 1 ノッチで 3 行スクロールし、カーソルのオフセットは変わらない。
- [ ] Windows のホイール設定を 5 行にすると 5 行スクロールする。
- [ ] 1 行 256 バイトで横スクロールしても、オフセット列が左端に残る。
- [ ] タッチパッドでピクセル単位の滑らかなスクロールができる。
- [ ] カーソルが画面外にあるとき → キーを押すと、カーソルが見える位置まで表示が戻る。

## 5. ジャンプと移動

### VIEW-29 オフセットへ移動 (移動バー)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-10 |
| 呼び出し | Ctrl+G。移動 > オフセットへ移動…。ステータスバーのカーソル位置をクリック。コマンドパレット「移動: オフセットへ移動」 |

**概要**: 入力式で指定したオフセット (またはアドレス) にカーソルを移す。モーダルにしない移動バーで入力する。

**仕様**:

1. Ctrl+G で、検索バー (00-overview 9 章) と同じ場所に移動バーを開き、入力欄にフォーカスを移す。入力欄には前回の入力を全選択した状態で入れておく。検索バーが開いている場合は、同じ場所に移動バーを表示する (同時に表示するのは 1 つだけ)。
2. 入力は 00-overview 6 章の入力式 (数値の各書き方、単位 `K` `M` `G` `T`、演算子、6.2 の名前 `cur` `start` `end` `sel.start` `sel.end` `sel.last` `sel.len` `sector` `rec` `recno` `bm.名前`、読み取り関数 `u8()` `u32le()` など) をすべて受け付ける。`sel.end` は選択範囲の直後の位置 (最後のバイトを含まない) なので、選択範囲の最後のバイトへ移るには `sel.last` を使う。
3. 基準 (移動バー内の選択。既定「自動」):
   - 自動: 先頭が `+` または `-` ならカーソルからの相対、それ以外は先頭からの絶対 (00-overview 6.2)。
   - 先頭から: 入力値をオフセット (またはアドレス) とする。
   - カーソルから: 入力値をカーソルに足す (負の値も可)。
   - 末尾から: `end − 入力値` とする。
4. 単位 (既定「バイト」): バイト / 行 (入力値 × 1 行のバイト数) / セクタ (入力値 × セクタサイズ) / レコード (入力値 × レコード長 + 最初のレコードの開始オフセット。VIEW-18 がオンのときだけ)。
5. ベースアドレスを設定している場合は「アドレスで指定 / オフセットで指定」を切り替えられる (VIEW-20 の 4)。アドレスで指定した場合は、入力値からベースアドレスを引いたものをオフセットとする。
6. 入力欄の横に解釈結果を常に表示する (例: `= 0x1F00 (7,936)`)。
7. 移動先が 0 未満、または最大値 (VIEW-25 の 1) を超える場合は、入力欄を赤枠にし、説明文 (例: 「ファイルの末尾 (0x3E8) を超えています」) を出して移動できないようにする。
8. Enter で移動して移動バーを閉じ、エディタにフォーカスを戻す。Shift+Enter で移動して移動バーを開いたままにする。Esc で移動せずに閉じる。
9. 「選択しながら移動」(既定オフ) をオンにすると、移動前のカーソル位置から移動先までを選択する (選択の規則は EDIT)。
10. 移動前の位置をジャンプ履歴 (VIEW-31) に記録する。
11. 移動先は VIEW-34 の「ジャンプ」の規則で表示する。
12. 入力の履歴を最大 20 件保存し、入力欄で ↑ / ↓ を押すか、一覧から呼び出せる。履歴はセッションをまたいで保存する。
13. コマンドラインとスクリプトから同じ移動を実行できる (AUTO で定める)。

**画面**: エディタ上部の移動バー。入力欄、解釈結果、基準の選択、単位の選択、アドレス / オフセットの切り替え、「選択しながら移動」、移動ボタン、閉じるボタン。幅が足りない場合 (訳文が長い場合を含む) は、選択項目を 2 段目に折り返す。

**巨大ファイル・長時間処理**: 移動は定数時間。100 GB のファイルの末尾付近への移動も 100 ms 以内に表示する (00-overview 11.1)。

**エラー**: 入力式の文法の誤り (例: 閉じていない括弧)、存在しないブックマーク名、0 除算、64 bit を超える値は、入力欄に赤枠と説明文を出す。

**受け入れ基準**:

- [ ] `0x1F00`、`1F00h`、`$1F00` のどれでもオフセット 0x1F00 に移る。
- [ ] `+0x10` でカーソルから 16 バイト先へ、`end-0x10` で末尾の 16 バイト前へ移る (接頭辞のない `16` は 16 進表示では 0x16 と解釈される。00-overview 6.1)。
- [ ] オフセット 0x10 から 16 バイトを選択した状態で、`sel.end` で 0x20 に、`sel.last` で 0x1F に移る。
- [ ] EXE ファイルで `u32le(0x3C)` を入力すると PE ヘッダの位置に移る。
- [ ] 末尾を超える値では赤枠と説明文が出て、Enter を押しても移動しない。
- [ ] 単位「セクタ」で `8` を入力すると 4,096 (セクタサイズ 512) に移る。
- [ ] Shift+Enter で移動しても移動バーが開いたままになる。
- [ ] 移動後に Alt+← で移動前の位置に戻る。
- [ ] 100 GB のファイルで末尾付近への移動が 100 ms 以内に表示される (OS のキャッシュに載っている状態)。
- [ ] UI をドイツ語にしても移動バーの項目が切れずに表示される。

### VIEW-31 ジャンプ履歴 (戻る / 進む)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-13 |
| 呼び出し | Alt+← / Alt+→。マウスの「戻る」「進む」ボタン。移動 > 戻る / 進む / 履歴の一覧。コマンドパレット「移動: 戻る」「移動: 進む」「移動: 履歴の一覧」 |

**概要**: ジャンプする前の位置を記録し、Web ブラウザのように戻る・進むで行き来できるようにする。

**仕様**:

1. 次の操作でカーソルが移る直前の位置 (オフセット、一番上の行、操作中の列) を履歴に記録する:
   - オフセットへ移動 (VIEW-29)、ファイルの先頭・末尾 (VIEW-30)、セクタ・ページ・レコード単位の移動 (VIEW-32、VIEW-33、VIEW-18)
   - 検索で次・前の一致に移る、結果一覧からのジャンプ、差分へのジャンプ (FIND、ANA)
   - ブックマークへの移動、インスペクタのポインタとしてのジャンプ (INSP)、テンプレートのツリーからのジャンプ (TPL)
   - ミニマップ・ビジュアライザのクリック (VIEW-35、VIEW-36)
   - マウスのクリックで、カーソルが元の位置から 1 画面分 (*b* × *V* バイト) 以上離れた場合
2. 矢印キー・PageUp / PageDown・スクロールでは記録しない。
3. 直前の記録と同じ行への移動は記録しない (連続した重複をまとめる)。
4. 履歴はビュー (VIEW-37 のペインを含む) ごとに持ち、最大 100 件。超えたら古いものから消す。
5. 戻る: 現在位置を「進む」側に積み、1 つ前の位置に移る。進む: その逆。戻ったあとに新しいジャンプをすると、進む側の履歴を消す。
6. 履歴の位置は挿入・削除に追従する (記録した位置より前で挿入・削除が起きたら位置をずらす)。削除された範囲に入った位置は、削除範囲の先頭に移す。
7. 移動先がドキュメントの最大値を超えている場合は、最大値に移す。
8. 「履歴の一覧」は、最新 20 件を「アドレス + その位置から 8 バイトの Hex」の形で一覧表示し、選ぶとその位置に移る。
9. 戻る・進む自体は、新たな記録を追加しない。
10. 戻る・進むの対象がない場合は、メニュー項目を無効にし、キーを押しても何もしない。
11. 履歴はセッションの間だけ持ち、ドキュメントの付随データ (00-overview 10 章) には保存しない。

**画面**: 移動メニューの項目とサブメニュー。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] Ctrl+G で 3 か所に移動したあと、Alt+← を 3 回押すと順に元の位置へ戻り、Alt+→ で進める。
- [ ] 戻ったあとに新しく移動すると、Alt+→ が無効になる。
- [ ] 矢印キーの移動では履歴が増えない。
- [ ] 記録した位置の前に 16 バイト挿入してから戻ると、16 バイト後ろの位置 (同じデータ) に移る。
- [ ] マウスの「戻る」ボタンで戻れる。

### VIEW-32 セクタ単位の移動

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案。F2-09 と同時) |
| 呼び出し | 移動 > 次のセクタ / 前のセクタ / セクタへ移動…。コマンドパレット「移動: 次のセクタ」「移動: 前のセクタ」「移動: セクタへ移動」(ショートカットは既定なし) |

**概要**: ディスクやディスクイメージを、セクタ単位で前後に移動する。

**仕様**:

1. セクタサイズは、ディスク・ボリュームではデータソースの値、ファイルでは表示設定の値 (既定 512。VIEW-19 の 6)。
2. 次のセクタ: カーソルを次のセクタの先頭 (セクタサイズの倍数の位置) に移す。最後のセクタでは動かない。セクタ番号は 0 始まり (オフセット ÷ セクタサイズ、切り捨て) で、セクタ数は ⌈長さ ÷ セクタサイズ⌉ とする (末尾の端数のセクタも 1 つのセクタと数える)。最後のセクタは番号がセクタ数 − 1 のセクタで、末尾の次の位置 (オフセット *L*) は、*L* がセクタサイズの倍数の場合も最後のセクタに属するものとして扱う。長さ 0 のドキュメントでは移動しない。
3. 前のセクタ: カーソルがセクタの先頭にない場合はそのセクタの先頭に、先頭にある場合は前のセクタの先頭に移す。
4. セクタへ移動: 移動バー (VIEW-29) を単位「セクタ」の状態で開く。
5. 移動したセクタの先頭行を画面の一番上に表示する。
6. ステータスバー (VIEW-40) に、カーソルのあるセクタ番号 (10 進) を表示する (ディスク・ボリュームでは常に、ファイルではオフセットの形式がセクタのとき、または区切り線がセクタのとき)。
7. ジャンプ履歴に記録する。

**画面**: 移動メニュー。

**巨大ファイル・長時間処理**: 定数時間。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] セクタサイズ 512 で、オフセット 0x210 から「次のセクタ」で 0x400 に移る。
- [ ] オフセット 0x210 から「前のセクタ」で 0x200 に、もう一度で 0x000 に移る。
- [ ] 4,096 バイトセクタのディスクで、4,096 バイト単位で移動する。

### VIEW-33 区切り線とページ表示

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 表示 > 区切り線 (なし / セクタ / ページ / 任意の長さ…)、表示 > ページ単位で表示。コマンドパレット「表示: 区切り線」「表示: ページ単位で表示」「移動: 次のページ」「移動: 前のページ」(ショートカットは既定なし) |

**概要**: 一定のバイト数 (セクタ、ページ、任意の長さ) ごとに区切り線と見出しを表示する。表示をページ単位で切り替えることもできる。

**仕様**:

1. 区切りの長さ: セクタ (VIEW-32 のセクタサイズ)、ページ (既定 4,096)、任意 (1 行のバイト数の倍数で、1 行分〜2^31 − 1 バイト)。既定は「なし」。ディスク・ボリュームを開いたときの既定は「セクタ」。
2. 区切りの長さが 1 行のバイト数の倍数でない場合は選べない (区切り線は行の境目に引くため)。行の先頭のずれ (VIEW-20) があって区切りの位置が行の境目と合わない場合も選べない。
3. 区切り線: 区切りの境目の行の上に 1 px の線を引く。設定「見出しを表示」(既定オン) では、線の右端に `セクタ 15` や `ページ 3 (0x3000)` のような小さな見出しを描く。見出しは行の高さを変えずに線に重ねる。
4. ページ単位で表示 (既定オフ): 表示を 1 区切りずつに切り替える。スクロールバーとホイールは区切り単位で動き、1 区切りの行数が表示行数より多い場合はその中でスクロールする。区切りの最後の行で ↓ を押すと次の区切りに移る。
5. 次のページ / 前のページ: VIEW-32 と同じ規則で区切りの先頭に移る。
6. ステータスバーに、カーソルのある区切りの番号と区切りの数 (例: `ページ 3 / 25,600`) を表示する (区切り線が「なし」以外のとき)。区切りの番号は見出し (3) と同じく 0 始まり (オフセット ÷ 区切りの長さ、切り捨て) で、区切りの数は ⌈長さ ÷ 区切りの長さ⌉ とする (末尾の端数も 1 つと数える。末尾の次の位置は最後の区切りに属する。VIEW-32 の 2 と同じ)。例: 1 MiB のファイル、ページ 4,096 バイトで、0x3000 の見出しは `ページ 3 (0x3000)`、0x2FF0 にカーソルがあるときのステータスバーは `ページ 2 / 256`。

**画面**: Hex ビュー内の線と見出し。

**巨大ファイル・長時間処理**: 区切りの位置は計算で求める。

**エラー**: 範囲外の長さは入力欄に赤枠と説明文を出す。

**受け入れ基準**:

- [ ] 区切り線「ページ」で 4,096 バイトごとに線と見出しが表示される。見出しとステータスバーの番号は 0 始まりで、0x3000 の行の見出しが `ページ 3 (0x3000)` になる。
- [ ] 1 行 24 バイトのとき、区切りの長さ 4,096 が選べず、理由が表示される。
- [ ] ページ単位で表示中、PageDown を押し続けると区切りをまたいで正しく移動する。

## 6. ミニマップと視覚化

### VIEW-35 ミニマップ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-03 |
| 呼び出し | 表示 > ミニマップ (表示切り替え、表示内容、範囲)。コマンドパレット「表示: ミニマップの表示切り替え」「表示: ミニマップの表示内容」(ショートカットは既定なし) |

**概要**: ドキュメント全体 (または周辺) のデータの性質を、Hex ビューの横に縦長の帯として色と棒の長さで表示する。クリックでその位置にジャンプでき、選択範囲・検索結果・差分などの位置も示す。

**仕様**:

1. 位置と大きさ: 縦スクロールバーの左に置く。幅は既定 80 epx (40〜200 epx、境界のドラッグで変更)。高さは Hex ビューと同じ。既定は非表示。
2. 範囲 (既定「全体」):
   - 全体: ドキュメントの先頭から末尾までを、ミニマップの高さ (物理ピクセル) に割り当てる。1 ピクセル行が表す範囲は *L* / 高さ バイト (端数は切り上げ。最小 1 行分)。
   - 周辺: 1 ピクセル行を Hex ビューの 1 行に対応させ、現在の表示位置を中心に表示する (ミニマップの高さ分の行)。
3. 表示内容 (既定「エントロピー」):

   | 表示内容 | 各ピクセル行の値 | 色 | 棒の長さ |
   | --- | --- | --- | --- |
   | エントロピー | 対象範囲のバイト値のシャノンエントロピー (0〜8 bit) | 低 (青系) → 高 (赤系) の連続した配色 | エントロピー / 8 |
   | バイトの種類 | 範囲内のバイトの種類 (VIEW-17 の「種類別」の 6 分類) の割合 | 種類ごとの色を割合に応じて横に並べる | 全幅 |
   | バイト値 | 範囲内のバイト値の平均 | グラデーション (VIEW-17) | 平均 / 255 |
   | ゼロ | 範囲内の `00` 以外のバイトの割合 | 単色 | 割合 |
   | バイトテーマ | 「周辺」のときだけ。各バイトを 1 ピクセルとし、バイトテーマの色で描く | バイトテーマ | 全幅 |

4. 色だけに頼らないため、「エントロピー」「バイト値」「ゼロ」では、値を棒の長さ (左寄せの横棒) でも示す。ハイコントラストでは色を使わず、棒の長さだけで示す (`WindowText` の棒)。
5. エントロピーの計算: 各ピクセル行の範囲が 4 KiB 以下のときはその範囲全体、4 KiB を超えるときは範囲の中央の 4 KiB を標本として計算する (概算)。設定「正確に計算」(既定オフ) をオンにすると、範囲全体を読む長時間処理として計算する。
6. 重ねて表示する印 (ミニマップの右端に幅 6 epx の印の帯を設ける。各印は ON / OFF を選べる。既定はすべて ON):

   | 印 | 形 |
   | --- | --- |
   | 表示中の範囲 | 半透明の枠 (ドラッグできる) |
   | カーソル | 横線 (全幅) |
   | 選択範囲 | 印の帯に塗りつぶし |
   | 検索結果 (FIND) | 印の帯に短い横線 |
   | ブックマーク (INSP) | 印の帯にブックマークの色の三角形 |
   | 差分 (ANA) | 印の帯に差分の種類ごとの模様 (変更: 塗りつぶし、挿入: 斜線、削除: 点) |
   | 変更されたバイト (VIEW-15) | 印の帯の左側に細い縦線 |

7. 操作:
   - クリック: その位置にカーソルを移し、ジャンプとして表示する (VIEW-34)。ジャンプ履歴に記録する。
   - 表示中の範囲の枠をドラッグ: カーソルを動かさずにスクロールする。
   - ホイール: Hex ビューと同じ縦スクロール。
   - マウスを合わせる: ツールチップでその位置のアドレス範囲と値 (例: `0x1A000000〜0x1A01FFFF エントロピー 7.98`) を表示する。
8. 編集でデータが変わったら、変わった範囲に対応するピクセル行だけを計算し直す (500 ms 待ってまとめて行う)。
9. ミニマップの表示状態・幅・表示内容・範囲は、全ドキュメント共通の設定として保存する。

**画面**: Hex ビューの右側、縦スクロールバーの左。右クリックメニューで表示内容・範囲・印の ON / OFF を変えられる。

**巨大ファイル・長時間処理**: 「全体」の概算は、ピクセル行の数 (最大 4,320 程度) × 4 KiB の読み込みで済み、計算は表示を止めずにバックグラウンドで行う。計算の終わっていないピクセル行は灰色の点線で描き、上から順に埋める。「正確に計算」は長時間処理 (処理センターに表示、キャンセル可) とし、結果をドキュメントごとにキャッシュする (ファイルが変わらない限り再利用)。

**エラー**: 読み取れない範囲を含むピクセル行は、斜線の模様で描く。

**受け入れ基準**:

- [ ] 100 GB のファイルでミニマップを表示し、1 秒以内に操作でき、5 秒以内に全体の概算が描き終わる (ローカルの SSD)。
- [ ] 圧縮データの部分が高エントロピー、ゼロ埋めの部分が低エントロピーとして、色と棒の長さで区別できる。
- [ ] ミニマップをクリックすると、その位置にカーソルが移り、Alt+← で元に戻れる。
- [ ] 選択範囲・検索結果・ブックマークの位置に印が表示される。
- [ ] ハイコントラストで、棒の長さでエントロピーの違いが分かる。
- [ ] 「正確に計算」が処理センターに表示され、キャンセルできる。

### VIEW-36 バイトの画像表示 (ビジュアライザ)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 3 提案) |
| 呼び出し | 表示 > パネル > 画像表示。コマンドパレット「表示: 画像表示パネル」(ショートカットは既定なし) |

**概要**: バイト列を画素の並びとして画像に描き、画像データ・テクスチャ・ビットマップの構造やデータの模様を目で見て探せるようにする。

**仕様**:

1. パネル (00-overview 9 章。既定は右側) に表示する。
2. 設定項目:

   | 項目 | 既定値 | 選択肢・範囲 |
   | --- | --- | --- |
   | 画素の形式 | 8 bit グレー | 1 bit 白黒、2 bit グレー、4 bit グレー、8 bit グレー、8 bit (バイトテーマの色)、RGB565 (LE / BE)、RGB555、RGB888、BGR888、RGBA8888、BGRA8888、ARGB8888 |
   | 幅 | 256 画素 | 1〜65,536 |
   | 1 行のバイト数 (ストライド) | 幅 × 画素のバイト数 | 幅 × 画素のバイト数以上 (各行の末尾の詰め物を飛ばす) |
   | 開始位置 | カーソルに追従 | カーソルに追従 / 選択範囲の先頭 / 固定 (入力式) |
   | 上下の向き | 上から下 | 上から下 / 下から上 (BMP 形式) |
   | 拡大率 | 自動 (パネルの幅に合わせる) | 1〜32 倍 (整数倍、拡大時は補間なし) |

3. 表示する範囲は、開始位置からパネルの高さに収まる行数分とする。パネル内のスクロールで開始位置より後ろを見られる。
4. 画素をクリックすると、その画素の先頭バイトに Hex ビューのカーソルを移す (ジャンプ履歴に記録)。
5. Hex ビューのカーソル位置と選択範囲を、画像の上に枠で示す。
6. 画素にマウスを合わせると、オフセットと画素の値 (例: `0x3F20 RGB(255, 128, 0)`) を表示する。
7. 表示中の画像を PNG として保存できる (パネルのメニュー「画像として保存…」)。
8. データが変わったら 200 ms 待って描き直す。

**画面**: パネル。上部に設定の行 (折り返し可能)、その下に画像。

**巨大ファイル・長時間処理**: 読み込むのは表示中の範囲 (幅 × 表示行数 × 画素のバイト数) だけ。表示範囲が 64 MB を超える組み合わせ (大きな幅と大きな高さ) では、拡大率を下げずに表示範囲の上端から 64 MB までを描き、残りは「表示範囲が大きすぎます」と表示する。

**エラー**: 範囲が末尾を超える部分は透明 (市松模様) で描く。読み取れない範囲は斜線で描く。

**受け入れ基準**:

- [ ] 非圧縮の 24 bit BMP ファイルの画素データの先頭にカーソルを置き、BGR888・幅を画像の幅・下から上に設定すると、画像が正しく見える。
- [ ] 画素をクリックすると、Hex ビューのカーソルがその画素のバイトに移る。
- [ ] 100 GB のファイルでも、パネルの表示とスクロールが 60 fps を保つ。
- [ ] 表示中の画像を PNG で保存できる。

## 7. 画面分割と複数ビュー

### VIEW-37 画面分割

| 項目 | 内容 |

| ロードマップ | F2-02 |
| 呼び出し | Ctrl+\\ (分割 / 分割の解除の切り替え)。表示 > 画面分割 (上下に分割 / 左右に分割 / 分割の解除 / スクロールを同期)。分割バーのダブルクリック。コマンドパレット「表示: 画面を上下に分割」「表示: 画面を左右に分割」「表示: 分割の解除」「表示: 分割したペインのスクロールを同期」 |

**概要**: 1 つのタブの中で同じドキュメントを 2 つのペインに分けて表示し、離れた 2 か所を同時に見ながら編集できるようにする。

**仕様**:

1. Ctrl+\\ を押すと、分割していなければ前回の向き (既定は上下) で 2 つのペインに分割する。分割していれば分割を解除する。
2. 分割したペインはそれぞれ独立した Hex ビューで、カーソル・選択範囲・スクロール位置・ジャンプ履歴を別々に持つ。
3. 表示設定 (1 行のバイト数、グループ化、セル形式、文字コード、テキスト列など) は、分割した時点で元のペインの設定を複製し、その後はペインごとに変えられる。設定「分割したペインの表示設定をそろえる」(既定オフ) をオンにすると、一方の変更をもう一方にも反映する。
4. 編集はドキュメントに対して行うため、一方のペインで編集した内容はもう一方にすぐ反映する。挿入・削除の位置より後ろを表示しているペインは、表示中のデータが動かないよう一番上の行の先頭オフセットをずらす。
5. 分割バーはドラッグで動かせる。各ペインの最小の大きさは 3 行 (上下分割) または 1 行分の最小幅 (左右分割)。分割バーをダブルクリックすると 1:1 に戻す。
6. 最後にクリックしたペイン (フォーカスのあるペイン) が「操作中のペイン」となり、メニュー・ショートカット・ステータスバーはそのペインを対象にする。操作中のペインは、ペインの境界に 2 px のアクセント色の枠を付けて示す (ハイコントラストでは `Highlight`)。
7. キーボードでのペイン間の移動: F6 / Shift+F6 (次 / 前の領域へ。00-overview 8.2、UI-52) では、分割した各ペインを別の領域として扱い、上 (左) のペイン → 下 (右) のペインの順にフォーカスを移す。ペインの間だけを移るコマンド「表示: 次のペインへ」も用意する (既定のショートカットはなし)。
8. 「スクロールを同期」(既定オフ) をオンにすると、一方のペインのスクロール量 (行数) をもう一方にも同じだけ伝える。オンにした時点の 2 つのペインの位置の差を保つ。
9. 分割を解除すると、操作中のペインを残す。
10. 分割の状態 (向き、比率、各ペインの位置) はドキュメントの付随データとして保存し、開き直したときに復元する。
11. 分割できるのは 2 ペインまで。3 つ以上の表示は「新しいビュー」(VIEW-38) を使う。

**画面**: タブの内容領域を分割バー (幅 4 epx) で 2 つに分ける。各ペインに独自のスクロールバーとミニマップ (表示している場合) を付ける。列見出しはペインごとに表示する。

**巨大ファイル・長時間処理**: 各ペインは独立して表示範囲だけを読み込む。データエンジンのキャッシュは共有する。

**エラー**: ウィンドウが小さく 2 ペインの最小の大きさを確保できない場合は、分割のコマンドを無効にする。

**受け入れ基準**:

- [ ] Ctrl+\\ で上下に分割され、もう一度押すと解除される。
- [ ] 上のペインでオフセット 0、下のペインで末尾を表示し、それぞれ独立してカーソルを動かせる。
- [ ] 一方のペインで 1 バイト上書きすると、もう一方のペインの同じ位置もすぐ変わる。
- [ ] 上のペインで先頭に 16 バイト挿入しても、下のペインに表示中のデータが画面上で動かない。
- [ ] 「スクロールを同期」をオンにすると、一方のスクロールでもう一方も同じ行数だけ動く。
- [ ] Ctrl+\\ が押せないキーボード配列でも、メニューとコマンドパレットから分割できる。

### VIEW-39 別ファイルとの並列表示と同期スクロール

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-02 (比較との連携は F2-01) |
| 呼び出し | 表示 > 並べて表示… (開いているドキュメントを選ぶ)。タブの右クリックメニュー「右に並べて表示」。表示 > 同期スクロール (オフ / 同じオフセット / 位置の差を保つ)。コマンドパレット「表示: 並べて表示」「表示: 同期スクロールの切り替え」 |

**概要**: 異なる 2 つ以上のドキュメントを左右に並べて表示し、スクロールとカーソル位置を同期させる。

**仕様**:

1. 「並べて表示」で、操作中のタブの右に、選んだドキュメントのビューを並べて表示する (タブグループを左右に分ける。タブグループの仕組みは UI)。最大 4 つまで並べられる。
2. 同期スクロールのモード (既定「同じオフセット」。並べた時点で有効にする):
   - オフ: 同期しない。
   - 同じオフセット: 一方の一番上の行の先頭オフセットとカーソルのオフセットを、ほかのビューにも同じ値で設定する。相手のドキュメントが短い場合は、相手の最大値で止める。
   - 位置の差を保つ: 同期を有効にした時点の各ビューのオフセットの差を保って動かす。
   - 比較に従う: 比較 (ANA) の結果がある場合だけ選べる。挿入・削除を考慮した対応位置に合わせて動かす (対応の求め方は ANA)。
3. 同期するのは、スクロール、カーソルの移動、ジャンプ。選択範囲は同期しない (設定「選択範囲も同期」、既定オフ)。
4. 1 行のバイト数が違うビュー同士では、オフセットを基準に同期する (行番号ではない)。
5. 表示中の範囲で、相手のビューと同じオフセットの値が違うバイトを強調する設定「違いを強調」(既定オフ) を用意する。これは表示中の範囲だけの単純な比較で、比較機能 (ANA) とは別に動く。強調は ANA の差分と同じ表示 (VIEW-17 の層 11) を使う。
6. 同期中は、ステータスバーに `同期` を表示する。
7. 並列表示の構成 (並べたドキュメントと同期のモード) は、セッションの復元 (UI) で復元する。

**画面**: 左右に並んだタブグループ。各グループの上部に同期のモードを示す小さなボタン (鎖の図柄) を置き、クリックで切り替える。

**巨大ファイル・長時間処理**: 「違いを強調」は表示中の範囲だけを比べるため、ファイルサイズに依存しない。

**エラー**: 一方のドキュメントが閉じられたら、並列表示を解除し、同期も解除する。

**受け入れ基準**:

- [ ] 2 つのファイルを並べ、一方で PageDown を押すと、もう一方も同じオフセットに移る。
- [ ] 「位置の差を保つ」で、0x100 と 0x300 を表示した状態から同期すると、0x200 の差を保って動く。
- [ ] 1 行 16 バイトと 1 行 32 バイトのビューでも、同じオフセットが表示される。
- [ ] 「違いを強調」で、表示中の範囲の違うバイトが強調される。
- [ ] 短いファイルの末尾を越える同期で、短いファイル側は末尾で止まる。

### VIEW-40 ステータスバーに表示する値の書式

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-12 |
| 呼び出し | ステータスバー (UI-06) に常に表示 |

**概要**: ステータスバーに表示する、操作中のビューの状態 (カーソル位置、選択範囲、表示の状態など) の値の書式を定める。ステータスバーの配置、項目の並び、表示・非表示の切り替え、クリックしたときの動作、幅が足りないときの省略、キーボード操作は UI-06 で定める (00-overview 1.1)。

**仕様**:

1. 各項目の値の書式 (項目の並びとクリックしたときの動作は UI-06):

   | 項目 | 表示の例 | 書式の規則 |
   | --- | --- | --- |
   | カーソル位置 | `オフセット: 0x00001F00` | 基数と桁数は VIEW-19。ベースアドレスを使うときは `@00401F00`、基準点があるときは `相対 +00000020` (VIEW-20)。下位ニブルの表示は VIEW-26 の 8 |
   | カーソルの値 | `値: 4F (79)` | Hex と 10 進 (符号なし)。セル形式 (VIEW-10) が 2 バイト以上のときはその単位の値 |
   | 選択範囲 | `選択: 0x1F00–0x1FFF (長さ 0x100 = 256)` | 開始と最後のバイトの位置 (閉区間)、長さ。マルチ選択では `選択: 3 範囲、合計 1,024 バイト`。選択がないときは表示しない |
   | セクタ / ページ / レコード | `セクタ 15`、`ページ 3 / 25,600`、`レコード #1024 +0x04` | VIEW-32、VIEW-33、VIEW-18 が有効なときだけ表示する |
   | 操作中の列 | `Hex` / `テキスト` | VIEW-27 |
   | 表示形式 | `int32`、`float` など | Hex 以外のセル形式 (VIEW-10) のときだけ表示する |
   | 文字コード | `UTF-8`、`932` など | カーソルのあるテキスト列の文字コード (VIEW-24 の 6) |
   | エンディアン | `LE` / `BE`。逆順表示中は `LE (逆順表示)` | ドキュメントのエンディアン (VIEW-11) |
   | 入力モード | `上書き` / `挿入`。読み取り専用のときは `読み取り専用` | EDIT |
   | 変更の有無 | `変更あり` (文字と記号 `●`) | 変更がないときは表示しない |
   | ファイルサイズ | `サイズ: 1.50 GB (1,610,612,736 バイト)` | 下記 2 |
   | 同期 | `同期` | 同期スクロール中だけ表示する (VIEW-39) |
   | ズーム | `120%` | 100% 以外のときだけ表示する (VIEW-43、UI-08) |

3. 選択範囲は「開始–最後のバイト」の閉区間で表示する (`sel.end` ではなく `sel.last` の値。00-overview 6.2)。項目のツールチップでは「開始」「終了 (このバイトを含む)」「長さ」と書いて示す。長さは 16 進と 10 進を併記する。
4. 表示内容は、カーソルの移動・選択の変更から 50 ms 以内に更新する。ただしマウスのドラッグ中は 30 fps を上限に更新する。
5. 文は文単位でリソース化し、複数形の規則に対応する (例: `1 件の処理`、`3 件の処理`)。
6. 右から左に書く言語では、項目の並びは UI-06 に従って反転するが、各項目内の 16 進の値は左から右に表示する。
7. スクリーンリーダーで読み上げる文は「カーソル位置、0x00001F00」のように項目名と値の組とする (読み上げの仕組みは UI-51)。

**画面**: ステータスバー (UI-06)。

**巨大ファイル・長時間処理**: 該当なし (表示する値はすべて定数時間で得られる)。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] カーソルを動かすと 50 ms 以内に位置と値の表示が変わる。
- [ ] 範囲を選択すると開始・最後のバイト・長さ (16 進と 10 進) が表示され、ツールチップに「終了 (このバイトを含む)」と示される。
- [ ] 編集すると `変更あり` が表示され、保存すると消える。
- [ ] ドイツ語の地域設定でファイルサイズが `1,50 GB (1.610.612.736 バイト)` の形式になり、オフセットの 16 進表記は変わらない。
- [ ] アラビア語で 16 進の値が左から右のまま表示される。

### VIEW-42 表示設定の保存と表示プリセット

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-05 (保存)、追加 (フェーズ 2 提案。プリセット) |

**仕様**:

1. 対象の表示設定: 1 行のバイト数、グループ化、中央区切り、セル形式、エンディアン、逆順表示、大文字・小文字、ゼロのグレー表示、交互色、変更バイトの強調、列の表示・非表示、テキスト列 (文字コードと開始位置)、バイトテーマ、レコード表示、オフセットの基数、ベースアドレス、行の先頭のずれ、基準点、区切り線、分割の状態。
2. 設定の決まり方 (後のものが優先):
   1. 組み込みの既定値 (この文書の各機能の「既定」)
   2. 全体の既定値 (「既定として保存」で保存したもの)
   3. データソースの種類ごとの既定値 (ディスク・ボリュームでは区切り線「セクタ」、オフセットの形式は 16 進など。ENG のデータソースが提示する。フェーズ 1 では重ねる仕組みだけを用意する。フェーズ 1 のデータソース (ファイル) は既定値を提示せず、ディスク・ボリューム (F2-09) から使う)

7. プリセットは JSON でエクスポート・インポートできる。
8. 設定の変更は即座に反映し、再起動は不要。

**画面**: 表示メニュー。プリセットの管理は設定画面 (UI) の「表示」ページ (一覧、名前と自動適用の条件の編集、削除、エクスポート、インポート)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: インポートした JSON が不正な場合は、理由を InfoBar で示し、プリセットを変えない。知らない項目は無視して読み込む (新しいバージョンで作ったプリセットとの互換性のため)。インポートするとプリセットが上限 (100 個) を超える場合は、切り捨てずに読み込まず、理由を InfoBar で示す (同じ名前で置き換わるものは数えない)。プリセットの編集で、ほかのプリセットと同じ名前にした場合は InfoBar で示し、変えない。

**受け入れ基準**:

- [ ] あるファイルで 1 行 32 バイトにして閉じ、開き直すと 1 行 32 バイトで表示される。別のファイルは既定値で表示される。
- [ ] 「既定として保存」したあと、新しく開いたファイルにその設定が使われる。
- [ ] `.nes` に自動適用するプリセットを作ると、初めて開いた `.nes` ファイルにその設定が適用される。
- [ ] プリセットをエクスポートし、別の環境でインポートできる。

### VIEW-43 ズームしたときの Hex ビューの文字サイズと行の高さ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | ズームの操作 (UI-08): Ctrl+= / Ctrl+- / Ctrl+0、Ctrl+ホイール、表示 > ズーム、ステータスバーのズーム表示のクリック |

**概要**: アプリのズーム (UI-08) の倍率に合わせて、Hex ビューの文字の大きさ・セル幅・行の高さを計算し直す。ズームの操作、倍率の範囲と段階、保存先、ステータスバーの表示は UI-08 で定める (00-overview 1.1)。

**仕様**:

1. Hex ビューのフォントの大きさ = 設定のフォントの大きさ (VIEW-01 の 3) × Hex 表示のズームの倍率 (UI-08 の 2。適用範囲が「今のタブだけ」ならそのタブの倍率) × 画面全体のズームの倍率 (UI-08 の 3) × Windows の文字サイズの設定 (VIEW-41 の 4)。画面全体のズームの倍率はルート要素の拡大 (UI-08 の 3 の 4) で掛かるので、Hex ビューは仕様 2 の物理ピクセルへの切り上げにだけその倍率を使う。
2. セル幅と行の高さは、1 の大きさのフォントで VIEW-01 の 4 の方法で求め直す (端数は物理ピクセルに合わせて切り上げる)。
3. 対象は Hex ビュー (オフセット列・Hex 列・テキスト列・列見出し) と、ミニマップ (VIEW-35) の「周辺」表示の行の高さ。ステータスバーやパネルなどの UI の大きさは変えない。
4. ズームしたときの表示位置: Ctrl+ホイールでのズームは、マウスポインタの下の行が画面上の同じ位置に残るようにする。キーとメニューでのズームは、カーソルの行が画面上の同じ高さに残るようにする (カーソルのバイトが画面内に残るという UI-08 の 4 を満たす)。
5. 1 行のバイト数が「自動」のときは、倍率の変更で 1 行のバイト数も変わる (VIEW-08)。
6. グリフアトラス (VIEW-04 の 3。自前描画に置き換えた場合) は倍率ごとに作り直す。作り直しが終わるまでは、前の倍率のアトラスを拡大・縮小して描く。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] Ctrl+= で拡大すると Hex ビューの文字・セル幅・行の高さが大きくなり、Ctrl+0 で 100% の大きさに戻る。
- [ ] Ctrl+ホイールで、マウスポインタの下の行が動かずに拡大される。
- [ ] キーでズームしても、カーソルの行が画面上の同じ高さに残る。
- [ ] Hex 表示のズームでは、ステータスバーやメニューの文字の大きさは変わらない (画面全体のズームでは変わる)。
- [ ] 1 行のバイト数が「自動」のとき、拡大すると 1 行のバイト数が減る。

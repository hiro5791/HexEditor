# 機能仕様書: データインスペクタ・ブックマーク・注釈

この文書は、カーソル位置のデータをさまざまな型で解釈して表示・編集するデータインスペクタと、ブックマーク、位置マネージャ、注釈、色付けルールの振る舞いを定める。共通の書式・用語・入力式・ショートカットは [00-overview.md](00-overview.md) に従う。

対象とするロードマップの ID: F1-04、F1-12、F2-06、F3-09。ロードマップにない機能は、調査 ([../research/feature-survey.md](../research/feature-survey.md) の 2.6 節と 2.11 節) をもとに「追加」として含める。

## 1. データインスペクタ

### INSP-01 データインスペクタのパネル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | 表示 > パネル > データインスペクタ、Ctrl+Shift+I、コマンドパレット「データインスペクタの表示切り替え」 |

**概要**: カーソル位置 (または選択範囲の先頭) のバイトを、整数・浮動小数点・文字・日時などの型で解釈して一覧に表示するパネル。

**仕様**:

1. 解釈の起点:
   - 選択範囲がない場合はカーソル位置。
   - 選択範囲がある場合は選択範囲の先頭 (設定「選択範囲があるときはカーソル位置を使う」で変更できる。既定オフ)。
   - マルチカーソル・マルチ選択では、主カーソル (最後に置いたカーソル) を使う。
2. 各行は「型の名前」「値」の 2 列で表示する。型のサイズより起点から末尾までのバイト数が少ない場合は、値の列に「—」と表示し、ツールチップで「データが足りません (4 バイト必要、残り 2 バイト)」と示す。
3. 起点が変わってから 50 ms 以内に表示を更新する。データの読み込みはブロックキャッシュから行い、キャッシュにない場合は読み込みが終わるまで値を「…」と表示する (UI を止めない)。
4. 1 回の更新で読むのは起点から最大 4 KB (文字列 (INSP-10) とユーザー定義型 (INSP-22) のため)。標準の型だけの場合は 128 バイト。
5. 行は種類ごとのグループ (整数、浮動小数点、可変長整数、文字・文字列、日時、その他、ユーザー定義) にまとめ、グループごとに折りたためる。
6. 既定で表示する行 (F1-04 の範囲): int8 / uint8、int16 / uint16、int32 / uint32、int64 / uint64、float、double、2 進 (8 bit)、文字 (ANSI、UTF-8、UTF-16)、GUID、Unix 時刻 (32 bit)、FILETIME、DOS 日時。その他の型は既定で非表示にし、INSP-19 で表示できる。
7. 行の右クリックメニュー: 値をコピー、すべての行をコピー (タブ区切りのテキスト)、値を編集 (INSP-17)、ポインタとして移動 (INSP-20)、この型で配列として移動 (INSP-21)、この行を非表示 (INSP-19)。
8. 読み取り専用のドキュメントでは、値の編集を無効にする (表示は同じ)。
9. 起点のオフセットをパネルの上部に表示する (例: 「0x00001F00 から」)。
10. パネルを閉じている間は解釈の計算をしない。
11. パネルのキー操作 (パネルの有効範囲。00-overview.md の 8.6): ↑ / ↓ で行を移動、Enter で値を編集 (INSP-17)、Space で 2 進の行のビットを反転 (INSP-08)、Shift+F10 / アプリケーションキーで右クリックメニュー。Hex ビューとの間のフォーカスの移動は F6 / Shift+F6 (00-overview.md の 8.2)。
12. 変換ビュー (EDIT-45) が有効なとき、インスペクタは既定で変換後 (Hex ビューの表示どおり) のバイトを解釈する。ツールバーの「元のデータを解釈」(既定オフ) で、変換前のバイトを解釈するように切り替えられる。変換後のバイトを解釈しているときの書き換え (INSP-17) は、EDIT-45 の 6 に従って逆変換して元のデータに書き込む。どちらを解釈しているかは起点のオフセットの横に表示する (例: 「変換後」)。

**画面**: 既定は右パネル。上部にツールバー (エンディアン、表示形式 (INSP-02)、日時のローカル / UTC (INSP-15)、行の設定)、その下に起点のオフセット、グループ分けした 2 列の一覧。値の列は等幅フォント。右から左に書く言語では、パネルの並びは反転するが、値の列の数値・Hex は左から右に表示する。

**巨大ファイル・長時間処理**: 起点の周辺 (最大 4 KB) だけを読むので、ファイルサイズに依存しない。

**エラー**: 読み込みエラー (不良セクタなど) の場合は、該当する行に「読み込めません」と表示する。

**受け入れ基準**:

- [ ] Ctrl+Shift+I でパネルの表示・非表示が切り替わる。
- [ ] カーソルを動かすと、50 ms 以内にすべての行が新しい位置の値に更新される。
- [ ] 末尾の 2 バイト手前にカーソルを置くと、int32 の行が「—」になる。
- [ ] 100 GB のファイルの末尾付近でも、表示が同じ速さで更新される。
- [ ] F6 でパネルにフォーカスを移し (00-overview 8.2)、↑ / ↓ で行を移動でき、ナレーターが「int32, 12345」のように型の名前と値を読み上げる。

### INSP-02 エンディアンと表示形式

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | インスペクタのツールバー、コマンドパレット「インスペクタ: エンディアンの切り替え」。ドキュメントのエンディアンの切り替えは VIEW-11 (ステータスバーのエンディアン表示をクリック、「表示: エンディアンの切り替え」) |

**概要**: 複数バイトの型をリトルエンディアンとビッグエンディアンのどちらで解釈するか、整数を何進数で表示するかを切り替える。

**仕様**:

1. エンディアン: 「ドキュメントに従う」(既定) / 「リトルエンディアン」/ 「ビッグエンディアン」。ドキュメントのエンディアンは VIEW-11 が持ち (00-overview 1.1)、「ドキュメントに従う」のときはその値で解釈する。リトル / ビッグを選ぶと、インスペクタの中だけでその値に固定する (ドキュメントのエンディアンは変えない)。この選択はドキュメントごとに付随データとして保存する (00-overview.md の 10 章)。
2. ツールバーのトグルボタンは、使っているエンディアン (「LE」/「BE」) と、ドキュメントに従っているか固定しているかを示す (インスペクタの中だけで固定しているときは「BE (インスペクタのみ)」のように表示する)。ステータスバーのエンディアン表示 (VIEW-40) はドキュメントのエンディアンを示し、クリックするとドキュメントのエンディアンを切り替える (VIEW-11)。インスペクタが「ドキュメントに従う」ならインスペクタの表示も変わる。数値検索 (04-search.md の FIND-13) の既定値はドキュメントのエンディアンに合わせる。
3. エンディアンの指定に従わない型がある (SQLite varint は常にビッグエンディアン、LEB128 はバイト順の概念がない、GUID の Windows 形式は先頭 3 フィールドが常にリトルエンディアンなど)。これらの行は名前の横に「(固定)」と表示する。
4. 整数の表示形式: 10 進 (既定) / 16 進 / 8 進。16 進は `0x` 付き、桁数は型のサイズに合わせて 0 で埋める (`0x0000002A`)。
5. 10 進の表示は地域設定の桁区切りを使う (00-overview.md の 5.4)。設定「インスペクタで桁区切りを使う」(既定オン) で無効にできる。
6. 浮動小数点の表示形式: 「最短で正確」(既定。値を元に戻せる最短の 10 進表記) / 「指数表記」/ 「16 進浮動小数点」(`0x1.8p+1`)。小数点は地域設定に従う。
7. 型ごとに一時的にエンディアンを変えるオプションはない (行を 2 つ表示したい場合は、INSP-19 で「反対のエンディアンでも表示」をオンにする。オンにした型は「int32 (BE)」のように反対のエンディアンの行を加える)。

**画面**: ツールバーのエンディアンの選択 (ドキュメントに従う / LE / BE のドロップダウン付きボタン) と表示形式のドロップダウン。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: なし。

**受け入れ基準**:

- [ ] `01 02 03 04` で、LE では uint32 が 67,305,985、BE では 16,909,060 と表示される。
- [ ] インスペクタが「ドキュメントに従う」のとき、ステータスバーの「LE」をクリックすると「BE」に変わり、インスペクタの表示も変わる。
- [ ] インスペクタで「ビッグエンディアン」に固定すると、ステータスバーと Hex ビューのエンディアンは変わらず、インスペクタだけが BE で解釈する。その後ステータスバーで切り替えても、インスペクタは BE のまま。
- [ ] 16 進表示で int16 の -1 が `0xFFFF` と表示される。
- [ ] インスペクタのエンディアンの選択が、ドキュメントを開き直しても保たれる。

### INSP-03 整数 (8 / 16 / 32 / 64 bit)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | インスペクタの「整数」グループ |

**概要**: 8、16、32、64 bit の整数を、符号あり・符号なしで表示する。

**仕様**:

1. 行: int8、uint8、int16、uint16、int32、uint32、int64、uint64。
2. 符号ありは 2 の補数で解釈する。
3. 表示形式は INSP-02 に従う。
4. 書き換え (INSP-17) では、入力式 (00-overview.md の 6 章) で値を入力する。符号ありの行では負の値を入力できる。範囲外の値はエラーにする。

**画面**: INSP-01 の一覧の行。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 範囲外の入力は「int16 の範囲 (-32,768〜32,767) を超えています」と表示する。

**受け入れ基準**:

- [ ] `FF` で int8 が -1、uint8 が 255 と表示される。
- [ ] `00 00 00 80` (LE) で int32 が -2,147,483,648 と表示される。
- [ ] `FF FF FF FF FF FF FF FF` で uint64 が 18,446,744,073,709,551,615 と表示される。

### INSP-04 整数 (24 / 48 / 128 bit)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | インスペクタの「整数」グループ (既定で非表示) |

**概要**: 音声データやファイルシステムで使われる 24 bit / 48 bit の整数と、128 bit の整数を表示する。

**仕様**:

1. 行: int24、uint24、int48、uint48、int128、uint128。
2. 128 bit は .NET の `Int128` / `UInt128` で扱う。10 進では最大 39 桁を表示する。
3. 表示形式・書き換えは INSP-03 と同じ。

**画面**: INSP-01 の一覧の行。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: INSP-03 と同じ。

**受け入れ基準**:

- [ ] `FF FF 7F` (LE) で int24 が 8,388,607 と表示される。
- [ ] `00 00 80` (LE) で int24 が -8,388,608 と表示される。
- [ ] 16 バイトすべて `FF` で int128 が -1、uint128 が 340,282,366,920,938,463,463,374,607,431,768,211,455 と表示される。

### INSP-05 浮動小数点 (float / double)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | インスペクタの「浮動小数点」グループ |

**概要**: IEEE 754 の単精度 (float、32 bit) と倍精度 (double、64 bit) を表示する。

**仕様**:

1. 行: float、double。
2. 特殊な値は次のように表示する: `+0`、`-0`、`∞`、`-∞`、`NaN` (ペイロードを `NaN (0x7FC00000)` のようにビット列で示す)。非正規化数は値の後ろに「(非正規化数)」と付ける。
3. 表示形式は INSP-02 に従う。
4. 書き換えでは、小数点 `.` のみの 10 進表記、指数表記、`inf`、`-inf`、`nan`、16 進浮動小数点 (`0x1.8p+1`) を受け付ける。最も近い値に丸めて書き込み (偶数への丸め)、丸めで値が変わった場合はパネルの下部に「格納される値: 0.100000001490116」と表示する。

**画面**: INSP-01 の一覧の行。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: float の範囲を超える値 (`1e39` など) は、無限大になる旨を示してエラーにする。

**受け入れ基準**:

- [ ] `00 00 80 3F` (LE) で float が 1 と表示される。
- [ ] `00 00 00 00 00 00 F0 7F` (LE) で double が ∞ と表示される。
- [ ] float の行に `0.1` を入力すると `CD CC CC 3D` が書き込まれ、格納される値が表示される。

### INSP-06 拡張の浮動小数点と固定小数点

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | インスペクタの「浮動小数点」グループ (既定で非表示) |

**概要**: half、bfloat16、80 bit の拡張倍精度、Turbo Pascal の Real48、固定小数点を表示する。

**仕様**:

1. 行と解釈:

   | 行 | サイズ | 解釈 |
   | --- | --- | --- |
   | half | 2 バイト | IEEE 754 binary16 (.NET の `Half`) |
   | bfloat16 | 2 バイト | 符号 1 bit、指数 8 bit、仮数 7 bit (float の上位 16 bit) |
   | long double (80 bit) | 10 バイト | x87 の拡張倍精度。符号 1 bit、指数 15 bit、整数ビットを明示した仮数 64 bit |
   | Real48 | 6 バイト | Turbo Pascal の 6 バイト実数。先頭バイトが指数 (バイアス 129)、残りが仮数 39 bit と符号 1 bit。指数 0 は値 0 |
   | 固定小数点 | 1 / 2 / 4 / 8 バイト | 符号の有無、全体のビット数、小数部のビット数を指定する (Q 形式) |

2. long double の表示は、最も近い 80 bit の値に丸めたときに同じ値に戻る 10 進の表記のうち、桁数が最も少ないものとする (有効数字は最大 21 桁。`BigInteger` で正確に 10 進に変換して求める)。例: π に最も近い 80 bit の値 (`35 C2 68 21 A2 DA 0F C9 00 40`、LE) は `3.1415926535897932385` (20 桁) と表示する。整数ビットが 0 なのに指数が 0 でない値 (非正規の表現) は「非正規の表現」と表示する。
3. 固定小数点の既定の行は「16.16 (符号あり, 32 bit)」と「8.8 (符号あり, 16 bit)」。行の設定で、符号・全体のビット数 (8 / 16 / 32 / 64)・小数部のビット数 (0〜全体のビット数) を指定した行を追加できる (最大 16 行)。
4. 固定小数点の値は、小数部のビット数から正確に表せる桁数まで表示する (16.16 なら小数点以下 16 桁まで、末尾の 0 は省く)。
5. 書き換えは INSP-05 と同じ書式で受け付け、最も近い値に丸める。固定小数点では範囲外の値をエラーにする。

**画面**: INSP-01 の一覧の行。固定小数点の行の追加は行の設定 (INSP-19) から行う。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 範囲外の入力はエラーにする。

**受け入れ基準**:

- [ ] `00 3C` (LE) で half が 1 と表示される。
- [ ] `80 3F` (LE) で bfloat16 が 1 と表示される。
- [ ] `00 00 00 00 00 00 00 80 FF 3F` (LE) で long double が 1 と表示される。
- [ ] `00 00 01 00` (LE) で 16.16 が 1 と表示される。
- [ ] long double の行に `3.14159265358979323846` を入力して書き込み、表示が同じ値に戻る (書き込まれた 80 bit の値と、表示の文字列を 80 bit の値に戻したものが一致する。文字列は `3.1415926535897932385`)。

### INSP-07 可変長整数 (LEB128 / SQLite varint)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | インスペクタの「可変長整数」グループ (既定で非表示) |

**概要**: DWARF や WebAssembly で使われる LEB128 と、SQLite の可変長整数を表示する。

**仕様**:

1. 行: ULEB128 (符号なし)、SLEB128 (符号あり)、SQLite varint。
2. LEB128 は最大 10 バイト (64 bit) まで読む。各行の値の後ろに使ったバイト数を表示する (例: `624485 (3 バイト)`)。10 バイト以内で終わらない場合、または 64 bit を超える場合は「64 bit を超えています」と表示する。
3. SQLite varint は 1〜9 バイト、ビッグエンディアン (9 バイト目は 8 bit すべてを使う)。エンディアンの指定に従わない (INSP-02 の 3)。
4. 対象のバイト範囲の強調 (INSP-18) は、実際に使ったバイト数の範囲にする。
5. 書き換え:
   - 新しい値の符号化の長さが元と同じなら、そのまま上書きする。
   - LEB128 で新しい値の方が短い場合は、継続ビット付きの冗長な符号化 (`0x80` を加える) で元の長さに合わせて上書きする。
   - 新しい値の方が長い場合、または SQLite varint で長さが違う場合は、エラー「バイト数が変わるため書き込めません (元: 2 バイト、新: 3 バイト)」にする。

**画面**: INSP-01 の一覧の行。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 上記の 2 と 5 のとおり。

**受け入れ基準**:

- [ ] `E5 8E 26` で ULEB128 が 624,485 (3 バイト) と表示される。
- [ ] `C0 BB 78` で SLEB128 が -123,456 (3 バイト) と表示される。
- [ ] `81 00` で SQLite varint が 128 (2 バイト) と表示される。
- [ ] 3 バイトの ULEB128 に 1 を書き込むと `81 80 00` になる。

### INSP-08 2 進表示

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | インスペクタの「その他」グループ |

**概要**: バイトを 2 進数のビット列として表示し、ビットごとに切り替えて書き換えられるようにする。

**仕様**:

1. 既定の行は「2 進 (8 bit)」。行の設定で「2 進 (16 / 32 / 64 bit)」を追加できる。16 bit 以上はエンディアンに従って値を組み立て、最上位ビットを左にして表示する。
2. 4 bit ごとに空白で区切る (`0100 0001`)。
3. 値の列で、ビットをクリックするか、ビットにフォーカスを置いて Space を押すと、そのビットを反転して書き込む (1 回の Undo)。ビット番号 (0 が最下位) をツールチップで示す。
4. 2 進の文字列 (`0b` は省略可、空白は無視) を入力して書き換えることもできる。

**画面**: INSP-01 の一覧の行。ビットは個別のボタンとして描画する。一覧で 2 進の行を選んで Tab を押すと、最上位ビットのボタンにフォーカスが移る (Shift+Tab で行に戻る)。キーボードの ← / → でビットを移動する。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 桁数が型のビット数を超える入力はエラーにする。

**受け入れ基準**:

- [ ] `41` で「0100 0001」と表示される。
- [ ] 最下位ビットをクリックすると `40` に書き換わり、Ctrl+Z で戻る。
- [ ] キーボードだけでビットを選んで反転できる (Tab でビットのボタンに入り、← / → で選び、Space で反転する)。

### INSP-09 文字 (ANSI / UTF-8 / UTF-16)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | インスペクタの「文字・文字列」グループ |

**概要**: 起点のバイトを 1 文字として各文字コードで解釈して表示する。

**仕様**:

1. 行:
   - ANSI: 表示中の文字コード (F1-06) が 1 バイト文字コードならそれで、それ以外はシステムの ANSI コードページで 1 バイトを解釈する。Shift_JIS などの 2 バイト文字コードの場合は、先行バイトなら 2 バイトで解釈する。
   - UTF-8: 起点から 1〜4 バイトの UTF-8 の並びとして解釈する。
   - UTF-16: 2 または 4 バイト (サロゲートペア) として解釈する。エンディアンに従う。
2. 値の列には文字とコードポイントを表示する (例: `あ  U+3042  (3 バイト)`)。
3. 制御文字は名前で表示する (`NUL`、`LF`、`ESC` など)。表示できない文字 (フォントにない文字) は代替フォントで表示し、それでも表示できなければコードポイントだけを表示する。
4. 不正な並び (UTF-8 の継続バイトから始まる、ペアになっていないサロゲートなど) は「不正 (継続バイト)」のように理由を表示する。
5. 書き換えでは 1 文字を入力し、その文字コードで符号化して上書きする。符号化したバイト数が元と違う場合も上書きする (後ろのバイトを上書きする。挿入はしない)。上書きする範囲は強調 (INSP-18) で事前に示す。
6. IME の変換中は書き換えを確定しない。

**画面**: INSP-01 の一覧の行。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 符号化できない文字はエラーにする。

**受け入れ基準**:

- [ ] `E3 81 82` で UTF-8 の行が「あ U+3042 (3 バイト)」と表示される。
- [ ] `3D D8 00 DE` (LE) で UTF-16 の行が U+1F600 と表示される。
- [ ] `80` で UTF-8 の行が「不正 (継続バイト)」と表示される。
- [ ] `0A` で ANSI の行が `LF` と表示される。

### INSP-10 文字列

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | インスペクタの「文字・文字列」グループ (既定で非表示) |

**概要**: 起点から始まる文字列を、NUL 終端または長さ付きの形式で解釈して表示する。

**仕様**:

1. 行:
   - NUL 終端の文字列: ANSI、UTF-8、UTF-16 (エンディアンに従う)。NUL (その文字コードでの 0) まで読む。
   - 長さ付きの文字列 (Pascal 形式): 先頭 1 / 2 / 4 バイトが長さ (バイト数) で、その後に文字列が続く。文字コードは ANSI または UTF-8 を選べる。2 / 4 バイトの長さはエンディアンに従う。
2. 読む長さの上限は 4 KB。表示は先頭 256 文字までで、超える場合は末尾に「…」を付ける。全体はツールチップと「値をコピー」で得られる。
3. 値の後ろに文字数とバイト数を表示する (例: `"Hello" (5 文字, 6 バイト)` — バイト数は終端または長さの部分を含む)。
4. 上限までに NUL がない場合は「終端なし (4 KB 以上)」と表示する。
5. 書き換え:
   - 新しい文字列の符号化 (終端・長さの部分を含む) が元以下のバイト数なら上書きし、残りを `00` で埋める。長さ付きの文字列では長さの部分も書き換える。
   - 元より長い場合はエラー「元の長さ (6 バイト) を超えています」にする。

**画面**: INSP-01 の一覧の行。

**巨大ファイル・長時間処理**: 読むのは最大 4 KB。

**エラー**: 上記の 4 と 5 のとおり。

**受け入れ基準**:

- [ ] `48 65 6C 6C 6F 00` で NUL 終端 (ANSI) が `"Hello" (5 文字, 6 バイト)` と表示される。
- [ ] `05 48 65 6C 6C 6F` で Pascal 形式 (1 バイト長) が `"Hello"` と表示される。
- [ ] `"Hi"` に書き換えると `48 69 00 00 00 00` になる。

### INSP-11 GUID / UUID

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | インスペクタの「その他」グループ |

**概要**: 16 バイトを GUID として表示し、バージョン 1 (時刻ベース) と 7 の UUID は時刻などの構成要素に分解して表示する。

**仕様**:

1. 行:
   - GUID (Windows): 先頭の 4 / 2 / 2 バイトのフィールドをリトルエンディアンで解釈する (`System.Guid` の形式)。表示は `{00112233-4455-6677-8899-AABBCCDDEEFF}`。
   - UUID (RFC 9562): 16 バイトをそのままの順序 (ビッグエンディアン) で解釈する。表示は `00112233-4455-6677-8899-aabbccddeeff`。
2. 両方の行はエンディアンの指定に従わない (INSP-02 の 3)。
3. 各行は展開でき、次の構成要素を表示する。
   - バージョン (1〜8、それ以外は「不明」) とバリアント (NCS / RFC / Microsoft / 予約)。
   - バージョン 1 と 6: タイムスタンプ (1582-10-15 00:00 UTC からの 100 ナノ秒単位、60 bit) を日時 (INSP-15 の表示に従う) で、クロックシーケンス (14 bit)、ノード (48 bit、`00-11-22-33-44-55` の形式。マルチキャストビットが 1 の場合は「乱数のノード」と表示)。
   - バージョン 7: 先頭 48 bit の Unix 時刻 (ミリ秒) を日時で表示する。
   - 構成要素の行を選ぶと、そのフィールドのバイトを強調する (INSP-18)。
4. 書き換えでは、波括弧・ハイフンの有無を問わず 32 桁の Hex を受け付ける。Windows の行では Windows 形式として、UUID の行では RFC 形式としてバイト列に変換する。

**画面**: INSP-01 の一覧の行。展開ボタン付き。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 32 桁でない入力はエラーにする。

**受け入れ基準**:

- [ ] `33 22 11 00 55 44 77 66 88 99 AA BB CC DD EE FF` で GUID (Windows) が `{00112233-4455-6677-8899-AABBCCDDEEFF}` と表示される。
- [ ] バージョン 1 の UUID でタイムスタンプが日時として表示され、ノードが MAC アドレスの形式で表示される。
- [ ] バージョン 7 の UUID で生成時刻 (ミリ秒) が表示される。

### INSP-12 色

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | インスペクタの「その他」グループ (既定で非表示) |

**概要**: バイトを色として解釈し、色見本と数値で表示する。

**仕様**:

1. 行:

   | 行 | サイズ | 解釈 |
   | --- | --- | --- |
   | RGBA8 | 4 バイト | R、G、B、A の順に 1 バイトずつ |
   | BGRA8 | 4 バイト | B、G、R、A の順 (Windows の DIB など) |
   | RGB8 | 3 バイト | R、G、B の順 |
   | RGB565 | 2 バイト | 16 bit の値 (エンディアンに従う) の上位から R 5 bit、G 6 bit、B 5 bit。8 bit への広げ方は下記 |

   RGB565 の成分は、上位のビットを下位に繰り返して 8 bit に広げる。5 bit の値 *v* は `(v << 3) | (v >> 2)`、6 bit の値 *v* は `(v << 2) | (v >> 4)` とする (例: 5 bit の 31 は 255、6 bit の 32 は 130、0 は 0)。

2. 値の列に色見本 (縦横 16 px の四角、枠線付き) と `#RRGGBBAA` 形式の文字列、10 進の成分 (`R 255, G 128, B 0, A 255`) を表示する。アルファのない形式 (RGB8、RGB565) は A を 255 として表示する。色見本だけで情報を伝えない (00-overview.md の 11.5)。
3. 透明度のある色は、市松模様の上に重ねて表示する。
4. 書き換え: `#RRGGBB`、`#RRGGBBAA` の文字列、または色の選択ダイアログ (WinUI の `ColorPicker` をフライアウトで表示) で指定する。RGB565 では最も近い値に丸め、丸めた結果を表示する。

**画面**: INSP-01 の一覧の行。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 不正な色の文字列はエラーにする。

**受け入れ基準**:

- [ ] `FF 80 00 FF` で RGBA8 が `#FF8000FF` と表示され、オレンジの色見本が出る。
- [ ] `00 F8` (LE) で RGB565 が `#FF0000FF` (`R 255, G 0, B 0, A 255`) の赤と表示される。
- [ ] ハイコントラストテーマでも、色の値が文字で読める。

### INSP-13 日時 (基本の形式)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | インスペクタの「日時」グループ |

**概要**: よく使われる日時の形式 (Unix 時刻、FILETIME、DOS 日時) を解釈して表示する。

**仕様**:

1. 行と解釈:

   | 行 | サイズ | 解釈 | タイムゾーン |
   | --- | --- | --- | --- |
   | Unix 時刻 (32 bit) | 4 バイト | 1970-01-01 00:00:00 からの秒数 (符号あり) | UTC |
   | Unix 時刻 (32 bit 符号なし) | 4 バイト | 同上 (符号なし。2106 年まで) | UTC |
   | Unix 時刻 (64 bit) | 8 バイト | 1970-01-01 からの秒数 (符号あり) | UTC |
   | FILETIME | 8 バイト | 1601-01-01 00:00:00 からの 100 ナノ秒単位 (符号なし) | UTC |
   | DOS 日付 | 2 バイト | 上位から年 7 bit (1980 年起点)、月 4 bit、日 5 bit | なし |
   | DOS 時刻 | 2 バイト | 上位から時 5 bit、分 6 bit、秒÷2 5 bit | なし |
   | DOS 日時 | 4 バイト | 先頭 2 バイトが DOS 時刻、後の 2 バイトが DOS 日付 (FAT のディレクトリエントリの順) | なし |

2. 既定で表示するのは、Unix 時刻 (32 bit)、FILETIME、DOS 日時 (INSP-01 の 6)。
3. 日時として表せない値は「範囲外」と表示し、生の数値を括弧内に示す (例: `範囲外 (9223372036854775807)`)。表示できる範囲は 0001-01-01〜9999-12-31。
4. DOS 日時の各フィールドが不正な場合 (月が 0 または 13 以上、日が 0、時が 24 以上など) は「不正 (月 = 13)」のように理由を表示する。
5. 表示形式とタイムゾーンの扱いは INSP-15 に従う。
6. 書き換えの入力は INSP-15 に従う。DOS 時刻は 2 秒単位に切り捨て、切り捨てた場合は格納される値を表示する。

**画面**: INSP-01 の一覧の行。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 形式の範囲外の日時 (DOS 日付で 1979 年など) の入力はエラーにし、範囲を示す。

**受け入れ基準**:

- [ ] `00 00 00 00` で Unix 時刻 (32 bit) が 1970-01-01 00:00:00 (UTC 表示) と表示される。
- [ ] `00 80 3E D5 DE B1 9D 01` (LE) で FILETIME が 1970-01-01 00:00:00 UTC と表示される。
- [ ] DOS 日時 `00 00 21 00` (LE) が 1980-01-01 00:00:00 と表示される。
- [ ] 月が 13 の DOS 日付が「不正 (月 = 13)」と表示される。

### INSP-14 日時 (拡張の形式)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | インスペクタの「日時」グループ (既定で非表示) |

**概要**: OLE、HFS+、APFS、Mac の絶対時刻、SQL Server、ミリ秒単位の Unix 時刻、10 進の数字で書かれた日時などを表示する。

**仕様**:

1. 行と解釈:

   | 行 | サイズ | 解釈 | タイムゾーン |
   | --- | --- | --- | --- |
   | Unix 時刻 (ミリ秒, 64 bit) / Java | 8 バイト | 1970-01-01 からのミリ秒 (符号あり)。Java の `System.currentTimeMillis()` と同じ | UTC |
   | OLE オートメーション日付 | 8 バイト | double。1899-12-30 00:00 からの日数 (小数部は時刻) | なし |
   | HFS+ 日時 | 4 バイト | 1904-01-01 00:00:00 からの秒数 (符号なし) | UTC (旧 HFS の値はローカル時刻だが区別しない) |
   | APFS 日時 | 8 バイト | 1970-01-01 からのナノ秒 (符号なし 64 bit) | UTC |
   | Mac 絶対時刻 (Cocoa) | 8 バイト | double。2001-01-01 00:00:00 からの秒数 | UTC |
   | SQL Server datetime | 8 バイト | 先頭 4 バイトが 1900-01-01 からの日数 (符号あり)、後の 4 バイトが 1/300 秒単位の時刻 | なし |
   | SQL Server smalldatetime | 4 バイト | 先頭 2 バイトが 1900-01-01 からの日数、後の 2 バイトが 0 時からの分 | なし |
   | .NET DateTime | 8 バイト | 下位 62 bit が 0001-01-01 からの 100 ナノ秒単位、上位 2 bit が種類 (Unspecified / UTC / Local) | 種類に従う |
   | 10 進の数字の日時 | 8〜14 バイト | ASCII の数字。`YYYYMMDDhhmmss` (14 桁)、`YYMMDDhhmmss` (12 桁、50〜99 は 19xx 年)、`YYYYMMDD` (8 桁)、Unix 秒 (10 桁)、Unix ミリ秒 (13 桁) を、長い形式から順に試す | 数字の形式は「なし」、Unix 秒・ミリ秒は UTC |

2. 10 進の数字の日時は、起点から ASCII の数字が続く桁数で形式を決める。数字が 8 桁未満の場合は「—」を表示する。日付として不正 (月 = 13 など) な場合は次に短い形式を試し、どれも不正なら「不正」と表示する。値の後ろに使った形式を示す (例: `2026-10-07 12:34:56 (YYYYMMDDhhmmss)`)。
3. 範囲外・不正な値の表示は INSP-13 と同じ。
4. 表示形式・タイムゾーン・書き換えは INSP-15 に従う。10 進の数字の日時の書き換えでは、元と同じ形式・桁数で書き込む。

**画面**: INSP-01 の一覧の行。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: INSP-13 と同じ。

**受け入れ基準**:

- [ ] OLE オートメーション日付で double の 0 が 1899-12-30 00:00:00 と表示される。
- [ ] HFS+ 日時で `00 00 00 00` が 1904-01-01 00:00:00 UTC と表示される。
- [ ] Mac 絶対時刻で double の 0 が 2001-01-01 00:00:00 UTC と表示される。
- [ ] ASCII の `20261007123456` が 2026-10-07 12:34:56 と表示される。
- [ ] SQL Server datetime で、日数 0・時刻 300 が 1900-01-01 00:00:01 と表示される。

### INSP-15 日時の表示形式とタイムゾーン

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | インスペクタのツールバー「ローカル / UTC」、行の設定 |

**概要**: 日時の行を、ローカル時刻と UTC のどちらで、どの書式で表示するかを決める。日時の入力の書式も定める。

**仕様**:

1. タイムゾーンの切り替え: 「ローカル時刻」(既定) / 「UTC」。タイムゾーンが UTC の形式 (INSP-13、INSP-14 の表) は、選んだ方に変換して表示し、末尾に「(UTC)」または「(UTC+09:00)」のようにオフセットを付ける。
2. タイムゾーンが「なし」の形式 (DOS、OLE、SQL Server など) は変換せず、値のとおり表示し、末尾に「(タイムゾーンなし)」と付ける。
3. 書式: 「地域設定に従う」(既定。日付の順序と区切りは地域設定、時刻は 24 時間制) / 「ISO 8601」(`2026-10-07T12:34:56.789+09:00`)。秒の小数部は形式の精度に合わせて表示する (FILETIME は 7 桁、ミリ秒の形式は 3 桁、秒単位の形式は表示しない)。末尾の 0 は省く。
4. 書き換えの入力は地域設定に依存しない書式だけを受け付ける (00-overview.md の 5.4)。
   - ISO 8601: `2026-10-07`、`2026-10-07 12:34:56`、`2026-10-07T12:34:56.789`、末尾に `Z` または `+09:00` を付けられる。
   - `now`: 現在時刻。
   - タイムゾーンを書かない場合は、1 の切り替えで選んでいるタイムゾーンとみなす。タイムゾーンが「なし」の形式では、入力した値をそのまま使う。
5. 形式の精度より細かい入力は切り捨て、切り捨てた場合は格納される値をパネルの下部に表示する。

**画面**: ツールバーのトグルボタン「ローカル / UTC」。書式は行の設定 (INSP-19) の画面で選ぶ。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 解釈できない入力は「日時は 2026-10-07 12:34:56 の形式で入力してください」と表示する。

**受け入れ基準**:

- [ ] 日本のタイムゾーンで、Unix 時刻 0 が「ローカル」では 1970-01-01 09:00:00 (UTC+09:00)、「UTC」では 1970-01-01 00:00:00 (UTC) と表示される。
- [ ] DOS 日時はローカル / UTC を切り替えても表示が変わらない。
- [ ] `2026-10-07T00:00:00Z` を FILETIME の行に入力すると、対応する 8 バイトが書き込まれる。
- [ ] 地域設定をドイツ語にしても、`2026-10-07 12:34:56` の入力を受け付ける。

### INSP-16 1 命令の逆アセンブル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案、F4-01 の逆アセンブルの実装後) |
| 呼び出し | インスペクタの「その他」グループ (既定で非表示) |

**概要**: 起点のバイトを 1 命令の機械語として逆アセンブルして表示する。逆アセンブラ (エンジン、対応アーキテクチャ、構文) は ANA-23 のものを使い、この機能はインスペクタでの表示だけを定める (00-overview 1.1)。

**仕様**:

1. アーキテクチャとモードを行の設定で選ぶ。選べるものは逆アセンブルビュー (ANA-23 の 1) で対応するものと同じ (x86 16 / 32 / 64 bit、ARM、Thumb、ARM64、MIPS、PowerPC、RISC-V など)。既定は x86 64 bit。エンディアンを持つアーキテクチャでは、インスペクタのエンディアン (INSP-02) に従う。

3. 値の列に、ニーモニックとオペランド、命令の長さを表示する (例: `mov eax, dword ptr [rbx + 8]  (3 バイト)`)。
4. 不正な命令の場合は「不正な命令」と表示する。
5. 対象のバイトの強調 (INSP-18) は命令の長さの範囲にする。
6. この行からは書き換えできない。
7. 分岐命令で分岐先が求まる場合は、右クリックメニューの「分岐先へ移動」で移動できる (ジャンプ履歴に記録する。分岐先の求め方は ANA-25)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 逆アセンブラの読み込みに失敗した場合は、行に「逆アセンブラを使えません」と表示する。

**受け入れ基準**:

- [ ] x86 64 bit で `48 89 E5` が `mov rbp, rsp (3 バイト)` と表示される。
- [ ] ARM64 で 4 バイトの命令が表示される。
- [ ] 分岐命令から「分岐先へ移動」で、分岐先のオフセットに移動する。

### INSP-17 インスペクタからの値の書き換え

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-04 |
| 呼び出し | 値の列をダブルクリック、行を選んで Enter、右クリックメニュー「値を編集」 |

**概要**: インスペクタの行に値を入力すると、その型の表現に変換したバイト列を起点に書き込む。

**仕様**:

1. 値の列が入力欄に変わる。入力欄には現在の値が全選択された状態で入る。Enter で確定、Esc で取り消す。フォーカスが外れたときは取り消す。
2. 入力の書式は各型の項に従う。整数は入力式 (00-overview.md の 6 章) を使える (例: `cur`、`0x100*4`)。入力欄の横に、書き込まれるバイト列 (Hex) を表示する。
3. 書き込みは、編集モード (上書き / 挿入) に関係なく常に上書きで行う。型のサイズ分のバイトを置き換え、ファイルの長さを変えない。
4. 書き込む範囲が末尾を超える場合はエラーにする。
5. 1 回の書き換えは 1 回の Undo で戻せる。マクロ記録 (F3-06) では「インスペクタでの書き換え (型、オフセット、値)」として記録する。
6. 書き込みの後もカーソルは動かさない。
7. 読み取り専用のドキュメントでは入力欄にならず、「読み取り専用です」とツールチップで示す。
8. 入力中は、書き込む範囲を Hex 表示で強調する (INSP-18)。

**画面**: 値の列の入力欄。不正な入力は 00-overview.md の 9 章の入力欄と同じく、赤枠と説明文で示す。

**巨大ファイル・長時間処理**: データエンジンの上書き操作として 100 ms 以内。

**エラー**: 範囲外・不正な書式・末尾を超える書き込みは、入力欄の下に説明文を出し、確定できないようにする。

**受け入れ基準**:

- [ ] uint16 の行に `0x1234` を入力して Enter を押すと、LE では `34 12` が書き込まれる。
- [ ] 挿入モードでも、書き換えでファイルの長さが変わらない。
- [ ] 書き換えが Ctrl+Z 1 回で戻る。
- [ ] 末尾の 2 バイト前で int32 を書き換えようとするとエラーになる。
- [ ] Esc で入力を取り消すと、データが変わらない。

### INSP-18 対象のバイトの強調

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | インスペクタの行にマウスを重ねる、または行を選ぶ |

**概要**: インスペクタの行が解釈しているバイトの範囲を、Hex 表示上で強調して示す。

**仕様**:

1. 行にマウスを重ねている間、または行がキーボードで選ばれている間、その型が使うバイト範囲 (可変長の型は実際に使った範囲) を Hex 列とテキスト列で枠線付きの背景で強調する。
2. 強調は選択範囲とは別の表示で、選択範囲を変えない。ほかの強調表示との重ね順は VIEW-17 (層 3「インスペクタの対象の強調」) に従う。
3. ハイコントラストテーマでは、システムの強調色の枠線で示す。
4. 設定「インスペクタの対象を強調する」(既定オン) で無効にできる。

**画面**: Hex ビュー上の枠線と背景。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: なし。

**受け入れ基準**:

- [ ] int32 の行にマウスを重ねると、起点から 4 バイトが強調される。
- [ ] ULEB128 の行では、実際に使ったバイト数だけが強調される。
- [ ] 強調しても選択範囲は変わらない。

### INSP-19 行の表示・非表示と並べ替え

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | インスペクタのツールバー「行の設定」、行の右クリックメニュー「この行を非表示」 |

**概要**: インスペクタに表示する行を選び、順序を変える。

**仕様**:

1. 「行の設定」ではすべての型をグループごとにチェックボックス付きで一覧にし、表示する行を選ぶ。
2. 行の順序は、ドラッグ、または行の設定の「上へ」「下へ」ボタンで変える。グループの順序も同じように変えられる。
3. 型ごとのオプション (反対のエンディアンでも表示 (INSP-02 の 7)、固定小数点の形式 (INSP-06)、逆アセンブルのアーキテクチャ (INSP-16) など) も行の設定で指定する。
4. 行の構成は名前を付けたプリセットとして保存できる。組み込みのプリセット: 「基本」(既定、INSP-01 の 6)、「すべて」、「日時」、「組み込み向け」(整数、固定小数点、half、2 進)。
5. 「既定に戻す」で「基本」に戻す。
6. 行の構成はアプリ全体で共通にする (ドキュメントごとではない)。

**画面**: パネル内に重ねて表示する設定画面 (フライアウト)。キーボードだけで操作できる。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: なし。

**受け入れ基準**:

- [ ] 「この行を非表示」で行が消え、行の設定で再び表示できる。
- [ ] 行の順序を変えると、再起動後も保たれる。
- [ ] プリセット「すべて」で、この文書のすべての型が表示される。
- [ ] キーボードだけで行の順序を変えられる。

### INSP-20 ポインタとして移動

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-09 |
| 呼び出し | 整数の行の右クリックメニュー「ポインタとして移動」、コマンドパレット「ポインタとして移動」 |

**概要**: 整数の値をオフセットまたはアドレスとみなして、その位置に移動する。

**仕様**:

1. 対象は整数の行 (8〜64 bit、符号あり・なし、可変長整数を含む)。
2. 解釈の方法 (サブメニューで選ぶ。最後に使った方法を既定にする):
   - 「絶対 (オフセット)」: 値をドキュメントのオフセットとする。
   - 「絶対 (アドレス)」: 値を表示上のアドレスとし、ベースアドレスを引いてオフセットにする。プロセスメモリでは仮想アドレスとして扱う。
   - 「カーソルからの相対」: 起点 + 値。
   - 「値の直後からの相対」: 起点 + 型のサイズ + 値 (x86 の相対分岐・RIP 相対など)。
   - 「基準を指定して相対」: 入力式で指定した基準 (例: `bm.header`、`0x400000` の引き算は `値 - 0x400000` として「基準」に `-0x400000` を指定) + 値。
3. 符号ありの行では負の値を後方への相対として扱う。
4. 移動はジャンプ履歴 (F1-13) に記録し、Alt+← で元の位置に戻れる。
5. 移動先がドキュメントの範囲外の場合は移動しない。

**画面**: 右クリックメニューのサブメニュー。「基準を指定して相対」は入力欄のフライアウトを開く。

**巨大ファイル・長時間処理**: 任意の位置へのジャンプの性能目標 (100 ms 以内) に従う。

**エラー**: 範囲外の場合は InfoBar に「移動先 0x1234567890 はドキュメントの範囲外です (長さ 0x100000)」と表示する。

**受け入れ基準**:

- [ ] uint32 の値 `0x100` で「絶対 (オフセット)」を選ぶと、オフセット 0x100 に移動する。
- [ ] ベースアドレス 0x400000 のドキュメントで、値 `0x401000` を「絶対 (アドレス)」で移動すると、オフセット 0x1000 に移動する。
- [ ] int8 の値 -16 で「値の直後からの相対」を選ぶと、起点 + 1 - 16 に移動する。
- [ ] 移動後に Alt+← で元の位置に戻る。

### INSP-21 配列として前後の要素に移動

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-09 |
| 呼び出し | 行の右クリックメニュー「この型で配列として移動」、インスペクタのツールバーの「前の要素」「次の要素」ボタン |

**概要**: 選んだ型を配列の要素とみなし、要素のサイズ単位でカーソルを前後に移動する。構造体の配列の値を順に確認するときに使う。

**仕様**:

1. 「この型で配列として移動」を選ぶと配列モードになり、ツールバーに「前の要素」「次の要素」ボタン、要素番号、要素のサイズ (間隔) の入力欄を表示する。
2. 要素のサイズの既定は型のサイズ。構造体の配列の場合は、入力式で間隔を指定できる (例: `0x28`)。
3. 配列モードに入ったときの起点を要素 0 とし、要素番号 = (カーソル - 要素 0 の位置) ÷ 間隔 で表示する。割り切れない位置では「(要素の境界ではありません)」と表示する。
4. 要素番号の欄に番号を入力すると、その要素に移動する (負の番号も可)。
5. 配列モードの間は、選んだ型の行を強調表示し、Hex 表示上で要素の境界を細い線で示す (表示範囲だけ)。
6. Esc (インスペクタにフォーカスがあるとき) またはツールバーの「配列モードを終了」で終了する。
7. 移動はジャンプ履歴に記録しない (連続した移動で履歴を埋めないため)。

**画面**: インスペクタのツールバーに配列モードの操作部を加える。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 移動先がドキュメントの範囲外になる場合はボタンを無効にする。

**受け入れ基準**:

- [ ] uint32 で配列モードにし、「次の要素」を 3 回押すと、起点 + 12 に移動し、要素番号が 3 と表示される。
- [ ] 間隔を `0x28` にすると、40 バイトずつ移動する。
- [ ] 要素番号に 10 を入力すると、起点 + 間隔 × 10 に移動する。

### INSP-22 ユーザー定義型

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-09 (プラグインによる追加は F3-07) |
| 呼び出し | 行の設定 (INSP-19) の「ユーザー定義型」グループ |

**概要**: 利用者が定義した型をインスペクタの行に加える。テンプレート言語またはプラグインで定義する。

**仕様**:

1. 定義の方法:
   - テンプレート言語 (07-templates.md): 型の定義に「インスペクタに表示する」属性を付ける。構造体を指定した場合は、展開できる行としてフィールドを表示する。書式・変換の属性 (07-templates.md) を表示に使う。
   - プラグイン (08-automation.md): インスペクタの型の拡張点を実装する。名前、サイズ (固定または可変)、バイト列から表示文字列への変換、表示文字列からバイト列への変換 (任意) を提供する。
2. ユーザー定義型の定義ファイルは設定フォルダの `inspector/` に置き、起動時とファイルの変更時に読み込む。
3. 各型の解釈には時間の上限 (既定 50 ms) を設ける。超えた場合は「時間切れ」と表示し、起点が変わるまで再実行しない。
4. 1 つの型の失敗 (例外・構文エラー) は、その行だけに「エラー: <メッセージ>」と表示し、他の行に影響させない。
5. 書き換えは、変換 (表示文字列からバイト列) が定義されている型だけで行える。書き換えの規則は INSP-17 に従う。
6. プラグインの型は、プラグインを有効にしたときだけ表示する (08-automation.md の許可に従う)。

**画面**: INSP-01 の一覧の「ユーザー定義」グループ。

**巨大ファイル・長時間処理**: 読むのは起点から最大 4 KB (INSP-01 の 4)。それを超えるデータが必要な型は「データが足りません」と表示する。

**エラー**: 定義ファイルの読み込みエラーは、通知 (InfoBar) にファイル名・行番号・理由を表示する。

**受け入れ基準**:

- [ ] テンプレート言語で定義した 6 バイトの構造体が、展開できる行としてインスペクタに表示される。
- [ ] 無限ループする型が 50 ms で「時間切れ」になり、UI が固まらない。
- [ ] 例外を投げるプラグインの型があっても、他の行は正しく表示される。
- [ ] 定義ファイルを保存し直すと、再起動せずに行が更新される。

## 2. ブックマーク

### INSP-23 ブックマークの設定と解除

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-12 |
| 呼び出し | 移動 > ブックマーク > ブックマークの設定 / 解除 (Ctrl+F2)、Hex ビューの右クリックメニュー「ブックマークを設定」、コマンドパレット「ブックマークの設定 / 解除」 |

**概要**: カーソル位置または選択範囲にブックマークを付ける。すでにある場合は外す。

**仕様**:

1. ブックマークは次の情報を持つ: 開始オフセット、長さ (0 以上)、名前、色、コメント (INSP-24)、グループ (INSP-27)、番号 (INSP-25)、型と位置の式 (INSP-29)、作成日時、更新日時。
2. Ctrl+F2 の動作:
   - カーソル位置から始まるブックマークがある場合は外す。名前を変えた・コメントを書いたブックマークを外したときは、InfoBar に「ブックマーク "header" を削除しました」と「元に戻す」ボタンを表示する (表示する時間は UI-36 の仕様 4 の自動で閉じる通知と同じ)。
   - ない場合は付ける。選択範囲があれば選択範囲を、なければカーソル位置の 1 バイトを範囲にする。名前は「ブックマーク N」(N はドキュメント内で増える番号)、色は既定の色 (設定、既定は色の一覧の 1 番目) にする。名前などの入力は求めない。
3. 付けたあと、名前などはブックマーク一覧 (INSP-26) または右クリックメニュー「ブックマークを編集」で変えられる。
4. ドキュメントの編集に合わせて位置を調整する。
   - ブックマークより前で挿入・削除: 開始位置をずらす。
   - ブックマークの範囲内で挿入: 長さを伸ばす。範囲内の削除: 長さを縮める。
   - 範囲がすべて削除された: 長さ 0 にして削除された位置に置き、一覧で「範囲が削除されました」の印を付ける (ブックマーク自体は消さない)。
   - データの Undo / Redo では、位置も元に戻る。
5. ブックマークの追加・削除・変更は、データの Undo 履歴に入れない (ドキュメントを「変更あり」にしない)。削除の取り消しは 2 の InfoBar と、一覧の「元に戻す」(直近 20 件の削除) で行う。
6. 1 つのドキュメントのブックマークの上限は 1,000,000 件。
7. ブックマークは 00-overview.md の 10 章に従ってファイル本体とは別に保存する。
8. Hex ビューでの表示: ブックマークの範囲を色付きの背景で示し、開始位置のオフセット列に目印 (アイコン) を付ける。ハイコントラストテーマでは背景の代わりに枠線で示す。マウスを重ねると名前とコメントの冒頭をツールチップで表示する (INSP-31)。
9. スクリーンリーダー: カーソルがブックマークの範囲に入ったとき、「ブックマーク header」と読み上げる。

**画面**: Hex ビュー上の背景・目印。InfoBar。

**巨大ファイル・長時間処理**: ブックマークは区間木で管理し、表示範囲のブックマークの検索と、編集時の位置の調整をブックマーク数の O(log n) にする。100 万件でもスクロールの 60 fps を保つ。

**エラー**: 上限に達した場合は「ブックマークの上限 (1,000,000 件) に達しました」と表示し、追加しない。

**受け入れ基準**:

- [ ] Ctrl+F2 でカーソル位置にブックマークが付き、もう一度 Ctrl+F2 で外れる。
- [ ] 4 バイトを選択して Ctrl+F2 を押すと、長さ 4 のブックマークになる。
- [ ] ブックマークより前に 10 バイト挿入すると、ブックマークが 10 バイト後ろにずれ、Ctrl+Z で元の位置に戻る。
- [ ] ブックマークを付けても、タイトルバーの「変更あり」の表示にならない。
- [ ] ファイルを閉じて開き直しても、ブックマークが残っている。
- [ ] 100 万件のブックマークがあるドキュメントでスクロールが 60 fps を保つ。

### INSP-24 名前・色・コメント

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-12 |
| 呼び出し | ブックマーク一覧の「編集」、Hex ビューの右クリックメニュー「ブックマークを編集」、コマンドパレット「ブックマークを編集」 |

**概要**: ブックマークの名前・色・範囲・コメント (Markdown) を編集する。

**仕様**:

1. 編集はフライアウト (非モーダル) で行う。項目: 名前、開始オフセット、長さ (または「終了 (このバイトを含む)」のオフセット)、色、グループ、番号 (なし / 1〜9、INSP-25)、コメント。
2. 名前: 1〜256 文字。ドキュメント内で重複してよい。ただし入力式の `bm.名前` (00-overview.md の 6.2) で使えるのは、英字・数字・`_` からなり英字か `_` で始まる名前だけで、重複している場合は最初に作ったものを指す。`bm.名前` に使えない名前の場合は、フライアウトに「入力式では使えない名前です」と表示する (エラーではない)。
3. 開始オフセットと長さは入力式で入力できる。
4. 色: 8 色の一覧 (ライト・ダーク・ハイコントラストのそれぞれで判読できる色を `ThemeResource` で定義) と、任意の色 (`ColorPicker`)。任意の色は、ダークテーマでは明度を自動で調整して表示する。
5. コメント: Markdown (CommonMark) で最大 64 KB。使える要素: 見出し、強調、リスト、コード (インライン・ブロック)、表、リンク。画像と HTML は表示しない (文字列として表示する)。
   - リンク先が `#0x1F00` や `#bm.header` の形の場合は、ドキュメント内のその位置へのリンクとして扱う。
   - `http` / `https` のリンクは、確認なしで既定のブラウザで開く。それ以外のスキームのリンクは開かない。
6. コメントの編集欄は、編集とプレビューを切り替えられる。
7. 変更は入力と同時に保存する (フライアウトの「保存」ボタンはない)。Esc でフライアウトを閉じる。

**画面**: ブックマークの位置の近くに表示するフライアウト。コメント欄は等幅フォントの複数行の入力欄と、プレビュー。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 範囲がドキュメントの外になる入力は赤枠と説明文で示し、反映しない。64 KB を超えるコメントは入力できない (残りの文字数を表示する)。

**受け入れ基準**:

- [ ] 名前を「header」にすると、オフセットの入力欄で `bm.header+8` が使える。
- [ ] コメントに `**太字**` と書くと、プレビューで太字になる。
- [ ] コメントの `[ヘッダ](#0x100)` をクリックすると、オフセット 0x100 に移動する。
- [ ] ハイコントラストテーマで、8 色のブックマークがすべて判別できる (枠線の形でも区別できる)。

### INSP-25 番号付きブックマーク

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-12 |
| 呼び出し | Ctrl+Shift+1〜9 (設定)、Ctrl+1〜9 (移動) (00-overview 8.2)、移動 > ブックマーク > 番号付きブックマーク、コマンドパレット「番号付きブックマーク N を設定」「番号付きブックマーク N へ移動」 |

**概要**: 1〜9 の番号を付けたブックマークを、キー 1 つで設定・移動する。番号は 1〜9 の 9 個とする (Ctrl+Shift+0 は Windows の入力言語の切り替えに使われることがあるため。00-overview 8.7)。

**仕様**:

1. Ctrl+Shift+N (N は 1〜9) を押すと、番号 N をカーソル位置に設定する。
   - カーソル位置から始まるブックマークがあれば、そのブックマークに番号 N を付ける。
   - なければ新しいブックマーク (長さ 1、名前「[N]」) を作り、番号 N を付ける。
   - 番号 N が別のブックマークに付いていた場合は、そちらから番号を外す。外されたブックマークが番号の設定で自動的に作られ、その後変更されていないものなら、ブックマーク自体を削除する。
   - 番号 N がすでにカーソル位置のブックマークに付いている場合は、番号を外す (切り替え)。
2. Ctrl+N を押すと、番号 N のブックマークの開始位置に移動する (ジャンプ履歴に記録する)。番号 N が設定されていない場合は、ステータスバーに「番号付きブックマーク 3 は設定されていません」と表示する。
3. 番号はドキュメントごとに持つ。
4. Ctrl+1〜9 と Ctrl+Shift+1〜9 は数字キーの段でもテンキーでも押せる (00-overview.md の 8.7)。Ctrl+0 はズームを 100% に戻すキー (UI-08) で、番号付きブックマークには使わない。
5. 番号付きのブックマークは、Hex ビューのオフセット列の目印に番号を表示する。

**画面**: オフセット列の番号付きの目印。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 2 のとおり。

**受け入れ基準**:

- [ ] Ctrl+Shift+3 で番号 3 を設定し、別の位置から Ctrl+3 で戻れる。
- [ ] 別の位置で Ctrl+Shift+3 を押すと、番号 3 が新しい位置に移る。
- [ ] 設定していない番号で Ctrl+5 を押すと、ステータスバーにメッセージが出て、カーソルは動かない。
- [ ] テンキーの数字でも同じ動作になる。

### INSP-29 型付きブックマークと位置の式

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 3 提案) |
| 呼び出し | ブックマークの編集 (INSP-24) の「型」「位置の式」欄 |

**概要**: ブックマークに型 (インスペクタの型、または構造体テンプレート) を付けて値を一覧に表示し、位置を固定のオフセットではなく式で決める。

**仕様**:

1. 型: インスペクタのすべての型 (INSP-03〜INSP-16、INSP-22) と、構造体テンプレート (07-templates.md) の型名を指定できる。型を付けると、長さは型のサイズになる (可変長の型は解釈した長さ)。
2. 型付きブックマークの値は、一覧の「値」列とツールチップに表示する。エンディアンはブックマークごとに指定できる (既定はドキュメントのエンディアン。VIEW-11)。
3. 構造体テンプレートの型を付けた場合は、ブックマークを選ぶとテンプレート結果パネルにその位置の構造体を表示する。
4. 一覧の値の列から値を書き換えられる (INSP-17 の規則に従う)。
5. 位置の式: 開始オフセットを入力式 (00-overview.md の 6 章) で指定する。ドキュメントの値を読む関数 (`u8(x)`、`u16le(x)`、`u32le(x)`、`s64be(x)` など) は、すべての入力欄で使える共通の読み取り関数 (00-overview.md の 6.2) を使う。この欄では、それに加えて次の関数を使える。
   - `align(x, n)`: x を n の倍数に切り上げる (n は 1 以上)。
   - 例: PE ヘッダの位置は `u32le(0x3C)`。セクション表は `bm.pe + 0x18 + u16le(bm.pe + 0x14)`。4 バイト境界にそろえた位置は `align(bm.data + u16le(bm.data), 4)`。
6. 位置の式を持つブックマークは、ドキュメントが編集されるたびに (最後の編集から 200 ms 後に) 式を評価し直して位置を更新する。INSP-23 の 4 の位置の調整は行わない。
7. 式の中の `bm.名前` の参照は 32 段まで。循環する参照はエラーにする。
8. 一覧で、位置の式を持つブックマークには「式」の印を付ける。

**画面**: ブックマークの編集フライアウトの「型」(検索できるドロップダウン)、「エンディアン」、「位置の式」(入力欄と解釈結果) の欄。

**巨大ファイル・長時間処理**: 1 つの式で読むのは関数の呼び出し 1 回あたり最大 8 バイト。式の評価の合計時間が 1 回の再評価で 100 ms を超える場合は、残りを次の再評価に回す。

**エラー**: 式のエラー (構文、循環参照、範囲外の読み込み) は、一覧のそのブックマークの行に警告の印と理由を表示し、位置は最後に評価できた値のままにする。

**受け入れ基準**:

- [ ] 位置の式 `u32le(0x3C)` のブックマークが、EXE ファイルの PE ヘッダの位置を指す。
- [ ] オフセット 0x3C の値を書き換えると、200 ms 後にブックマークの位置が変わる。
- [ ] 型 uint32 のブックマークの値が一覧に表示され、一覧から書き換えられる。
- [ ] 2 つのブックマークが互いを参照すると、両方に循環参照のエラーが表示される。

**巨大ファイル・長時間処理**: 10 万件を超える読み書きは長時間処理として扱う。

**エラー**: 形式が不正なファイルは、行番号 (CSV) または位置 (JSON / XML) と理由を表示し、何も読み込まない。

**受け入れ基準**:

- [ ] JSON にエクスポートして別のドキュメントにインポートすると、グループ・番号・コメントを含めて同じブックマークになる。
- [ ] CSV を Excel で開いて編集し、インポートできる。
- [ ] オフセットのずれ `+0x200` を指定すると、すべてのブックマークが 0x200 後ろに読み込まれる。
- [ ] 不正な JSON を読み込むと、理由が表示され、ブックマークは変わらない。

### INSP-31 位置マネージャ (長い説明とツールチップ)

| 項目 | 内容 |

### INSP-32 注釈の表示 (共通の注釈レイヤー)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 表示 > 注釈、コマンドパレット「注釈の表示切り替え」「注釈の列の表示切り替え」 |

**概要**: ブックマーク以外の機能 (YARA、構造体テンプレート、スクリプトなど) がバイト範囲に付けるラベル・色・説明を、共通の仕組みで Hex ビューに表示する。

**仕様**:

1. 注釈は次の情報を持つ: 範囲 (開始・長さ)、ラベル (最大 256 文字)、色、説明 (Markdown、最大 64 KB)、出どころ。
2. 出どころの種類: ブックマーク、YARA (04-search.md の FIND-33)、すべて検索の結果 (FIND-20)、構造体テンプレート (07-templates.md)、スクリプト・プラグイン (08-automation.md)。出どころごとに表示 / 非表示を切り替えられる。

4. 表示:
   - 範囲の背景色、または下線 (出どころごとに選べる。既定はブックマークとテンプレートが背景色、YARA と検索の結果が枠線)。
   - 「注釈の列」(既定は非表示): テキスト列の右に列を加え、その行で始まる注釈のラベルを表示する。収まらない部分は「…」で省く。1 行に複数ある場合は「header +2」のように件数を示す。
   - 同じバイトに重なる注釈は、内側の範囲ほど上に描画する。重なりは最大 4 段まで線で区別し、それを超える分は描画しない (ツールチップでは全件を示す)。
5. ツールチップ: マウスを重ねると、そのバイトを含むすべての注釈 (出どころ、ラベル、範囲、説明の冒頭) を表示する。INSP-31 の「カーソル位置の説明を表示」も、ブックマーク以外の注釈を含めて表示する。
6. ほかの強調表示との重なりの順序は VIEW-17 に従う。ブックマークとテンプレートの出どころの注釈は、それぞれ VIEW-17 のブックマークの層 (層 7) とテンプレートの層 (層 9) で描き、それ以外の出どころ (YARA、すべて検索の結果、スクリプト・プラグイン) は注釈の層 (層 8) で描く。注釈どうしの重なりは 4 の規則に従う。

**画面**: Hex ビューの背景・枠線・下線、注釈の列。表示 > 注釈 のサブメニューに出どころごとのチェック。

**巨大ファイル・長時間処理**: 注釈は出どころごとに区間木で持ち、表示範囲の注釈だけを取り出す。注釈が合計 1,000 万件あっても、表示範囲の取り出しは 1 フレームあたり 2 ms 以内とする。

**エラー**: なし。

**受け入れ基準**:

- [ ] YARA の一致が注釈として枠線で表示され、ツールチップにルール名が出る。
- [ ] 注釈の列をオンにすると、行の右にラベルが表示される。
- [ ] 出どころ「YARA」を非表示にすると、YARA の注釈だけが消える。
- [ ] 1 つのバイトに 3 つの注釈が重なっていると、ツールチップに 3 件とも表示される。

## 4. 色付けルール

### INSP-33 色付けルール

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-06 |
| 呼び出し | 表示 > 色付けルール、コマンドパレット「色付けルール」「選択範囲の値で色付けルールを作成」 |

**概要**: 値・範囲・パターン・正規表現などの条件に一致したバイトを、指定の色で表示する。データを変えずに見た目だけを変える。

**仕様**:

1. ルールは次の情報を持つ: 名前、有効 / 無効、条件、文字色、背景色、枠線 (なし / 実線 / 破線 / 点線)、適用先 (Hex 列 / テキスト列 / 両方、既定は両方)、範囲 (ドキュメント全体 / オフセット範囲)。
2. 条件の種類:

   | 種類 | 指定 | 例 |
   | --- | --- | --- |
   | バイト値 | 値と範囲の並び | `00`、`20-7E`、`7F, 80-FF` |
   | オフセット範囲 | 開始と「終了 (このバイトを含む)」の入力式 | `0x0`〜`0x3F`、`bm.header`〜`bm.header+0x3F`、`sel.start`〜`sel.last` |
   | 周期 | オフセット mod x = y と長さ | 512 バイトごとの先頭 2 バイト |
   | Hex パターン | ワイルドカード付きの Hex (04-search.md の FIND-06) | `50 4B 03 04` |
   | テキスト | 文字列、文字コード、大文字・小文字の区別 (FIND-07、FIND-10) | `PNG` |
   | 正規表現 | テキストまたはバイト列の正規表現 (FIND-18、FIND-19)。一致の最大長は 256 バイト | `[\x00-\x1F]{8,}` |
   | 数値 | 型 (整数・浮動小数点)、エンディアン、値または範囲、位置の条件 | uint32 で `0..0xFF`、4 の倍数の位置 |

3. ルールの集まりは 2 種類ある。
   - 全体のルール: すべてのドキュメントに適用する。設定として保存する。
   - ドキュメントのルール: そのドキュメントだけに適用する。付随データ (00-overview.md の 10 章) として保存する。
4. 1 つの集まりのルールの上限は 256 件。
5. 組み込みのプリセット (既定ではすべて無効): 「ゼロを薄く表示」(`00` の文字色を薄くする)、「印字可能な ASCII」(`20-7E`)、「制御文字」(`00-1F, 7F`)、「`FF`」、「上位ビットが 1」(`80-FF`)。
6. 「選択範囲の値で色付けルールを作成」: 選択範囲の内容 (1〜256 バイト) を Hex パターンの条件にしたルールを作り、編集画面を開く。
7. ルールの編集は「色付けルール」パネルで行う。変更はその場で表示に反映する。ルールの一覧のキー操作 (00-overview.md の 8.6): Enter で選んだルールを編集、Delete で削除、Space で有効 / 無効の切り替え。
8. ルールはデータを変えない。表示とエクスポート (HTML・RTF など、03・11 の機能で「色を含める」を選んだ場合) にだけ使う。

**画面**: 「色付けルール」パネル (既定は右パネル)。上部に「全体」「このドキュメント」の切り替え、ルールの一覧 (有効のチェック、色見本と文字での色の説明、名前、条件の要約)、選んだルールの編集欄。

**巨大ファイル・長時間処理**:

- ルールの評価は表示範囲 (前後 1 画面分を含む) だけで行い、ファイル全体は走査しない。パターン・正規表現・数値のルールは、表示範囲の前後に「一致の最大長」分を加えて読む。
- 評価はバックグラウンドで行い、結果が出るまでは色なしで描画する (描画を待たせない)。結果はチャンクとスナップショットの版ごとにキャッシュする。
- 有効なルールが 64 件のとき、1 画面分の評価を 4 ms 以内に終える (60 fps を保つ)。

**エラー**: 条件の構文エラーは編集欄に赤枠と説明文で示し、そのルールを無効のまま保存する。

**受け入れ基準**:

- [ ] 「ゼロを薄く表示」を有効にすると、`00` が薄い色で表示される。
- [ ] Hex パターン `50 4B 03 04` のルールで、ZIP のローカルファイルヘッダが色付けされる。
- [ ] 画面の境界をまたぐ 8 バイトのパターンが、スクロールの前後で同じように色付けされる。
- [ ] 全体のルールはすべてのドキュメントに、ドキュメントのルールはそのドキュメントだけに適用される。
- [ ] 有効なルールが 64 件でも、スクロールが 60 fps を保つ。
- [ ] 色付けルールを有効にしても、ファイルの内容は変わらない。

### INSP-34 色付けルールの優先順位と凡例

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-06 |
| 呼び出し | 「色付けルール」パネルの並べ替え、表示 > 色付けルール > 凡例、コマンドパレット「凡例の表示切り替え」 |

**概要**: 同じバイトに複数の色付けルールが一致したときの優先順位を定め、何の色かを凡例で示す。選択範囲・検索の一致・ブックマーク・注釈・テンプレート・差分・変更されたバイトなど、色付けルール以外の強調表示との重なりの順序は VIEW-17 で定める (00-overview 1.1)。

**仕様**:

1. 色付けルールの優先順位: 一覧の上にあるルールほど優先する。同じバイトに複数のルールが一致した場合、背景色・文字色・枠線それぞれについて、それを指定している最も上のルールのものを使う。ドキュメントのルールは全体のルールより優先する。
2. 色付けルール全体は、VIEW-17 の色の重ね順の 1 つの層 (層 10「色付けルール」) として描く。ほかの層との重なり方 (選択範囲の下でもセル下端の帯として残す、変更されたバイトの下線を必ず描く、など) は VIEW-17 の 5〜9 に従う。
3. 凡例: 「凡例」パネル (またはステータスバーの上に重ねる小さな一覧) に、有効な色付けルールと表示中の注釈の出どころ、ブックマークのグループを、色見本・枠線の形・名前で並べる。
   - 各項目に、表示範囲での一致件数を表示する。
   - 「全体の件数を数える」ボタンを押すと、ドキュメント全体での件数をバックグラウンドで数える (長時間処理)。
   - 色付けルールの項目の「次へ」「前へ」ボタンで、そのルールに一致する次 / 前の位置に移動する (検索エンジン (04-search.md の FIND-01) を使う)。
4. ハイコントラストテーマ: 色付けルールの色は使わず、システムの色と枠線の形 (実線・破線・点線・二重線) の組み合わせで区別する。ルールの順に形を割り当て、凡例に形を示す。設定「ハイコントラストでも色付けルールの色を使う」(既定オフ) で色を使える。

**画面**: 「色付けルール」パネルの一覧のドラッグ (または「上へ」「下へ」ボタン) で優先順位を変える。凡例パネル。

**巨大ファイル・長時間処理**: 「全体の件数を数える」と「次へ」「前へ」は検索エンジンで行い、進捗とキャンセルを提供する。

**エラー**: なし。

**受け入れ基準**:

- [ ] `00` を赤、`00-1F` を青にするルールで、赤のルールを上にすると `00` が赤、下にすると青になる。
- [ ] 選択範囲が色付けルールより手前に表示される (VIEW-17)。
- [ ] 変更されたバイトが、色付けルールの色に関係なく下線で示される。
- [ ] 凡例の「次へ」で、そのルールに一致する次の位置に移動する。
- [ ] ハイコントラストテーマで、2 つのルールが枠線の形で区別でき、凡例に形が示される。

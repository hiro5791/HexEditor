# 機能仕様書: 配布形態と自動更新

1 つのコードベースから 3 種類の配布形態 (MSIX、ポータブル、インストーラ) を作る方法、インストールとアンインストール、自動更新、ビルドとリリースの自動化、版の付け方を定める。共通の書式・用語は [00-overview.md](00-overview.md) に従う。調査の根拠は [../research/feature-survey.md](../research/feature-survey.md) の 4 章。

対象とするロードマップの項目: F0-15、F1-24。あわせて、F1-22 (Explorer 連携) と F2-09 / F2-10 (管理者権限の補助プロセス) の配布形態ごとの実装、F1-26 (翻訳の進捗をリリースノートに載せる) を扱う。ロードマップにない機能は「追加 (フェーズ N 提案)」とした。

- 利用者から見た UI (設定画面、InfoBar、Explorer のメニューの見え方) は [09-ui-and-settings.md](09-ui-and-settings.md) で定める。
- コマンドラインの書式とすべてのオプションは [08-automation.md](08-automation.md) の AUTO-36〜AUTO-44 で定める。この文書は、`hexed.exe` を配布形態ごとにどう呼べるようにするか (PKG-03、PKG-05、PKG-08) だけを定める。
- アプリが行う通信は 00-overview.md 11.4 の一覧のものだけ。この文書が扱うのは、更新の確認とダウンロード (PKG-17〜PKG-21) と、同じ仕組みで行う追加コンポーネントのダウンロード (PKG-17 の 7)。テレメトリは送らない (09 の UI-57)。

## 1. 配布形態

### PKG-01 3 種類の配布形態

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | なし (配布の方針) |

**概要**: 同じソースコードから MSIX、ポータブル、インストーラの 3 種類を作る。違いは保存先・登録方法・更新方法に限り、機能は同じにする。

**仕様**:

1. 3 種類の違いは次のとおり。

   | 項目 | MSIX | インストーラ | ポータブル |
   | --- | --- | --- | --- |
   | 配布ファイル | Microsoft Store でだけ配る (`.msixbundle` を提出。PKG-04) | `Setup.exe` (Velopack) | `.zip` |
   | インストール先 | `C:\Program Files\WindowsApps\` (Windows が管理) | `%LocalAppData%\HexEditor\` | 利用者が展開した任意のフォルダ |
   | 管理者権限 | 不要 | 不要 (ユーザー単位) | 不要 |
   | 設定の保存先 | パッケージの `LocalState` | `%LocalAppData%\HexEditorData\` | `<exe のフォルダ>\Data\` |
   | ファイル関連付け | マニフェストで宣言 | インストール時に HKCU に登録 | 利用者が設定画面で登録したときだけ |
   | 右クリックメニュー | Windows 11 の新しいメニュー (+ 従来のメニュー) | 従来のメニュー (新しいメニューはコード署名を導入した後。09 の UI-55) | 利用者が登録したときだけ |
   | 自動更新 | Microsoft Store | Velopack (差分更新) | 新しい版の通知だけ (手動で入れ替え) |
   | 管理者権限の補助プロセス | 同梱しない (PKG-14) | 同梱 | 同梱 |
   | 管理者権限が必要な操作 (01 の ENG-28) | アプリ全体を管理者として実行したときだけ (PKG-04) | 必要なときだけ補助プロセスを UAC で起動。アプリ全体を管理者として実行してもよい | インストーラと同じ |
   | コード署名 | Microsoft Store が署名する | 署名しない (PKG-25) | 署名しない (PKG-25) |

2. 機能の差は、Windows の仕組みと配布の方法の上でどうしても必要なものだけにする。MSIX 版は Microsoft Store でだけ配る (署名のない MSIX は一般の利用者がインストールできないため。PKG-25)。この文書の「MSIX 版」は Microsoft Store 版 (Store 版) と同じものを指す。MSIX 版は管理者権限の補助プロセスを同梱しないため、管理者権限が必要な操作 (物理ディスク・内蔵ディスクのボリュームの読み書き、昇格したプロセス・システムのプロセスのメモリの読み書きなど) は、利用者がアプリ全体を管理者として実行したときだけ使える (PKG-04、PKG-14)。同じユーザーの昇格していないプロセスのメモリと、取り外し可能な USB ストレージのボリュームは、管理者権限なしでどの配布形態でも読み書きできる (01 の ENG-28 の概要の表)。
3. 配布形態に依存する処理は `IAppEnvironment` (PKG-12) を通して行い、それ以外のコードで配布形態を判定しない。
4. 各フェーズの終わりに 3 種類 × 2 アーキテクチャ (PKG-15) をすべてビルドできる状態にする (ロードマップの方針)。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] リリースのビルド (PKG-24) で、3 種類 × 2 アーキテクチャの成果物がすべて作られる。
- [ ] 3 種類のどれでも、00-overview.md の全機能の受け入れテスト (配布形態に依存しないもの) が同じ結果になる。ここでの「全機能の受け入れテスト」は、配布形態に依存しない自動の UI テスト (テストケースの種別が「自動: UI」で、環境に配布形態の指定がないもの) を指し、それを各配布形態で実行して結果を比べる。
- [ ] `IAppEnvironment` の実装以外に、配布形態を判定するコード (`#if HEX_DISTRO_*`、パッケージ ID の取得) がない (静的チェック)。

### PKG-02 MSIX パッケージ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | Microsoft Store からインストール (PKG-04) |

**概要**: Microsoft Store に提出する MSIX パッケージを作る。MSIX は Microsoft Store でだけ配り、GitHub Releases などで直接配らない (PKG-04、PKG-26)。

**仕様**:

1. x64 と ARM64 の `.msix` を作り、1 つの `.msixbundle` にまとめる。
2. .NET と Windows App SDK はパッケージに同梱する (自己完結型。`WindowsAppSDKSelfContained=true`、`SelfContained=true`)。Windows App SDK のフレームワークパッケージに依存しない。
3. パッケージは自分たちでは署名しない。Microsoft Store が署名して配る (PKG-04、PKG-25)。署名のない MSIX は一般の利用者がインストールできないため、Store の外では配らない。
4. 更新は Microsoft Store の仕組みで行う (PKG-19)。
5. パッケージの ID: `Name` は `HexEditor`、プレビュー版も同じ ID とする (PKG-21)。`PublisherDisplayName` は `Hiroyura`。`Publisher` (パッケージ ID の発行者の文字列) は Microsoft Store が割り当てた値を使う (Partner Center に表示される値をマニフェストに書く)。
6. 最低の OS は `TargetDeviceFamily Name="Windows.Desktop" MinVersion="10.0.17763.0"` (00-overview.md 4 章)。

**画面**: Microsoft Store のインストールの画面 (アプリ側の UI はない)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: パッケージの不備は CI でのインストールの確認 (PKG-24) で、Store に提出する前に検出する。Store の認定で不合格になった場合は、Partner Center が示す理由に従って直し、提出し直す。

**受け入れ基準**:

- [ ] 証明書の操作をしていない Windows 11 で、Microsoft Store からインストールできる。
- [ ] ARM64 の PC では ARM64 版、x64 の PC では x64 版がインストールされる。
- [ ] Windows App SDK のランタイムが入っていない Windows 10 (1809) でも起動する。

### PKG-03 MSIX のマニフェスト

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15、F1-22 |
| 呼び出し | なし (ビルド時) |

**概要**: `Package.appxmanifest` で、ファイル関連付け、右クリックメニュー、実行エイリアス、対応言語を宣言する。

**仕様**:

1. 宣言する拡張:

   | 拡張 | 内容 |
   | --- | --- |
   | `uap:FileTypeAssociation` (`Name="hexeditor.project"`) | `.hexproj`、`.hexworkspace`。既定のアプリの候補 |
   | `uap:FileTypeAssociation` (`Name="hexeditor.binary"`) | `.bin`、`.dat`、`.img`、`.rom`、`.dmp`、`.raw`、`.iso`。「プログラムから開く」の候補 (09 の UI-56) |

   | `uap5:AppExecutionAlias` | `hexed.exe` (コンソール用の CLI、08 の AUTO-36。`desktop:Subsystem="console"`) と `hexeditor.exe` (GUI 本体)。どのフォルダからでもコマンドラインで呼べるようにする |
   | `uap:VisualElements` | アイコン、表示名 (言語ごとのリソース)、背景色は透明 |

3. `Resources` に 23 言語 (00-overview.md 5.1 のフォルダ名) をすべて列挙する。表示名・説明はパッケージのリソース (`resources.pri`) で言語ごとに持つ。
4. マニフェストの版 (`Identity Version`) は PKG-28 の対応表で SemVer から作る。手で書かない。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] MSIX 版のインストール後、`.hexproj` が HexEditor に関連付けられ、`.iso` の「プログラムから開く」に HexEditor が出る。
- [ ] MSIX 版のインストール後、コマンドプロンプトで `hexeditor.exe file.bin` を実行すると開く。
- [ ] MSIX 版のインストール後、コマンドプロンプトで `hexed hash file.bin` を実行すると、同じコンソールに結果が出て終了コードが返る。
- [ ] ドイツ語の Windows で、スタートメニューの説明がドイツ語で表示される (訳がある場合)。

### PKG-04 Microsoft Store での配布

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | Microsoft Store |

**概要**: MSIX (PKG-02) を Microsoft Store で配る (2026-10-07 決定)。MSIX を配るのは Store だけとする (2026-10-07 決定。PKG-25)。

**仕様**:

1. Store 版は `HexDistro=Msix` (PKG-10) でビルドする。MSIX は Store 版だけなので、MSIX の構成はこの 1 つだけとする。Store 版は次のとおりにする: `allowElevation` を宣言しない、管理者権限の補助プロセスを同梱しない、自動更新を Store に任せる (PKG-19)、`Publisher` を Store が割り当てた値にする (`PublisherDisplayName` は `Hiroyura`。PKG-02)。
2. Store 版の管理者権限の扱い (2026-10-07 決定):
   1. 管理者権限なしで起動した Store 版でも、同じユーザーの昇格していないプロセスのメモリと、取り外し可能な USB ストレージのボリューム (`\\.\E:` の形式) は読み書きできる (01 の ENG-28 の概要の表、ENG-29、ENG-32)。
   2. 管理者権限が必要な機能 (物理ディスク・内蔵ディスクのボリュームを開くこと、昇格したプロセス・システムのプロセス・他のユーザーのプロセスのメモリの読み書き、デバイス情報の取得、OS の USB 書き込み保護の切り替え。01 の ENG-28 の呼び出し) は、利用者がアプリ全体を管理者として起動したときに使える。起動の方法は、スタートメニューで HexEditor を右クリックし、「その他」>「管理者として実行」を選ぶ。このとき補助プロセスを使わず、同じプロセスで処理する (01 の ENG-28 の仕様 10)。
   3. 管理者として実行していないときに管理者権限が必要な機能を選んだ場合は、メニューの項目を無効にせず、案内ダイアログ (01 の ENG-28 の仕様 12) を出す。ダイアログには、管理者権限が必要な理由、管理者として起動し直す手順 (仕様 2 の 2)、インストーラ版・ポータブル版なら必要なときだけ UAC の確認を出して使えることとダウンロードページへのリンクを示す。Store 版ではプログラムから管理者として起動し直すボタンは出さない (手順だけを示す)。
   4. 未決定 (実装時に確認): Store 版で利用者が手動で管理者として実行できることを、実装時に Windows 10 / 11 の実機で確認する。できなかった場合は、管理者権限が必要な機能はインストーラ版・ポータブル版でだけ提供する (その場合、仕様 2 の 3 の案内から起動し直す手順を除き、インストーラ版・ポータブル版の案内とダウンロードページへのリンクだけを示す)。
   5. 将来の改善の候補 (未決定): Store に `allowElevation` の利用を申請し、認められれば Store 版でも必要なときだけ UAC で昇格できるようにする。現時点では申請しない。
3. Store に提出するパッケージは自分たちでは署名しない (Store が署名する)。
4. Store の掲載情報 (説明、スクリーンショット) は 23 言語で用意する。スクリーンショットは 09 の UI-47 の自動撮影を使う。

**画面**: Store の掲載ページ。アプリ内では管理者権限の案内ダイアログ (01 の ENG-28 の仕様 12)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] Store 版のパッケージに `allowElevation` と補助プロセスが含まれない (CI で確認)。
- [ ] 管理者として実行していない Store 版で、「ディスクを開く」のメニューが有効で、物理ディスクを開こうとすると案内ダイアログが出る。ダイアログに、理由、管理者として起動し直す手順、ダウンロードページへのリンクがある。
- [ ] スタートメニューの「管理者として実行」で起動した Store 版で、UAC の確認の後、物理ディスクを開いて読める (仕様 2 の 4 の実機での確認)。タイトルに「(管理者)」が付く。
- [ ] 管理者として実行していない Store 版で、自分が起動したメモ帳のプロセスと、USB メモリのボリューム (`\\.\E:`) を開ける。

### PKG-05 ポータブル版

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | zip を展開して `HexEditor.exe` を実行 |

**概要**: インストール不要で、zip を展開するだけで使える自己完結型の版。設定は exe の隣に保存する。

**仕様**:

1. zip の中身は 1 つのフォルダ `HexEditor\` にまとめる: `HexEditor.exe`、`hexed.exe` (コマンドライン。08 の AUTO-36)、.NET と Windows App SDK のランタイム一式、`HexEditor.Elevated.exe` (PKG-14)、`portable.marker`、`THIRD-PARTY-NOTICES.txt`、`README.txt` (使い方、登録を解除してから削除する手順 (`hexed --unregister` を含む)、コマンドラインの呼び方)。
   - ポータブル版は PATH を変えない (PKG-06)。`README.txt` には、`<展開したフォルダ>\hexed.exe` をフルパスで呼ぶ方法と、必要なら利用者が自分でユーザーの PATH にフォルダを追加する方法を書く。
2. `portable.marker` が exe と同じフォルダにあるときにポータブルとして動く。中身は空でよい。1 行目に `DataDirectory=<パス>` を書くと、データフォルダの場所を変えられる (相対パスは exe のフォルダから。既定は `Data`)。
3. データフォルダ (既定 `<exe のフォルダ>\Data\`) に、設定・状態・付随データ・復旧用データ・ログを置く (PKG-13)。初回起動時に作る。
4. `portable.marker` がない場合 (利用者が消した場合) は、インストーラ版と同じ保存先 (`%LocalAppData%\HexEditorData\`) を使う。ただしレジストリへの登録は行わない。
5. 起動に必要なランタイムはすべて zip に含め、PC に何もインストールされていなくても動く。
6. 同じ PC で別のフォルダに置いた複数のポータブル版は、それぞれ独立したアプリとして動く (単一インスタンスのキーが別。PKG-11)。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: データフォルダに書き込めない場合は PKG-06 に従う。

**受け入れ基準**:

- [ ] .NET も Windows App SDK も入っていない Windows 10 (1809) で、zip を展開して起動できる。
- [ ] 起動後、`Data\settings.json` が exe の隣にでき、`%LocalAppData%` と `%AppData%` に HexEditor のフォルダができない。
- [ ] `portable.marker` に `DataDirectory=..\HexData` と書くと、そのフォルダに保存される。
- [ ] 2 つのフォルダに置いたポータブル版を同時に起動すると、2 つのプロセスとして独立して動く。

### PKG-06 ポータブル版の書き込みの制限と読み取り専用メディア

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | 自動 (起動時) |

**概要**: ポータブル版は、利用者が許可しない限り PC 側 (レジストリ、ユーザーフォルダ) に何も残さない。書き込めない場所から起動した場合も動く。

**仕様**:

1. ポータブル版がレジストリに書くのは、利用者が設定画面で登録した次の項目だけ: 右クリックメニュー (09 の UI-54)、ファイル関連付け (09 の UI-56)、Windows 11 の新しい右クリックメニュー用のスパースパッケージ (09 の UI-55。コード署名を導入した後に提供する)。
2. Windows のトースト通知は、非パッケージのアプリでは登録のためにレジストリへ書き込むため、ポータブル版では既定で無効にする (`notifications.toast = false`)。利用者が有効にしたときだけ登録する。
3. Windows 自身が記録するもの (ファイルを開くダイアログの履歴、ジャンプリスト、Prefetch など) はアプリが制御できない。README とドキュメントにその旨を書く。ジャンプリストは設定で無効にできる (09 の UI-35)。
4. 一時ファイル (編集で追加したデータの退避先) は既定で `%TEMP%\HexEditor-<exe のパスのハッシュ 8 桁>\` に置き、アプリの終了時に消す。設定 `storage.tempDirectory` でデータフォルダ内に変えられる。
5. 起動時に、データフォルダに書き込めるかを確認する (`Data\.write-test` を作って消す)。書き込めない場合 (CD-ROM、書き込み禁止の USB メモリ、権限のないフォルダ):

   1. データフォルダに既存の設定があれば読み込む。
   2. 設定の変更はセッション中だけ有効にし、ファイルには書かない。
   3. 復旧用データは `%TEMP%\HexEditor-<ハッシュ>\recovery\` に書き、終了時に消す (異常終了した場合は残る)。
   4. アプリ全体の InfoBar で「データフォルダに書き込めないため、設定は保存されません」と「設定をエクスポート」ボタンを表示する。

6. USB メモリから起動した場合、最近使ったファイルのうち同じドライブのものは exe からの相対パスで記録する (09 の UI-32)。

**画面**: InfoBar。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 仕様 5 のとおり。`%TEMP%` にも書き込めない場合は、編集の追加データをメモリだけで持ち (メモリ上限を超える編集は拒否する)、復旧用データは作らず、その旨を InfoBar で表示する。

**受け入れ基準**:

- [ ] ポータブル版を起動・編集・終了した後、レジストリの `HKCU\Software` 以下に HexEditor の値が増えていない (Process Monitor で確認)。
- [ ] 書き込み禁止の USB メモリから起動でき、InfoBar が表示される。
- [ ] 書き込み禁止のメディアから起動しても、ファイルを開いて編集し、別の場所に保存できる。
- [ ] 正常終了後、`%TEMP%\HexEditor-<ハッシュ>\` が残っていない。

### PKG-07 インストーラ版 (Velopack)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | `HexEditor-<版>-<アーキテクチャ>-Setup.exe` を実行 |

**概要**: Velopack で作る `Setup.exe` で、ユーザー単位に管理者権限なしでインストールする。差分更新に対応する。

**仕様**:

1. `vpk pack` で、アーキテクチャごとに `Setup.exe`、完全版パッケージ (`-full.nupkg`)、差分パッケージ (`-delta.nupkg`)、リリース情報ファイルを作る。パッケージ ID は `HexEditor`。

3. `Setup.exe` は選択肢を出さない。インストール後にアプリを起動する。
4. ショートカットはスタートメニューにだけ作る (デスクトップには作らない)。

7. データフォルダは `%LocalAppData%\HexEditorData\` とし、インストール先とは分ける (Velopack がアンインストール時にインストール先を丸ごと消すため。PKG-09)。

**画面**: Velopack のインストール中の画面 (進捗のみ)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: インストールの失敗は Velopack のエラー画面とログ (`%LocalAppData%\HexEditor\` 内) で示す。

**受け入れ基準**:

- [ ] 一般ユーザーの権限だけで、UAC の確認なしにインストールできる。
- [ ] インストール後、スタートメニューに HexEditor があり、デスクトップにショートカットがない。
- [ ] Windows の「アプリ」設定に表示され、そこからアンインストールできる。
- [ ] Win+R で `HexEditor` と入力すると起動する (App Paths)。
- [ ] インストール後に開いた新しいコマンドプロンプトで `hexed --version` が動く。

### PKG-08 インストール・更新・アンインストール時のフック

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15、F1-22 |
| 呼び出し | Velopack がインストール・更新・アンインストール時にアプリを特別な引数で起動する |

**概要**: インストーラ版で、Velopack のフックを使って Explorer 連携を登録・解除する。

**仕様**:

1. フックは起動処理の最初 (PKG-11) で `VelopackApp.Build()` に登録する。フックの中では UI を出さず、XAML を初期化しない。
2. 各フックの処理:

   | フック | 処理 |
   | --- | --- |
   | インストール後 | 右クリックメニュー (09 の UI-54)、ファイル関連付け (09 の UI-56)、App Paths (`HKCU\Software\Microsoft\Windows\CurrentVersion\App Paths\HexEditor.exe`) を登録し、`SHChangeNotify(SHCNE_ASSOCCHANGED)` を呼ぶ。ユーザーの PATH にアプリのフォルダを追加する (仕様 6) |
   | 更新後 | 登録を新しい版の内容で登録し直す (登録内容は冪等にする。利用者が設定で解除した項目は登録しない) |
   | アンインストール前 | 登録したレジストリの値をすべて消す。ジャンプリストを消す。トースト通知の登録を解除する。PATH に追加していれば消す。設定 `uninstall.removeUserData` が `true` ならデータフォルダを消す |
   | 初回起動 | 何もしない (初回起動の表示は 09 の UI-38 がアプリ側で行う) |

3. 登録先はすべて HKCU。HKLM には書かない。登録するキーの一覧をコード内の 1 か所 (`ShellRegistration` クラス) に定義し、登録と解除で同じ一覧を使う。
4. フックは 5 秒以内に終える (Velopack の制限時間より十分短くする)。
5. 登録の状態 (利用者が設定画面で解除したかどうか) はデータフォルダの `state.json` に記録し、更新後のフックはそれに従う。
6. コマンドライン (`hexed.exe`、08 の AUTO-36) を使えるように、インストール時にユーザーの PATH (`HKCU\Environment` の `Path`) に `%LocalAppData%\HexEditor\current\` を追加し、`WM_SETTINGCHANGE` で通知する (既定: 追加する)。
   - 追加は既存の値の末尾に 1 回だけ行い、既に同じフォルダがあれば追加しない。システムの PATH (HKLM) には書かない。
   - 設定画面「詳細」の「コマンドラインから使えるようにする」(既定オン) で外せる。外した場合は `state.json` に記録し (仕様 5)、更新後のフックで追加し直さない。
   - アンインストール前のフックと `--unregister` (08 の AUTO-36 の 9) で、追加した項目だけを消す。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: フックの失敗はデータフォルダの `logs\install.log` に記録する。インストール自体は失敗にしない。次回のアプリの起動時に登録の状態を確認し、登録されていなければ設定画面「Explorer 連携」に「登録されていません」と表示する。

**受け入れ基準**:

- [ ] インストール後、`HKCU\Software\Classes\*\shell\HexEditor` がある。
- [ ] アンインストール後、`ShellRegistration` の一覧にあるキーがすべて消えている (自動テスト)。
- [ ] 右クリックメニューの登録を設定で解除してから更新しても、登録が復活しない。
- [ ] インストール後、ユーザーの PATH に `%LocalAppData%\HexEditor\current\` が 1 つだけあり、アンインストール後に消えている。
- [ ] HKLM に何も書き込まれていない (Process Monitor で確認)。

### PKG-09 アンインストール

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | Windows の「アプリ」設定。ポータブル版はツール > 設定 > 詳細 >「この PC から登録を解除」、またはコマンドライン `--unregister` (08 の AUTO-36 の 9) |

**概要**: 配布形態ごとのアンインストールの動作と、ユーザーデータの扱いを定める。

**仕様**:

1. 配布形態ごとの動作:

   | 配布形態 | アプリ本体 | 登録 (レジストリ) | ユーザーデータ |
   | --- | --- | --- | --- |
   | MSIX | Windows が削除 | Windows が削除 | Windows が `LocalState` ごと削除する (残せない) |
   | インストーラ | Velopack が `%LocalAppData%\HexEditor\` を削除 | フックで削除 (PKG-08) | 既定で残す。`uninstall.removeUserData = true` なら削除 |
   | ポータブル | 利用者がフォルダを削除 | 「この PC から登録を解除」で削除 | フォルダと一緒に削除される |

2. 設定 `uninstall.removeUserData` (既定 `false`) は設定画面「詳細」に置く。インストーラ版だけに表示する。説明に「残したデータは次にインストールしたときに使われます」と書く。
3. MSIX 版の設定画面「詳細」には「アンインストールすると設定も削除されます。必要な場合は設定をエクスポートしてください」と表示し、「設定をエクスポート」ボタンを置く (09 の UI-25)。
4. ポータブル版の「この PC から登録を解除」は、レジストリの登録、ジャンプリスト、トースト通知の登録、`%TEMP%` の一時フォルダを消す。完了後に「フォルダを削除すればアンインストールは完了です」と表示する。
5. 実行中のアプリがある状態でアンインストールした場合 (インストーラ版) は、Velopack がアプリを終了させる。未保存の変更は復旧用データとして残る (データフォルダを消す設定の場合は残らない)。

**画面**: 設定画面「詳細」。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 登録の解除に失敗した項目は、ポータブル版では一覧で表示する。インストーラ版ではログに記録する。

**受け入れ基準**:

- [ ] インストーラ版を既定の設定でアンインストールし、再インストールすると、前の設定が残っている。
- [ ] `uninstall.removeUserData = true` でアンインストールすると、`%LocalAppData%\HexEditorData\` が消える。
- [ ] ポータブル版で「この PC から登録を解除」を実行した後、レジストリに HexEditor のキーが残らない。

### PKG-10 ビルド構成の切り替え

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | `dotnet publish -p:HexDistro=<値> -r <RID>` |

**概要**: 1 つの csproj を MSBuild のプロパティ `HexDistro` で 3 種類に作り分ける。

**仕様**:

1. `HexDistro` の値と、それに対応する MSBuild の設定:

   | プロパティ | `Msix` | `Installer` | `Portable` |
   | --- | --- | --- | --- |
   | `WindowsPackageType` | `MSIX` | `None` | `None` |
   | `WindowsAppSDKSelfContained` | `true` | `true` | `true` |
   | `SelfContained` | `true` | `true` | `true` |
   | `EnableMsixTooling` | `true` | `true` | `true` |
   | `PublishReadyToRun` | `true` | `true` | `true` |
   | `DefineConstants` に追加 | `HEX_DISTRO_MSIX` | `HEX_DISTRO_INSTALLER` | `HEX_DISTRO_PORTABLE` |
   | Velopack の参照 | なし | あり | なし |
   | 後処理 | MSIX の作成 (署名しない。PKG-04) | `vpk pack` | `portable.marker` を追加して zip |

2. `HexDistro` を指定しない場合 (開発中の `dotnet build`) は `Installer` と同じ設定で、Velopack の初期化を行わない「開発」モードにする (PKG-12)。
3. `HexDistro=Msix` は Microsoft Store 版 (PKG-04) のビルドとする。MSIX は Store でだけ配るため、Store 版と別の MSIX の構成は持たない。
4. すべての構成で `DISABLE_XAML_GENERATED_MAIN` を定義し、起動処理を自分で書く (PKG-11)。
5. `RuntimeIdentifier` は `win-x64` と `win-arm64` (PKG-15)。
6. トリミング (`PublishTrimmed`) は使わない (WinUI と CsWinRT の対応が安定するまで。再検討の時期は未決定)。将来トリミングを使う場合も、次の規則を守る。
   - C# スクリプト (08 の AUTO-03) とプラグイン (08 の AUTO-29、AUTO-30) は、ビルド時に分からない API を実行時に呼ぶ。このため、これらに公開するアセンブリはトリミングしない (`TrimmerRootAssembly` で丸ごと残す): `HexEditor.Sdk`、`HexEditor.Sdk.UI`、AUTO-03 の 5 に挙げた .NET の基本ライブラリ、プラグインと共有する .NET の基本ライブラリ・Windows App SDK (AUTO-30 の 3)。
   - トリミングしてよいのは、アプリの内部だけで使うアセンブリに限る。
   - CI で、AUTO-03 の 5 の API を呼ぶ C# スクリプトとサンプルのプラグイン (AUTO-46) をトリミング後の配布物で実行し、失敗しないことを確認する。
7. `DefineConstants` の定数は、`IAppEnvironment` の実装の選択 (PKG-12) と、Velopack の参照の有無にだけ使う。
8. ビルドの入口として `build/publish.ps1 -Distro <Msix|Installer|Portable> -Arch <x64|arm64>` を用意し、CI もローカルも同じスクリプトを使う。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: `HexDistro` に不正な値を指定した場合は、ビルドをエラーで止める。

**受け入れ基準**:

- [ ] `build/publish.ps1` で 3 種類 × 2 アーキテクチャの 6 通りがすべてビルドできる。
- [ ] `Portable` の出力に Velopack の DLL が含まれない。
- [ ] `HexDistro=Foo` でビルドするとエラーになる。

### PKG-11 起動処理

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15、F0-16 |
| 呼び出し | アプリの起動 |

**概要**: `Program.Main` を自分で書き、Velopack の初期化 → 実行環境の判定 → 単一インスタンス化 → XAML の起動の順に行う。

**仕様**:

1. 処理の順番:

   ```csharp
   public static class Program
   {
       [STAThread]
       private static int Main(string[] args)
       {
           // 1. Velopack のフック (インストーラ版のみ)。フック用の引数なら処理して終了する
           VelopackBootstrap.Run(args);          // HEX_DISTRO_INSTALLER 以外では何もしない

           // 2. 実行環境の判定 (保存先・ログの場所が決まる)
           var env = AppEnvironment.Detect();

           // 3. ログと未処理例外の記録 (PKG-30)
           CrashHandler.Install(env);

           // 4. COM の準備
           WinRT.ComWrappersSupport.InitializeComWrappers();

           // 5. 単一インスタンス化。既存のインスタンスがあれば起動を転送して終了する
           if (SingleInstance.TryRedirect(env, args))
           {
               return 0;
           }

           // 6. 表示言語の設定 (最初のウィンドウを作る前。09 の UI-43)
           Localization.ApplyLanguageOverride(env);

           // 7. XAML の起動
           Application.Start(_ =>
           {
               var context = new DispatcherQueueSynchronizationContext(
                   DispatcherQueue.GetForCurrentThread());
               SynchronizationContext.SetSynchronizationContext(context);
               _ = new App(env);
           });
           return 0;
       }
   }
   ```

2. 単一インスタンスのキー (`AppInstance.FindOrRegisterForKey` に渡す文字列) は `HexEditor-<配布形態>-<exe のフォルダのパスの SHA-256 先頭 8 桁>-<User|Admin>` とする。MSIX 版はパッケージごとに分かれるため `HexEditor-Msix-<User|Admin>`。
3. 転送 (`RedirectActivationToAsync`) は STA スレッドを止めないよう別スレッドで行い、完了を最大 5 秒待つ (09 の UI-15)。転送の前に `AllowSetForegroundWindow` で既存プロセスに前面化を許可する。
4. 起動処理の 1〜5 で XAML の型を使わない。2 つ目のプロセスが転送して終了するまでを 300 ms 以内にする。
5. 管理者権限の補助プロセス (`HexEditor.Elevated.exe`) は別の実行ファイルで、この起動処理を通らない (PKG-14)。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 1〜5 で例外が起きた場合は、データフォルダ (判定できなければ `%TEMP%`) の `logs\startup-error.log` に書き、`MessageBox` (Win32) で「起動できませんでした」と理由・ログの場所を表示して終了する。

**受け入れ基準**:

- [ ] アプリの起動中に 2 回目の起動をすると、2 つ目のプロセスが 300 ms 以内に終わり、既存のウィンドウにタブが開く。
- [ ] インストーラ版で、Velopack のフック用の引数で起動したときにウィンドウが表示されない。
- [ ] 一般権限と管理者権限のインスタンスを同時に起動できる。
- [ ] 起動から操作可能まで 2 秒以内 (00-overview.md 11.1)。

### PKG-12 実行環境の判定 (IAppEnvironment)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | 起動処理 (PKG-11) で 1 回判定し、DI で全体に渡す |

**概要**: パッケージ ID の有無と目印ファイルから実行環境を判定し、配布形態で変わる処理を `IAppEnvironment` にまとめる。

**仕様**:

1. 判定の手順:

   1. `GetCurrentPackageFullName` を呼ぶ。成功すればパッケージ版 (`Msix`)。`APPMODEL_ERROR_NO_PACKAGE` (15700) なら非パッケージ。
   2. 非パッケージで、exe と同じフォルダに `portable.marker` があれば `Portable`。
   3. 非パッケージで、Velopack のインストール先の構造 (`..\Update.exe` があり、exe が `current\` の中) なら `Installer`。
   4. どれでもなければ `Development` (開発中の実行)。データフォルダは `%LocalAppData%\HexEditorData-dev\` とし、登録・更新は行わない。

2. ビルド時の `HexDistro` (PKG-10) と判定の結果が違う場合は、判定の結果を使い、ログに警告を書く (例: `Portable` のビルドから `portable.marker` を消した場合は、PKG-05 の仕様 4 の動作)。
3. `IAppEnvironment` の定義:

   ```csharp
   public interface IAppEnvironment
   {
       Distribution Distribution { get; }        // Msix, Installer, Portable, Development
       bool IsPackaged { get; }                  // true なら Microsoft Store 版 (PKG-04)
       bool IsElevated { get; }
       Architecture ProcessArchitecture { get; }
       SemanticVersion AppVersion { get; }
       ReleaseChannel Channel { get; }           // Stable, Preview
       string AppUserModelId { get; }

       DataLocations Locations { get; }          // PKG-13 の各フォルダ
       bool IsDataDirectoryWritable { get; }

       IShellIntegration ShellIntegration { get; }  // 右クリックメニュー、関連付け、ジャンプリスト
       IUpdateService UpdateService { get; }        // PKG-17〜PKG-22
       IElevationLauncher ElevationLauncher { get; } // PKG-14
   }
   ```

4. AppUserModelID は、MSIX 版はパッケージから決まるものを使う。非パッケージ版は起動処理で `SetCurrentProcessExplicitAppUserModelID` を呼んで設定する。インストーラ版は Velopack が作るショートカットの AppUserModelID と同じ値にする (タスクバーのまとまりとジャンプリストのため)。Velopack 1.2 の既定の値 `velopack.HexEditor` (`velopack.<パッケージ ID>`) を使う (Velopack も起動時に同じ値を設定する)。ポータブル版は `HexEditor.Portable.<exe のフォルダのハッシュ 8 桁>`、開発中の実行は `HexEditor.Development`。
5. 各実装 (`MsixEnvironment`、`InstallerEnvironment`、`PortableEnvironment`、`DevelopmentEnvironment`) は単体テストで差し替えられるようにする。

**画面**: バージョン情報 (09 の UI-40) に判定結果を表示する。

**巨大ファイル・長時間処理**: 該当なし。判定は 50 ms 以内。

**エラー**: 判定に失敗した場合 (例外) は `Development` として扱い、ログに記録する。

**受け入れ基準**:

- [ ] 3 種類の配布形態それぞれで、バージョン情報に正しい配布形態が表示される。
- [ ] `IAppEnvironment` を差し替えた単体テストで、保存先が配布形態ごとに正しく決まる。
- [ ] インストーラ版で、タスクバーのアイコンがスタートメニューのショートカットと同じグループになる。

### PKG-13 データの保存先

**概要**: 設定・状態・復旧用データ・ログ・一時ファイルの保存先を、配布形態ごとに定める。

   | 追加データの退避 (01 の ENG-04) | 上記の `recovery\<ドキュメント ID>\add.bin` | 上記の `recovery\<ドキュメント ID>\add.bin` | 上記の `recovery\<ドキュメント ID>\add.bin` |
   | 一時ファイル (パスを持たない項目のコピーなど) | `%LocalAppData%\Packages\<P>\LocalCache\temp\` | `%LocalAppData%\HexEditorData\temp\` | `%TEMP%\HexEditor-<H>\` (PKG-06) |

   インストーラ版のデータはすべて `%LocalAppData%\HexEditorData\` 以下に置き、Velopack のインストール先 `%LocalAppData%\HexEditor\` には置かない (Velopack が更新・アンインストールでインストール先を置き換え・削除するため。PKG-07 の 7)。

2. MSIX 版は `ApplicationData.Current.LocalFolder` と `LocalCacheFolder` の API でパスを取る。パスを文字列で組み立てない。
3. 追加データの退避は、異常終了の後に復旧用データからそのまま参照するため、復旧用データのドキュメントごとのフォルダ (`recovery\<ドキュメント ID>\`) に置く (01 の ENG-27 の仕様 2)。巨大ファイルの編集で容量の大きいドライブを使うため、設定 `storage.tempDirectory` を指定すると、ドキュメントごとのフォルダ (追加データの退避と復旧用データ) と一時ファイルを `<指定のフォルダ>\HexEditor\` の下に置く。起動時の復旧の確認 (ENG-27 の仕様 6) は、既定の `recovery\` と指定のフォルダの両方を調べる。ジャーナル (ENG-23) は既定の `recovery\` に置く。
4. 一時フォルダの中身は起動時に、実行中の他のインスタンスが使っていないもの (ロックされていないもの) を消す。

6. どの保存先も、ファイルの内容をコピーしない (00-overview.md 11.3 のとおり、巨大な追加データは参照として記録する)。

## 3. 自動更新

この章 (PKG-17〜PKG-22) の受け入れ基準のうち、インストーラ版・ポータブル版の更新の確認・ダウンロードを伴うものは、テスト用のビルドで更新の確認先をテスト用の配布元に差し替えて確認する (PKG-17 の仕様 8)。

### PKG-17 更新の確認

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-24 |
| 呼び出し | 自動 (起動後、24 時間ごと)。ヘルプ > 更新の確認。コマンドパレット「ヘルプ: 更新の確認」 |

**概要**: 新しい版があるかを定期的に確認する。確認の頻度と無効化を設定できる。

**仕様**:

1. 自動の確認は、起動から 30 秒後 (起動の性能に影響させないため) と、その後 24 時間ごとに行う。前回の確認から 24 時間たっていなければ起動時の確認は行わず、前回から 24 時間後に行う。前回の確認の日時は設定フォルダの `state.json` の `update` の区分に記録する (失敗した確認も、次の周期で再試行するため記録する)。
2. 設定 (設定画面「更新」):

   | キー | 既定 | 内容 |
   | --- | --- | --- |
   | `update.checkAutomatically` | `true` | 自動で確認する |
   | `update.downloadAutomatically` | `true` (インストーラ版のみ表示) | 見つかったら裏でダウンロードする |
   | `update.channel` | `stable` | `stable` / `preview` (PKG-21) |
   | `update.skippedVersion` | (空) | 「この版をスキップ」した版 |

3. `network.offline` (09 の UI-58) が `true` のときは、自動・手動とも確認しない。
4. 配布形態ごとの確認方法:

   | 配布形態 | 方法 |
   | --- | --- |
   | インストーラ | Velopack の `UpdateManager` と `GithubSource` で GitHub Releases を確認 |
   | MSIX (Microsoft Store) | `StoreContext.GetAppAndOptionalStorePackageUpdatesAsync()` |
   | ポータブル | GitHub Releases の API (`/repos/<owner>/<repo>/releases`) で最新版の版番号だけを取得 |
   | 開発中の実行 | 確認しない (「この版では更新を確認できません」)。テスト用のビルドで仕様 8 の確認先があるときだけ、ポータブル版と同じ方法で確認する (UI テストで使う) |

5. 送る情報は、HTTP の要求に必要なもの (User-Agent に `HexEditor/<版>`) だけ。利用者の識別子や利用状況を送らない (09 の UI-57)。
6. 手動の確認では、結果 (「最新の版です」「版 X があります」「確認できませんでした」) を必ず表示する。自動の確認では、新しい版があるときだけ表示する。
7. 追加コンポーネント (C# スクリプト用のコンパイラ。08 の AUTO-03) の取得も、この節 (PKG-17〜PKG-21) と同じ仕組みで行う。
   - 配布元はアプリ本体と同じ GitHub Releases の同じ版のリリース (PKG-26 の `HexEditor-<V>-<アーキテクチャ>-csharp.zip`)。チャネル (PKG-21) はアプリ本体と同じものを使い、アプリの版と同じ版のコンポーネントだけを入れる。
   - 配布形態ごとの違い: インストーラ版・ポータブル版は上記の zip をダウンロードする。MSIX 版 (Store 版) で Store の外からコードをダウンロードしてよいかは Store のポリシーを確認して決める (未決定)。ダウンロードする場合は同じ zip を使い、パッケージの `LocalCache\components\` に置く (オプションパッケージは使わない)。
   - 検証: zip の SHA-256 を `SHA256SUMS.txt` (PKG-26) と比べ、展開した各ファイルの SHA-256 を、同じリリースのビルドで本体に埋め込んだ一覧 (PKG-24 の手順 2) と比べる。Roslyn のアセンブリは、あわせて Microsoft の Authenticode 署名を確認する。どれかが合わなければ入れない。手動で展開した場合も、使う前に同じ確認をする。自分たちの DLL にはコード署名をしないため (PKG-25)、署名者による確認は行わない。
   - アプリを更新したとき: 追加済みのコンポーネントは、更新後の初回起動時に新しい版をダウンロードする (`update.checkAutomatically` が `true` の場合。`false` なら次に C# スクリプトを使うときに確認する)。古い版のフォルダは新しい版を入れた後に消す。
   - 通信は 00-overview.md 11.4 の「追加コンポーネントのダウンロード」に当たる。`network.offline` または `network.downloads.enabled = false` (09 の UI-58) のときはダウンロードしない。送る情報は仕様 5 と同じ。
   - 保存先は PKG-13 の「追加コンポーネント」。
8. テスト用の更新の確認先: テスト用のビルド (Debug ビルドと、テスト用に作る Release ビルド。テスト方針 ([../test/00-test-strategy.md](../test/00-test-strategy.md)) の 7.2) だけは、設定 `test.update.source` で更新の確認先を差し替えられる。更新のテスト (PKG-08 の一部、PKG-17〜PKG-22) はこの設定で行う。
   - 値は GitHub と同じ形のリポジトリの URL (`https://github.com/<owner>/<repo>`)。既定は空 (製品の配布元を使う)。
   - 指定した場合、インストーラ版・ポータブル版の更新の確認とダウンロード (仕様 4、PKG-18、PKG-20)、チャネルの判定 (PKG-21)、追加コンポーネントの取得 (仕様 7)、「ダウンロードページを開く」「リリースノート」で開くページ (PKG-20、PKG-22) のすべてで、製品の配布元の代わりにこのリポジトリを使う。`github.com` 以外のホストを指定した場合は、そのホストの `/api/v3/` を API の場所とし (GitHub Enterprise と同じ形)、そのホストだけに接続する。
   - 接続できない場合のテストには、応答しないアドレスを指定する (例: `https://192.0.2.1/<owner>/<repo>`。`192.0.2.0/24` は文書用に予約されたアドレス)。
   - MSIX 版 (Store 版) の確認 (PKG-19) は Microsoft Store を使うため、この設定の対象外。
   - 製品版はこのキーを読まない (知らないキーとして残すだけ。09 の UI-23 の 4)。設定画面・JSON スキーマ (09 の UI-23 の 8) には出さない。
   - 設定ファイルに書くため、更新の適用後の再起動 (PKG-18) や、更新後の版でも同じ確認先を使い続ける。

**画面**: 09 の UI-36 の InfoBar。PKG-22。

**巨大ファイル・長時間処理**: 確認はバックグラウンドで行い、UI を止めない。タイムアウトは 15 秒。

**エラー**: 自動の確認の失敗は表示せずログに記録し、次の周期で再試行する。手動の確認の失敗は InfoBar に理由 (接続できない、GitHub の API の利用制限など) を表示する。

**受け入れ基準**:

- [ ] `update.checkAutomatically = false` にすると、起動・24 時間経過のどちらでも確認の通信が発生しない。
- [ ] ヘルプ > 更新の確認 で、最新のときに「最新の版です」と表示される。
- [ ] 起動直後 30 秒間は更新の確認の通信が発生しない。
- [ ] ネットワークを切った状態で手動の確認をすると、15 秒以内に「確認できませんでした」と表示される (確認先を応答しないアドレスにした場合 (仕様 8) も同じ)。
- [ ] preview のチャネルのインストーラ版で C# スクリプト コンポーネントを追加すると、アプリと同じ版・同じチャネルのコンポーネントが `%LocalAppData%\HexEditorData\components\` に入る。
- [ ] アプリを更新すると、次の起動時にコンポーネントも同じ版に更新される。

### PKG-18 インストーラ版の更新 (Velopack)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-24 |
| 呼び出し | PKG-17 で新しい版が見つかったとき |

**概要**: Velopack で差分パッケージをダウンロードし、終了時または利用者が選んだときに更新する。

**仕様**:

1. 新しい版が見つかり、`update.downloadAutomatically` が `true` なら裏でダウンロードする。差分パッケージがあれば差分を使い、なければ完全版を使う (Velopack が選ぶ)。ダウンロードは帯域を使い切らないよう低い優先度にする。
2. ダウンロードが終わったら InfoBar で「版 X の準備ができました」と「再起動して更新」「リリースノート」「後で」を表示する (PKG-22)。
3. 「再起動して更新」は、未保存の変更の確認 (09 の UI-13) をしてからアプリを終了し、Velopack が更新を適用してアプリを再起動する。再起動後はセッションを復元する (09 の UI-31)。
4. 「後で」を選んだ場合は、次にアプリを終了したときに適用する (`WaitExitThenApplyUpdates`)。次回の起動は新しい版になる。
5. 実行中の長時間処理 (保存を含む) があるときは「再起動して更新」を無効にし、理由を表示する。
6. 更新後、新しい版の初回起動時に InfoBar で「版 X に更新しました」と「リリースノート」を表示する。
7. ダウンロードしたパッケージは Velopack が SHA-256 で検証する。検証に失敗したものは適用しない。

### PKG-24 リリースのビルド

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | GitHub Actions のワークフロー `release.yml` (`v*` のタグの push) |

**概要**: タグを push すると、全成果物のビルド・検証・公開までを自動で行う。コード署名の手順は置くが、既定では行わない (PKG-25)。

**仕様**:

1. 手順:

   1. タグ名を検証する (`v` + SemVer。PKG-28)。`CHANGELOG.md` にその版の節がなければ失敗にする。
   2. 2 アーキテクチャ × 3 種類をビルドする (`HexVersion` にタグの版を渡す)。補助プロセス (`HexEditor.Elevated.exe`、PKG-14) と C# スクリプト コンポーネントのファイル (PKG-17 の 7) を先にビルドし、それらの SHA-256 の一覧を本体に埋め込む。
   3. コード署名 (PKG-25)。既定では無効で、何もしない。
   4. ポータブル版の zip と、C# スクリプト コンポーネントの zip (PKG-26) を作る。コンポーネントの中の Roslyn のアセンブリは配布元のまま (Microsoft の署名付き) 含める。
   5. Velopack: 前の版のパッケージを GitHub Releases から取得し (`vpk download github`)、`vpk pack` で `Setup.exe`・完全版・差分パッケージを作る。
   6. MSIX: アーキテクチャごとの `.msix` を作り、`.msixbundle` にまとめる。署名はしない (Store が署名する。PKG-04)。Store に提出するファイルは GitHub Releases に載せず、ワークフローの成果物として保存する。Partner Center への提出は保守担当者が行う。
   7. 検証: クリーンな Windows (x64 のランナー) で、`Setup.exe` のサイレントインストール → 起動 → 終了 → アンインストール、MSIX のインストール → 起動 → 削除、ポータブル版の起動 → 終了を行い、各段階でプロセスの終了コードとログを確認する。MSIX のインストールの確認では、そのランナーの中だけで信頼するテスト用の証明書をその場で作ってパッケージに署名する。この証明書とテスト用に署名したパッケージは公開しない。
   8. チェックサムのファイルを作る (PKG-26)。
   9. リリースノートを作る (PKG-29)。
   10. GitHub Releases に公開する (PKG-26)。Velopack のファイルは `vpk upload github` で上げる。
   11. 安定版なら winget のマニフェストを提出する (PKG-27)。

2. プレビュー版のタグ (`-preview.N`) は手順 10 で Pre-release として自動で公開する。安定版のタグは下書き (Draft) として作り、保守担当者が内容を確認して公開する。公開した時点で手順 11 を行う (別のワークフロー `publish.yml`、`release: published` で起動)。
3. リリースのワークフローは `main` ブランチ上のコミットに付いたタグだけで動かす。
4. 同じタグでの再実行は、既存の下書きのファイルを置き換える。公開済みの版は再実行できない (失敗にする)。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。全体を 60 分以内に終える。

**エラー**: どの手順で失敗しても、GitHub Releases に何も公開しない (下書きも作らない)。失敗した手順を GitHub の Issue として自動で作る。

**受け入れ基準**:

- [ ] `v0.1.0` のタグを push すると、PKG-26 の全ファイルを含む下書きのリリースができる。
- [ ] `v0.2.0-preview.1` のタグでは Pre-release として公開される。
- [ ] 検証の手順でアプリが起動しない場合、リリースが作られない。
- [ ] 2 回目以降のリリースで差分パッケージが作られる。

### PKG-25 コード署名

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | リリースのビルド (PKG-24) の中 |

**概要**: 当面、配布する実行ファイル・インストーラ・zip にはコード署名をしない (2026-10-07 決定)。MSIX は Microsoft Store が署名する。後から署名を加えられるように、リリースのワークフローには既定で無効の署名の手順を 1 つだけ置く。

**仕様**:

1. 署名しないもの: 自分たちの `.exe` と `.dll` (`HexEditor.exe`、`hexed.exe`、`HexEditor.*.dll`、`HexEditor.Elevated.exe`、`IExplorerCommand` の DLL)、`Setup.exe`、`Update.exe`、ポータブル版の zip、C# スクリプト コンポーネントの zip。第三者のバイナリ (.NET のランタイム、Roslyn、libewf など) は配布元の状態のまま同梱する (配布元の署名があればそのまま残る)。
2. MSIX は Microsoft Store でだけ配り、Store が署名する (PKG-02、PKG-04)。署名のない MSIX は一般の利用者がインストールできないため、Store の外では MSIX を配らない。
3. インストーラ版とポータブル版の利用者には、ダウンロードしたファイルを初めて実行するときに Windows SmartScreen の警告 (「Windows によって PC が保護されました」) が出る。リリースノート (PKG-29) と README (リポジトリの `README.md` とポータブル版の `README.txt`) に次を書く。
   - 警告が出る理由 (コード署名をしていないため)。
   - 続ける手順 (警告の「詳細情報」を押し、「実行」を押す)。
   - ダウンロードしたファイルを `SHA256SUMS.txt` で確認する方法 (PKG-26)。
   - 警告を出さずに入れたい利用者には Microsoft Store 版を勧めること。あわせて、Store 版では管理者権限が必要な機能 (物理ディスク・内蔵ディスクのボリューム、昇格したプロセスのメモリなど) を使うには、アプリ全体を管理者として実行する必要があること (必要なときだけ UAC で昇格する補助プロセスはインストーラ版・ポータブル版にだけある)。同じユーザーのプロセスのメモリと USB ストレージのボリュームは、どの版でも管理者権限なしで使えること (PKG-04)。
4. 署名がないことに合わせた動作:
   - 補助プロセスの確認は、署名者ではなく SHA-256 の照合で行う (PKG-14)。UAC の確認画面の発行元は「不明」と表示される。
   - 追加コンポーネントの確認は、SHA-256 の照合と Roslyn の Microsoft の署名で行う (PKG-17 の 7)。
   - Windows 11 の新しい右クリックメニューに使うスパースパッケージは署名が必要なため、インストーラ版とポータブル版では提供せず、従来のメニューを使う (09 の UI-55)。
5. 後から署名を加えるための構成:
   - 署名の処理は 1 つのスクリプト (`build/sign.ps1`) にまとめ、リリースのワークフローの手順 3 (PKG-24) と、`vpk pack` の署名の指定 (`Setup.exe`、`Update.exe` 用) からだけ呼ぶ。
   - リポジトリ変数 `HEX_SIGNING_ENABLED` (既定 `false`) が `true` のときだけ署名する。既定では何もせず、ワークフローのログに「コード署名: 無効」と出す。
   - 署名の対象は仕様 1 の一覧とし、スクリプトの中の 1 か所に定義する。署名の方式と証明書は、署名を導入するときに決める。
   - 署名が無効の間、CI は署名に関する Secrets を必要としない。

**画面**: なし (SmartScreen の警告と UAC の確認画面は Windows が出す)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 署名が無効の間は該当なし。署名を有効にした場合、署名の失敗はリリースのビルドを失敗にする (PKG-24)。

**受け入れ基準**:

- [ ] `HEX_SIGNING_ENABLED` を設定していない状態で、署名に関する Secrets なしにリリースのビルドが成功し、ログに「コード署名: 無効」と出る。
- [ ] リリースノートと `README.md`・`README.txt` に、SmartScreen の警告、続ける手順、Microsoft Store 版の案内がある。
- [ ] GitHub Releases に MSIX のファイルが含まれない。

### PKG-27 winget への提出

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | 安定版の公開時 (PKG-24 の手順 11) |

**概要**: 安定版を公開したら、winget (Windows パッケージマネージャー) のマニフェストを自動で更新して提出する。

**仕様**:

1. winget に登録するのはインストーラ版 (`Setup.exe`、x64 と arm64) とする。インストーラの種類は `exe`、サイレントインストールの引数は Velopack の `Setup.exe` のもの、スコープは `user`。
2. パッケージの識別子は `Hiroyura.HexEditor`。マニフェストの発行者 (`Publisher`) は `Hiroyura`。
3. 最初の版は手動で提出し、2 回目以降は `wingetcreate update --submit` (または同等の GitHub Action) で `microsoft/winget-pkgs` に PR を作る。GitHub のトークンは Secrets の `WINGET_TOKEN`。
4. プレビュー版は提出しない。
5. マニフェストの説明 (`ShortDescription`) は英語と日本語を書く。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 提出の失敗はリリースの公開を取り消さない。失敗を GitHub の Issue として自動で作る。

**受け入れ基準**:

- [ ] 安定版を公開すると、`microsoft/winget-pkgs` に PR が作られる。
- [ ] `winget install Hiroyura.HexEditor` で、管理者権限なしにインストールできる。
- [ ] ARM64 の PC で `winget install` すると ARM64 版が入る。

## 5. 版とリリースノート

### PKG-28 版の付け方

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-15 |
| 呼び出し | タグの作成 (保守担当者) |

**概要**: 版は SemVer で付け、Git のタグを唯一の情報源にする。MSIX などの数値 4 つの版は対応表で作る。

**仕様**:

1. 版は SemVer 2.0: `MAJOR.MINOR.PATCH`、プレビューは `MAJOR.MINOR.PATCH-preview.N` (N は 1〜998)。
2. 唯一の情報源は Git のタグ `v<版>`。CI はタグから版を取り出し、MSBuild のプロパティ `HexVersion` で渡す。`Directory.Build.props` は `HexVersion` から下の表の各値を計算する。タグのないローカルのビルドは `0.0.0-local` (Velopack は 0.0.1 以上の版しか受け付けないため、インストーラ版のパッケージの版だけ `0.0.1-local` とする。MSIX の版は `0.0.0.0`)。
3. 各所の版:

   | 用途 | 値 | 例 (`1.3.0-preview.2`) | 例 (`1.3.0`) |
   | --- | --- | --- | --- |
   | `InformationalVersion` (バージョン情報の表示) | SemVer + `+<コミットの短いハッシュ>` | `1.3.0-preview.2+abc1234` | `1.3.0+def5678` |
   | Velopack の版 | SemVer | `1.3.0-preview.2` | `1.3.0` |
   | MSIX の `Identity Version`、`FileVersion` | `MAJOR.MINOR.(PATCH×1000 + P).0`。P はプレビューなら N、安定版なら 999 | `1.3.2.0` | `1.3.999.0` |
   | `AssemblyVersion` | `MAJOR.MINOR.0.0` | `1.3.0.0` | `1.3.0.0` |

   MSIX の版は第 4 の数を 0 に保ち (Store の要件)、プレビュー < 安定版 < 次の修正版 の順序を保つ。PATCH の上限は 64。
4. 互換性の規則: 設定ファイル・プロジェクトファイル・スクリプトの API の互換性を壊す変更は MAJOR を上げる。機能の追加は MINOR、修正だけなら PATCH。
5. 現在の版は `IAppEnvironment.AppVersion` (PKG-12) から取得し、コード内に版を書かない。

**画面**: バージョン情報 (09 の UI-40)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: タグの形式が違う場合、N が範囲外の場合、PATCH が 64 を超える場合は、リリースのビルドを失敗にする。

**受け入れ基準**:

- [ ] `v1.3.0-preview.2` のタグでビルドした MSIX の版が `1.3.2.0` になる。
- [ ] `1.3.0-preview.2` の MSIX 版から `1.3.0` の MSIX 版に更新できる (版の順序が正しい)。
- [ ] バージョン情報にコミットのハッシュが表示される。

### PKG-29 リリースノート

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-24、F1-26 |
| 呼び出し | リリースのビルド (PKG-24 の手順 9) |

**概要**: 変更履歴と、言語ごとの翻訳の進捗を含むリリースノートを自動で作る。

**仕様**:

1. 変更履歴は `CHANGELOG.md` (Keep a Changelog の形式) に英語で書く。リリースノートには、その版の節 (Added、Changed、Fixed、Removed、Security) をそのまま使う。
2. リリースノートの構成:

   1. どのファイルを選べばよいか (PKG-26 の仕様 3)
   2. 変更履歴
   3. 翻訳の進捗 (仕様 3)
   4. 既知の問題 (`CHANGELOG.md` の Known Issues。あれば)
   5. 配布形態ごとの注意 (コード署名をしていないことによる SmartScreen の警告と続ける手順、Microsoft Store 版の案内と Store 版での管理者権限の扱い (PKG-25 の仕様 3) は毎回書く。その他はあれば)
   6. チェックサムの確認方法

3. 翻訳の進捗は、ビルド時の `translation-coverage.json` (09 の UI-49) から次の表を作る。

   | 言語 | 翻訳済み | 確認済み | 前回からの差 |
   | --- | --- | --- | --- |
   | 日本語 (ja) | 100% | 100% | ±0 |
   | Deutsch (de) | 100% | 87% | +5 |

   表の下に、翻訳の修正を提案する方法 (GitHub の Issue の作成ページと、`.resw` を直す Pull Request の手順へのリンク。09 の UI-41、UI-49) を書く。
4. 「確認済み」が 50% 未満の言語には、表に「機械翻訳が中心です」と注記する。
5. リリースノートは英語で作る。日本語の要約は任意 (未決定)。

**画面**: GitHub Releases の本文。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: `CHANGELOG.md` にその版の節がない場合はリリースのビルドを失敗にする (PKG-24)。`translation-coverage.json` がない場合は翻訳の表を省き、警告を出す。

**受け入れ基準**:

- [ ] リリースノートに 23 言語の翻訳の進捗の表がある。
- [ ] `CHANGELOG.md` に節がない版のタグでは、リリースのビルドが失敗する。

## 6. 異常終了と移行

### PKG-30 異常終了時のデータ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 0 提案) |
| 呼び出し | 未処理の例外、プロセスの異常終了の後の起動 |

**概要**: 異常終了したときに、復旧用データとクラッシュ情報をローカルに残し、次の起動で知らせる。

**仕様**:

1. 未処理の例外 (`AppDomain.UnhandledException`、`Application.UnhandledException`、`TaskScheduler.UnobservedTaskException`) を捕捉したら、次の順に行う。

   1. 未保存の編集内容を復旧用データ (PKG-13 の `recovery\`) に書き出す (00-overview.md 11.3)。2 秒で打ち切る。
   2. クラッシュ情報を `crash\<日時>.txt` に書く: 版、配布形態、アーキテクチャ、OS の版、例外の型・メッセージ・スタックトレース、直近のログ 200 行。ファイルの内容は書かない。ファイルのパスは `log.level = debug` のときだけ書く (09 の UI-57)。
   3. プロセスを終了する。

2. 次の起動時に、`crash\` に未確認のクラッシュ情報があれば InfoBar で「前回、HexEditor が異常終了しました」と「クラッシュ情報を開く」「問題を報告」(09 の UI-40。クラッシュ情報の内容を本文に入れる案内付き) を表示する。復旧用データがあれば復旧の提案 (01) を先に出す。
3. クラッシュ情報は最新の 10 件を残し、古いものは消す。
4. ダンプファイルは既定で作らない。設定 `diagnostics.writeMiniDump` (既定 `false`) を `true` にすると、`crash\` にミニダンプ (メモリの内容を含まないもの、`MiniDumpNormal`) を書く。
5. 復旧用データとクラッシュ情報は外部に送信しない。

**画面**: InfoBar。

**巨大ファイル・長時間処理**: 復旧用データは参照として記録し、巨大な追加データをコピーしない (00-overview.md 11.3)。

**エラー**: クラッシュ情報を書けない場合は `%TEMP%\HexEditor-crash-<日時>.txt` に書く。それも失敗した場合は何もしない。

**受け入れ基準**:

- [ ] 開発用のコマンドでわざと例外を起こすと、`crash\` にファイルができ、次の起動で InfoBar が出る。
- [ ] 3 種類の配布形態で、クラッシュ情報と復旧用データが PKG-13 の場所にできる。
- [ ] クラッシュ情報に開いていたファイルの内容が含まれない。

### PKG-31 配布形態の間の移行と共存

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | 初回起動時 (自動)。ツール > 設定 > 詳細 >「他の版から設定を取り込む」 |

**概要**: 別の配布形態の HexEditor から設定を取り込めるようにし、同じ PC に複数の配布形態がある場合の動作を定める。

**仕様**:

1. 初回起動時に、他の配布形態の設定フォルダ (PKG-13 の MSIX・インストーラの場所。ポータブル版は場所が分からないため対象外) に `settings.json` があれば、スタートページの「はじめに」に「<配布形態> の HexEditor の設定を取り込む」ボタンを出す。
2. 取り込みは 09 の UI-25 のインポートと同じ処理 (設定、キー割り当て、配色。区分ごとに選べる) で、元のフォルダは変更しない。最近使ったファイルとドキュメントの付随データも、選べば取り込む。
3. 同じ PC に複数の配布形態があってもよい。データ・単一インスタンスのキー (PKG-11)・自動更新はそれぞれ独立する。
4. 右クリックメニューとファイル関連付けは、複数の配布形態が登録すると重複して表示される。設定画面「Explorer 連携」で、他の配布形態の登録があることを示す (09 の UI-54)。
5. MSIX 版とインストーラ版の両方がある場合、`hexeditor.exe` / `hexed.exe` の実行エイリアス (MSIX) と App Paths・ユーザーの PATH (インストーラ) のどちらが使われるかは Windows の規則に従う。ドキュメントに注意を書く。

**画面**: スタートページ、設定画面「詳細」。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 取り込みに失敗した区分は一覧で示し、他の区分は取り込む。

**受け入れ基準**:

- [ ] インストーラ版を使った PC にポータブル版を入れて起動すると、設定を取り込むボタンが出て、押すと同じテーマとショートカットになる。
- [ ] インストーラ版と MSIX 版を同時にインストールしても、それぞれが起動し、設定が混ざらない。

# 機能仕様書: UI と設定

メインウィンドウ、タブ、複数ウィンドウ、コマンドパレット、ショートカット、設定、外観、セッション、通知、ヘルプ、国際化、アクセシビリティ、Explorer 連携、プライバシーの仕様を定める。共通の書式・用語・入力式・ショートカット表・UI 部品は [00-overview.md](00-overview.md) に従う。

対象とするロードマップの項目: F0-12 (ステータスバーの配置)、F0-13 (処理センターの UI)、F0-14、F0-16、F0-17、F1-01、F1-02、F1-03、F1-19 (UI 部分)、F1-20、F1-21、F1-22、F1-25、F1-26、F4-10。ロードマップにない機能は「追加 (フェーズ N 提案)」とした。

- 配布形態ごとの違い (保存先・登録方法・更新) の詳細は [10-packaging.md](10-packaging.md) で定める。この文書は利用者から見た振る舞いを定める。
- 重なる領域の分担は 00-overview.md 1.1 に従う。この文書が主担当のもの: ステータスバーの配置とクリックしたときの動作 (UI-06。値の書式は 02 の VIEW-40)、アプリ全体のズーム (UI-08。Hex ビューの文字サイズと行の高さの計算は 02 の VIEW-43)、最近使ったファイルの画面と操作 (UI-32。記録する情報・件数・保存先は 01 の ENG-16)、ドラッグ & ドロップのドロップ先ごとの動作 (UI-34。開く処理は 01 の ENG-12、選択範囲のドラッグは 03 の EDIT-18)、Hex ビューの UI オートメーションと読み上げ (UI-50、UI-51。表示面は 02 の VIEW-41)。
- セーフモードは 08 の AUTO-30 が主担当で、この文書は起動時の動作 (UI-30) だけを定める。コマンドラインのオプションは 08 の AUTO-36〜AUTO-44 が定め、この文書はオプション名を参照するだけにする。
- ショートカットは 00-overview.md 8 章の表と有効範囲 (8.1) に従う。

## 1. メインウィンドウ

### UI-01 メインウィンドウの構成

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 0 提案) |
| 呼び出し | アプリの起動時。表示 > パネルの表示切り替え |

**概要**: メインウィンドウの領域の並びと、各領域の最小サイズ・表示切り替えを定める。

**仕様**:

1. 上から順に次の領域を置く。

   | 順 | 領域 | 高さ / 幅 | 既定 |
   | --- | --- | --- | --- |
   | 1 | タイトルバー (UI-02)。メニューバー (UI-03) を含む | 高さ 48 px | 表示 |
   | 2 | ツールバー (UI-04) | 高さ 40 px | 非表示 |
   | 3 | タブ列 (UI-09) | 高さ 36 px | 表示 |
   | 4 | 作業領域: 左パネル / エディタ / 右パネル、その下に下パネル | 残り全部 | エディタのみ |
   | 5 | ステータスバー (UI-06) | 高さ 28 px | 表示 |

2. エディタ領域は、文書が 1 つもないときスタートページ (UI-38) を表示する。
3. 検索バーなどエディタに重ねる UI はエディタ領域の上端に置き、パネルの上には重ねない。
4. ウィンドウの最小サイズは 640 × 400 px (表示倍率 100% 換算)。幅 1024 px 未満では左右のパネルを自動で折りたたみ、パネルのタブ見出しだけを縦に表示する。折りたたんだパネルは見出しのクリックでエディタの上に重ねて開く。
5. 各領域の境界はドラッグで大きさを変えられる。パネルの幅・高さの最小値は 160 px、エディタの最小幅は 320 px。
6. 表示 > パネルの表示切り替え に、左パネル・右パネル・下パネル・ツールバー・ステータスバー・メニューバーの各表示切り替えを置く。
7. ウィンドウの位置・大きさ・最大化状態・各領域の大きさはセッション (UI-31) に保存する。

**画面**: `Grid` の行で領域を分け、作業領域は列 3 つ + 下段の `Grid`。境界は分割バー (幅 4 px、フォーカス可能、矢印キーで 8 px ずつ移動)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 保存されたウィンドウ位置が現在のモニターの範囲外の場合は、主モニターの中央に既定サイズ (1280 × 800 px、画面に入らない場合は作業領域の 90%) で表示する。

**受け入れ基準**:

- [ ] 初回起動時、タイトルバー・タブ列・エディタ (スタートページ)・ステータスバーだけが表示される。
- [ ] 幅 1000 px にすると左右パネルが折りたたまれ、見出しのクリックで重ねて開ける。
- [ ] モニターを外した状態で再起動しても、ウィンドウが画面内に表示される。
- [ ] 分割バーをキーボードだけで動かせる。

### UI-02 タイトルバー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 0 提案) |
| 呼び出し | 常に表示 |

**概要**: Windows App SDK の `TitleBar` を使った独自のタイトルバー。アイコン、メニューバー、文書名、コマンドパレットの入口、ウィンドウ操作ボタンを置く。

**仕様**:

1. `ExtendsContentIntoTitleBar = true` とし、`Microsoft.UI.Xaml.Controls.TitleBar` を使う。
2. 左から順に、アプリのアイコン、メニューバー (UI-03)、タイトル、コマンドパレットの入口、システムのウィンドウ操作ボタン (最小化・最大化・閉じる) を置く。
3. タイトルは「`<文書名>` - HexEditor」。未保存の変更があれば文書名の前に `●` を付ける。文書がないときは「HexEditor」。管理者として実行中は末尾に「(管理者)」を、セーフモード (UI-30) では「(セーフモード)」を付ける。「(管理者)」は、アプリ全体が管理者として動いているときだけ付け (どの配布形態でも。01 の ENG-28 の仕様 10、10 の PKG-04)、補助プロセス (01 の ENG-28) だけが昇格しているときは付けない。プレビュー版 (10 の PKG-21) では「HexEditor Preview」とする。
4. コマンドパレットの入口は幅 240〜400 px のボタンで、「コマンドを検索 (Ctrl+Shift+P)」と表示する。クリックでコマンドパレット (UI-17) を開く。ウィンドウ幅が 900 px 未満では虫眼鏡アイコンだけにする。
5. メニューバーと入口ボタン以外の余白はウィンドウのドラッグ領域にする。対話する要素は `InputNonClientPointerSource` で入力を通す領域として登録する。ダブルクリックで最大化 / 元に戻す。右クリックでシステムメニューを出す。
6. ウィンドウが非アクティブのときは、タイトルとアイコンを `TextFillColorDisabledBrush` 相当の色にする。
7. 操作ボタンの色はテーマ (UI-26) とハイコントラストに追従させる。
8. 右から左に書く言語では、タイトルバーの内容 (アイコン、メニューバー、タイトル) の並びを左右反転する。システムのウィンドウ操作ボタン (最小化・最大化・閉じる) は Windows が描くため、Windows App SDK の `TitleBar` では右端のまま動かせない (ウィンドウに `WS_EX_LAYOUTRTL` を付けると XAML の内容まで反転するため使わない)。内容が操作ボタンの下に重ならないようにする。

**画面**: タイトルバー。高さ 48 px。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 未保存の変更があるとタイトルに `●` が付き、保存すると消える。
- [ ] 管理者として実行すると (Store 版を含む)、タイトルの末尾に「(管理者)」が付く。補助プロセスでディスクを開いただけでは付かない。
- [ ] タイトルバーの余白をドラッグしてウィンドウを動かせ、ダブルクリックで最大化できる。
- [ ] メニューバーとコマンドパレットの入口がドラッグ領域に吸われずクリックできる。
- [ ] Windows 10 (1809) と Windows 11 の両方で、ライト / ダーク / ハイコントラストの操作ボタンが判読できる。
- [ ] アラビア語表示で、タイトルバーの内容の並びが左右反転し、内容が操作ボタンの下に重ならない (操作ボタンの位置は仕様 8 のとおり)。

### UI-03 メニューバー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 0 提案) |
| 呼び出し | タイトルバー内に常に表示。Alt キーまたは F10 でフォーカス (Windows の標準動作) |

**概要**: 00-overview.md 7 章のメニュー構成をそのまま持つメニューバー。すべての項目はコマンド (UI-16) に対応する。

**仕様**:

1. メニューは 00-overview.md 7 章の順 (ファイル、編集、検索、移動、表示、データ、解析、ツール、フォレンジック、ヘルプ) に並べる。
2. 各項目はコマンド登録 (UI-16) から作る。項目にはコマンドの表示名と、現在割り当てられているショートカット (UI-18 で変更した結果) を表示する。
3. 使えないコマンド (文書がない、読み取り専用など) は無効表示にする。非表示にはしない。ただし、管理者権限がないことだけが理由のコマンド (ディスクを開くなど) は無効にせず、選ぶと管理者権限の案内ダイアログ (01 の ENG-28 の仕様 12) を出す。
4. まだ機能が 1 つもないメニュー (例: フェーズ 5 より前のフォレンジック) はメニューごと表示しない。
5. アクセスキー (Alt + 下線文字) は言語ごとにリソースで定める。日本語では「ファイル(F)」の形で表示する。同じメニュー内でアクセスキーが重ならないことを CI で確認する (UI-42)。
6. ツール > プラグイン の下には、プラグインやスクリプトが登録したコマンドを表示する (詳細は 08)。
7. メニューバーの表示は設定 `ui.menuBar.visible` (既定 `true`) で切り替えられる。非表示のときも Alt キーで一時的に表示する。

**画面**: `MenuBar`。サブメニューは `MenuFlyoutSubItem`。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] メニュー項目のショートカット表示が、ショートカットを変更すると即座に変わる。
- [ ] Alt → F → O の順に押すと「開く」が実行される (日本語・英語の両方)。
- [ ] すべてのメニュー項目がコマンドパレットから同じ名前で見つかる (自動テスト)。
- [ ] 各言語で、同じメニュー内のアクセスキーが重複していない (自動テスト)。

### UI-04 ツールバー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | 表示 > パネルの表示切り替え > ツールバー。コマンドパレット「表示: ツールバーの表示切り替え」 |

**概要**: よく使うコマンドをアイコンで並べる任意のバー。既定では非表示。

**仕様**:

1. 既定のボタン: 新規作成、開く、保存、元に戻す、やり直し、切り取り、コピー、貼り付け、検索、オフセットへ移動、上書き / 挿入の切り替え、データインスペクタ。
2. ツールバーの右クリック >「ツールバーのカスタマイズ」で、コマンド登録 (UI-16) にある任意のコマンドを追加・削除・並べ替えできる。アイコンのないコマンドは表示名の先頭 2 文字をアイコン代わりに表示する。
3. 各ボタンのツールチップに「表示名 (ショートカット)」を出す。
4. 幅に入りきらないボタンは右端の「…」メニューに移す。
5. 構成は設定 `ui.toolbar.items` (コマンド ID の配列) に保存する。

**画面**: `CommandBar` (ラベルなし、`DefaultLabelPosition="Collapsed"`)。アイコンは Segoe Fluent Icons。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 設定に存在しないコマンド ID がある場合は、そのボタンを表示せず、設定画面のツールバー項目に「見つからないコマンド: N 件」と表示する。

**受け入れ基準**:

- [ ] 初回起動時にツールバーが表示されていない。
- [ ] カスタマイズで追加したボタンが再起動後も残る。
- [ ] ウィンドウを狭めると、はみ出したボタンが「…」メニューに入る。

### UI-05 パネル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | 表示 > パネルの表示切り替え。各パネルのショートカット (例: Ctrl+Shift+I でデータインスペクタ)。コマンドパレット「表示: <パネル名>」 |

**概要**: データインスペクタ、ブックマーク、結果一覧などの補助画面を、左・右・下の 3 か所にドッキングして表示する仕組み。00-overview.md 9 章の「パネル」の詳細。

**仕様**:

1. 各パネルは既定の場所を持つ。データインスペクタ = 右、ブックマーク = 左、テンプレートの結果 = 右、検索結果などの結果一覧 = 下。各パネルの既定の場所はそのパネルの仕様 (02〜08) で定める。
2. 同じ場所に複数のパネルがある場合は、上部のタブでまとめる。
3. パネルの見出しをドラッグして、左・右・下の別の場所、または別のウィンドウ (切り離した浮動パネル) に移せる。ドラッグ中はドロップ先を半透明の枠で示す。
4. キーボードでは、パネル見出しの右クリックメニュー (または Shift+F10) の「移動 > 左 / 右 / 下 / 浮動」で移す。
5. 浮動パネルはメインウィンドウの子ウィンドウとして常に前面に置き、メインウィンドウを閉じると一緒に閉じる。浮動パネルの見出しのダブルクリックで元の場所に戻す。
6. パネルは作業中の文書 (アクティブなタブ) に追従して内容を切り替える。文書がない場合は「文書が開かれていません」と表示する。
7. パネルの配置・大きさ・表示状態はウィンドウごとにセッション (UI-31) に保存し、新しいウィンドウは最後に閉じたウィンドウの配置を引き継ぐ。
8. 表示 > パネルの表示切り替え >「パネルの配置を元に戻す」で既定の配置に戻す。

**画面**: パネル領域は見出しのタブ列 + 内容。見出しの右端に「…」(移動・閉じる) と「×」。

**巨大ファイル・長時間処理**: パネルの内容の計算 (例: テンプレートの解析) は各機能の仕様に従いバックグラウンドで行う。パネルの開閉は文書のサイズに依存しない。

**エラー**: 浮動パネルの保存位置が画面外の場合はメインウィンドウの右上に表示する。

**受け入れ基準**:

- [ ] データインスペクタを右から下へドラッグで移し、再起動後も下にある。
- [ ] キーボードだけでパネルを浮動にし、元に戻せる。
- [ ] 同じ場所に 2 つのパネルを置くとタブでまとまる。
- [ ] 「パネルの配置を元に戻す」で既定の配置に戻る。

### UI-06 ステータスバー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-12 |
| 呼び出し | 常に表示 (表示 > パネルの表示切り替え > ステータスバー で非表示にできる) |

**概要**: 使いやすさの原則 5「今の状態が常に見える」を満たすため、カーソル位置・選択範囲・モードなどを常に表示する帯。この項目がステータスバーの配置とクリックしたときの動作の主担当で、各値の書式は 02 の VIEW-40 が定める (00-overview.md 1.1)。

**仕様**:

1. 左から順に次の項目を置く。表示例の書式は VIEW-40 に従う (ここでは例として示す)。* は既定で表示する項目。

   | 項目 | 表示例 | クリックしたとき |
   | --- | --- | --- |
   | カーソル位置 * | `オフセット: 0x00001F00` (ベースアドレスでは `@00401F00`、基準点では `相対 +00000020`) | オフセットへ移動 (Ctrl+G。移動バー VIEW-29 を開く) |
   | カーソルの値 * | `値: 4F (79)` | データインスペクタを開く (Ctrl+Shift+I と同じ) |
   | 選択範囲 * | `選択: 0x1F00–0x1FFF (長さ 0x100 = 256)`。マルチ選択では `選択: 3 範囲、合計 1,024 バイト`。選択がないときは非表示 | 範囲を選択 (Ctrl+E と同じ) |
   | セクタ / ページ / レコード | `セクタ 15`、`ページ 3 / 25,600`、`レコード #1024 +0x04` (VIEW-32、VIEW-33、VIEW-18 が有効なときだけ) | 移動バーを該当の単位で開く |
   | 操作中の列 | `Hex` / `テキスト` | 列を切り替える (Tab と同じ。VIEW-27) |
   | 表示形式 | `int32`、`float` など (Hex 以外のセル形式のときだけ) | セルの表示形式のメニュー |
   | 文字コード * | `UTF-8`、`932` など | 文字コードの選択メニュー (VIEW-21) |
   | エンディアン * | `LE` / `BE`。逆順表示中は `LE (逆順表示)` | 切り替え (VIEW-11) |
   | 入力モード * | `上書き` / `挿入`。読み取り専用のときは鍵アイコン + `読み取り専用` | 上書き / 挿入の切り替え (Insert と同じ)。読み取り専用のときは読み取り専用の切り替え (EDIT-16) |
   | 書き込み保護 * | 盾のアイコン + `書き込み保護` (FOR-01 が有効なときだけ) | 書き込み保護モードの切り替え (FOR-01) |
   | 変更の有無 * | `● 変更あり` / 表示なし | なし |
   | ファイルサイズ * | `サイズ: 1.50 GB (1,610,612,736 バイト)` | 正確なバイト数をクリップボードにコピー |
   | 同期 | `同期` (VIEW-39 が有効なときだけ) | 同期のモードのメニュー |
   | ズーム | `120%` (100% のときは非表示) | 100% に戻す (Ctrl+0 と同じ。UI-08) |
   | 自動化 * | マクロの記録中 (AUTO-27)、実行中のスクリプトの数 (AUTO-01)、外部からの自動操作が有効 (AUTO-45) のアイコン (該当するときだけ) | 記録中は記録の停止、それ以外は出力パネル (AUTO-24) を開く |
   | 処理センター * | 実行中の件数と全体の進捗バー | 処理センター (UI-37) を開く |
   | 通知 * | ベルのアイコン + 未読数 | 通知の履歴 (UI-36) を開く |

2. 右クリックメニューで各項目の表示・非表示を切り替えられる。設定 `ui.statusBar.items` に保存する。
3. 値が変わったときの更新は 1 フレーム (16 ms) 以内 (VIEW-40 の 50 ms 以内を満たす)。カーソル移動のキーリピート中も遅れない。マウスのドラッグ中は 30 fps を上限にする。
4. 各項目はキーボードでフォーカスでき (F6 / Shift+F6 の領域の移動 UI-52 で到達し、← / → で項目間を移動)、Enter でクリックと同じ動作をする。
5. 幅が足りない場合の省略の規則はこの項目だけで定める (VIEW-40 は従う)。優先度の低い項目から「…」に入れる。順: ズーム → 同期 → 表示形式 → 操作中の列 → セクタ / ページ / レコード → カーソルの値 → ファイルサイズの括弧内 → エンディアン → 文字コード → ファイルサイズ → 自動化 → 通知。カーソル位置・選択範囲・入力モード・書き込み保護・変更の有無・処理センターは常に表示する。
6. 右から左に書く言語では項目の並びを左右反転する。各項目内の 16 進の値は左から右のまま (UI-44)。

**画面**: 高さ 28 px の帯。項目は区切り線で分ける。

**巨大ファイル・長時間処理**: サイズ・オフセットは `long` で表示する。8 EB まで桁あふれせずに表示する。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 100 GB のファイルの末尾にカーソルを置くと、正しいオフセットが表示される。
- [ ] 「上書き」をクリックすると「挿入」に変わり、Insert キーと同じ動作をする。
- [ ] 項目を非表示にして再起動しても非表示のまま。
- [ ] 幅 640 px でもカーソル位置・選択範囲・モードが表示されている。

### UI-08 ズーム

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | Hex 表示のズーム: 表示 > ズーム > 拡大 / 縮小 / 100% に戻す。Ctrl+= / Ctrl+- / Ctrl+0 (グローバル。00-overview.md 8.2)。Ctrl+マウスホイール。ステータスバーの倍率表示のクリック (100% に戻す。UI-06)。コマンドパレット「表示: 拡大」「表示: 縮小」「表示: ズームを 100% に戻す」。画面全体のズーム: 表示 > ズーム > 画面全体を拡大 / 縮小 / 100% に戻す (既定のキーなし)。コマンドパレット「表示: 画面全体を拡大」など |

**概要**: 2 種類のズームを持つ。「Hex 表示のズーム」は編集中のデータの文字だけを大きくし、「画面全体のズーム」はメニュー・パネル・ダイアログを含むアプリ全体を大きくする。Hex 表示のズームは、全タブ共通か今のタブだけかを設定で選べる。この項目がズームの操作・倍率の段階・保存の主担当で、倍率から Hex ビューの文字サイズと行の高さを計算する方法は 02 の VIEW-43 が定める (00-overview.md 1.1)。

**仕様**:

1. 倍率の範囲は、どちらのズームも 50〜400%。段階は 50, 67, 75, 80, 90, 100, 110, 125, 150, 175, 200, 250, 300, 400%。拡大・縮小は 1 回で 1 段階動く。
2. Hex 表示のズーム:
   1. 対象は Hex 表示 (オフセット・Hex 列・テキスト列・列見出し) と、パネル内の Hex 表示。
   2. 適用範囲は設定 `view.zoom.hexScope` で選ぶ。`all` (既定): 全タブ・全ウィンドウで 1 つの倍率を共通に使い、設定 `view.zoom.hex` (既定 100) に保存する。`tab`: タブ (ビュー) ごとに倍率を持つ。
   3. `tab` のとき、新しく開いたタブは、その時点で表示中のタブの倍率を引き継ぐ。表示中のタブがなければ `view.zoom.hex` の倍率で開く。
   4. `tab` のときの各タブの倍率は、タブを開いている間とセッション復元 (UI-31) で保つ。タブを閉じたら破棄し、同じファイルを開き直しても引き継がない。
   5. `tab` から `all` に切り替えたときは、表示中のタブの倍率を `view.zoom.hex` にして全タブに適用する。
3. 画面全体のズーム:
   1. 対象はメニュー・ツールバー・パネル・ステータスバー・ダイアログ・Hex 表示を含むアプリ全体。Windows の表示倍率と文字サイズの設定に、さらに掛け合わせる。
   2. 全ウィンドウで共通の 1 つの倍率を持ち、設定 `view.zoom.ui` (既定 100) に保存する。
   3. Hex 表示の最終的な大きさは、画面全体の倍率 × Hex 表示の倍率になる。
   4. 実装方法 (ルート要素の拡大か、文字サイズのリソースの一括変更か) は試作して決める (未決定)。どちらの方法でも、文字がぼやけず、400% で画面が崩れないこと。
4. ズーム後もカーソルのあるバイトが画面内に残るようにスクロール位置を調整する。
5. Ctrl+マウスホイールは 1 ノッチで 1 段階 (Hex 表示のズーム)。高精度タッチパッドのピンチも同じ扱い。
6. `Ctrl+=` `Ctrl+-` は記号キーのため、メニューとコマンドパレットからも実行できる (00-overview.md 8 章)。

**画面**:

- ステータスバー (UI-06) に、倍率が 100% でないズームの倍率を表示する。Hex 表示は `Hex 125%`、画面全体は `画面 110%` の形式。クリックするとそのズームを 100% に戻す。
- 設定画面の「表示」に、Hex 表示のズームの適用範囲 (全タブ共通 / 今のタブだけ) と、画面全体のズームの倍率を置く。

**巨大ファイル・長時間処理**: 該当なし (描画は見えている行だけ)。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 100% から Ctrl+= を 2 回押すと 125% になり、ステータスバーに `Hex 125%` と表示される。
- [ ] Ctrl+0 で 100% に戻り、ステータスバーの倍率表示が消える。
- [ ] 適用範囲が「全タブ共通」のとき、タブ A で拡大するとタブ B も同じ倍率になる。
- [ ] 適用範囲が「今のタブだけ」のとき、タブ A で拡大してもタブ B の倍率は変わらない。新しく開いたタブは、開いたときに表示していたタブの倍率になる。
- [ ] 「今のタブだけ」で拡大したタブを閉じて同じファイルを開き直すと、倍率は引き継がれない。
- [ ] 画面全体を 150% にすると、メニュー・パネル・ダイアログの文字も大きくなり、ステータスバーに `画面 150%` と表示される。
- [ ] 画面全体 400% で、メイン画面と設定画面が崩れず、文字がぼやけない。
- [ ] ズームしてもカーソル位置のバイトが画面内にある。
- [ ] ドイツ語配列でもメニューから拡大・縮小できる。

### UI-09 タブ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-01 |
| 呼び出し | 文書を開くと自動で作成。Ctrl+Tab / Ctrl+Shift+Tab、Ctrl+PageDown / Ctrl+PageUp で切り替え。Ctrl+W / Ctrl+F4 で閉じる。マウスの中ボタンのクリックで閉じる |

**概要**: 1 つのウィンドウで複数の文書をタブで切り替えて扱う。

**仕様**:

1. 文書 1 つにつきタブ 1 つ。同じファイルをもう一度開こうとした場合は、新しいタブを作らず既存のタブをアクティブにする (同じファイルかどうかはファイル ID `FILE_ID_INFO` で判定し、パスの表記揺れやハードリンクも同一とみなす)。
2. タブの見出しには、種類のアイコン (ファイル / ディスク / プロセス / 新規)、表示名、状態を表示する。

   | 状態 | 表示 |
   | --- | --- |
   | 未保存の変更あり | 閉じるボタンの位置に `●`。ホバーで `×` に変わる |
   | 読み取り専用 | 鍵アイコン |
   | ピン留め | ピンのアイコン (UI-10) |
   | 外部で変更された | 警告アイコン (01 の ENG-19) |
   | 長時間処理を実行中 | 小さな進捗リング |

3. 表示名はファイル名。同じファイル名のタブが複数あるときは、区別できる最小の親フォルダ名を付ける (例: `data.bin — a\x`、`data.bin — b\x`)。
4. ツールチップに完全なパス、サイズ、種類、読み取り専用かどうかを表示する。
5. タブの幅は 100〜240 px。入りきらない場合はタブ列を横スクロールし、右端に「すべてのタブ」ボタン (一覧から選ぶ) を置く。
6. Ctrl+Tab は最近使った順 (MRU) でタブを切り替える。Ctrl キーを押している間は切り替え候補の一覧を表示する。Ctrl+PageDown / Ctrl+PageUp は見出しの並び順で切り替える。
7. タブの右端の「+」ボタンで新規作成 (Ctrl+N と同じ)。
8. 未保存の変更があるタブを閉じるときは確認ダイアログを出す (UI-13)。
9. タブの右クリックメニュー: 閉じる、他のタブを閉じる、右側のタブを閉じる、保存済みのタブを閉じる、すべて閉じる、ピン留め / ピン留めを外す、新しいウィンドウに移動、別のウィンドウに移動 > (ウィンドウ一覧)、パスをコピー、エクスプローラーで表示、読み取り専用。
10. タブの最大数に上限は設けない。開いていないタブ (アクティブでないタブ) は表示用のキャッシュを解放し、メモリ上限 (00-overview.md 11.2) は全タブで共有する。

**画面**: `TabView` (`TabWidthMode="SizeToContent"`、最小・最大幅を指定)。

**巨大ファイル・長時間処理**: タブの切り替えは文書のサイズに関係なく 100 ms 以内に表示する。

**エラー**: 開けなかった文書のタブは作らず、InfoBar でエラーを表示する (01 で定める)。

**受け入れ基準**:

- [ ] 同じファイルを 2 回開くと既存のタブがアクティブになる (別のパス表記・ハードリンクでも同じ)。
- [ ] 同名のファイルを 2 つ開くと親フォルダ名で区別される。
- [ ] Ctrl+Tab で直前に使っていたタブに切り替わる。
- [ ] 50 個のタブを開いても、タブの切り替えが 100 ms 以内。
- [ ] 中ボタンのクリックでタブが閉じる。

### UI-11 タブの切り離しとウィンドウ間の移動

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-01 |
| 呼び出し | タブをタブ列の外へドラッグ。タブの右クリック > 新しいウィンドウに移動 / 別のウィンドウに移動。コマンドパレット「タブ: 新しいウィンドウに移動」 |

**概要**: タブを別ウィンドウに切り離したり、別のウィンドウのタブ列に移したりする。

**仕様**:

1. タブをタブ列の外 (タブ列から上下 32 px 以上) にドロップすると、ドロップした位置に新しいウィンドウを作り、そのタブを移す。
2. 別のウィンドウのタブ列にドロップすると、その位置にタブを移す。
3. 移したタブは、文書の状態 (未保存の編集、Undo 履歴、カーソル、選択、表示設定、実行中の長時間処理) をすべて保ったまま移る。文書を読み直さない。
4. ウィンドウの最後のタブを切り離した場合は、新しいウィンドウを作らずそのウィンドウ自体を移動する。
5. 別のプロセス (別のインスタンス、例: 管理者として実行中のもの) のウィンドウへはドラッグで移せない。ドロップできないカーソルを表示する。
6. 切り離した直後のウィンドウの大きさは元のウィンドウと同じにする。

**画面**: `TabView` の `TabDroppedOutside`、`TabStripDragOver`、`TabStripDrop` を使う。

**巨大ファイル・長時間処理**: 移動は文書のサイズに関係なく 200 ms 以内に完了する。実行中の長時間処理は中断しない。

**エラー**: 移動に失敗した場合 (想定外の例外) はタブを元のウィンドウに残し、InfoBar で「タブを移動できませんでした」と表示する。

**受け入れ基準**:

- [ ] 未保存の編集があるタブを切り離しても、新しいウィンドウで Undo できる。
- [ ] 検索中のタブを別ウィンドウに移しても、検索が続き結果が届く。
- [ ] 2 つのウィンドウの間でタブをドラッグで移せる。
- [ ] タブが 1 つのウィンドウでタブを外へドラッグすると、ウィンドウが移動する。

### UI-13 閉じるときの確認

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-01 |
| 呼び出し | 未保存の変更があるタブ・ウィンドウ・アプリを閉じるとき |

**概要**: 未保存の変更や実行中の処理があるときに、閉じる前に保存するかどうかを尋ねる。

**仕様**:

1. 1 つの文書の場合、ダイアログに「<名前> への変更を保存しますか?」と変更量 (例: 「3 か所、合計 1.2 MB」) を表示し、ボタンは「保存」「保存しない」「キャンセル」にする。

5. ウィンドウを閉じる場合、そのウィンドウのタブだけが対象。最後のウィンドウを閉じるとアプリを終了する。

**受け入れ基準**:

- [ ] 変更のあるタブを Ctrl+W で閉じるとダイアログが出て、「キャンセル」でタブが残る。
- [ ] 変更のある文書が 3 つある状態でアプリを終了すると、3 件の一覧が出る。
- [ ] 保存中に閉じると「保存が終わったら閉じる」を選べ、保存の完了後に閉じる。
- [ ] ダイアログのボタンに「はい / いいえ」が使われていない。

### UI-14 複数ウィンドウ

| 項目 | 内容 |

| ロードマップ | F1-01 |
| 呼び出し | ファイル > 新しいウィンドウ。Ctrl+Shift+N (グローバル。00-overview.md 8.2)。コマンドパレット「ウィンドウ: 新しいウィンドウ」。ジャンプリストの「新しいウィンドウ」。コマンドライン `--new-window` (08 の AUTO-37) |

**概要**: 1 つのプロセスで複数のメインウィンドウを開く。

1. 新しいウィンドウは空 (スタートページ) で開く。パネルの配置は最後にアクティブだったウィンドウを引き継ぐ。
2. 設定・ショートカット・テーマ・最近使ったファイルは全ウィンドウで共通。変更は即座に全ウィンドウに反映する。
3. 外部から開いたファイル (UI-15) と、ファイル > 開く で開いたファイルは、最後にアクティブだったウィンドウに開く。
4. 最後のウィンドウを閉じるとアプリを終了する。
5. ウィンドウごとの状態 (位置、大きさ、タブ、パネル) はセッション (UI-31) にウィンドウ単位で保存する。
6. コマンドパレット「ウィンドウ: 次のウィンドウ」(既定なし) でウィンドウを順に切り替える。

**画面**: メインウィンドウと同じ構成。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] Ctrl+Shift+N で、同じプロセスに空の新しいウィンドウが開く。
- [ ] 2 つのウィンドウを開いた状態でテーマを変えると、両方に反映される。
- [ ] 2 つのウィンドウとそれぞれのタブが再起動後に復元される。
- [ ] 最後のウィンドウを閉じるとプロセスが終了する。

### UI-15 単一インスタンスと起動の転送

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-16 |
| 呼び出し | アプリの 2 回目以降の起動 (ダブルクリック、右クリックメニュー、コマンドライン、ジャンプリスト) |

**概要**: 2 つ目の起動は既存のプロセスに転送し、既存のウィンドウに新しいタブとして開く。

**仕様**:

1. 起動処理 (10 の PKG-11) で `Microsoft.Windows.AppLifecycle.AppInstance.FindOrRegisterForKey` を呼ぶ。キーは配布形態・実行ファイルの場所・権限で分ける (10 の PKG-11)。既存のインスタンスがあれば `RedirectActivationToAsync` で起動引数を渡し、2 つ目のプロセスは終了する。
2. 既存のインスタンスは受け取った引数を解釈し (コマンドラインの書式は 08 の AUTO-36・AUTO-37 で定める)、設定 `window.openExternalIn` に従って開く。

   | 値 | 動作 |
   | --- | --- |
   | `lastActiveWindow` (既定) | 最後にアクティブだったウィンドウに新しいタブで開く |
   | `newWindow` | 新しいウィンドウで開く |

   コマンドラインの `--new-window` (08 の AUTO-37) は設定より優先する。
   `newWindow` と `--new-window` は複数ウィンドウ (UI-14、F1-01) とともにフェーズ 1 で対応する。フェーズ 0 では常に `lastActiveWindow` の動作をする。
3. 開いたウィンドウを前面に出す。2 つ目のプロセスは転送の前に `AllowSetForegroundWindow` で既存プロセスに前面化を許可する。
4. ファイルを指定しない起動 (スタートメニューからの起動など) は、既存のウィンドウを前面に出すだけにする。設定 `window.launchWithoutFileOpensNewWindow` (既定 `false`) が `true` なら新しいウィンドウを開く。
5. 管理者として実行中のインスタンスと一般権限のインスタンスは別のインスタンスとして扱う (Windows は権限の違うプロセス間の転送を制限するため)。
6. 転送が 5 秒以内に完了しない場合 (既存プロセスが応答しない場合)、2 つ目のプロセスは独立したインスタンスとして起動し、InfoBar で「既存のウィンドウが応答しないため、新しいインスタンスで開きました」と表示する。
7. 複数のファイルを同時に渡された場合 (Explorer で複数選択して開く)、すべてを同じウィンドウのタブとして開く。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。転送はファイルの読み込み前に行う。

**エラー**: 仕様 6 のとおり。

**受け入れ基準**:

- [ ] アプリを起動した状態で、Explorer からファイルをダブルクリックすると、既存のウィンドウに新しいタブで開き、プロセスは 1 つのまま。
- [ ] 設定を `newWindow` にすると、同じプロセスの新しいウィンドウで開く。
- [ ] Explorer で 5 ファイルを選んで開くと、1 つのウィンドウに 5 タブ開く。
- [ ] 既存のウィンドウが他のアプリの後ろにあっても前面に出る。
- [ ] 既存プロセスをデバッガで止めた状態で起動すると、5 秒後に新しいインスタンスが起動する。

### UI-16 コマンド登録

### UI-17 コマンドパレット

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-02 |
| 呼び出し | ヘルプ > コマンドパレット。Ctrl+Shift+P / F1 (グローバル。00-overview.md 8.2。コードエディタでも同じ)。タイトルバーの入口 (UI-02) |

**概要**: 全コマンドを名前であいまい検索して実行する。接頭辞を付けると、ファイル・オフセット・ブックマークなどにも移動できる。

**仕様**:

1. タイトルバーの下中央に、幅 600 px (ウィンドウ幅の 90% まで) の入力欄と候補一覧を重ねて表示する。モーダルにしない。Esc またはフォーカスが外れると閉じ、エディタにフォーカスを戻す。
2. 入力の先頭文字でモードを切り替える。

   | 接頭辞 | モード | 内容 |
   | --- | --- | --- |
   | `>` | コマンド | 全コマンド。Ctrl+Shift+P / F1 はこのモードで開く |
   | なし | ファイル | 開いているタブと最近使ったファイル (UI-32) |
   | `:` | オフセットへ移動 | 00-overview.md 6 章の入力式。入力中に移動先を一覧に表示し、Enter で移動 (Ctrl+G と同じ処理) |
   | `@` | ブックマーク | 現在の文書のブックマーク (05) |
   | `#` | 設定 | 設定項目を検索し、選ぶと設定画面のその項目を開く (UI-22) |
   | `?` | ヘルプ | 接頭辞の一覧を表示する |

3. 検索はあいまい一致 (入力の文字が順に含まれていれば一致) で、次の順に点数を付けて並べる: 先頭一致 > 単語の先頭一致 > 連続一致 > 飛び飛びの一致。一致した文字を太字で示す。
4. コマンドモードでは、表示言語の表示名・英語名・コマンド ID・カテゴリ名・検索用の別名 (UI-16 の 1。日本語の読みなど) のどれに一致しても候補にする。英語名で一致した場合は、表示名の横に英語名を薄く表示する。大文字・小文字・全角半角・アクセント記号の違いは無視する (Invariant で比較。00-overview.md 5.4)。
5. 各候補には「カテゴリ: 表示名」、ショートカット、使えない場合はその理由 (例: 「文書が開かれていません」) を表示する。使えないコマンドは選べるが、実行するとエラーの InfoBar を出す (UI-16)。
6. 入力が空のとき、コマンドモードでは最近使ったコマンド (最大 10 件、新しい順) を先頭に「最近使ったもの」として出し、その後に全コマンドを五十音順 (表示言語の並び順) に出す。最近使ったコマンドは設定フォルダの `state.json` に最大 50 件保存する。
7. 引数が必要なコマンド (例: 「表示: 1 行のバイト数を設定」) は、選んだ後に同じ入力欄で引数を尋ねる。
8. ↑↓ で候補を選び、Enter で実行、Esc で閉じる。Tab キーで候補の表示名を入力欄に補完する。コマンドパレットの入力欄は文字を入力できる場所なので、AltGr (Ctrl+Alt) で入力される文字はショートカットより優先する (UI-20)。
9. 候補の一覧は仮想化し、1,000 件以上でも遅れない。

**画面**: 入力欄 (`AutoSuggestBox` 相当の独自部品) と候補一覧 (`ListView`)。

**巨大ファイル・長時間処理**: 該当なし。オフセットモードの移動は 02 のジャンプの性能目標に従う。

**エラー**: オフセットモードで不正な入力の場合は、一覧に入力式のエラー内容を表示し、Enter を無効にする (00-overview.md 9 章「入力欄」)。

**受け入れ基準**:

- [ ] Ctrl+Shift+P を押してから 100 ms 以内に入力欄が表示される。
- [ ] 日本語表示で `open` と入力すると「ファイル: 開く」が候補に出る。`ひらく` (`ja` のリソースの検索用の別名に置いた読み) でも出る。
- [ ] 1,000 個のコマンドがある状態で、1 文字入力するごとの絞り込みが 16 ms 以内。
- [ ] `:end-0x10` と入力して Enter で、末尾 16 バイト前に移動する。
- [ ] 実行したコマンドが次回の起動後も「最近使ったもの」の先頭に出る。
- [ ] トルコ語表示で `I` / `i` を含む英語名の検索結果が英語表示と同じ。

### UI-18 ショートカットの変更

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-03 |
| 呼び出し | ツール > 設定 > キーボード。コマンドパレット「設定: キーボードショートカット」。コマンドパレットの候補の右クリック >「ショートカットを変更」 |

**概要**: 各コマンドのキー割り当てを変更・追加・削除し、重複を検出する。

**仕様**:

1. 設定画面の「キーボード」に、全コマンドの一覧 (カテゴリ、表示名、英語名、割り当てキー、有効範囲、由来) を表で表示する。由来は「既定」「プリセット」「利用者」のいずれか。
2. 上部の検索欄で、表示名・英語名・コマンド ID・キーの表記 (例: `ctrl+g`) で絞り込める。「キーで検索」ボタンを押すと、次に押したキーの組み合わせに割り当てられたコマンドを絞り込む。
3. 行の「編集」でキー入力待ちの欄を開き、押したキーの組み合わせをそのまま記録する。2 ストロークまでの連続キー (例: `Ctrl+K, Ctrl+S`) を記録できる。Enter で確定、Esc で取り消し。
4. 1 つのコマンドに複数のキーを割り当てられる。
5. 有効範囲 (`when`) は 00-overview.md 8.1 の 5 つから選ぶ。

   | 表示名 | `when` の値 | 対象 |
   | --- | --- | --- |
   | グローバル | `global` | アプリ全体 |
   | エディタ | `editor` | Hex ビューにフォーカスがあるとき |
   | 検索バー | `findBar` | 検索バー・置換バーにフォーカスがあるとき |
   | コードエディタ | `codeEditor` | スクリプトエディタ・テンプレートエディタにフォーカスがあるとき |
   | パネル | `panel` | 一覧形式のパネルにフォーカスがあるとき |

   狭い有効範囲 (エディタ・検索バー・コードエディタ・パネル) の割り当ては、グローバルの同じキーより優先する (8.1)。
6. 重複の検出: 確定しようとしたキーが、同じ有効範囲で他のコマンドに割り当て済みの場合、その一覧を表示し、「置き換える (他の割り当てを外す)」「キャンセル」を選ばせる。同じ有効範囲で 1 つのキーに 2 つのコマンドを割り当てることはできない (00-overview.md 8 章)。狭い有効範囲の割り当てがグローバルの割り当てを隠す場合は、確定できるが「<有効範囲> では <グローバルのコマンド> の代わりにこのコマンドが動きます」と警告する (例: コードエディタの F11 と全画面表示)。
7. 割り当てられないキー: Alt+F4、Windows キーとの組み合わせ、Ctrl+Alt+Delete、修飾キーだけ、修飾キーなしの文字キー・数字キー (入力に使うため。ファンクションキー・Insert・Delete などは可)。選ぶと理由を表示して拒否する。文字を入力できる場所 (入力欄、テキスト列、コードエディタ) での AltGr との重なりは UI-20 に従う。
8. 行ごとの「既定に戻す」、表全体の「すべて既定に戻す」(確認ダイアログあり) を置く。
9. 割り当ては設定フォルダの `keybindings.json` に、プリセットとの差分として保存する。

   ```json
   {
     "$schemaVersion": 1,
     "preset": "default",
     "bindings": [
       { "command": "edit.fill", "key": "Ctrl+K Ctrl+F", "when": "editor" },
       { "command": "-file.print", "key": "Ctrl+P" }
     ]
   }
   ```

   `-` で始まる `command` は、そのキーの割り当てを外すことを表す。`when` を省略した場合は `global` とみなす。
10. 変更は即座に全ウィンドウのメニュー表示・ツールチップ・コマンドパレットに反映する。

**画面**: 設定画面内の表 (`ListView` + 見出しの `Grid`)。キー入力待ちの欄は専用の入力部品。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: `keybindings.json` が不正な場合は、読み込める部分だけを使い、InfoBar で「キーボードショートカットの設定に誤りがあります (N 行目)」と「ファイルを開く」ボタンを表示する。

**受け入れ基準**:

- [ ] 「オフセットへ移動」に Ctrl+J を追加すると、メニューに Ctrl+G と並んで表示され、Ctrl+J で動く。
- [ ] Ctrl+F を「オフセットへ移動」に割り当てようとすると、「検索」との重複が表示される。
- [ ] 「置き換える」を選ぶと、「検索」から Ctrl+F が外れる。
- [ ] 修飾キーなしの `A` を割り当てようとすると拒否される。
- [ ] 「すべて既定に戻す」で `keybindings.json` の `bindings` が空になる。

**概要**: どのキーボード配列でもショートカットが正しく表示・実行されるようにする (00-overview.md 5.4)。

**仕様**:

1. 割り当ては仮想キーコードと修飾キーの組で保存する (例: `Ctrl+OemComma`)。英字キーは配列上の文字で一致する (AZERTY でも「Z」と刻印されたキーで Ctrl+Z が動く)。
2. キーの表示名は、現在のキーボード配列から `ToUnicodeEx` / `GetKeyNameTextW` で求めて表示する (例: ドイツ語配列の `OemPlus` は `+`)。修飾キー (Ctrl・Shift・Alt) の表示名も `GetKeyNameTextW` で求めた OS の表記を使い、アプリで翻訳しない (例: ドイツ語配列では Ctrl が `Strg`)。配列が変わったとき (`WM_INPUTLANGCHANGE`) に表示を更新する。
3. 現在の配列で押せない仮想キー (`MapVirtualKeyExW` が 0 を返すもの) を使う割り当ては、設定画面とショートカット一覧 (UI-39) に「この配列では押せません」と表示する。そのコマンドはメニューとコマンドパレットから実行できる。
4. AltGr の扱い (00-overview.md 8.1): AltGr は Ctrl+Alt として届く。文字を入力できる場所 (入力欄 (検索バー・コマンドパレット・ダイアログの入力欄を含む)、Hex 表示のテキスト列、コードエディタ) では、Ctrl+Alt+キーが現在の配列で文字を生む場合、文字の入力を優先し、ショートカットを実行しない。どの有効範囲の割り当てでも同じ。Hex 表示の Hex 列など文字を入力しない場所では、ショートカットを実行する (例: エディタの Ctrl+Alt+↑ / ↓)。設定画面では、そのような割り当てに「AltGr の文字入力と重なります」と表示する。
5. IME の変換中のキー入力はショートカットとして扱わない (00-overview.md 5.4)。

**画面**: 設定画面の「キーボード」の表。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] ドイツ語配列で、Ctrl+, の表示が配列の表記 (修飾キーの名前を含めて `GetKeyNameTextW` で求めた OS の表記。仕様 2) で表示される。
- [ ] ドイツ語配列のテキスト列で AltGr+7 を押すと `{` が入力され、ショートカットは実行されない。
- [ ] フランス語配列 (AZERTY) で「Z」と刻印されたキーで Ctrl+Z が動く。
- [ ] 日本語 IME の変換中に Ctrl+G を押しても「オフセットへ移動」が開かない (変換操作として扱われる)。

### UI-23 設定の保存形式と保存先

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-21 |
| 呼び出し | 自動。ツール > 設定 > 詳細 >「データフォルダを開く」「設定ファイルを開く」 |

**概要**: 設定とアプリの状態を JSON ファイルで保存する。保存先は配布形態で変わる。

**仕様**:

1. 設定フォルダには次のファイルを置く。

   | ファイル / フォルダ | 内容 |
   | --- | --- |
   | `settings.json` | 利用者が変更した設定 (既定値と違うものだけ) |
   | `keybindings.json` | キー割り当て (UI-18) |
   | `themes/*.json` | 独自の配色 (UI-28) |
   | `session.json` | セッション (UI-31) |
   | `recent.json` | 最近使ったファイル (UI-32) |
   | `state.json` | 最近使ったコマンド、閉じたタブ、ダイアログの「次回から表示しない」などの状態 |
   | `documents/` | ドキュメントに付随するデータ (00-overview.md 10 章) |

   復旧用データ・ログ・一時ファイルの場所は 10 の PKG-13 で定める。
2. 設定フォルダの場所は配布形態で決まる (詳細は 10 の PKG-13)。

   | 配布形態 | 設定フォルダ |
   | --- | --- |
   | MSIX | `%LocalAppData%\Packages\<パッケージファミリ名>\LocalState\` (`ApplicationData.Current.LocalFolder`) |
   | インストーラ | `%LocalAppData%\HexEditorData\` |
   | ポータブル | `<exe のフォルダ>\Data\` (`portable.marker` がある場合) |

3. `settings.json` は、設定キーを `.` で区切った平らな JSON にする。先頭に `$schema` と `$schemaVersion` を置く。この 2 つは設定のキーではなく、常に書く (仕様 4 の「既定値と同じ値は書かない」の対象外)。

   | キー | 内容 |
   | --- | --- |
   | `$schema` | 同梱の JSON スキーマ (仕様 8) を指す URL (`file:` の URL)。外部のエディタの補完・検査用で、アプリは読み込み時に使わない (なくてもよい)。書き込むときは現在の版のスキーマの場所を書く (アプリの更新やポータブル版の移動で場所が変わっても追従する) |
   | `$schemaVersion` | 設定ファイルの形式の版 (整数。1 から始め、キーの名前や値の形を変えたときに 1 増やす)。仕様 6 の移行の判定に使う。アプリの版とは別 |

   ```json
   {
     "$schema": "file:///C:/Program%20Files/HexEditor/settings.schema.json",
     "$schemaVersion": 1,
     "ui.theme": "dark",
     "view.zoom.hex": 125,
     "ui.language": "ja"
   }
   ```

4. 既定値と同じ値は書かない。知らないキーは読み込み時に捨てず、書き込み時にもそのまま残す (新しい版で作った設定を古い版で開いても壊さない)。
5. 書き込みは一時ファイルに書いてから置き換える (書き込み中に落ちても壊れない)。変更から 500 ms 待って、まとめて書く。
6. `$schemaVersion` が古い場合は、読み込み時に移行し、移行前のファイルを `settings.json.bak-v<旧版>` として残す。新しすぎる場合は読み込めるキーだけ使い、書き込みを止めて InfoBar で知らせる。
7. 設定ファイルを外部で編集した場合は、変更を検知して 1 秒以内に再読み込みし、反映する。
8. JSON スキーマ (`settings.schema.json`) をアプリに同梱し、`settings.json` の `$schema` に参照を書く (外部のエディタで補完できるようにする)。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: `settings.json` が JSON として読めない場合は、既定値で起動し、壊れたファイルを `settings.json.broken-<日時>` に名前を変えて残し、InfoBar で「設定ファイルを読み込めなかったため、既定の設定で起動しました」と「ファイルを開く」ボタンを表示する。外部編集で不正になった場合は、直前の値を使い続け、行番号付きで InfoBar に表示する。

**受け入れ基準**:

- [ ] 初回起動直後の `settings.json` には `$schema` と `$schemaVersion` だけがある (仕様 3)。
- [ ] テキストエディタで `ui.theme` を書き換えて保存すると、1 秒以内にテーマが変わる。
- [ ] `settings.json` を壊して起動すると、既定値で起動し、`.broken-` 付きのファイルが残る。
- [ ] 知らないキーを書いておくと、設定を変更して保存した後もそのキーが残る。
- [ ] 書き込み中にプロセスを強制終了しても、`settings.json` が JSON として読める (一時ファイルへの書き込み中・置き換えの直前と直後の各時点で、テスト方針 (../test/00-test-strategy.md) 7.2 の強制終了で再現する)。

### UI-28 Hex 表示の配色

| 項目 | 内容 |

**仕様**:

1. 配色で決める要素: 背景、交互の行の背景、オフセット列の文字、Hex 列の文字、テキスト列の文字、`00` のバイト、表示できない文字 (`.`)、変更されたバイト、挿入されたバイト、選択範囲の背景と文字、カーソル、カーソル行の背景、検索の一致、ブックマーク、差分 (追加・削除・変更)、区切り線、レコードの交互色。

### UI-29 フォント

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | ツール > 設定 > 外観 > フォント |

**概要**: Hex 表示のフォントと大きさを選ぶ。UI のフォントは Windows の標準に従う。

**仕様**:

1. UI のフォントは変更できない。Windows の標準 UI フォント (Segoe UI Variable と各言語の代替フォント) を使い、大きさは Windows の「文字の大きさ」に従う (00-overview.md 5.4)。
2. Hex 表示のフォント `view.font.family`: 既定は `Cascadia Mono`、ない場合は `Consolas`。一覧には等幅フォントだけを表示し、「すべてのフォントを表示」をオンにすると全フォントを出す。等幅でないフォントを選んだ場合は、文字ごとに同じ幅のセルに中央揃えで描画する。
3. Hex 表示の大きさ `view.font.size`: 6〜72 pt、既定 11 pt。0.5 pt 刻み。ズーム (UI-08) はこの大きさに掛ける。
4. 行間 `view.font.lineHeight`: 1.0〜2.0 倍、既定 1.2 倍。
5. テキスト列の代替フォント `view.font.fallback`: 既定は空 (Windows のフォントリンクに任せる)。表示できない文字の扱いは 00-overview.md 5.4 に従う。
6. 合字 (リガチャ) は常に無効にする。
7. Hex 表示の文字の大きさは、設定 `view.font.followTextScaling` (既定 `true`) のとき、Windows の「文字の大きさ」に合わせて拡大する。
8. 変更はプレビュー付きで即座に反映する。

**画面**: 設定画面に `ComboBox` (フォント名を各フォントで表示)、`NumberBox`、プレビュー。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 設定したフォントがない場合 (別の PC で設定をインポートした場合など) は既定のフォントで表示し、設定画面に「<フォント名> が見つかりません」と表示する。

**受け入れ基準**:

- [ ] フォントの一覧に既定では等幅フォントだけが表示される。
- [ ] Cascadia Mono がない環境で Consolas が使われる。
- [ ] Windows の文字の大きさを 150% にすると、UI と Hex 表示の文字が大きくなる (`followTextScaling` が `true` の場合)。

### UI-30 起動時の動作

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-20 |
| 呼び出し | ツール > 設定 > 全般 > 起動時。Shift キーを押しながら起動 (セーフモード) |

**概要**: 起動時に前回のセッションを復元するか、空の状態で始めるかを決める。セーフモードで起動したときの表示もここで定める。

**仕様**:

1. 設定 `session.restoreOnStartup`: `always` (既定、前回のセッションを復元)、`ask` (スタートページに「前回のセッションを復元」ボタンを出す)、`never`。
2. 起動時にファイルが指定された場合 (関連付け、コマンドライン) も、`always` ならセッションを復元したうえで指定されたファイルをアクティブなタブにする。
3. 異常終了後の起動では、復旧用データの提案 (01、00-overview.md 11.3) を先に出し、その後にセッションを復元する。復旧した文書のタブはセッションのタブと重複させない。
4. セーフモード (08 の AUTO-30 が主担当): 最初のウィンドウが表示されるまで Shift キーを押し続けて起動した場合、またはコマンドラインの `--safe-mode` (08 の AUTO-37) で起動した場合は、セーフモードで起動する。
   - Shift キーの判定は起動処理 (10 の PKG-11) で `GetAsyncKeyState(VK_SHIFT)` を使って行い、既存のインスタンスに転送する起動では判定しない。
   - セーフモードで何を読み込まないかは AUTO-30 に従う。セッションの復元 (仕様 1) と復旧用データの提案 (仕様 3) は通常どおり行う。
   - セーフモード中は、タイトルに「(セーフモード)」を付け (UI-02)、アプリ全体の InfoBar で「セーフモードで起動しました。プラグインと自動実行のスクリプトは読み込まれていません」と「通常どおり再起動」ボタンを表示する。

**画面**: 設定画面の `ComboBox`。

**巨大ファイル・長時間処理**: UI-31 のとおり。

**エラー**: UI-31 のとおり。

**受け入れ基準**:

- [ ] `never` にすると、再起動後にスタートページだけが表示される。
- [ ] `ask` にすると、スタートページに「前回のセッションを復元」が出て、押すとタブが戻る。
- [ ] Shift キーを押しながら起動すると、タイトルに「(セーフモード)」が付き、InfoBar が出て、プラグインが読み込まれない。

### UI-31 セッション復元

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-20 |
| 呼び出し | 自動 (終了時に保存、起動時に復元)。コマンドパレット「ウィンドウ: 前回のセッションを復元」 |

**概要**: 開いていたウィンドウ・タブ・カーソル位置・パネルの配置を、再起動後に元に戻す。

**仕様**:

1. 保存する内容:

   | 単位 | 内容 |
   | --- | --- |
   | ウィンドウ | 位置、大きさ、最大化・全画面、モニター、パネルの配置と大きさ、アクティブなタブ |
   | タブ | 種類 (ファイル / ディスク / 新規)、パス、並び順、ピン留め、読み取り専用、カーソル、選択範囲、スクロール位置、画面分割の状態、文書ごとの表示設定 |
   | アプリ | 閉じたタブの記録 (UI-12)、最後にアクティブだったウィンドウ |

2. 正常終了時と、30 秒ごと (変化があったときだけ) に `session.json` に保存する。
3. 未保存の変更は、終了時の確認 (UI-13) で保存するか破棄するので、セッションには含めない。未保存の変更をセッションに保持する機能 (ホットエグジット) は、復旧用データを使って実現する予定 (追加、フェーズ 2 提案。それまでは未対応)。
4. 新規作成 (名前のない) タブで内容が空のものは復元しない。内容があるものは仕様 3 により終了時に確認する。
5. プロセスメモリのタブは復元しない (プロセス ID が変わるため)。ディスクのタブは、管理者権限が必要な場合、補助プロセスの起動を確認してから開く (01)。権限の確認を取り消した場合はそのタブを「開けません」の状態で残し、タブ内に「開く」ボタンを出す。
6. ファイルは遅延して開く: アクティブなタブだけをすぐに開き、他のタブは初めて表示したときに開く。タブの見出しは保存された名前で即座に表示する。
7. ファイルのサイズや更新日時が前回と違う場合は、カーソル位置をファイルの長さの範囲に収めて開き、タブ内の InfoBar で「前回の終了後にファイルが変更されています」と表示する。

**画面**: なし。

**巨大ファイル・長時間処理**: 仕様 6 により、タブの数やファイルのサイズに関係なく起動の性能目標 (00-overview.md 11.1、2 秒) を守る。

**エラー**: ファイルが見つからないタブは、タブを残して内容に「ファイルが見つかりません: <パス>」と「閉じる」「場所を探す」ボタンを表示する。`session.json` が壊れている場合は空のセッションで起動し、壊れたファイルを `session.json.broken-<日時>` として残す。

**受け入れ基準**:

- [ ] 2 つのウィンドウ・合計 10 タブを開いて終了し、起動すると、同じ位置・同じタブ・同じカーソル位置で戻る。
- [ ] 100 GB のファイルを含む 20 タブのセッションでも、2 秒以内に操作可能になる。
- [ ] 削除したファイルのタブは「ファイルが見つかりません」と表示される。
- [ ] プロセスを強制終了した後の起動でも、30 秒以内の状態のセッションが復元される。

### UI-32 最近使ったファイル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-19 (UI 部分) |
| 呼び出し | ファイル > 最近使ったファイル。スタートページ (UI-38)。コマンドパレットの接頭辞なしのモード (UI-17)。ジャンプリスト (UI-35) |

**概要**: 最近開いたファイルを一覧にし、ピン留め・削除・消去ができる。この項目が画面と操作の主担当で、記録する情報・件数・保存先・前回の位置の復元は 01 の ENG-16 が定める (00-overview.md 1.1)。

**仕様**:

1. ファイルを開くたび、または閉じるたびに一覧の先頭に移す。記録する対象 (ファイル、ディスク・ボリューム、SFTP のファイルなど。プロセスメモリは記録しない) は ENG-16 に従う。ディスクの表示例: `PhysicalDrive1 (Samsung SSD 990, 2 TB)`。
2. 記録する件数 `recent.maxItems`: ENG-16 のとおり 0〜100、既定 25。0 は記録しない。ピン留めした項目は件数に数えない。
3. ファイル > 最近使ったファイル のサブメニューには、ピン留めした項目、その後に最近の 10 件を表示する。各項目はファイル名と短縮したパスを表示し、ツールチップに完全なパスを出す。サブメニューの末尾に「閉じたタブを開き直す」「一覧を消去」「すべて表示…」を置く。
4. 「すべて表示…」とスタートページでは、全件を検索欄付きの一覧で表示する。列はファイル名、フォルダ、サイズ、最後に開いた日時。行の右クリックで「ピン留め / ピン留めを外す」「一覧から削除」「パスをコピー」「エクスプローラーで表示」。
5. 「一覧を消去」はピン留めしていない項目だけを消す。消した直後の InfoBar に「元に戻す」を出す。
6. 見つからないファイルは薄く表示し、「見つかりません」と付記する。選ぶと「<パス> が見つかりません」と「一覧から削除」ボタンを表示する。存在の確認は一覧を表示した後にバックグラウンドで行う。ネットワークパスは確認せず (ENG-16)、通常の表示のままにする。
7. 前回の位置の復元 `recent.restorePosition` (既定 `true`): 開いたとき、前回のカーソル位置・スクロール位置・選択範囲を復元する。復元する内容と保存場所は ENG-16 と 00-overview.md 10 章の付随データに従う。
8. ポータブル版では、exe と同じドライブにあるファイルを exe からの相対パスで記録し、USB メモリのドライブ文字が変わっても開けるようにする。
9. 一覧は `recent.json` に保存する (ENG-16)。「一覧を消去」と設定 `recent.maxItems = 0` (ENG-16 の 7 のとおりピン留めした項目も消す) は、ジャンプリスト (UI-35) の最近使った項目も消す。

**画面**: `MenuFlyoutSubItem`、スタートページの一覧 (`ListView`)。

**巨大ファイル・長時間処理**: 仕様 6 のとおり、存在確認で UI を止めない。

**エラー**: 仕様 6 のとおり。

**受け入れ基準**:

- [ ] ピン留めしたファイルが、他のファイルを 30 個開いても一覧に残る。
- [ ] 「一覧を消去」でピン留めした項目が残り、「元に戻す」で全項目が戻る。
- [ ] 応答しないネットワークドライブのファイルがあっても、サブメニューがすぐに開く (500 ms 以下。判定はテスト方針 (../test/00-test-strategy.md) 7.3)。
- [ ] ポータブル版を USB メモリから別のドライブ文字で起動しても、同じ USB 内のファイルが開ける。
- [ ] `recent.maxItems` を 0 にすると、ジャンプリストの最近使った項目も消える。

### UI-34 ドラッグ & ドロップ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-08 (UI 部分) |
| 呼び出し | Explorer などからウィンドウへファイル・テキストをドロップ。選択範囲・タブ・パネルのドラッグ |

**概要**: ファイルなどをウィンドウにドロップしたときの動作を、ドロップ先ごとに定める。この項目がドロップ先ごとの動作の一覧の主担当で、ファイルを開く処理は 01 の ENG-12、選択範囲のドラッグとバイト列の挿入は 03 の EDIT-18 が定める (00-overview.md 1.1)。

**仕様**:

1. ドロップ先ごとの動作:

   | ドロップするもの | ドロップ先 | 動作 | 詳細 |
   | --- | --- | --- | --- |
   | ファイル (他のアプリから) | エディタ領域 (Hex ビュー)・スタートページ・空のウィンドウ | 新しいタブで開く (末尾に追加) | ENG-12 |
   | ファイル (他のアプリから) + Ctrl | Hex ビュー | ファイルの内容をドロップ位置に挿入する | EDIT-18 の 6、EDIT-30 |
   | ファイル (他のアプリから) | タブ列 | ドロップした位置にタブを挿入して開く。ドラッグ中は挿入位置を縦線で示す | ENG-12 |
   | `.hexworkspace` / `.hexproj` | どこでも | ワークスペース (UI-33) またはプロジェクト (00-overview.md 10 章) として開く | |
   | `.hexplugin` | どこでも | プラグインの追加 (08 の AUTO-32) | |
   | フォルダ | どこでも | 開かない (仕様 4) | |
   | テキスト (他のアプリから) | Hex ビュー | 形式を選択して貼り付け (EDIT-26) のダイアログをドロップ位置で開く | EDIT-18 の 6 |
   | 選択範囲 (同じ文書) | Hex ビュー | 移動 (Ctrl でコピー、上書きモードで Shift なら上書き) | EDIT-18 の 2、3 |
   | 選択範囲 (他のタブ) | 他のタブの Hex ビュー (タブ見出しの上で 500 ms 待つとそのタブに切り替わる) | 挿入 (コピー) | EDIT-18 の 4 |
   | 選択範囲 | 他のアプリ | EDIT-22 のコピーと同じ形式を渡す | EDIT-18 の 5 |
   | タブ | 別のウィンドウのタブ列・タブ列の外 | タブの移動・切り離し | UI-11 |
   | パネルの見出し | 左・右・下のパネル領域 | パネルの移動 | UI-05 |

2. 読み取り専用・固定長の文書の Hex ビューへの挿入のドロップは受け付けない (ポインタを禁止の形にする。EDIT-18)。ファイルを開くドロップは受け付ける。
3. 複数のファイルは一度にすべて開く。21 個以上の場合は「N 個のファイルを開きますか?」と確認する (ボタン「開く」「キャンセル」)。
4. フォルダは開かない。ファイルとフォルダを混ぜてドロップした場合はファイルだけを開く。InfoBar で「フォルダは開けません (N 個をスキップしました)。フォルダ内を検索するには複数ファイル検索を使ってください」と「複数ファイル検索」ボタンを表示する。
5. パスを持たない項目 (ZIP の中のファイル、ブラウザからの仮想ファイル) は、ENG-12 の 2 のとおり無題のドキュメントとして開く。
6. ドラッグ中はカーソルの横に動作を表示する (`DragUIOverride.Caption`。「開く」「挿入」「移動」「コピー」「上書き」)。
7. 管理者として実行中は、Windows の制限 (UIPI。権限の低いプロセスから高いプロセスへのドロップを Windows が拒否する) で Explorer からドロップできない。

### UI-36 通知 (InfoBar)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 0 提案) |
| 呼び出し | 各機能から表示。ステータスバーの通知アイコン (UI-06) で履歴を表示 |

**概要**: 編集を妨げない通知を InfoBar で表示する。00-overview.md 9 章「通知」の詳細。

**仕様**:

1. 通知には範囲がある: 「文書」(タブ内のエディタ上部に表示し、そのタブがアクティブなときだけ見える)、「ウィンドウ」(作業領域の上部)、「アプリ」(全ウィンドウ)。
2. 重要度は WinUI の `InfoBarSeverity` の `Informational`、`Success`、`Warning`、`Error` の 4 種類。アイコンと色で区別し、ハイコントラストでもアイコンで区別できる。使い分けは次のとおり。

   | 重要度 | 使う場面 | 例 |
   | --- | --- | --- |
   | `Informational` | 状態の説明・操作の案内。失敗ではなく、利用者の対応は不要 | 管理者として実行中のドロップの制限 (UI-34 の 7)、新しい版がある (10 の PKG-22) |
   | `Success` | 利用者が始めた操作 (長時間処理を含む) が完了した | 更新した (「版 X に更新しました」。10 の PKG-22)、「一覧を消去」の完了 (UI-32 の 5) |
   | `Warning` | 操作は行ったが、一部をスキップした・結果に注意が必要 | フォルダのドロップをスキップした (UI-34 の 4)、新しすぎる設定ファイルのため書き込みを止めた (UI-23 の 6) |
   | `Error` | 操作が失敗し、目的の結果が得られなかった | ファイルを開けない、保存に失敗した、使えないコマンドを実行した (UI-16) |

3. 同時に表示するのは範囲ごとに最大 3 件。それ以上は「他に N 件」とまとめ、押すと履歴を開く。同じ内容の通知は 1 件にまとめ、回数を付ける。
4. `Informational` と `Success` は 8 秒後に自動で閉じる (マウスが乗っている間とキーボードフォーカスがある間は閉じない)。`Warning` と `Error` は自動で閉じない。
5. 取り消せる操作の通知には「元に戻す」ボタンを付ける。他の操作ボタンは最大 2 つ。
6. 通知の表示はスクリーンリーダーに読み上げさせる (UI-51)。
7. ステータスバーの通知アイコンから、直近 100 件の履歴 (時刻、内容、範囲) を表示する。履歴はアプリの終了で消える。
8. アプリがアクティブでないときに 10 秒以上かかった長時間処理が終わった場合は、Windows のトースト通知 (`AppNotificationManager`) も出す。設定 `notifications.toast` (既定 `true`、ポータブル版は既定 `false`。10 の PKG-06 を参照)。

**画面**: `InfoBar`。履歴は `Flyout` 内の `ListView`。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 同じ警告 (`Warning`) を 5 回出すと 1 件にまとまり、「×5」と表示される。
- [ ] `Error` の通知は自動で閉じない。
- [ ] ナレーターで、通知の表示時に内容が読み上げられる。
- [ ] 別のアプリを使っている間に 1 分かかる検索が終わると、トースト通知が出る。

### UI-37 処理センター

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-13 (UI 部分) |
| 呼び出し | ステータスバーの進捗表示 (UI-06) のクリック。コマンドパレット「表示: 処理センター」 |

**概要**: 実行中・完了した長時間処理の一覧を表示し、進捗の確認とキャンセルを行う。00-overview.md 9 章「処理センター」の詳細。

**仕様**:

1. ステータスバーには、実行中の処理の件数と、全体の進捗 (各処理の残りバイト数の合計で計算) を細い進捗バーで表示する。進捗を計算できない処理だけのときは不確定の進捗表示にする。
2. 処理センターは、ステータスバーから上に開く `Flyout` (幅 420 px) で、実行中の処理と、直近に完了した処理 (最大 20 件) を表示する。
3. 各処理の表示: 処理名 (例: 「検索: DE AD BE EF」)、対象の文書名、進捗率、処理速度 (例: `1.2 GB/s`)、残り時間 (例: 「残り約 2 分」)、経過時間、キャンセルボタン。
4. 処理速度と残り時間の計算は 01 の ENG-09 の仕様 3 に従う (処理速度は直近 10 秒の移動平均、残り時間は開始から 3 秒たってから表示する)。
5. 完了した処理には結果 (成功 / キャンセル / 失敗とその理由) と「結果を表示」ボタン (結果一覧を開く、該当箇所へ移動など) を表示する。「完了した項目を消去」ボタンを置く。
6. キャンセルは 500 ms 以内に処理を止める (00-overview.md 3 章の「長時間処理」の要件。各機能で守る)。キャンセルできない段階 (保存の最後の置き換えなど) ではボタンを無効にし、理由をツールチップに出す。
7. 処理の開始から 0.5 秒以内に終わったものは一覧に出さない。
8. 処理が文書内に結果を出す場合 (検索の進捗など) は、そのタブの見出しにも進捗リング (UI-09) を出す。

**画面**: ステータスバーの進捗表示、`Flyout` 内の `ListView`。

**巨大ファイル・長時間処理**: 処理センター自体の更新は 1 秒に 4 回まで。処理の数に関係なく UI を止めない。

**エラー**: 失敗した処理は一覧に赤のアイコンと理由を表示し、通知 (UI-36) も出す。

**受け入れ基準**:

- [ ] 10 GB のファイルのハッシュ計算中に、処理センターに速度と残り時間が表示される。
- [ ] キャンセルボタンで 500 ms 以内に処理が止まり、「キャンセル」と表示される。
- [ ] 2 つの処理を同時に実行すると、両方が一覧に出て、ステータスバーの件数が 2 になる。
- [ ] 0.3 秒で終わる検索は一覧に出ない。

**仕様**:

2. 次の要素は `FlowDirection="LeftToRight"` に固定する: Hex 表示 (オフセット・Hex 列・テキスト列)、コードエディタ (テンプレート・スクリプト)、オフセット・数値・Hex バイト列の入力欄、ファイルパスの表示、ショートカットの表記。

5. Hex 表示のテキスト列でアラビア文字などを表示するときも、1 バイトまたは 1 文字ごとのセルに置き、双方向テキストの並べ替えを行わない。

### UI-45 地域設定に従う書式

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-17 |
| 呼び出し | 自動 |

**概要**: UI に表示する 10 進数・日付・ファイルサイズを Windows の地域設定で書式化し、入力の解釈は地域設定に依存させない (00-overview.md 5.4)。

**仕様**:

1. UI 上の 10 進数 (件数、バイト数、10 進のオフセット)、日付・時刻、ファイルサイズは、Windows の地域設定 (`CultureInfo.CurrentCulture`) で書式化する。表示言語とは独立させる。
2. ファイルサイズの単位は 1024 の累乗で、`KB`、`MB`、`GB`、`TB` と書く。小数点以下は 2 桁 (1 KB 未満はバイト数)。バイト数に付ける語 (英語の `Bytes`) は表示言語のリソースで翻訳し (例: 日本語は「バイト」)、数値の書式 (桁区切り・小数点) は仕様 1 のとおり地域設定に従う。
3. Hex 表示内の値 (16 進・2 進・8 進) と、データインスペクタの数値の表示は、地域設定に依存しない (桁区切りなし、小数点は `.`)。インスペクタの書式は 05 に従う。
4. 入力欄の解釈は常に 00-overview.md 6 章に従い、地域設定に依存させない (`CultureInfo.InvariantCulture`)。
5. 大文字・小文字を区別しない比較は序数比較 (`StringComparison.OrdinalIgnoreCase`) で行う。並べ替えの表示 (コマンドパレットの五十音順など) だけ表示言語の照合順序を使う。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] 地域設定がドイツのとき、ステータスバーのサイズが `1.610.612.736 Bytes` の形 (桁区切りが `.`) で表示される。`Bytes` の語は表示言語に従う (この例は英語表示。仕様 2)。

### UI-49 機械翻訳と翻訳の確認

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-26 |
| 呼び出し | CI (`main` ブランチへの push 時、毎晩) |

**概要**: 未翻訳の文字列を CI で機械翻訳し、本プロジェクトが確認する流れを自動化する。翻訳の修正は GitHub の Issue と Pull Request で誰からでも受け付ける (00-overview.md 5.3)。

**仕様**:

1. 訳文の状態は、リポジトリ内の状態ファイル `docs/i18n/translation-status.json` で管理する。言語と文字列のキーごとに、状態 (「機械翻訳」/「確認済み」/「要再確認」) と、訳したときの英語の原文のハッシュを持つ。状態ファイルにない文字列は未翻訳とする。
2. 流れ:

   1. 開発者が `en` と `ja` の `.resw` を変更して `main` に入れる。`ja` は開発者が書くため「確認済み」とする。
   2. CI が残り 21 言語の未翻訳の文字列を、用語集 (UI-48) を渡して機械翻訳し、各言語の `.resw` に書き込む。状態ファイルでその文字列を「機械翻訳」にする。機械翻訳の提供元は未決定 (DeepL API または Azure AI Translator)。API キーは GitHub の Secrets に置く。
   3. CI は、手順 2 の変更を 1 つの Pull Request にまとめて作る (毎晩、変更がある場合だけ)。
   4. 本プロジェクトが訳を確認し、必要なら直して、状態ファイルでその文字列を「確認済み」にする。確認は Pull Request で行う。

3. 「確認済み」の訳は機械翻訳で上書きしない。原文が変わった場合 (状態ファイルの原文のハッシュと一致しない場合) は、確認済みの訳を残したまま「要再確認」の状態にする。要再確認の訳はそのまま表示に使い、機械翻訳で上書きしない。「機械翻訳」の訳は、原文が変わったときに機械翻訳し直す。
4. 言語ごとに、翻訳済みの割合と「確認済み」の割合を集計し、リリースノート (10 の PKG-29) と表示言語の一覧 (UI-43) に使う。割合はビルド時に `translation-coverage.json` としてアプリに同梱する。
5. 翻訳の修正の受け付け: 誰でも GitHub で翻訳の修正を提案できる。
   - Issue: 翻訳の報告用の Issue フォーム (UI-41 の仕様 2) で報告する。
   - Pull Request: 該当する言語の `.resw` を直接直して送る。手順 (ファイルの場所、キーの探し方、用語集の参照) を `CONTRIBUTING.md` に書く。
   - 本プロジェクトが確認して取り込んだ訳は、状態ファイルで「確認済み」にする。Pull Request の CI で、リソースの検査 (UI-42) と用語集の検査 (UI-48 の仕様 5) を行う。
6. 機械翻訳は CI でだけ行う。アプリは翻訳のためにネットワークに接続しない。

**画面**: なし。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 機械翻訳の API が失敗した場合は CI を警告にし、その文字列は未翻訳 (英語表示) のまま次回に再試行する。状態ファイルの形式が不正な場合、または状態ファイルと `.resw` のキーが合わない場合は、CI を失敗にする。

**受け入れ基準**:

- [ ] `en` に文字列を追加して `main` に入れると、翌日までに 21 言語の機械翻訳を含む PR が作られ、状態ファイルでその文字列が「機械翻訳」になっている。
- [ ] 「確認済み」の訳がある文字列の原文を変えても、訳が機械翻訳で置き換わらず、「要再確認」になる。
- [ ] `translation-coverage.json` に 23 言語の割合が入っている。

6. ステータスバー・パネル・設定画面などの標準コントロールにも、`AutomationProperties.Name` を全要素に付ける (アイコンだけのボタンを含む)。CI の UI テストで、名前のない操作可能な要素がないことを確認する。

### UI-51 スクリーンリーダーでの読み上げ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | 自動 (カーソル移動時)。コマンドパレット「アクセシビリティ: 現在位置を読み上げ」(既定なし) |

**概要**: カーソル位置のオフセット・バイト値・文字を、ナレーターと NVDA で読み上げる (00-overview.md 11.5)。この項目と UI-50 が Hex ビューの UI オートメーションと読み上げの主担当で、表示面 (色に頼らない表示、フォーカスの枠、読み上げに使う状態の受け渡し) は 02 の VIEW-41 が定める (00-overview.md 1.1)。

1. カーソルが動いたとき、`AutomationPeer.RaiseNotificationEvent` (`NotificationProcessing.MostRecent`) で読み上げ文を送る。読み上げ文には、VIEW-41 の 5 で Hex ビューから渡される状態を付ける: 操作中の列 (Hex 列 / テキスト列)、下位ニブル (「下位」)、「変更あり」「挿入」、「選択中」、「読み込み中」「読み取れません」、そのバイトを含むブックマークの名前 (「ブックマーク 名前」)。該当しない状態は読まない。

   | 値 | 読み上げ文の例 |
   | --- | --- |
   | `full` (既定) | 「オフセット 0x1F00、値 4A、文字 J、Hex 列、変更あり、ブックマーク header」 (状態は仕様 1) |
   | `brief` | 「4A J」 |

4. 選択範囲が変わったときは「選択 16 バイト、0x1F00 から 0x1F0F」と読み上げる。
5. 上書き / 挿入の切り替え、Hex 列 / テキスト列の切り替え、読み取り専用の切り替え、長時間処理の完了、通知 (UI-36) の表示を読み上げる。
6. 「現在位置を読み上げ」は `full` の形で、現在の選択範囲とファイルサイズも読み上げる。
7. 表示できない文字は「表示できない文字」と読み上げる。`00` は「ヌル」と読み上げる (言語ごとのリソース)。

**エラー**: 該当なし。

### UI-57 テレメトリを送らない方針

### UI-58 ネットワークを使う機能の管理

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | ツール > 設定 > プライバシー |

**概要**: インターネットに接続する機能を一覧にし、個別に、またはまとめて無効にできるようにする (00-overview.md 11.4)。

**仕様**:

1. アプリが自分から行う通信は、00-overview.md 11.4 のとおり次のものだけ。

   | 機能 | 接続先 | 設定 | 既定 |
   | --- | --- | --- | --- |
   | 更新の確認とダウンロード | GitHub Releases (インストーラ版・ポータブル版)、Microsoft Store (MSIX 版) | `update.checkAutomatically` (10 の PKG-17) | 有効 |
   | テンプレート・プラグインなどのダウンロード (オンラインリポジトリ) | テンプレートのリポジトリ (07 の TPL-36)、プラグインの配布先 (08 の AUTO-32。提供は未決定) | `network.downloads.enabled` | 有効 (利用者が操作したときだけ接続) |
   | 追加コンポーネントのダウンロード | C# スクリプト用のコンパイラ (08 の AUTO-03)。更新と同じ配布元 (10 の PKG-17〜PKG-21) | `network.downloads.enabled` | 有効 (利用者が操作したとき、または追加済みのコンポーネントをアプリの更新に合わせて更新するときだけ接続) |
   | 翻訳の誤り報告・ドキュメントのページを開く | GitHub の Issue の作成画面 (翻訳の報告。UI-41)、ドキュメントのサイト・GitHub の Issue (UI-40) | `network.translationReport.enabled` (翻訳の誤り報告) | 有効 (既定のブラウザで開くだけで、アプリは接続しない) |

2. 利用者が接続先を指定する機能 (リモートのデータソース 01 の ENG-40〜ENG-42、スクリプトの通信 08 の AUTO-18) は、利用者の操作または許可があったときだけ通信する (00-overview.md 11.4)。アプリが自分から行う通信ではないため、仕様 1 の一覧と `network.offline` の対象外とし、設定画面「プライバシー」には説明として一覧だけ示す。
3. 設定 `network.offline` (既定 `false`): `true` にすると仕様 1 の更新・ダウンロードをすべて無効にする。メニューの該当項目は無効表示にし、理由「オフラインモードが有効です」を表示する。ブラウザでページを開く項目は無効にせず、開く前に URL を表示して、開くかどうかを利用者に選ばせる (UI-41 の 6)。署名の失効の確認もネットワークに接続しない (08 の AUTO-35)。
4. 接続にはシステムのプロキシ設定を使う。
5. 初回起動時に、仕様 1 の一覧と設定場所を 1 行で示す (UI-38)。
6. テレメトリは送らない (UI-57)。仕様 1 の通信でも、開いたファイルの内容・名前・パスは送らない。

**画面**: 設定画面「プライバシー」に一覧と各スイッチ、`network.offline` のスイッチ。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし (各機能の接続エラーは各機能で定める)。

**受け入れ基準**:

- [ ] `network.offline` を有効にすると、ヘルプ > 更新の確認 が無効表示になる。
- [ ] `network.offline` を有効にして 1 時間操作しても (仕様 2 の機能を使わない場合。操作の内容はテストケース TC-UI-58-02 の台本で、TC-UI-57-01 の台本に更新の確認とドキュメントを開く操作を加えたもの)、外部への通信がない。
- [ ] `network.offline` を有効にすると、C# スクリプト コンポーネントの追加でダウンロードせず、手動で入れる手順が案内される。

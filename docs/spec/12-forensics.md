# 機能仕様書: フォレンジック機能

この文書はフォレンジック (証拠保全・ディスク解析) 機能の振る舞いを定める。共通の書式・用語・入力式・ショートカット・UI 部品は [00-overview.md](00-overview.md) に従う。

- 対象とするロードマップの ID: F5-01 (パーティション解析)、F5-02 (ファイルシステム解析)、F5-03 (ディスクイメージ)、F5-04 (失われたパーティションのスキャン)、F5-05 (ファイルの切り出し)、F5-06 (安全な消去)、F5-07 (ディスクのクローン)、F5-08 (書き込み保護)。
- 調査 ([../research/feature-survey.md](../research/feature-survey.md) の 2.1、2.3、2.16) に挙がっているがロードマップにない機能は「追加 (フェーズ 5 提案)」として書く。
- **この領域の優先度は全体で最も低い (フェーズ 5)。** フェーズ 0〜4 の機能を削ってまでここに手を付けない。
- すべての機能は [../roadmap.md](../roadmap.md) の「使いやすさの原則」に従う。特に、長時間処理はすべて処理センター (00 の 9 章) で進捗・残り時間・キャンセルを出す。

## 共通の前提

ここに書く規則は、この文書のすべての機能に適用する。各機能の記述ではくり返さない。

### ディスクへのアクセス

1. 物理ディスク・論理ボリュームの読み書き、ボリュームのロック・ディスマウント、読み取り専用のデバイス情報の取得 (FOR-27、FOR-28)、OS の USB ストレージ書き込み保護の切り替え (FOR-02) は、昇格した補助プロセス (ENG-28) を通して行う。補助プロセスが受け付ける操作は 00 の 11.4 に挙げたものだけで、この文書の機能もその範囲に収める。アプリが自分から UI プロセスを昇格させることはしない (利用者がアプリ全体を管理者として実行した場合は仕様 4)。ディスク・ボリュームを開く処理は ENG-29、書き込みは ENG-30 に従う。
2. ディスクの読み書きは、データソースのセクタサイズ (論理セクタサイズ。512 または 4096 など) の境界にそろえる。この文書の処理が要求する範囲がセクタ境界にそろっていない場合は、補助プロセスへの要求をセクタ境界まで広げ、結果から必要な部分を切り出す。書き込みでは、範囲の端のセクタを読み込んで合成してから書く (読み込み → 合成 → 書き込み)。
3. マウントされているボリュームを含むディスクに書き込む前に、ENG-30 の仕様 2・3 の「ボリュームのロック」(`FSCTL_LOCK_VOLUME`、失敗時はディスマウントの確認) を、書き込み範囲に重なるすべてのボリュームに対して行う。ロックできなければ書き込まない。
4. アプリ全体を管理者として実行している場合 (どの配布形態でも) は、仕様 1 の操作を補助プロセスを使わずに同じプロセスで行う (ENG-28 の仕様 10)。取り外し可能な USB ストレージのボリュームは、管理者権限なしで UI のプロセスから直接開ける (ENG-29 の仕様 3 の 1)。
5. MSIX 版 (Microsoft Store 版) は補助プロセスを同梱しないため、管理者権限が必要なディスクの機能は、利用者がアプリ全体を管理者として実行したときだけ使える。管理者として実行していないときも、ディスクを対象とする機能はメニューで有効のままにし、選ぶと管理者権限の案内ダイアログ (ENG-28 の仕様 12) を出す (インストーラ版とポータブル版では補助プロセスで使える。[10-packaging.md](10-packaging.md) の PKG-04、ENG-28 の仕様 11)。イメージファイルを対象とする機能は管理者権限なしで使える。

### 破壊的な操作の確認

1. ディスク・ボリューム・イメージ・ファイルへ書き込む操作 (消去、クローン、復元、墨塗り、パーティションの書き込み) は、00 の 9 章の確認ダイアログを必ず出す。ダイアログには、対象 (ディスク番号、モデル名、シリアル番号、容量、含まれるボリュームのドライブ文字とラベル)、書き込む範囲 (開始 LBA・セクタ数・バイト数)、書き込む内容、取り消せないこと、を書く。
2. ディスク全体またはパーティション全体に書き込む操作では「強い確認」を使う。強い確認は、確認ダイアログに入力欄を追加し、対象の表示名 (例: `ディスク 2`) を利用者が入力するまで実行ボタンを無効にするもの。既定のフォーカスは「キャンセル」に置き、Enter キーだけでは実行されないようにする。
3. 実行ボタンの文言は動作を表す (「ディスク 2 を消去する」「ディスク 3 へクローンする」など)。
4. 書き込み保護モード (FOR-01) が有効なときは、これらの操作はダイアログを出す前に拒否する。
5. 実行した破壊的な操作は、成功・失敗・キャンセルにかかわらず監査ログ (FOR-04) に記録する。

### 出力先の検査

1. イメージ・切り出したファイル・レポートなどの出力先は、調査対象のディスク (証拠一覧 FOR-03 に登録されたもの、および処理の入力元) 上のボリュームであってはならない。出力先のボリュームが入力元と同じ物理ディスク上にある場合は実行しない。
2. 出力先の空き容量を事前に確認し、不足する場合は実行前に必要量と空き容量を示して止める。
3. 出力先のファイルシステムが 1 ファイルの上限 (FAT32 の 4 GiB - 1 など) を持つ場合、上限を超える出力には分割を求める。

### 日時

日時は FOR-05 の規則に従う。この文書で「日時」と書いたものは、内部では UTC で持ち、表示では UTC とローカル時刻の両方を示す。

## 書き込み保護と証拠管理

### FOR-01 書き込み保護モード

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-08 |
| 呼び出し | メニュー: フォレンジック → 書き込み保護モード (チェック付き項目)。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: 書き込み保護モードの切り替え」。ステータスバーの書き込み保護の表示をクリック。コマンドライン: `--write-block` (起動時に有効にする。オプションの定義は AUTO-37) |

**概要**: 調査対象への書き込みをアプリ全体で禁止するモード。有効な間は、どのドキュメントもデータソースへ書き込めず、ディスクへ書き込む機能はすべて拒否される。

**仕様**:

1. モードはアプリ全体で 1 つ。既定は無効。設定で「起動時に常に有効にする」を選べる (既定はオフ)。モードの状態は再起動後も保持する。
2. 有効にすると次のようになる。
   - 新しく開くファイル・ディスク・ボリューム・イメージは、データソースを読み取り専用のアクセス権 (`GENERIC_READ` のみ) で開く。
   - すべてのドキュメントを読み取り専用 (EDIT-16) にし、利用者は解除できない (EDIT-16 の仕様 4、ENG-14)。例外は仕様 5 のドキュメント単位の例外だけ。データを変える操作 (入力、削除、貼り付け、塗りつぶし、データ演算など) は EDIT-16 のとおり無効になる。
   - すでに開いているドキュメントは、データソースを読み取り専用で開き直す。未保存の編集があるドキュメントは編集内容を保持するが (EDIT-16 の仕様 5)、「保存」は無効になり、「名前を付けて保存」で証拠以外の場所 (共通の前提「出力先の検査」) に保存することだけができる。
   - UI のプロセスは、モードの状態を補助プロセス (ENG-28) に `SetWriteBlock` コマンドで通知する (補助プロセスの起動・再接続の直後と、モードを切り替えたとき)。補助プロセスは、書き込み保護モードが有効な間、書き込み・ロック・ディスマウント・デバイスへの書き込みを伴う制御コマンドの要求をすべて拒否する (読み取りと、読み取り専用のデバイス情報の取得、OS の USB 書き込み保護 (FOR-02) の切り替えは受け付ける)。UI 側の表示だけに頼らず、補助プロセス側でも拒否する (UI 側の不具合で書き込みが通らないようにするため)。
   - 消去 (FOR-30〜32)、クローン (FOR-24)、セクタ範囲の復元 (FOR-25)、パーティションの書き込み (FOR-08)、ファイルの安全な削除 (TOOL-17)、代替データストリームの作成・削除 (TOOL-21) のメニュー項目は無効表示になり、ツールチップに「書き込み保護モードが有効です」と表示する。
3. 状態の表示:
   - ステータスバーの左端に「書き込み保護」の表示を出す。錠のアイコンと文字の両方で示し、色だけに頼らない (00 の 11.5)。
   - ウィンドウのタイトルに「[書き込み保護]」を付ける。
   - 各タブのヘッダに錠のアイコンを付ける。
4. 無効にする操作には確認ダイアログを出す。ダイアログには、現在開いている証拠のドキュメントの数と名前を表示し、ボタンは「書き込み保護を解除する」と「キャンセル」にする。解除した日時と操作者 (Windows のユーザー名) を監査ログに記録する。
5. ドキュメント単位の例外: 書き込み保護モードのまま、特定のドキュメント 1 つだけ書き込みを許可できる (例: 調査用のメモファイル)。タブの右クリックメニュー「このドキュメントへの書き込みを許可」から行い、強い確認 (共通の前提) を出す。証拠一覧 (FOR-03) に登録されているデータソースには例外を設定できない (メニューを無効表示にする)。例外はそのドキュメントを閉じるまで有効で、タブの錠のアイコンを「開いた錠」に変える。例外の設定と解除は監査ログに記録する。
6. アプリ自身が書き込むもの (設定、付随データ、復旧用データ、一時ファイル、監査ログ、イメージ・レポートの出力) は制限しない。ただし出力先は共通の前提「出力先の検査」に従う。
7. 書き込み保護モードは、このアプリからの書き込みだけを防ぐ。OS や他のアプリによる書き込み (ボリュームのマウント時にファイルシステムが行う書き込みなど) は防げない。モードを初めて有効にしたとき、このことを InfoBar で一度だけ知らせ、ハードウェアの書き込み防止装置または FOR-02 の併用を勧める。

**画面**: ステータスバーの表示、タイトルバー、タブの錠のアイコン、フォレンジックメニューのチェック付き項目、解除の確認ダイアログ。

**巨大ファイル・長時間処理**: 該当なし (開き直しはデータソースのハンドルを取り直すだけで、データを読み直さない)。

**エラー**:

- 開いているドキュメントを読み取り専用で開き直せない場合 (ファイルが削除されたなど): そのタブに InfoBar で「読み取り専用で開き直せませんでした」と表示し、タブのデータソースへのアクセスを止める (表示はキャッシュにある範囲だけ)。
- 補助プロセスが書き込み要求を拒否した場合: 要求元の機能のエラーとして「書き込み保護モードのため書き込めません」を表示する。

**受け入れ基準**:

- [ ] モードを有効にすると、ステータスバー・タイトル・タブに表示が出る。ハイコントラストテーマでも判読できる。
- [ ] モードが有効な状態で、開いているファイルのタブが読み取り専用になり、「編集を許可する」ボタンが出ない。
- [ ] モードを有効にする前に編集していたファイルで Ctrl+S を押しても保存されず、元のファイルの内容・更新日時が変わらない。編集内容は残り、「名前を付けて保存」で別の場所に保存できる。
- [ ] モードが有効な状態 (補助プロセスに `SetWriteBlock` (ENG-28 の仕様 4) で有効を通知した状態) で、補助プロセスに直接書き込み要求を送るテストを行うと、拒否の応答が返り、ディスクの内容が変わらない。
- [ ] 消去・クローン・復元のメニュー項目が無効表示になり、理由がツールチップに出る。
- [ ] モードの解除には確認ダイアログが出て、「キャンセル」を選ぶとモードが有効なまま残る。
- [ ] 証拠一覧に登録したディスクのタブでは「このドキュメントへの書き込みを許可」が無効表示になる。
- [ ] 解除・例外の設定が監査ログに日時付きで記録される。
- [ ] `--write-block` を付けて起動すると、最初のドキュメントが開く前にモードが有効になっている。

### FOR-02 OS の USB ストレージ書き込み保護

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | メニュー: フォレンジック → OS の USB 書き込み保護。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: OS の USB 書き込み保護の切り替え」 |

**概要**: Windows の設定 (`StorageDevicePolicies` の `WriteProtect`) を切り替えて、これから接続する USB ストレージへの書き込みを OS 全体で禁止する。FOR-01 では防げない OS や他のアプリからの書き込みを減らす補助手段。

**仕様**:

1. 有効にすると、レジストリ `HKLM\SYSTEM\CurrentControlSet\Control\StorageDevicePolicies` の `WriteProtect` (DWORD) を `1` にする。無効にすると `0` にする。値がもともと存在しなかった場合は、無効にするときに値を削除して元の状態に戻す。
2. 変更は補助プロセス (ENG-28 の `SetUsbWriteProtect`) で行う (管理者権限が必要。アプリを管理者として実行している場合は同じプロセスで行う)。補助プロセスがこの操作を受け付けることは 00 の 11.4 で定めている。
3. 設定は、変更後に接続した USB ストレージにだけ効く。すでに接続されているデバイスには効かないことをダイアログで明示し、「設定を変更する」「キャンセル」のボタンを出す。
4. アプリの終了時に有効のままであれば、「OS の USB 書き込み保護が有効のままです」と通知し、「無効にして終了」「有効のまま終了」を選ばせる。
5. 変更は監査ログに記録する。
6. この機能は USB 接続のストレージだけを対象とし、SATA・NVMe の内蔵ディスクは保護しないことを画面に明示する。

**画面**: 確認ダイアログ。フォレンジックメニューのチェック付き項目 (現在のレジストリの値を反映する)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**:

- 昇格を拒否された場合: 「管理者権限が必要です」と表示し、設定を変えない。補助プロセスも管理者権限も使えない場合 (管理者として実行していない Store 版など) は、ENG-28 の仕様 12 の案内ダイアログを出し、設定を変えない。
- グループポリシーなどで値が管理されていて書き換えられない場合: 書き込み失敗の理由を表示する。

**受け入れ基準**:

- [ ] 有効にした後に接続した USB メモリに、エクスプローラーからファイルをコピーできない。
- [ ] 無効にすると、レジストリの値が変更前の状態 (値なしを含む) に戻る。
- [ ] 有効のまま終了しようとすると、終了前に選択を求められる。

### FOR-03 ケースと証拠一覧

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | メニュー: フォレンジック → ケース → 新しいケース / ケースを開く / ケースを閉じる / 証拠を追加。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: 新しいケース」「フォレンジック: ケースを開く」「フォレンジック: 証拠を追加」。証拠パネルの右クリックメニュー |

**概要**: 1 つの調査案件 (ケース) ごとに、調査対象 (証拠) の一覧、取得時のハッシュ、監査ログ、作成したイメージ・切り出したファイル・レポートをまとめて管理する。必要最小限の管理機能にとどめる。

**仕様**:

1. ケースは 1 つのフォルダで表す。フォルダの中に `case.json` (ケース情報と証拠一覧)、`audit.log` (FOR-04)、`exports/` (切り出したファイル・書き出したファイル)、`reports/` (レポート) を作る。イメージの保存先は任意 (既定は `images/`)。
2. ケース情報: ケース番号、ケース名、調査者名、組織名、説明、作成日時、タイムゾーン (FAT などのタイムゾーンを持たない日時を解釈するための既定値。FOR-05)。ケース番号とケース名は必須。
3. 同時に開けるケースは 1 つ。ケースを開いている間、ウィンドウのタイトルとステータスバーにケース名を表示する。
4. ケースを開くと、書き込み保護モード (FOR-01) が無効であれば「書き込み保護モードを有効にしますか」と InfoBar で提案する (ボタン「有効にする」)。設定で「ケースを開いたら自動で有効にする」を選べる (既定はオン)。
5. 証拠の登録: 開いているドキュメント (ディスク、ボリューム、イメージ、ファイル) を「証拠を追加」で登録する。登録項目は次のとおり。
   - 証拠番号 (ケース内で一意、既定は `E001` からの連番)、説明
   - データソースの種類とパス (例: `\\.\PhysicalDrive2`、イメージファイルのパス)
   - ディスクの場合はモデル名、シリアル番号、容量 (バイト数とセクタ数)、セクタサイズ
   - 取得時のハッシュ (アルゴリズム名と値。FOR-20 でイメージを作った場合はそのとき計算した値。手動登録の場合は「証拠を追加」時に計算するかを選ぶ。既定は SHA-256 と MD5 を計算する)
   - 登録日時、登録者
6. 証拠パネル: 証拠一覧を結果一覧 (00 の 9 章) で表示する。列は証拠番号、説明、種類、パス、容量、ハッシュ、検証結果 (FOR-22)、登録日時。行のダブルクリックでその証拠を開く (書き込み保護モードで開く)。
7. 証拠の削除は一覧から外すだけで、データソース自体には何もしない。外した操作は監査ログに記録し、`case.json` からは消さずに「除外」の印を付けて残す。
8. `case.json` は UTF-8 の JSON で保存し、変更のたびに保存する。保存は一時ファイルに書いてから置き換える。

**画面**: 証拠パネル (既定は左)。新しいケースのダイアログ (入力欄はケース番号、ケース名、調査者名、組織名、説明、フォルダ、タイムゾーン)。証拠を追加のダイアログ (証拠番号、説明、ハッシュを計算するか、アルゴリズムの選択)。

**巨大ファイル・長時間処理**: 登録時のハッシュ計算は長時間処理。処理センターに出し、キャンセルした場合は証拠を登録したまま「ハッシュ未計算」とする。

**エラー**:

- ケースフォルダに書き込めない: ケースを作らず、理由を表示する。
- `case.json` が壊れている: 「ケースファイルを読み込めません」と行番号付きで表示し、ケースを開かない。ファイルは変更しない。
- 既に登録されているデータソースを再登録しようとした: 既存の証拠番号を示して止める。

**受け入れ基準**:

- [ ] 新しいケースを作ると、指定したフォルダに `case.json`、`audit.log`、`exports/`、`reports/` ができる。
- [ ] ディスクを証拠に追加すると、モデル名・シリアル番号・容量・ハッシュが一覧に表示される。
- [ ] ケースを閉じて開き直すと、証拠一覧が同じ内容で復元される。
- [ ] 証拠を一覧から外すと、`case.json` に「除外」として残り、監査ログに記録される。

### FOR-04 監査ログ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | メニュー: フォレンジック → ケース → 監査ログを表示。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: 監査ログを表示」「フォレンジック: 監査ログを検証」 |

**概要**: ケースを開いている間の操作を、日時付きで追記専用のログに記録する。改ざんを検出できるよう、各行に前の行のハッシュを含める。

**仕様**:

1. 記録先はケースフォルダの `audit.log`。形式は JSON Lines (1 行 1 件、UTF-8)。
2. 各行の項目: 連番、日時 (UTC、ISO 8601、100 ナノ秒単位まで。例: `2026-10-07T03:15:42.1234567Z`)、操作者 (Windows のユーザー名)、コンピューター名、アプリのバージョン、操作の種類、対象 (証拠番号とデータソースのパス)、パラメーター、結果 (成功 / 失敗 / キャンセル)、メッセージ、前の行の SHA-256、この行の SHA-256 (この項目自身を除いた内容のハッシュ)。
3. 記録する操作: ケースの作成・オープン・クローズ、証拠の追加・除外、ドキュメントを開く・閉じる、書き込み保護モードの切り替えと例外 (FOR-01)、OS の USB 書き込み保護 (FOR-02)、ハッシュ計算とその結果、イメージ作成・検証 (FOR-20、FOR-22)、ファイルの書き出し、カービング (FOR-19)、すべての書き込み操作 (保存、消去、クローン、復元、墨塗り)、レポート作成、設定の変更のうちフォレンジックに関わるもの。
4. カーソル移動・スクロール・検索などの閲覧操作は既定では記録しない。設定「閲覧操作も記録する」(既定オフ) で、ジャンプ・検索・ブックマークの追加を記録できる。
5. ログは追記だけを行い、アプリから行を編集・削除する手段は用意しない。
6. 「監査ログを検証」で、全行のハッシュの連鎖を確かめる。連鎖が切れた行があれば、その行番号を示す。
7. 監査ログパネルでは、ログを結果一覧で表示する。日時の列は UTC とローカル時刻の両方を出す (FOR-05)。CSV / JSON へのエクスポートができる。
8. ケースを開いていないときは監査ログを記録しない。ただし書き込み保護モードの切り替えは、ケースがなくても設定フォルダの `forensics-audit.log` に同じ形式で記録する。

**画面**: 監査ログパネル (既定は下)。

**巨大ファイル・長時間処理**: ログが 100 万行を超えても一覧は仮想化して表示する。検証は長時間処理として処理センターに出す。

**エラー**:

- ログに書き込めない (ディスク容量不足など): 操作を始める前に検出できる場合は操作を実行しない。操作中に失敗した場合は、エディタ上部に閉じられない InfoBar で「監査ログに記録できません」を表示し続け、書き込みを伴う操作をすべて無効にする。
- 検証で連鎖の切れが見つかった: 結果を赤枠と文で示し、その事実自体を新しい行として記録する。

**受け入れ基準**:

- [ ] イメージを作成すると、開始・終了の 2 行と、計算したハッシュ値が記録される。
- [ ] `audit.log` の途中の 1 文字をテキストエディタで変えると、「監査ログを検証」がその行を報告する。
- [ ] 日時がすべて `Z` 付きの UTC で記録される。
- [ ] ログに書き込めない状態を作ると、消去・クローンのメニューが無効になる。

### FOR-05 日時の扱い

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | 設定: フォレンジック → 日時の表示。ケースのプロパティ (タイムゾーン) |

**概要**: フォレンジック機能で扱う日時を、内部では UTC で持ち、画面では UTC とローカル時刻を併記する。タイムゾーンを持たない日時 (FAT など) は、その旨を明示する。

**仕様**:

1. 内部表現は UTC の日時 (100 ナノ秒単位) とする。元のデータの精度 (2 秒、10 ミリ秒、1 秒、ナノ秒など) を一緒に持ち、表示ではその精度までを示す。
2. 表示形式は ISO 8601 とする。UTC は `2026-10-07T03:15:42Z`、ローカルは `2026-10-07T12:15:42+09:00`。地域設定による書式化 (00 の 5.4) は、フォレンジックの日時には適用しない (調査結果の比較で表記がそろうように)。
3. 表示の設定 (既定は「両方」): 「UTC」「ローカル」「両方」。「両方」の場合、一覧では UTC の列とローカルの列を並べ、詳細表示では UTC の後に括弧でローカルを付ける。ローカル時刻のタイムゾーンは、ケースのタイムゾーン (FOR-03) か、ケースがない場合は Windows のタイムゾーンを使う。
4. 形式ごとの解釈:

   | 形式 | 解釈 |
   | --- | --- |
   | NTFS (FILETIME) | UTC |
   | FAT12/16/32 | タイムゾーンなし。ケースのタイムゾーン (既定は Windows のタイムゾーン) のローカル時刻とみなして UTC に変換し、「タイムゾーン推定」の印を付ける |
   | exFAT | UTC オフセットの項目が有効なら使う。無効なら FAT と同じ扱い |
   | ext2/3/4 | UNIX 時刻 (UTC)。拡張領域があればナノ秒と 2038 年以降の値を使う |
   | HFS+ | 1904 年起点の UTC。ボリュームヘッダーの作成日時だけはローカル時刻なので FAT と同じ扱い |
   | APFS | 1970 年起点のナノ秒、UTC |
   | ISO 9660 | 記録された UTC オフセットを使う |
   | UDF | 記録されたタイムゾーンを使う。未指定なら FAT と同じ扱い |
   | GPT・LDM・LVM2 などのメタデータ | 各形式の定義に従う (多くは UTC) |

5. 不正な値 (範囲外、存在しない日付) は、生の値を 16 進で表示し「不正な日時」と示す。例外にしない。
6. 監査ログ・レポートは常に UTC で記録し、レポートには併せてローカル時刻とタイムゾーン名を出す。

**画面**: 設定画面の項目。日時を表示するすべての一覧・詳細表示。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし (不正な値は仕様 5 のとおり表示する)。

**受け入れ基準**:

- [ ] NTFS の更新日時が、`dir` の表示 (ローカル) と UTC 変換が一致する。
- [ ] FAT の日時に「タイムゾーン推定」の印が付き、ケースのタイムゾーンを変えるとローカル表示と UTC が変わる。
- [ ] 設定を「UTC」にすると、すべての一覧から UTC 以外の日時の列が消える。
- [ ] 範囲外の FILETIME (`0xFFFFFFFFFFFFFFFF`) を表示しても例外にならず「不正な日時」と表示される。

## パーティション

### FOR-06 パーティション解析と表示

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-01 |
| 呼び出し | ディスク・イメージを開いたときに自動。メニュー: フォレンジック → パーティション。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: パーティションを表示」「フォレンジック: パーティションを別タブで開く」「フォレンジック: パーティションの先頭へ移動」。パーティションパネル・Hex ビューの右クリックメニュー |

**概要**: ディスクまたはディスクイメージのパーティション構造を解析し、一覧と配置図で表示する。パーティションを選ぶと、その先頭をオフセット 0 とした別のドキュメントとして開ける。

**仕様**:

1. 対応する形式と判定方法:

   | 形式 | 判定と解析 |
   | --- | --- |
   | MBR | LBA 0 の末尾 `55 AA`。オフセット `0x1BE` からの 4 エントリ (状態、CHS 開始・終了、種類 ID、開始 LBA、セクタ数)。ディスク署名 (`0x1B8`) |
   | 拡張パーティション | 種類 ID `05`・`0F`・`85`。EBR の連鎖をたどり、論理パーティションを列挙する。EBR 内の開始 LBA は各 EBR 相対、次の EBR は拡張パーティション先頭からの相対として計算する。同じ EBR を 2 回たどったら打ち切る (循環の検出)。論理パーティションは最大 256 個まで |
   | 保護 MBR | MBR の種類 ID `EE` がディスク全体を覆う場合。GPT として解析する。`EE` 以外のエントリも持つ場合は「ハイブリッド MBR」として両方を表示し、警告を出す |
   | GPT | LBA 1 の `EFI PART`。ヘッダーの CRC32 とエントリ配列の CRC32 を検証する。ディスク末尾のバックアップヘッダーも読み、主ヘッダーと比較する。エントリ (既定 128 個 × 128 バイト) の種類 GUID、固有 GUID、開始・終了 LBA、属性、名前 (UTF-16) を表示する。よく使われる種類 GUID (Windows 基本データ、EFI システム、Microsoft 予約、回復、Linux ファイルシステム、Linux LVM、Linux スワップ、Apple APFS、Apple HFS+、LDM メタデータ・データなど) は名前で表示する |
   | Apple パーティションマップ | ブロック 0 の `ER` (ドライバ記述子、ブロックサイズを取得) と、ブロック 1 以降の `PM` エントリ (名前、種類、開始ブロック、ブロック数) |
   | BSD ディスクラベル | LBA 1 (オフセット 512) またはスライス (MBR の種類 ID `A5`・`A6`・`A9`) の先頭から 1 セクタ以内のマジック `0x82564557`。パーティション (最大 16) のオフセット・サイズ・種類 |
   | LDM・LVM2 | FOR-07 で解析する。ここでは「LDM メタデータ」「LVM2 物理ボリューム」として 1 行で表示する |

2. ディスクのセクタサイズは、ディスクではデバイスから取得し (ENG-29)、イメージでは開くときの指定 (ENG-31、FOR-21) を使う。GPT が見つからない場合、512 と 4096 の両方で `EFI PART` を探し、見つかったほうのセクタサイズを提案する (InfoBar)。
3. 一覧の列: 番号、形式 (MBR / 論理 / GPT / APM / BSD)、種類 (ID または GUID とその名前)、名前、開始 LBA、終了 LBA、セクタ数、サイズ、開始オフセット、属性・フラグ (起動可能など)、推定ファイルシステム (先頭セクタの署名から判定。FOR-09 と同じ判定)、状態 (正常 / 警告)。
4. 未割り当ての領域 (パーティションの間の隙間、最後のパーティションの後) も「未割り当て」の行として表示する。1 MiB 未満の隙間は設定「小さな隙間も表示する」(既定オフ) のときだけ表示する。
5. 配置図: ディスク全体を横長の帯で表し、パーティションと未割り当て領域を幅に比例した区画で表示する (1% 未満の区画も最小幅で表示する)。区画には番号と名前を書き、色に加えて模様 (未割り当ては斜線) で区別する。
6. 行または区画を選ぶと、次の操作ができる。
   - 「パーティションの先頭へ移動」: 開始オフセットへジャンプする。
   - 「パーティションを選択」: パーティションの範囲を選択範囲にする。
   - 「パーティションを別タブで開く」: パーティションの範囲だけを対象とし、パーティションの先頭をオフセット 0 とするドキュメントを開く。タブ名は `ディスク 2 - パーティション 3`。表示上のアドレス (00 の 3 章) のベースは 0 とし、設定でディスク上の絶対オフセットを表示に切り替えられる。このドキュメントは元のディスクドキュメントと同じデータソースを共有し、セクタサイズ・読み取り専用と書き込み保護の状態を引き継ぐ。範囲を新しいタブで開く仕組みは ENG-39 の連動ビューと同じで、ベースアドレスの既定だけが異なる (ENG-39 は親での開始位置、ここでは 0)。
   - 「エントリの構造を表示」: その表 (MBR・GPT エントリなど) に標準テンプレート (07 の MBR / GPT) を適用し、Hex ビュー上で色分けする。
7. Hex ビューの右クリックメニューに「ここをパーティションの先頭として開く」を置く。カーソル位置 (セクタ境界に切り下げ) から末尾までを、上と同じ方法で別タブに開く。ファイルシステムの解析 (FOR-09) はこの別タブで行える。
8. 検査と警告: GPT の CRC 不一致、主ヘッダーとバックアップヘッダーの不一致、パーティションの重なり、ディスクの範囲外を指すエントリ、ハイブリッド MBR。各警告は状態の列に「警告」と出し、詳細を一覧の下の欄に文で示す。
9. ステータスバーに、カーソル位置の LBA とそのパーティション番号を表示する (ディスク・イメージのドキュメントのとき)。

**画面**: パーティションパネル (既定は左)。上段に配置図、中段に一覧、下段に選択した行の詳細と警告。

**巨大ファイル・長時間処理**: 解析は各形式の表の数セクタを読むだけで、ディスクの大きさに依存しない。拡張パーティションの連鎖が長い場合でも上限 256 個で止める。解析は非同期に行い、終わるまで一覧に「解析中」を表示する。

**エラー**:

- パーティション表が見つからない: 一覧に「パーティション表が見つかりません」と表示し、FOR-08 の「失われたパーティションのスキャン」へのリンクを出す。
- 読み込みエラー (不良セクタ): 読めなかったセクタの LBA を示し、読めた範囲だけで一覧を作る。

**受け入れ基準**:

- [ ] MBR のディスクイメージで、基本パーティション 3 個と拡張パーティション内の論理パーティション 5 個が正しい開始 LBA で表示される。
- [ ] EBR の連鎖が循環しているイメージで、無限ループにならずに警告が出る。
- [ ] GPT のエントリ配列を 1 バイト書き換えたイメージで、CRC 不一致の警告が出る。
- [ ] バックアップ GPT だけが壊れたイメージで、主ヘッダーから一覧を作り、不一致の警告を出す。
- [ ] 4096 バイトセクタの GPT イメージを 512 として開くと、セクタサイズの変更を提案される。
- [ ] Apple パーティションマップと BSD ディスクラベルのテスト用イメージで、各パーティションが表示される。
- [ ] 「パーティションを別タブで開く」で開いたタブのオフセット 0 が、ディスク上のパーティション開始オフセットのバイトと一致する。

### FOR-07 LDM 動的ディスクと LVM2

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | パーティションパネルの「LDM メタデータ」「LVM2 物理ボリューム」行の右クリックメニュー「論理ボリュームを表示」。コマンドパレット: 「フォレンジック: 論理ボリュームを表示」。ショートカット: 既定なし |

**概要**: Windows の動的ディスク (LDM) と Linux の LVM2 のメタデータを読み、論理ボリュームの構成 (どのディスクのどの範囲をどの順につなぐか) を表示する。単純・スパン・ストライプの論理ボリュームは、仮想的なドキュメントとして開ける。

**仕様**:

1. LDM:
   - MBR の種類 ID `42`、または GPT の LDM メタデータ・LDM データの種類 GUID で判定する。
   - PRIVHEAD (MBR のディスクでは LBA 6、GPT のディスクでは LDM メタデータパーティション内) を読み、TOCBLOCK、VMDB、VBLK (ディスク、ディスクグループ、ボリューム、コンポーネント、パーティションの各レコード) を解析する。
   - ボリュームごとに、名前、種類 (シンプル / スパン / ストライプ / ミラー / RAID-5)、サイズ、構成するディスクと範囲を表示する。
2. LVM2:
   - 先頭 4 セクタ内の `LABELONE` ラベルと PV ヘッダーで判定する。
   - メタデータ領域 (`LVM2 x[5A%r0N*>`) にある最新のテキストメタデータを読み、ボリュームグループ、物理ボリューム、論理ボリュームとそのセグメント (linear / striped) を表示する。
3. 仮想ドキュメントとして開く: シンプル・スパン (LDM)、linear (LVM2)、ストライプ (LDM・LVM2 の striped) は、構成するすべてのディスクが開かれていれば「論理ボリュームを開く」で 1 つの読み取り専用ドキュメントとして開ける。ディスクの識別は LDM のディスク GUID、LVM2 の PV UUID で行い、開いているディスク・イメージの中から自動で探す。見つからないディスクは、ファイルまたはディスクを選んで割り当てる。
4. ミラー・RAID-5 (LDM) は構成の表示だけを行い、仮想ドキュメントとしては FOR-26 の RAID 再構成の設定を自動で埋めて開く。
5. LVM2 のシンプロビジョニング、スナップショット、キャッシュ、RAID 型の LV は構成の表示だけを行い、開けない (「対応していない種類です」と表示)。

**画面**: パーティションパネルの下に表示する「論理ボリューム」の一覧 (列: 名前、種類、サイズ、構成、状態)。構成要素の割り当てダイアログ。

**巨大ファイル・長時間処理**: メタデータの読み込みは 1 MiB 程度で、ディスクの大きさに依存しない。仮想ドキュメントの読み込みは要求された範囲だけを構成ディスクから読む。

**エラー**:

- 構成ディスクが足りない: どのディスク (GUID・UUID) が足りないかを表示し、開かない。
- メタデータの不整合 (シーケンス番号の不一致など): 最新と判断したものを使い、警告を出す。

**受け入れ基準**:

- [ ] 2 台構成の LDM ストライプのイメージを両方開くと、論理ボリュームを 1 つのドキュメントとして開け、内容が元のボリュームのイメージと一致する。
- [ ] LVM2 の linear LV が 2 つの PV にまたがるイメージで、LV を開ける。
- [ ] 構成ディスクが 1 台足りない場合に、足りないディスクの識別子が表示される。

### FOR-08 失われたパーティションのスキャン

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-04 |
| 呼び出し | メニュー: フォレンジック → パーティション → 失われたパーティションをスキャン。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: 失われたパーティションをスキャン」。パーティションパネルの「未割り当て」行の右クリックメニュー |

**概要**: ディスクまたはイメージの全体 (または指定範囲) を走査し、ファイルシステムの先頭やパーティション表の痕跡を探して、削除・破損したパーティションの候補を一覧にする。

**仕様**:

1. 入力: 対象範囲 (既定はディスク全体。パーティションパネルの未割り当て行から呼んだ場合はその範囲)、走査の間隔 (「1 MiB 境界」「シリンダ境界 (63 セクタ)」「すべてのセクタ」から複数選択。既定は 1 MiB 境界とシリンダ境界)。
2. 探すもの:

   | 対象 | 判定 |
   | --- | --- |
   | NTFS | セクタ先頭から 3 バイト目の `NTFS    `、BPB の整合性 (セクタサイズ、クラスタサイズが 2 の累乗)。末尾のバックアップブートセクタからも逆算する |
   | FAT12/16/32 | ジャンプ命令、BPB の整合性、末尾 `55 AA`。FAT32 はバックアップブートセクタ (先頭から 6 セクタ目) |
   | exFAT | 3 バイト目の `EXFAT   `、ブート領域のチェックサム。バックアップブート領域 (12 セクタ後) |
   | ext2/3/4 | 先頭から 1080 バイト目のマジック `0xEF53` と、スーパーブロックの整合性 |
   | HFS+ / HFSX | 先頭から 1024 バイト目の `H+` / `HX` |
   | APFS | 先頭から 32 バイト目の `NXSB` |
   | ISO 9660 / UDF | 先頭から 32768 バイト目の `CD001`・`BEA01`・`NSR02`・`NSR03` |
   | LVM2 / LDM | `LABELONE`、`PRIVHEAD` |
   | BitLocker | 3 バイト目の `-FVE-FS-` |
   | GPT ヘッダー・EBR | `EFI PART`、`55 AA` と妥当なエントリを持つセクタ |

3. 各候補について、開始 LBA、推定サイズ (BPB・スーパーブロックの値から)、種類、確度 (高: 主と予備の両方が一致、中: 主だけ、低: 署名だけ)、既存のパーティションとの重なりを求める。
4. 結果は結果一覧で表示する。行を選ぶと、そのオフセットへジャンプする。右クリックメニュー:
   - 「パーティションとして開く」: FOR-06 の「パーティションを別タブで開く」と同じ方法で、候補の範囲を開く。
   - 「ファイルシステムを表示」: 候補を開いてすぐに FOR-09 のブラウザを表示する。
   - 「パーティション表のエントリを作成」: 選んだ候補 (複数可) から MBR または GPT のエントリを作り、データエンジン上の編集としてディスクのドキュメントに加える。保存するまでディスクには書かない。保存はディスクへの書き込みなので、共通の前提の確認ダイアログを出す。書き込み保護モードでは無効。
5. 一覧を CSV / JSON にエクスポートできる。

**画面**: スキャン条件のダイアログ (範囲の入力欄、間隔のチェックボックス、対象の種類のチェックボックス)。結果一覧パネル。

**巨大ファイル・長時間処理**: 長時間処理。処理センターに出し、進捗 (LBA)、速度、残り時間、見つかった件数を表示する。結果は見つかるたびに一覧に追加する。「すべてのセクタ」はディスクの読み込み速度に比例した時間がかかることを、ダイアログに目安時間 (容量 ÷ 想定 200 MB/s) で表示する。キャンセルしても、それまでの結果は残す。

**エラー**:

- 読み込みエラー: 該当セクタを飛ばして続け、読めなかった範囲を結果の末尾にまとめて表示する。
- 候補が 0 件: 「パーティションの候補は見つかりませんでした」と表示し、「すべてのセクタ」での再スキャンを提案する。

**受け入れ基準**:

- [ ] MBR を 0 で埋めた NTFS + FAT32 のテスト用イメージで、2 つのパーティションが確度「高」で見つかる。
- [ ] 見つかった候補を「パーティションとして開く」と、ファイルシステムのブラウザでファイル一覧が見える。
- [ ] 「パーティション表のエントリを作成」の後、保存しなければディスク (イメージ) の内容が変わらない。
- [ ] 100 GB のイメージのスキャン中に UI が固まらず、キャンセルできる。

## ファイルシステム

### FOR-09 ファイルシステムブラウザ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-02 |
| 呼び出し | メニュー: フォレンジック → ファイルシステム → ブラウザを表示。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: ファイルシステムを表示」「フォレンジック: ファイルを別タブで開く」「フォレンジック: ファイルを書き出す」。パーティションパネルの右クリックメニュー「ファイルシステムを表示」 |

**概要**: ボリューム・パーティション・イメージ上のファイルシステムを OS を通さずに解析し、ディレクトリツリーとファイル一覧で閲覧する。ファイルを選ぶと、その実データがある範囲を Hex ビューで示し、別タブで開いたり書き出したりできる。各ファイルシステムの詳細は FOR-10〜FOR-14 で定める。

**仕様**:

1. 対象: ボリュームのドキュメント、パーティションのドキュメント (FOR-06)、ファイルシステムのイメージ。先頭の署名でファイルシステムの種類を判定する (FOR-08 の表と同じ)。判定できない場合は種類を選ぶダイアログを出す。
2. ブラウザはドキュメントごとに 1 つ。左にディレクトリツリー、右にファイル一覧、下に選んだ項目の詳細を表示する。
3. ファイル一覧の列: 名前、拡張子、サイズ、割り当てサイズ、作成日時、更新日時、アクセス日時、メタデータ変更日時 (形式にある場合)、属性、ファイル ID (MFT 番号・inode 番号・ディレクトリエントリの位置)、先頭クラスタ、断片の数、状態 (通常 / 削除 / 孤立)、パス。日時は FOR-05 に従う。列の表示・非表示は切り替えられる。
4. ツリーには、ルートのほかに次の仮想フォルダを置く。
   - 「$メタデータ」: ファイルシステムのメタデータファイル ($MFT、FAT 領域、スーパーブロックなど)。
   - 「削除されたファイル」: FOR-17。
   - 「孤立したファイル」: 親ディレクトリが見つからないエントリ。
   - 「未割り当て領域」「ボリュームスラック」: FOR-16。
5. 項目の選択時の動作:
   - ファイルを 1 回クリック: 詳細欄に全項目と断片 (エクステント) の一覧 (論理オフセット、開始クラスタ、クラスタ数、ディスク上のオフセット) を表示する。
   - ダブルクリックまたは Enter: ファイルの先頭のデータがあるオフセットへジャンプし、ファイルのすべての断片をマルチ選択 (EDIT-07) として選択する (FOR-15)。
   - データがメタデータ内に格納されている (NTFS の常駐データ、ext4 のインラインデータなど) 場合は、その格納位置へジャンプする。
6. 右クリックメニュー:
   - 「ファイルを別タブで開く」: ファイルの論理的な内容 (断片を順につないだもの。スパース部分は 0、NTFS 圧縮は展開したもの) を読み取り専用のドキュメントとして開く。タブ名は `ファイル名 (ディスク 2 - パーティション 3)`。このタブのオフセットとディスク上のオフセットの対応は、ステータスバーに表示する。
   - 「ファイルを書き出す」: 選んだファイル・フォルダを指定フォルダに書き出す (ケースがあれば既定は `exports/`)。オプションは、ディレクトリ構造を保つ (既定オン)、代替データストリームも書き出す (既定オン、`名前_ストリーム名` で保存)、スラックも別ファイルで書き出す (既定オフ)、削除されたファイルを含める (既定オフ)。書き出したファイルごとに MD5 と SHA-256 を計算し、`export-manifest.csv` (元のパス、ファイル ID、サイズ、日時 (UTC)、ハッシュ、書き出し先) を作る。書き出したファイルの日時は元の値に合わせない (調査用の写しとしてマニフェストに記録する)。
   - 「メタデータの位置へ移動」: MFT レコード・ディレクトリエントリ・inode の位置へジャンプする。
   - 「パスをコピー」「一覧を CSV / JSON にエクスポート」。
7. ファイル一覧の上に絞り込み欄を置く (名前の部分一致、ワイルドカード `*` `?`)。ボリューム全体を対象にした名前検索は「ファイルを検索」で行い、結果を結果一覧に出す。
8. ファイルシステムの解析は読み込みだけを行い、ファイルシステムを変更しない。ファイルの作成・削除・名前の変更などはこのブラウザからはできない。
9. ファイルシステムの概要 (種類、ボリューム名、シリアル番号、クラスタサイズ、総クラスタ数、空きクラスタ数、作成日時など) をツリーのルートの詳細に表示する。

**画面**: ファイルシステムパネル (既定は左。ツリーと一覧を上下に分ける) と詳細欄。幅が足りない場合は一覧を詳細欄の上に重ねる。

**巨大ファイル・長時間処理**: ディレクトリの内容はツリーを展開したときに読み込む (遅延読み込み)。ボリューム全体の走査が必要な処理 (削除ファイルの列挙、名前検索、クラスタの逆引き表の作成) は長時間処理として処理センターに出し、途中結果を順に表示する。ファイル一覧は仮想化し、1 つのディレクトリに 100 万件あっても表示できる。書き出しは長時間処理。

**エラー**:

- メタデータの破損 (署名の不一致、範囲外のクラスタ番号、循環するチェーン): そのエントリに「破損」の印を付け、詳細欄に理由を出す。解析全体は止めない。
- 読み込みエラー: 読めなかったファイルは書き出し時に読めた部分だけを書き、読めなかった範囲は 0 で埋め、マニフェストに範囲を記録する。
- 書き出し先の空き容量不足: 書き出し前に検出して止める。

**受け入れ基準**:

- [ ] NTFS・FAT32・exFAT のテスト用イメージで、OS でマウントした場合と同じファイル一覧 (名前・サイズ・更新日時) が表示される。
- [ ] ファイルをダブルクリックすると、そのファイルの全断片が選択され、先頭へジャンプする。
- [ ] 「ファイルを別タブで開く」の内容のハッシュが、OS 経由でコピーしたファイルのハッシュと一致する。
- [ ] 書き出すと、`export-manifest.csv` にハッシュ付きで記録され、監査ログにも記録される。
- [ ] 100 万ファイルのディレクトリを開いても UI が固まらない。

### FOR-10 NTFS の解析

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-02 |
| 呼び出し | FOR-09 のブラウザ。右クリックメニュー「MFT レコードを表示」「INDX を表示」「$LogFile を表示」。コマンドパレット: 「フォレンジック: MFT レコードへ移動」(MFT 番号を入力)。ショートカット: 既定なし |

**概要**: NTFS のブートセクタ、$MFT、MFT レコードと属性、ディレクトリのインデックス (INDX)、代替データストリーム、$LogFile の基本構造を解析して表示する。

**仕様**:

1. ブートセクタ: BPB (セクタサイズ、クラスタあたりのセクタ数、総セクタ数、$MFT と $MFTMirr の開始クラスタ、MFT レコードサイズ、インデックスレコードサイズ、ボリュームシリアル番号) を表示する。末尾のバックアップブートセクタと比較し、違いがあれば警告する。
2. $MFT: レコード 0 のデータ属性のランリストから $MFT 自体の配置を求める。$MFTMirr の先頭 4 レコードと比較する。
3. MFT レコード:
   - `FILE` 署名、更新シーケンス配列 (フィックスアップ) を検証して適用する。フィックスアップが合わないレコードは「破損」として表示し、適用前の生データも見られるようにする。
   - ヘッダー (シーケンス番号、ハードリンク数、フラグ (使用中・ディレクトリ)、使用サイズ、ベースレコード、次の属性 ID) を表示する。
   - 属性: $STANDARD_INFORMATION (4 つの日時、属性、所有者 ID、セキュリティ ID、USN)、$FILE_NAME (名前空間 (POSIX / Win32 / DOS / Win32&DOS) ごと、親の参照、4 つの日時)、$DATA (名前なし・名前付き)、$INDEX_ROOT、$INDEX_ALLOCATION、$BITMAP、$ATTRIBUTE_LIST、$OBJECT_ID、$REPARSE_POINT、$SECURITY_DESCRIPTOR、$VOLUME_NAME、$VOLUME_INFORMATION、$EA、$EA_INFORMATION、$LOGGED_UTILITY_STREAM。未知の属性は種類番号と生データで表示する。
   - 常駐 / 非常駐、ランリスト (開始 VCN、終了 VCN、クラスタの割り当て、スパースの区間) を表示する。
   - $ATTRIBUTE_LIST がある場合、拡張レコードの属性を合わせて 1 つのファイルとして表示する。
   - 「MFT レコードを表示」で、レコードを構造体テンプレート (07) として Hex ビュー上で色分けし、ツリー表示する。
4. 日時: $STANDARD_INFORMATION と $FILE_NAME の日時を両方表示し、$STANDARD_INFORMATION の日時が $FILE_NAME の日時より前、または小数部が 0 の場合に「日時の不一致」の印を付ける (日時の改ざんの手がかり)。
5. 代替データストリーム: 名前付きの $DATA を `ファイル名:ストリーム名` の項目としてファイル一覧に出す (設定で非表示にできる。既定は表示)。`Zone.Identifier` などの小さいストリームは詳細欄で内容をテキスト表示する。
6. ディレクトリインデックス: $INDEX_ROOT と $INDEX_ALLOCATION の INDX レコード (`INDX` 署名、フィックスアップ) を解析してファイル一覧を作る。INDX レコードの使用領域より後ろ (インデックススラック) に残っているエントリも解析し、「インデックススラックのエントリ」として削除されたファイル (FOR-17) に加える。
7. 圧縮 (LZNT1) されたファイルは「ファイルを別タブで開く」と書き出しで展開する。Hex ビュー上の断片の表示は圧縮されたままの位置を示す。
8. EFS で暗号化されたファイルは生データだけを扱い、「EFS で暗号化されています」と示す。復号はしない。
9. $LogFile の基本:
   - リスタート領域 (`RSTR` ページ 2 つ) の現在の LSN、クライアント情報を表示する。
   - レコードページ (`RCRD`) を順に解析し、ログレコードの一覧 (LSN、前の LSN、クライアントの前の LSN、種類、トランザクション ID、Redo 操作、Undo 操作、対象の MFT 番号 (取れる場合)、長さ) を結果一覧に出す。
   - ログの再生 (Redo / Undo の適用) は行わない。
10. メタデータファイル ($MFT、$MFTMirr、$LogFile、$Volume、$AttrDef、$Bitmap、$Boot、$BadClus、$Secure、$UpCase、$Extend 以下) は「$メタデータ」フォルダに表示する。$Bitmap を空き領域の判定 (FOR-16) に使う。

**画面**: FOR-09 のブラウザと詳細欄。MFT レコード表示はテンプレートのツリーパネル (07) を使う。$LogFile の一覧は結果一覧パネル。

**巨大ファイル・長時間処理**: MFT レコードは必要なものだけ読む。$MFT 全体の走査 (削除ファイル、孤立ファイル、名前検索、$LogFile の一覧) は長時間処理。$MFT が数 GB (数百万レコード) でも、レコードは順に読んで結果だけを保持する。

**エラー**: フィックスアップの不一致、ランリストの不正 (範囲外、長さ 0)、属性の長さの不正は、そのレコード・属性に「破損」を付けて続行する。

**受け入れ基準**:

- [ ] テスト用 NTFS イメージで、ADS を持つファイルが `file.txt:secret` として一覧に出て、内容を開ける。
- [ ] フィックスアップを壊した MFT レコードが「破損」と表示され、解析全体は続く。
- [ ] $STANDARD_INFORMATION の日時を書き換えたファイルに「日時の不一致」の印が付く。
- [ ] 削除後にインデックススラックに残ったファイル名が、削除されたファイルとして表示される。
- [ ] NTFS 圧縮されたファイルを書き出すと、OS でコピーしたファイルとハッシュが一致する。
- [ ] $LogFile の一覧に LSN と Redo / Undo の操作名が表示される。

### FOR-11 FAT12 / FAT16 / FAT32 / exFAT の解析

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-02 |
| 呼び出し | FOR-09 のブラウザ。右クリックメニュー「ディレクトリエントリを表示」「クラスタチェーンを表示」。ショートカット: 既定なし |

**概要**: FAT 系と exFAT のブート領域、FAT、ディレクトリエントリ、クラスタチェーンを解析して表示する。

**仕様**:

1. FAT の種類はクラスタ数で判定する (4085 未満が FAT12、65525 未満が FAT16、それ以上が FAT32)。BPB の文字列は判定に使わない。
2. ブートセクタ・BPB の全項目と、FAT32 の FSInfo (空きクラスタ数、次の空きクラスタ) を表示する。FAT32 のバックアップブートセクタと比較する。
3. FAT: 複数の FAT (通常 2 つ) を比較し、違いのあるエントリ数を表示する。違いがある場合、どちらの FAT を使うかを選べる (既定は 1 つ目)。
4. ディレクトリエントリ: 短い名前 (8.3)、属性、日時 (作成は 10 ミリ秒単位、更新は 2 秒単位、アクセスは日付のみ)、先頭クラスタ、サイズを表示する。長い名前 (LFN) のエントリを順序番号とチェックサムで検証して組み立てる。チェックサムが合わない LFN は短い名前を使い、警告を出す。
5. クラスタチェーン: 先頭クラスタから FAT をたどる。循環・範囲外・途中の空きクラスタを検出したら、そこで止めて「破損」を付ける。チェーンの長さとファイルサイズが合わない場合も警告する。
6. 削除されたエントリ (先頭バイト `E5`) は FOR-17 に出す。先頭の 1 文字は不明なので `_` で表示し、LFN が残っていれば LFN から復元した名前を使う。
7. exFAT:
   - メインブート領域とバックアップブート領域のチェックサム (11 セクタ分) を検証する。
   - 割り当てビットマップ、大文字変換表、ボリュームラベルの各エントリを表示する。
   - ファイルのエントリセット (File、Stream Extension、File Name) をセットのチェックサムで検証して組み立てる。
   - Stream Extension の NoFatChain フラグが立っている場合は、連続したクラスタとして扱い、FAT をたどらない。
   - 日時は 10 ミリ秒単位の補正と UTC オフセットを使う (FOR-05)。
   - 削除されたエントリ (エントリの種類の使用中ビットが 0) は FOR-17 に出す。
8. 空き領域の判定は、FAT 系は FAT の空きエントリ、exFAT は割り当てビットマップで行う。

**画面**: FOR-09 のブラウザと詳細欄。ディレクトリエントリの表示にはテンプレート (07) を使う。

**巨大ファイル・長時間処理**: FAT32 の FAT は最大で数百 MB になるため、全体を読み込まず、必要な範囲を 64 KB 単位でキャッシュして読む。FAT の比較・削除エントリの列挙は長時間処理。

**エラー**: BPB の値の矛盾 (クラスタサイズが 2 の累乗でない、FAT の領域が範囲外) は、ブラウザの上部に警告を出し、利用者が値を上書き指定して再解析できるようにする。

**受け入れ基準**:

- [ ] FAT12・FAT16・FAT32・exFAT の各テスト用イメージで、長い名前を含むファイル一覧が正しく表示される。
- [ ] 2 つの FAT が食い違うイメージで、違いの数が表示され、使う FAT を切り替えられる。
- [ ] 循環するクラスタチェーンを持つファイルで、無限ループにならず「破損」と表示される。
- [ ] exFAT の NoFatChain のファイルを書き出すと、内容が元のファイルと一致する。

### FOR-12 ext2 / ext3 / ext4 の解析

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | FOR-09 のブラウザ。右クリックメニュー「inode を表示」。コマンドパレット: 「フォレンジック: inode へ移動」(inode 番号を入力)。ショートカット: 既定なし |

**概要**: ext2 / ext3 / ext4 のスーパーブロック、グループ記述子、inode、エクステントとブロックマップ、ディレクトリエントリを解析して表示する。

**仕様**:

1. スーパーブロック (先頭から 1024 バイト) の主要項目 (ブロックサイズ、inode 数、ブロック数、グループあたりの数、機能フラグ (compat / incompat / ro_compat)、UUID、ボリューム名、最後のマウント日時・パス、ジャーナルの inode) を表示する。
2. グループ記述子 (32 バイト版と 64 bit 機能時の 64 バイト版)、flex_bg、メタデータのチェックサム (metadata_csum が有効な場合は検証して不一致を警告) に対応する。
3. inode: モード、所有者、サイズ、日時 (atime / ctime / mtime / crtime / dtime。拡張領域のナノ秒)、リンク数、フラグ、拡張属性を表示する。データの位置は、エクステントツリー (ext4) と直接・間接・二重間接・三重間接ブロック (ext2/3) の両方に対応する。インラインデータ (データが inode 内) にも対応する。
4. ディレクトリ: 線形のディレクトリエントリを読む。htree (ハッシュインデックス) のディレクトリも、葉のブロックを線形に読むことでエントリを列挙する。エントリの `rec_len` の余り (削除で前のエントリに吸収された領域) に残る名前を解析し、FOR-17 に出す。
5. 削除された inode (dtime が 0 でない、リンク数 0) を FOR-17 に出す。ext3/4 では削除時にブロックの位置情報が消えることが多いため、位置情報が残っていない場合は「データの位置は不明」と表示する。
6. ジャーナル (jbd2) はスーパーブロックとブロックの種類 (記述子・コミット・取り消し) の一覧だけを表示する。ジャーナルの再生はしない。
7. fscrypt で暗号化されたディレクトリ・ファイルは「暗号化されています」と示し、名前・内容を生データのまま扱う。
8. 空き領域の判定はブロックビットマップで行う。

**画面**: FOR-09 のブラウザと詳細欄。

**巨大ファイル・長時間処理**: inode テーブル全体の走査 (削除された inode、名前検索) は長時間処理。

**エラー**: エクステントヘッダーのマジック (`0xF30A`) の不一致、範囲外のブロック番号は、その inode に「破損」を付けて続行する。

**受け入れ基準**:

- [ ] ext2・ext3・ext4 のテスト用イメージで、ファイル一覧とファイルの内容が、テスト用イメージの作成時に記録したマニフェスト (全ファイルのパス・サイズ・更新日時・ハッシュ) と一致する。
- [ ] 64 bit 機能と flex_bg が有効な ext4 で正しく読める。
- [ ] 削除したファイルの名前がディレクトリエントリの余りから見つかる。

### FOR-13 HFS+ / APFS の基本解析

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | FOR-09 のブラウザ。ショートカット: 既定なし |

**概要**: macOS の HFS+ (HFSX を含む) と APFS を読み取り専用で解析し、ファイル一覧と内容を閲覧できるようにする。基本的な構造だけに対応する。

**仕様**:

1. HFS+ / HFSX:
   - ボリュームヘッダー (先頭から 1024 バイト) と末尾の予備ボリュームヘッダーを表示・比較する。
   - カタログ B 木を読み、フォルダとファイル (データフォークとリソースフォーク) を一覧にする。リソースフォークは `ファイル名/..namedfork/rsrc` として表示する。
   - 9 個を超える断片はエクステントオーバーフロー B 木から読む。
   - ハードリンク (`iNode` ファイルへの参照) を解決する。
   - HFS+ の圧縮 (decmpfs、zlib と LZVN) は対応しない。生データを扱い、「圧縮されています」と示す。
   - ジャーナルは表示だけ行い、再生しない。
2. APFS:
   - コンテナのスーパーブロック (`NXSB`) から最新の有効なチェックポイントを選ぶ (チェックサム Fletcher-64 を検証)。
   - オブジェクトマップをたどり、ボリュームのスーパーブロック (`APSB`) を列挙する。ボリューム名、役割、暗号化の有無を表示する。
   - 暗号化されていないボリュームのファイルシステムツリーを読み、ファイル一覧と内容 (エクステント) を表示する。
   - スナップショットは一覧だけを表示する (未決定: スナップショットの中身の閲覧)。
   - 暗号化されたボリューム (FileVault を含む) は暗号化の検出 (FOR-29) だけを行い、ファイル一覧は出さない。
   - Fusion Drive、APFS の圧縮ファイル、クローンの共有エクステントの区別は対応しない (圧縮ファイルは「圧縮されています」と示す)。
3. 空き領域の判定は、HFS+ は割り当てファイル、APFS は空き領域マネージャで行う。APFS で空き領域の判定ができない場合は、空き領域の強調 (FOR-16) を無効にする。

**画面**: FOR-09 のブラウザと詳細欄。APFS はツリーの最上位にボリュームを並べる。

**巨大ファイル・長時間処理**: B 木のノードは必要なものだけ読む。カタログ全体の走査は長時間処理。

**エラー**: チェックサムの不一致 (APFS)、B 木のノードの不正は、そのノード以下に「破損」を付けて続行する。APFS で有効なチェックポイントが見つからない場合は「APFS のチェックポイントが見つかりません」と表示する。

**受け入れ基準**:

- [ ] HFS+ のテスト用イメージで、データフォークとリソースフォークを持つファイルが表示され、内容を開ける。
- [ ] 暗号化されていない APFS のテスト用イメージで、ファイル一覧と内容が、テスト用イメージの作成時に記録したマニフェスト (全ファイルのパス・サイズ・更新日時・ハッシュ) と一致する。
- [ ] 暗号化された APFS ボリュームでは、ボリュームが「暗号化」と表示され、ファイル一覧は出ない。

### FOR-14 ISO 9660 / UDF の解析

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | FOR-09 のブラウザ。ショートカット: 既定なし |

**概要**: 光ディスクのイメージ (ISO) やボリュームの ISO 9660 と UDF を解析し、ファイル一覧と内容を閲覧できるようにする。

**仕様**:

1. セクタサイズは 2048 バイト。生のセクタ (2352 バイト、`.bin`) のイメージは対象外とする (未決定: 2352 バイトセクタの変換)。
2. ISO 9660:
   - ボリューム記述子 (セクタ 16 から、終端記述子まで) を列挙する。基本 (PVD)、補助 (Joliet の SVD)、ブートレコード (El Torito) を表示する。
   - Joliet があれば Joliet の名前 (UTF-16) を、なければ Rock Ridge (SUSP の `NM`・`PX`・`TF`・`SL`) の名前と属性を、どちらもなければ基本の名前を使う。表示する名前の種類は切り替えられる。
   - El Torito のブートカタログのエントリ (プラットフォーム、エミュレーションの種類、開始セクタ、セクタ数) を表示し、ブートイメージを書き出せる。
   - 複数セッションのディスクは、最後のセッションのボリューム記述子を使う。どのセッションを使うかを選べる。
3. UDF:
   - ボリューム認識シーケンス (`BEA01`・`NSR02`・`NSR03`・`TEA01`) を確認し、アンカー (セクタ 256、末尾 - 256、末尾) からボリューム記述子シーケンスを読む。
   - パーティション記述子、論理ボリューム記述子、ファイルセット記述子、ファイルエントリ (FE / EFE) を読み、ファイル一覧と内容を表示する。
   - UDF 1.02〜2.60 に対応する。メタデータパーティション (2.50 以降) に対応する。仮想パーティション (VAT) とスペアリングテーブルは未決定。
   - ISO 9660 と UDF の両方を持つブリッジ形式では、既定で UDF を使い、切り替えられる。
4. 削除された項目と空き領域の強調は、ISO 9660 では対象外 (書き換えない媒体のため)。UDF は未割り当て領域のビットマップがあれば FOR-16 を使える。

**画面**: FOR-09 のブラウザと詳細欄。

**巨大ファイル・長時間処理**: 数十 GB の BD イメージでも、ディレクトリを展開したときだけ読む。

**エラー**: 記述子のタグのチェックサム・CRC (UDF) の不一致は警告として表示して続行する。

**受け入れ基準**:

- [ ] Joliet と Rock Ridge を持つ ISO イメージで、名前の種類を切り替えられる。
- [ ] El Torito の起動可能な ISO から、ブートイメージを書き出せる。
- [ ] UDF 2.50 の BD イメージで、ファイル一覧と内容が表示される。

### FOR-15 クラスタとファイルの対応付け

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-02 |
| 呼び出し | メニュー: フォレンジック → ファイルシステム → クラスタへ移動 / この位置のファイル / ファイルのクラスタを表示。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: クラスタへ移動」「フォレンジック: この位置を使っているファイル」「フォレンジック: ファイルのクラスタを表示」。Hex ビューとファイル一覧の右クリックメニュー |

**概要**: ディスク上のオフセット (セクタ・クラスタ) とファイルの対応を双方向に調べる。カーソル位置のクラスタを使っているファイルを示し、ファイルの全クラスタを Hex ビュー上で強調する。

**仕様**:

1. ステータスバーに、ファイルシステムを解析しているドキュメントでは次の項目を追加する: LBA、クラスタ番号、クラスタ内のオフセット、そのクラスタの持ち主 (ファイルのパス、メタデータ名、「未割り当て」、「スラック」のいずれか)。持ち主がまだ分からない場合は「調べる」リンクを出す。
2. 「クラスタへ移動」: クラスタ番号を入力すると (入力式は 00 の 6 章。この入力欄に限り、名前 `cluster` で現在のクラスタ番号を使える)、そのクラスタの先頭オフセットへジャンプする。FAT 系のクラスタ番号 2 始まりなど、形式ごとの番号の付け方に従う。ext / HFS+ / APFS では「ブロックへ移動」と表示する。
3. 「この位置を使っているファイル」(逆引き): カーソル位置または選択範囲のクラスタを使っているファイル・メタデータを調べて一覧にする。
   - 初回は、ボリューム全体の割り当てを走査して、クラスタの範囲 → ファイル ID の表 (区間木) を作る。作成は長時間処理で、完了までの間は「作成中」と表示する。作った表はドキュメントの付随データ (00 の 10 章) として保存し、データソースのサイズとファイルシステムのシリアル番号が同じなら再利用する。
   - 削除されたファイルの以前のクラスタ (FOR-17) も「削除されたファイル (割り当て解除済み)」として一緒に表示する。
4. 「ファイルのクラスタを表示」: 選んだファイルのすべての断片を、Hex ビュー上で強調表示 (色付けの層。05 の色付けルールと同じ描画層を使い、色に加えて枠線で示す) し、マルチ選択として選択する。断片の一覧 (論理オフセット、ディスク上のオフセット、長さ、クラスタ範囲) をパネルに表示し、行のクリックでその断片へジャンプする。
5. 強調の表示中は、移動メニューに「次の断片」「前の断片」を出す (コマンドパレット: 「フォレンジック: 次の断片」「フォレンジック: 前の断片」。ショートカット: 既定なし)。
6. ミニマップ (VIEW-35) が表示されている場合、強調中のファイルの断片の位置をミニマップにも印で示す。

**画面**: ステータスバーの項目、断片一覧パネル (既定は下)、Hex ビューの強調。

**巨大ファイル・長時間処理**: 逆引き表の作成は長時間処理。ファイル数 1,000 万のボリュームでも、表のメモリ使用量は 00 の 11.2 の上限に収まるよう、上限を超えた部分は一時ファイルに退避する。

**エラー**: 範囲外のクラスタ番号の入力は入力欄の赤枠で示す (00 の 9 章)。逆引き表の作成中に破損したメタデータがあった場合、そのファイルを飛ばし、件数を表示する。

**受け入れ基準**:

- [ ] 断片化したファイルの途中のクラスタにカーソルを置くと、ステータスバーにそのファイルのパスが表示される。
- [ ] 「クラスタへ移動」で FAT32 のクラスタ 2 を指定すると、データ領域の先頭へジャンプする。
- [ ] 「ファイルのクラスタを表示」で、全断片が Hex ビューで強調され、「次の断片」で順に移動できる。
- [ ] 逆引き表は 2 回目以降 (再起動後を含む) は作り直さない。

### FOR-16 スラック領域と空き領域の強調・抽出

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | メニュー: 表示 → フォレンジックの強調 (チェック付き)。メニュー: フォレンジック → ファイルシステム → 未割り当て領域を書き出す / スラックを書き出す。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: 空き領域とスラックの強調の切り替え」「フォレンジック: 未割り当て領域を書き出す」「フォレンジック: スラックを書き出す」 |

**概要**: ファイルシステムの割り当て情報をもとに、Hex ビュー上で空き (未割り当て) 領域、ファイルスラック、ボリュームスラック、ファイルシステムのメタデータを色と模様で区別して表示する。これらの領域を 1 つのファイルとして書き出せる。

**仕様**:

1. 区別する領域:

   | 領域 | 定義 |
   | --- | --- |
   | メタデータ | ブートセクタ、FAT、$MFT、inode テーブル、ビットマップなど、ファイルシステム自身の構造 |
   | ファイルのデータ | ファイルに割り当てられ、ファイルサイズ以内のバイト |
   | RAM スラック | ファイルの末尾から、その末尾を含むセクタの終わりまで |
   | ドライブスラック | RAM スラックの後ろから、そのクラスタの終わりまで |
   | 未割り当て | 割り当てビットマップ・FAT で空きとされているクラスタ |
   | ボリュームスラック | ファイルシステムの終わりからパーティションの終わりまで |
   | パーティションの隙間 | パーティションに属さないディスク上の領域 (ディスクのドキュメントのとき) |

2. 強調は、背景色に加えて模様 (スラックは斜線、未割り当ては点) と、行の左端の印で示す。ハイコントラストテーマでは模様と印だけで区別できるようにする。色は設定で変更できる。凡例を Hex ビューの右上に表示できる (既定は表示)。
3. 強調は既定ではオフ。ファイルシステムを解析しているドキュメントでだけ使える。
4. 強調の判定に逆引き表 (FOR-15) は使わない。割り当てビットマップと、表示中の範囲に含まれるファイルの末尾の位置から求める。ファイルスラックの判定には各ファイルの末尾クラスタの一覧が必要なため、初回はこの一覧を作る長時間処理を行い、完了するまではスラックの強調を出さない (InfoBar で「スラックの位置を計算中」と表示する)。
5. 「未割り当て領域を書き出す」: 未割り当てクラスタを順につないで 1 つのファイルに書き出す。同時に、書き出したファイルのオフセットと元のディスク上のオフセットの対応表 (`.map.csv`) を作る。書き出しを開かずに、仮想ドキュメントとして開くこともできる (「未割り当て領域を別タブで開く」)。このタブでは元の位置がステータスバーに表示される。
6. 「スラックを書き出す」: 全ファイルのスラック (RAM スラックとドライブスラック) を同じ形式で書き出す。対応表には元のファイルのパスも入れる。
7. 未割り当て領域とスラックは、検索 (04)・文字列の抽出・カービング (FOR-19) の対象範囲として選べる。

**画面**: Hex ビューの強調と凡例。書き出しのダイアログ (出力先、対応表を作るか)。

**巨大ファイル・長時間処理**: 末尾クラスタの一覧の作成と書き出しは長時間処理。強調の描画は表示中の範囲だけを判定し、スクロール性能 (00 の 11.1) を落とさない。

**エラー**: 割り当て情報を読めない (ビットマップの破損など): 強調を無効にし、理由を InfoBar で示す。

**受け入れ基準**:

- [ ] テスト用 NTFS イメージで、サイズ 100 バイトのファイルの末尾クラスタに RAM スラックとドライブスラックが別の模様で表示される。
- [ ] ハイコントラストテーマで、色を使わずに各領域を区別できる。
- [ ] 未割り当て領域を書き出したファイルのサイズが、空きクラスタ数 × クラスタサイズと一致する。
- [ ] 対応表を使って、書き出したファイル上の任意の位置から元のディスク上の位置を求められる。

### FOR-17 削除されたエントリの表示と復元

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | FOR-09 のブラウザの「削除されたファイル」フォルダ。メニュー: フォレンジック → ファイルシステム → 削除されたファイルを探す。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: 削除されたファイルを探す」 |

**概要**: ファイルシステムに残っている削除済みのエントリ (MFT レコード、ディレクトリエントリ、inode、インデックススラック) を列挙し、復元できる見込みを示した上で、内容を開く・書き出す。

**仕様**:

1. 形式ごとの対象: NTFS (使用中フラグが 0 の MFT レコード、インデックススラックのエントリ)、FAT (`E5` のエントリ)、exFAT (使用中ビットが 0 のエントリセット)、ext (dtime のある inode、ディレクトリエントリの余り)、HFS+・APFS (対象外。未決定)、UDF (対象外)。
2. 一覧の列は FOR-09 と同じものに、「元のパス」(親ディレクトリから求めたもの。親も削除されていれば分かる範囲で)、「状態」を加える。
3. 状態 (復元の見込み):

   | 状態 | 条件 |
   | --- | --- |
   | 良好 | データのクラスタがすべて未割り当てのまま |
   | 一部上書き | データのクラスタの一部が他のファイルに割り当てられている |
   | 上書き済み | データのクラスタがすべて他のファイルに割り当てられている |
   | 位置不明 | データの位置情報が残っていない (ext3/4 など) |
   | 常駐 | データが MFT レコード内に残っている (NTFS) |

4. FAT・exFAT で FAT のチェーンが消えている場合は、先頭クラスタからファイルサイズ分の連続したクラスタと仮定して読む。この仮定を詳細欄に明記する。
5. 「ファイルを別タブで開く」「ファイルを書き出す」は FOR-09 と同じ。書き出しのマニフェストに状態の列を加える。「上書き済み」のファイルを書き出す場合は、内容が他のファイルのものである可能性を確認ダイアログで示す (ボタン「書き出す」「キャンセル」)。
6. ファイルシステムに書き込んで削除を取り消す (エントリを使用中に戻す) 機能は持たない。

**画面**: FOR-09 のブラウザ。

**巨大ファイル・長時間処理**: 削除エントリの列挙はメタデータ全体の走査で、長時間処理。見つかった順に一覧に追加する。

**エラー**: FOR-09 と同じ。

**受け入れ基準**:

- [ ] ファイルを削除した直後のテスト用 NTFS・FAT32・exFAT イメージで、そのファイルが状態「良好」で表示され、書き出した内容が元のファイルと一致する。
- [ ] 削除後に別のファイルで上書きしたイメージで、状態が「上書き済み」または「一部上書き」になる。
- [ ] ファイルシステムに書き込む操作が提供されていない (メニューに出ない)。

## カービング

### FOR-18 カービング用のシグネチャ定義

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-05 |
| 呼び出し | メニュー: フォレンジック → カービング → シグネチャの管理。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: カービングのシグネチャを管理」 |

**概要**: ファイルの切り出し (カービング) に使うファイル形式の定義 (ヘッダー・フッター・最大サイズなど) を一覧で管理し、追加・編集・読み込み・書き出しを行う。

**仕様**:

1. 定義は JSON ファイル (`carving-signatures.json`、設定フォルダ) に保存する。組み込みの定義は別に持ち、編集はできないが、無効にすることと、複製して編集することはできる。
2. 1 つの定義の項目:

   | 項目 | 内容 | 既定値 |
   | --- | --- | --- |
   | 名前 | 表示名 | 必須 |
   | 拡張子 | 書き出すときの拡張子 | 必須 |
   | ヘッダー | Hex バイト列 (00 の 6.3。`??` と `?` のワイルドカード可)。複数指定可 | 必須 |
   | ヘッダーの位置 | ファイル先頭からヘッダーまでのオフセット (例: MP4 の `ftyp` は 4) | 0 |
   | フッター | Hex バイト列。なくてもよい | なし |
   | フッターを含める | フッターの後ろに何バイト含めるか | フッターの長さ |
   | 最大サイズ | フッターが見つからない場合に切り出す長さ、およびフッターを探す範囲の上限 | 10 MiB |
   | 最小サイズ | これより小さいものは結果に含めない | 0 |
   | サイズの取得 | ヘッダー内の値からサイズを求める規則 (オフセット、型 (8〜64 bit)、エンディアン、加える値)。指定するとフッターより優先する | なし |
   | 構造の検証 | 構造体テンプレート (07) の名前。指定すると、テンプレートの解析が成功したものだけを結果に含め、解析結果の終端をサイズとする | なし |
   | セクタ境界のみ | ヘッダーをセクタの先頭でだけ探す | オン |
   | 有効 | スキャンに使うか | オン |

3. 組み込みの定義: JPEG、PNG、GIF、BMP、TIFF、PDF、ZIP (DOCX・XLSX・PPTX・JAR・APK を含む)、RAR (4 / 5)、7z、GZIP、BZIP2、MP3 (ID3)、MP4 / MOV、AVI、WAV、SQLite、PE (EXE / DLL)、ELF、OLE 複合ドキュメント (DOC・XLS・MSG)、Windows レジストリハイブ、EVTX、LNK、RTF、HTML、XML。各定義はサイズの取得または構造の検証を使い、フッターだけに頼らないものを優先する。
4. 定義の JSON ファイルを読み込み・書き出しできる。読み込み時に不正な定義 (ヘッダーが空、Hex の書式誤り、最大サイズが最小サイズ未満) があれば、その定義を名前と理由付きで示し、他の定義だけを取り込む。
5. 定義の編集画面で、開いているドキュメントの選択範囲を対象に「この定義で試す」を実行し、見つかった件数と最初の 10 件の位置を表示できる。

**画面**: シグネチャの管理ダイアログ (左に定義の一覧、右に編集欄)。入力欄は 00 の 9 章の入力欄 (サイズは入力式を受け付ける)。

**巨大ファイル・長時間処理**: 「この定義で試す」は選択範囲を対象とし、長時間処理として扱う。

**エラー**: 入力の誤りは入力欄の赤枠と説明で示し、保存ボタンを無効にする。

**受け入れ基準**:

- [ ] 新しい定義をヘッダー `CA FE BA BE`、最大サイズ `1M` で作り、保存後の再起動でも残っている。
- [ ] 組み込みの定義は編集できず、複製すると編集できる。
- [ ] 不正な定義を含む JSON を読み込むと、不正なものだけが理由付きで除外される。

### FOR-19 カービングの実行

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-05 |
| 呼び出し | メニュー: フォレンジック → カービング → ファイルを切り出す。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: ファイルを切り出す」。Hex ビューの右クリックメニュー (選択範囲があるとき) |

**概要**: 指定した範囲をシグネチャ (FOR-18) で走査し、見つかったファイルを一覧にして、指定フォルダに書き出す。

**仕様**:

1. 入力:
   - 対象範囲: ドキュメント全体 (既定)、選択範囲、未割り当て領域のみ (FOR-16。ファイルシステムを解析している場合)、スラックのみ。
   - 使う定義 (既定は有効なものすべて)。
   - 見つけたファイルの内側をスキップする (既定オフ。オンにすると、切り出した範囲の中では次のヘッダーを探さない)。
   - 書き出し先フォルダ (ケースがあれば既定は `exports/carved/`)。「一覧だけ作り、書き出さない」も選べる (既定は書き出す)。
2. 走査はチャンク単位で行い、境界には最長のヘッダー長 - 1 バイトを重ねる (検索 04 と同じ方式)。セクタ境界のみの定義は、各セクタの先頭 (ヘッダーの位置を引いた位置) だけを比べる。
3. 切り出す長さの決め方は、構造の検証 → サイズの取得 → フッター → 最大サイズ の順に、定義にあるものを使う。最大サイズは対象範囲の終わりで切る。
4. 書き出すファイルの名前は `<種類>/<開始オフセット 16 進 16 桁>.<拡張子>` (例: `jpeg/00000001A2B3C400.jpg`)。同時に、`carving-manifest.csv` (番号、種類、開始オフセット、開始 LBA、長さ、長さの決め方、MD5、SHA-256、書き出し先) を作る。
5. 結果は結果一覧に表示する。行の選択で開始位置へジャンプし、範囲を選択する。画像の形式 (JPEG・PNG・GIF・BMP) は、詳細欄に縮小表示する (設定でオフにできる)。
6. 断片化したファイルの再構成は行わない。
7. 開始と終了、件数、マニフェストのハッシュは監査ログに記録する。

**画面**: カービングのダイアログ (範囲、定義の選択、オプション、書き出し先)。結果一覧パネル (既定は下) と詳細欄。

**巨大ファイル・長時間処理**: 長時間処理。進捗、速度、残り時間、種類ごとの件数を処理センターに表示する。目標は単純なバイト列検索と同じ (00 の 11.1 の検索の目標の 50% 以上)。書き出しは走査と並行して行う。キャンセルしてもそれまでの結果とマニフェストは残す。結果が 100 万件を超えても一覧は表示できる。

**エラー**:

- 書き出し先の空き容量が不足した: 走査を一時停止し、「空き容量が不足しています」と表示して、書き出し先の変更か中止を選ばせる。
- 読み込みエラー: そのチャンクを飛ばし、読めなかった範囲をマニフェストの末尾に記録する。
- 書き出し先が対象と同じディスク: 共通の前提「出力先の検査」に従い、開始しない。

**受け入れ基準**:

- [ ] JPEG・PNG・PDF・ZIP を連続して埋め込んだテスト用イメージで、4 つのファイルが見つかり、書き出したファイルのハッシュが元のファイルと一致する。
- [ ] 未割り当て領域のみを対象にすると、既存のファイルの中にある JPEG は見つからない。
- [ ] 100 GB のイメージで UI が固まらず、途中でキャンセルしてもマニフェストが残る。
- [ ] 書き出し先が対象と同じディスクの場合、開始できない。

## イメージとクローン

### FOR-20 ディスクイメージの作成

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-03 |
| 呼び出し | メニュー: フォレンジック → イメージ → イメージを作成。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: イメージを作成」。パーティションパネル・証拠パネルの右クリックメニュー |

**概要**: 物理ディスク・ボリューム・パーティション・開いているドキュメントの範囲を、raw (dd) 形式 (分割可) または E01 形式のイメージファイルとして取得する。取得と同時にハッシュを計算し、取得後に検証できる。

**仕様**:

1. 入力元: 物理ディスク、論理ボリューム、パーティション、開いているドキュメントの全体または選択範囲 (セクタ境界に広げる)。入力元は読み取り専用で開く。書き込み保護モード (FOR-01) が無効なら、開始前に「書き込み保護モードを有効にする」を提案する。
2. 出力形式:

   | 形式 | 内容 |
   | --- | --- |
   | raw | 1 つのファイル (`.dd`、`.raw`、`.img`)。読めなかったセクタは指定の値で埋める |
   | 分割 raw | 指定サイズごとのファイル (`名前.001`、`名前.002` …)。分割サイズの既定は 2 GiB |
   | E01 | EnCase 6 互換の Expert Witness 形式。セグメントは `.E01`〜`.E99`、続けて `.EAA`〜`.ZZZ`。セグメントサイズの既定は 2 GiB |

3. 共通のオプション:
   - ハッシュ: MD5、SHA-1、SHA-256 から複数選択 (既定は MD5 と SHA-256)。取得中に読み込んだデータからその場で計算する (読み直さない)。
   - 読み込みエラー時の再試行回数 (既定 3)。再試行しても読めない場合、読み込み単位を 1 セクタまで小さくして読める部分を取り、読めないセクタは 0 (設定で変更可) で埋める。読めなかったセクタの範囲を記録する。
   - 読み込み単位 (既定 1 MiB)。
   - 取得後に検証する (既定オン。FOR-22)。
4. E01 のオプション:
   - ケース情報: ケース番号、証拠番号、調査者名、説明、メモ (ケースがあれば FOR-03 の値を初期値にする)。
   - 圧縮: なし / 速度優先 (zlib レベル 1) / 容量優先 (zlib レベル 9)。既定は速度優先。
   - チャンクサイズ: 64 セクタ (32 KiB) 固定。
   - 取得した MD5 と SHA-1 を E01 の hash / digest セクションに書く。読めなかったセクタの範囲を error2 セクションに書く。
   - E01 の書き込みは libewf (仕様 8) で行う (セクション: header、header2、volume、table、table2、sectors、error2、hash、digest、done / next)。Ex01 (EnCase 7 以降の形式) の書き込みは対象外。
5. 取得の記録: 出力先に `<名前>.txt` (取得ログ) を作る。内容は、入力元 (モデル名、シリアル番号、容量、セクタサイズ、パス)、出力形式とファイル一覧、開始・終了日時 (UTC とローカル)、読み込んだセクタ数、読めなかったセクタの範囲、各ハッシュ値、検証結果、アプリのバージョン、ケース情報。同じ内容を監査ログに記録し、ケースがあれば証拠一覧に「取得時のハッシュ」として登録する。
6. 出力先は共通の前提「出力先の検査」に従う。raw は容量 + 1 MiB、E01 は圧縮なしと同じ容量を空き容量の目安として確認する (E01 で圧縮する場合は不足しても警告にとどめ、開始できる)。
7. 取得中、入力元のディスクの他のタブは開いたまま閲覧できる (読み込みだけなので)。
8. E01 の読み書き (この機能と FOR-21、FOR-22、FOR-23) には libewf (LGPL-3.0) を使う。LGPL-3.0 の条件を満たすため、次のように配布する。
   - libewf はアプリ本体と分けた DLL (`libewf.dll`) として同梱し、実行時に動的に読み込む。静的リンクはしない。
   - 利用者が DLL を同じ API の別のビルドに差し替えても動くようにする (DLL の署名やハッシュの照合で差し替えを拒否しない)。
   - x64 版と ARM64 版のそれぞれに、そのアーキテクチャ向けのネイティブビルドの DLL を同梱する。DLL は CI で libewf のソースからビルドする (10 の PKG-24)。
   - バージョン情報の「サードパーティのライセンス」(09 の UI-40) に、LGPL-3.0 の全文と、使った版の libewf のソースコードへのリンクを載せる。
   - DLL を読み込めない場合は、E01 の作成と読み込みを無効にし、「E01 を扱うライブラリ (libewf) を読み込めません」と表示する。raw と分割 raw は影響を受けない。

**画面**: イメージ作成のダイアログ (入力元の選択、出力形式、出力先と名前、分割サイズ、ハッシュ、エラー時の動作、E01 の情報)。処理センターの項目。完了時の InfoBar (ハッシュ値と「取得ログを開く」ボタン)。

**巨大ファイル・長時間処理**: 長時間処理。進捗 (読んだバイト数 / 全体)、速度、残り時間、読めなかったセクタ数を処理センターに表示する。読み込み・ハッシュ計算・圧縮・書き込みは並列に行い、目標は入力元の読み込み速度の 90% 以上 (圧縮なしの場合)。メモリ使用量は読み込み単位 × 並列数に限る。キャンセルした場合は、出力済みのファイルを残すか削除するかを選ばせ、取得ログに「中断」と書く。

**エラー**:

- 出力先の書き込みエラー・容量不足: 処理を一時停止し、「再試行」「中止」を選ばせる。
- 入力元が取り外された: 中止し、取得ログに「入力元が失われました」と書く。
- 読み込みエラー: 仕様 3 のとおり。完了時に読めなかったセクタ数を警告として示す。

**受け入れ基準**:

- [ ] 1 GiB のテスト用ディスクイメージを入力元として raw で取得すると、出力のハッシュが入力元のハッシュと一致する。
- [ ] 分割サイズ `100M` で取得すると、`.001`〜`.011` ができ、連結したものが入力元と一致する。
- [ ] E01 で取得したイメージを本アプリ (FOR-21) で開け、格納された MD5 と内容の MD5 が一致する。基準の検証として、libewf の `ewfverify` で検証が成功する (格納された MD5 と計算した MD5 が一致する)。互換性の確認として、FTK Imager でも開ける。
- [ ] 読めないセクタを含む仮想ディスク (テスト用のデータソース) で、該当セクタが 0 で埋められ、取得ログと E01 の error2 にその範囲が記録される。
- [ ] 取得中にキャンセルでき、取得ログに「中断」と書かれる。

### FOR-21 イメージをディスクとして開く

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-03 |
| 呼び出し | メニュー: フォレンジック → イメージ → イメージを開く。メニュー: ファイル → 開く (Ctrl+O。拡張子で自動判定)。ファイル → 詳細を指定して開く… の「ディスクイメージとして開く」(ENG-31)。コマンドパレット: 「フォレンジック: イメージをディスクとして開く」。このコマンド自体のショートカットは既定なし |

**概要**: raw・分割 raw・E01 のイメージを、物理ディスクと同じように (セクタサイズを持ち、パーティション解析ができるドキュメントとして) 開く。単一ファイルの raw イメージをセクタサイズを指定して開く処理は ENG-31 が定め、この機能は分割 raw と E01 の読み込み、イメージの情報の表示を加える。

**仕様**:

1. 対応形式: raw (`.dd` `.raw` `.img` `.bin` `.iso` ほか任意)、分割 raw (`.001` を選ぶと `.002` 以降を自動で連結。連番が途切れたらそこまで)、E01 (`.E01` を選ぶと残りのセグメントを自動で探す)。
2. 「ファイル → 開く」で `.E01` `.001` を開いた場合は自動でイメージとして開く。他の拡張子はファイルとして開き、ENG-31 の仕様 6 の InfoBar、またはファイルのタブの右クリックメニュー「ディスクイメージとして開き直す」で切り替えられる。
3. 開くときのオプション: セクタサイズ (ENG-31 の仕様 1 と同じ選択肢。E01 は格納された値)、読み取り専用 (raw と分割 raw は既定でオン (ENG-14)。書き込み保護モードでは常にオン。E01 は常に読み取り専用)。
4. 開いたイメージのドキュメントは、ディスクのドキュメントと同じ機能 (パーティション解析 FOR-06、ファイルシステム FOR-09、セクタ表示、LBA への移動) を使える。
5. E01 を開くと、格納されたケース情報、取得日時、取得ツール、チャンク数、圧縮の有無、格納されたハッシュを「イメージの情報」に表示する。error2 セクションの範囲は、Hex ビュー上で「取得時に読めなかったセクタ」として強調する。
6. E01 の各チャンクの Adler-32 を読み込み時に検証し、不一致のチャンクは読み込みエラーとして扱う (内容は 0 で表示し、ステータスバーと InfoBar で知らせる)。
7. 読み込みは要求された範囲のチャンクだけを展開する。展開済みのチャンクはブロックキャッシュ (ENG-06) に載せる。
8. E01 の読み込みには libewf を使う (配布の条件は FOR-20 の仕様 8)。libewf を読み込めない場合、E01 は開けず、raw と分割 raw だけを開ける。

**画面**: 開くときのダイアログ (セクタサイズ、読み取り専用)。イメージの情報パネル (またはダイアログ)。

**巨大ファイル・長時間処理**: 開く処理はセグメントのヘッダーとテーブルの読み込みだけで、00 の 11.1 の「1 秒以内に先頭を表示」を満たす。E01 のテーブルが大きい (数 TB のイメージ) 場合は、テーブルを必要な範囲だけ読む。

**エラー**:

- セグメントが足りない: 足りないセグメント名を示し、「ある分だけ開く」(足りない範囲は読み込みエラー扱い) と「キャンセル」を選ばせる。
- 形式が壊れている: 「E01 のヘッダーを読み込めません」など、どの部分で失敗したかを示す。

**受け入れ基準**:

- [ ] FOR-20 で作った E01 (libewf の `ewfverify` で検証が成功するもの) と、FTK Imager で作った E01 の両方を開け、内容のハッシュが格納されたハッシュと一致する。
- [ ] `.001` を開くと、全セグメントが 1 つのドキュメントとして連結される。
- [ ] 1 TB の E01 を開いて 1 秒以内に先頭が表示される。
- [ ] E01 のチャンクを 1 バイト壊すと、そのチャンクの範囲が読み込みエラーとして示される。

### FOR-23 スケルトンイメージとスパースイメージ

**巨大ファイル・長時間処理**: 含める範囲だけを読む。範囲の計算 (ビットマップの読み込み) も長時間処理に含める。

**エラー**: ファイルシステムを解析できないパーティションでは、スパース・スケルトンの選択時に「このパーティションは全体を含めます」と表示する。

**受け入れ基準**:

- [ ] 使用率 10% の NTFS パーティションのスパース raw イメージが、NTFS 上で実際の使用量が約 10% になる。

**概要**: 入力元 (ディスク、イメージ、パーティション) の内容を、別の物理ディスクへセクタ単位でそのまま書き込む。

- [ ] テスト用の仮想ディスク (VHD を OS でアタッチしたもの) へイメージをクローンすると、検証が「一致」になる。

### FOR-25 セクタ範囲の保存と復元

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-07 |
| 呼び出し | メニュー: フォレンジック → イメージ → セクタ範囲を保存 / セクタ範囲を復元。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: セクタ範囲を保存」「フォレンジック: セクタ範囲を復元」。Hex ビューの右クリックメニュー (ディスクのドキュメントで選択範囲があるとき) |

**概要**: ディスクの指定したセクタ範囲 (MBR、GPT、ブートセクタなど) をファイルに保存し、後で同じ位置 (または指定した位置) に書き戻す。パーティション表を修復する前の退避などに使う。

**仕様**:

1. 保存: 開始 LBA と セクタ数 (または選択範囲。セクタ境界に広げる) を入力し、ファイルに保存する。入力欄は入力式を受け付け、`sector` `sel.start` `sel.len` などの名前を使える (00 の 6.2)。保存すると、データファイル (`.bin`) と付随ファイル (`.bin.json`: 入力元のディスクのモデル名・シリアル番号・容量・セクタサイズ、開始 LBA、セクタ数、保存日時 (UTC)、SHA-256) を作る。
2. 復元: データファイルを選ぶと付随ファイルを読み、書き込み先 (既定は付随ファイルの開始 LBA)、書き込み先のディスクを表示する。
   - 付随ファイルのディスクと書き込み先のディスクのシリアル番号・容量が違う場合は警告し、確認ダイアログに含める。
   - データファイルの SHA-256 が付随ファイルの値と合わない場合は実行しない。
   - 付随ファイルがない場合は、書き込み先の開始 LBA を利用者が入力する。
3. 復元前の退避 (既定オン): 書き込む範囲の現在の内容を、同じ形式で `<名前>.before-<日時>.bin` に保存してから書く。
4. 復元の確認: 確認ダイアログ (共通の前提) を出す。範囲がディスク全体またはパーティション全体に及ぶ場合は強い確認にする。ボタンは「N セクタを書き込む」と「キャンセル」。
5. 書き込みは、範囲に重なるボリュームをロックしてから行う。書き込み後に読み直してデータファイルと比べ、結果を表示する。
6. 書き込み保護モードでは復元は無効。保存はできる。
7. 保存・復元は監査ログに記録する。

**画面**: 保存のダイアログ (開始 LBA、セクタ数、出力先)。復元のダイアログ (データファイル、付随ファイルの内容、書き込み先、退避するか)。

**巨大ファイル・長時間処理**: 範囲が大きい場合 (既定で 64 MiB 以上) は長時間処理として処理センターに出す。

**エラー**: 書き込みエラー: 書き込めた範囲と失敗した LBA を示し、退避ファイルからの書き戻しを提案する。

**受け入れ基準**:

- [ ] テスト用ディスクの LBA 0〜33 を保存し、GPT を壊した後に復元すると、パーティションが元どおりに認識される。
- [ ] 復元前の退避ファイルが作られ、その内容が書き込み前の範囲と一致する。
- [ ] データファイルを 1 バイト変えると、ハッシュの不一致で復元が拒否される。

### FOR-27 HPA / DCO の検出

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | メニュー: フォレンジック → デバイス → HPA / DCO の確認。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: HPA と DCO を確認」。ディスクを開いたときの自動確認 (設定。既定オン) |

**概要**: ATA ディスクの隠し領域 (HPA: Host Protected Area、DCO: Device Configuration Overlay) があるかを調べ、OS から見える容量と実際の容量の差を報告する。

**仕様**:

1. 補助プロセス (ENG-28 の `QueryDeviceInfo`) から ATA パススルー (`IOCTL_ATA_PASS_THROUGH`) で次のコマンドを送る (いずれも読み取りだけのコマンド。00 の 11.4 の「読み取り専用のデバイス情報の取得」)。

2. 結果: 3 つの最大 LBA と、HPA の有無・サイズ、DCO の有無・サイズを表示する。HPA・DCO がある場合は InfoBar で知らせる。
3. HPA・DCO の解除 (SET MAX ADDRESS、DEVICE CONFIGURATION RESTORE) は行わない。デバイスの設定を変える操作であり、対象外とする。
4. NVMe のディスクは HPA・DCO を持たないため、名前空間のサイズと容量を表示し、「HPA / DCO は該当しません」と示す。
5. USB 変換などでコマンドが通らない場合は「このデバイスでは確認できません」と表示する。
6. 結果は監査ログに記録し、レポート (FOR-33) に含められる。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 昇格を拒否された: 「管理者権限が必要です」。補助プロセスも管理者権限も使えない (管理者として実行していない Store 版など): ENG-28 の仕様 12 の案内ダイアログ。コマンドの失敗: ATA のステータスとエラーレジスタの値を表示する。

**受け入れ基準**:

- [ ] HPA を設定した SATA ディスク (テスト機材) で、HPA の有無とサイズが表示される。
- [ ] USB 接続のディスクでコマンドが通らない場合に、例外にならず「確認できません」と表示される。

### FOR-28 SMART 情報

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | メニュー: フォレンジック → デバイス → SMART 情報。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: SMART 情報を表示」 |

**概要**: ディスクの SMART (自己診断) 情報を取得して表示し、レポートに含める。取得の前にディスクの状態を記録する目的で使う。

**仕様**:

1. 取得は補助プロセス (ENG-28 の `QueryDeviceInfo`) で行う。ATA / SATA: SMART READ DATA と READ THRESHOLDS で属性の一覧を取得する。列は ID、名前 (主要な属性は名前で表示。不明なものは「不明」)、現在値、最悪値、閾値、生の値 (16 進と 10 進)、状態 (閾値を下回っていれば「注意」)。
2. NVMe: SMART / Health Information (ログページ `02h`) を `IOCTL_STORAGE_QUERY_PROPERTY` で取得する。項目は警告ビット、温度、残りの予備領域、使用率、読み書きしたデータ量、電源投入回数・時間、異常終了の回数、メディアのエラー数など。
3. デバイス情報: モデル名、シリアル番号、ファームウェアのバージョン、容量、セクタサイズ (論理・物理)、接続の種類、回転数 (分かる場合)、TRIM 対応の有無。
4. 取得日時 (UTC) とともに表示し、テキスト・JSON に書き出せる。ケースがあれば監査ログに記録する。
5. SMART のセルフテストの実行は行わない (デバイスの状態を変えるため対象外)。

**画面**: デバイス情報パネル (FOR-27 と共通) の「SMART」タブ。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 取得できない場合は理由 (SMART 無効、USB 変換で非対応など) を表示する。

**受け入れ基準**:

- [ ] SATA SSD と NVMe SSD (テスト機材) で、それぞれの項目が表示される。
- [ ] 書き出した JSON に取得日時 (UTC) とシリアル番号が含まれる。

### FOR-29 暗号化ボリュームの検出

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | パーティション解析 (FOR-06)・ファイルシステムの判定 (FOR-09) のときに自動。コマンドパレット: 「フォレンジック: 暗号化の情報を表示」。ショートカット: 既定なし |

**概要**: BitLocker などの暗号化されたボリュームを検出し、暗号化のメタデータ (方式、保護機能の種類など) を表示する。復号はしない。

**仕様**:

1. BitLocker:
   - ボリュームの先頭の 3 バイト目の `-FVE-FS-` (BitLocker To Go を含む)、または `MSWIN4.1` と FVE メタデータの位置情報で判定する。
   - ボリュームヘッダーにある 3 つの FVE メタデータブロックの位置を読み、メタデータブロック (`-FVE-FS-` 署名) を解析する。表示する項目: バージョン、暗号化方式 (AES-CBC 128/256、AES-XTS 128/256 など)、ボリュームの GUID、作成日時、説明 (コンピューター名と日付)、キー保護機能の一覧 (種類 (TPM、回復パスワード、スタートアップキー、パスワードなど)、GUID、作成日時)、暗号化の状態 (完了 / 進行中 / 一時停止)、暗号化済みの範囲 (分かる場合)。
   - 3 つのメタデータブロックの内容が食い違う場合は警告する。
2. その他の検出 (判定と名前の表示だけ):

   | 種類 | 判定 |
   | --- | --- |
   | LUKS (1 / 2) | 先頭の `LUKS BA BE` とバージョン。暗号方式、UUID、キースロットの数を表示 |
   | APFS の暗号化ボリューム・FileVault 2 | APFS ボリュームのフラグ (FOR-13) |
   | Core Storage | GPT の種類 GUID |
   | VeraCrypt / TrueCrypt | 署名がないため判定できない。ファイルシステムの署名がなく、先頭 64 KiB のエントロピー (06) が 7.9 ビット / バイト以上のパーティションに「暗号化または圧縮されたデータの可能性」と表示するだけ |

3. 復号は対象外。ただし BitLocker のボリュームが Windows によってロック解除されている場合は、論理ボリューム (`\\.\X:`) を開けば OS が復号した内容を読めることを、詳細欄に案内として表示し、「論理ボリュームとして開く」のボタンを出す (該当するドライブ文字が見つかった場合だけ)。
4. 暗号化されたボリュームでは、ファイルシステムブラウザ (FOR-09) を「暗号化されています」と表示して開かない。

**画面**: パーティションパネルの詳細欄、または「暗号化の情報」ダイアログ。

**巨大ファイル・長時間処理**: 該当なし (メタデータの数セクタだけを読む)。

**エラー**: メタデータブロックが壊れている: 読めた項目だけを表示し、警告を出す。

**受け入れ基準**:

- [ ] BitLocker で暗号化したテスト用の VHD で、暗号化方式とキー保護機能の一覧が表示される。
- [ ] Windows でロック解除済みの BitLocker ボリュームで「論理ボリュームとして開く」が表示され、開くとファイルシステムブラウザが使える。
- [ ] LUKS2 のテスト用イメージで、LUKS2 と表示される。

## 安全な消去

### FOR-30 範囲・ディスクの安全な消去

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-06 |
| 呼び出し | メニュー: フォレンジック → 消去 → 選択範囲を消去 / ディスクを消去。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: 選択範囲を安全に消去」「フォレンジック: ディスクを安全に消去」。Hex ビューの右クリックメニュー (選択範囲があるとき) |

**概要**: ディスク・ボリューム・ファイルの指定範囲、またはディスク全体を、指定した方式で複数回上書きして、元のデータを読めなくする。

**仕様**:

1. 対象: 選択範囲 (ファイル・ディスク・ボリュームのドキュメント。ディスクではセクタ境界に広げ、広げた範囲を確認ダイアログに示す)、ディスク全体。ファイル単位の安全な削除 (内容を上書きしてからファイルを削除する) は TOOL-17 で定める (00 の 1.1)。
2. 方式: TOOL-17 の仕様 2 の方式 (0 で 1 回 (既定)、乱数で 1 回、DoD 5220.22-M (3 回)、任意) と同じ。

3. オプション「最後に読み直して検証する」(既定オン): 最後の回のパターンと一致するかを読み直して確かめる (乱数の場合は書いたデータのハッシュと比べる)。
4. 確認: 確認ダイアログ (共通の前提) を出す。対象、範囲、方式と回数、所要時間の目安を示し、「取り消せません」と書く。ディスク全体の場合は強い確認にする。ボタンは「N バイトを消去する」「ディスク N を消去する」など。
5. SSD・フラッシュメディアでは、ウェアレベリングのため上書きで元のデータが消える保証がないことを、確認ダイアログに表示する (ディスクの種類が SSD と分かる場合。TOOL-17 の仕様 5 と同じ限界)。ATA Secure Erase・NVMe Format・Sanitize の実行は対象外。
6. ディスクへの書き込みは、範囲に重なるボリュームをロックしてから行う。ファイルが対象の場合は、データエンジンを通さずにファイルの該当範囲を直接書き換える (Undo できない)。消去の後、開いているドキュメントの該当範囲のキャッシュを捨てて読み直す。
7. 消去中の範囲を持つドキュメントの未保存の編集は、消去前に「保存」「破棄」を選ばせる (未保存の編集がある範囲を消去しない)。
8. 書き込み保護モード、または証拠一覧のデータソースが対象の場合は実行しない。
9. 対象、範囲、方式、結果を監査ログに記録する。

**画面**: 消去のダイアログ (対象、範囲の入力欄、方式、回数・パターン、検証のチェックボックス)。確認ダイアログ。

**巨大ファイル・長時間処理**: 長時間処理。回ごとの進捗、速度、残り時間 (全回数分) を表示する。キャンセルの確認で「途中までの範囲は上書き済みで、残りは元のままです」と示す。

**エラー**: 書き込みエラー: 失敗した位置を記録し、残りを続けるか中止するかを選ばせる。完了時に書けなかった範囲を表示する。検証の不一致: 不一致の範囲を表示する。

**受け入れ基準**:

- [ ] テスト用の仮想ディスクで「乱数で 1 回」を実行した後、範囲内に元のデータのパターンが見つからない。
- [ ] DoD 方式で 3 回分の進捗が表示され、検証が成功する。
- [ ] ディスク全体の消去で強い確認が出て、対象名を入力しないと実行できない。
- [ ] 書き込み保護モードではメニューが無効になる。

### FOR-31 空き領域とスラックの消去

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F5-06 |
| 呼び出し | メニュー: フォレンジック → 消去 → 空き領域を消去 / スラックを消去。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: 空き領域を消去」「フォレンジック: ファイルスラックを消去」 |

**概要**: ボリュームの空き領域 (未割り当てクラスタ) と、ファイルのスラック領域を上書きして、削除済みのデータの残りを消す。

**仕様**:

1. 空き領域の消去には 2 つの方法がある。
   - OS 経由 (既定。マウント中のボリューム): ボリューム上に一時フォルダを作り、空き容量がなくなるまで指定パターンのファイルを書き、最後に削除する。小さいファイルも多数作って、MFT の空きレコードに常駐していたデータも上書きする (NTFS)。ボリュームのロックは不要で、他のアプリと並行して実行できるが、実行中は空き容量がなくなることを確認ダイアログに示す。
   - 直接書き込み: ファイルシステムの割り当て情報 (FOR-16) から未割り当てクラスタを求め、ボリュームをロックしてクラスタを直接上書きする。NTFS、FAT12/16/32、exFAT に対応する。ロックできない (システムボリュームなど) 場合は実行しない。
2. スラックの消去: ボリュームをロックし、各ファイルの末尾クラスタのファイル末尾以降 (RAM スラックとドライブスラック) を直接上書きする。NTFS、FAT12/16/32、exFAT に対応する。圧縮・スパース・常駐のファイルは対象外とし、件数を表示する。
3. 方式 (パターンと回数) は TOOL-17 の仕様 2 と同じ。
4. 確認: 確認ダイアログを出す。対象のボリューム (ドライブ文字、ラベル、ファイルシステム)、消去する容量、方法、方式、所要時間の目安、直接書き込みの場合は「ファイルシステムの割り当て情報が正しくないと、ファイルを壊すおそれがあります」を示す。直接書き込みの前には、ファイルシステムに不整合がないか (NTFS の dirty フラグなど) を確かめ、不整合があれば実行しない (「chkdsk で修復してから実行してください」)。
5. 書き込み保護モード、または証拠一覧のデータソースが対象の場合は実行しない。
6. 結果 (上書きした容量、対象外にしたファイルの数、所要時間) を表示し、監査ログに記録する。

**画面**: 消去のダイアログ (対象ボリューム、空き領域 / スラック、方法、方式)。確認ダイアログ。

**巨大ファイル・長時間処理**: 長時間処理。キャンセルした場合、OS 経由の方法では作った一時ファイルを必ず削除する。直接書き込みはクラスタ単位で区切りのよいところで止める。

**エラー**: OS 経由の方法で一時ファイルを削除できなかった: パスを示して手動での削除を求める。直接書き込み中のエラー: 中止し、位置を示す。

**受け入れ基準**:

- [ ] 削除済みファイルの内容が未割り当て領域に残っているテスト用ボリュームで、空き領域の消去 (両方の方法) の後、その内容が見つからない。
- [ ] スラックの消去の後、既存のファイルの内容 (ハッシュ) が変わらず、スラックが指定パターンになっている。
- [ ] OS 経由の方法をキャンセルすると、一時ファイルが残らない。
- [ ] dirty フラグの立った NTFS では直接書き込みが実行されない。

### FOR-32 ファイルシステムを理解した墨塗り

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | ファイルシステムブラウザの右クリックメニュー「ファイルの内容を墨塗り」。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: ファイルの内容を墨塗り」 |

**概要**: ディスクイメージの写しを他者に渡す前に、指定したファイルの内容 (データとスラック) だけを、ファイルシステムの構造を保ったまま指定パターンで上書きする。

**仕様**:

1. 対象: ファイルシステムブラウザで選んだファイル (複数可)。上書きするのは各ファイルのデータの断片とスラック。オプションで名前 (ディレクトリエントリ・MFT の $FILE_NAME) も同じ長さの `_` に置き換えられる (既定オフ)。メタデータ (サイズ、日時、断片の位置) は変えない。
2. 既定の動作は、データエンジン上の編集として行う (保存するまで書き込まない、Undo できる)。編集後、利用者が「名前を付けて保存」で別のイメージファイルとして保存することを前提とする。保存先が元のイメージ・ディスクの場合は、確認ダイアログ (共通の前提) を出す。
3. パターンは TOOL-17 の仕様 2 の方式から 1 回分を選ぶ (既定は `00`)。
4. NTFS の常駐データ (MFT レコード内) も対象とする。圧縮されたファイルは圧縮された断片を上書きする。
5. 墨塗りしたファイルの一覧 (パス、ファイル ID、上書きした範囲) を `redaction-log.csv` として出力し、監査ログに記録する。
6. 書き込み保護モードでは、ドキュメントが読み取り専用 (FOR-01 の仕様 2、EDIT-16) のため実行できない (メニューを無効表示にする)。FOR-01 の仕様 5 のドキュメント単位の例外を設定したドキュメント (証拠一覧に登録されていないもの) では実行できる。

**画面**: 墨塗りのダイアログ (対象ファイルの一覧、パターン、名前も置き換えるか)。

**巨大ファイル・長時間処理**: 塗りつぶしはデータエンジンの塗りつぶしピースで表すため、範囲の大きさに関係なく速い (00 の 11.1)。保存は長時間処理。

**エラー**: 断片の情報が壊れているファイルは対象外にし、理由を一覧に示す。

**受け入れ基準**:

- [ ] テスト用イメージで 1 つのファイルを墨塗りして別名で保存すると、新しいイメージのファイルシステムブラウザでそのファイルの内容がすべて `00` になり、他のファイルのハッシュは変わらない。
- [ ] 墨塗りの直後に Ctrl+Z で元に戻せる。
- [ ] `redaction-log.csv` に上書きした範囲が記録される。

## レポート

### FOR-33 レポートの作成

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | メニュー: フォレンジック → レポートを作成。ショートカット: 既定なし。コマンドパレット: 「フォレンジック: レポートを作成」 |

**概要**: ケースの情報、証拠一覧とハッシュ、取得・検証の記録、解析結果、ブックマークなどをまとめて、HTML または PDF のレポートを作る。

**仕様**:

1. 含める項目 (チェックボックスで選ぶ。既定はすべてオン。該当するデータがない項目は出さない):
   - 表紙: ケース番号、ケース名、調査者名、組織名、作成日時 (UTC とローカル、タイムゾーン名)、アプリの名前とバージョン。
   - 証拠一覧: 各証拠の情報、取得時のハッシュ、検証結果。
   - 取得の記録: イメージ作成 (FOR-20) の取得ログの内容。
   - デバイス情報: HPA / DCO (FOR-27)、SMART (FOR-28)。
   - パーティション: 一覧と配置図 (FOR-06)、論理ボリューム (FOR-07)、暗号化の情報 (FOR-29)。
   - ファイルシステムの概要 (FOR-09)。
   - ブックマーク: 名前、オフセット (16 進と 10 進)、LBA、コメント、その位置の Hex ダンプ (既定 64 バイト、最大 4 KiB)。
   - カービング・削除ファイル・書き出しの結果: 件数と、マニフェストの一覧 (1,000 件を超える場合は先頭 1,000 件とし、全件は CSV を添付する)。
   - 監査ログ: 全件または期間を指定。
2. 形式:
   - HTML: 1 つのファイル (CSS を埋め込み、外部の参照なし)。画像 (配置図) は SVG で埋め込む。
   - PDF: HTML を作り、WebView2 の PDF 出力 (`PrintToPdfAsync`) で変換する。用紙は A4 (既定) とレター、縦向き。各ページにケース番号とページ番号を入れる。
3. 表示言語は UI の言語に従う。日時は FOR-05 に従い、UTC を主、ローカルを併記する。
4. 保存先はケースの `reports/` (既定)。作成したレポートファイルの SHA-256 を計算し、監査ログに記録し、完了時の InfoBar に表示する。
5. レポートの見た目の変更 (テンプレートの編集) は対象外。ロゴ画像とヘッダーの文言だけを設定で変えられる。

**画面**: レポートのダイアログ (項目のチェックボックス、形式、用紙、保存先)。完了時の InfoBar (「開く」「フォルダを開く」ボタン)。

**巨大ファイル・長時間処理**: 監査ログや一覧が大きい場合は長時間処理として処理センターに出す。HTML は逐次書き出し、全体をメモリに持たない。PDF 変換で HTML が 50 MB を超える場合は、PDF には一覧の先頭だけを入れ、全件は HTML か CSV で出すことを提案する。

**エラー**: WebView2 ランタイムがない・PDF 変換に失敗した: HTML だけを作り、「PDF を作成できませんでした」と理由を示す。

**受け入れ基準**:

- [ ] 証拠 2 件、ブックマーク 3 件のケースで HTML レポートを作ると、すべての項目がオフラインのブラウザで表示できる。
- [ ] PDF のレポートの各ページにケース番号とページ番号が入る。
- [ ] レポートの SHA-256 が監査ログに記録され、ファイルのハッシュと一致する。
- [ ] 日時が UTC とローカルで併記される。

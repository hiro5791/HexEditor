# 機能仕様書: 概要と共通仕様

この仕様書は HexEditor の全機能の振る舞いを定める。実装・テスト・レビューはこの仕様書を基準に行う。

- 機能の優先順位 (いつ作るか) は [../roadmap.md](../roadmap.md) で管理する。この仕様書は「何を作るか」を定める。
- 調査の根拠は [../research/feature-survey.md](../research/feature-survey.md)。

## 2. 機能記述の書式

各機能は次の書式で書く。

```markdown
### ENG-01 機能名

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-01 (ロードマップにない機能は「追加 (フェーズ N 提案)」) |
| 呼び出し | メニュー、ショートカット、コマンドパレットのコマンド名、右クリックメニュー |

**概要**: 1〜3 文で何をする機能か。

**仕様**:
1. 振る舞いを番号付きで書く。入力、処理、出力、既定値、上限値を具体的に書く。

**画面**: 使う UI 要素と配置。

**巨大ファイル・長時間処理**: サイズに依存する処理の扱い。該当しない場合は「該当なし」。

**エラー**: 起こりうる失敗と、利用者への見せ方。

**受け入れ基準**:
- [ ] 確認できる形で書く。
```

- 機能 ID (`ENG-01` など) はファイル内で連番にする。一度付けた ID は変えない。廃止した機能は「廃止」と書いて ID を残す。
- 「〜できるとよい」のような曖昧な書き方はしない。決まっていないことは「未決定」と明記する。

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| ドキュメント | 開いている編集対象 1 つ。ファイル、ディスク、プロセスメモリなど |
| データソース | ドキュメントの元データ。`IByteSource` で抽象化する |
| オフセット | ドキュメント先頭からのバイト位置。0 始まり、64 bit 符号付き整数 (`long`) |
| アドレス | 表示上の位置。オフセットにベースアドレスを足したもの。プロセスメモリでは仮想アドレス |
| カーソル | 入力位置。バイト単位 (Hex 列ではさらにニブル単位) |
| 選択範囲 | 開始オフセットと長さの組。マルチ選択では複数の組 |
| Hex 列 / テキスト列 | 画面上のバイト値の 16 進表示部分 / 文字表示部分 |
| 上書きモード / 挿入モード | 入力時に既存バイトを置き換えるか、間に挿入するか |
| ピース | データエンジンがデータを表す単位。元データ・追加データ・塗りつぶしのいずれかの範囲を指す |
| 長時間処理 | 0.5 秒以上かかりうる処理。必ずバックグラウンドで実行し、進捗とキャンセルを提供する |

### 5.2 言語の選択

1. 既定では Windows の表示言語の優先順位に従って選ぶ。
2. 設定画面で 23 言語から明示的に選べる。言語名はその言語自身の表記で表示する (例: 日本語、Deutsch、العربية)。
3. 言語の変更はアプリの再起動で反映する。変更時に「今すぐ再起動」ボタンを出す。
4. 翻訳されていない文字列は英語で表示する。

### 5.3 翻訳の運用

1. 開発者は英語 (`en`) と日本語 (`ja`) の文字列を書く。英語が原文。
2. CI で未翻訳の文字列を残り 21 言語に機械翻訳する。用語集 (`docs/i18n/glossary.csv`) を使い、専門用語の訳を言語内でそろえる。
3. 翻訳の確認は本プロジェクトが行う。機械翻訳した訳と確認した訳の状態はリポジトリ内のファイルで管理し、確認した訳は機械翻訳で上書きしない (09 の UI-49)。誰でも GitHub の Issue、または `.resw` を直す Pull Request で翻訳の修正を提案できる。
4. 各言語の「確認済み」(人が確認した訳) の割合をリリースノートに載せる。
5. アプリのヘルプメニューに「翻訳の誤りを報告」を置き、表示言語・文字列のキー・現在の訳文を入力済みにした GitHub の Issue の作成画面を開く (09 の UI-41)。

### 5.4 翻訳以外の国際化の要件

| 項目 | 要件 |
| --- | --- |
| 右から左に書く言語 | アラビア語・ペルシア語では画面全体を左右反転する。ただし Hex 表示部分 (オフセット・Hex 列・テキスト列) とコードエディタは常に左から右 |
| 文字入力 | IME の変換中の文字を確定前に処理しない。検索欄・入力欄・テキスト列の入力で、日本語・中国語・韓国語・タイ語・ベトナム語の入力を確認する |

## 6. 入力式 (オフセット・長さ・値の入力)

オフセット、長さ、選択範囲、数値を入力するすべての欄は、次の書式を受け付ける。

### 6.1 数値の書き方

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `0x` で始まる | 16 進 | `0x1F00` |
| `h` で終わる | 16 進 | `1F00h` |
| `$` で始まる | 16 進 | `$1F00` |
| `0b` で始まる | 2 進 | `0b1010` |
| `0o` で始まる | 8 進 | `0o777` |
| `d` で終わる / 接頭辞なし | 10 進 (※) | `4096`, `4096d` |
| `_` を含む | 桁区切りとして無視 | `0x1_0000` |
| `K` `M` `G` `T` で終わる | 1024 の累乗倍 | `4K` = 4096, `1.5G` |

※ 接頭辞のない数値を 10 進と 16 進のどちらで解釈するかは設定で選べる。ただし `K` `M` `G` `T` で終わる接頭辞のない数値 (`10G`、`1.5G` など) は、設定によらず常に 10 進とする (`0x` などの接頭辞が付いた `0x10G` は 16 進)。既定は 16 進表示のときは 16 進、10 進表示のときは 10 進。入力欄の横に解釈結果 (例: `= 7,936 (0x1F00)`) を常に表示する。

### 6.2 演算と名前

- 演算子: `+` `-` `*` `/` `%` `&` `|` `^` `~` `<<` `>>`、括弧。
- 名前:

| 名前 | 意味 |
| --- | --- |
| `cur` | カーソル位置 |
| `start` | ドキュメントの先頭 (0) |
| `end` | ドキュメントの末尾 (長さ) |
| `sel.start` | 選択範囲の先頭のバイトの位置 |
| `sel.end` | 選択範囲の直後の位置 (`sel.start + sel.len`。最後のバイトは含まない) |
| `sel.last` | 選択範囲の最後のバイトの位置 (`sel.end - 1`) |
| `sel.len` | 選択範囲の長さ |
| `sector` | セクタサイズ (ディスクの場合。ファイルでは表示設定の値、既定 512) |
| `cluster` | クラスタサイズ (ファイルシステムを解析しているドキュメントのみ、FOR-15) |
| `rec` | レコード表示 (VIEW-18) のレコード長 |
| `recno` | カーソル位置のレコード番号 (0 始まり) |
| `bm.名前` | 名前付きブックマークの位置 |

- 範囲を表す名前は、すべて「先頭を含み、末尾を含まない」で統一する。画面上で「終了」と表示する欄は、利用者に分かるよう「終了 (このバイトを含む)」のように含むかどうかを必ず明記する。
- 読み取り関数: `u8(x)` `s8(x)`、`u16le(x)` `u16be(x)` `s16le(x)` `s16be(x)`、同様に 24 / 32 / 64 bit、`f32le(x)` `f32be(x)` `f64le(x)` `f64be(x)`。オフセット `x` の値を読む。ポインタをたどる入力 (例: `u32le(0x3C)`) に使う。読み取れない位置を指した場合は入力エラーにする。
- 電卓 (TOOL-22) はこれに加えて独自の関数を持てる。独自の関数は電卓の中でだけ使える。
- 先頭が `+` または `-` の入力は、ジャンプ欄ではカーソルからの相対位置と解釈する。
- 計算は 64 bit 符号付き整数で行い、桁あふれは入力エラーにする。ただしデータ演算のオペランド・増分・最小値・最大値 (EDIT-31 の仕様 5、EDIT-36) は、符号なし 8 バイトの値を入力できるよう 128 bit で計算し、数値は `0xFFFFFFFFFFFFFFFF` まで書ける (要素の型と大きさに収まるかは各欄で調べる)。
- 例: `end-0x10`, `cur+sector*4`, `sel.end`, `bm.header+8`, `u32le(0x3C)+4`。

### 6.3 Hex バイト列の入力

- 空白、カンマ、`0x` 接頭辞、`\x` 接頭辞、改行は区切りとして扱う: `DE AD BE EF`、`0xDE,0xAD`、`\xDE\xAD`、`DEADBEEF` はすべて同じ。
- 奇数桁の場合はエラーにする (最後のニブルを補完しない)。
- 検索欄では `??` (任意の 1 バイト) と `?` (任意の 1 ニブル) をワイルドカードとして使える。

## 8. 既定のショートカット

ここにないショートカットを各ファイルで新たに割り当てる場合は、この表に追記してから使う。同じ有効範囲の中での重複は禁止。すべてのショートカットは設定で変更できる。この表にないコマンドの既定のキーは「既定なし」とし、コマンドパレットとメニューから実行する。

### 8.1 有効範囲

ショートカットには有効範囲がある。狭い有効範囲の割り当てが、広い有効範囲の割り当てより優先する。

| 有効範囲 | 対象 |
| --- | --- |
| グローバル | アプリ全体 |
| エディタ | Hex ビューにフォーカスがあるとき |
| 検索バー | 検索バー・置換バーにフォーカスがあるとき |
| コードエディタ | スクリプトエディタ・テンプレートエディタにフォーカスがあるとき |
| パネル | 一覧形式のパネル (ブックマーク一覧、結果一覧など) にフォーカスがあるとき |

文字を入力できる場所 (入力欄、テキスト列、コードエディタ) では、AltGr (Ctrl+Alt) で入力される文字がショートカットより優先する (UI-20)。

コードエディタでは、エディタ部品が持つ標準の編集キー (Ctrl+F の検索、Ctrl+H の置換、Ctrl+G の行へ移動、Ctrl+/ のコメント切り替えなど) がグローバルの同じキーより優先する。優先順位の詳細は AUTO-20。

### 8.7 注意事項

- `Ctrl+,` `Ctrl+=` `Ctrl+-` `Ctrl+\` は記号キーなので、配列によって押せない場合がある。これらはコマンドパレットとメニューからも必ず実行できる。
- Ctrl+1〜9 と Ctrl+Shift+1〜9 のブックマークは、数字キーの段で押す (テンキーでも可)。Ctrl+Shift+0 は Windows の入力言語の切り替えに使われることがあるため、番号付きブックマークは 1〜9 の 9 個とする。
- F12 は 2 つの意味を持つ。フォーカスのあるパネル (テンプレートの結果ツリー / 逆アセンブルビュー) の動作を優先する。Hex ビューにフォーカスがある場合は、カーソル位置にテンプレートの定義があればそれを優先し、なければ逆アセンブルの分岐先へ移動する (TPL-24、ANA-25)。
- マウス操作 (Ctrl+ホイールでズーム、タブの中クリックで閉じる) と OS 標準のキー (Alt / F10 でメニュー、Shift+F10 で右クリックメニュー) は表に載せずに使ってよい。

## 10. ドキュメントに付随するデータ

ブックマーク、色付けルール、適用中のテンプレート、表示設定、カーソル位置などは、ファイル本体とは別に保存する。

- 保存先: 設定フォルダの `documents/` 以下。キーはファイルの絶対パス。サイズ・更新日時が変わっていた場合は、付随データを適用する前に利用者に確認する。
- プロジェクトファイル (`.hexproj`、JSON) にエクスポート・インポートでき、他の人と共有できる。プロジェクトファイルにはファイル本体へのパスと付随データを入れる。
- ファイル本体には何も書き込まない。

## 11. 非機能要件

### 11.1 性能

| 項目 | 目標 |
| --- | --- |
| 起動 | 2 秒以内に操作可能 (一般的な SSD 環境) |
| ファイルを開く | サイズに関係なく 1 秒以内に先頭を表示 (100 GB でも同じ) |
| スクロール・カーソル移動 | 60 fps を保つ。キー入力から画面反映まで 50 ms 以内 |
| 任意の位置へのジャンプ | 100 ms 以内に表示 (データが OS のキャッシュにない場合はディスク性能に依存) |
| 挿入・削除・塗りつぶし | データ量に関係なく 100 ms 以内 (データエンジンの操作として) |
| 検索 (単純なバイト列) | 同じ機械・同じストレージで同じファイルを読むだけの速度の 80% 以上 (NVMe SSD ではおおむね 1 GiB/s 以上。測り方は FIND-01) |
| 保存 (長さが変わらない場合) | 変更されたバイト量に比例する時間 |

### 11.2 メモリ

- メモリ使用量はファイルサイズに比例させない。既定の上限は 1 GB (キャッシュ、Undo、追加データを含む。上限を超える追加データは一時ファイルへ退避する)。
- 上限は設定で変更できる。

### 11.3 信頼性

- 保存の途中でアプリや OS が落ちても、元のファイルの内容を失わない。
  - 長さが変わる保存 (一時ファイルと置き換え、ENG-22): 元のファイルはそのまま残る。
  - 長さが変わらない保存 (その場保存、ENG-23): 書き込む前に元のバイトを記録しておき、次の起動時に元へ戻せる。
  - 次の場合は例外で、実行前に「途中で止まると元に戻せない」ことを示して確認を取る。
    - ずらしながらのその場保存 (ENG-24)
    - その場保存で、元のバイトの記録が上限を超える場合 (ENG-23)
    - ディスク・ボリュームへの書き込み (ENG-30)
- 編集中のデータは定期的 (既定 1 分ごと) に復旧用データとして保存する。異常終了後の起動時に復旧を提案する。巨大な追加データは復旧用データに参照として記録し、コピーしない。
- 未処理の例外が起きても、未保存の編集内容を復旧用データに書き出してから終了する。

### 11.4 セキュリティ

- 開いたファイルの内容を、利用者の指示なしに外部に送信しない。テレメトリは送らない (UI-57)。
- アプリが自分から行う通信は次のものだけで、いずれも設定で無効にできる (UI-58)。
  - 更新の確認とダウンロード
  - テンプレート・プラグインなどのダウンロード (オンラインリポジトリ)
  - 追加コンポーネント (C# スクリプト用のコンパイラなど) のダウンロード
  - 翻訳の誤り報告・ドキュメントのページを開く (ブラウザで開くだけ)
- 利用者が接続先を指定する機能 (リモートのデータソース ENG-40〜42、スクリプトの通信 AUTO-18) は、利用者の操作または許可があったときだけ通信する。これらは利用者の明示的な操作なので、オフラインモード (`network.offline`、UI-58) の対象外とする。起動時やセッション復元時に自動で接続し直すことはしない。
- 署名の確認 (プラグインの AUTO-35、追加コンポーネントの Roslyn の署名 PKG-17) で OS が行う証明書の失効確認は、オフラインモードではキャッシュだけを使う。
- スクリプトとプラグインは、初回実行時に利用者の許可を求める (詳細は 08)。
- 管理者権限の補助プロセスは、決められた操作だけを受け付ける。
  - デバイス (ディスク・ボリューム) の読み書き、ボリュームのロック・ディスマウント
  - プロセスメモリの読み書き
  - 読み取り専用のデバイス情報の取得 (SMART、HPA / DCO、FOR-27・FOR-28)
  - OS の USB ストレージ書き込み保護の切り替え (FOR-02)
- アプリ全体を管理者として実行している場合 (どの配布形態でも) は、上の操作を補助プロセスを使わずに同じプロセスで行う。その場合も同じ操作の許可リストを通し、それ以外の操作は行わない (01 の ENG-28 の仕様 10)。
- 管理者として実行している間は、スクリプトの実行とプラグインの読み込みの前に、管理者権限で動くことを示して確認する (08 の AUTO-34)。

### 11.5 アクセシビリティ

- すべての操作をキーボードだけで行える。
- スクリーンリーダー (ナレーター、NVDA) で、カーソル位置のオフセット・バイト値・文字を読み上げられる。
- ハイコントラストテーマで全画面が判読できる。色だけで情報を伝えない (変更されたバイトは色に加えて下線でも示すなど)。
- 文字サイズの拡大 (Windows の設定) と表示倍率 400% で崩れない。

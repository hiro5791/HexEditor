- ロードマップにない機能 (調査 [../research/feature-survey.md](../research/feature-survey.md) の 2.12、2.15 などから追加したもの) は「追加 (フェーズ N 提案)」と記す。

## 印刷

### TOOL-01 印刷とページ設定

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-06 |
| 呼び出し | メニュー「ファイル > 印刷...」、Ctrl+P、コマンドパレット「ファイル: 印刷」 |

**概要**: ドキュメントの全体・選択範囲・指定範囲を、画面と同じ Hex ダンプの形で印刷する。フォント、余白、1 行のバイト数、ヘッダ・フッタを指定できる。

**仕様**:

1. Ctrl+P で印刷ダイアログを開く。ダイアログの左に設定、右にプレビュー (TOOL-02) を置く。
2. 設定項目と既定値:

   | 項目 | 選択肢・範囲 | 既定値 |
   | --- | --- | --- |
   | プリンタ | Windows に登録されたプリンタ (「Microsoft Print to PDF」を含む) | Windows の既定のプリンタ |
   | 印刷範囲 | すべて / 選択範囲 (選択がある場合だけ選べる。マルチ選択は範囲ごとに区切って印刷) / オフセットの範囲 (入力式) / ページの範囲 (例: `1-3, 8`) | 選択があれば選択範囲、なければすべて |
   | 用紙・向き | プリンタが対応する用紙、縦 / 横 | プリンタの既定 |
   | 余白 | 上下左右、0〜50 mm (地域設定がインチの場合はインチで表示) | 各 15 mm |
   | フォント | 等幅フォントの一覧、6〜24 pt | Cascadia Mono 9 pt |
   | 1 行のバイト数 | 4〜64、または「用紙に合わせる」(余白とフォントから入る最大の 8 の倍数) | 画面と同じ。用紙に入らない場合は「用紙に合わせる」 |
   | 列 | オフセット / Hex / テキストの表示・非表示 | 画面と同じ |
   | グループ化・オフセットの基数・文字コード | 画面と同じ選択肢 | 画面と同じ |
   | 色 | カラー (変更バイト・ブックマーク・色付けルールの背景色を印刷) / 白黒 (色の代わりに下線・網掛けで示す) | 白黒 |
   | ヘッダ・フッタ | 左・中央・右の 3 か所ずつ。文字列と置換記号 (3) | ヘッダ左: `{name}`、ヘッダ右: `{range}`、フッタ中央: `{page} / {pages}`、フッタ右: `{date}` |
   | 部数 | 1〜999 | 1 |

3. ヘッダ・フッタの置換記号: `{name}` (ファイル名)、`{path}` (フルパス)、`{page}`、`{pages}`、`{date}`、`{time}` (地域設定の書式)、`{range}` (印刷範囲のオフセット)、`{size}` (ドキュメントのサイズ)、`{modified}` (未保存の変更がある場合「(変更あり)」)。
4. 未保存の変更がある場合は、変更後の内容を印刷する。
5. 設定は「既定として保存」で次回以降の既定値にできる。
6. 印刷の処理は長時間処理として扱い、処理センターに進捗 (ページ数) と停止ボタンを出す。印刷中も編集できる (印刷開始時点の内容のスナップショットを印刷する)。
7. 印刷の実装方式 (WinUI 3 の `PrintManager` を使うか、Win32 の印刷 API を使うか) は未決定。どちらでも上記の項目を満たすこと。

**画面**: 印刷ダイアログ (設定とプレビュー)。キーボードだけで全項目を操作できる。

**巨大ファイル・長時間処理**:

- ページ数は行数とページあたりの行数から計算で求め、データを読まずに即座に表示する。
- 1,000 ページを超える場合は、印刷の前に「1,234,567 ページを印刷します。用紙の量を確認してください」と確認する (ボタン: 「印刷する」「範囲を変える」)。
- 100,000 ページを超える範囲は印刷できない。範囲を狭めるよう案内する (PDF への出力も同じ上限)。
- データは印刷するページの分だけ順に読む。

**エラー**: プリンタがない・エラーになった場合は Windows のエラー内容を表示する。印刷中のデータの読み込みエラー (ディスクの不良セクタなど) は、そのバイトを `??` で印刷し、最後に「読めなかった範囲があります」と表示する。

**受け入れ基準**:

- [ ] Ctrl+P で印刷ダイアログが開き、選択がある場合は印刷範囲の既定が「選択範囲」になる。
- [ ] ヘッダ・フッタの置換記号が正しく置き換わる。
- [ ] 白黒の印刷で、変更バイトが下線で区別できる。
- [ ] 100 GB のファイルで印刷ダイアログを開いても、1 秒以内にページ数が表示される。
- [ ] 1,000 ページを超える印刷で確認ダイアログが出る。
- [ ] 印刷中に編集しても、印刷結果は印刷開始時点の内容になる。

### TOOL-02 印刷プレビュー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-06 |
| 呼び出し | 印刷ダイアログ (TOOL-01) の右側、メニュー「ファイル > 印刷プレビュー」、コマンドパレット「ファイル: 印刷プレビュー」 |

**概要**: 印刷結果をページ単位で表示し、設定の変更をその場で反映する。

**仕様**:

1. 設定を変えると、500 ms 以内にプレビューを更新する。
2. ページの移動: 前 / 次のページ、ページ番号の入力、先頭 / 末尾。PageUp / PageDown / Home / End (プレビューにフォーカスがある場合)。
3. 表示倍率: ページ全体、幅に合わせる、50〜400%。
4. 表示: 1 ページ / 2 ページ見開き。
5. プレビューで表示しているページだけを描画する (全ページを作らない)。

**画面**: 印刷ダイアログの右側。ページの下に「12 / 3,456 ページ」と表示する。

**巨大ファイル・長時間処理**: 表示するページのデータだけを読む。何ページ目に移動しても 200 ms 以内に表示する。

**エラー**: 読み込みエラーは TOOL-01 と同じ表示 (`??`)。

**受け入れ基準**:

- [ ] フォントサイズを変えると、500 ms 以内にプレビューとページ数が変わる。
- [ ] 100 GB のファイルで最後のページへの移動が 200 ms 以内に表示される。
- [ ] プレビューのページ送りをキーボードで行える。

### TOOL-03 PDF への出力

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-06 |
| 呼び出し | 印刷ダイアログの「PDF として保存...」、メニュー「ファイル > エクスポート > PDF...」、コマンドパレット「ファイル: PDF としてエクスポート」 |

**概要**: 印刷と同じ内容を PDF ファイルに書き出す。プリンタドライバに頼らず、文字を検索・コピーできる PDF を作る。

**仕様**:

1. 設定項目は印刷 (TOOL-01) と同じ (プリンタと部数を除く)。用紙は A4 / Letter / A3 / Legal から選ぶ (既定は地域設定に合わせて A4 か Letter)。
2. 文字は画像ではなくテキストとして書き、フォントは使用する文字だけを埋め込む (サブセット)。テキスト列の文字が表示用のフォントにない場合は、代替フォントを埋め込む。
3. PDF の文書情報に、タイトル (ファイル名)、作成アプリ名、作成日時を入れる。各ページにしおり (オフセットの範囲) を付ける (1,000 ページごとに 1 つ)。
4. 「Microsoft Print to PDF」でも PDF にできるが、この機能のほうがファイルが小さく文字を検索できる旨をヘルプに書く。
5. 書き出しは一時ファイルに書いてから置き換える。

**画面**: 保存ダイアログ、処理センターの進捗。

**巨大ファイル・長時間処理**: ページ単位でストリームとして書き出し、メモリ使用量をページ数に比例させない。上限は TOOL-01 と同じ 100,000 ページ。

**エラー**: 書き込みの失敗・空き容量不足は理由を表示し、書きかけのファイルを削除する。

**受け入れ基準**:

- [ ] 出力した PDF で Hex 値を検索・コピーできる。
- [ ] 10,000 ページの PDF の出力中、メモリ使用量が 200 MB を超えない。
- [ ] 日本語の文字を含むテキスト列が、PDF で正しく表示される。

## インポートとエクスポート

### TOOL-04 インポート / エクスポートの共通仕様

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-11 |
| 呼び出し | メニュー「ファイル > インポート...」「ファイル > エクスポート...」、コマンドパレット「ファイル: インポート」「ファイル: エクスポート」、右クリックメニュー (選択範囲がある場合)「選択範囲をエクスポート...」 |

**概要**: テキスト形式などのファイルを読み込んでバイト列にし (インポート)、ドキュメントの全体や範囲を各形式のファイルに書き出す (エクスポート)。形式ごとの変換処理は、Copy As (03)、コマンドライン (AUTO-44)、スクリプト (AUTO-09) と共通にする。

**仕様**:

1. 形式の一覧:

   | 形式 | ID | インポート | エクスポート | 機能 |
   | --- | --- | --- | --- | --- |
   | Intel HEX | `ihex` | ○ | ○ | TOOL-05 |
   | Motorola S-record | `srec` | ○ | ○ | TOOL-06 |
   | Base64 / Base32 / Ascii85 / UUEncode / Quoted-Printable / URL エンコード | `base64` `base32` `ascii85` `uu` `qp` `url` | ○ | ○ | TOOL-07 |
   | Hex テキスト / 10 進テキスト | `hextext` `dectext` | ○ | ○ | TOOL-08 |
   | ソースコードの配列 (C, C++, C#, Java, JavaScript, Python, Rust, Go, Pascal, VB.NET) | `c` `cpp` `csharp` `java` `js` `python` `rust` `go` `pascal` `vbnet` | ○ | ○ | TOOL-09 |
   | ダンプ (テキスト、HTML、RTF、TeX、Markdown) | `dump-text` `html` `rtf` `tex` `markdown` | — | ○ | TOOL-10 |
   | PDF | `pdf` | — | ○ | TOOL-03 |
   | IPS / IPS32 パッチ | `ips` `ips32` | ○ (パッチの適用 EDIT-43) | ○ (パッチの作成 EDIT-42) | TOOL-12 |
   | バイナリ (範囲をそのまま書き出す) | `bin` | ○ (ファイルの挿入) | ○ | この項 |
   | プラグインの形式 | プラグインが定める | プラグインによる | プラグインによる | AUTO-31 |

2. **インポートのダイアログ**:
   1. ファイルを選ぶ (またはダイアログにドラッグ & ドロップする)。
   2. 形式を内容から自動判定し、候補を選択済みにする (利用者が変えられる)。判定は先頭 64 KB で行う (例: `:` で始まる行が続けば Intel HEX、`S0`〜`S9` で始まれば S-record)。
   3. 形式ごとのオプション (各機能の項) を表示する。
   4. 読み込み先を選ぶ: 「新しいドキュメント」(既定) / 「カーソル位置に挿入」/ 「カーソル位置から上書き」。
   5. 「プレビュー」欄に、変換後の先頭 256 バイトの Hex と、変換後のサイズ・アドレスの範囲・警告の件数を表示する。
   6. 「インポート」で実行する。カーソル位置への挿入・上書きは 1 回の Undo で戻せる。
3. **エクスポートのダイアログ**:
   1. 対象を選ぶ: 「ドキュメント全体」/ 「選択範囲」(選択がある場合の既定) / 「オフセットの範囲」(入力式)。マルチ選択の場合は「範囲ごとに別ファイル」/ 「つなげて 1 つのファイル」を選ぶ。
   2. 形式を選ぶ。形式ごとのオプションを表示する。
   3. 出力の先頭 20 行のプレビューと、出力のおおよそのサイズを表示する。
   4. 保存先を選び、「エクスポート」で実行する。
4. オプションは形式ごとに前回の値を記憶する。
5. テキスト形式の出力の改行 (CRLF / LF) と文字コード (UTF-8 (BOM なし) / UTF-8 (BOM あり) / ASCII) を選べる。既定は CRLF、UTF-8 (BOM なし)。
6. テキスト形式の入力は、改行 (CRLF / LF / CR) と BOM を自動で判別する。
7. Intel HEX・S-record・Base64 のファイルを「開く」で開いた場合は、ENG-38 がデコードしてドキュメントとして開き、保存時の元の形式への変換は TOOL-11 で定める。

**画面**: インポートとエクスポートのダイアログ (形式の一覧、オプション、プレビュー)。

**巨大ファイル・長時間処理**:

- 変換はすべてストリームで行う。インポートの結果は、読み込み先のドキュメントの追加データ (一時ファイルへの退避を含む、00 の 11.2) として持ち、メモリに全体を置かない。
- エクスポートは一時ファイルに書いてから置き換える。出力が 1 GB を超える見込みの場合は、出力のおおよそのサイズを示して確認する (テキスト形式は元の 2〜5 倍になるため)。
- 0.5 秒を超える処理は処理センターに出し、キャンセルできる。

**エラー**:

- 形式の誤り (チェックサムの不一致、不正な文字) は、行番号・列・内容を一覧にしてダイアログに表示する。形式ごとに「誤りを無視して続ける」を選べるかを定める。一覧はインポートのダイアログのプレビューの下にも出す (警告だけの場合も含む。最大 1,000 件)。
- 書き込みの失敗・空き容量不足は理由を表示し、書きかけのファイルを削除する。

**受け入れ基準**:

- [ ] 形式の自動判定が、Intel HEX・S-record・Base64・Hex テキストのファイルで正しい形式を選ぶ。
- [ ] 1 GB の Intel HEX をインポートしても、メモリ使用量が 1 GB の上限を超えない。
- [ ] 「カーソル位置に挿入」のインポートが 1 回の Ctrl+Z で戻る。
- [ ] エクスポートを途中でキャンセルすると、出力ファイルが残らない。
- [ ] エクスポートとコマンドライン (`hexed convert`) とスクリプト (`exportRange`) の出力が、同じオプションで一致する。

### TOOL-05 Intel HEX

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-11 |
| 呼び出し | インポート / エクスポートのダイアログで形式「Intel HEX」を選ぶ |

**概要**: マイコンのファームウェアなどで使う Intel HEX 形式 (I8HEX / I16HEX / I32HEX) を読み書きする。チェックサムを検証し、アドレスの空き (ギャップ) を扱う。

**仕様**:

1. 対応するレコード型: `00` データ、`01` ファイルの終わり、`02` 拡張セグメントアドレス、`03` 開始セグメントアドレス、`04` 拡張リニアアドレス、`05` 開始リニアアドレス。
2. **インポート**:
   - 各行のチェックサム (全バイトの和の 2 の補数) を検証する。誤りがある場合は一覧を表示し、「誤りを無視して読み込む」「キャンセル」を選ばせる (既定はキャンセル)。
   - 行の形式の誤り (`:` で始まらない、奇数桁、バイト数とデータ長の不一致、未知のレコード型) は同じく一覧にする。空行と行末の空白は無視する。
   - アドレスの配置 (オプション):
     - 「最小アドレスを先頭にする」(既定): 最小アドレスをオフセット 0 に置き、ドキュメントの表示上のベースアドレス (アドレス = オフセット + ベースアドレス) を最小アドレスにする。
     - 「アドレスをそのままオフセットにする」: アドレス 0 からの位置に置く。
   - ギャップ (データのないアドレス) は指定値で埋める (既定 `FF`、0〜FF を指定可)。埋めた範囲は塗りつぶしピースで表し、データを作らない。ギャップの範囲は、オプション「ギャップにブックマークを付ける」(既定: オフ) で確認できるようにする。
   - 重複したアドレス (同じアドレスに 2 回データがある) は、既定ではエラーとして一覧に出す。「後のデータを優先」を選べる。
   - 開始アドレス (`03` / `05`) は、ドキュメントの付随データとして保持し、エクスポート時の既定値にする。プレビュー欄に表示する。
3. **エクスポート**:

   | オプション | 選択肢 | 既定値 |
   | --- | --- | --- |
   | 1 レコードのデータ長 | 1〜255 バイト | 16 (32 も選択肢として示す) |
   | アドレスの形式 | 自動 / I8HEX (16 bit) / I16HEX (セグメント) / I32HEX (リニア) | 自動 (64 KB 以下なら I8HEX、超えるなら I32HEX) |
   | 開始アドレス | 0〜0xFFFFFFFF | ドキュメントの表示上のベースアドレス |
   | 実行開始アドレス (`03` / `05`) | なし / 値を指定 | インポート時の値。なければなし |
   | ギャップの省略 | しない / 指定値が N バイト以上続く範囲を出力しない | しない (省略する場合の既定は `FF` が 16 バイト以上) |
   | 16 進の大文字・小文字 | 大文字 / 小文字 | 大文字 |

   - レコードは 64 KB の境界をまたがないように分ける (`04` / `02` のレコードを境界で出す)。
   - 実行開始アドレスのレコード型 (`03` 開始セグメントアドレス / `05` 開始リニアアドレス) を選べる。既定はインポート時の型、なければ `05`。
   - 「インポート時の値」は、ENG-38 で開いたドキュメントの元のファイルの値、またはインポートで新しいドキュメントにしたときの付随データ (仕様 2)。ファイルごとに決まる値 (実行開始アドレス、S-record のヘッダ) は、前回の値として記憶しない (TOOL-04 の仕様 4 の例外)。
4. 範囲の上限: I8HEX は 64 KB、I16HEX は 1 MB、I32HEX は 4 GB。エクスポートする範囲のアドレス (開始アドレス + 長さ) が上限を超える場合はエラーにする。

**画面**: TOOL-04 のダイアログのオプション欄。インポートのプレビューに「アドレス範囲: 0x08000000〜0x0801FFFF、データ 98,304 バイト、ギャップ 32,768 バイト」のように表示する。

**巨大ファイル・長時間処理**: 4 GB のアドレス空間に点在するデータでも、ギャップは塗りつぶしピースで表すため、メモリ使用量はデータ量に比例し、アドレス空間の大きさに比例しない。

**エラー**: 2、4 のとおり。誤りの一覧は最大 1,000 件を表示し、それ以上は件数だけを示す。

**受け入れ基準**:

- [ ] チェックサムを 1 か所誤らせたファイルで、行番号付きのエラーが出る。
- [ ] 0x0000 と 0xFFFF0000 にデータがある I32HEX ファイルを、1 秒以内・少ないメモリでインポートできる (ギャップを塗りつぶしピースで表すため)。
- [ ] エクスポートした Intel HEX を再びインポートすると、元のバイト列と一致する (ギャップの省略をしない場合)。
- [ ] 64 KB の境界で `04` レコードが出力される。
- [ ] 参照のツール (GNU binutils の `objcopy -O ihex`。版の例: binutils 2.42) で作った Intel HEX と、同じ設定でエクスポートした結果が一致する。参照ファイルの作成に使ったツールの版は、テストデータと一緒に記録する。

### TOOL-07 エンコード形式 (Base64 など)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-11 |
| 呼び出し | インポート / エクスポートのダイアログで形式を選ぶ |

**概要**: Base64、Base32、Ascii85、UUEncode、Quoted-Printable、URL エンコードのテキストを読み書きする。

**仕様**:

1. 形式ごとのオプション:

   | 形式 | インポートのオプション | エクスポートのオプション |
   | --- | --- | --- |
   | Base64 | 標準 / URL セーフ (自動判別)、空白・改行を無視、パディングなしを許す | 標準 / URL セーフ、1 行の文字数 (76 (既定) / 64 / 改行なし / 任意)、パディングの有無 |

3. PEM 形式 (`-----BEGIN ...-----` で囲まれた Base64) は、囲みの行を自動で取り除いて Base64 として読む。

**画面**: TOOL-04 のダイアログのオプション欄。

**巨大ファイル・長時間処理**: ストリームで変換する。

**エラー**: 2 のとおり。

**受け入れ基準**:

- [ ] 各形式でエクスポートしてインポートすると、元のバイト列と一致する (全 256 種のバイト値を含むデータで確認)。
- [ ] RFC 4648 のテストベクタで Base64 と Base32 の結果が一致する。
- [ ] PEM 形式の証明書を Base64 としてインポートできる。

### TOOL-08 Hex テキストと 10 進テキスト

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-11 |
| 呼び出し | インポート / エクスポートのダイアログで形式「Hex テキスト」「10 進テキスト」を選ぶ |

**概要**: バイト値を 16 進または 10 進の数字で書いたテキストを読み書きする。他のツールのダンプ (xxd、`hexdump -C`、このアプリのダンプ) からもバイト列を取り出せる。

**仕様**:

1. **Hex テキストのインポート**:
   - 00 の 6.3 の書式 (空白・カンマ・`0x`・`\x`・改行を区切りとして扱う) で読む。
   - 「ダンプからの読み取り」(既定: 自動): 行頭のオフセット列と、行末のテキスト列を見分けて取り除く。対応するダンプ: このアプリのダンプ (TOOL-10)、xxd、`hexdump -C`、`od -A x -t x1`、Windows の `certutil -encodehex`。判別できない行はエラーの一覧に出す。
   - 奇数桁はエラー (00 の 6.3)。
2. **10 進テキストのインポート**: 空白・カンマ・セミコロン・改行で区切った 10 進の数値を読む。オプション「1 つの値のサイズ」(1 / 2 / 4 / 8 バイト、既定 1)、「符号」(符号なし / 符号あり)、「エンディアン」。範囲外の値はエラー。
3. **Hex テキストのエクスポート**:

   | オプション | 選択肢 | 既定値 |
   | --- | --- | --- |
   | 1 行のバイト数 | 1〜1,024、または改行なし | 16 |
   | 区切り | 空白 / カンマと空白 / なし / 任意の文字列 | 空白 |
   | 接頭辞 | なし / `0x` / `\x` / `$` / 任意 | なし |
   | 大文字・小文字 | 大文字 / 小文字 | 大文字 |
   | 行頭にオフセットを付ける | する / しない | しない |

4. **10 進テキストのエクスポート**: 1 つの値のサイズ・符号・エンディアン、1 行の値の数 (既定 16)、区切り (既定 カンマと空白)。

**画面**: TOOL-04 のダイアログのオプション欄。

**巨大ファイル・長時間処理**: ストリームで変換する。

**エラー**: 不正な文字・奇数桁・範囲外の値は行と列を一覧にする。

**受け入れ基準**:

- [ ] xxd と `hexdump -C` の出力を、ダンプからの読み取りで元のバイト列に戻せる。
- [ ] 10 進テキスト `255, 0, 128` が `FF 00 80` になる。
- [ ] 2 バイト・ビッグエンディアンの 10 進テキスト `258` が `01 02` になる。

### TOOL-09 ソースコードの配列

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-11 |
| 呼び出し | インポート / エクスポートのダイアログで形式「ソースコード」を選ぶ |

**概要**: バイト列を各プログラミング言語の配列の定義として書き出す。配列の定義からバイト列を読み込むこともできる。

**仕様**:

1. 対応する言語: C、C++、C#、Java、JavaScript、Python、Rust、Go、Pascal、VB.NET。
2. エクスポートの変換処理は、Copy As (03) の同じ言語の形式と共通にする。オプションも共通 (要素のサイズ 1 / 2 / 4 / 8 バイト、エンディアン、16 進 / 10 進、1 行の要素数、変数名、`const` / `static` などの修飾)。
3. ファイルへの書き出しでは、Copy As のオプションに加えて次を選べる。
   - C / C++: ヘッダファイルとして出す (インクルードガード付き)、長さの定数 (`#define NAME_LEN 1234` / `const size_t`) を付ける。
   - 全言語: 先頭に、元のファイル名・範囲・作成日時のコメントを付ける (既定: 付ける)。
4. インポート: 配列の定義のテキストから数値のリテラル (16 進 `0x..`、10 進、8 進、文字リテラル `'A'`、文字列リテラル `"..."` (エスケープを解釈)) を順に取り出す。要素のサイズは型名 (`uint16_t`、`short`、`u32` など) から推定し、利用者が変えられる。この解釈は「形式を選択して貼り付け」(03) と共通にする。

**画面**: TOOL-04 のダイアログのオプション欄。

**巨大ファイル・長時間処理**: ストリームで変換する。出力が 100 MB を超える見込みの場合は、コンパイラで扱いにくい旨を確認ダイアログに書く。インポートは、フェーズ 2 では配列の定義のテキスト全体を読んでから解釈する (型名から要素のサイズを推定し、最後の括弧の組を値にするため)。ストリームでの解釈は後のフェーズで行う。

**エラー**: インポートで数値として解釈できない部分は、最初の 1 か所だけでなくすべての位置を一覧にする。「誤りを無視して読み込む」では、その部分を飛ばして読む。

**受け入れ基準**:

- [ ] 各言語の出力が、その言語のコンパイラ・インタプリタでエラーなく読める (CI で確認)。
- [ ] エクスポートの結果が、同じオプションの Copy As の結果と一致する。
- [ ] C の配列 `{ 0x01, 0x02, 'A' }` をインポートすると `01 02 41` になる。

### TOOL-10 ダンプのエクスポート (テキスト・HTML・RTF・TeX・Markdown)

1. 共通のオプション: 1 行のバイト数、グループ化、列 (オフセット / Hex / テキスト)、オフセットの基数、文字コード、大文字・小文字 (既定はすべて画面と同じ)。

### TOOL-11 エンコード形式のファイルを元の形式で保存する

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-11 |
| 呼び出し | ENG-38 でデコードして開いたドキュメントの保存 (Ctrl+S)、名前を付けて保存 (Ctrl+Shift+S)、タブの右クリック「形式の設定...」 |

**概要**: ENG-38 でデコードして開いた Intel HEX・S-record・Base64 のドキュメントを、保存時に元の形式に戻して書き出す規則を定める。ファイルの判定・デコード・InfoBar・誤りの一覧など、開く処理は ENG-38 が定める (00 の 1.1)。

**仕様**:

1. 保存で使う設定は、開いたときに元のファイルから読み取ったもの (ENG-38 の仕様 2) を使う。
   - Intel HEX / S-record: 1 レコードのデータ長 (最も多く使われていた値。判定できなければ 16 バイト)、アドレスの形式 (I8HEX / I16HEX / I32HEX、S1 / S2 / S3)、実行開始アドレス (`03` / `05`、`S7` / `S8` / `S9`)、`S0` の文字列、レコード数 (`S5` / `S6`) の有無、16 進の大文字・小文字、改行コード。
   - Base64: 1 行の文字数 (76、64、改行なしなど)、標準 / URL セーフ、パディングの有無、改行コード。
2. 保存 (Ctrl+S) は、この設定でエクスポート (TOOL-05〜07) と同じ変換を行い、安全な保存 (ENG-22) で書き出す (属性・ACL・作成日時の引き継ぎ、一時ファイルの記録、バックアップ (ENG-26) も通常の保存と同じ)。Intel HEX / S-record の隙間 (データなし。ENG-38 の仕様 3) は出力しない。設定はタブの右クリック「形式の設定...」で変えられる。
3. 「名前を付けて保存」では、元の形式・バイナリ・他の形式 (TOOL-04 の形式の一覧) を選べる。形式は保存先の拡張子で決め、同じ拡張子の形式が複数ある場合 (`.txt` など) は形式を選ばせる。Intel HEX・S-record・Base64・バイナリ以外の形式は、その形式の前回の設定でのエクスポートとして書き出し、ドキュメントの保存先と形式は変えない (未保存の変更も残る)。
   - 「形式の設定」には、実行開始アドレスのレコード型 (`03` / `05`) と、最後の行の後の改行の有無も置く。
4. 元のファイルに、データとして読めない行 (コメント行など `:` (S-record は `S`) で始まらない行、未知のレコード型の行) があった場合、その行は開くときに形式の誤りとして一覧に出し、ドキュメントは読み取り専用で開く (ENG-38 の仕様 6。コメント行を特別に扱う形式はない)。InfoBar の「編集を許可」で編集して保存すると、それらの行は出力されず失われるため、最初の保存のときにその旨を確認する (ボタン: 「保存する」「名前を付けて保存」「キャンセル」)。
5. 外部での変更の検知 (ENG-19) は、変換前のファイル (テキストのファイル) に対して行う。

**画面**: 「形式の設定」ダイアログ (仕様 1 の項目)、名前を付けて保存の形式の選択欄。

**巨大ファイル・長時間処理**: 保存時の変換はファイルサイズに比例する長時間処理 (進捗・キャンセルあり)。一時ファイルに書いてから置き換える (ENG-22)。

**エラー**: 保存する内容が元の形式で表せない場合 (アドレスが TOOL-05 の仕様 4、TOOL-06 の仕様 4 の上限を超える) は、書き込みを始める前に理由を示し、「名前を付けて保存」で他の形式を選ぶよう案内する。

**受け入れ基準**:

- [ ] 1 バイト編集して保存すると、その行のデータとチェックサムだけが変わり、他の行は元のファイルと一致する (レコード長などの設定を引き継ぐため)。
- [ ] 「名前を付けて保存」でバイナリとしても保存できる。
- [ ] コメント行を含む Intel HEX を開くとコメント行が誤りの一覧に出て、「編集を許可」で編集して初めて保存するとき、失われる旨の確認が出る。

### TOOL-12 IPS / IPS32 パッチの形式

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-11 (形式の読み書き)。パッチの作成・適用の操作は F4-03 (EDIT-42・EDIT-43) |
| 呼び出し | エクスポートのダイアログで形式「IPS パッチ」(EDIT-42 のパッチの作成を呼ぶ)、インポートのダイアログで形式「IPS パッチ」(EDIT-43 のパッチの適用を呼ぶ)、メニュー「データ > パッチ」(EDIT-42・EDIT-43)、コマンドライン `hexed patch` (AUTO-43) |

**概要**: IPS と IPS32 のパッチファイルの読み書きを定める。パッチを作る操作 (EDIT-42) と当てる操作 (EDIT-43)、コマンドラインからの適用 (AUTO-43) が主担当で、この形式の処理を使う (00 の 1.1)。

**仕様**:

1. **IPS の形式**: ヘッダ `PATCH` (5 バイト)、レコードの並び、終端 `EOF` (3 バイト)、その後に省略できる切り詰めの長さ (3 バイト、ビッグエンディアン)。
   - レコード: オフセット (3 バイト、ビッグエンディアン)、長さ (2 バイト)、データ。長さが 0 の場合は RLE レコードで、続く 2 バイトが繰り返し回数、1 バイトが値。
   - オフセットの上限は 0xFFFFFF (16 MiB 未満)。
2. **IPS32 の形式**: ヘッダ `IPS32`、オフセットは 4 バイト、終端 `EEOF`。オフセットの上限は 0xFFFFFFFF (4 GiB 未満)。
3. **書き出しの規則**:
   - 差分 (元のデータと現在の内容) を、変更された範囲ごとのレコードにする。同じ値が 8 バイト以上続く部分は RLE レコードにする (オプション「RLE を使う」、既定: 使う)。
   - 1 レコードの長さは 65,535 バイトまで。超える範囲は分割する。
   - 差分の間隔が 5 バイト以下のときは、レコードのヘッダ (5 バイト) を節約するため 1 つのレコードにまとめる。
   - IPS では、オフセットがちょうど `0x454F46` (`EOF` の ASCII) になるレコードは終端と区別できないため、1 バイト手前から始めるレコードにする (手前の 1 バイトは元の値を入れる)。
   - 内容が短くなった場合は、切り詰めの長さを付ける。長くなった部分は通常のレコードとして書く。
   - 変更が 16 MiB 以上の位置にある場合、形式「自動」なら IPS32 を選び、「IPS」を指定していればエラーにする。4 GiB 以上の位置はどちらでも表せないためエラーにする (EDIT-42 の仕様 4)。
4. **読み込みの規則**: ヘッダの不一致、レコードの途中でのファイルの終わり、終端がないことはエラーにする。レコードの範囲が対象の長さを超える場合は、対象を延長する (IPS の一般的な動作)。ただし長さ固定のドキュメントでは、長さが変わるパッチは適用しない (EDIT-43 の仕様 6)。
5. 差分の元 (元のデータ) は EDIT-42 の仕様 1 に従う (既定は保存されている内容。2 つのファイル、履歴の 2 時点も選べる)。

**画面**: エクスポートのダイアログ (形式: 自動 / IPS / IPS32、RLE を使う)。作成の画面は EDIT-42、適用の画面は EDIT-43。

**巨大ファイル・長時間処理**: 差分はデータエンジンの変更範囲 (ピース) から求め、ファイル全体を比較しない。

**エラー**: 3、4 のとおり。壊れたパッチのエラーには、何番目のレコード (ファイル内のオフセット) かを含める。

**受け入れ基準**:

- [ ] 作った IPS を、一般的な IPS の適用ツール (Lunar IPS、Flips) で当てた結果が、現在の内容と一致する。
- [ ] 変更が `0x454F46` から始まる場合も、正しく適用できる IPS が作られる。
- [ ] 内容を短くした場合に、切り詰めの長さが付き、適用後の長さが一致する。
- [ ] 20 MiB の位置の変更が、形式「自動」で IPS32 になる。

**エラー**: 書き込みの失敗・空き容量不足は理由を表示し、それまでに作ったファイルの一覧を示す。

- [ ] 未保存の変更があるドキュメントを分割すると、変更後の内容で分割される。

### TOOL-15 インターリーブとデインターリーブ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-07 |
| 呼び出し | メニュー「ツール > ファイルツール > インターリーブ...」「ツール > ファイルツール > デインターリーブ...」、コマンドパレット「ファイルツール: インターリーブ」「ファイルツール: デインターリーブ」 |

**概要**: 複数のファイルを指定の単位で交互に並べて 1 つにし (インターリーブ)、逆に 1 つのファイルを交互に振り分けて複数に分ける (デインターリーブ)。8 bit の EPROM 2 個で 16 bit のバスを構成する場合などに使う。

**仕様**:

1. **デインターリーブ**: 入力 1 つ (ファイルまたはドキュメント)、分ける数 N (2〜16、既定 2)、単位 (1 / 2 / 4 / 8 バイト、または任意のバイト数、既定 1)。入力の先頭から単位ごとに、出力 1、出力 2、…、出力 N、出力 1、… の順に振り分ける。
   - 例: N = 2、単位 1 で `00 11 22 33` → 出力 1 は `00 22`、出力 2 は `11 33`。
   - 出力のファイル名の形式 (既定 `{base}.{index}{ext}`。偶数・奇数の用途のため `{index0}` (0 始まり) も使える)。
   - 入力の長さが「N × 単位」の倍数でない場合は、最後の不足分を指定値で埋めるか (既定 `FF`)、端数を最後の出力に入れたままにするかを選ぶ。
2. **インターリーブ**: 入力 N 個 (順序を指定)、単位。各入力から単位ずつ順に取り出して 1 つにする。
   - 入力の長さが違う場合: 「短いものを指定値で埋める」(既定 `FF`) / 「エラーにする」を選ぶ。
   - 結果は新しいドキュメントとして開く (既定) か、ファイルに保存する。
3. 実行前に、出力の数・サイズの要約を表示する。

**画面**: インターリーブとデインターリーブのダイアログ (入力の一覧、N、単位、出力、要約)。

**巨大ファイル・長時間処理**: ストリームで処理する (入力・出力ごとに 1 MB のバッファ)。処理センターに出し、キャンセルできる。

**エラー**: TOOL-13 と同じ。

**受け入れ基準**:

- [ ] `00 11 22 33` を N = 2、単位 1 でデインターリーブすると `00 22` と `11 33` になる。
- [ ] デインターリーブの結果をインターリーブすると、元とハッシュが一致する (単位 1・2・4 で確認)。
- [ ] 長さの違う入力で、指定値で埋めて結合される。

### TOOL-17 安全な削除 (シュレッダー)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-07 |
| 呼び出し | メニュー「ツール > ファイルツール > 安全な削除...」、コマンドパレット「ファイルツール: 安全な削除」 |

**概要**: ファイルの内容を上書きしてから削除し、通常の方法では復元できないようにする。安全な削除の主担当で、ディスク・範囲・空き領域・スラックの消去 (FOR-30・FOR-31) もこの機能の上書きの方式 (仕様 2) を使う (00 の 1.1)。

1. 対象: ファイル (複数可) とフォルダ (中のファイルをすべて対象にする)。ドラッグ & ドロップで追加できる。
2. 上書きの方式:

   | 方式 | 内容 |
   | --- | --- |
   | 0 で 1 回 (既定) | すべて `00` で 1 回上書きする |
   | 乱数で 1 回 | 暗号論的な乱数で 1 回上書きする |
   | DoD 5220.22-M (3 回) | `00`、`FF`、乱数の順に 3 回上書きする |
   | 任意 | 回数 (1〜35) と、各回のパターン (Hex バイト列 (00 の 6.3) または乱数) を指定する |

3. 手順 (ファイルごと):
   1. ファイルを排他で開く (他のプログラムが開いている場合は失敗にする)。
   2. 方式に従って全体を上書きし、各回の後に `FlushFileBuffers` でディスクに書き出す。
   3. オプション「最後の上書きを読み戻して確認する」(既定: オフ) がオンなら、読み戻して確認する。
   4. ファイルの長さを 0 にし、ファイル名をランダムな名前に 1 回変えてから削除する (ごみ箱には入れない)。
   5. NTFS の代替データストリームがある場合は、それらも同じ方式で上書きしてから削除する。
4. 実行前の確認ダイアログ (00 の 9 章): 対象のファイル数・合計サイズ・方式と、「この操作は取り消せません。ファイルはごみ箱に入らず、復元できません」と表示する。ボタン: 「完全に削除する」「キャンセル」。
5. 確認ダイアログに、次の限界を必ず表示する。
   - SSD・USB メモリ・SD カードでは、ウェアレベリングのため、上書きしても元のデータが別の場所に残ることがある。
   - ボリュームシャドウコピー、バックアップ、OneDrive などの同期フォルダ、圧縮・暗号化・重複除去されたファイル、ReFS などのコピーオンライトのファイルシステムでは、元のデータが残ることがある。
   - 空き領域・スラック領域の消去はこの機能では行わない (FOR-31 を参照)。
6. アプリで開いているファイルは対象にできない (先に閉じるよう案内する)。
7. システムフォルダ (`C:\Windows`、`Program Files` など) と、ドライブのルートそのものは対象にできない。
8. 書き込み保護モード (FOR-01) が有効な間は実行できない (メニューを無効表示にし、ツールチップに「書き込み保護モードが有効です」と示す)。

**画面**: 安全な削除のダイアログ (対象の一覧・方式・オプション)、確認ダイアログ、処理センターの進捗。

**巨大ファイル・長時間処理**: 上書きはストリームで行い、処理センターにファイルごとと全体の進捗を出す。キャンセルした場合、途中まで上書きしたファイルは削除せずに残し、その旨 (内容が壊れていること) を表示する。

**エラー**: 開けない・書けないファイルは飛ばして続け、最後に失敗したファイルの一覧と理由を表示する。

**受け入れ基準**:

- [ ] 削除したファイルの元の領域を (テスト用の仮想ディスクで) 読むと、指定のパターンで上書きされている。
- [ ] 確認ダイアログに、取り消せないことと SSD などの限界が表示される。
- [ ] 他のプログラムが開いているファイルが、失敗として一覧に出る。
- [ ] アプリで開いているファイルを対象にできない。
- [ ] `C:\Windows` 以下のファイルを対象にできない。
- [ ] 書き込み保護モードではメニューが無効になる。

### TOOL-18 チェックサムファイルの作成

| 項目 | 内容 |

2. アルゴリズム: 06 のアルゴリズムから選ぶ (既定 SHA-256)。
3. 出力の形式:

   | 形式 | 内容 | 既定のファイル名 |
   | --- | --- | --- |
   | GNU (coreutils) | 各行 `ハッシュ値  相対パス`。バイナリモードの印 `*` を付けるかを選べる | `SHA256SUMS` (アルゴリズムに応じて変える) |
   | BSD | 各行 `SHA256 (相対パス) = ハッシュ値` | `CHECKSUM.SHA256` |
   | ファイルごと (サイドカー) | 対象のファイルごとに `ファイル名.sha256` を作る (中身は GNU 形式の 1 行) | `ファイル名.sha256`、`.md5`、`.sha1`、`.sha512` |
   | SFV | 各行 `相対パス ハッシュ値` (CRC-32 のみ) | `フォルダ名.sfv` |

4. パスは、チェックサムファイルの場所からの相対パスで書く。区切り文字は `/` と `\` から選べる (既定 `/`。他の OS の `sha256sum` で検証できるようにするため)。
5. 出力の文字コードは UTF-8 (BOM なし)、改行は LF (既定) / CRLF。
6. 出力先に同名のファイルがある場合は上書きの確認を出す。

**画面**: チェックサムファイル作成のダイアログ (対象、アルゴリズム、形式、オプション)、処理センターの進捗。

**巨大ファイル・長時間処理**: ハッシュの計算は 06 と同じ速度。ファイルごとの進捗と全体の進捗を処理センターに出し、キャンセルできる。

**エラー**: 読めないファイルは飛ばし、最後に一覧と理由を表示する (チェックサムファイルには含めない)。

**受け入れ基準**:

- [ ] GNU 形式で作った `SHA256SUMS` を、Linux の `sha256sum -c` で検証して全件 OK になる。
- [ ] BSD 形式を macOS の `shasum -c` で検証できる。
- [ ] 日本語のファイル名を含むフォルダで、UTF-8 のパスが正しく書かれる。

### TOOL-19 チェックサムファイルの検証

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | メニュー「ツール > ファイルツール > チェックサムファイルの検証...」、コマンドパレット「ファイルツール: チェックサムファイルを検証」、チェックサムファイルをアプリで開くときの InfoBar の「検証する」、コマンドライン `hexed hash --check` (AUTO-38) |

**概要**: チェックサムファイルを読み、記載されたファイルのハッシュを計算して一致を確認する。

**仕様**:

1. 対応する形式: TOOL-18 の全形式。形式とアルゴリズムは、拡張子・ファイル名・ハッシュ値の長さ・行の書式から自動で判定する。判定できない場合はアルゴリズムを選ばせる。
2. 単体のファイルを選んだ場合に、同じ名前のサイドカー (`ファイル名.sha256` など) があれば、それで検証することを提案する。
3. 結果は共通の結果一覧 (00 の 9 章) に出す。列: 状態、パス、期待値、計算値、サイズ。
   - 状態: 「一致」/ 「不一致」/ 「見つからない」/ 「読み取りエラー」。色に加えてアイコンと文字で示す。
4. 一覧の上に件数の要約 (例: 「一致 120、不一致 1、見つからない 2」) を表示する。
5. 不一致の行の右クリック「開く」でファイルを開ける。
6. ハッシュ値の比較は大文字・小文字を区別しない。
7. 拡張子 `.sha256` などのファイルや `SHA256SUMS` をアプリで開いた場合、エディタ上部に InfoBar「チェックサムファイルです」と「検証する」ボタンを出す。

**画面**: 結果一覧のパネル、処理センターの進捗。

**巨大ファイル・長時間処理**: ファイルごとに順に計算し、結果は確定したものから一覧に出す。キャンセルできる。

**エラー**: チェックサムファイルの書式の誤りは、行番号を示して該当行を飛ばす。

**受け入れ基準**:

- [ ] 1 ファイルを改ざんしたフォルダで、そのファイルだけが「不一致」になる。
- [ ] `sha256sum` で作ったファイル (`*` 付きの行を含む) を検証できる。
- [ ] `.md5` を開くと InfoBar の「検証する」で検証が始まる。
- [ ] 状態を色だけでなくアイコンと文字で区別できる。

### TOOL-20 フォルダの比較

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | メニュー「ツール > ファイルツール > フォルダの比較...」、コマンドパレット「ファイルツール: フォルダを比較」 |

**概要**: 2 つのフォルダの中のファイルを相対パスで対応付け、内容が同じか違うかを一覧にする。違うファイルは、ファイルの比較 (06) で開いて差分を見る。

**仕様**:

1. 2 つのフォルダを選ぶ。オプション: サブフォルダを含める (既定: 含める)、対象のファイル名のパターン (例: `*.bin`、既定: すべて)。
2. 比較の手順:
   1. 相対パスで対応付ける (大文字・小文字は区別しない)。
   2. サイズが違えば「異なる」。
   3. サイズが同じなら、内容をバイトごとに比較する (オプション「ハッシュで比較」を選ぶと SHA-256 で比較し、その値を一覧に出す)。
3. 結果を共通の結果一覧に出す。列: 状態 (「同じ」/ 「異なる」/ 「左だけ」/ 「右だけ」/ 「読み取りエラー」)、相対パス、左のサイズ、右のサイズ、最初の差分のオフセット (バイトごとの比較の場合)。既定では「同じ」を隠す (絞り込みで表示できる)。
4. 「異なる」の行を開く (Enter / ダブルクリック) と、2 つのファイルをファイルの比較の画面 (06) で開く。
5. フォルダ全体の同期やコピーは行わない (この機能は比較の表示だけ)。

**画面**: フォルダの比較のダイアログ、結果一覧のパネル。

**巨大ファイル・長時間処理**: ファイルを順に比較し、結果は確定したものから一覧に出す。違いが見つかった時点でそのファイルの比較を止める (最初の差分のオフセットを記録)。キャンセルできる。

**エラー**: 読めないファイル・フォルダは「読み取りエラー」として一覧に出し、続ける。

**受け入れ基準**:

- [ ] 1 ファイルだけ違う 2 つのフォルダで、そのファイルだけが「異なる」になり、最初の差分のオフセットが正しい。
- [ ] 片方にしかないファイルが「左だけ」「右だけ」になる。
- [ ] 「異なる」の行からファイルの比較が開く。

### TOOL-21 NTFS 代替データストリームの管理

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-09 |
| 呼び出し | メニュー「ファイル > 代替データストリーム...」「ツール > ファイルツール > 代替データストリーム...」、コマンドパレット「ファイルツール: 代替データストリームを管理」「ファイル: 代替データストリームを開く」、タブの右クリック「代替データストリーム...」、ENG-37 の InfoBar の「一覧を表示」 |

**概要**: NTFS (と ReFS) のファイルが持つ代替データストリーム (ADS) を一覧し、開く・作成・名前の変更・削除・書き出し・読み込みを行う管理画面。ストリームをドキュメントとして開いて編集・保存する処理は ENG-37 が担当する (00 の 1.1)。

**仕様**:

1. 対象のファイルを選ぶ (既定はアクティブなドキュメントのファイル)。
2. `FindFirstStreamW` / `FindNextStreamW` でストリームを列挙し、一覧に表示する。列: ストリーム名 (`::$DATA` の既定のストリームを含む)、サイズ、先頭のバイトの Hex (16 バイト)、既知のストリームの説明 (例: `Zone.Identifier` は「インターネットから取得したファイルの印」)。
3. 操作:
   - 開く: ストリームを新しいタブで開く (ENG-37。タブの名前は `ファイル名:ストリーム名`)。
   - 作成: 名前を入力して空のストリームを作り、開く (ENG-37)。名前に使えない文字 (`:` `\` `/` と制御文字) を含む場合は入力欄を赤枠にする。同名のストリームがある場合は作らない。
   - 名前の変更: 新しい名前でコピーしてから元を削除する (NTFS にストリームの名前変更の API がないため)。
   - 削除: 確認ダイアログ (ストリーム名とサイズ、取り消せないこと) を出してから削除する。ボタンは「削除」「キャンセル」。タブで開いているストリームは削除・名前の変更・読み込みができない (先に閉じるよう示す)。
   - ファイルに書き出す / ファイルから読み込む (ストリームの内容を置き換える)。
4. 代替データストリームに対応しないボリューム (FAT、exFAT、ネットワーク上の一部の共有) では、「このボリュームは代替データストリームに対応していません」と表示する。ReFS は対応するボリュームとして扱う (サイズの上限は ENG-37 の仕様 5)。
5. フォルダを対象にした場合も、フォルダ自体のストリームを一覧する。
6. 書き込み保護モード (FOR-01) が有効な間は、一覧と「開く」(読み取り専用) だけができ、作成・名前の変更・削除・読み込みは無効にする。

**画面**: 代替データストリームのダイアログ (またはパネル)。一覧とボタン (開く・作成・名前の変更・削除・書き出し・読み込み)。

**巨大ファイル・長時間処理**: 列挙はストリームの数に比例する。書き出し・読み込みはストリームでコピーし、処理センターに出す。

**エラー**: アクセス拒否・ボリュームの非対応は理由を表示する。

**受け入れ基準**:

- [ ] インターネットから取得したファイルで `Zone.Identifier` が一覧に出て、説明が表示される。
- [ ] ストリームを作成・削除でき、`dir /r` の結果と一致する。
- [ ] FAT32 の USB メモリのファイルで、非対応の表示が出る。

### TOOL-22 電卓 (式の計算)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-08 |
| 呼び出し | メニュー「ツール > 電卓」、コマンドパレット「ツール: 電卓」(ショートカットは既定なし) |

**概要**: 入力式 (00 の 6 章) と同じ書き方で式を計算し、結果を 16 進・10 進・8 進・2 進で同時に表示する。開いているドキュメントの位置や値も式で使える。

**仕様**:

1. 電卓はパネル (00 の 9 章) として開き、編集を妨げない。
2. 式の書き方は 00 の 6 章と同じ (数値の書き方、演算子、名前 `cur` `start` `end` `sel.start` `sel.end` `sel.last` `sel.len` `sector` `rec` `recno` `bm.名前`、読み取り関数 `u8(x)`〜`f64be(x)`)。名前と読み取り関数はアクティブなドキュメントの値を使う。ドキュメントがない場合、名前や読み取り関数を使うとエラーにする。
3. 電卓だけで使える追加の書き方 (00 の 6.2 の「電卓の独自の関数」。他の入力欄では使えない):

   | 書き方 | 意味 |
   | --- | --- |
   | `u16(式)` `u24(式)` `u32(式)` `u64(式)`、`s16(式)`〜`s64(式)` | エンディアンを省いた読み取り。アクティブなドキュメントのエンディアン (VIEW-11) で読む。エンディアンを明示する `u32le(式)` などは 00 の 6.2 の共通の読み取り関数 |
   | `ans` | 直前の結果 |
   | `min(a, b)` `max(a, b)` `abs(a)` | 最小・最大・絶対値 |
   | `align(a, n)` | `a` を `n` の倍数に切り上げる |
   | `popcnt(a)` `clz(a)` `ctz(a)` | 1 のビットの数、上位・下位の 0 のビットの数 (プログラマモードのビット幅で数える) |
   | `rol(a, n)` `ror(a, n)` | ビットの回転 (プログラマモードのビット幅) |
   | `bswap(a)` | バイト順の反転 (プログラマモードのビット幅) |
   | `==` `!=` `<` `<=` `>` `>=` | 比較 (結果は 1 / 0) |

4. 計算の規則:
   - 整数の式は 64 bit の符号付き整数で計算する。桁あふれした場合は結果の横に「桁あふれ」と表示する (結果は 2 の補数で折り返した値)。
   - 小数点を含む数値 (`1.5`、`1.5G` は 1.5 × 2^30 で整数になる場合を除く) を含む式は、倍精度浮動小数点数で計算し、結果を 10 進の小数で表示する。
   - 整数の割り算は 0 の方向に切り捨てる。0 での割り算はエラー。
   - シフトの量が 64 以上の場合はエラー。
5. 結果の表示: 16 進、10 進 (符号付き・符号なし)、8 進、2 進 (4 桁ごとに区切る)、ファイルサイズ表記 (例: `1.5 GiB`)。各行の横にコピーのボタンを置く。10 進の表示は地域設定の桁区切りに従い、コピーする値は桁区切りなしにする。
6. 入力しながら結果を更新する (式が不完全なときは前の結果を薄く表示する)。Enter で確定し、履歴に追加する。
7. 履歴: 式と結果を最大 1,000 件保存し、再起動後も使える。履歴をクリックすると式を入力欄に戻す。
8. 結果の使いみち (ボタン): 「この位置へ移動」(結果をオフセットとしてジャンプ)、「カーソル位置に書き込む」(サイズ 1 / 2 / 4 / 8 バイトとエンディアンを選ぶ。Undo できる)、「選択範囲の長さにする」。

**画面**: パネル。上に入力欄、その下に結果の表 (基数ごとの行)、ボタン、履歴。入力欄は左から右 (アラビア語・ペルシア語の表示でも)。

**巨大ファイル・長時間処理**: 該当なし (読み取り関数の読み込みは 1 回 8 バイトまで)。

**エラー**: 式の誤りは入力欄の赤枠と、誤りの位置・説明 (例: 「3 文字目: 閉じ括弧がありません」) で示す (00 の 9 章の入力欄)。

**受け入れ基準**:

- [ ] `0x1F00 + 10h * 2` の結果が 16 進で `0x1F20` になる。
- [ ] `end - cur` がアクティブなドキュメントの値で計算される。
- [ ] `u32be(0)` が先頭の 4 バイトをビッグエンディアンで読んだ値になる。
- [ ] ドキュメントのエンディアンがビッグのとき、`u32(0)` が `u32be(0)` と同じ値になる。
- [ ] `ans` や `popcnt` を、ジャンプ欄など電卓以外の入力欄で使うとエラーになる。
- [ ] `0x7FFFFFFFFFFFFFFF + 1` で「桁あふれ」が表示される。
- [ ] `1 / 0` がエラーになる。
- [ ] 履歴が再起動後も残る。
- [ ] 「カーソル位置に書き込む」が Ctrl+Z で戻る。
- [ ] 地域設定がドイツ語でも、入力の小数点は `.` で解釈される。

### TOOL-23 プログラマモード

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-08 |
| 呼び出し | 電卓パネルの「プログラマ」の切り替え、コマンドパレット「ツール: 電卓 (プログラマモード)」 |

**概要**: ビット幅と符号を指定した整数の計算と、ビット単位の表示・操作を行う。

**仕様**:

1. ビット幅: 8 / 16 / 32 / 64 (既定 32)。符号: 符号なし / 符号付き (2 の補数、既定 符号なし)。計算はこのビット幅で折り返す。
2. ビットの表: 現在の値の全ビットを、上位から 4 ビットごとに区切って表示する。各ビットはクリック (またはフォーカスして Space) で 0 / 1 を切り替えられる。各ビットの下にビット番号を表示する。
3. ビットの選択: ビットの範囲をドラッグ (または Shift+矢印) で選ぶと、その範囲の値 (ビットフィールドの値) と、範囲を取り出すマスクとシフトの式 (例: `(x >> 4) & 0xF`) を表示する。
4. 演算のボタン: AND、OR、XOR、NOT、NAND、NOR、左右シフト (論理 / 算術)、左右の回転、2 の補数 (符号反転)、バイトスワップ。キーボードでは式として入力できる。
5. 「カーソル位置から読む」: アクティブなドキュメントのカーソル位置から、ビット幅ぶんのバイトをエンディアンを指定して読み込む。
6. 表示する基数ごとの値は TOOL-22 と同じ。符号付きの場合は 10 進を符号付きで表示する。

**画面**: 電卓パネルの中で、結果の表の下にビットの表を置く。ビットの各セルにスクリーンリーダー用の名前 (例: 「ビット 31、値 1」) を付ける。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし (ビット幅で折り返す)。

**受け入れ基準**:

- [ ] 8 bit・符号付きで `0x7F + 1` が `-128` になる。
- [ ] ビットをクリックすると値が変わり、他の基数の表示も変わる。
- [ ] ビットの範囲を選ぶと、ビットフィールドの値とマスク・シフトの式が表示される。
- [ ] ビットの表をキーボードとスクリーンリーダーで操作できる。

### TOOL-24 基数・データ型の変換

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-08 |
| 呼び出し | メニュー「ツール > 基数・データ型の変換」、コマンドパレット「ツール: 基数・データ型の変換」 |

**概要**: 1 つの値を、16 進・10 進・8 進・2 進・浮動小数点・文字列 (ASCII・UTF-8・UTF-16・EBCDIC など) の表現で同時に表示し、どの欄からでも入力して他の欄を変換する。

**仕様**:

1. 欄の一覧 (どれに入力しても他の欄を更新する):

   | 欄 | 内容 |
   | --- | --- |
   | バイト列 (Hex) | 変換の基準。00 の 6.3 の書式で入力する |
   | 16 進 / 10 進 (符号なし・符号付き) / 8 進 / 2 進 | バイト列を整数として解釈した値 (1〜8 バイト。8 バイトを超える場合は空欄にする) |
   | half / float / double | バイト列を IEEE 754 として解釈した値 (2 / 4 / 8 バイトのとき) |
   | ASCII | 0x20〜0x7E 以外は `\xNN` で表示する |
   | UTF-8 / UTF-16 LE / UTF-16 BE / UTF-32 | 不正なバイト列は置換文字と警告で示す |
   | コードページ | 選んだコードページ (Shift_JIS、EBCDIC 037 / 500 / 1047 / 930 など。F1-06 の全コードページ) の文字列 |
   | Base64 | バイト列の Base64 |

2. エンディアン (リトル / ビッグ) を切り替えると、数値の欄の解釈が変わる (バイト列は変わらない)。
3. 「カーソル位置から読む」(選択範囲がある場合は選択範囲、最大 64 バイト)、「カーソル位置に書き込む」(Undo できる)、「検索バーに送る」(バイト列を Hex の検索条件にする)。
4. 文字列の欄に入力した場合は、その文字コードでバイト列に変換する。変換できない文字は赤字で示し、変換しない。

**画面**: パネル。欄を縦に並べ、各欄の横にコピーのボタンを置く。数値・文字列の欄は左から右で表示する (アラビア語などの文字列の内容は Unicode の双方向アルゴリズムに従う)。

**巨大ファイル・長時間処理**: 該当なし (最大 64 バイト)。

**エラー**: 解釈できない入力は入力欄の赤枠と説明で示す。

**受け入れ基準**:

- [ ] 10 進の欄に `1078530011` を入力すると、エンディアンがビッグのとき float の欄が `3.1415927` になる。
- [ ] UTF-8 の欄に「あ」を入力するとバイト列が `E3 81 82` になり、UTF-16 LE の欄に「あ」を入力するとバイト列が `42 30` になる (各文字列の欄は、基準のバイト列をその文字コードで解釈した結果を示すため、`E3 81 82` のときの UTF-16 LE の欄は「あ」にならない)。
- [ ] EBCDIC 037 のバイト列 `C1 C2 C3` が `ABC` と表示される。
- [ ] 「カーソル位置から読む」で選択範囲のバイト列が入る。

### TOOL-25 IEEE 754 浮動小数点のビジュアライザ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | メニュー「ツール > 浮動小数点のビジュアライザ」、コマンドパレット「ツール: 浮動小数点のビジュアライザ」、データインスペクタの float / double の行の右クリック「ビジュアライザで開く」 |

**概要**: 浮動小数点数のビット構成 (符号・指数部・仮数部) を図で示し、各部分の意味と正確な値を表示する。ビットを切り替えて値の変化を確かめられる。

**仕様**:

1. 形式: half (16 bit)、bfloat16、float (32 bit)、double (64 bit)、x87 拡張精度 (80 bit)。
2. 表示する内容:
   - ビットの列。符号・指数部・仮数部を、色に加えて上部の区間ラベル (「符号」「指数部 (8 ビット)」「仮数部 (23 ビット)」) で区別する。各ビットはクリックで切り替えられる。
   - 符号 (0 / 1 と +/-)、指数部 (ビット列、バイアス付きの値、バイアスを引いた値)、仮数部 (ビット列、暗黙の 1 を含めた値)。
   - 分類: 正規化数 / 非正規化数 / ゼロ (+0 / -0) / 無限大 / NaN (quiet / signaling とペイロード)。
   - 値: 最短の 10 進表現 (往復で同じビットになる最短の表記)、正確な 10 進展開 (全桁)、16 進の浮動小数点表記 (例: `0x1.921fb6p+1`)。
   - 隣の値: 1 つ大きい・1 つ小さい表現可能な値と、ULP (最小単位) の大きさ。
3. 入力: 10 進の値 (`0.1` など。最も近い表現可能な値に丸め、丸めの誤差を表示する)、Hex のバイト列、ビットの直接の切り替え。`inf`、`-inf`、`nan` も入力できる。
4. 「カーソル位置から読む」(エンディアンを指定)、「カーソル位置に書き込む」(Undo できる)。
5. 形式を切り替えると、同じ値を新しい形式で表したときの値と丸めの誤差を表示する。

**画面**: パネルまたは独立したウィンドウ。ビットの各セルにスクリーンリーダー用の名前 (例: 「指数部 ビット 3、値 1」) を付ける。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 解釈できない入力は入力欄の赤枠と説明で示す。

**受け入れ基準**:

- [ ] `0.1` を float で入力すると、ビット列 `0x3DCCCCCD`、正確な値 `0.100000001490116119384765625`、丸めの誤差が表示される。
- [ ] `0x00000001` (float) が「非正規化数」と分類される。
- [ ] 指数部のビットを全部 1 にすると、無限大または NaN と分類される。
- [ ] 区間を色だけでなくラベルでも区別できる (ハイコントラストテーマで確認)。

### TOOL-26 文字コード表

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | メニュー「ツール > 文字コード表」、コマンドパレット「ツール: 文字コード表」 |

**概要**: 選んだ文字コード (コードページ) の 256 のバイト値と文字の対応を表で表示する。文字を選んでカーソル位置に入力できる。

**仕様**:

1. 文字コードは F1-06 で対応する全コードページから選ぶ。既定はアクティブなドキュメントのテキスト列の文字コード。
2. 1 バイトの文字コード: 16 × 16 の表で、各セルにバイト値 (Hex) と文字を表示する。制御文字は略称 (`NUL`、`LF` など) で、未定義のバイトは空欄 (斜線) で表示する。
3. 複数バイトの文字コード (Shift_JIS、EUC-JP、GBK、Big5、UHC など): 最初の表で先行バイトを示し、先行バイトのセルを選ぶと、2 バイト目の表を表示する。
4. セルを選ぶと、詳細欄に次を表示する: バイト値 (Hex・10 進・8 進・2 進)、文字、Unicode のコードポイント (`U+XXXX`)、Unicode の文字名 (英語)、同じ文字の UTF-8 / UTF-16 のバイト列。UTF-16 のバイト列は既定でリトルエンディアン (LE、例: 「あ」は `42 30`) で表示し、詳細欄の「LE / BE」の切り替えでビッグエンディアン (BE、例: `30 42`) にできる (切り替えは記憶する)。
5. 表示の切り替え: Hex / 10 進 / 8 進の見出し、「一覧表示」(1 行 1 バイトの表。列: Hex、10 進、8 進、文字、コードポイント、名前)。
6. 操作: 「カーソル位置に入力」(Enter / ダブルクリック。現在の入力モード (上書き / 挿入) に従う)、「コピー」(文字 / バイト値)、文字の検索 (文字・名前・コードポイントで検索して該当のセルを選ぶ)。
7. 表示できない文字は代替フォントで表示し、それでも表示できない場合は `□` と文字名で示す。

**画面**: パネル。表のセルはキーボード (矢印キー) で移動でき、スクリーンリーダーで「0x41、A、ラテン大文字 A」のように読み上げる (文字名は英語)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] コードページ 437 の表で `0xB0` が `░` と表示される。
- [ ] Shift_JIS で先行バイト `0x82` を選ぶと、2 バイト目の表にひらがなが表示される。セル `0xA0` (「あ」) の詳細欄の UTF-16 のバイト列が、既定で `42 30` (LE)、BE に切り替えると `30 42` になる。
- [ ] セルを選んで Enter を押すと、カーソル位置にそのバイトが入力され、Undo できる。
- [ ] 表を矢印キーで移動し、スクリーンリーダーで読み上げられる。

### TOOL-28 日時の変換

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | メニュー「ツール > 日時の変換」、コマンドパレット「ツール: 日時の変換」 |

**概要**: 日時を、ファイルや構造体でよく使われる各種のタイムスタンプ形式の値とバイト列に相互に変換する。インスペクタ (05) の日時の型と同じ定義を使う。

**画面**: パネル。日時の入力欄と、形式ごとの行 (数値・バイト列・コピーのボタン)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 5 のとおり。解釈できない入力は入力欄の赤枠と説明で示す。

**受け入れ基準**:

- [ ] `2000-01-01T00:00:00Z` の FILETIME が `0x01BF53EB256D4000` になる。
- [ ] Unix 時刻 `0` が `1970-01-01T00:00:00Z` と表示される。
- [ ] 同じバイト列を読んだとき、データインスペクタの表示と一致する。

# 機能仕様書: データエンジン、データソース、開く・保存

この文書は、編集対象のデータを保持するデータエンジンと、ファイル・ディスク・プロセスメモリなどのデータソース、およびドキュメントを開く・保存する・閉じる操作の振る舞いを定める。書式・用語・入力式・メニュー構成・ショートカットは [00-overview.md](00-overview.md) に従う。

対象とするロードマップの ID: F0-01、F0-08、F0-09、F0-13、F1-18、F1-19 (最近使ったファイルの部分)、F1-23、F2-09、F2-10、F4-09。あわせて、調査 ([../research/feature-survey.md](../research/feature-survey.md) の 2.1 と 3 章) にあるこの領域の機能をすべて含める。ロードマップにない機能は「追加 (フェーズ N 提案)」と書く。

関連する他の文書:

- 表示 (読み込み中・読めないバイトの見せ方、巨大なスクロール) は 02 (VIEW)。
- 編集操作・Undo / Redo の操作体系・塗りつぶしの UI は 03 (EDIT)。この文書はそれらを支えるエンジン側の振る舞いを定める。
- タブ、セッション復元、設定画面、Explorer 連携は 09 (UI)。
- 配布形態ごとの違い (MSIX での補助プロセスなど) は 10 (PKG)。
- パーティション・ファイルシステム解析、E01 などのイメージ形式、ディスクのクローンは 12 (FOR)。

## 1. データエンジン

### ENG-01 データソースの抽象化 (IByteSource)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-01 |
| 呼び出し | なし (内部の仕組み) |

**概要**: ファイル、ディスク、プロセスメモリなど、すべての元データを `IByteSource` という共通の形で扱う。データエンジンと各機能は、データソースの種類ではなく、データソースが申告する能力 (書けるか、長さを変えられるかなど) を見て振る舞いを決める。

**仕様**:

1. `IByteSource` は `HexEditor.Core` に置き、WinUI に依存しない。
2. すべてのデータソースは次の情報を提供する。

   | 項目 | 型 | 意味 |
   | --- | --- | --- |
   | 表示名 | 文字列 | タブとタイトルに出す名前 (例: `data.bin`、`ディスク 1`、`notepad.exe (PID 1234)`) |
   | 識別子 | 文字列 | 同じ対象を二重に開かないための比較キー (ファイルは最終パスとファイル ID、ディスクはデバイスのパスとシリアル番号) |
   | 長さ | `long` | バイト数。0 以上、最大 2^63 − 1 |
   | ベースアドレス | `long` | オフセット 0 に対応するアドレス。ファイルは 0 |
   | 論理セクタサイズ | `int` | 読み書きの境界。ファイルは 1 (表示上の `sector` は 512)、ディスクは 512 / 4096 など |
   | 物理セクタサイズ | `int` | 情報表示用。不明な場合は論理セクタサイズと同じ |
   | 能力 | フラグ | 下の表 |

3. 能力のフラグ:

   | フラグ | 意味 | ファイル | ディスク・ボリューム | プロセスメモリ |
   | --- | --- | --- | --- | --- |
   | `CanWrite` | 書き込める | ○ (権限による) | ○ (補助プロセス経由。USB ストレージのボリュームは直接も可。ENG-29) | ○ (権限による) |
   | `CanResize` | 長さを変えられる (挿入・削除できる) | ○ | × | × |
   | `CanReplace` | 一時ファイルと置き換える保存ができる | ○ | × | × |
   | `IsVolatile` | データが外部要因で変わりうる | × (外部変更は ENG-19 で検知) | ○ | ○ |
   | `HasGaps` | 読めない範囲がある (領域マップを持つ) | × | × (読み取りエラーは別扱い) | ○ |
   | `NeedsAlignment` | 読み書きをセクタ境界に揃える必要がある | × | ○ | × (ページ単位で扱う) |

4. 読み込みは非同期で、位置と長さを指定する。結果には「読めたバイト」と「読めなかった範囲とその理由 (未割り当て・アクセス不可・I/O エラー・切断)」を含める。1 回の読み込みが一部失敗しても、読めた部分は返す。末尾 (長さ) を越える範囲を指定した場合は、末尾までのバイトだけを返し、返す長さが指定より短くなる。末尾を越えた部分はエラーにせず、「読めなかった範囲」にも含めない。
5. 読み込みは複数のスレッドから同時に呼べる (スレッドセーフ)。ファイルは `RandomAccess.Read` を使う。`MemoryMappedFile` は使わない。
6. 書き込みは `CanWrite` のデータソースだけが提供する。書き込みは保存処理 (ENG-20) からだけ呼ばれ、編集操作が直接データソースに書くことはない (例外: ENG-34 の即時書き込みモード)。
7. 領域マップ (`HasGaps` の場合): 範囲ごとに「読める / 未割り当て / アクセス不可」と付加情報 (保護属性、モジュール名など) を返す。
8. 変更通知: データソースは「外部で変更された」「切断された」を通知できる。通知の扱いは ENG-19 と各データソースの機能で定める。
9. 新しいデータソースの種類は、プラグイン (08) からも追加できる。その場合も同じ能力のフラグで振る舞いが決まる。

**画面**: なし。データソースの種類と能力は、ステータスバーのデータソース表示 (例: 「ファイル」「ディスク (読み取り専用)」) とドキュメントのプロパティで確認できる。

**巨大ファイル・長時間処理**: 長さを求めるのに全体を読まないこと。長さは OS への問い合わせ (ファイルサイズ、ディスクの長さ、アドレス空間の上限) で求める。

**エラー**: 読み込みの失敗は例外ではなく、結果の「読めなかった範囲」で返す。データソースそのものが使えなくなった場合 (デバイスの取り外し、プロセスの終了、接続の切断) は「切断」を通知する。

**受け入れ基準**:

- [ ] 能力のフラグを偽装したテスト用のデータソースで、`CanResize` が偽のとき挿入・削除が無効になり、`CanWrite` が偽のとき保存が無効になる。
- [ ] 一部の範囲が読めないテスト用のデータソースで、読めた部分のバイトと読めなかった範囲が両方返る。末尾を越える範囲を指定すると、末尾までのバイトだけが返り (返る長さが指定より短い)、エラーにならず、末尾を越えた部分は読めなかった範囲にも含まれない。
- [ ] 8 スレッドから同時に読み込んでも結果が正しい。
- [ ] `HexEditor.Core` が WinUI の名前空間を参照していないことをビルドで確認できる。

### ENG-02 ピースツリー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-01 |
| 呼び出し | なし (内部の仕組み) |

**概要**: ドキュメントの内容を、元データを変更せずに「ピース」の並びとして表す。ピースは永続的な平衡木 (AVL 木) で管理し、挿入・削除・オフセットの検索をピースの数の対数時間で行う。

**仕様**:

1. ピースは次の 3 種類のいずれかの範囲を指す。
   - 元データ: データソースの (開始位置, 長さ)。
   - 追加データ: 追加バッファ (ENG-04) の (開始位置, 長さ)。
   - 生成データ: 塗りつぶし・乱数などの規則 (ENG-03) と長さ。
2. ピースは AVL 木のノードに文書の順に並べる (1 ノードに 1 ピース)。各ノードは部分木の合計の長さ・ピースの数・高さを持つ。挿入・削除・範囲の複製は、木の分割 (split) と結合 (join) で行う。分割・結合はどちらも O(log n) で、範囲の複製では部分木をそのまま共有できる (複製するピースの数に関係なく O(log n))。
3. 次の操作を提供する。いずれもピースの数を n として O(log n) で行う (データ量に依存しない)。
   - オフセットからピースを探す。
   - 挿入: 指定オフセットにバイト列、または他のピースの範囲を挿入する。
   - 削除: 指定範囲を削除する。
   - 上書き: 削除と挿入を 1 つの操作として行う。長さは変わらない。
   - 範囲の複製: 同じドキュメント内の範囲を、データをコピーせずピースの参照として別の位置に挿入する (コピー & 貼り付け)。
4. 隣り合うピースが同じデータの連続した範囲を指す場合は 1 つにまとめる。連続した文字入力は追加バッファの末尾に追記し、直前のピースを伸ばす。
5. ドキュメントの長さの上限は 2^63 − 1 バイト。操作の結果がこれを超える場合はその操作を拒否する。
6. 読み込みは、範囲にかかるピースを順にたどり、元データはブロックキャッシュ (ENG-06) から、追加データは追加バッファから、生成データは規則から計算して返す。
7. 「変更された範囲」の列挙を提供する。変更された範囲とは、元データ以外のピース、または元データのピースのうちドキュメント上の位置と元データ上の位置が異なるもの。表示の強調 (02) と保存方式の選択 (ENG-20) で使う。
8. ドキュメントを開いた直後は、元データ全体を指すピース 1 つだけの木になる (長さ 0 のファイルではピースなし)。
9. 他のドキュメントからの貼り付けは、データを追加バッファに複製する (他のドキュメントのデータソースは参照しない)。
10. 長さを変えられないデータソース (`CanResize` が偽) では、同じピースツリーを上書きだけに制限して使う (ENG-07)。

**画面**: なし。

**巨大ファイル・長時間処理**: 1 回の挿入・削除・上書き・範囲の複製は、扱うデータ量に関係なく 100 ms 以内に終わる (00 の 11.1)。100 GB の範囲の削除も 1 バイトの削除と同じ時間で終わる。

**エラー**: 長さの上限を超える操作、範囲外を指す操作は拒否し、ドキュメントを変更しない。呼び出し側 (03) が利用者に理由を示す。

**受け入れ基準**:

- [ ] 100 GB の (疎な) ファイルで、先頭・中央・末尾への 1 バイトの挿入がそれぞれ 100 ms 以内に終わる。
- [ ] 100 GB のファイルで、10 GB の範囲の削除と、10 GB の範囲の複製がそれぞれ 100 ms 以内に終わる。
- [ ] ランダムな挿入・削除・上書きを 100 万回行った結果が、同じ操作を単純な配列に行った結果と一致する (プロパティベースのテスト)。
- [ ] 連続して 1,000 文字を入力しても、ピースの数が 1,000 個に増えない。
- [ ] 元データのファイルが、保存するまで 1 バイトも変更されない。

### ENG-03 生成ピース (塗りつぶし・乱数)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-01 (UI は F1-14、03 で定める) |
| 呼び出し | なし (内部の仕組み。塗りつぶし・挿入の操作から使われる) |

**概要**: 「50 GB を 00 で埋める」のような操作を、実データを作らず規則だけを持つピース 1 つで表す。

**仕様**:

1. 生成ピースの規則は次の 2 種類。
   - パターン: 1〜4,096 バイトのパターンの繰り返し。パターンは追加バッファに 1 回だけ置き、ピースはその位置と「パターン内の開始位置 (位相)」を持つ。
   - 乱数: シード (64 bit) とアルゴリズムの識別子。任意の位置のバイトを、その位置から直接計算できる方式 (カウンタ方式の擬似乱数) を使う。アルゴリズムは SplitMix64 をカウンタ方式で使う (位置 p のバイトは、SplitMix64(シード + ⌊p / 8⌋ × 0x9E3779B97F4A7C15) の下位から p mod 8 番目のバイト)。暗号用途の乱数ではない。
2. 生成ピースを途中で分割 (中央に挿入するなど) した場合、後ろ側のピースは位相 (パターン) または開始位置 (乱数) を引き継ぎ、内容は分割前と変わらない。
3. 長さを変えられないデータソースの変更範囲マップ (ENG-07) でも同じ規則を使う。
4. 保存・検索・ハッシュなどの読み込みでは、生成ピースの内容を 64 KiB 単位で計算して渡す。
5. 暗号用途の乱数 (安全な消去など) は生成ピースでは表さず、実データとして扱う (TOOL-17、FOR-30、FOR-31)。

**画面**: なし。

**巨大ファイル・長時間処理**: 生成ピースの作成は長さに関係なく 100 ms 以内。生成ピースを含む範囲の保存は、生成した内容を順に書き出すため、書き込み量に比例した時間がかかる (ENG-22)。

**エラー**: パターンの長さが 0 または 4,096 バイトを超える場合は拒否する。

**受け入れ基準**:

- [ ] 1 TB の範囲を `DE AD BE EF` で塗りつぶす操作が 100 ms 以内に終わり、メモリ使用量がほぼ増えない。
- [ ] パターンの塗りつぶしの途中に 1 バイト挿入しても、挿入位置の前後のパターンが崩れない。
- [ ] 同じシードの乱数ピースは、何度読んでも、分割した後でも同じ内容を返す。

### ENG-04 追加バッファと一時ファイルへの退避

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-01 |
| 呼び出し | なし (内部の仕組み) |

**概要**: 入力・貼り付けなどで新しく加わったデータを「追加バッファ」に追記していく。追加バッファがメモリの上限を超えた場合は、古い部分から一時ファイルに退避し、メモリ使用量を一定に保つ。

**仕様**:

1. 追加バッファは追記専用で、一度書いた位置の内容は変えない (永続化された木から安全に参照できるようにするため)。
2. 追加バッファは 1 MiB のチャンクで管理する。メモリ上のチャンクの合計が上限 (既定 256 MiB、設定で 16 MiB〜エンジンのメモリ上限の 50%) を超えたら、最も長く使われていないチャンクを一時ファイルに書き出してメモリから外す。退避したチャンクを読むときは一時ファイルから読む (ブロックキャッシュを通す)。
3. 一時ファイルの置き場所は、既定で設定フォルダの `recovery/<ドキュメント ID>/add.bin`。設定で別のフォルダを指定できる。復旧用データ (ENG-27) から参照するため、通常の一時フォルダは使わない。
4. 一時ファイルは現在のユーザーだけが読み書きできるアクセス権で作る (設定フォルダのアクセス権を継承する)。
5. 一時ファイルはドキュメントを閉じたときに削除する。異常終了で残ったものは、次回起動時に復旧用データ (ENG-27) と一緒に扱い、復旧の対象でないものは削除する。
6. 1 回の貼り付けなどで追加されるデータが追加バッファのメモリ上限を超える場合は、メモリを経由せず直接一時ファイルに書く。
7. 追加バッファの総量 (メモリと一時ファイルの合計) に上限は設けない。退避先のドライブの空き容量が 1 GiB を下回ったら InfoBar で警告する。

**画面**: 設定画面 (09) に「一時ファイルの場所」「追加データをメモリに置く上限」を置く。

**巨大ファイル・長時間処理**: 数 GB の貼り付け・ファイルの挿入は長時間処理 (ENG-09) として実行し、一時ファイルへの書き込みの進捗を表示する。

**エラー**: 一時ファイルへの書き込みに失敗した場合 (容量不足など)、その編集操作は適用せず、ドキュメントは操作前の状態のままにする。メッセージは「一時ファイルに書き込めないため、この編集を適用できませんでした。理由: 〜。一時ファイルの場所: 〜」の趣旨。

**受け入れ基準**:

- [ ] 2 GiB を貼り付けたとき、エンジンのメモリ使用量が上限 (既定 1 GiB) を超えない。
- [ ] 退避後も、貼り付けたデータを正しく表示・検索・保存できる。
- [ ] ドキュメントを閉じると一時ファイルが削除される。
- [ ] 退避先の空き容量が不足する状況をテスト用のデータソースで再現し、編集が適用されず元の状態のままであることを確認できる。

### ENG-05 永続木によるスナップショット (Undo の土台)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-01 (Undo / Redo の操作は F0-06、分岐する履歴は F4-02。03 で定める) |
| 呼び出し | なし (内部の仕組み) |

**概要**: ピースツリーと変更範囲マップを不変 (永続データ構造) にし、編集のたびに変更したノードだけを新しく作る。ある時点のドキュメントの状態は「その時点のルートへの参照」1 つで表せ、Undo・Redo・バックグラウンド処理の基準として使う。

**仕様**:

1. 編集操作は既存のノードを変更せず、根から変更箇所までの経路のノードだけを複製した新しいルートを作る (経路の複製)。1 回の編集で増えるメモリは O(log n) ノード分。
2. スナップショットはルートへの参照で、作成は O(1)。
3. Undo の履歴は、各時点のスナップショットと操作の説明 (例: 「0x1000 に 4 バイト挿入」) の列で持つ。分岐する履歴 (F4-02) も同じスナップショットで表す。
4. スナップショットはスレッド間で共有できる。バックグラウンド処理 (検索、ハッシュ、保存) は開始時のスナップショットを読み、処理中に利用者が編集を続けても結果は開始時の内容に対するものになる (保存中の扱いは ENG-20)。
5. 保存後も Undo 履歴を保つ。保存前のスナップショットが参照する元データは、次のように読み続けられるようにする。
   - 安全な保存 (ENG-22) の後: 置き換え前のファイルを開いたままにして読む。
   - その場保存 (ENG-23、ENG-30、ENG-34) の後: 上書きした範囲の旧内容を追加バッファに退避し、保存前の版を「ファイル本体と退避した旧内容の重ね合わせ」として読む。
6. 履歴のうち「保存した時点」に印を付ける。現在の状態が保存した時点のスナップショットと同じなら、変更なしとして扱う (Undo で保存時点に戻れば「変更あり」の表示が消える)。
7. 履歴の上限は設けない。メモリ使用量が上限に近づいた場合の扱いは ENG-08。

**画面**: なし。

**巨大ファイル・長時間処理**: スナップショットの作成・切り替え (Undo / Redo) はデータ量に関係なく 100 ms 以内。

**エラー**: 保存前の版の元データが読めなくなった場合 (置き換え前のファイルを開いたままにできなかった場合など) は、その版より前の Undo 履歴を破棄し、InfoBar で「保存前の内容に戻すための元データを保持できないため、保存前の Undo 履歴を削除しました」の趣旨を伝える。

**受け入れ基準**:

- [ ] 100 GB のファイルで 10 GB の範囲を削除し、Undo・Redo をそれぞれ 100 ms 以内に行える。
- [ ] 1 万回の編集の後、任意の時点に Undo で戻った内容が、その時点で記録しておいたハッシュと一致する。
- [ ] 検索を実行中に編集しても、検索結果は検索開始時の内容に対するものになる。
- [ ] 保存後に Undo して保存前の内容に戻れる (安全な保存、その場保存の両方)。
- [ ] 保存した時点まで Undo すると「変更あり」の表示が消える。

### ENG-06 ブロックキャッシュと非同期読み込み

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-01 |
| 呼び出し | なし (内部の仕組み) |

**概要**: データソースからの読み込みを 64 KiB のブロック単位でキャッシュし、表示が I/O 待ちで止まらないように非同期で読み込む。まだ読み込んでいない箇所は「読み込み中」として返し、読み込みが終わったら表示を更新させる。

**仕様**:

1. ブロックはデータソースごとに、オフセットを 64 KiB で割った番号で識別する。論理セクタサイズが 64 KiB を超えるデータソースでは、ブロックサイズを論理セクタサイズに合わせる。
2. キャッシュは LRU で、上限は既定 256 MiB (設定で 16 MiB〜エンジンのメモリ上限の 50%)。
3. 読み込み要求には優先度を付ける。高い順に、表示 (画面に見えている範囲)、先読み (スクロール方向の次の 2 画面分)、バックグラウンド処理。表示の要求は、待っている他の要求より先に実行する。
4. 表示からの読み込みはブロックしない。キャッシュにないブロックは「読み込み中」の状態を返し、読み込みを開始する。読み込みが終わったら、その範囲が変わったことを通知する。表示 (02) は通知を受けて再描画する。
5. 同じデータソースへの同時の読み込みは最大 4 本 (設定で 1〜16)。
6. 検索・ハッシュ・保存などの順次読み込みは、表示用のキャッシュを追い出さないよう、キャッシュを通さずに 1 MiB〜4 MiB 単位で読む。ただし、変更されていない元データの読み込みで、表示用キャッシュにすでにあるブロックは再利用する。
7. 1 つのブロックの読み込みが 5 秒以上かかる場合は、ステータスバーに「データを待っています」と表示する (ネットワークドライブ、スリープから復帰中のディスク、クラウドのみのファイルなど)。
8. 読み込みエラーの扱い:
   1. ブロック全体の読み込みに失敗したら 1 回だけ再試行する。
   2. それでも失敗したら、論理セクタ単位 (ファイルは 4 KiB 単位) に分けて読み、失敗した部分だけを「読めない」とし、エラーコードを記録する。
   3. 読めない範囲は、利用者が再読み込み (ENG-18) するまで再試行しない。
9. 変わりうるデータソース (`IsVolatile`) では、キャッシュの内容を「表示を更新」(ENG-18) または自動更新の間隔で捨てて読み直す。
10. 外部変更を検知した場合 (ENG-19)、そのデータソースのキャッシュをすべて捨てる。

**画面**: 表示側の見せ方 (読み込み中・読めないバイト) は 02 で定める。エンジンはバイトごとに「有効 / 読み込み中 / 読めない (理由)」の状態を返す。

**巨大ファイル・長時間処理**: 先読みは表示位置の周辺だけで、ファイル全体を読み込まない。キャッシュの上限を超えてメモリを使わない。

**エラー**: 読めない範囲は表示上で区別でき、ステータスバーまたはツールチップで理由 (I/O エラー、アクセス不可など) とエラーコードを確認できる。読めない範囲を含む操作 (保存、検索など) の扱いは各機能で定める。保存では、読めない元データを含むドキュメントの保存を拒否し、範囲を示す。

**受け入れ基準**:

- [ ] 100 GB のファイルで任意の位置にジャンプしたとき、表示が 100 ms 以内に更新される (OS のキャッシュにある場合)。
- [ ] 1 回の読み込みに 2 秒かかるテスト用のデータソースでも、スクロール中に UI が止まらない (UI スレッドが 50 ms 以上ブロックされない)。
- [ ] 1 GB のファイルの全体を検索した後も、検索前に表示していた範囲のブロックがキャッシュに残っている。
- [ ] 一部のセクタが読めないテスト用のデータソースで、読めないのはそのセクタだけで、前後のバイトは表示される。
- [ ] キャッシュのメモリ使用量が設定した上限を超えない。

### ENG-07 長さ固定のデータソースの変更範囲マップ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-01、F2-09、F2-10 |
| 呼び出し | なし (内部の仕組み) |

**概要**: ディスク、ボリューム、プロセスメモリのように長さを変えられないデータソースでは、ピースツリー (ENG-02) を上書きだけに制限して使う。元データ以外のピースが「変更した範囲」になる。保存時は変更した範囲だけを書き込む。

**仕様**:

1. 変更範囲マップはピースツリーそのもの。上書きは「削除と挿入を 1 つの操作として行う」(ENG-02 の仕様 3) ため長さは変わらず、ENG-05 と同じ方式で Undo できる。
2. 各範囲の内容は、追加バッファ上のデータ、または生成データ (ENG-03) のいずれか。例えば「ディスク全体を 00 で埋める」は 1 つの生成データの範囲で表す。
3. 重なる範囲を上書きした場合は、新しい内容で古い範囲を切り詰め・分割する。隣り合う範囲は、内容が連続していれば 1 つにまとめる。
4. 受け付ける操作は上書き (入力、上書き貼り付け、塗りつぶし、データ演算) だけ。挿入モードへの切り替え、挿入、削除、切り取り、挿入貼り付けは無効にする。挿入モードに切り替えようとした場合 (Insert キー) は、InfoBar で「このデータソースは長さを変えられないため、上書きモードだけを使えます」と示す。
5. 末尾を越える上書き貼り付けは、末尾までで切り詰める。切り詰める前に確認ダイアログで「貼り付けるデータのうち N バイトは末尾を越えるため貼り付けません」と示し、「末尾まで貼り付ける」「キャンセル」を選ばせる。
6. 書き込み時 (保存) は、セクタ境界に揃える必要があるデータソース (`NeedsAlignment`) では、変更範囲をセクタ境界まで広げ、変更されていない部分は元データを読んで埋める (読み込み → 変更 → 書き込み)。
7. 変更範囲の列挙 (ENG-02 の仕様 7 と同じ用途) を提供する。

**画面**: なし。ステータスバーのモード表示は「上書き (固定長)」とする (02 / 09 で表示)。

**巨大ファイル・長時間処理**: 変更範囲の数を n として、操作は O(log n)。2 TB のディスク全体の塗りつぶしも 100 ms 以内に変更範囲マップへ反映される (実際の書き込みは保存時で、長時間処理になる)。

**エラー**: 長さを変える操作は、メニュー・コマンドパレット・右クリックメニューで無効表示にする。スクリプトなどから呼ばれた場合は「このデータソースは長さを変えられません」のエラーを返す。

**受け入れ基準**:

- [ ] ディスクを開いたドキュメントで、挿入・削除・挿入貼り付けがすべて無効になっている。
- [ ] 2 TB のテスト用データソース全体を塗りつぶす操作が 100 ms 以内に終わり、Undo できる。
- [ ] 512 バイトセクタのテスト用データソースで、オフセット 100 の 1 バイトを変えて保存すると、セクタ 0 (512 バイト) だけが書き込まれ、他のバイトは元のまま。
- [ ] 重なる上書きを 10 万回ランダムに行った結果が、単純な配列に同じ操作をした結果と一致する。

### ENG-08 メモリ使用量の管理

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-01 |
| 呼び出し | 設定 (Ctrl+,) の「パフォーマンス」 |

**概要**: エンジンが使うメモリ (ブロックキャッシュ、追加バッファ、木のノード、Undo 履歴) の合計を上限 (既定 1 GiB) 以下に保つ。ファイルサイズに比例してメモリを使わない。

**仕様**:

1. 上限は既定 1 GiB、設定で 256 MiB〜搭載メモリの 75% の範囲で変更できる。上限はアプリ全体 (全ドキュメントの合計) に対するもの。
2. エンジンは使用量を 1 秒ごとに集計する。上限を超えた場合は次の順で減らす。
   1. ブロックキャッシュを 16 MiB まで縮める。
   2. 追加バッファのチャンクを一時ファイルへ退避する (ENG-04)。
   3. それでも超える場合 (木のノードが多すぎる場合) は、InfoBar で「編集の数が多く、メモリの上限 (1 GiB) を超えています。保存すると使用量が減ります」と示す。Undo 履歴は自動では削除しない。
3. OS からメモリ不足の通知を受けた場合は、上限に関係なくブロックキャッシュを 16 MiB まで縮める。
4. 保存後、保存前の Undo 履歴を破棄してメモリを解放するコマンド「Undo 履歴を消去」を提供する (確認ダイアログあり。03 の Undo 操作と共通)。
5. 現在の使用量の内訳 (キャッシュ、追加バッファのメモリ分と一時ファイル分、木のノード) をドキュメントのプロパティと「パフォーマンス」設定に表示する。

**画面**: 設定画面の「パフォーマンス」に、メモリの上限、キャッシュの上限、追加データをメモリに置く上限、使用量の内訳を置く。

**巨大ファイル・長時間処理**: ファイルを開いただけではメモリはほぼ増えない (先頭の表示に必要なブロックだけ)。

**エラー**: 上限を超えた状態でも動作は続ける (編集を拒否しない)。ただし一時ファイルへの退避に失敗した場合は ENG-04 のエラーになる。

**受け入れ基準**:

- [ ] 100 GB のファイルを開いて先頭から末尾までスクロールしても、エンジンのメモリ使用量が 300 MiB を超えない (既定設定)。
- [ ] 10 個の 10 GB のファイルを同時に開いて全体を検索しても、合計が上限を超えない。
- [ ] OS のメモリ不足の通知を受けると、キャッシュが 16 MiB まで縮む。通知は、テスト用のビルドの異常を再現する仕組み (テスト方針 (docs/test/00-test-strategy.md) 7.2 の「メモリ不足の通知」。`--test-hooks` またはテスト用のメニュー) で発生させる。

### ENG-09 長時間処理の基盤

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-13 |
| 呼び出し | ステータスバーの進捗表示をクリック → 処理センター。コマンドパレット「表示: 処理センター」 |

**概要**: 0.5 秒以上かかりうる処理 (保存、検索、ハッシュ、塗りつぶしの書き込み、スナップショットなど) をすべてバックグラウンドで実行し、進捗・処理速度・残り時間・キャンセルを共通の形で提供する。UI は固まらない。

**仕様**:

1. 長時間処理は次の情報を持つ: 名前 (例: 「保存: data.bin」)、対象のドキュメント、種類 (読み取りのみ / ドキュメントを変更する / 外部に書き出す)、進捗 (処理済みバイト数と全体のバイト数。全体が分からない場合は不確定)、開始時刻、状態 (待機中・実行中・キャンセル中・完了・失敗・キャンセル済み)。
2. 開始から 0.5 秒以内に終わった処理は何も表示しない。0.5 秒を超えたら、ステータスバーに進捗バーと処理名を出す。複数の処理が動いている場合は「処理中 (3)」のように件数を出す。
3. 処理速度は直近 10 秒の移動平均で計算する。残り時間は開始から 3 秒たってから表示する。数値と時間は地域設定に従って書式化する。
4. 進捗の UI への反映は 1 秒に最大 10 回とする。
5. キャンセル: 処理センターの各行、およびステータスバーの進捗表示のフライアウトにキャンセルボタンを置く。キャンセルを押してから 200 ms 以内に処理が止まる (処理は 1 MiB または 100 ms ごとにキャンセルを確認する)。
6. 処理の種類ごとの完了・キャンセル時の扱い:

   | 種類 | 完了時 | キャンセル・失敗時 |
   | --- | --- | --- |
   | 読み取りのみ (検索、ハッシュ、統計) | 結果を表示 | 途中までの結果を表示するかは各機能で定める |
   | ドキュメントを変更する (すべて置換、ファイルの挿入など) | 1 つの Undo 単位として反映 | ドキュメントは開始前の状態のまま |
   | 外部に書き出す (保存、エクスポート、スナップショット) | 書き出し先を確定 | 途中まで書いた出力を削除し、既存のファイルを壊さない (保存の詳細は ENG-20〜ENG-24) |

7. 同時実行の規則:
   - 読み取りのみの処理は、同じドキュメントでも同時に複数実行できる (開始時のスナップショットを読む)。
   - ドキュメントを変更する処理と保存は、1 つのドキュメントにつき同時に 1 つ。後から開始したものは待機中になる。
   - ドキュメントを変更する処理と保存の実行中は、そのドキュメントの編集を受け付けない (表示・スクロール・検索はできる)。編集しようとした場合は InfoBar で「処理中のため編集できません (処理名)」と示す。
8. 処理が 10 秒以上続いた場合、タスクバーのボタンに進捗を表示する。ウィンドウが非アクティブのときに完了・失敗したら、タスクバーのボタンを点滅させる。
9. 処理の実行中は、OS がスリープしないように要求する (画面の消灯は妨げない)。
10. バックグラウンドの読み込みは、表示の読み込みより低い優先度で行う (ENG-06)。
11. 処理が失敗した場合は、処理センターに失敗の理由を残し、InfoBar でも知らせる。処理センターの履歴は直近 50 件を保持し、アプリの終了で消える。
12. 処理中のドキュメントを閉じる場合、またはアプリを終了する場合は、確認ダイアログで実行中の処理の一覧を示し、「処理をキャンセルして閉じる」「キャンセル」を選ばせる。保存中の場合は「保存の完了を待って閉じる」も選べる。
13. 長時間処理は API として `HexEditor.Core` に置き、スクリプト (08) からも同じ形で使える (進捗の報告とキャンセルの受け取り)。

**画面**:

- ステータスバー右側に進捗表示 (処理名、進捗バー、パーセント)。クリックで処理センターを開く。
- 処理センター: ステータスバーの進捗表示から開くフライアウト (09 の UI-37)。各処理の処理名、対象、進捗、処理速度、残り時間、状態、キャンセルボタンを表示する。

**巨大ファイル・長時間処理**: この機能そのものが長時間処理の仕組み。

**エラー**: 処理の失敗は、処理名・対象・理由 (OS のエラーメッセージを含む)・次に取れる行動 (再試行、別の場所に保存など) を示す。

**受け入れ基準**:

- [ ] 0.5 秒未満で終わる処理では進捗表示が出ない。
- [ ] 10 GB のファイルのハッシュ計算中に、スクロールとカーソル移動が 60 fps を保つ。
- [ ] キャンセルボタンを押してから 200 ms 以内に処理が止まる。
- [ ] 「すべて置換」をキャンセルした後、ドキュメントの内容が開始前と同じ (ハッシュで確認)。
- [ ] 保存中に入力しようとすると、InfoBar が出て入力が無視される。
- [ ] 残り時間・処理速度の表示が、ドイツ語・アラビア語の地域設定で正しく書式化される。

### ENG-10 新規作成

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-08 |
| 呼び出し | ファイル > 新規作成 (Ctrl+N)、ファイル > 新規作成 (サイズを指定)…、コマンドパレット「ファイル: 新規作成」「ファイル: サイズを指定して新規作成」、タブバーの「+」ボタン |

**概要**: 保存先の決まっていない空のドキュメントを作る。サイズと塗りつぶしの値を指定して作ることもできる。

**仕様**:

1. Ctrl+N で長さ 0 の「無題 1」を新しいタブで開く。番号はアプリの起動中に作った無題のドキュメントの通し番号 (1 から)。
2. 「サイズを指定して新規作成」はダイアログで次を入力する。
   - サイズ: 入力式 (00 の 6 章)。0〜2^63 − 1。既定 `0`。
   - 塗りつぶしの値: Hex バイト列 (00 の 6.3)。1〜4,096 バイト。既定 `00`。
   - 作成されるドキュメントは、指定サイズの生成ピース (ENG-03) 1 つで、すぐに開く (サイズに関係なく 100 ms 以内)。
3. 無題のドキュメントは長さを変えられ、すべての編集ができる。データソースは空 (元データなし) で、内容はすべて追加バッファと生成ピース。
4. 無題のドキュメントを保存すると「名前を付けて保存」(ENG-21) になる。
5. 無題のドキュメントも復旧用データ (ENG-27) の対象。
6. 編集していない無題のドキュメント (長さ 0) は、閉じるときに確認しない。

**画面**: 「サイズを指定して新規作成」のダイアログ: サイズの入力欄 (解釈結果を横に表示)、塗りつぶしの値の入力欄、「作成」「キャンセル」ボタン。

**巨大ファイル・長時間処理**: 1 TiB を指定しても即座に作成する。保存時は書き込み量に比例した時間がかかり、空き容量の確認 (ENG-25) を行う。

**エラー**: サイズ・塗りつぶしの値が不正な場合は入力欄を赤枠にし、「作成」を無効にする。

**受け入れ基準**:

- [ ] Ctrl+N を 3 回押すと「無題 1」「無題 2」「無題 3」のタブができる。
- [ ] サイズ `1T`、値 `FF` で作成すると、100 ms 以内に長さ 1,099,511,627,776 バイトのドキュメントが開き、全体が FF。
- [ ] 無題のドキュメントで Ctrl+S を押すと「名前を付けて保存」のダイアログが開く。

### ENG-11 ファイルを開く

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-08 (巨大ファイルを即座に開く: F0-01) |
| 呼び出し | ファイル > 開く (Ctrl+O)、ファイル > 詳細を指定して開く…、コマンドパレット「ファイル: 開く」「ファイル: 詳細を指定して開く」、コマンドライン (AUTO-37)、Explorer 連携 (UI-54〜56)、ドラッグ & ドロップ (UI-34、ENG-12)、最近使ったファイル (ENG-16) |

**概要**: ファイルを選んでドキュメントとして開く。サイズに関係なく 1 秒以内に先頭を表示する。ファイル全体を読み込まず、開くときに全体を走査しない。

**仕様**:

1. 「開く」は Windows の標準のファイルを開くダイアログを使う。複数のファイルを選べる。既定のフィルタは「すべてのファイル (\*.\*)」。前回開いたフォルダを初期表示する。ダイアログに「読み取り専用で開く」のチェックボックスを付ける。
2. 「詳細を指定して開く」はアプリ独自のダイアログで、次を指定できる。
   - パス (参照ボタン付き)
   - 読み取り専用で開く (ENG-14)
   - 範囲を指定して開く (ENG-13)
   - ディスクイメージとして開く、セクタサイズ (ENG-31)
   - 形式: 自動 / バイナリのまま / Intel HEX / S-record / Base64 (ENG-38)
   - 他のアプリの書き込みを禁止する (ENG-15)
3. 開く手順:
   1. パスを最終パスに解決する (シンボリックリンク・ジャンクションをたどる)。識別子 (ENG-01) が同じドキュメントがすでに開いていれば、新しく開かずにそのタブをアクティブにする。
   2. ファイルを開く。共有モードは ENG-15 に従う。
   3. ファイルサイズとファイル ID、最終更新日時を取得する。
   4. 元データ全体を指すピース 1 つのピースツリーを作る。
   5. タブを作り、カーソル位置を復元する (ENG-16)。表示範囲のブロックを非同期で読み込む。
   6. ファイル形式の判定 (テンプレートの自動適用など、07) は先頭 64 KiB だけを使い、表示の後にバックグラウンドで行う。
4. 対応するパス: Unicode のファイル名、260 文字を超えるパス、UNC パス (`\\server\share\...`)、`\\?\` で始まるパス。
5. フォルダ、名前付きパイプ、デバイスのパス (`\\.\` で始まるもの) を「開く」で指定した場合は、ファイルとしては開かない。デバイスのパスはディスクを開く (ENG-29) に案内する。
6. 長さ 0 のファイルも開ける。
7. スパースファイルは通常のファイルとして開く (未割り当ての範囲は 00 として読める)。保存時の扱いは ENG-22。
8. クラウドのみのファイル (OneDrive のプレースホルダなど) は、読み込みのときに OS がダウンロードする。待ち時間の表示は ENG-06 の仕様 7。
9. 開いたファイルは最近使ったファイル (ENG-16) に追加する。
10. 開くドキュメントの数に上限はない。

**画面**: 「詳細を指定して開く」のダイアログ。範囲・形式などの項目は、既定値のまま「開く」を押せば通常の「開く」と同じになるようにする。

**巨大ファイル・長時間処理**: 開く処理はファイルサイズに依存しない。100 GB のファイルでも 1 秒以内に先頭を表示する (00 の 11.1)。開くときにハッシュ計算・全体の走査・行数の計算を行わない。

**エラー**:

| 状況 | 利用者への見せ方 |
| --- | --- |
| ファイルが存在しない | 「ファイルが見つかりません: パス」。最近使ったファイルから開いた場合は一覧から削除するボタンを出す |
| アクセスが拒否された | 「このファイルを開く権限がありません」。読み取り専用でも開けない場合はタブを作らない |
| 他のプロセスが排他的に開いている (共有違反) | 「他のアプリがこのファイルを使用中のため開けません」。使用中のプロセス名が分かる場合は表示する (Windows の Restart Manager で取得) |
| 書き込みはできないが読み取りはできる | 読み取り専用で開き、InfoBar で理由 (読み取り専用属性、権限、読み取り専用のメディア、他のアプリが書き込み中) を示す |
| パスがフォルダ | 「フォルダは開けません」 |

**受け入れ基準**:

- [ ] 100 GB のファイルを開いてから先頭の表示まで 1 秒以内 (OS のキャッシュがない状態でも、ディスクの応答時間を除いて)。
- [ ] 開く操作の間、ファイルの読み込み量が 1 MiB 以下 (先頭の表示と形式の判定のみ)。
- [ ] 同じファイルを 2 回開くと、2 つ目のタブは作られず既存のタブがアクティブになる。シンボリックリンク経由で開いた場合も同じ。
- [ ] 300 文字のパス、絵文字を含むファイル名、UNC パスのファイルを開ける。
- [ ] 他のアプリが排他的に開いているファイルを開くと、プロセス名を含むメッセージが出る。
- [ ] ダイアログで 5 つのファイルを選ぶと 5 つのタブが開く。

### ENG-12 ドラッグ & ドロップで開く

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-08 |
| 呼び出し | Explorer などからウィンドウにファイルをドロップ (ドロップ先ごとの動作は UI-34) |

**概要**: ドロップされた項目をドキュメントとして開くエンジン側の処理を定める。ドロップ先ごとの動作 (タブの挿入位置、フォルダの扱い、多数のファイルの確認、管理者として実行中の案内、ワークスペース・プロジェクトのファイル) は UI-34 が定める。選択範囲のドラッグは EDIT-18、Ctrl を押しながらのドロップでファイルの内容を挿入する操作は EDIT-30 が定める。

**仕様**:

1. パスを持つファイルは、ファイルを開く (ENG-11) と同じ手順で、1 ファイルごとに 1 つのドキュメントとして開く。
2. パスを持たない項目 (ZIP の中のファイル、ブラウザからの仮想ファイルなど) は、内容を一時ファイルにコピーしてから無題のドキュメントとして開く。タブには元の名前を表示し、保存は「名前を付けて保存」になる。コピーは長時間処理 (ENG-09) として行う。
3. フォルダはこの処理に渡さない (UI-34 の仕様 4)。

**画面**: UI-34。

**巨大ファイル・長時間処理**: パスを持つファイルは ENG-11 と同じく即座に開く。パスを持たない項目のコピーは長時間処理。

**エラー**: 開けないファイルは ENG-11 のエラーと同じ。見せ方は UI-34 のエラー (そのファイルだけエラーの InfoBar を出し、他のファイルは開く) に従う。

**受け入れ基準**:

- [ ] Explorer から 3 つのファイルをドロップすると、ENG-11 と同じ処理で 3 つのドキュメントが開く。
- [ ] ZIP フォルダの中のファイルをドロップすると、無題のドキュメントとして元の名前で開く。

### ENG-13 範囲を指定して部分的に開く

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | ファイル > 詳細を指定して開く… の「範囲を指定して開く」、コマンドパレット「ファイル: 範囲を指定して開く」 |

**概要**: ファイルの一部の範囲 (開始位置と長さ) だけをドキュメントとして開く。巨大なファイルの一部だけを編集したいときや、ログ・イメージの特定の領域だけを扱いたいときに使う。

**仕様**:

1. 開始位置と、長さまたは終了位置を入力式で指定する。この入力欄では `end` はファイルの長さを表す。例: 開始 `0x1000_0000`、長さ `64M`。
2. ドキュメントのオフセット 0 は指定した開始位置に対応し、ベースアドレスは開始位置とする (表示上のアドレスはファイル内の位置と一致する)。
3. 既定では長さを固定する (上書きのみ。ENG-07 と同じ制約)。保存は範囲内の変更箇所だけをファイルに書き込む (ENG-23 の方式)。
4. 「長さの変更を許可する」を選ぶと挿入・削除ができる。保存時はファイル全体を、範囲外はそのまま、範囲内は編集後の内容にして安全な保存 (ENG-22) で書き出す。
5. タブには `data.bin [0x10000000–0x13FFFFFF]` のように範囲を表示する。
6. 同じファイルの、重ならない範囲を別々のタブで開ける。重なる範囲を開こうとした場合、または同じファイルを全体で開いている場合は、確認ダイアログで「同じデータを 2 つのタブで編集すると、後から保存した方が優先されます」と示し、「読み取り専用で開く」「そのまま開く」「キャンセル」を選ばせる。
7. 外部変更の検知 (ENG-19) はファイル全体について行う。

**画面**: 「詳細を指定して開く」のダイアログ内の範囲の入力欄 (開始、長さ / 終了の切り替え、解釈結果)。

**巨大ファイル・長時間処理**: 開く処理は範囲の大きさに依存しない。長さを変えた場合の保存はファイル全体の書き出しになるため、ファイルサイズに比例した時間がかかる。

**エラー**: 開始位置がファイルの長さ以上、または長さが 0 以下の場合は入力欄を赤枠にし、「開く」を無効にする。終了がファイルの長さを超える場合は、ファイルの末尾までに切り詰めることを入力欄の下に示す。

**受け入れ基準**:

- [ ] 10 GiB のファイルの `5G` から長さ `1M` を開くと、表示上のアドレスが 0x140000000 から始まる。
- [ ] 範囲内の 1 バイトを変えて保存すると、ファイルのその位置の 1 バイトだけが変わり、ファイルの長さは変わらない。
- [ ] 長さの変更を許可して 10 バイト挿入して保存すると、ファイルが 10 バイト長くなり、範囲の前後のデータが保たれる。

### ENG-14 読み取り専用で開く

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-23 |
| 呼び出し | ファイル > 読み取り専用で開く… (Windows の標準の「開く」ダイアログには独自のチェックボックスを置けないため、別の項目にする)、ファイル > 詳細を指定して開く… の「読み取り専用で開く」、ディスク・プロセスを開くダイアログの「読み取り専用で開く」。開いた後の切り替え (編集 > 読み取り専用) は EDIT-16 |

**概要**: ドキュメントを読み取り専用の状態で開く条件と、書き込めないデータソースの扱いを定める。読み取り専用の切り替え、編集の保護 (無効にするコマンド、InfoBar、解除の手順)、表示は EDIT-16 が定める。アプリ全体の書き込み保護モードによる強制は FOR-01 が定める。

**仕様**:

1. 次の場合は、ドキュメントを読み取り専用 (EDIT-16) の状態で開く。
   - 「読み取り専用で開く」を指定した場合 (ENG-11、ENG-29、ENG-32、ENG-40)。この場合、データソースも読み取りのアクセス権だけで開く。
   - ファイルに読み取り専用属性がある、書き込み権限がない、読み取り専用のメディアにある、他のアプリが書き込みのために開いている (共有モードの都合で書き込みハンドルを取れない) 場合。InfoBar で理由を示す (ENG-11 のエラー)。
   - ディスク・ボリュームを開いた場合 (既定。ENG-29 のダイアログで変更できる)。
   - プロセスメモリを開いた場合 (既定。ENG-32 の設定で変更できる)。
   - スナップショット (ENG-35)、メモリダンプ (ENG-36)、UDP (ENG-42) など、書き戻す先のないデータソース。
   - 書き込み保護モード (FOR-01) が有効な場合。
2. 書き戻す先のないデータソース (`CanWrite` を持たないもの。ENG-01) では、読み取り専用を解除できない。EDIT-16 の「編集を許可する」ボタンを出さず、理由 (「データソースが書き込みに対応していません」) を示す。
3. 利用者が読み取り専用を解除したとき (EDIT-16 の仕様 4)、エンジン側では次を行う。
   - ファイル: 書き込み用のハンドルを開けるか (属性、権限、共有違反) を確認する。読み取り専用属性が原因の場合は、利用者が承認したときだけ、保存時に属性を外す (ENG-22 の仕様 5)。権限がない場合は解除できず、理由を返す。
   - ディスク・ボリューム・プロセスメモリ: EDIT-16 の確認に加えて、確認ダイアログで「このデバイスに書き込めるようにします。保存するまで実際には書き込みません」の趣旨と対象 (ディスクのモデル名・サイズ、またはプロセス名・PID) を示し、「書き込みを許可」「キャンセル」を選ばせる。許可された場合は、データソースを読み書きのアクセス権で開き直す (補助プロセス経由のものは ENG-28 の `OpenDevice` / `OpenProcess`)。
4. 読み取り専用のドキュメントは保存 (ENG-20) できない。

**画面**: ファイル メニューの「読み取り専用で開く…」(ファイルの選択は標準の「開く」ダイアログ)。アプリ独自の「開く」ダイアログ (詳細を指定して開く、ディスク・プロセスを開く) では「読み取り専用で開く」のチェックボックス。読み取り専用の表示は EDIT-16。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 解除できない場合の理由 (権限がない、読み取り専用のメディア、書き込み保護モード、データソースが書き込みに対応しない) を EDIT-16 の InfoBar で示す。

**受け入れ基準**:

- [ ] 読み取り専用属性のファイルを開くと読み取り専用になり、解除して保存すると属性が外れて保存される。
- [ ] ディスクを開くと既定で読み取り専用になり、解除時に確認ダイアログが出る。
- [ ] スナップショットを開いたドキュメントでは「編集を許可する」ボタンが出ない。
- [ ] 「読み取り専用で開く」で開いたファイルを、他のアプリが書き込み用に開ける。

### ENG-15 ファイルのロックと共有の方針

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-08 |
| 呼び出し | 設定 (Ctrl+,) の「ファイル」、ファイル > 詳細を指定して開く… の「他のアプリの書き込みを禁止する」 |

**概要**: 開いているファイルを他のアプリがどこまで使えるか (共有モード) を定める。既定では他のアプリの読み書きを妨げず、未保存の変更があるときだけ他のアプリの書き込みを禁止して、表示中の内容が壊れないようにする。

**仕様**:

1. ファイルを開くときは読み取り用のハンドルを、共有モード「読み取り・書き込み・削除をすべて許可」で開く。他のアプリはファイルを読む・書く・名前を変える・削除することができる (変更は ENG-19 で検知する)。
2. 編集を始めた時点 (最初の変更) で、同じファイルに 2 つ目のハンドルを、共有モード「読み取り・削除だけ許可」(書き込みを許可しない) で開く。これにより、他のアプリはその後このファイルを書き込み用に開けなくなる。
   - 他のアプリがすでに書き込み用に開いている場合、このハンドルは開けない。その場合は InfoBar で「他のアプリがこのファイルに書き込める状態です。外部で変更されると、保存していない変更が正しく保存できなくなる可能性があります」と示す。
   - 変更をすべて取り消した (保存時点に戻った) とき、および保存が終わったときに、このハンドルを閉じる。
3. 設定「ファイルのロック」で次から選べる。
   - 編集中だけ他のアプリの書き込みを禁止する (既定。上の 1、2)
   - 開いている間、常に他のアプリの書き込みを禁止する
   - ロックしない (他のアプリの書き込みを常に許可する)
4. 「詳細を指定して開く」の「他のアプリの書き込みを禁止する」は、そのドキュメントだけ「常に禁止する」にする。
5. 保存時は、自分の書き込み禁止のハンドルを閉じてから書き込み用のハンドルを開き、保存後に元の方針に戻す。
6. 削除を許可しているため、他のアプリが名前を変えたり削除したりしても、開いているハンドルからは元の内容を読み続けられる (ENG-19 の扱い)。
7. 保存後も、保存前の Undo 履歴が参照する置き換え前のファイルのハンドルは閉じない (ENG-05、ENG-22)。

**画面**: 設定画面「ファイル」に「ファイルのロック」の選択肢。ドキュメントのプロパティに現在のロックの状態を表示する。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 仕様 2 の InfoBar。保存時に書き込み用のハンドルを開けない場合は、ENG-20 のエラー (使用中のプロセス名を示す) になる。

**受け入れ基準**:

- [ ] ファイルを開いただけの状態で、他のアプリ (テスト用のプロセス) がそのファイルに書き込める。
- [ ] 1 バイト変更した後は、他のアプリがそのファイルを書き込み用に開けない。
- [ ] 変更を Undo で取り消すと、再び他のアプリが書き込める。
- [ ] 開いている間に他のアプリがファイルを削除しても、表示中の内容が読める。

### ENG-16 最近使ったファイル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-19 (セッション復元 F1-20 は 09) |
| 呼び出し | 画面と操作は UI-32 (ファイル > 最近使ったファイル、スタートページ、コマンドパレット)。ジャンプリストは UI-35 |

**概要**: 最近開いたファイルとディスクの一覧に記録する情報、件数、保存先と、前回のカーソル位置の復元の規則を定める。一覧の画面と操作 (サブメニュー、ピン留め・削除・消去、見つからないファイルの表示) は UI-32 が定める (00 の 1.1)。

**仕様**:

1. 記録する対象: ファイル (範囲を指定して開いたものは範囲も)、ディスク・ボリューム (デバイスのパスとシリアル番号)、ディスクイメージとして開いたファイル (セクタサイズも)、SFTP のファイル (ENG-41)。プロセスメモリは記録しない (プロセス ID が毎回変わるため)。
2. 各項目に記録する情報: 種類、パス (またはデバイスの識別子、`sftp://` の URI)、表示名、最後に開いた日時、ピン留めの有無と順序、開くときのオプション (範囲、セクタサイズ、形式 (ENG-38))。
3. 件数は既定 25 件 (設定 `recent.maxItems`、0〜100。0 は記録しない)。ピン留めした項目はこの件数に含めず、上限なし。
4. 並び順: ピン留めした項目 (ピン留めした順)、その後に最後に開いた日時の新しい順。
5. ファイルを開き直したとき、前回閉じたときのカーソル位置・スクロール位置・選択範囲を復元する (設定 `recent.restorePosition`、既定オン)。前回の位置がファイルの長さを超える場合は末尾に置く。ブックマークなど他の付随データの適用は 00 の 10 章に従う (サイズ・更新日時が変わっていたら確認する)。
6. 保存先: 一覧は設定フォルダの `recent.json`、前回の位置は 00 の 10 章の `documents/` (付随データと同じ仕組み)。
7. `recent.maxItems` を 0 にすると、記録をやめ、既存の一覧 (ピン留めを含む) を消去する。

**画面**: UI-32。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 開けない場合は ENG-11 のエラー。設定フォルダに書き込めない場合は一覧を更新せず、ログに記録する (利用者には出さない)。

**受け入れ基準**:

- [ ] 30 個のファイルを順に開くと、一覧には新しい 25 件だけが残る。
- [ ] ピン留めした項目は、他のファイルを何個開いても一覧に残る。
- [ ] オフセット 0x12345 にカーソルを置いて閉じ、一覧から開き直すとカーソルが 0x12345 にある。
- [ ] 範囲を指定して開いたファイルを一覧から開き直すと、同じ範囲で開く。

### ENG-17 閉じる・終了

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-08 |
| 呼び出し | ファイル > 閉じる (Ctrl+W / Ctrl+F4)、ファイル > すべて閉じる、ファイル > すべて保存、ファイル > 終了、タブの × ボタン、タブの右クリックメニュー「閉じる」「他のタブを閉じる」「右側のタブを閉じる」、ウィンドウを閉じる。コマンドパレットにも同名のコマンドを置く。「すべて閉じる」「すべて保存」のショートカットは既定なし |

**概要**: ドキュメントを閉じる。未保存の変更がある場合は保存するかを確認する。アプリの終了時は、未保存のドキュメントをまとめて確認する。

**仕様**:

1. 未保存の変更がないドキュメントは確認なしで閉じる。
2. 未保存の変更があるドキュメントを 1 つ閉じる場合は確認ダイアログを出す。本文に「data.bin への変更を保存しますか? (変更: N か所、M バイト)」の趣旨を書き、ボタンは「保存」「保存しない」「キャンセル」。
3. 複数のドキュメントを閉じる場合 (ウィンドウを閉じる、終了、すべて閉じる、他のタブを閉じる) で未保存のものがあるときは、1 つのダイアログに一覧 (チェックボックス付き。既定ですべてオン) を出し、ボタンは「選択したものを保存して閉じる」「保存せずに閉じる」「キャンセル」。
4. 保存中に失敗した場合は、そのドキュメントを閉じずに残し、閉じる処理を中断する。
5. 長時間処理が実行中のドキュメントを閉じる場合は ENG-09 の仕様 12 に従う。
6. 閉じるときに、カーソル位置などの付随データ (ENG-16) を保存し、追加バッファの一時ファイルと復旧用データを削除する (保存しないで閉じた場合も削除する)。
7. 「すべて保存」は、未保存の変更があるすべてのドキュメントを順に保存する (無題のものは「名前を付けて保存」のダイアログを順に出す)。
8. 閉じたタブを開き直す (Ctrl+Shift+T) はファイルを開き直すだけで、保存しなかった変更は戻らない (09 で定める)。
9. 終了時、未保存の変更がなくても、復旧用データの削除・一時ファイルの削除が終わってからプロセスを終了する。補助プロセス (ENG-28) にも終了を通知する。

**画面**: 確認ダイアログ (00 の 9 章の書式)。

**巨大ファイル・長時間処理**: 閉じる処理そのものは即座に終わる。保存を選んだ場合は保存の長時間処理を待つ (ダイアログは閉じ、処理センターで進捗を示す。保存が終わったら閉じる)。

**エラー**: 保存の失敗は ENG-20 のエラーとして示し、ドキュメントを閉じない。

**受け入れ基準**:

- [ ] 変更のないタブは Ctrl+W ですぐに閉じる。
- [ ] 変更のある 3 つのタブを開いたままウィンドウを閉じると、3 件の一覧が入った 1 つのダイアログが出る。
- [ ] 一覧のうち 1 件のチェックを外して「選択したものを保存して閉じる」を押すと、2 件だけ保存されて終了する。
- [ ] 閉じた後、そのドキュメントの一時ファイルが残っていない。

### ENG-18 再読み込みと変更の破棄

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | ファイル > 再読み込み (Ctrl+R)、ファイル > 変更を破棄して再読み込み、コマンドパレット「ファイル: 再読み込み」「ファイル: 変更を破棄して再読み込み」。「変更を破棄して再読み込み」のショートカットは既定なし |

**概要**: データソースの内容を読み直す。「再読み込み」は未保存の変更を残したまま、変更していない部分の表示を最新にする。「変更を破棄して再読み込み」はすべての変更を捨てて、データソースの現在の内容に戻す。

**仕様**:

1. 再読み込み (変更を残す):
   - ブロックキャッシュを捨て、読めなかった範囲の記録も消して読み直す (ENG-06)。
   - ファイルでは、外部で変更されていない場合は表示が変わらない。外部で変更されている場合は ENG-19 の扱いになる。
   - ディスク・プロセスメモリなど変わりうるデータソースでは、変更していないバイトを最新の内容で表示する。変更したバイトはそのまま残す。
2. 変わりうるデータソースでは、自動更新を設定できる (ドキュメントごと。既定オフ、間隔 100 ms〜60 秒、既定 1 秒)。自動更新では表示中の範囲だけを読み直す。前回から変わったバイトの強調表示は 02 で定める。
3. 変更を破棄して再読み込み:
   - 未保存の変更がある場合は確認ダイアログで「N か所、M バイトの変更を破棄します」と示し、ボタンは「破棄して再読み込み」「キャンセル」。
   - データソースが外部で変更されていない場合は、破棄を 1 つの Undo 単位として記録する (Ctrl+Z で破棄前に戻せる)。確認ダイアログにもそう書く。
   - 外部で変更されている場合は、Undo 履歴を消去する。確認ダイアログに「元に戻せません」と書く。
4. ファイルのサイズが変わっていた場合は、カーソルと選択範囲を新しい長さの範囲内に収める。

**画面**: ファイルメニューの項目。自動更新の設定はドキュメントのプロパティと、変わりうるデータソースのタブの右クリックメニューに置く。

**巨大ファイル・長時間処理**: 再読み込みは表示範囲だけを読むため、サイズに依存しない。

**エラー**: 再読み込みでファイルが開けない (削除されたなど) 場合は ENG-19 の扱い。デバイスが切断されている場合は「デバイスに接続できません」と示す。

**受け入れ基準**:

- [ ] 未保存の変更があるディスクで「再読み込み」しても、変更したバイトが残る。
- [ ] 外部で変更されていないファイルで「変更を破棄して再読み込み」した後、Ctrl+Z で破棄前の内容に戻る。
- [ ] プロセスメモリで自動更新を 1 秒にすると、対象プロセスが書き換えた値が 1 秒以内に表示に反映される。

### ENG-19 外部変更の検知と再読み込み・マージ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-18 |
| 呼び出し | 自動 (検知時に InfoBar)。設定 (Ctrl+,) の「ファイル」 |

**概要**: 開いているファイルが他のアプリによって変更・置き換え・削除されたことを検知して知らせ、再読み込み・マージ・比較・無視から選べるようにする。

**仕様**:

1. 検知の方法:
   - ファイルのあるフォルダの変更通知 (`ReadDirectoryChangesW` 相当) を監視する。
   - ウィンドウがアクティブになったとき、およびタブを切り替えたときに、サイズ・最終更新日時・ファイル ID をハンドルとパスの両方で確認する。
   - 変更通知が使えない場所 (一部のネットワークドライブ) では、アクティブなドキュメントについて 5 秒ごとに確認する。
2. 変更の種類を区別する。
   - 内容の変更: 同じファイル (ファイル ID が同じ) のサイズ・更新日時が変わった。
   - 置き換え: 同じパスに別のファイル (ファイル ID が違う) がある。他のエディタの安全な保存などで起こる。開いているハンドルは置き換え前のファイルを指しているため、元の内容は読める。
   - 削除・移動: パスにファイルがない。
3. 自分の保存による変化は検知の対象から除く。
4. 未保存の変更がない場合:
   - 設定「未編集のファイルは自動で再読み込みする」(`files.autoReloadUnmodified`、既定オン) なら、自動で再読み込みし、InfoBar (`Informational`) で「外部で変更されたため再読み込みしました」と示す (UI-36 の仕様 4 のとおり 8 秒で自動で閉じる)。カーソル位置は保つ (新しい長さに収める)。
   - オフなら、下の 5 と同じ InfoBar を出す。
5. 未保存の変更がある場合は、警告の InfoBar に「data.bin は外部で変更されました」と、次のボタンを出す。
   - 再読み込み: 変更を破棄して新しい内容を読む (ENG-18 の「変更を破棄して再読み込み」と同じ確認)。
   - マージ: 新しい内容を元データとし、自分の変更を同じオフセットに適用し直す。外部の変更でファイルの長さが変わっている場合は、オフセットがずれて正しく適用できない可能性があることを確認ダイアログで示す。マージは 1 つの Undo 単位として記録する。
   - 比較: 現在のドキュメントとディスク上の新しい内容を比較する。比較の実行と表示は ANA-08 (保存済みの内容との比較) に従う。ANA-08 はフェーズ 2 のため、それまではこのボタンを出さない (仕様 6 も同じ)。
   - 無視: このまま編集を続ける。その後保存すると、外部の変更を上書きする (保存時に確認ダイアログで「外部で変更されたファイルを上書きします」と示す)。
6. 書き込み禁止のハンドル (ENG-15) を持てていなかった場合で、内容の変更 (同じファイルへの書き込み) を検知したときは、変更していない部分の表示がすでに外部の内容に変わっている。この場合はマージを選べないようにし、InfoBar に「保存していない変更と外部の変更が混ざっています」と示す。「再読み込み」「名前を付けて保存 (現在の表示内容を別のファイルに保存)」「比較」を選べる。
7. 置き換えの場合は、開いているハンドルから元の内容を読めるため、マージと比較を正しく行える。
8. 削除・移動の場合は、InfoBar に「data.bin は削除または移動されました」と示す。開いているハンドルから内容は読めるため、編集を続けられる。保存すると元のパスに新しく作る (確認ダイアログで「元の場所にファイルを作り直します」と示す)。「名前を付けて保存」「閉じる」のボタンも出す。
9. 同じファイルの複数の変更通知は 500 ms まとめてから 1 回だけ扱う (他のアプリが書き込み中に何度も通知しない)。
10. 外部変更を検知したら、そのファイルのブロックキャッシュを捨てる。

**画面**: エディタ上部の InfoBar (00 の 9 章)。タブには外部で変更されたことを示すアイコンを付ける (色だけでなく形で区別する)。

**巨大ファイル・長時間処理**: 検知はファイル全体を読まない (サイズ・日時・ID だけ)。マージは編集の数に比例し、ファイルサイズには依存しない。比較は ANA-08 の長時間処理。

**エラー**: 監視を開始できない場合 (フォルダの権限など) は、アクティブ化時の確認だけで検知する。利用者には出さない。

**受け入れ基準**:

- [ ] 未編集のファイルを他のアプリで書き換えると、自動で再読み込みされ InfoBar が出る。
- [ ] 編集中のファイルを他のエディタが置き換え保存すると、警告の InfoBar が出て、「マージ」で自分の変更が新しい内容に適用される。
- [ ] 開いているファイルを削除すると InfoBar が出て、編集を続けられ、保存で元のパスに作り直せる。
- [ ] 自分で保存したときは InfoBar が出ない。
- [ ] 他のアプリが 1 秒間に 100 回書き込んでも、InfoBar は 1 回しか出ない。

## 3. 保存

### ENG-20 保存 (保存方式の選択)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-08、F0-09 |
| 呼び出し | ファイル > 保存 (Ctrl+S)、ファイル > すべて保存 (既定なし)、コマンドパレット「ファイル: 保存」「ファイル: すべて保存」、タブの右クリックメニュー「保存」 |

**概要**: 未保存の変更をデータソースに書き込む。ドキュメントの状態とデータソースの能力から、最も安全で速い保存方式を自動で選ぶ。

**仕様**:

1. 保存方式は次の順に判定する。

   | 条件 | 方式 |
   | --- | --- |
   | 無題のドキュメント、または元のパスが削除されていて利用者が別の場所を選んだ | 名前を付けて保存 (ENG-21) |
   | 変更がない | 何もしない (書き込まない。更新日時も変えない) |
   | 長さを変えられないデータソース (ディスク、ボリューム、プロセスメモリ、範囲を指定して開いた長さ固定のもの) | 変更範囲だけを書き込む (ENG-23 の手順。ディスクは ENG-30、プロセスメモリは ENG-34) |
   | ファイルで、長さが変わらず、元データのピースがすべて元と同じ位置にある (ずれていない) | その場保存 (ENG-23)。設定「長さが変わらない場合の保存方法」を「常に安全な保存」にしている場合は安全な保存 |
   | 上記以外のファイル | 安全な保存 (ENG-22)。設定「長さが変わる場合もその場で書く」がオンなら、ずらしながらのその場保存 (ENG-24) |
   | 仮想データソース (Intel HEX など、ENG-38) | 元の形式に変換して安全な保存 (変換の規則は TOOL-11) |
   | 選択範囲から開いた連動ビュー (ENG-39) | 親のドキュメントを保存する |

2. 保存は長時間処理 (ENG-09) として実行する。開始時のスナップショットを書き出し、保存中はそのドキュメントの編集を受け付けない。表示・スクロール・検索はできる。
3. 保存の前に次を確認する。いずれかに当たれば確認ダイアログまたはエラーを出す。
   - 読み取り専用 (ENG-14) なら保存できない。
   - 外部で変更されている (ENG-19 で「無視」を選んでいた) なら、上書きの確認。
   - 読めない元データ (I/O エラーの範囲) を含むなら保存できない。範囲の一覧を示す。プロセスメモリの未割り当て領域のように書き込み対象でない範囲は対象外。
   - 空き容量 (ENG-25)。
4. 保存に成功したら:
   - Undo 履歴に保存した時点の印を付ける (ENG-05)。「変更あり」の表示を消す。
   - 新しいファイルの内容を元データとし、ピースツリーを元データ全体を指すピース 1 つに置き換える (表示内容は変わらない)。
   - 復旧用データ (ENG-27) を削除する。
   - 書き込み禁止のハンドル (ENG-15) を方針どおりに戻す。
5. 保存に失敗したら、元のファイル (またはデバイス) の内容は保存前のまま (ENG-22) か、ジャーナルで戻せる状態 (ENG-23) にし、ドキュメントは「変更あり」のまま残す。
6. 設定「保存時に更新日時を変えない」(既定オフ) をオンにすると、保存後に最終更新日時を保存前の値に戻す (ファイルだけ)。
7. 保存の途中で編集を受け付けないことを、保存開始時にステータスバーの進捗表示で示す。0.5 秒未満で終わる保存では何も表示しない (ENG-09)。

**画面**: ステータスバーの進捗表示、処理センター。保存方式はステータスバーの進捗表示のツールチップに出す (例: 「保存中 (安全な保存)」)。

**巨大ファイル・長時間処理**: 長さが変わらない保存は、変更したバイト量に比例した時間で終わる (00 の 11.1)。長さが変わる保存はファイル全体の書き出しになり、ファイルサイズに比例する。いずれもキャンセルできる (ENG-24 の書き込み開始後を除く)。

**エラー**:

| 状況 | 利用者への見せ方 |
| --- | --- |
| 空き容量不足 | ENG-25 のダイアログ |
| 書き込み権限がない | 「保存する権限がありません」。「名前を付けて保存」ボタンを付ける |
| 他のアプリが使用中 | 「他のアプリ (プロセス名) が使用中のため保存できません」。「再試行」ボタンを付ける |
| 書き込み中の I/O エラー | 「書き込み中にエラーが発生しました (OS のメッセージ)。元のファイルは変更されていません」 |
| ファイルシステムのファイルサイズ上限 (FAT32 の 4 GiB − 1 バイトなど) を超える | 書き込みを始める前に「このドライブのファイルシステム (FAT32) では 4 GiB 以上のファイルを保存できません」。空き容量も足りない場合も、このメッセージだけを出す (ENG-25 の仕様 5) |

**受け入れ基準**:

- [ ] 100 GB のファイルの 1 バイトを変えて保存すると、1 秒以内に終わる。
- [ ] 変更のないドキュメントで Ctrl+S を押しても、ファイルの更新日時が変わらない。
- [ ] 保存中に表示のスクロールと検索ができる。
- [ ] 保存後、Undo すると「変更あり」になり、Redo すると「変更あり」が消える。
- [ ] FAT32 のドライブに 5 GiB のファイルを保存しようとすると、書き込みを始める前にエラーが出る。空き容量も足りない場合も、出るのはファイルサイズ上限のエラーだけで、空き容量不足のダイアログは出ない。

### ENG-21 名前を付けて保存

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-08 |
| 呼び出し | ファイル > 名前を付けて保存 (Ctrl+Shift+S)、コマンドパレット「ファイル: 名前を付けて保存」、タブの右クリックメニュー |

**概要**: ドキュメントの内容を、新しいパスのファイルに書き出す。保存後、ドキュメントは新しいファイルを指す (ファイルの場合)。

**仕様**:

1. Windows の標準の保存ダイアログを使う。初期フォルダは元のファイルのフォルダ (無題の場合は前回保存したフォルダ)、初期のファイル名は元のファイル名 (無題の場合は「無題 1.bin」)。
2. 既存のファイルを選んだ場合は、ダイアログで上書きの確認をする (標準のダイアログの確認を使う)。
3. 選んだパスが他のタブで開いているファイルの場合は、「そのファイルは別のタブで開いています。先に閉じてください」として保存しない。
4. 選んだパスが現在のファイル自身の場合は「保存」(ENG-20) と同じ。
5. 書き出し方:
   - 新しいパスにファイルがない場合: 同じフォルダに一時ファイルを作って書き出し、最後に名前を変えて確定する (途中で失敗しても、中途半端なファイルが目的のパスに残らない)。
   - 既存のファイルを上書きする場合: 安全な保存 (ENG-22) と同じ手順で置き換える。
6. ファイルの場合、保存後はドキュメントが新しいファイルを指す。タブの名前、最近使ったファイル (ENG-16)、付随データのキー (00 の 10 章) を新しいパスに切り替える。元のファイルは変更しない。
7. 元のファイルのハンドルは、保存前の Undo 履歴が参照している間は閉じない (ENG-05)。
8. ディスク・ボリュームの場合は、ドキュメントの内容 (変更を含む) を新しいファイルに書き出すが、ドキュメントはディスクを指したまま (「コピーを保存」の動作)。全体を書き出すため raw イメージの作成になる。高度なイメージ作成 (E01、ハッシュ付き) は FOR-20。
9. プロセスメモリの場合は「名前を付けて保存」を無効にし、スナップショット (ENG-35) の保存へ案内する。

**画面**: 標準の保存ダイアログ。

**巨大ファイル・長時間処理**: 全体の書き出しのため、サイズに比例した時間がかかる。長時間処理として進捗を示し、キャンセルできる。キャンセル時は一時ファイルを削除する。

**エラー**: ENG-20 のエラーと同じ。加えて、パスが長すぎる・使えない文字を含む場合は「この名前では保存できません」と理由を示す。

**受け入れ基準**:

- [ ] 名前を付けて保存した後、タブの名前が新しいファイル名になり、元のファイルの内容とハッシュが変わっていない。
- [ ] 書き出しの途中でキャンセルすると、目的のパスにファイルが残らない。
- [ ] ディスクを名前を付けて保存すると、ドキュメントはディスクを指したまま、ファイルにディスクの内容が書き出される。

### ENG-22 安全な保存 (一時ファイルと置き換え)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-09 |
| 呼び出し | 保存 (ENG-20) から自動で選ばれる。設定 (Ctrl+,) の「保存」 |

**概要**: 同じフォルダの一時ファイルに全体を書き出し、書き終わってから元のファイルと置き換える (`ReplaceFile`)。途中でアプリや OS が落ちても元のファイルは壊れない。長さが変わる保存の既定の方式。

**仕様**:

1. 手順:
   1. 保存先の最終パスを求める (シンボリックリンクの場合はリンク先のファイルを置き換え、リンク自体は残す)。
   2. 空き容量を確認する (ENG-25)。
   3. 保存先と同じフォルダに一時ファイルを作る。名前は `.<元の名前>.~hex<ランダムな 8 桁の 16 進>.tmp`、隠し属性を付ける。作成後すぐに最終的な長さを確保し、容量不足を書き込み前に検出する。
   4. 開始時のスナップショットを先頭から順に書き出す。読み込みと書き込みを重ねて行い (4 MiB のバッファ 2 つ)、進捗を報告する。
   5. 元のファイルがスパースファイルの場合は、一時ファイルもスパースにし、すべて 00 の 64 KiB 単位のブロックは書かずに未割り当てのままにする。
   6. 書き込みをディスクに確実に反映する (`FlushFileBuffers`。設定「保存時にディスクへの書き込みを待つ」、既定オン)。
   7. 自分の書き込み禁止のハンドル (ENG-15) を閉じる。
   8. `ReplaceFile` で元のファイルを一時ファイルに置き換える。属性、アクセス権 (ACL)、作成日時、代替データストリーム (ADS) を引き継ぐ。`ReplaceFile` が ADS を引き継がない場合は、置き換え前に一時ファイルへコピーする。
   9. 置き換え前のファイルは、Undo 履歴が参照するため開いたままにする。名前は見えないようにし (削除予約を付けて、パスからは消す)、アプリが閉じたとき (異常終了を含む) に OS が削除するようにする。
   10. 新しいファイルを開き直し、ドキュメントの元データにする。
2. 置き換え前のファイルを開いたまま `ReplaceFile` で置き換えられることは確認済み (読み取りのハンドルを `FILE_SHARE_DELETE` 付きで開いている場合。NTFS、2026-10-07)。それでも置き換えに失敗した場合 (他のアプリのハンドルなど) は、置き換え前のファイルのハンドルを閉じて置き換え、保存前の Undo 履歴を破棄する (ENG-05 の「エラー」)。
3. ネットワーク上の共有など、`ReplaceFile` が使えない場所では、名前の変更による置き換え (元のファイル → 退避名、一時ファイル → 元の名前、退避ファイルの削除) を行う。途中で失敗した場合は退避名から元の名前に戻す。
4. 置き換え後に、元のファイルとの違いが生じる点:
   - ファイル ID が変わる (ファイル ID で追跡しているツールからは別のファイルに見える)。
   - ハードリンクが切れる。元のファイルのリンク数が 2 以上の場合は、保存前に確認ダイアログで「このファイルには N 個のハードリンクがあります。安全な保存ではリンクが切れます」と示し、「安全に保存 (リンクを切る)」「その場で保存 (リンクを保つ。途中で落ちると壊れる可能性あり)」「キャンセル」を選ばせる。「その場で保存」は ENG-23 (長さが同じ場合) または ENG-24 (長さが違う場合)。ENG-24 (フェーズ 2 提案) を実装するまでは、長さが違う場合は「その場で保存」を出さない。
5. 読み取り専用属性があり、利用者が読み取り専用を解除していた場合 (EDIT-16、ENG-14) は、置き換え後に読み取り専用属性を外す。
6. バックアップ (ENG-26) が有効な場合は、置き換え前のファイルをバックアップとして残す。
7. 一時ファイルの名前と保存先は、復旧用データ (ENG-27) に記録する。異常終了で一時ファイルが残った場合は、次回起動時に復旧の画面で削除を提案する。

**画面**: 設定画面「保存」に、「保存時にディスクへの書き込みを待つ」「長さが変わらない場合の保存方法」「長さが変わる場合もその場で書く」「保存時に更新日時を変えない」「バックアップを作る」を置く。

**巨大ファイル・長時間処理**: ファイルサイズに比例した時間がかかる。書き込み速度はストレージの順次書き込み速度の 80% 以上を目標とする。キャンセルは手順 8 の前までできる。キャンセル時は一時ファイルを削除する。手順 8 以降はキャンセルボタンを無効にする。

**エラー**:

- 手順 1〜7 で失敗した場合: 一時ファイルを削除し、元のファイルは変更されていないことを示す。
- 手順 8 で失敗した場合: 元の名前に元の内容がある状態に戻す。戻せない場合は「保存の最後の段階で失敗しました。元の内容はパス A、新しい内容はパス B にあります」と、両方のパスを示し、Explorer で開くボタンを付ける。
- 手順 9、10 で失敗した場合: 保存自体は成功として扱い、Undo 履歴の破棄 (ENG-05 のエラー) や再読み込みの失敗を InfoBar で示す。

**受け入れ基準**:

- [ ] 10 GiB のファイルに 1 バイト挿入して保存している途中でプロセスを強制終了しても、元のファイルのハッシュが変わっていない。
- [ ] 保存後、元のファイルの ACL・属性・作成日時・代替データストリームが保たれている。
- [ ] 保存後、Undo で保存前の内容に戻れる。アプリを閉じると置き換え前のファイルが残っていない。
- [ ] スパースファイル (論理サイズ 100 GiB、実使用 1 MiB) を保存しても、保存後の実使用量が 100 GiB にならない。
- [ ] ハードリンクのあるファイルの保存で確認ダイアログが出る。
- [ ] 保存の途中でキャンセルすると、一時ファイルが残らない。

### ENG-23 その場保存 (長さが変わらない場合)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-09 |
| 呼び出し | 保存 (ENG-20) から自動で選ばれる |

**概要**: 長さが変わらず、データがずれていない場合に、変更した範囲だけを元のファイル (またはデバイス) に直接書き込む。書き込む前に旧内容 (元のバイト) をジャーナルに記録し、途中でアプリや OS が落ちても、次の起動時に保存前の状態に戻せるようにする (00 の 11.3)。

**仕様**:

1. 適用条件 (ファイルの場合): 保存前後で長さが同じで、ピースツリーのすべての元データのピースが元と同じ位置を指している (ENG-02 の「変更された範囲」がすべて、その位置での置き換えだけ)。データがずれている場合 (削除と挿入で長さが釣り合っただけ) は適用しない。
2. 手順:
   1. 書き込む範囲 (変更された範囲。セクタ境界が必要なデータソースではセクタ境界まで広げる) を求める。
   2. ジャーナル: 書き込む範囲の旧内容を元データから読み、復旧用フォルダの `journal-<ドキュメント ID>.bin` に書く。ジャーナルには対象の識別情報 (パス、ファイル ID、長さ、最終更新日時、またはデバイスの識別子) と、各範囲のオフセット・長さ・旧内容を入れる。書き終えたらディスクへの反映を待つ。
   3. 旧内容を追加バッファにも退避し、保存前の版 (Undo 履歴) が参照できるようにする (ENG-05)。
   4. 変更した範囲を書き込む。オフセットの昇順に書く。
   5. ディスクへの反映を待つ。
   6. ジャーナルを削除する。
3. ジャーナルの上限 (既定 1 GiB、設定で 0〜無制限) を書き込む量が超える場合、またはジャーナルの置き場所の空き容量が足りない場合は、00 の 11.3 の要件を満たせないため、書き込みを始める前に確認ダイアログで「変更が大きいため旧内容を記録できません。保存の途中で止まると元に戻せません」と示し、「安全な保存を使う」(ファイルの場合のみ)「保護なしで書き込む」「キャンセル」を選ばせる。保護なしの場合も旧内容は Undo 用に追加バッファへ退避する (退避が一時ファイルに入る)。
4. 起動時にジャーナルが残っている場合は、復旧の画面 (ENG-27) で「前回、data.bin の保存が途中で中断されました」と示し、「保存前の状態に戻す」「このままにする」を選ばせる。「保存前の状態に戻す」はジャーナルの旧内容を書き戻す。対象の識別情報が一致しない場合 (その後ファイルが変更された) は書き戻さず、その旨を示す。比べるのはパス・ファイル ID・長さで、最終更新日時は比べない (中断した保存そのものが最終更新日時を変えるため。ジャーナルには記録する)。ジャーナルに終わりの印がない (旧内容の記録の途中で止まった) 場合は、ファイルはまだ書き換わっていないため、書き戻さずにジャーナルを削除する。
5. 変更範囲が多数ある場合 (100 万か所など) も、範囲ごとに書き込みの呼び出しをせず、近い範囲 (間隔 64 KiB 以内) はまとめて 1 回で書く (間の未変更部分は元データを書き戻す)。

**画面**: なし (ENG-20 の進捗表示)。ジャーナルが使えない場合の確認ダイアログ。

**巨大ファイル・長時間処理**: 書き込み量は変更したバイト量 (とジャーナル分) に比例し、ファイルサイズには依存しない。キャンセルは手順 4 の開始前までできる。手順 4 の途中でキャンセルされた場合は、ジャーナルから書き戻して保存前の状態に戻す。

**エラー**: 手順 4 で書き込みに失敗した場合は、ジャーナルから旧内容を書き戻し、「保存に失敗したため、保存前の状態に戻しました」と示す。書き戻しにも失敗した場合は、ジャーナルを残し「ファイルの一部だけが書き換わっています。次回起動時に復旧できます」と示す。

**受け入れ基準**:

- [ ] 100 GB のファイルの 10 か所を変更して保存すると、書き込み量が変更したバイト量の数倍以内 (ジャーナルを含む) で、1 秒以内に終わる。
- [ ] 1 バイト削除して別の位置に 1 バイト挿入した (長さが同じ) ドキュメントの保存では、その場保存ではなく安全な保存が選ばれる。
- [ ] 書き込みの途中でプロセスを強制終了した後、起動すると復旧の画面が出て、「保存前の状態に戻す」で保存前のハッシュに戻る。
- [ ] その場保存の後、Undo で保存前の内容に戻れる。

### ENG-24 ずらしながらのその場保存

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 空き容量不足のダイアログ (ENG-25) の「その場でずらしながら保存」、ハードリンクの確認 (ENG-22) の「その場で保存」、設定 (Ctrl+,) の「保存」の「長さが変わる場合もその場で書く」 |

**概要**: 長さが変わる保存を、一時ファイルを作らず元のファイルの中でデータをずらしながら行う。追加のディスク容量がほとんど要らないが、途中でアプリや OS が落ちるとファイルが壊れる。

**仕様**:

1. 書き込み計画を作る: 保存後のファイルの各範囲について、どの元データ (またはそれ以外) を書くかを求め、まだ必要な元データを上書きしない順序を決める。
   - データを後ろにずらす範囲は末尾側から、前にずらす範囲は先頭側から書く。
   - 循環する依存関係 (入れ替えなど) がある場合、必要な元データを退避ファイル (追加バッファの一時ファイルと同じ場所) にコピーしてから書く。
2. 必要な退避の量を計画の段階で計算し、確認ダイアログに示す。
3. 実行前に、毎回確認ダイアログを出す。本文: 「data.bin をその場で書き換えます。保存中にアプリや PC が停止すると、ファイルが壊れて元に戻せなくなります。書き換える量: X、一時的に必要な容量: Y」。ボタンは「その場で保存」「キャンセル」。設定「長さが変わる場合もその場で書く」をオンにしている場合も確認は出す (確認を省略する設定は設けない)。
4. ファイルが長くなる場合は先にファイルを伸ばし、短くなる場合は最後に切り詰める。
5. 書き込みを始めたら、キャンセルできない (キャンセルボタンを無効にし、理由をツールチップで示す)。
6. 実行中は復旧用フォルダに「中断マーカー」(対象のパスと開始時刻) を置き、完了したら削除する。起動時にマーカーが残っていれば、「前回、data.bin のその場保存が中断されました。ファイルが壊れている可能性があります」と示す (自動の修復はしない)。
7. 保存前の Undo 履歴が参照する元データは、書き換える前に追加バッファへ退避する。退避の量が大きすぎて空き容量が足りない場合は、計画の段階で「保存前の Undo 履歴を破棄します」と確認ダイアログに書く。

**画面**: 確認ダイアログ。処理センターの進捗表示 (キャンセル不可の表示)。

**巨大ファイル・長時間処理**: ずらす範囲のデータ量に比例した時間がかかる (先頭に 1 バイト挿入すると、ファイル全体の読み書きになる)。

**エラー**: 書き込み中の I/O エラーでは処理を止め、「その場保存の途中でエラーが発生しました。ファイルが壊れている可能性があります。保存していない内容はこのタブに残っています。別の場所に保存してください」と示し、「名前を付けて保存」ボタンを付ける。ドキュメントの内容 (スナップショット) は保持する。

**受け入れ基準**:

- [ ] 空き容量がファイルサイズより小さいドライブで、10 GiB のファイルの先頭に 1 KiB 挿入して保存できる。
- [ ] 保存後のファイルが、同じ編集を安全な保存で保存したものとバイト単位で一致する (ランダムな編集 1,000 パターンで確認)。
- [ ] 実行のたびに確認ダイアログが出る。
- [ ] 実行中にプロセスを強制終了した後、起動時に中断の警告が出る。

### ENG-25 空き容量の事前チェック

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-09 |
| 呼び出し | 保存・名前を付けて保存・スナップショット保存などの書き出しの前に自動 |

**概要**: 書き出しを始める前に、保存先のドライブに十分な空き容量があるかを確認する。足りない場合は書き込みを始めず、別の方法を選ばせる。

**仕様**:

1. 必要な容量:

   | 方式 | 必要な容量 (保存先のドライブ) |
   | --- | --- |
   | 安全な保存・名前を付けて保存 | 保存後のサイズ + 16 MiB。スパースの場合は 00 以外のブロックの合計の見積もり + 16 MiB |
   | その場保存 (ENG-23) | 保存先: 0。ジャーナルの置き場所: ジャーナルのサイズ + 16 MiB |
   | ずらしながらのその場保存 (ENG-24) | 伸びる分 + 16 MiB。退避ファイルの置き場所: 退避の量 + 16 MiB |

2. 空き容量は、ユーザーごとのクォータを考慮した値 (`GetDiskFreeSpaceEx` で得られる、呼び出し元が使える容量) で判断する。
3. 安全な保存では、置き換え前のファイルの領域は Undo のために開いたままにするため、すぐには解放されない。空き容量の計算でも解放されないものとして扱う。
4. 足りない場合は、ダイアログで「保存先のドライブ (D:) の空き容量が足りません。必要: X、空き: Y」と示し、次のボタンを出す。
   - 別の場所に保存 (名前を付けて保存のダイアログを開く)
   - その場でずらしながら保存 (ENG-24。ファイルで、伸びる分の空きがある場合だけ。ENG-24 (フェーズ 2 提案) を実装するまでは出さない)
   - キャンセル
5. ファイルシステムのファイルサイズ上限 (FAT32 の 4 GiB − 1 バイト) も同時に確認する (ENG-20 のエラー)。ファイルサイズ上限の確認を空き容量の確認より先に行い、上限を超える場合は空き容量が足りなくても上限のエラーだけを出す (空き容量不足のダイアログは出さない。メッセージは 1 つだけ)。
6. 確認の後で空き容量がなくなった場合 (他のアプリの書き込みなど) は、書き込みの失敗として扱う (ENG-22 の手順 1〜7 の失敗)。
7. 追加バッファの一時ファイルの置き場所の空き容量は ENG-04 の仕様 7 で警告する。

**画面**: 空き容量不足のダイアログ。サイズは地域設定で書式化し、単位を付ける。

**巨大ファイル・長時間処理**: 確認はサイズに依存せず即座に終わる (スパースの見積もりは、元ファイルの割り当て済み範囲の問い合わせと変更範囲から計算し、全体を読まない)。

**エラー**: 空き容量を取得できない場合 (一部のネットワークドライブ) は確認を省略し、書き込みを試みる。失敗したら通常の書き込みエラーになる。

**受け入れ基準**:

- [ ] 空き容量 1 GiB のドライブで 2 GiB のファイルを安全に保存しようとすると、書き込みを始める前にダイアログが出て、ファイルが変更されていない。
- [ ] クォータが設定されたユーザーでは、クォータの残りで判断される。
- [ ] ダイアログの「別の場所に保存」で保存ダイアログが開く。

### ENG-26 バックアップファイルの作成

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案) |
| 呼び出し | 設定 (Ctrl+,) の「保存」の「バックアップを作る」 |

**概要**: 保存のたびに、保存前のファイルをバックアップとして残す。既定ではオフ。

**仕様**:

1. 設定「バックアップを作る」(`save.backup.enabled`、既定オフ)。オンにすると、保存のたびに保存前のファイルを残す。置き場所は `save.backup.location` (`sameFolder` / `folder`) と `save.backup.folder`、世代数は `save.backup.generations`。
2. 置き場所: 「元のファイルと同じフォルダ」(既定) または「指定したフォルダ」。名前は `<元の名前>.bak`。指定したフォルダに置く場合、同じ名前が衝突しないように、フォルダ内に元のフォルダ構造の代わりにパスのハッシュの短縮形 (8 桁) を付ける (`<元の名前>.<ハッシュ>.bak`)。
3. 世代数: 既定 1 (設定で 1〜10)。2 以上の場合は `.bak`、`.bak2`… とし、古いものから削除する。
4. 安全な保存 (ENG-22) では、置き換え前のファイルの名前を変えてバックアップにする (コピーしない)。この場合、Undo 用に開いているハンドルはバックアップのファイルを指す。
5. その場保存 (ENG-23、ENG-24) では、保存前にファイル全体をコピーする必要がある。ファイルサイズが 1 GiB を超える場合は、確認ダイアログで「バックアップのためにファイル全体 (X) をコピーします」と示し、「コピーして保存」「バックアップなしで保存」「キャンセル」を選ばせる。
6. ディスク・ボリューム・プロセスメモリの保存ではバックアップを作らない (変更前の内容はジャーナルで保持する。ENG-23、ENG-30)。

**画面**: 設定画面「保存」の項目。

**巨大ファイル・長時間処理**: 安全な保存では名前の変更だけで即座に終わる。その場保存ではファイル全体のコピーになり、長時間処理として進捗を示す。

**エラー**: バックアップを作れない場合 (権限、空き容量) は保存を始めず、「バックアップを作れないため保存を中止しました (理由)」と示し、「バックアップなしで保存」ボタンを付ける。

**受け入れ基準**:

- [ ] バックアップを有効にして保存すると、同じフォルダに保存前の内容の `.bak` ができる。
- [ ] 世代数 3 で 5 回保存すると、バックアップが 3 つだけ残る。
- [ ] 安全な保存でのバックアップ作成が、ファイルサイズに関係なく 1 秒以内に終わる (書き出し自体の時間を除く)。

### ENG-27 復旧用データの自動保存と異常終了からの復旧

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 1 提案。00 の 11.3 の要件) |
| 呼び出し | 自動。起動時の復旧の画面。設定 (Ctrl+,) の「保存」の「復旧用データの保存間隔」 |

**概要**: 未保存の編集内容を定期的に復旧用データとして保存し、アプリや OS が異常終了した後の起動時に復旧を提案する。元のファイルには自動で書き込まない。

**仕様**:

1. 保存間隔は既定 1 分 (設定 `save.recoveryIntervalMinutes` で 0 = 無効、1〜60 分)。前回の保存から変更があったドキュメントだけを保存する。
2. 保存先は設定フォルダの `recovery/<ドキュメント ID>/`。内容:
   - ドキュメントの情報: 種類、パス (またはデバイス・プロセスの識別子)、開いたときの元データの長さ・最終更新日時・ファイル ID、範囲 (ENG-13)、表示名。
   - 現在の内容の表現: ピースツリー (または変更範囲マップ) のピースの一覧。元データのピースは位置と長さだけを記録し、元データをコピーしない。生成ピースは規則だけを記録する。
   - 追加バッファ: 追加バッファの一時ファイル (ENG-04) は同じフォルダにあり、そのまま参照する。メモリ上のチャンクのうち未書き出しのものを追記する。巨大な追加データはコピーしない (00 の 11.3)。
   - 別のドキュメントから貼り付けた範囲 (EDIT-24 の範囲の参照): 参照元のドキュメントは異常終了の後には残らないため、範囲の内容を同じフォルダの `ext-*.bin` に 1 回だけコピーして記録する (貼り付けた量に比例する。同じ範囲は次の書き出しでコピーし直さない)。
   - カーソル位置と選択範囲。
3. 書き込みはバックグラウンドで行い、編集を止めない。保存の途中で落ちても前回の復旧用データが壊れないよう、新しいデータを書いてから入れ替える。
4. 未処理の例外でアプリが終了する場合は、終了前に全ドキュメントの復旧用データを書き出す (00 の 11.3)。
5. 保存した (ENG-20)、または保存せずに閉じた (ENG-17) ドキュメントの復旧用データは削除する。
6. 起動時に `recovery/` に残っているデータがあれば、復旧の画面を出す。
   - 一覧: 表示名、パス、最後に復旧用データを保存した日時、変更の量。
   - ボタン: 「復旧する」「破棄」「あとで」(あとでは次回起動時にもう一度出す)。
   - 「復旧する」は、元データを開き直し、記録したピースの一覧を復元したドキュメントを「変更あり」の状態で開く。Undo 履歴は復元しない (復旧した状態から始まる)。
   - 元データの長さ・最終更新日時・ファイル ID が記録と違う場合は、「元のファイルが変更されているため、正しく復旧できない可能性があります」と示し、読み取り専用で開く。
   - 無題のドキュメントは、元データなしでそのまま復元する。
7. ジャーナル (ENG-23)、中断マーカー (ENG-24)、安全な保存の残った一時ファイル (ENG-22) も同じ画面で扱う。
8. ドキュメントの種類ごとの扱い:
   - ディスク・ボリューム: 変更範囲マップを復旧する。開き直しには、開いたときと同じく管理者権限 (ENG-28。USB ストレージのボリュームは不要。ENG-29 の仕様 3) が必要。デバイスのシリアル番号が一致しない場合は復旧しない。
   - プロセスメモリ: 復旧しない (プロセスが終了しているため)。変更範囲を Intel HEX などに書き出す (TOOL-04、TOOL-05 のエクスポート) ことだけ提案する。
9. 複数のアプリのインスタンスがある場合 (別ウィンドウの単一インスタンスで動くため通常はない) も、他のインスタンスが使用中の復旧用データは対象にしない (ロックファイルで判定する)。

**画面**: 起動時の復旧の画面 (ダイアログ)。

**巨大ファイル・長時間処理**: 復旧用データの量は変更の量に比例し、ファイルサイズには依存しない。1 回の保存に 0.5 秒以上かかる場合も、バックグラウンドで行い進捗は出さない (処理センターにも出さない)。

**エラー**: 復旧用データを書けない場合 (容量不足など) は、InfoBar で 1 回だけ「復旧用データを保存できません (理由)。異常終了すると編集内容が失われます」と示す。復旧に失敗した場合は、理由を示し、復旧用データは消さずに残す (「破棄」で消せる)。

**受け入れ基準**:

- [ ] 編集して 1 分以上待ってからプロセスを強制終了し、起動すると復旧の画面が出て、編集内容が復元される。
- [ ] 100 GiB のファイルを 1 バイト編集したときの復旧用データが 1 MiB 未満。
- [ ] 保存すると復旧用データが消える。
- [ ] 元のファイルが変わっていた場合、警告付きで読み取り専用として復旧される。
- [ ] 未処理の例外の後に起動すると、直前の編集まで復旧できる。例外は、テスト用のビルドの異常を再現する仕組み (テスト方針 (docs/test/00-test-strategy.md) 7.2 の「未処理の例外」。`--test-hooks` またはテスト用のメニュー) で発生させる。

## 4. 昇格した補助プロセス

### ENG-28 昇格した補助プロセス

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-09、F2-10 |
| 呼び出し | 管理者権限が必要な操作 (物理ディスク・内蔵ディスクのボリュームを開く、昇格したプロセス・システムのプロセス・他のユーザーのプロセスを開く、デバイス情報の取得 (FOR-27、FOR-28)、OS の USB 書き込み保護の切り替え (FOR-02)) をしたときに自動で起動 |

**概要**: UI のプロセスは一般ユーザー権限のまま動かし、管理者権限が必要な操作だけを別の昇格した補助プロセスに依頼する。補助プロセスが受け付けるのは、00 の 11.4 に挙げた操作 (デバイスの読み書きとボリュームのロック・ディスマウント、プロセスメモリの読み書き、読み取り専用のデバイス情報の取得、OS の USB ストレージ書き込み保護の切り替え) だけである。補助プロセスはインストーラ版とポータブル版にだけ同梱する。アプリ全体を管理者として実行している場合 (Microsoft Store 版を含む) は、補助プロセスを使わず同じプロセスで処理する (仕様 10)。補助プロセスも管理者権限も使えない場合は、機能を無効にせず案内ダイアログを出す (仕様 12)。

管理者権限の要否は次のとおり (どの配布形態でも同じ):

| 対象 | 管理者権限なしで | 管理者権限があれば |
| --- | --- | --- |
| 同じユーザーの、昇格していないプロセスのメモリ | 読み書きできる (UI のプロセスで直接開く。ENG-32) | 読み書きできる |
| 取り外し可能な USB ストレージのボリューム (`\\.\E:` の形式) | 読み書きできる (UI のプロセスで直接開く。ENG-29) | 読み書きできる |
| 物理ディスク全体 (`\\.\PhysicalDriveN`。USB ストレージを含む) | 開けない | 開ける |
| 内蔵ディスクのボリューム、光学ドライブ | 開けない | 開ける |
| 昇格したプロセス、システムのプロセス、他のユーザーのプロセス | 開けない | 開ける (`SeDebugPrivilege` を有効にする) |
| 保護されたプロセス (PPL など) | 開けない | 開けない (ENG-32 の仕様 4 の 3) |
| デバイス情報の取得、OS の USB 書き込み保護の切り替え | 使えない | 使える |

**仕様**:

1. 補助プロセスは `HexEditor.Elevated.exe` (UI を持たないコンソールなしのプログラム)。管理者権限が必要な操作が初めて行われたときに、UAC の昇格 (`runas`) で起動する。UAC の確認はアプリの起動ごとに原則 1 回。
2. 接続:
   1. UI のプロセスが名前付きパイプ `\\.\pipe\HexEditor.Helper.<ランダムな GUID>` を作る。パイプは現在のユーザーと SYSTEM だけが接続でき、リモートからの接続を拒否し、最初のインスタンスとして作る (同名のパイプを他のプロセスが先に作っていたら失敗させる)。
   2. 補助プロセスの起動引数に、パイプ名・UI のプロセス ID・32 バイトのランダムな合言葉を渡す。
   3. 補助プロセスは、パイプのサーバー側のプロセス ID が引数のプロセス ID と一致することを確認してから接続し、合言葉を送る。
   4. UI のプロセスは、接続してきたクライアントのプロセス ID が自分で起動した補助プロセスのものであること、合言葉が一致することを確認する。どちらかが違えば切断する。
3. メッセージの形式 (リトルエンディアン):

   ```text
   要求:  [長さ u32][要求 ID u32][コマンド u16][フラグ u16][本体 ...]
   応答:  [長さ u32][要求 ID u32][状態 u32 (0 = 成功、それ以外は Win32 エラーコード)][本体 ...]
   ```

   - 長さはヘッダを除く本体のバイト数。本体の最大は 1 MiB + 64 バイト。超えるメッセージを受け取ったら切断する。
   - 要求は最大 16 個まで応答を待たずに送れる。応答の順序は要求の順序と一致しなくてよい (要求 ID で対応付ける)。
4. 受け付けるコマンド (これ以外は拒否して切断する):

   | コマンド | 内容 |
   | --- | --- |
   | `Hello` | バージョンの確認。UI と補助プロセスのバージョンが違えば補助プロセスを終了し、再起動する |
   | `EnumDevices` | 物理ディスク・ボリューム・光学ドライブの一覧と情報 |
   | `OpenDevice` | デバイスを開き、ハンドル番号 (u32) を返す。受け付けるパスは `\\.\PhysicalDriveN`、`\\.\X:`、`\\?\Volume{GUID}`、`\\.\CdRomN` の形式だけ。読み取りのみか読み書きかを指定する |
   | `GetGeometry` | 長さ、論理・物理セクタサイズ、アラインメントの要件 |
   | `ReadSectors` / `WriteSectors` | セクタ境界に揃った範囲の読み書き (最大 1 MiB) |
   | `LockVolume` / `DismountVolume` / `UnlockVolume` | ボリュームのロック・ディスマウント・ロック解除 (ENG-30) |
   | `Flush` | 書き込みのディスクへの反映 |
   | `OpenProcess` | プロセス ID を指定して開き、ハンドル番号を返す。読み取りのみか読み書きかを指定する |
   | `QueryRegions` | メモリ領域の一覧 (ENG-33) |
   | `EnumModules` | モジュールの一覧 |
   | `ReadMemory` / `WriteMemory` | 仮想アドレスを指定した読み書き (最大 1 MiB) |
   | `ProtectMemory` | ページの保護属性の一時的な変更と復元 (ENG-34) |
   | `QueryDeviceInfo` | 読み取り専用のデバイス情報の取得 (FOR-27、FOR-28)。開いたデバイスのハンドル番号と情報の種類 (IDENTIFY DEVICE、READ NATIVE MAX ADDRESS (EXT)、DEVICE CONFIGURATION IDENTIFY、SMART READ DATA / READ THRESHOLDS、NVMe の SMART / Health Information) を指定する。ATA パススルーで送るコマンドはこれらの読み取り専用のものだけで、それ以外の指定は拒否する |
   | `GetUsbWriteProtect` / `SetUsbWriteProtect` | OS の USB ストレージ書き込み保護 (レジストリの `StorageDevicePolicies` の `WriteProtect` の 1 値) の取得と切り替え (FOR-02)。値は 0、1、値の削除だけを受け付ける |
   | `SetWriteBlock` | 書き込み保護モード (FOR-01) の状態 (有効・無効) の通知。補助プロセスの起動・再接続の直後 (`Hello` の後) と、モードを切り替えたときに送る |
   | `Close` | ハンドル番号を閉じる |
   | `Ping` | 生存確認 |

   - ファイルのパスを受け付けるコマンド、任意のプログラムを実行するコマンド、任意のレジストリの値を変えるコマンドは持たない。
   - 書き込み保護モード (FOR-01) が有効な間は、UI のプロセスがその状態を補助プロセスに `SetWriteBlock` で通知し、補助プロセスは `WriteSectors`、`WriteMemory`、`ProtectMemory`、`LockVolume`、`DismountVolume` と、読み書きを指定した `OpenDevice` / `OpenProcess` を拒否する (FOR-01 の仕様 2)。
   - ハンドル番号は補助プロセスの中の表の番号で、OS のハンドルそのものは UI のプロセスに渡さない。
5. 1 つの要求の待ち時間の上限は 30 秒 (設定で 5〜300 秒)。超えたら、その要求は失敗 (タイムアウト) として扱い、読み込みの場合は「読めない」にする。
6. 補助プロセスの終了:
   - UI のプロセスが終了した (パイプが切れた、または UI のプロセスのハンドルが終了を通知した) とき、開いているハンドルを閉じ、ロックしたボリュームのロックを解除してから終了する。
   - 開いているハンドルが 0 になってから 10 分たったら終了する (設定で 1〜60 分、または「アプリの終了まで残す」)。次に必要になったら再び UAC の確認が出る。
7. 補助プロセスが異常終了した場合、それを使っていたドキュメントは「切断」(ENG-01) になる。InfoBar で「管理者権限の補助プロセスが終了しました」と示し、「再接続」ボタンを付ける (UAC の確認が出る)。未保存の変更は残る。
8. UAC の確認で「いいえ」を選ばれた、または管理者の資格情報がない場合は、操作を中止し「管理者権限が得られなかったため、ディスクを開けませんでした」の趣旨を示す。
9. 補助プロセスは、実行したコマンドの種類・対象・結果をアプリのログに記録する。読み書きしたデータの内容は記録しない。
10. アプリ自体を管理者として実行している場合 (どの配布形態でも。Microsoft Store 版は利用者がスタートメニューから「管理者として実行」で起動した場合。10 の PKG-04) は、補助プロセスを使わず同じプロセスで処理する (同じコマンドの許可リストを通す)。UAC の確認は出ない。
11. 配布形態ごとの扱い:

    | 配布形態 | 管理者権限なしで起動した場合 | 管理者として実行した場合 |
    | --- | --- | --- |
    | インストーラ・ポータブル | 補助プロセスを UAC の確認を出して起動する (仕様 1) | 同じプロセスで処理する (仕様 10) |
    | MSIX (Microsoft Store 版) | 補助プロセスを同梱しないため、案内ダイアログ (仕様 12) を出す | 同じプロセスで処理する (仕様 10。実機での確認は 10 の PKG-04 の未決定) |

12. 管理者権限の案内: 管理者権限が必要な操作をしたとき、補助プロセスも管理者権限も使えない場合 (Store 版を管理者として実行していないとき、インストーラ版・ポータブル版で補助プロセスのファイルが見つからないとき) は、案内ダイアログを出す。メニュー・コマンドパレットの項目は無効にせず、選ぶとこのダイアログを出す (機能を黙って無効にしない)。
    1. 本文に、管理者権限が必要な理由を操作ごとに書く (例: 「物理ディスクを直接読むには、Windows の管理者権限が必要です」「このプロセスは管理者として動いているため、開くには管理者権限が必要です」)。
    2. 管理者として起動し直す手順を、配布形態ごとに番号付きで書く。
       - Store 版・インストーラ版: 「1. HexEditor を閉じます。2. スタートメニューで HexEditor を右クリックします。3. 「その他」>「管理者として実行」を選びます」。
       - ポータブル版: 「1. HexEditor を閉じます。2. エクスプローラーで `HexEditor.exe` を右クリックします。3. 「管理者として実行」を選びます」。
    3. 管理者として実行中の制限 (エクスプローラーからのドラッグ & ドロップで開けない。09 の UI-34 の仕様 7) を添える。
    4. 管理者権限なしで使える代わりの方法があれば添える (例: ディスクを開く操作では「取り外し可能な USB ストレージのボリュームは管理者権限なしで開けます」)。
    5. Store 版では、インストーラ版・ポータブル版なら必要なときだけ UAC の確認を出して管理者権限の操作を使えることと、ダウンロードページへのリンクを添える。
    6. ボタン: 「管理者として再起動」「閉じる」。「管理者として再起動」は、プログラムから管理者として起動し直せる配布形態 (インストーラ版・ポータブル版) だけに出す。Store 版では手順だけを示し、このボタンは出さない。
    7. 「管理者として再起動」を押すと、終了時と同じ確認 (未保存の変更。09 の UI-13) をしてからセッションを保存し、`HexEditor.exe` を `runas` で起動してから自分を終了する。新しいプロセスはセッション復元 (09 の UI-31) で開いていたタブを開き直す。UAC で拒否された場合は終了せず、元の状態のまま続ける。
    8. 補助プロセスを UAC で起動できる場合 (インストーラ版・ポータブル版の通常の状態) は、この案内を出さず、仕様 1 のとおり UAC の確認を出す。

**画面**: 補助プロセス自体は画面を持たない。ステータスバーに、補助プロセスが動いている間は盾のアイコンを表示する (ツールチップ「管理者権限の補助プロセスが実行中」)。アプリ全体を管理者として実行している間のタイトルバーの表示は 09 の UI-02。管理者権限の案内ダイアログ (仕様 12)。

**巨大ファイル・長時間処理**: 大きな範囲の読み書きは 1 MiB 単位の要求に分けて並行して送る。補助プロセス経由の読み込み速度は、直接の読み込みの 80% 以上を目標とする。

**エラー**: 仕様 5、7、8、12 のとおり。許可リストにないコマンドや不正なメッセージを受け取った場合、補助プロセスは切断して終了し、ログに記録する。

**受け入れ基準**:

- [ ] ディスクを開くと UAC の確認が 1 回だけ出て、続けて別のディスクを開いても再び出ない。
- [ ] アプリを管理者として実行していると、ディスクを開いても UAC の確認が出ず、補助プロセスが起動しない。
- [ ] 管理者として実行していない Store 版で「ディスクを開く」のメニューが有効で、物理ディスクを開こうとすると案内ダイアログ (仕様 12) が出る。ダイアログに「管理者として再起動」のボタンがない。
- [ ] インストーラ版で補助プロセスのファイルを削除してディスクを開こうとすると案内ダイアログが出て、「管理者として再起動」で管理者として起動し直し、開いていたファイルのタブが復元される。
- [ ] 許可リストにないコマンド、ファイルのパスを指定した `OpenDevice` を送ると、補助プロセスが拒否して切断する (テスト用のクライアントで確認)。
- [ ] 自分で起動していないプロセスがパイプに接続しようとしても拒否される。
- [ ] UI のプロセスを強制終了すると、補助プロセスも 5 秒以内に終了し、ロックしたボリュームのロックが解除される。
- [ ] 補助プロセスを強制終了すると、InfoBar が出て、「再接続」で読み込みを再開できる。

## 5. ディスク・ボリューム

### ENG-29 物理ディスク・論理ボリュームを開く

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-09 |
| 呼び出し | ファイル > ディスクを開く… (Ctrl+Shift+D)、コマンドパレット「ファイル: ディスクを開く」 |

**概要**: 物理ディスク、論理ボリューム (ドライブ文字・マウントポイント)、光学ドライブを、セクタ単位で読めるドキュメントとして開く。既定では読み取り専用。

**仕様**:

1. 「ディスクを開く」のダイアログに、2 つの一覧を表示する。一覧の取得は管理者権限なしで行う (取得できない情報は「不明」と表示する)。
   - 物理ディスク: 番号、モデル名、サイズ、接続方式 (SATA、NVMe、USB など)、パーティションの形式 (MBR / GPT / なし)、論理 / 物理セクタサイズ、取り外し可能か、システムディスクか。
   - ボリューム: ドライブ文字またはマウントポイント、ラベル、ファイルシステム、サイズ、所属する物理ディスク、BitLocker の状態。
   - 光学ドライブ: ドライブ文字、メディアの有無。
2. ダイアログの選択肢: 「読み取り専用で開く」(既定オン)、「範囲を指定して開く」(開始・長さをセクタ数またはバイトで指定。ENG-13 と同じ入力)。
3. 開き方:
   1. 取り外し可能な USB ストレージのボリューム (`\\.\E:` の形式) は、まず UI のプロセスから直接開く (管理者権限なしで開ける。ENG-28 の概要の表)。アクセスが拒否された場合は仕様 3 の 2 に進む。
   2. それ以外 (物理ディスク全体 `\\.\PhysicalDriveN`、内蔵ディスクのボリューム、光学ドライブ) は管理者権限が必要なため、補助プロセス (ENG-28) で開く。アプリを管理者として実行している場合は同じプロセスで開く (ENG-28 の仕様 10)。どちらも使えない場合 (管理者として実行していない Store 版など) は、ENG-28 の仕様 12 の案内ダイアログを出す。
   3. 一覧では、管理者権限なしで開けない項目に盾のアイコンを付ける (アプリを管理者として実行している場合は付けない)。項目は選べるままにする。
   4. ドキュメントは長さ固定 (ENG-07) で、データソースの能力は `CanWrite` (補助プロセス経由、または UI のプロセスで直接)、`IsVolatile`、`NeedsAlignment`。
4. 長さ: 物理ディスクはデバイスの長さ、ボリュームはボリュームの長さ (ファイルシステムの範囲外の末尾のセクタも読めるようにする)。
5. 論理セクタサイズを入力式の `sector` (00 の 6.2) とオフセットのセクタ / LBA 表示 (02) に使う。
6. 読み込みは常にセクタ境界に揃えて行う (ENG-06 のブロックはセクタサイズの倍数)。
7. 表示名: 物理ディスクは「ディスク 1 (モデル名, サイズ)」、ボリュームは「ボリューム C: (ラベル)」。
8. 同じデバイスを 2 回開こうとした場合は、既存のタブをアクティブにする。
9. ボリュームの内容はファイルシステムが書き換えるため変わりうる。表示は自動では更新しない (再読み込み ENG-18、または自動更新を使う)。
10. BitLocker で暗号化されたボリューム: ロック解除済みのボリュームは復号された内容を読む。物理ディスク側からは暗号化された内容が見える。ロック中のボリュームは読めない。
11. デバイスが取り外された場合は「切断」にし、InfoBar で「デバイスが取り外されました」と示す。同じシリアル番号のデバイスが再び接続されたら「再接続」ボタンを有効にする。未保存の変更は残る。
12. 開いたディスク・ボリュームは最近使ったファイル (ENG-16) に記録する。

**画面**: 「ディスクを開く」のダイアログ (2 つの一覧と選択肢、「開く」「キャンセル」)。一覧は列の並べ替えができ、キーボードで選べる。

**巨大ファイル・長時間処理**: 開く処理はディスクのサイズに依存しない (ファイルと同じく 1 秒以内に先頭を表示)。

**エラー**:

| 状況 | 利用者への見せ方 |
| --- | --- |
| 管理者権限が得られない | ENG-28 の仕様 8 |
| 補助プロセスも管理者権限も使えない (管理者として実行していない Store 版など) | ENG-28 の仕様 12 の案内ダイアログ |
| デバイスが使用中で開けない | 「デバイスを開けませんでした (OS のメッセージ)」 |
| メディアがない (光学ドライブ、カードリーダー) | 「メディアが入っていません」 |
| BitLocker でロックされている | 「このボリュームは BitLocker でロックされています。ロックを解除してから開いてください」 |
| 読み込みエラー (不良セクタ) | ENG-06 のとおり、そのセクタだけを読めないものとして表示する |

**受け入れ基準**:

- [ ] 一般ユーザー権限のアプリで、ディスクとボリュームの一覧が表示される。
- [ ] 一般ユーザー権限のアプリ (Store 版を含む) で、USB メモリのボリューム (`\\.\E:`) を UAC の確認なしで開ける。
- [ ] 一般ユーザー権限のアプリで、物理ディスクと内蔵ディスクのボリュームに盾のアイコンが付く。
- [ ] 2 TB のディスクを開いて 1 秒以内に先頭のセクタが表示される。
- [ ] 4Kn のディスクで `sector` が 4096 になる。
- [ ] ボリュームの最後のセクタまで読める。
- [ ] USB メモリを開いたまま抜くと InfoBar が出て、挿し直すと「再接続」で読み込みを再開できる。

### ENG-30 ディスク・ボリュームへの書き込み

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-09 |
| 呼び出し | ディスク・ボリュームのドキュメントで保存 (Ctrl+S) |

**概要**: ディスク・ボリュームの変更範囲を、セクタ境界に揃えて書き込む。マウント中のボリュームに書き込む場合は、事前にロック (必要ならディスマウント) する。書き込み前に旧内容をジャーナルに保存し、Undo と中断からの復旧ができるようにする。

**仕様**:

1. 保存の前に、毎回確認ダイアログを出す。本文には次を書く。
   - 対象: ディスクの番号・モデル名・サイズ (またはボリューム名)。
   - 書き込む量: N か所、M バイト (セクタ単位に広げた量)。
   - 影響するボリューム: 書き込む範囲に含まれるボリュームと、それをロックまたはディスマウントすること。
   - 「この操作で、ディスクのデータやファイルシステムが壊れる可能性があります」の警告。
   - 「書き込みの途中で止まると、元に戻せない場合があります」の警告 (00 の 11.3 の例外)。ジャーナル (仕様 4) で書き込み前のセクタの内容には戻せるが、ロックの解除後に OS やファイルシステムが行った変更までは戻せないため、元に戻せることを保証しない。
   - ボタン: 「ディスクに書き込む」「キャンセル」。既定のボタンは「キャンセル」。
2. 書き込む範囲に含まれるボリュームを求める。物理ディスクへの書き込みでも、範囲がボリュームに重なる場合は、そのボリュームをロックする必要がある (OS はマウント中のボリュームの範囲への直接の書き込みを拒否する)。パーティションテーブルや未割り当て領域など、どのボリュームにも重ならない範囲はロック不要。
3. ロックの手順 (デバイスを開いたプロセスで行う。補助プロセスで開いたものは補助プロセス、UI のプロセスで直接開いた USB ストレージのボリューム (ENG-29 の仕様 3 の 1) は UI のプロセス):
   1. 該当するボリュームごとに `FSCTL_LOCK_VOLUME` を試す。
   2. ロックできない場合 (開いているファイルがある) は、確認ダイアログで「ボリューム D: は使用中のためロックできません。強制的にディスマウントすると、開いているファイルのデータが失われる可能性があります」と示し、「強制的にディスマウントして書き込む」「キャンセル」を選ばせる。
   3. システムボリューム、ページファイルのあるボリューム、アプリ自身が動いているボリュームはロックもディスマウントもできないため、そこに重なる範囲の書き込みは拒否する (「Windows が使用中のボリュームには書き込めません」)。
4. 書き込みの手順:
   1. 変更範囲をセクタ境界まで広げる (ENG-07 の仕様 6)。
   2. 旧内容をジャーナル (ENG-23 の手順 2) に保存する。ジャーナルの上限を超える場合は ENG-23 の仕様 3 と同じ確認。
   3. セクタ単位で書き込む (近い範囲はまとめる)。
   4. ディスクへの反映を待つ。
   5. ボリュームのロックを解除する (OS が再マウントする)。
   6. ジャーナルを削除する。
5. 書き込み後、旧内容を追加バッファに退避し、Undo で書き込み前の内容に戻せるようにする (ENG-05)。Undo して再び保存すると、旧内容がディスクに書き戻される。
6. 書き込みの途中でキャンセルされた場合、またはエラーが起きた場合は、ジャーナルから書き戻してロックを解除する。
7. 書き込み保護モード (FOR-01) が有効な場合は、保存を無効にする。

**画面**: 確認ダイアログ (2 段階: 書き込みの確認、ロックできない場合のディスマウントの確認)。処理センターの進捗表示。

**巨大ファイル・長時間処理**: 書き込み量 (変更範囲) に比例した時間がかかる。ディスク全体の塗りつぶし (2 TB) などは長時間処理として進捗・残り時間を示す。ジャーナルに旧内容を保存するため、全体の上書きは確認 (仕様 4 の 2) が出る。

**エラー**:

| 状況 | 利用者への見せ方 |
| --- | --- |
| ロックできず、ディスマウントも拒否された | 書き込みを中止し、「ボリューム D: をロックできないため書き込みを中止しました」 |
| 書き込みエラー | ジャーナルから書き戻し、「書き込み中にエラーが発生したため、書き込み前の状態に戻しました (セクタ番号、OS のメッセージ)」 |
| 書き戻しにも失敗 | ジャーナルを残し、「ディスクの一部だけが書き換わっています。次回起動時に復旧できます」 |
| 書き込み禁止のメディア | 「このデバイスは書き込みが禁止されています」 |

**受け入れ基準**:

- [ ] 仮想ディスク (VHD をマウントしたもの) で、マウント中のボリュームの範囲を書き換えて保存すると、ロック → 書き込み → ロック解除が行われ、書き込んだ内容が読み戻せる。
- [ ] 開いているファイルがあるボリュームでは、ディスマウントの確認ダイアログが出る。
- [ ] システムボリュームに重なる範囲の書き込みは拒否される。
- [ ] 書き込み後に Undo して保存すると、書き込み前の内容に戻る。
- [ ] 書き込みの途中で補助プロセスを強制終了した後、起動すると復旧の画面が出て、書き込み前に戻せる。

### ENG-31 ディスクイメージを開く (セクタサイズの指定)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案)。分割 raw・E01 などのイメージ形式とイメージの作成は F5-03 (FOR-20、FOR-21) |
| 呼び出し | ファイル > 詳細を指定して開く… の「ディスクイメージとして開く」、コマンドパレット「ファイル: ディスクイメージとして開く」 |

**概要**: raw 形式のディスクイメージ (`.img`、`.dd`、`.raw`、`.iso` など) を、セクタサイズを指定してディスクと同じように扱う。

**仕様**:

1. セクタサイズを選ぶ: 512 (既定)、2048、4096、または任意 (128〜65,536 の 2 の累乗)。拡張子が `.iso` の場合の既定は 2048。
2. ディスクイメージとして開いたファイルは、データソースの論理セクタサイズが指定値になる。入力式の `sector`、セクタ / LBA 表示 (VIEW-32)、パーティション解析 (FOR-06) がこの値を使う。
3. 既定では長さを固定する (上書きのみ)。「長さの変更を許可する」を選ぶと通常のファイルと同じく挿入・削除できる。
4. 保存はファイルと同じ (ENG-20)。
5. ファイルの長さがセクタサイズの倍数でない場合は、InfoBar で「ファイルの長さがセクタサイズの倍数ではありません (端数 N バイト)」と示す (開くことはできる)。
6. 拡張子 `.img` `.dd` `.raw` `.iso` `.bin` のファイルを通常の「開く」で開いた場合、ディスクイメージとして開き直すかを InfoBar で提案する (設定でオフにできる)。
7. 分割 raw・E01 の解釈は FOR-21 で定める。VHD / VHDX / VMDK の読み込みは未決定 (FOR-21)。

**画面**: 「詳細を指定して開く」のダイアログの項目。ステータスバーにセクタサイズを表示する。

**巨大ファイル・長時間処理**: ファイルを開く (ENG-11) と同じ。

**エラー**: セクタサイズの入力が範囲外または 2 の累乗でない場合は入力欄を赤枠にする。

**受け入れ基準**:

- [ ] `.iso` を「ディスクイメージとして開く」と、セクタサイズの既定が 2048 になる。
- [ ] セクタサイズ 4096 で開いたイメージで、`sector*2` へのジャンプがオフセット 8192 に移動する。
- [ ] 長さ固定で開いたイメージで、挿入が無効になっている。

## 6. プロセスメモリ

### ENG-32 プロセスを開く

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-10 |
| 呼び出し | ファイル > プロセスを開く… (Ctrl+Shift+M)、コマンドパレット「ファイル: プロセスを開く」 |

**概要**: 実行中のプロセスを一覧から選び、その仮想アドレス空間をドキュメントとして開く。オフセットは仮想アドレスと一致させる。プロセス全体のほか、特定のモジュールや領域だけを開くこともできる。

**仕様**:

1. 「プロセスを開く」のダイアログに、プロセスの一覧を表示する。列: アイコン、名前、PID、アーキテクチャ (x64、x86、ARM64、ARM64EC)、ユーザー、ウィンドウのタイトル、使用メモリ (コミットサイズ)。
   - 名前・PID・タイトルで絞り込める。
   - 「自分のプロセスだけ表示」(既定オフ)、「更新」ボタン。
   - 管理者権限なしでは開けないプロセス (昇格したプロセス、システムのプロセス、他のユーザーのプロセス) には盾のアイコンを付け、ツールチップで「開くには管理者権限が必要です」と示す。アプリを管理者として実行している場合は付けない。
   - 保護されたプロセス (PPL など) には錠のアイコンを付け、ツールチップで「Windows によって保護されているため開けません」と示す (管理者権限があっても開けない)。
   - 同じユーザーの、昇格していないプロセスには何も付けない。どの配布形態 (Store 版を含む) でも管理者権限なしで開ける。
2. 開く範囲を選ぶ: 「アドレス空間全体」(既定)、「モジュールを選ぶ」(モジュールの一覧から選ぶ)、「範囲を指定」(開始アドレスと長さ)。
3. 「読み取り専用で開く」(既定オン。設定「プロセスを読み取り専用で開く」で既定を変えられる)。
4. 開き方:
   1. まず UI のプロセスから直接開く (同じユーザーで、昇格していないプロセスは管理者権限なしで開ける)。
   2. アクセスが拒否された場合は、確認ダイアログで「このプロセスを開くには管理者権限が必要です」と示し、「管理者権限で開く」「キャンセル」を選ばせる。「管理者権限で開く」は補助プロセス (ENG-28) を使う。アプリを管理者として実行している場合は、この確認を出さずに同じプロセスで開く (`SeDebugPrivilege` を有効にする。ENG-28 の仕様 10)。補助プロセスも管理者権限も使えない場合 (管理者として実行していない Store 版など) は、この確認の代わりに ENG-28 の仕様 12 の案内ダイアログを出す。
   3. 保護されたプロセス (PPL など) は管理者権限でも開けない。「このプロセスは Windows によって保護されているため開けません」と示す。
5. アドレス空間全体を開いた場合:
   - オフセット = 仮想アドレス (ベースアドレス 0)。
   - 長さ = ユーザーモードのアドレス空間の上限 + 1 (64 bit のプロセスでは OS が報告する最大アドレスまで。32 bit のプロセスでは 4 GiB、大きいアドレスに対応していないものは 2 GiB)。
   - 読めない範囲 (未割り当て・予約のみ・アクセス不可・ガードページ) は領域マップ (ENG-33) で示し、読み込まない。
6. モジュールまたは範囲を開いた場合: オフセット 0 が開始アドレスに対応し、ベースアドレスを開始アドレスにする (表示上のアドレスは仮想アドレスと一致する)。
7. ドキュメントは長さ固定 (ENG-07) で、`IsVolatile`、`HasGaps`。キャッシュの扱いと自動更新は ENG-18。
8. 表示名: 「notepad.exe (PID 1234)」。モジュールの場合は「notepad.exe (PID 1234) - kernel32.dll」。
9. 対象のプロセスが終了した場合は「切断」にし、InfoBar で「プロセスが終了しました」と示す。キャッシュにあるデータは表示し続け、それ以外は読めないものとする。編集はできなくなる (読み取り専用にする)。
10. ガードページ (PAGE_GUARD) は読まない (読むと対象のプロセスで例外が起きるため)。

**画面**: 「プロセスを開く」のダイアログ。

**巨大ファイル・長時間処理**: 開く処理はアドレス空間の大きさに依存しない。広大なアドレス空間の表示 (読めない範囲の折りたたみなど) は 02 で定める。

**エラー**:

| 状況 | 利用者への見せ方 |
| --- | --- |
| アクセスが拒否された | 仕様 4 の 2 |
| 保護されたプロセス | 仕様 4 の 3 |
| プロセスが一覧の表示後に終了した | 「プロセスが見つかりません (終了した可能性があります)」。一覧を更新する |
| 読み込みに失敗した (ページが解放されたなど) | その範囲を読めないものとして表示する (ENG-06) |

**受け入れ基準**:

- [ ] 自分が起動したメモ帳を、UAC の確認なしで開ける (Store 版を含むすべての配布形態)。
- [ ] 管理者として動いているプロセスを開こうとすると確認ダイアログが出て、「管理者権限で開く」で開ける (インストーラ版・ポータブル版)。
- [ ] 管理者として実行していない Store 版で、管理者として動いているプロセスを開こうとすると案内ダイアログ (ENG-28 の仕様 12) が出る。
- [ ] 一覧で、管理者として動いているプロセスに盾のアイコン、保護されたプロセスに錠のアイコンが付く。
- [ ] 開いたプロセスで、モジュールのベースアドレスにジャンプすると `MZ` が表示される。
- [ ] ガードページを含むスレッドのスタックを表示しても、対象のプロセスが異常終了しない。
- [ ] 対象のプロセスを終了すると InfoBar が出て、ドキュメントが読み取り専用になる。

### ENG-33 メモリ領域・モジュールの一覧

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-10 |
| 呼び出し | プロセスメモリのドキュメントで自動表示されるパネル「メモリマップ」。表示 > パネル > メモリマップ、コマンドパレット「表示: メモリマップ」「移動: 次のメモリ領域」「移動: 前のメモリ領域」、ショートカットは既定なし |

**概要**: プロセスのメモリ領域 (割り当て状態、保護属性、種類、対応するモジュール・ファイル) とモジュールの一覧をパネルに表示し、選んだ領域にジャンプできるようにする。読めない範囲を区別して示す。

**仕様**:

1. 「メモリマップ」パネルに 2 つのタブを置く。
   - 領域: 開始アドレス、終了アドレス、サイズ、状態 (コミット / 予約 / 空き)、保護属性 (R、RW、RX、RWX、WC (書き込み時コピー)、アクセス不可、ガード)、種類 (イメージ / マップ / プライベート)、モジュール名またはマップしたファイル名。
   - モジュール: 名前、ベースアドレス、サイズ、パス。
2. 一覧は並べ替え・絞り込み (名前、保護属性、状態) ができる。既定では「空き」の領域を隠す (表示の切り替えあり)。
3. 行をダブルクリックまたは Enter で、その領域の先頭にジャンプする。右クリックメニュー: 「領域を選択」「この領域を新しいタブで開く」(ENG-39)「アドレスをコピー」。
4. カーソルのある領域を一覧で強調し、ステータスバーにも領域の情報 (モジュール名 + オフセット、保護属性) を出す。例: `kernel32.dll+0x1A2B0 (RX)`。
5. 「次のメモリ領域」「前のメモリ領域」コマンドで、読める領域の先頭へ移動する。
6. 一覧はパネルが表示されている間、5 秒ごと (設定で 1〜60 秒、またはオフ) と、再読み込み (ENG-18) のときに更新する。更新しても選択とスクロール位置を保つ。
7. エンジンは領域マップを使い、読めない範囲を読み込まずに「未割り当て」(空き・予約) または「アクセス不可」(アクセス不可・ガード) の状態で返す。表示 (02) はこの 2 つを読み込みエラーと区別して示す。
8. スレッドのスタック・ヒープの領域への名前付けは未決定。

**画面**: 下部パネル「メモリマップ」(00 の 9 章のパネル)。結果一覧の共通部品 (00 の 9 章) を使う。

**巨大ファイル・長時間処理**: 領域の数は数万になりうる。一覧は仮想化して表示する。取得は 100 ms 以内に終わる想定で、それを超える場合もバックグラウンドで取得し UI を止めない。

**エラー**: 領域の一覧を取得できない場合は、パネルに「メモリ領域の一覧を取得できませんでした (理由)」と表示する。ドキュメントは開いたままにする。

**受け入れ基準**:

- [ ] プロセスを開くとメモリマップのパネルが表示され、モジュールのタブに実行ファイルと `ntdll.dll` がある。
- [ ] 領域の行をダブルクリックすると、その開始アドレスにカーソルが移動する。
- [ ] 「次のメモリ領域」で、読めない範囲を飛ばして次の読める領域の先頭に移動する。
- [ ] 1 万以上の領域を持つプロセスでも、パネルのスクロールが 60 fps を保つ。

### ENG-34 プロセスメモリへの書き込み

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-10 |
| 呼び出し | プロセスメモリのドキュメントで保存 (Ctrl+S)。即時書き込みモードはタブの右クリックメニュー「即時書き込み」とコマンドパレット「ファイル: 即時書き込みの切り替え」 |

**概要**: プロセスメモリの変更範囲を、対象のプロセスに書き込む。既定では保存時にまとめて書き込み、設定により編集のたびに即座に書き込むこともできる。

**仕様**:

1. 既定 (保存時に書き込む): 保存 (Ctrl+S) で変更範囲を書き込む。最初の保存のときだけ、確認ダイアログで「プロセス notepad.exe (PID 1234) のメモリに N バイト書き込みます。プロセスが異常終了する可能性があります」と示し、「書き込む」「キャンセル」を選ばせる (同じドキュメントでは 2 回目以降は確認しない)。
2. 即時書き込みモード (ドキュメントごと、既定オフ): 編集のたびに、その変更をすぐに書き込む。切り替え時に確認ダイアログを出す。即時書き込みモードでも Undo できる (Undo の内容を書き込む)。
3. 書き込み先のページが書き込み不可 (読み取り専用・実行専用) の場合:
   - 確認ダイアログで「書き込み先のページが読み取り専用です (保護属性)。一時的に書き込み可能にして書き込みますか」と示し、「保護を一時的に変更して書き込む」「書き込まない」を選ばせる。
   - 選んだ場合は保護属性を変更して書き込み、元の保護属性に戻す。
4. 書き込む前に旧内容を読み、追加バッファに退避する (Undo のため。ENG-05)。プロセスメモリはジャーナル (ENG-23) を使わない (プロセスの終了で意味を失うため)。
5. 書き込みは範囲ごとに行い、一部の範囲が失敗しても他の範囲は書き込む。失敗した範囲は「変更あり」のまま残す。
6. 書き込みは対象のプロセスを停止せずに行う。書き込みの原子性 (他のスレッドが途中の値を読まないこと) は保証しない。
7. 未割り当ての範囲への書き込み (編集) はできない。読めない範囲で入力しようとした場合は「この範囲は割り当てられていないため編集できません」と示す。

**画面**: 確認ダイアログ。即時書き込みモードの間は、ステータスバーに「即時書き込み」と表示する。

**巨大ファイル・長時間処理**: 書き込み量に比例した時間。1 MiB 単位で書き込む。

**エラー**: 書き込みに失敗した範囲の一覧 (アドレス、長さ、理由) を示す。プロセスが終了していた場合は「プロセスが終了したため書き込めませんでした」。

**受け入れ基準**:

- [ ] テスト用のプロセスの変数のアドレスに値を書き込んで保存すると、そのプロセスが新しい値を読む。
- [ ] 読み取り専用のページへの書き込みで確認ダイアログが出て、書き込み後に保護属性が元に戻っている。
- [ ] 即時書き込みモードで入力すると、保存しなくても対象のプロセスに反映される。Undo すると元の値に戻る。
- [ ] 書き込めない範囲を含む保存で、失敗した範囲だけが「変更あり」で残る。

### ENG-35 プロセスのスナップショットとダンプ保存

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | プロセスメモリのドキュメントで、ファイル > エクスポート > スナップショットを保存… / ミニダンプとして保存…、コマンドパレット「ファイル: プロセスのスナップショットを保存」「ファイル: ミニダンプとして保存」 |

**概要**: プロセスの読める領域の内容を、その時点のスナップショットとしてファイルに保存する。保存したスナップショットは、アドレスと領域の情報を保ったまま読み取り専用で開け、別の時点のスナップショットやライブのプロセスと比較できる。スナップショットの作成と保存 (ファイル形式を含む) はこの機能が主担当で、比較は ANA-09 が定める (00 の 1.1)。

**仕様**:

1. 対象を選ぶ: 「読めるすべての領域」(既定)、「選んだ領域・モジュール」(メモリマップのパネルで選んだもの)、「書き込み可能な領域だけ」。
2. 「取得中は対象のプロセスを一時停止する」(既定オフ)。オンにすると、取得の間だけ対象のプロセスのスレッドを停止し、一貫した内容を得る。停止できない場合は警告して続ける。
3. スナップショットのファイル形式 (`.hexsnap`):

   ```text
   [マジック "HXSNAP01" 8 バイト][メタデータの長さ u32][メタデータ (UTF-8 の JSON)][データ]
   ```

   - メタデータ: プロセス名、PID、アーキテクチャ、取得日時 (UTC)、領域の一覧 (開始アドレス、サイズ、保護属性、種類、モジュール名、ファイル内の位置)、モジュールの一覧。
   - データ: 領域の内容を順に置く。各領域は 4 KiB 境界から始める。
   - 読めなかったページはメタデータに記録し、データには含めない。
4. スナップショットを開くと、アドレス空間全体 (ENG-32 の仕様 5 と同じ形) の読み取り専用のドキュメントになり、メモリマップのパネル (ENG-33) も使える。
5. スナップショットどうし、またはスナップショットとライブのプロセスの比較は ANA-09 で行う。ANA-09 の「スナップショットを作成」は、この機能の作成処理 (仕様 1〜3) を使う。
6. ミニダンプとして保存: Windows のミニダンプ形式 (全メモリを含む) で保存する。デバッガ (WinDbg、Visual Studio) で開くためのもの。ミニダンプを開く機能は ENG-36 の仕様 4。

**画面**: 保存のダイアログ (対象の選択、一時停止の選択、保存先)。

**巨大ファイル・長時間処理**: 数 GB になりうる。長時間処理として進捗を示し、キャンセルできる (キャンセル時は途中のファイルを削除する)。保存先の空き容量を確認する (ENG-25)。

**エラー**: 一部の領域が読めなかった場合は、完了時に「N 個の領域 (合計 M バイト) を読めませんでした」と示す (保存は完了させる)。プロセスが取得中に終了した場合は中止し、途中のファイルを削除する。

**受け入れ基準**:

- [ ] スナップショットを保存して開くと、元のプロセスと同じアドレスに同じ内容が表示される。
- [ ] 値を変えた前後の 2 つのスナップショットを比較すると、変えたアドレスが差分として出る。
- [ ] ミニダンプとして保存したファイルを WinDbg で開ける。
- [ ] 取得中にキャンセルすると、途中のファイルが残らない。

### ENG-36 物理メモリ (RAM) とメモリダンプ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 5 提案) |
| 呼び出し | ファイル > 詳細を指定して開く… の形式「メモリダンプ」、コマンドパレット「ファイル: メモリダンプを開く」 |

**概要**: 物理メモリを直接読むことは、Windows ではカーネルドライバなしにはできない。このため、物理メモリを読むドライバは作らない方針とし、代わりに他のツールで取得したメモリダンプ (物理メモリのイメージ、クラッシュダンプ、ミニダンプ) を開いて、物理アドレスまたは仮想アドレスで読めるようにする。

**仕様**:

1. 制約: 一般のアプリから物理メモリ (`\Device\PhysicalMemory`) は開けない。読むには署名されたカーネルドライバが必要で、メモリ整合性 (HVCI) が有効な環境では読み込めない場合がある。ドライバの開発・署名・配布の負担と、攻撃に悪用されるリスクが大きいため、物理メモリを直接読む機能は実装しない (将来再検討する場合も「未決定」として扱う)。
2. 物理メモリのイメージ (raw 形式。WinPmem などで取得した `.raw` `.mem` `.bin`): ディスクイメージと同様にファイルとして開き、オフセットを物理アドレスとして扱う。読み取り専用。
3. Windows のクラッシュダンプ (`MEMORY.DMP`、完全ダンプ・カーネルダンプ): ダンプの物理メモリの範囲の情報を読み、物理アドレス空間のドキュメントとして開く。ダンプに含まれない物理ページは「未割り当て」として示す。読み取り専用。
4. ミニダンプ (ENG-35 のミニダンプ、他のツールのもの): メモリの範囲の一覧を読み、プロセスの仮想アドレス空間のドキュメントとして開く (ENG-32 と同じ形、メモリマップのパネルも使える)。読み取り専用。
5. ダンプの形式は、ファイルの先頭のシグネチャで判定する。判定できない場合は raw として扱う。
6. 圧縮されたダンプ (カーネルの圧縮形式など) への対応は未決定。

**画面**: 「詳細を指定して開く」の形式の選択肢。ダンプを開いたときに、ダンプの種類と取得日時をドキュメントのプロパティに表示する。

**巨大ファイル・長時間処理**: ダンプのヘッダと範囲の一覧だけを読み、全体を走査しない。64 GB のダンプも 1 秒以内に開く。

**エラー**: ダンプの形式が壊れている場合は「メモリダンプの形式を読めませんでした。raw として開きますか」と示し、「raw として開く」「キャンセル」を選ばせる。

**受け入れ基準**:

- [ ] Windows の完全メモリダンプを開くと、ダンプに含まれる物理アドレスの範囲だけが読め、他は「未割り当て」になる。
- [ ] ENG-35 で保存したミニダンプを開くと、元のプロセスと同じアドレスに同じ内容が表示される。
- [ ] 64 GB のダンプを 1 秒以内に開ける。

## 7. その他のデータソース

### ENG-37 NTFS 代替データストリーム

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-09 |
| 呼び出し | 代替データストリームの管理画面 (TOOL-21) の「開く」「作成」、コマンドパレット「ファイル: 代替データストリームを開く」(TOOL-21 の管理画面を開く)。ショートカットは既定なし |

**概要**: NTFS (と ReFS) のファイルが持つ代替データストリーム (ADS) を、ドキュメントとして開いて編集・保存する。ストリームの一覧・作成・名前の変更・削除・書き出し・読み込みの管理画面は TOOL-21 が定める (00 の 1.1)。

**仕様**:

1. 開く: TOOL-21 で選んだストリームを新しいタブで開く。表示名は `data.bin:Zone.Identifier`。データソースはストリームのパス (`ファイル名:ストリーム名`) を開いたもので、通常のファイルと同じく編集できる。
2. ストリームの保存:
   - 長さが変わらない場合: その場保存 (ENG-23)。
   - 長さが変わる場合: ストリームでは置き換え (`ReplaceFile`) が使えないため、旧内容をジャーナルに保存してから、ストリームの内容を書き直して長さを合わせる。ジャーナルの上限 (ENG-23 の仕様 3) を超える場合は同じ確認を出す。
3. 設定「代替データストリームがあるファイルを開いたときに知らせる」(既定オフ) をオンにすると、メイン以外のストリームがあるファイルを開いたときに InfoBar で「このファイルには代替データストリームが N 個あります」と示し、「一覧を表示」ボタン (TOOL-21 を開く) を付ける。
4. 安全な保存 (ENG-22) でメインのストリームを保存しても、ADS は失われない。
5. ADS に対応しないファイルシステム (FAT、exFAT など) のファイルでは、このコマンドを無効にし、ツールチップに理由を示す。ReFS ではストリームのサイズに OS の上限があり、それを超える保存はエラーにする。

**画面**: タブ (表示名にストリーム名を含める)。管理画面は TOOL-21。

**巨大ファイル・長時間処理**: 大きなストリームはファイルと同じく即座に開く。長さが変わる保存はストリームのサイズに比例する。

**エラー**: ストリームを開けない場合は OS の理由を示す。ReFS の上限を超える保存は「ReFS では代替データストリームの大きさに上限があるため保存できません」と示す。

**受け入れ基準**:

- [ ] インターネットからダウンロードしたファイルの `Zone.Identifier` を開いて、内容を表示できる。
- [ ] ストリームに書き込んで保存し、`dir /r` で同じサイズが表示される。
- [ ] メインのストリームに挿入して安全な保存をした後も、ADS が残っている。
- [ ] FAT32 のドライブのファイルではコマンドが無効になる。

### ENG-38 Intel HEX / S-record / Base64 を開く

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案)。インポート・エクスポート (F2-11、TOOL-04〜07) と同じ変換処理を使う |
| 呼び出し | ファイル > 詳細を指定して開く… の形式、コマンドパレット「ファイル: Intel HEX として開く」「ファイル: S-record として開く」「ファイル: Base64 として開く」、自動判定時の InfoBar |

**概要**: Intel HEX、Motorola S-record、Base64 のテキストファイルを、デコードしたバイナリのドキュメントとして開いて編集できるようにする。この機能が「ドキュメントとして開く」の主担当で、各形式の仕様は TOOL-05〜07、元の形式で保存する規則は TOOL-11 が定める (00 の 1.1)。

**仕様**:

1. 判定: 拡張子 (`.hex` `.ihx` `.ihex` → Intel HEX、`.s19` `.s28` `.s37` `.srec` `.mot` `.mhx` → S-record、`.b64` → Base64) のファイルを「開く」で開くと、形式「自動」ではデコードして開く。タブの InfoBar に「Intel HEX をデコードして表示しています」と「テキストのまま開く」ボタンを出す。拡張子が違っても先頭 64 KiB の内容から判定できた場合は、InfoBar で「Intel HEX として開き直す」を提案する。
2. デコード:
   - 開くときにバックグラウンドで全体をデコードし、結果を一時ファイル (追加バッファの置き場所) に書く。デコードが終わった範囲から表示できる。デコード中はドキュメントを読み取り専用にし、完了したら編集できるようにする。
   - 対応するレコードと解釈は、Intel HEX は TOOL-05、S-record は TOOL-06、Base64 は TOOL-07 のインポートと同じ。
   - デコード時に、保存で使う元の形式の設定 (1 レコードのデータ長、アドレスの種類、ヘッダ、改行コードなど。TOOL-11 の仕様 1) を記録する。
3. アドレス: Intel HEX と S-record では、最小のアドレスをベースアドレスとし、最大のアドレス + 1 までをドキュメントにする (最大 4 GiB)。データのないアドレス (隙間) は「データなし」の状態として示し (表示は 02)、値としては塗りつぶしの値 (既定 FF、設定可能) を返す。
4. 編集: Intel HEX と S-record は長さ固定 (上書きのみ) とする。隙間に書き込むと、その範囲がデータありになる。Base64 は長さを変えられる。
5. 保存: 元の形式に変換して安全な保存 (ENG-22) で書き出す。変換の規則 (保つ設定、隙間の扱い、失われる情報の確認) は TOOL-11。
6. チェックサムの誤り・形式の誤りのある行は、開くときに一覧にして、結果一覧 (00 の 9 章) に「行番号、内容、理由」を出す。誤りがある場合も開けるが、読み取り専用にし、InfoBar で「N 行に誤りがあります」と「編集を許可」ボタンを示す。
7. 同じアドレスに複数のレコードがある (重なる) 場合は、後の行の内容を使い、誤りの一覧に「アドレスの重なり」として出す。
8. Base32、Ascii85、UUEncode、Quoted-Printable などその他のエンコードは、インポート (TOOL-04、TOOL-07) で扱い、この機能の対象にしない。

**画面**: 「詳細を指定して開く」の形式の選択肢、InfoBar、誤りの一覧 (下部パネル)。ステータスバーに形式 (「Intel HEX」など) を表示する。

**巨大ファイル・長時間処理**: デコード・エンコードはファイルサイズに比例する長時間処理 (進捗・キャンセルあり)。デコードの結果は一時ファイルに置き、メモリに全体を持たない。レコードの位置の索引は 64 KiB のデータごとに 1 つだけ持ち、64 MiB を超えたら一時ファイルに退避する。

**エラー**: 形式として全く読めない場合は「Intel HEX として読めませんでした (最初の誤り: 行 N)」と示し、「バイナリのまま開く」ボタンを付ける。アドレスが 4 GiB を超える場合 (S-record の範囲外など) はその行を誤りとして扱う。

**受け入れ基準**:

- [ ] Intel HEX のファイルを開くと、レコードのアドレスにデータが表示され、隙間は「データなし」として区別される。
- [ ] チェックサムの誤りがある行が一覧に出る。
- [ ] 1 GB の Base64 ファイルを開いても、メモリ使用量が上限を超えず、デコード中も先頭が表示される。

### ENG-39 選択範囲・ブックマークを新しいタブで開く

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 選択範囲の右クリックメニュー「新しいタブで開く」、ブックマーク一覧 (05) の右クリックメニュー「新しいタブで開く」、メモリマップ (ENG-33) の右クリックメニュー、ファイル > 選択範囲を新しいタブで開く、コマンドパレット「ファイル: 選択範囲を新しいタブで開く」「ファイル: 選択範囲をコピーとして新しいタブで開く」、ショートカットは既定なし |

**概要**: ドキュメントの一部の範囲を、新しいタブで独立したドキュメントのように扱う。既定では親のドキュメントと連動する表示 (連動ビュー) で、編集は親に反映される。親と切り離したコピーとして開くこともできる。

**仕様**:

1. 連動ビュー (既定):
   - 親のドキュメントの範囲 [開始, 開始 + 長さ) を表示する。オフセット 0 が開始位置に対応し、ベースアドレスは親での開始位置のアドレスとする。
   - 長さ固定 (上書きのみ)。編集は親のドキュメントの編集として記録され、親の Undo 履歴に入る。親でも子でも Undo できる (同じ履歴)。
   - 親で範囲より前に挿入・削除をした場合、子の範囲は親のデータに追従して移動する (範囲は親のピースに対する位置として持つ)。親で範囲の中身を挿入・削除した場合は、子の長さを固定したまま、範囲の内容が変わる。
   - 範囲が親から完全に削除された場合、子のタブは「切断」になり、InfoBar で「元の範囲が削除されました」と示す。
   - 保存は親のドキュメントを保存する。
   - タブの名前は `data.bin [0x1000–0x1FFF]`。親のタブを閉じると子のタブも閉じる (親の未保存の確認は親について 1 回だけ)。
2. コピーとして開く:
   - 範囲の内容を持つ無題のドキュメントを作る。データのコピーはせず、ピースの参照で作る (即座に開く)。ベースアドレスは 0。
   - 長さを変えられ、親とは独立している。保存は「名前を付けて保存」。
   - 親のデータソースのファイルが保存などで変わっても、内容は開いたときのまま (親が参照していた元データを保持する)。
3. ブックマークから開く場合は、ブックマークの範囲 (範囲を持たないブックマークは開けない) を使い、タブの名前にブックマークの名前を使う。
4. 構造体テンプレート (07) の「仮想セクション」(展開したデータの解析) も、この仕組みの上で、変換後のデータを持つ読み取り専用の子ドキュメントとして開く (詳細は 07)。

**画面**: タブ。連動ビューのタブには親とつながっていることを示すアイコンを付け、ツールチップに親のドキュメント名と範囲を示す。

**巨大ファイル・長時間処理**: どちらの開き方も範囲の大きさに関係なく 100 ms 以内に開く。

**エラー**: 選択範囲がない (長さ 0) 場合はコマンドを無効にする。マルチ選択の場合は、最初の範囲を開くか、範囲ごとにタブを開くかを確認する (10 個を超える場合は確認ダイアログで件数を示す)。

**受け入れ基準**:

- [ ] 10 GB のファイルの 5 GB の範囲を連動ビューで開くと、100 ms 以内に開き、表示上のアドレスが親と一致する。
- [ ] 連動ビューで 1 バイト変えると親の同じ位置が変わり、親で Ctrl+Z を押すと子の表示も戻る。
- [ ] 親で範囲より前に 100 バイト挿入しても、連動ビューの内容が変わらない (範囲が追従する)。
- [ ] コピーとして開いたドキュメントに挿入しても、親は変わらない。

### ENG-40 リモート: GDB サーバー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | ファイル > リモートに接続 > GDB サーバー…、コマンドパレット「ファイル: GDB サーバーに接続」 |

**概要**: GDB のリモートシリアルプロトコル (RSP) で GDB サーバー (gdbserver、QEMU、OpenOCD、組み込み機器のデバッグプローブなど) に TCP で接続し、対象のメモリをドキュメントとして読み書きする。

**仕様**:

1. 接続ダイアログ: ホスト (既定 `localhost`)、ポート (既定 1234)、アドレスの幅 (32 bit / 64 bit。既定 64 bit)、「読み取り専用で開く」(既定オン)。
2. ドキュメントはアドレス空間全体 (アドレスの幅に応じて 4 GiB または 2^63 − 1 バイトまで) を長さ固定で表す。オフセット = 対象のアドレス。
3. 読み込みは `m` パケット、書き込みは `M` (または対象が対応していれば `X`) パケットを使う。1 回の大きさは対象が報告するパケットサイズ (`qSupported` の `PacketSize`) に合わせる。
4. 対象がエラーを返した範囲は「アクセス不可」として示す (ENG-06 の読めない範囲)。
5. データは変わりうる (`IsVolatile`)。再読み込みと自動更新は ENG-18。
6. 書き込みは保存時 (ENG-34 と同じ確認)。即時書き込みモードも ENG-34 と同じ。
7. 対象の実行の停止・再開・ブレークポイントなど、デバッガとしての操作はこの機能の対象にしない。
8. 1 つの要求の待ち時間の上限は 5 秒 (設定で変更可)。接続が切れた場合は「切断」にし、「再接続」ボタンを付ける。未保存の変更は残る。
9. 接続先は利用者が指定したホストだけで、利用者が接続の操作をしたときだけ通信する (00 の 11.4 の「利用者が接続先を指定する機能」)。アプリの起動時やセッションの復元 (UI-31) で自動的に接続しない (復元したタブには「接続」ボタンを出す)。接続履歴 (ホストとポート) は最近使ったファイル (ENG-16) に記録しない (設定で記録できる。未決定)。

**画面**: 接続ダイアログ。ステータスバーに接続先と接続状態を表示する。

**巨大ファイル・長時間処理**: 読み込みは表示範囲だけ。全体の検索などはネットワークの速度に依存する長時間処理になる。

**エラー**: 接続できない場合は「GDB サーバーに接続できませんでした (ホスト:ポート、理由)」。プロトコルの応答が不正な場合は切断し、「GDB サーバーの応答を解釈できませんでした」。

**受け入れ基準**:

- [ ] QEMU の GDB サーバーに接続し、ゲストのメモリを表示できる。
- [ ] 書き込みを許可して保存すると、`x` コマンド (GDB) で同じ値が読める。
- [ ] 接続先を停止すると「切断」になり、再起動後に「再接続」で読み込みを再開できる。

### ENG-41 リモート: SSH / SFTP

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | ファイル > リモートに接続 > SFTP…、コマンドパレット「ファイル: SFTP で開く」、最近使ったファイル (ENG-16) |

**概要**: SSH 上の SFTP でリモートのファイルを開き、ローカルのファイルと同じように表示・編集・保存する。ファイル全体をダウンロードせず、必要な範囲だけを読む。

**仕様**:

1. 接続ダイアログ: ホスト、ポート (既定 22)、ユーザー名、認証方式 (パスワード / 鍵ファイル / SSH エージェント (Windows の OpenSSH エージェント、Pageant))。接続後にリモートのファイルを選ぶ画面 (フォルダの一覧) を出す。
2. ホスト鍵の確認: 初めて接続するホストでは、鍵の種類と SHA-256 のフィンガープリントを示し、「信頼して接続」「キャンセル」を選ばせる。信頼したホスト鍵はアプリの設定フォルダに保存する。以前と違う鍵の場合は警告し、既定では接続しない。
3. パスワードとパスフレーズは、利用者が「保存する」を選んだ場合だけ Windows の資格情報マネージャーに保存する。設定ファイルには保存しない。
4. 読み込みは SFTP の位置指定の読み込みを使い、ブロックキャッシュ (ENG-06) を通す。長さはリモートのファイルサイズ。ドキュメントはローカルのファイルと同じく長さを変えられる (`CanResize`)。
5. 保存:
   - 長さが変わらず、データがずれていない場合: 変更範囲だけを書き込む (ジャーナルは使わない。確認ダイアログで「途中で接続が切れると、リモートのファイルの一部だけが書き換わる可能性があります」と示す。設定で確認を省略できる)。
   - それ以外: 同じフォルダに一時ファイルを作って全体を書き出し、名前の変更で置き換える (サーバーが POSIX の名前変更の拡張に対応していれば上書きの名前変更、なければ退避 → 置き換え → 削除の手順)。
6. 外部変更の検知: ファイルのサイズと更新日時を、ウィンドウのアクティブ化時と 30 秒ごとに確認する (ENG-19 と同じ扱い)。書き込みの禁止 (ENG-15) はできない。
7. 接続が切れた場合は「切断」にし、自動で 1 回だけ再接続を試みる。失敗したら InfoBar で「再接続」ボタンを示す。未保存の変更は残る (追加バッファはローカルにある)。
8. 最近使ったファイルには `sftp://ユーザー@ホスト:ポート/パス` の形で記録する (パスワードは含めない)。
9. 通信は 00 の 11.4 の「利用者が接続先を指定する機能」として、利用者が接続の操作 (接続ダイアログ、最近使ったファイルから開く) をしたときと、その接続を使っている間 (読み込み、保存、仕様 6 の確認、仕様 7 の再接続) だけ行う。アプリの起動時やセッションの復元 (UI-31) で自動的に接続しない (復元したタブには「接続」ボタンを出す)。

**画面**: 接続ダイアログ、リモートのファイルの選択画面、ホスト鍵の確認ダイアログ。タブのツールチップにリモートのパスを示す。

**巨大ファイル・長時間処理**: 開く処理はファイルサイズに依存しない。全体の書き出し (長さが変わる保存) はネットワークの速度に依存する長時間処理。

**エラー**: 認証の失敗、ホスト鍵の不一致、権限の不足、接続の切断を、それぞれ区別して示す。

**受け入れ基準**:

- [ ] SFTP サーバー上の 10 GB のファイルを開いて、1 秒以内に先頭が表示される (ローカルネットワーク)。
- [ ] 1 バイト変えて保存すると、リモートのファイルのその位置だけが変わる。
- [ ] ホスト鍵が変わったサーバーに接続しようとすると警告が出て、既定では接続しない。
- [ ] パスワードを保存しない設定で、設定フォルダにパスワードが残っていない。

### ENG-42 リモート: UDP の受信

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | ファイル > リモートに接続 > UDP を受信…、コマンドパレット「ファイル: UDP を受信」 |

**概要**: 指定した UDP ポートで受信したデータグラムを、末尾に追記していく読み取り専用のドキュメントとして表示する。組み込み機器やネットワークのデバッグで、受信したバイト列をその場で確認するために使う。

**仕様**:

1. 設定: 待ち受けるアドレス (既定 `127.0.0.1`。すべてのアドレス `0.0.0.0` / `::` も選べる)、ポート (1〜65535。既定なし、入力必須)、保持する上限 (既定 64 MiB、1 MiB〜エンジンのメモリ上限まで。超えた分は一時ファイル)。
2. 受信したデータグラムを受信順に末尾へ追記する。各データグラムの開始位置・長さ・受信時刻・送信元を記録し、パケットの一覧 (結果一覧の共通部品) に表示する。一覧の行を選ぶとその位置にジャンプする。表示上のパケットの区切り線は 02 で定める。
3. ドキュメントは読み取り専用 (ENG-14)。長さは受信に応じて増える。カーソルが末尾にある場合は末尾に追従してスクロールする (設定でオフにできる)。
4. 上限に達したら受信の記録を止め、InfoBar で「上限 (64 MiB) に達したため記録を停止しました」と示す。「古いデータを捨てて続ける」を選ぶと、先頭から捨てて続ける (その場合はベースアドレスを捨てたバイト数だけ進め、表示上のアドレスを受信開始からの通算の位置に保つ)。
5. 「一時停止」「再開」「消去」のボタンをパネルに置く。
6. 「名前を付けて保存」で、受信したデータを 1 つのファイルとして保存できる。パケットの一覧は結果一覧のエクスポート (CSV / JSON) で保存できる。
7. `127.0.0.1` 以外で待ち受ける場合は、Windows ファイアウォールの確認が出ることがあることを、開始前に示す。
8. 受信だけを行い、送信はしない。待ち受けは利用者が開始したときだけ行い (00 の 11.4 の「利用者が接続先を指定する機能」)、アプリの起動時やセッションの復元 (UI-31) で自動的に再開しない。

**画面**: 開始ダイアログ、下部パネル「パケット」(一覧と、一時停止・再開・消去のボタン)。ステータスバーに受信数と受信量を表示する。

**巨大ファイル・長時間処理**: 受信は上限の範囲で行い、メモリの上限を超えない。

**エラー**: ポートが使用中の場合は「ポート N は他のアプリが使用中です」。権限やファイアウォールで受信できない場合は OS の理由を示す。

**受け入れ基準**:

- [ ] ポート 9000 で待ち受け、別のプロセスから 3 つのデータグラムを送ると、3 つが順に追記され、パケットの一覧に 3 行出る。
- [ ] 上限に達すると記録が止まり、InfoBar が出る。
- [ ] 「古いデータを捨てて続ける」を選んだ後も、表示上のアドレスが受信開始からの通算の位置になっている。

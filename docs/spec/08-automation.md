# 機能仕様書: 自動化 (スクリプト・マクロ・プラグイン・コマンドライン)

スクリプト (JavaScript / C#)、自動化 API、スクリプトエディタとデバッガ、マクロ、プラグイン、コマンドライン、外部からの自動操作を定める。共通の書式・用語・入力式・ショートカットは [00-overview.md](00-overview.md) に従う。

- 対象のロードマップ項目: F3-05 (スクリプト)、F3-06 (マクロ記録)、F3-07 (プラグイン)、F3-08 (コマンドライン)。
- ロードマップにない機能 (調査 [../research/feature-survey.md](../research/feature-survey.md) の 2.14 などから追加したもの) は「追加 (フェーズ N 提案)」と記す。
- 関連する文書: データ演算・パッチ・Copy As は [03-editing.md](03-editing.md)、検索は [04-search.md](04-search.md)、インスペクタ・ブックマークは [05-inspector-and-annotations.md](05-inspector-and-annotations.md)、ハッシュ・比較は [06-analysis.md](06-analysis.md)、テンプレートは [07-templates.md](07-templates.md)、ショートカットの変更と設定画面は [09-ui-and-settings.md](09-ui-and-settings.md)、配布物の構成は [10-packaging.md](10-packaging.md)、インポート・エクスポート形式は [11-tools.md](11-tools.md)。

## 基本方針

| 項目 | 決定事項 |
| --- | --- |
| スクリプト言語 | JavaScript (Jint で実行) と C# (C# スクリプト `.csx` と C# プラグイン DLL) |
| API | 言語に依存しない 1 つのオブジェクトモデルを定義し、JavaScript と C# の両方に同じ形で公開する。名前の付け方だけ言語の慣習に合わせる (JavaScript は `camelCase`、C# は `PascalCase`) |
| 速度 | データ量に比例する処理 (範囲の XOR、検索、ハッシュ、コピーなど) は API 側の一括処理として C# で実行する。スクリプトの 1 バイトずつのループに頼らない |
| 安全性 | JavaScript はサンドボックス内で動き、許可された API だけを使える。C# スクリプトとプラグインは PC 上で何でもできる完全信頼のコードとして扱い、初回に利用者の許可を求める |
| 実行場所 | スクリプトは UI スレッドとは別の専用スレッドで動く。UI を固めない |

## スクリプトの基盤

### AUTO-01 スクリプトの実行

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05 |
| 呼び出し | メニュー「ツール > スクリプト > スクリプトを実行...」、F5 (グローバルの「スクリプトを実行」、コードエディタの「実行 / 続行」。00 の 8.2・8.5)、コマンドパレット「スクリプト: 実行」、スクリプト一覧パネルの右クリック「実行」 |

**概要**: JavaScript ファイル (`.js`、`.mjs`) と C# スクリプト (`.csx`) を、開いているドキュメントに対して実行する。実行中の状態は処理センターに表示し、いつでも停止できる。

**仕様**:

1. 拡張子で言語を決める。`.js` と `.mjs` は JavaScript (AUTO-02)、`.csx` は C# スクリプト (AUTO-03)。それ以外の拡張子はエラーにする。
2. F5 の動作は次の順で決める。
   1. フォーカスがスクリプトエディタ (AUTO-20。00 の 8.5 のコードエディタの有効範囲) にある場合: デバッガで一時停止中なら続行する (AUTO-21)。そうでなければ、そのスクリプトを実行する (未保存でもエディタの内容で実行する)。
   2. フォーカスがスクリプト一覧パネル (AUTO-19) にある場合: 選択中のスクリプトを実行する。
   3. それ以外: 直前に実行したスクリプトを再実行する。まだ実行したことがない場合はファイル選択ダイアログを開く。
3. 実行対象のドキュメントは、実行開始時のアクティブなドキュメント (`app.activeDocument`) とする。ドキュメントがなくても実行できる (`app.activeDocument` は `null`)。
4. 実行前に信頼の確認 (AUTO-34) を行う。許可されなければ実行しない。
5. スクリプトにパラメータの宣言 (AUTO-26) がある場合、実行前にパラメータ入力ダイアログを出す。
6. 実行中は次のとおりにする。
   - 処理センターに「スクリプト: 名前」として登録し、経過時間・進捗 (スクリプトが報告した場合)・停止ボタンを表示する。
   - スクリプトが書き込みを行っているドキュメントは、利用者の編集を受け付けない (読み取りは可能)。エディタ上部に InfoBar「スクリプト「名前」を実行中です」と停止ボタンを出す。他のドキュメントは通常どおり編集できる。
   - 同時に実行できるスクリプトは、既定で 4 本まで (設定で 1〜16)。同じドキュメントに書き込む 2 本目のスクリプトは、1 本目が終わるまで待機する。
7. スクリプトによる編集は、既定で 1 回の実行を 1 つの Undo 単位 (名前「スクリプト: 名前」) にまとめる。スクリプトが `beginUndoGroup` (AUTO-08) で明示的に区切った場合はその単位に従う。
8. 停止は次の 2 段階で行う。
   1. 停止ボタン・Esc (処理センターにフォーカスがある場合)・`app.stop` の呼び出しで、キャンセル要求を出す (AUTO-05)。
   2. 3 秒たっても終わらない場合、JavaScript は実行を強制的に中断する。C# スクリプトは強制中断できないため、「応答しません」と表示し続ける (AUTO-03 の制限)。
9. スクリプトが例外で終了した場合も、それまでの編集は Undo 単位としてドキュメントに残る。利用者はその単位を Undo で取り消せる。
10. 実行の結果 (成功・失敗・停止、経過時間、変更したドキュメント) を出力パネル (AUTO-24) に 1 行で記録する。

**画面**: 処理センターの項目、エディタ上部の InfoBar、出力パネル。ステータスバーに実行中のスクリプト数を表示する。

**巨大ファイル・長時間処理**: スクリプト自体が長時間処理として扱われる。データ量に比例する処理は一括処理 API (AUTO-09) を使うよう、サンプルと API ドキュメントで案内する。

**エラー**:

- 構文エラー・コンパイルエラー: 実行せず、エラー一覧 (ファイル名・行・列・メッセージ) を出力パネルに出し、スクリプトエディタで該当行を開けるようにする。
- 実行時の例外: 出力パネルに例外のメッセージとスタックトレース (スクリプトの行番号付き) を出し、InfoBar「スクリプト「名前」がエラーで終了しました」と「詳細」ボタンを出す。
- 実行時間・メモリ・再帰の上限超過 (AUTO-02): 例外として扱い、どの上限を超えたかを表示する。

**受け入れ基準**:

- [ ] `.js` と `.csx` のスクリプトを F5 で実行でき、結果が出力パネルに出る。
- [ ] 実行中も UI が固まらず、他のドキュメントを編集できる。
- [ ] スクリプトが書き込んでいるドキュメントには利用者が入力できず、InfoBar が出る。
- [ ] 1 回の実行による変更が 1 回の Ctrl+Z で元に戻る。
- [ ] `while(true){}` の JavaScript を停止ボタンで 3 秒以内に止められる。
- [ ] 例外で終了したスクリプトの行番号が出力パネルに出て、クリックで該当行へ移動できる。

### AUTO-02 JavaScript の実行環境 (Jint)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05 |
| 呼び出し | AUTO-01 から使われる。設定「設定 > スクリプト > JavaScript」 |

**概要**: JavaScript は純粋な .NET 実装のインタプリタ Jint で実行する。追加のランタイムを必要とせず、実行時間・メモリ・再帰の深さに上限を設けて、暴走したスクリプトがアプリを巻き込まないようにする。

**仕様**:

1. 言語仕様は Jint が対応する ECMAScript の範囲 (ES2023 相当を目標) とする。`async` / `await`、`Promise`、型付き配列 (`Uint8Array` など)、`BigInt`、ES モジュールを使える。
2. .NET への直接アクセス (Jint の CLR 連携) は無効にする。スクリプトから使えるのは、自動化 API (AUTO-04〜AUTO-18) と ECMAScript 標準の組み込みオブジェクトだけ。
3. モジュールの読み込み (`import`) は次の場所だけを許す。
   - 実行中のスクリプトと同じフォルダ以下
   - スクリプトライブラリのフォルダ (`<設定フォルダ>/scripts/lib/`)
   - `hexeditor:` で始まる組み込みモジュール (例: `import { crc32 } from "hexeditor:hash"`)
4. 実行の上限は次のとおり。いずれも設定で変更できる。スクリプトはメタデータ (AUTO-26) で上限の引き上げを要求でき、要求が設定の上限値を超える場合は設定の上限値を使う。

   | 上限 | 既定値 | 設定できる範囲 | 数え方 |
   | --- | --- | --- | --- |
   | 実行時間 | 60 秒 | 1 秒〜無制限 | JavaScript のコードを実行している時間。一括処理 API の完了待ち、利用者の入力待ち、デバッガでの一時停止の時間は含めない |
   | メモリ | 512 MB | 16 MB〜4 GB | Jint が管理する JavaScript のオブジェクトの使用量 |
   | 再帰の深さ | 1,000 | 100〜10,000 | 関数呼び出しの深さ |

5. 対話的な実行で実行時間の上限に達したときは、スクリプトを一時停止し、InfoBar「スクリプト「名前」が 60 秒を超えました」と「続ける (さらに 60 秒)」「停止」ボタンを出す。ヘッドレス実行 (AUTO-41) では、そのまま終了コード 7 で終わる。
6. `console.log` / `console.info` / `console.warn` / `console.error` / `console.table` は出力パネル (AUTO-24) に出す。
7. 64 bit 整数の値は `BigInt` で扱う。オフセットと長さは `number` で扱い、2^53 を超える値はエラーにする (2^53 バイト = 8 PB)。
8. 文字列は UTF-16 (ECMAScript 標準)。バイト列との変換は `text.encode(string, encoding)` / `text.decode(bytes, encoding)` (AUTO-12) で行い、アプリが対応する全文字コードを使える。
9. 1 つのスクリプトの実行ごとに新しい Jint のエンジンを作る。実行間でグローバル変数は共有しない (永続化は `script.storage`、AUTO-17)。例外としてコンソール (AUTO-23) は同じエンジンを使い続ける。

**画面**: 設定画面の「スクリプト > JavaScript」に上限値の入力欄を置く。

**巨大ファイル・長時間処理**: Jint はインタプリタであり、1 バイトずつのループはネイティブより 2 桁程度遅い。データ量に比例する処理は一括処理 API (AUTO-09) で行う。

**エラー**:

- 上限超過: `RangeError` 相当の例外を投げ、メッセージに超えた上限 (例: 「メモリの上限 512 MB を超えました」) を含める。
- 許可されていない `import`: 「このモジュールは読み込めません: パス」の例外。

**受け入れ基準**:

- [ ] `async` / `await`、`Uint8Array`、`BigInt`、`import` を使うスクリプトが動く。
- [ ] スクリプトから `System.IO.File` などの .NET の型に触れられない。
- [ ] 無限ループのスクリプトが 60 秒で一時停止し、「続ける」を選ぶとさらに 60 秒動く。
- [ ] 1 GB の配列を確保しようとするスクリプトが、アプリを落とさずにメモリ上限のエラーで終わる。
- [ ] 無限再帰が再帰の上限のエラーで終わる。
- [ ] 一括処理 API の完了待ちの時間が実行時間の上限に数えられない (10 GB の XOR を 60 秒の上限で実行して最後まで終わる)。

### AUTO-03 C# スクリプト (Roslyn の追加コンポーネント)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05 |
| 呼び出し | AUTO-01 から使われる。メニュー「ツール > スクリプト > C# スクリプト コンポーネントを追加...」、設定「設定 > スクリプト > C#」 |

**概要**: C# スクリプト (`.csx`) を Roslyn でコンパイルして実行する。Roslyn は大きいため本体には含めず、初めて C# スクリプトを使うときに追加コンポーネントとして入れる。

**仕様**:

1. 書式は Roslyn の C# スクリプト (`Microsoft.CodeAnalysis.CSharp.Scripting`) に従う。トップレベルの文、`#load` (同じフォルダとスクリプトライブラリのフォルダのみ)、`await` を使える。`#r` は SDK とアプリが許可したアセンブリ (5 を参照) だけを参照できる。NuGet パッケージの参照 (`#r "nuget:..."`) は使えない。
2. スクリプトのグローバル変数として、JavaScript と同じ名前の API (`App`、`Doc` (= `App.ActiveDocument`)、`Ui`、`Hash`、`Clipboard`、`Settings`、`Script`、`Ct` (キャンセル用の `CancellationToken`)) を公開する。型は SDK (AUTO-29) の型そのもの。
3. **Roslyn の入れ方 (追加コンポーネント)**:

   | 配布形態 | 入れ方 |
   | --- | --- |
   | インストーラ版 | アプリ内の「C# スクリプト コンポーネントを追加」で、更新と同じ配布元・同じチャネルからダウンロードし、データフォルダの `%LocalAppData%\HexEditorData\components\csharp\<バージョン>\` に置く (Velopack のインストール先 `%LocalAppData%\HexEditor\` には置かない。更新・アンインストールで消えるため) |
   | MSIX 版 (Microsoft Store 版) | Store の外からコードをダウンロードしてよいかは Store のポリシーを確認して決める (未決定。10 の PKG-17 の 7)。入れる場合は同上で、置き場所はパッケージの `LocalCache\components\csharp\<バージョン>\`。MSIX のオプションパッケージは使わない |
   | ポータブル版 | 同上。置き場所はデータフォルダ (既定 `<exe のフォルダ>\Data\`) の `components\csharp\<バージョン>\`。オフライン用に、コンポーネントだけの zip も配布し、手動で展開して使えるようにする |

   - 置き場所の一覧は 10 の PKG-13、ダウンロード・検証・チャネルの扱いは 10 の PKG-17〜PKG-21 (更新と同じ仕組み) に従う。
   - ダウンロードの前に、サイズ (目安: 約 20 MB)、保存先、通信先を示して確認を取る。
   - この通信は 00 の 11.4 の「追加コンポーネントのダウンロード」に当たる。`network.offline` または `network.downloads.enabled = false` (09 の UI-58) のときはダウンロードせず、手動で入れる手順 (zip) を案内する。
   - ダウンロードしたファイルは、ハッシュ (アプリ本体に埋め込んだ SHA-256 の一覧) と、Roslyn のアセンブリの Microsoft の署名 (Authenticode) を検証してから使う (10 の PKG-17 の 7)。
   - コンポーネントのバージョンはアプリのバージョンと対にする。アプリを更新したときは、コンポーネントも合わせて更新する (自動更新が有効な場合は自動で、無効な場合は次に C# スクリプトを使うときに確認する)。
4. **方式の比較と決定の理由**:

   | 方式 | 本体のサイズ | 初回の使いやすさ | 判断 |
   | --- | --- | --- | --- |
   | Roslyn を本体に同梱 | 約 20 MB 増える (全利用者が負担) | すぐ使える | 採用しない。C# スクリプトを使う人は一部で、起動時間とダウンロード量を全員に負担させない |
   | 追加コンポーネント (採用) | 増えない | 初回だけダウンロードが必要。オフライン環境では手動で入れる | 採用。本体を小さく保てる |
   | 外部の .NET SDK (`dotnet`) を使う | 増えない | .NET SDK のインストールが必要 | 採用しない。利用者に開発環境を要求しない |

5. 参照できるアセンブリは次に限る。アプリは自己完結型で配布するため、配布物でトリミング (未使用コードの削除) によって消えた API をスクリプトが呼ぶと失敗する。これを防ぐため、次のアセンブリはトリミングの対象から外す (規則は 10 の PKG-10。プラグインが使うアセンブリ (AUTO-29、AUTO-30) も同じ扱い)。
   - SDK (`HexEditor.Sdk`)
   - .NET の基本ライブラリのうち `System.Runtime`、`System.Collections`、`System.Linq`、`System.Text.RegularExpressions`、`System.Text.Json`、`System.Memory`、`System.Numerics`、`System.Security.Cryptography`、`System.IO` (ファイル操作は可能。C# スクリプトはサンドボックスではない)
6. コンパイル結果はキャッシュする。キーは「スクリプト本文の SHA-256 + `#load` したファイルのハッシュ + SDK のバージョン + コンポーネントのバージョン」。キャッシュ先は `<アプリのデータフォルダ>/cache/csx/`。上限 200 MB を超えたら古いものから消す。
   - 目安: キャッシュがない場合のコンパイルは初回 3 秒以内 (Roslyn の読み込みを含む)、2 回目以降のコンパイルは 1 秒以内、キャッシュがある場合は 0.2 秒以内に実行を始める。
7. **実行と分離**: コンパイルしたアセンブリは、実行ごとに回収可能な `AssemblyLoadContext` に読み込み、実行後に解放する。同じプロセス内で動くため、次の制限がある。
   - 実行時間・メモリの上限は強制できない。キャンセルは `Ct` (`CancellationToken`) による協調的なものだけ。`Ct` を見ないループは止められない。この場合、処理センターに「応答しません」と表示し、アプリの再起動を案内する。再起動前に未保存の編集を復旧用データに書き出す。
   - C# スクリプトはファイル・ネットワーク・プロセスなど .NET でできることは何でもできる。許可の宣言 (AUTO-26) は利用者への説明としてだけ使う (AUTO-34)。
8. コンポーネントがない状態で `.csx` を実行しようとした場合は、コンポーネントの追加を案内するダイアログを出す (ボタン: 「追加する」「キャンセル」)。

**画面**: コンポーネントの追加ダイアログ (サイズ・保存先・通信先・進捗)。設定画面「スクリプト > C#」にコンポーネントのバージョン、削除ボタン、キャッシュの削除ボタンを置く。

**巨大ファイル・長時間処理**: C# のコードはネイティブ速度で動くため、1 バイトずつのループも実用的な速度になる。ただし一括処理 API のほうが速い場合が多い。

**エラー**:

- ダウンロードの失敗・ハッシュや署名の検証失敗: コンポーネントを入れず、理由を表示する。手動で入れる手順 (zip の配布場所) を案内する。
- コンパイルエラー: 実行せず、エラー一覧 (行・列・エラー番号・メッセージ) を出力パネルとエディタに出す。
- 参照できないアセンブリの `#r`: コンパイルエラーとして扱う。

**受け入れ基準**:

- [ ] コンポーネントを入れていない状態で、本体の配布物に Roslyn のアセンブリが含まれていない。
- [ ] `.csx` を初めて実行すると追加の案内が出て、追加後にそのまま実行される。
- [ ] オフライン環境で、手動で展開したコンポーネントが認識される。
- [ ] 同じスクリプトの 2 回目の実行が、0.2 秒以内に始まる。
- [ ] 5 に挙げた API (`System.Text.Json` など) をスクリプトから呼べる。
- [ ] `Ct` を確認するループが停止ボタンで止まる。
- [ ] 改ざんしたコンポーネントの zip がハッシュの検証で拒否される。

## 自動化 API

### AUTO-04 API の設計原則と型定義

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05 |
| 呼び出し | ヘルプ「ドキュメント > 自動化 API」、スクリプトエディタの補完 |

**概要**: スクリプト・プラグイン・外部からの自動操作 (AUTO-45) が使う API を、言語に依存しない 1 つのモデルとして定義する。型定義から JavaScript 用の TypeScript 型定義 (`.d.ts`) と C# の SDK を生成し、両者の食い違いを防ぐ。

**仕様**:

1. API のモデルは、主なオブジェクトを次のように持つ。

   ```text
   app
   ├─ documents[]            Document の一覧
   ├─ activeDocument         Document
   │   ├─ cursor / selection Selection (AUTO-10)
   │   ├─ bookmarks          Bookmarks (AUTO-11)
   │   └─ (読み書き・一括処理のメソッド) (AUTO-08, AUTO-09)
   ├─ commands               コマンドの実行 (AUTO-06)
   ├─ inspector / text       値と文字列の変換 (AUTO-12)
   ├─ templates              テンプレート (AUTO-13)
   ├─ hash                   ハッシュ (AUTO-14)
   ├─ clipboard              クリップボード (AUTO-15)
   ├─ ui                     ダイアログ・進捗・出力 (AUTO-16)
   ├─ settings / script      設定とスクリプト用の保存領域 (AUTO-17)
   └─ fs / net / process     ファイル・ネットワーク・外部プログラム (許可が必要、AUTO-18)
   ```

2. 型定義の元は 1 つ (C# の SDK のインターフェイスと XML ドキュメントコメント) とし、ビルド時に次を生成する。
   - `hexeditor.d.ts` (JavaScript の補完・エラー検出用)
   - JSON-RPC のメソッド一覧 (AUTO-45)
   - API リファレンス (英語と日本語)
3. 名前の対応: JavaScript は `camelCase` (例: `doc.readBytes`)、C# は `PascalCase` (例: `Doc.ReadBytes`)。引数の順序と意味は同じにする。
4. バイト列は JavaScript では `Uint8Array`、C# では `byte[]` または `ReadOnlyMemory<byte>`。オフセットと長さは JavaScript では `number`、C# では `long`。
5. 範囲は `{ start, length }` (JavaScript) / `ByteRange(Start, Length)` (C#) で表す。範囲を受け取る引数は、入力式 (00 の 6 章) の文字列も受け付ける (例: `"sel"`、`"0x100:0x20"` (開始:長さ)、`"0x100..0x120"` (開始..終了、終了は含まない))。
6. 数値を受け取る引数は、入力式の文字列も受け付ける (例: `doc.goTo("end-0x10")`)。
7. API のバージョンは `app.apiVersion` (例: `1.3`) で取得できる。同じメジャーバージョンの中では後方互換を保つ (メソッドの追加は可、削除・意味の変更は不可)。廃止予定の API は 1 メジャーバージョンの間、警告付きで残す。
8. スクリプトはメタデータの `@api` (AUTO-26) で必要な API のバージョンを宣言できる。アプリが満たさない場合は実行前にエラーにする (本文は実行しない)。エラーには必要なバージョンとアプリの API のバージョン (`app.apiVersion`) の両方を含める。ヘッドレス実行 (AUTO-41) では終了コード 4 (スクリプトのエラー、AUTO-36 の 7) で終わる。
9. 例外は共通の種類にそろえる: `ArgumentError` (引数が不正)、`RangeError` (範囲外)、`ReadOnlyError` (読み取り専用)、`IoError` (読み書きの失敗)、`PermissionError` (許可がない)、`CanceledError` (キャンセルされた)、`LimitError` (上限超過)。C# では同名の例外クラス (`HexEditor.Sdk` 名前空間) にする。

**画面**: 該当なし (API リファレンスはヘルプから開く)。

**巨大ファイル・長時間処理**: 該当なし (各 API の項で定める)。

**エラー**: 9 のとおり。

**受け入れ基準**:

- [ ] ビルドのたびに `hexeditor.d.ts` と API リファレンスが生成され、C# の SDK と食い違いがないことを CI で確認する。
- [ ] 同じ処理を JavaScript と C# で書いたサンプル (AUTO-46) が同じ結果になる。
- [ ] 範囲・数値の引数に入力式の文字列を渡せる。
- [ ] `@api 99.0` を宣言したスクリプトが、実行前に、必要なバージョンとアプリの API のバージョンを含むエラーになり、本文が実行されない。ヘッドレス実行では終了コード 4 になる。

### AUTO-05 非同期処理とキャンセル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05 |
| 呼び出し | API の全体に適用される |

**概要**: スクリプトは UI スレッドと別のスレッドで動く。少量の読み書きは同期 API で簡単に書け、データ量に比例する処理は非同期 API で進捗とキャンセルに対応する。

**仕様**:

1. スクリプトは専用のワーカースレッドで動く。UI スレッドでは実行しない。
2. API は次の規則で同期と非同期を分ける。

   | 種類 | 形 | 例 |
   | --- | --- | --- |
   | プロパティの取得、少量の読み書き (1 回 16 MB 以下) | 同期 | `doc.length`、`doc.readBytes(off, 16)`、`doc.writeBytes(off, data)` |
   | データ量に比例する処理、利用者の操作を待つ処理 | 非同期 (JavaScript は `Promise`、C# は `Task`) | `doc.findAll(...)`、`doc.transform(...)`、`hash.compute(...)`、`doc.save()`、`ui.prompt(...)` |

   - 同期 API に 16 MB を超える量を渡すと `LimitError` にする。大きな範囲は `doc.chunks` (AUTO-09) で分けて読む。
3. 非同期 API はすべて、省略できる引数 `options` に `signal` (JavaScript、`AbortSignal` 相当) / `CancellationToken` (C#) と `progress` (進捗を受け取る関数) を受け取る。省略した場合は、スクリプト全体のキャンセルと処理センターの進捗表示につながる。
4. スクリプト全体のキャンセルは `script.signal` (JavaScript) / `Ct` (C#) で参照できる。停止ボタンが押されるとキャンセル状態になり、実行中の非同期 API は `CanceledError` で終わる。
5. スクリプトは `ui.progress.report(割合, 説明)` で処理センターの進捗を更新できる (AUTO-16)。一括処理 API は自分の進捗を自動で報告する。
6. 非同期 API を同時に複数呼んでもよい (例: 2 つのドキュメントのハッシュを同時に計算する)。同じドキュメントへの書き込みは呼び出した順に直列化する。
7. UI に関わる API (`ui.*`、`clipboard.*`) は、内部で UI スレッドに処理を渡し、結果をスクリプトのスレッドに返す。
8. JavaScript でトップレベルの `await` を使える。トップレベルの `Promise` がすべて終わったときにスクリプトの終了とする。

**画面**: 処理センターの進捗表示。

**巨大ファイル・長時間処理**: この項で定める仕組みそのもの。

**エラー**: キャンセル時は `CanceledError`。スクリプトがこれを捕まえずに終わった場合は「停止しました」と記録し、エラーとしては扱わない。

**受け入れ基準**:

- [ ] 100 GB のドキュメントに対する `findAll` の実行中に停止ボタンを押すと、1 秒以内に `CanceledError` で終わる。
- [ ] 同期 API に 17 MB を渡すと `LimitError` になる。
- [ ] スクリプトの実行中に、UI のスクロール・他のタブの編集が 50 ms 以内に反応する。
- [ ] 2 つのハッシュ計算を `Promise.all` で同時に実行できる。

### AUTO-06 App オブジェクトとコマンドの実行

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05 |
| 呼び出し | API `app` |

**概要**: アプリ全体を表すオブジェクト。開いているドキュメント、ファイルを開く操作、アプリの全コマンドの実行、イベントを提供する。

**仕様**:

1. 主なメンバー:

   | メンバー | 内容 |
   | --- | --- |
   | `version` / `apiVersion` | アプリと API のバージョン |
   | `language` | UI の表示言語のタグ (例: `ja`)。スクリプトが自分のメッセージを訳し分けるのに使う |
   | `documents` | 開いているドキュメントの一覧 (読み取り専用の配列) |
   | `activeDocument` | アクティブなドキュメント。ない場合は `null`。代入するとそのタブをアクティブにする |
   | `open(path, options)` | ファイルを開く。`options`: `readOnly`、`offset`、`select`、`encoding`、`background` (タブをアクティブにしない) |
   | `openDisk(id, options)` / `openProcess(pid, options)` | ディスク・プロセスメモリを開く (許可 `disk` が必要、AUTO-34) |
   | `newDocument(options)` | 新規ドキュメント。`options.length` と `options.fill` で初期内容を指定できる |
   | `commands.execute(id, args)` | アプリのコマンドを ID で実行する (例: `"edit.fill"`)。メニューやコマンドパレットにある全コマンドを呼べる |
   | `commands.list()` | コマンドの ID・表示名・引数の一覧 |
   | `on(event, handler)` | イベントの購読 (下表) |
   | `stop()` | 実行中のスクリプト自身を終了する |

2. コマンド ID は全コマンドで固定の英語の識別子 (`領域.動作` の形) とし、表示名とは別に持つ。表示言語が変わってもスクリプトは動く。マクロ (AUTO-27) もこの ID で記録する。
3. 利用者に確認を求めるコマンド (例: 「保存しない」の確認) をスクリプトから実行した場合、引数 `args.confirm` で答えを渡せる。渡さない場合は対話的な実行ではダイアログを出し、ヘッドレス実行では安全側の答え (キャンセル) を選ぶ。
4. イベント:

   | イベント | 発生する時 |
   | --- | --- |
   | `documentOpened` / `documentClosed` | ドキュメントを開いた / 閉じた |
   | `activeDocumentChanged` | アクティブなタブが変わった |
   | `beforeSave` / `afterSave` | 保存の直前 / 直後。`beforeSave` のハンドラは `event.cancel(理由)` で保存を中止できる |
   | `selectionChanged` | 選択範囲・カーソルが変わった。連続した変化は 100 ms ごとにまとめて 1 回通知する |

   - イベントを購読したスクリプトは、`app.stop()` を呼ぶかスクリプトを停止するまで常駐する。常駐中のスクリプトはスクリプト一覧パネルに「常駐」と表示する。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: `open` は 01 と同じく、サイズに関係なくすぐに戻る。

**エラー**: 存在しないコマンド ID は `ArgumentError`。開けないファイルは `IoError` (理由を含む)。

**受け入れ基準**:

- [ ] `app.commands.list()` に、コマンドパレットにある全コマンドが含まれる。
- [ ] 表示言語を英語・日本語・アラビア語に変えても、同じコマンド ID のスクリプトが同じ結果になる。
- [ ] `beforeSave` で `cancel` を呼ぶと保存が中止され、理由が InfoBar に出る。
- [ ] `selectionChanged` が、矢印キーを押し続けても 1 秒あたり 10 回以下に抑えられる。

### AUTO-08 データの読み書き

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05 |
| 呼び出し | API `Document` のメソッド |

**概要**: ドキュメントのバイト列を読み、書き換え、挿入・削除・塗りつぶしを行う。

**仕様**:

1. メソッド:

   | メソッド | 内容 |
   | --- | --- |
   | `readBytes(offset, length)` | バイト列を読む (同期、16 MB まで)。末尾を越える部分は返さない (返す長さが短くなる) |
   | `readByte(offset)` | 1 バイト読む |
   | `readInt(offset, type, endian)` / `readFloat(offset, type, endian)` | 整数・浮動小数点として読む。`type`: `i8` `u8` `i16` `u16` `i24` `u24` `i32` `u32` `i64` `u64` / `f16` `f32` `f64`。`endian`: `"le"` / `"be"`、省略時はドキュメントの既定のエンディアン。64 bit 整数は JavaScript では `BigInt` |
   | `readString(offset, maxLength, encoding, options)` | 文字列として読む。`options.stopAtNull` (既定 `true`) |
   | `writeBytes(offset, data)` | 上書きする (長さは変わらない)。末尾を越える部分は、長さを変えられるドキュメントなら追加し、変えられないなら `RangeError` |
   | `writeInt` / `writeFloat` / `writeString` | 値を書く (引数は読むほうと対応) |
   | `insertBytes(offset, data)` | 挿入する。`canResize` が `false` なら `ReadOnlyError` |
   | `delete(range)` | 削除する |
   | `fill(range, pattern, options)` | パターンで塗りつぶす。`pattern` は `Uint8Array`、Hex 文字列、または `"random"`。`options.insert` が `true` なら挿入 |
   | `resize(newLength, fill)` | 長さを変える (切り詰め・延長) |

2. 書き込み系のメソッドは、エディタの編集と同じデータエンジンの操作を使う (03 と同じ Undo、変更バイトの強調表示)。
3. Hex 文字列を受け取る引数は 00 の 6.3 の書式を受け付ける。
4. `fill` と `insertBytes` は、データ量に関係なく 100 ms 以内に終わる (00 の 11.1。データエンジンの塗りつぶしピースを使う)。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: 読み込みは 16 MB までの同期 API。それ以上は `chunks` (AUTO-09) を使う。塗りつぶし・挿入・削除はデータ量に関係なく速い。

**エラー**: 範囲外の読み書きは `RangeError`、読み取り専用は `ReadOnlyError`、I/O の失敗 (ディスクの読み取りエラーなど) は `IoError` (オフセットを含む)。

**受け入れ基準**:

- [ ] `readInt(0, "u32", "be")` が `0xDEADBEEF` のバイト列から 3735928559 を返す。
- [ ] `readInt(0, "u64")` が JavaScript では `BigInt` を返す。
- [ ] 100 GB のドキュメントに `fill({start: 0, length: 50G}, "00")` が 100 ms 以内に戻る。
- [ ] `writeBytes` で書いたバイトが、手で入力した場合と同じく変更バイトとして強調表示される。
- [ ] 長さを変えられないディスクのドキュメントで `insertBytes` が `ReadOnlyError` になる。

### AUTO-09 一括処理 API

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05 |
| 呼び出し | API `Document` のメソッド |

**概要**: データ量に比例する処理を、スクリプトのループではなく C# の実装で一度に行う。スクリプトが遅い言語 (Jint) でも、巨大ファイルを実用的な速度で処理できる。

**仕様**:

1. メソッド (すべて非同期、`options` に `signal` と `progress` を受け取る):

   | メソッド | 内容 | 対応する機能 |
   | --- | --- | --- |
   | `transform(range, op, operand, options)` | データ演算。`op`: `xor` `and` `or` `not` `add` `sub` `mul` `div` `shl` `shr` `rol` `ror` `neg` `swap` (バイトスワップ) `reverse`。`operand` は数値・Hex 文字列 (繰り返しキー)。`options.unit` (1/2/4/8 バイト)、`options.endian`、`options.overflow` (`wrap` / `saturate`) | 03 のデータ演算 |
   | `findAll(pattern, options)` | すべて検索。`options.type`: `hex` (ワイルドカード可) / `text` / `regex` / `int` / `float`、`encoding`、`caseSensitive`、`range`、`alignment`、`max` (既定 1,000,000 件)。結果は `{ start, length }` の配列 | 04 |
   | `find(pattern, options)` | 最初の 1 件 (`options.from`、`options.backward`)。見つからなければ `null` | 04 |
   | `replaceAll(pattern, replacement, options)` | すべて置換。置換した件数を返す | 04 |
   | `copyRange(src, destDoc, destOffset, options)` | 範囲のコピー (`options.insert`)。別のドキュメントへのコピーもできる。データエンジンの参照で行い、実データを複製しない | 03 |
   | `exportRange(range, path, options)` | 範囲をファイルに書き出す (許可 `file-write` または利用者が選んだパス) | 11 |
   | `chunks(range, chunkSize)` | 範囲を `chunkSize` (既定 1 MB、最大 16 MB) ごとに読む非同期イテレータ。`for await (const { offset, data } of doc.chunks(...))` | — |
   | `transformChunks(range, fn, options)` | 範囲をチャンクごとに読み、スクリプトの関数 `fn(data, offset)` が返したバイト列で上書きする (長さは同じであること) | — |
   | `count(pattern, options)` | 一致の件数だけを数える | 04 |
   | `histogram(range)` | バイト値 0〜255 の出現数 (長さ 256 の配列) | 06 |
   | `entropy(range, options)` | エントロピー。`options.blockSize` を指定するとブロックごとの配列 | 06 |
   | `compare(otherDoc, options)` | 比較。差分の範囲の配列 | 06 |
   | `strings(options)` | 文字列の抽出 (最小長・文字コード) | 04 |

2. 一括処理の結果を利用者に見せたい場合は `ui.showResults` (AUTO-16) で結果一覧に出せる。
3. 一括処理による変更は、通常の編集と同じく Undo できる。
4. 速度の目標: 同じ処理をメニューから実行した場合との差が 10% 以内。

**画面**: 処理センターの進捗表示 (処理ごとに「スクリプト: 名前 - 処理名」として表示する)。

**巨大ファイル・長時間処理**: すべての処理はチャンク単位で行い、メモリ使用量はデータ量に比例しない。`findAll` の結果が `max` を超える場合は、`max` 件で打ち切り、結果に `truncated: true` を付ける。

**受け入れ基準**:

- [ ] 10 GB のファイルの `findAll` の実行中に、アプリのメモリ使用量が 1 GB を超えない。

- [ ] 一括処理の変更が 1 回の Undo で元に戻る。

**受け入れ基準**:

- [ ] 許可なしで `fs.readText("C:/Windows/win.ini")` が `PermissionError` になる。
- [ ] `ui.pickFile` で選んだファイルは許可なしで読める。
- [ ] 許可なしで `net.fetch` が `PermissionError` になる。

**エラー**: 該当なし。

**受け入れ基準**:

### AUTO-26 スクリプトのメタデータとパラメータ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05 |
| 呼び出し | スクリプトファイルの先頭に書く |

**概要**: スクリプトの名前・説明・必要な許可・パラメータなどを、ファイル先頭のコメントで宣言する。パラメータを宣言すると、実行時に入力ダイアログが自動で作られる。

**仕様**:

1. 書式 (JavaScript と C# で共通。`//` のコメント):

   ```javascript
   // ==HexEditorScript==
   // @name         XOR デコード
   // @name:en      XOR decode
   // @description  選択範囲を指定したキーで XOR する
   // @version      1.0.0
   // @author       Example
   // @api          1.0
   // @param        key hex "5A" キー
   // @param        whole checkbox false ファイル全体を対象にする
   // @permission   file-read
   // @timeout      300
   // @on           open *.bin
   // ==/HexEditorScript==
   ```

2. 項目:

   | 項目 | 内容 |
   | --- | --- |
   | `@name` / `@name:<言語タグ>` | 表示名。言語タグ付きは表示言語に合わせて選ぶ |
   | `@description` / `@description:<言語タグ>` | 説明 |
   | `@version` / `@author` | バージョン、作者 |
   | `@api` | 必要な API のバージョン (AUTO-04) |
   | `@param 名前 型 既定値 ラベル` | パラメータ。型は `ui.prompt` / `ui.form` と同じ |
   | `@permission` | 必要な許可 (AUTO-34)。複数行に書ける |
   | `@timeout` / `@memory` | 実行時間 (秒) とメモリ (MB) の上限の要求 (AUTO-02) |
   | `@on` | 自動実行の候補 (AUTO-25) |
   | `@menu` | メニュー「ツール > スクリプト」の下に表示する位置 (例: `@menu 変換/XOR デコード`) |
   | `@context` | 右クリックメニューに出す条件 (`selection`: 選択があるとき、`always`)。右クリックメニューの「スクリプト」の下に出す |

3. パラメータがある場合、実行前に `ui.form` と同じ入力ダイアログを出す。前回の入力値をスクリプトごとに記憶し、次回の既定値にする。
4. メタデータがないスクリプトも実行できる (名前はファイル名、許可なし、パラメータなし)。
5. メタデータの書式の誤り (不明な項目・型の誤り) は警告として出力パネルに出し、実行は続ける。

**画面**: パラメータの入力ダイアログ。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 5 のとおり。

**受け入れ基準**:

- [ ] `@param` を書いたスクリプトの実行前に入力ダイアログが出て、値が `script.args` に入る。
- [ ] 2 回目の実行で、前回の入力値が既定値になる。
- [ ] `@name:en` が、英語の表示で使われる。
- [ ] `@context selection` のスクリプトが、選択があるときだけ右クリックメニューに出る。

## マクロ

### AUTO-27 マクロの記録

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-06 |
| 呼び出し | Ctrl+Shift+R (記録の開始 / 停止)、メニュー「ツール > マクロ > 記録の開始 / 停止」、コマンドパレット「マクロ: 記録の開始 / 停止」 |

**概要**: 利用者の操作 (コマンド、入力、カーソル移動) を記録し、JavaScript のスクリプトとして保存する。記録したマクロは AUTO-28 で再生でき、スクリプトエディタで手直しできる。

**仕様**:

1. 記録はキー入力ではなくコマンド単位で行う。各操作をコマンド ID と引数 (AUTO-06) として記録し、`app.commands.execute(...)` または対応する API の呼び出し (例: `doc.writeBytes`) に変換する。
2. 記録する操作と変換のしかた:

   | 操作 | 記録される内容 |
   | --- | --- |
   | 文字・Hex の入力 | 連続した入力を 1 回の `writeBytes` / `insertBytes` にまとめる |
   | カーソル移動 (矢印・PageUp/Down・Home/End) | 移動のコマンド (`"cursor.right"` など) と回数。連続した同じ移動はまとめる |
   | マウスでのクリック・選択 | 位置の記録方式 (3) に従う |
   | ダイアログを使うコマンド (塗りつぶし・データ演算・置換など) | ダイアログで確定した値を引数として記録する。再生時はダイアログを出さない |
   | 検索 | 検索条件を引数として記録する |
   | ファイルを開く・保存 | パスを引数として記録する |
   | タブの切り替え | ドキュメントの相対的な指定 (次のタブなど) で記録する |

3. 位置の記録方式を、記録開始時に選べる (前回の選択を記憶する)。
   - 相対 (既定): マウスでの位置指定を、記録開始時のカーソルからの相対オフセットで記録する。
   - 絶対: オフセットそのものを記録する。
4. 記録中は、ステータスバーに赤い丸と「記録中」の文字と記録した操作の数を表示する。
5. 記録できない操作 (他のアプリとのやりとり、スクリプトの実行中の操作など) を行った場合は、ステータスバーに「記録できない操作: 名前」と一時表示し、その操作は記録しない。
6. 停止すると、記録内容を「直前のマクロ」として保持し、保存ダイアログ (名前・保存先・ショートカット) を表示する。保存しなかった場合も「直前のマクロ」はアプリの終了まで再生できる。
7. 保存したマクロは `<設定フォルダ>/macros/` の `.js` ファイルになり、メタデータ (AUTO-26) と各操作のコメント (操作の表示名) を含む。
8. 記録中に Ctrl+Shift+R 以外で記録を止める方法: ステータスバーの「記録中」をクリック、コマンドパレット。

出力の例:

```javascript
// ==HexEditorScript==
// @name  マクロ 2026-10-07 14:03
// @api   1.0
// ==/HexEditorScript==
const doc = app.activeDocument;
// オフセットへ移動: cur+0x10
doc.goTo(doc.cursor + 0x10);
// 入力: DE AD
doc.writeBytes(doc.cursor, [0xDE, 0xAD]);
doc.cursor += 2;
// 塗りつぶし
await app.commands.execute("edit.fill", { range: "sel", pattern: "00" });
```

**画面**: ステータスバーの記録表示、停止時の保存ダイアログ。

**巨大ファイル・長時間処理**: 記録そのものはデータ量に関係しない。長時間処理のコマンドは、完了を待つ形 (`await`) で記録する。

**エラー**: 保存先に書き込めない場合は理由を表示し、別の場所を選ばせる。

**受け入れ基準**:

- [ ] Ctrl+Shift+R で記録を開始・停止でき、ステータスバーに記録中と表示される。
- [ ] 「DEAD」を入力した記録が 1 回の `writeBytes` になる。
- [ ] 塗りつぶしダイアログの値が引数として記録され、再生時にダイアログが出ない。
- [ ] 表示言語を変えても、記録したマクロが同じ結果を出す。
- [ ] 記録したマクロをスクリプトエディタで開いて編集できる。

### AUTO-28 マクロの再生と管理

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-06 |
| 呼び出し | メニュー「ツール > マクロ > 直前のマクロを再生」「ツール > マクロ > 繰り返し再生...」、コマンドパレット「マクロ: 直前のマクロを再生」「マクロ: 繰り返し再生」、スクリプト一覧 (マクロのフォルダ)。ショートカットは既定なし (ショートカットの設定画面で割り当てる) |

**概要**: 記録したマクロを 1 回または繰り返し再生する。マクロごとにショートカットを割り当てられる。

**仕様**:

1. 「直前のマクロを再生」: 直前に記録した (または直前に再生した) マクロを 1 回再生する。
2. 「繰り返し再生」ダイアログで次を選ぶ。
   - 回数を指定 (1〜1,000,000)
   - ファイルの末尾に達するまで (カーソルが末尾に達した、または移動できなくなった時点で止める)
   - 検索結果ごと (結果一覧の各行の位置にカーソルを置いて 1 回ずつ実行する)
   - 選択範囲の中で (カーソルが選択範囲の外に出たら止める)
3. 繰り返し再生全体を 1 つの Undo 単位にする。
4. 再生は長時間処理として処理センターに出し、回数の進捗と停止ボタンを表示する。
5. 再生中にマクロの中の操作が失敗した場合 (検索で見つからない、範囲外など)、その回で止め、何回目のどの操作で止まったかを表示する。
6. マクロはスクリプトと同じ仕組み (AUTO-01) で実行する。保存したマクロはスクリプト一覧に出て、コマンドとしてショートカットを割り当てられる (AUTO-19)。
7. 利用者がアプリ内で記録したマクロは、信頼の確認 (AUTO-34) を出さない。アプリは記録したマクロを保存する時点で、その「パス + 内容の SHA-256」(AUTO-34 の 1) を信頼済みの一覧に登録し、これによって自分で記録したマクロと見分ける (マクロのファイルの中の印では見分けない。印は他人が書き加えられるため)。保存していない「直前のマクロ」はメモリ上にだけあるため、確認なしで再生する。保存後にアプリの外で内容が変わった場合は、通常のスクリプトと同じく信頼の確認を出す (アプリ内のスクリプトエディタで保存した場合は、AUTO-34 の 1 のとおり確認を出さない)。

**画面**: 繰り返し再生のダイアログ、処理センター。

**巨大ファイル・長時間処理**: 1 回の再生に 1 ms かかるマクロを 100 万回繰り返す場合でも、UI を止めず、停止できる。画面の再描画は 100 ms ごとにまとめる。

**エラー**: 5 のとおり。

**受け入れ基準**:

- [ ] 記録したマクロを「直前のマクロを再生」で再生できる。
- [ ] 「ファイルの末尾に達するまで」で、末尾で自動的に止まる。
- [ ] 1 万回の繰り返し再生が 1 回の Ctrl+Z で元に戻る。
- [ ] 保存したマクロにショートカットを割り当てて実行でき、信頼の確認が出ない。

### AUTO-30 プラグインの読み込みと分離

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-07 |
| 呼び出し | アプリの起動時、プラグインの有効化時 |

**概要**: プラグインを決まったフォルダから読み込み、プラグインごとに `AssemblyLoadContext` を分けて依存ライブラリの衝突を防ぐ。

**仕様**:

1. プラグインは 1 つのフォルダにまとめ、マニフェスト `plugin.json` を置く。

   ```json
   {
     "id": "example.crc-tools",
     "name": "CRC Tools",
     "name.ja": "CRC ツール",
     "version": "1.2.0",
     "publisher": "Example",
     "sdk": "1.3",
     "minAppVersion": "1.4.0",
     "entry": "Example.CrcTools.dll",
     "permissions": ["file-read"],
     "description": "Additional CRC algorithms."
   }
   ```

2. 置き場所は `<設定フォルダ>/plugins/<id>/<version>/`。同じ `id` の複数のバージョンがある場合は、最新のものを読み込む。
3. 読み込みの手順:
   1. マニフェストを検証する (必須項目、SDK のバージョン、アプリのバージョン)。
   2. 署名を確認する (AUTO-35)。
   3. 初めて読み込むプラグイン、またはファイルが変わったプラグインは、信頼の確認 (AUTO-34) を出す。許可されたものだけ次に進む。
   4. プラグインごとに専用の `AssemblyLoadContext` を作り、`entry` のアセンブリを読み込む。SDK、.NET の基本ライブラリ、Windows App SDK はアプリ側のものを共有する。それ以外の依存ライブラリはプラグインのフォルダから読み込む (プラグイン同士で別のバージョンを使える)。
   5. `IPlugin` を実装した型を 1 つ探し、`Initialize(IPluginContext)` を呼ぶ。プラグインはここで拡張ポイントを登録する。
4. 読み込みは起動を遅らせない。最初のウィンドウを表示した後にバックグラウンドで読み込み、終わったものから拡張ポイントを有効にする。ただし起動時に開くファイルのインポート形式など、必要になったプラグインはその時点で優先して読み込む。
5. `AssemblyLoadContext` は依存関係の分離のためのもので、セキュリティの境界ではない。プラグインはアプリと同じ権限で動く (AUTO-34 で利用者に説明する)。
6. プラグインのアンロード (アプリを再起動せずに外すこと) には対応しない。無効化・削除・更新はアプリの再起動で反映する。理由: WinUI のオブジェクトや静的な参照が残りやすく、回収可能な `AssemblyLoadContext` を確実に解放できないため。
7. プラグインのコードの例外の扱い:
   - 拡張ポイントの呼び出しはすべて例外を捕まえ、出力パネルの「プラグイン: 名前」に記録する。アプリは動き続ける。
   - 同じプラグインで 1 分間に 10 回以上の例外が起きた場合、そのプラグインを一時的に止め、InfoBar で「プラグイン「名前」でエラーが続いたため停止しました」と知らせる (ボタン: 「プラグインを無効にする」「再起動時にもう一度試す」)。
   - プラグインが原因と考えられるアプリの異常終了が起きた場合 (異常終了時の呼び出し履歴にプラグインのアセンブリが含まれる)、次の起動時にそのプラグインを無効にするか確認する。
8. セーフモード: この項目がセーフモードの主担当である (00 の 1.1)。起動時の操作と表示は 09 の UI-30 が定める。
   - 入り方: コマンドラインの `--safe-mode` (AUTO-37)、または起動時に Shift キーを押し続ける (最初のウィンドウが表示されるまで)。どちらも新しくプロセスを起動する場合だけ有効で、既存のインスタンスに転送された起動では無視する。
   - セーフモードでは、プラグインを 1 つも読み込まず、フック (AUTO-25) を実行しない。外部からの自動操作 (AUTO-45) も開始しない。スクリプトとマクロは利用者が明示的に実行した場合だけ動く。
   - 設定・プラグインの一覧・フックの登録は変更しない。次に通常どおり起動すると元に戻る。

**画面**: 該当なし (管理は AUTO-32)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: マニフェストの誤り・バージョンの不一致・読み込みの失敗は、プラグインマネージャ (AUTO-32) にそのプラグインの状態として理由を表示する。

**受け入れ基準**:

- [ ] 同じライブラリの別のバージョンに依存する 2 つのプラグインが、同時に動く。
- [ ] プラグインを 10 個入れても、起動時間 (00 の 11.1) が 2 秒を超えない。
- [ ] 拡張ポイントで例外を投げるプラグインがあっても、アプリが落ちない。
- [ ] `--safe-mode` で起動するとプラグインが読み込まれない。Shift キーを押しながら起動した場合も同じ。
- [ ] マニフェストの `sdk` が合わないプラグインが、理由付きで「読み込めません」と表示される。

### AUTO-31 拡張ポイント

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-07 |
| 呼び出し | プラグインの `Initialize` で登録する |

**概要**: プラグインが機能を追加できる場所 (拡張ポイント) を定める。

**仕様**:

1. 拡張ポイント:

   | 拡張ポイント | インターフェイス | 追加できるもの | 関連 |
   | --- | --- | --- | --- |
   | インスペクタの型 | `IInspectorType` | データインスペクタに表示する型 (読み取り・書き込み・表示文字列) | 05 |
   | ハッシュ | `IHashAlgorithm` | ハッシュ・チェックサムのアルゴリズム (逐次入力型) | 06 |
   | インポート形式 | `IImportFormat` | ファイルや文字列をバイト列に変換する形式 (形式の自動判定を含む) | 11 |
   | エクスポート形式 | `IExportFormat` | バイト列をファイルに書き出す形式。Copy As (03) の形式としても使える | 03, 11 |
   | データソース | `IByteSourceProvider` | 新しい種類のデータソース (例: リモートの機器、独自のコンテナ)。読み取り専用か、長さを変えられるかを宣言する | 01 |
   | 変換ビュー | `ITransformView` | 元のデータを変換して見せる読み書き可能なビュー (例: 復号して見せる、ビット反転して見せる)。書き込みは逆変換して元データに戻す | 03 |
   | データ演算 | `IDataTransform` | データ演算 (03) のメニューに出る変換 | 03 |
   | コマンド | `ICommand` | コマンド (ID・表示名・実行可能かの判定・実行)。コマンドパレットに出て、ショートカットを割り当てられる | 09 |
   | メニュー | `IMenuContribution` | メニュー・右クリックメニューへの項目の追加。置ける場所はメニューの「ツール > プラグイン」の下と、右クリックメニューの「プラグイン」の下に限る | 09 |
   | パネル | `IPanelProvider` | パネル (WinUI の `UIElement`、`HexEditor.Sdk.UI`) | 09 |
   | テンプレートの関数 | `ITemplateFunction` | テンプレート言語から呼べる関数 (例: 独自の展開処理、チェックサムの検証) | 07 |
   | ファイル形式の判定 | `IFileTypeDetector` | マジックによる形式の判定。テンプレートの自動適用 (07) に使われる | 07 |
   | 逆アセンブラ | `IDisassembler` | 追加のアーキテクチャ | 06 |
   | 色付けルール | `IColorRuleProvider` | 値に応じた色付け (05) の規則 | 05 |
   | スクリプト API | `IScriptApiProvider` | スクリプトから `app.plugins.get("id").api` で使えるオブジェクト | AUTO-04 |

2. すべての拡張ポイントは、アプリ本体の同じ種類の機能と同じ場所・同じ見た目で表示する。プラグインが追加したものには、ツールチップと設定画面にプラグイン名を表示する。
3. 拡張ポイントの ID は `<プラグイン ID>.<名前>` とし、アプリ本体や他のプラグインと重複しないようにする。重複した場合は後から読み込んだものを無効にし、警告を出す。
4. データ量に比例する処理 (ハッシュ、インポート・エクスポート、データ演算) のインターフェイスは、`ReadOnlySpan<byte>` のチャンクを受け取る逐次処理の形にし、`CancellationToken` と進捗の通知を受け取る。プラグインに全データを一度に渡さない。
5. UI スレッドで呼ばれる拡張ポイント (インスペクタの型の表示、メニューの実行可能判定、色付けルールなど) は、1 回の呼び出しを 10 ms 以内に終える決まりとする。100 ms を超えた呼び出しは出力パネルに警告を出し、続けて超えるものは呼び出しを止める (AUTO-30 の 7 と同じ扱い)。
6. プラグインが追加した文字列 (表示名など) は、プラグインが自分で翻訳する。SDK はリソースの仕組み (`.resw` と同じ形式、表示言語の取得) を提供する。

**画面**: 各拡張ポイントの表示先 (インスペクタ、ハッシュパネル、インポート・エクスポートのダイアログなど)。

**巨大ファイル・長時間処理**: 4 のとおり。

**エラー**: 3、5 のとおり。

**受け入れ基準**:

- [ ] サンプルプラグインで、インスペクタの型・ハッシュ・インポート形式・エクスポート形式・データソース・変換ビュー・コマンド・パネル・テンプレートの関数を 1 つずつ追加でき、それぞれ本体の機能と同じ場所に出る。
- [ ] プラグインのハッシュで 10 GB のファイルを計算しても、メモリ使用量がファイルサイズに比例しない。
- [ ] UI スレッドで 200 ms かかるインスペクタの型を入れると警告が出て、UI が固まり続けない。
- [ ] ID が重複した 2 つのプラグインのうち、後のものが無効になり警告が出る。

## セキュリティ

### AUTO-34 信頼の確認と許可

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-05, F3-07 |
| 呼び出し | スクリプト・プラグインの初回実行時に自動で表示 (アプリを管理者として実行中は毎回。仕様 8)。設定「設定 > スクリプト > 信頼と許可」 |

**概要**: スクリプトとプラグインを初めて実行するときに、利用者に許可を求める。JavaScript には必要な許可だけを与え、C# スクリプトとプラグインは完全信頼のコードであることを明示して確認する。

**仕様**:

1. 信頼の確認を出す条件:
   - 初めて実行するスクリプト・プラグイン。スクリプトは「パス + 内容の SHA-256」、プラグインは「`id` + 全ファイルのハッシュ」で識別する。
   - 内容が変わったもの (再確認)。
   - 確認を出さないもの: アプリに同梱のサンプル、アプリ内のスクリプトエディタで利用者が保存したもの、アプリ内で記録したマクロ (保存時に信頼済みの一覧に登録する。AUTO-28 の 7)、コンソールの入力。
2. 確認ダイアログに表示するもの:
   - 名前、パス、作者 / 発行者、署名の状態 (AUTO-35)
   - 種類に応じた説明:
     - JavaScript: 「このスクリプトは開いているドキュメントを読み書きできます。それ以外に次の許可を求めています」と、要求している許可の一覧
     - C# スクリプト・プラグイン: 「このコードはあなたの PC 上で、あなたと同じ権限で何でも実行できます (ファイルの読み書き、ネットワーク通信を含む)。信頼できる作成者のものだけを実行してください」
   - インターネットから取得したファイル (Mark of the Web が付いているもの) の場合は、その旨の警告
   - ボタン: 「1 回だけ実行する」「常に許可する」「実行しない」(プラグインは「有効にする」「有効にしない」)
3. JavaScript の許可の種類:

   | 許可 | 内容 | 既定 |
   | --- | --- | --- |
   | (なし) | 開いているドキュメントの読み書き、スクリプト自身のフォルダの読み取り、利用者がダイアログで選んだファイル、`script.storage` | 常に可 |
   | `file-read` | 任意のファイルの読み取り | 不可 |
   | `file-write` | 任意のファイルの作成・書き込み・削除 | 不可 |
   | `network` | `net.fetch` による通信 | 不可 |
   | `process` | 外部プログラムの実行 | 不可 |
   | `disk` | ディスク・ボリューム・プロセスメモリを開く | 不可 |
   | `clipboard-read` | クリップボードの読み取り | 不可 |
   | `settings` | アプリの設定の変更 | 不可 |

4. メタデータ (AUTO-26) で宣言していない許可が必要な API を呼んだ場合は、その場で確認ダイアログを出す (対話的な実行のとき)。拒否すると `PermissionError`。
5. 「常に許可する」で与えた許可は、設定「信頼と許可」に一覧し、取り消せる。
6. ヘッドレス実行 (AUTO-41) では確認ダイアログを出せないため、次のどちらかで許可を与える。どちらもない場合は終了コード 5 で終わる。
   - 対話的な実行で「常に許可する」を選んだ記録がある。
   - コマンドラインの `--trust` と `--allow 許可,...` (利用者がコマンドで明示したことを許可とみなす)。
7. 管理者権限が必要な操作 (ディスクへの書き込みなど) は、スクリプトから呼んでも、アプリ本体と同じ確認 (01) を省略しない。
8. アプリ全体を管理者として実行している場合 (01 の ENG-28 の仕様 10、10 の PKG-04) は、スクリプトの実行とプラグインの読み込みの前に、毎回確認ダイアログを出す。
   - 本文: 「HexEditor は管理者として実行中です。このスクリプト (プラグイン) は管理者権限で動き、PC 全体に影響する操作ができます」と、名前とパス。
   - ボタン: 「実行する」「実行しない」(プラグインは「読み込む」「読み込まない」)。既定のボタンは「実行しない」(「読み込まない」)。
   - 仕様 1 の信頼の確認を出す場合は、同じダイアログにこの警告を加え、確認を 1 回にまとめる。「常に許可する」の記録があっても、この確認は省略しない。
   - 確認を出さないもの: 仕様 1 の「確認を出さないもの」と同じ (同梱のサンプル、アプリ内で保存したスクリプト、記録したマクロ、コンソールの入力)。
   - 起動時に自動で読み込むプラグインは、起動ごとに 1 回だけ、読み込むプラグインの一覧をまとめて確認する。「読み込まない」を選んだ場合は、その起動の間はプラグインを読み込まない。
   - ヘッドレス実行 (AUTO-41) では確認を出せないため、コマンドラインの `--trust` がある場合だけ実行する。ない場合は終了コード 5 で終わる。
9. 組織向けの設定: 設定ファイルの `scripts.policy` で「スクリプトとプラグインをすべて無効」「署名されたプラグインだけ」を指定できる。この設定がある場合は設定画面で変更できない。

**画面**: 信頼の確認ダイアログ、設定画面の「信頼と許可」(一覧と取り消し)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 許可がない API は `PermissionError`。

**受け入れ基準**:

- [ ] 初めて実行する JavaScript で確認ダイアログが出て、要求する許可が一覧される。
- [ ] スクリプトを外部のエディタで書き換えると、次の実行で再確認される。
- [ ] 「1 回だけ実行する」を選んだ場合、次の実行でも確認が出る。
- [ ] C# スクリプトの確認ダイアログに、完全信頼である旨の説明が出る。
- [ ] インターネットから取得したスクリプトで追加の警告が出る。
- [ ] ヘッドレス実行で許可がない場合、終了コード 5 で終わる。
- [ ] 管理者として実行中は、「常に許可する」を選んだスクリプトでも、実行の前に管理者権限で動く旨の確認が出る。
- [ ] 管理者として実行中に起動すると、自動で読み込むプラグインの確認が 1 回だけ出て、「読み込まない」を選ぶとプラグインが読み込まれない。
- [ ] `scripts.policy` で無効にすると、スクリプトのメニューが無効になり理由が表示される。

### AUTO-35 署名の確認

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-07 |
| 呼び出し | プラグインの追加時・読み込み時、C# スクリプト コンポーネントの追加時 |

**概要**: プラグインのアセンブリの Authenticode 署名を確認し、発行者を利用者に示す。

**仕様**:

1. プラグインのフォルダ内のすべての `.dll` の Authenticode 署名を確認する。状態は次の 3 つ。
   - 署名あり (有効): 発行者名を表示する。
   - 署名なし: 「署名されていません」と表示する (読み込みは可能。信頼の確認で警告を強める)。
   - 署名が無効 (改ざん、期限切れの証明書でタイムスタンプなし、失効): 読み込まない。
2. 設定「署名されたプラグインだけを読み込む」(既定: オフ)。オンの場合、署名なしのプラグインは読み込まない。
3. 信頼済みの発行者の一覧: 信頼の確認で「この発行者を常に信頼する」を選ぶと、同じ発行者の署名のあるプラグインは以後確認を出さない。一覧から取り消せる。
4. スクリプト (`.js`、`.csx`) の署名には対応しない。スクリプトは内容のハッシュで識別する (AUTO-34)。
5. 失効の確認は Windows の署名の検証 (`WinVerifyTrust`) に任せる。ネットワークに接続できない場合、および `network.offline` (09 の UI-58) が `true` の場合 (キャッシュだけを使い、接続しない) は、確認できなかった旨を表示し、署名ありとして扱う。

**画面**: プラグインマネージャと信頼の確認ダイアログの署名の表示。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**: 1 のとおり。

**受け入れ基準**:

- [ ] 署名のあるプラグインで発行者名が表示される。
- [ ] DLL を 1 バイト書き換えたプラグインが「署名が無効」で読み込まれない。
- [ ] 「署名されたプラグインだけ」をオンにすると署名なしのプラグインが読み込まれない。

## コマンドライン

### AUTO-36 コマンドラインの共通仕様

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-08 |
| 呼び出し | `hexed` (コンソール用の実行ファイル)、`HexEditor.exe` (GUI の実行ファイル、ファイルを開く用途) |

**概要**: コマンドラインからファイルを開く・ハッシュを計算する・比較する・スクリプトを実行するなどの操作を行う。結果を標準出力に出し、終了コードで成否を返す。

**仕様**:

1. 実行ファイルは 2 つ。
   - `HexEditor.exe`: GUI のアプリ本体 (Windows サブシステム)。ファイルを開く用途 (AUTO-37) の引数と `--unregister` (仕様 9) だけを受け付ける。コンソールに出力しない。
   - `hexed.exe`: コンソール用の小さな実行ファイル (コンソールサブシステム)。全サブコマンドを受け付ける。ヘッドレスのサブコマンドは WinUI を読み込まずに `HexEditor.Core` だけで実行する。`open` サブコマンドは GUI に処理を渡す。
   - 配布形態ごとの呼び出し方 (詳細は 10 の PKG-03、PKG-05、PKG-08):

     | 配布形態 | `hexed` の呼び出し方 |
     | --- | --- |
     | MSIX | App Execution Alias で `hexed.exe` と `hexeditor.exe` を登録する。どのフォルダからでも `hexed` で呼べる |
     | インストーラ | インストール時にユーザーの PATH にアプリのフォルダを追加する (既定: 追加する。設定画面で外せる)。`hexed` で呼べる |
     | ポータブル | PATH は変えない。`<展開したフォルダ>\hexed.exe` をフルパスで呼ぶか、利用者が自分で PATH に追加する。`README.txt` に書く |

2. 書式: `hexed <サブコマンド> [引数] [オプション]`。サブコマンドを省略して `hexed ファイル` と書いた場合は `open` とみなす。

   | サブコマンド | 内容 | 機能 |
   | --- | --- | --- |
   | `open` | GUI で開く | AUTO-37 |
   | `hash` | ハッシュ・チェックサムの計算と検証 | AUTO-38 |
   | `dump` | Hex ダンプの出力 | AUTO-39 |
   | `compare` | 2 つのファイルの比較 | AUTO-40 |
   | `run` | スクリプトのヘッドレス実行 | AUTO-41 |
   | `template` | テンプレートを適用して結果を出力 | AUTO-42 |
   | `patch` | パッチの適用 | AUTO-43 |
   | `convert` | 形式の変換 (Intel HEX など) | AUTO-44 |
   | `find` | 検索して一致の位置を出力 | AUTO-44 |

3. 共通のオプション: `--help` / `-h` (使い方)、`--version`、`--quiet` / `-q` (結果以外を出さない)、`--format text|json` (出力の形式。既定 `text`)、`--output` / `-o パス` (標準出力の代わりにファイルに出す)、`--lang 言語タグ` (メッセージの言語)、`--no-color`。
4. オフセット・長さ・範囲を受け取るオプションは、入力式 (00 の 6 章) を受け付ける。接頭辞のない数値は 10 進とする (コマンドラインでは表示状態がないため)。範囲は `開始:長さ` または `開始..終了` (終了は含まない)。PowerShell では `$` が変数として解釈されるため、`$1F00` の形は引用符で囲む必要がある旨をヘルプに書く。
5. 出力:
   - 結果 (ハッシュ値・ダンプ・JSON など) は標準出力に UTF-8 で出す。進捗・警告・エラーは標準エラー出力に出す。
   - メッセージは表示言語に従って訳す。結果の書式・JSON のキーは訳さない (機械で読むため)。
   - JSON の出力には `"schema": "hexeditor.<サブコマンド>/1"` を含め、形式の版を示す。
   - 標準エラー出力が端末の場合は、長い処理の進捗を 1 行で表示する (リダイレクト時は出さない)。
6. Ctrl+C でキャンセルし、終了コード 6 で終わる。書きかけの出力ファイルは削除する。
7. 終了コード (全サブコマンド共通):

   | コード | 意味 |
   | --- | --- |
   | 0 | 成功 (`compare`: 一致、`find`: 見つかった、`hash --check`: すべて一致) |
   | 1 | 処理は成功したが結果が否定 (`compare`: 違いがある、`find`: 見つからない、`hash --check`: 不一致がある、`patch --verify`: 検証に失敗) |
   | 2 | 引数の誤り (不明なオプション、入力式の誤りなど) |
   | 3 | 入出力のエラー (ファイルがない、読めない、書けない、空き容量不足) |
   | 4 | スクリプト・テンプレートのエラー (構文エラー、実行時の例外) |
   | 5 | 許可がない (信頼されていないスクリプト、アクセス拒否、管理者権限が必要) |
   | 6 | キャンセルされた (Ctrl+C) |
   | 7 | 上限を超えた (スクリプトの実行時間・メモリ、`--timeout`) |
   | 8 | 形式のエラー (Intel HEX のチェックサムの誤り、壊れたパッチなど) |
   | 10 | 内部エラー (想定外の例外。詳細はログ) |

8. ヘッドレスのサブコマンドは GUI のインスタンスの有無に関係なく、そのプロセスの中で完結する。設定 (ハッシュの既定のアルゴリズムなど) は GUI と同じ設定ファイルを読み取り専用で読む。

### AUTO-37 ファイルを開くコマンド

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-08 |
| 呼び出し | `hexed open ...`、`hexed ファイル ...`、`HexEditor.exe ファイル ...` |

**概要**: ファイル・ディスク・プロセスを、位置・選択範囲・読み取り専用などを指定して GUI で開く。既に起動しているアプリがあれば、そのウィンドウのタブとして開く。

**仕様**:

1. 書式: `hexed open [パス...] [オプション]`
2. オプション:

   | オプション | 内容 |
   | --- | --- |
   | `--offset 式` / `-g 式` | カーソルをその位置に置く |
   | `--select 範囲` | その範囲を選択する (`開始:長さ` / `開始..終了`) |

   | `--volume ドライブ` | 論理ボリュームを開く (例: `--volume C:`) |
   | `--process PID または名前` | プロセスメモリを開く |
   | `--encoding 文字コード` | テキスト列の文字コード |
   | `--template 名前またはパス` | テンプレートを適用して開く |
   | `--compare パス1 パス2` | 2 つのファイルを比較の画面で開く |
   | `--run スクリプト` | 開いた後にスクリプトを実行する (信頼の確認は通常どおり) |
   | `--new-window` | 新しいウィンドウで開く (既存のインスタンスがあればその中に新しいウィンドウを作る)。設定 `window.openExternalIn` (09 の UI-15) より優先する。パスを指定しなければ空の新しいウィンドウを開く (ファイル > 新しいウィンドウ、Ctrl+Shift+N と同じ。09 の UI-14) |
   | `--new-document` | 新しい空のドキュメントを開く (ファイル > 新規作成、Ctrl+N と同じ。タスクバーのジャンプリストの「新規作成」が使う。09 の UI-35)。既存のインスタンスがあればそのウィンドウで開く |

   | `--wait` / `-w` | 開いたドキュメントがすべて閉じられるまで `hexed` を終了しない (外部ツールのエディタとして使うため)。`hexed` だけで使える |
   | `--safe-mode` | セーフモード (AUTO-30 の 8) で起動する。新しく起動する場合だけ有効 |
   | `--write-block` | アプリ全体の書き込み保護モード (12 の FOR-01) を有効にして起動する。最初のドキュメントを開く前に有効になる。既存のインスタンスに渡した場合は、そのインスタンスの書き込み保護を有効にする (コマンドラインから無効にはできない) |
   | `--pseudo-locale qps-ploc` / `qps-plocm` | 疑似翻訳 (09 の UI-46) で表示して起動する。設定 `ui.language` は変えず、そのプロセスの間だけ有効。新しく起動する場合だけ有効。疑似翻訳を同梱しない安定版では、`hexed` は終了コード 2 (「この版では使えません」) で終わり、`HexEditor.exe` はこのオプションを無視してログに記録する |
   | `--plugin-dev フォルダ` | 開発用のフォルダのプラグインを読み込んで起動する (AUTO-33)。新しく起動する場合だけ有効 |
   | `--ui-lang 言語タグ` | 表示言語を指定して起動する (23 言語のどれか。例: `--ui-lang ar`)。設定 `ui.language` は変えず、そのプロセスの間だけ有効。新しく起動する場合だけ有効。`hexed` 共通の `--lang` (メッセージの言語) とは別 |
   | `--test-profile フォルダ` | 設定・最近使ったファイル・セッション・復旧用データ・付随データをすべて指定のフォルダに置いて起動する。普段の設定を読まず、書き換えない。新しく起動する場合だけ有効で、既存のインスタンスには渡さない ([../test/00-test-strategy.md](../test/00-test-strategy.md) の 8.3) |
   | `--test-hooks 設定ファイル` | 異常を再現する仕組み (遅い読み込み、I/O エラー、強制終了など) を有効にして起動する。テスト用のビルドだけで使え、製品版では終了コード 2 (「この版では使えません」) で終わる ([../test/00-test-strategy.md](../test/00-test-strategy.md) の 7.2) |

3. 単一インスタンスの処理 (F0-16。GUI 側の動作は 09 の UI-15):
   1. `hexed` は相対パスを自分のカレントフォルダを基準に絶対パスに変換してから、`HexEditor.exe` に渡す (既存のインスタンスとカレントフォルダが違っても正しく開くため)。
   2. `HexEditor.exe` は既存のインスタンスがあれば、`AppInstance` のリダイレクトで引数をそのインスタンスに渡し、すぐに終了する。既存のインスタンスはファイルをタブとして開き、ウィンドウを前面に出す。
   3. 既存のインスタンスがない、または `--new-instance` の場合は、新しく起動する。
4. 同じファイルが既に開いている場合は、そのタブをアクティブにし、`--offset` / `--select` を適用する。
5. `hexed open` の終了コードは、GUI に引き渡せた時点で 0 (`--wait` の場合はドキュメントが閉じられた時点で 0)。開く処理自体の失敗 (ファイルがないなど) は GUI 側で表示する。ただし `hexed` の時点で分かる誤り (引数の誤り、パスが存在しない) は `hexed` が終了コード 2 / 3 で返す。
6. 管理者権限が必要なディスク・プロセスの指定は、GUI 側の通常の手順 (補助プロセスの昇格、管理者として実行中は同じプロセスで処理、どちらも使えない場合は案内ダイアログ。01 の ENG-28) に従う。

**画面**: 該当なし (開いた結果は GUI のタブ)。

**巨大ファイル・長時間処理**: 開く処理は 01 と同じ (サイズに関係なく 1 秒以内に先頭を表示)。`--offset` で末尾近くを指定しても同じ。

**エラー**: 5 のとおり。

**受け入れ基準**:

- [ ] `hexed open a.bin --offset 0x1000 --select 0x1000:0x10` で、カーソルと選択が指定どおりになる。
- [ ] アプリの起動中に別のフォルダから `hexed b.bin` を実行すると、既存のウィンドウに `b.bin` のタブが開く。
- [ ] `--new-instance` で別のプロセスが起動する。
- [ ] `--wait` で、タブを閉じるまで `hexed` が終わらない。
- [ ] 100 GB のファイルを `--offset end-16` で開いて 1 秒以内に表示される。
- [ ] 存在しないパスで `hexed` が終了コード 3 になる。

### AUTO-38 ハッシュの計算と検証 (hash)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-08 |
| 呼び出し | `hexed hash ...` |

**概要**: ファイルのハッシュ・チェックサムを計算して出力する。チェックサムファイル (TOOL のチェックサムファイル機能と同じ形式) の検証もできる。

**仕様**:

1. 書式: `hexed hash [パス...] [--algorithm ID,...] [--range 範囲] [--format text|json|gnu|bsd] [--check チェックサムファイル] [--recurse]`
2. `--algorithm` / `-a`: 06 のアルゴリズム ID をカンマ区切りで指定する。既定は `sha256`。`--algorithm list` で使える ID の一覧を出す。プラグインのアルゴリズムも使える (プラグインの読み込みは AUTO-30 の信頼済みのものだけ)。
3. パスにはワイルドカード (`*.bin`) とフォルダを指定できる。フォルダは `--recurse` でサブフォルダも含める。パスを `-` にすると標準入力を読む。
4. 出力の形式:
   - `text` (既定): `アルゴリズム  値  パス` を 1 行ずつ
   - `gnu`: `値  パス` (GNU coreutils の `sha256sum` と同じ。そのままチェックサムファイルになる)
   - `bsd`: `SHA256 (パス) = 値`
   - `json`: ファイルごとのオブジェクトの配列
5. `--check ファイル`: チェックサムファイル (`.sha256`、`.md5`、`SHA256SUMS`、`.sfv` など。形式は自動判定、11 と同じ) を読み、各ファイルを検証して `OK` / `FAILED` / `MISSING` を出力する。
6. 複数のアルゴリズムは 1 回の読み込みで同時に計算する。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: ストレージの読み込み速度で計算する。進捗は標準エラー出力 (端末の場合)。

**エラー**: 読めないファイルはそのファイルの行にエラーを出して続け、最後に終了コード 3 を返す。

**受け入れ基準**:

- [ ] `hexed hash a.bin -a sha256 --format gnu` の出力が `sha256sum a.bin` と一致する。
- [ ] `hexed hash --check SHA256SUMS` で、1 つ改ざんしたファイルがあると `FAILED` が出て終了コード 1 になる。
- [ ] 10 GB のファイルの SHA-256 が、ストレージの読み込み速度の 80% 以上で計算される (CPU が律速でない場合)。

### AUTO-39 Hex ダンプの出力 (dump)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 3 提案) |
| 呼び出し | `hexed dump ...` |

**概要**: ファイルの指定範囲を Hex ダンプとして標準出力に出す。エクスポート (11) と同じ形式を使える。

**仕様**:

**受け入れ基準**:

- [ ] `--style xxd` の出力が `xxd` の出力と一致する (同じ幅の場合)。

### AUTO-40 ファイルの比較 (compare)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-08 |
| 呼び出し | `hexed compare ...` |

**概要**: 2 つのファイルを比較し、差分を出力する。終了コードで一致・不一致を返す。

**仕様**:

1. 書式: `hexed compare パス1 パス2 [--mode byte|resync] [--range1 範囲] [--range2 範囲] [--max 件数] [--format text|json] [--brief]`
2. `--mode byte` (既定): 同じオフセットのバイトどうしを比較する (06 の単純比較)。`resync`: 挿入・削除を考慮した比較 (06)。
3. 出力 (`text`): 差分の範囲ごとに `種類 (変更 / 挿入 / 削除)  オフセット1  オフセット2  長さ` と、短い差分 (16 バイト以下) は両方の Hex 値。最後に差分の件数と合計バイト数。
4. `--brief`: 一致・不一致だけを 1 行で出す。最初の差分で比較を打ち切る。
5. `--max`: 出力する差分の件数の上限 (既定 1,000。超えた分は件数だけ数える)。
6. 長さが違うファイルの `byte` モードでは、短いほうの末尾以降を「片方にだけある」差分として出す。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: `byte` モードは両ファイルを並行して読み、ストレージの読み込み速度で比較する。`resync` モードの上限は 06 に従う。

**エラー**: 読めないファイルは終了コード 3。

**受け入れ基準**:

- [ ] 同じファイルどうしで終了コード 0、1 バイト違うファイルで終了コード 1 になる。
- [ ] `--brief` が最初の差分で終わる (100 GB のファイルの先頭に差分がある場合に 1 秒以内)。
- [ ] `--format json` の差分が、GUI の比較結果と一致する。

### AUTO-41 スクリプトのヘッドレス実行 (run)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-08 |
| 呼び出し | `hexed run ...` |

**概要**: GUI を起動せずにスクリプトを実行する。一括処理やビルドの工程に組み込むために使う。

**仕様**:

1. 書式: `hexed run スクリプト [ファイル...] [--arg 名前=値]... [--trust] [--allow 許可,...] [--save | --save-as パス | --dry-run] [--timeout 秒] [--readonly]`
2. 引数のファイルを開いた状態でスクリプトを始める。`app.documents` に開いた順に入り、最初のファイルが `app.activeDocument` になる。
3. `--arg`: パラメータ (AUTO-26) の値を与える。宣言していない名前も `script.args` に入る。
4. 保存の扱い:
   - 既定: スクリプトが `doc.save()` を呼んだドキュメントだけ保存する。終了時に未保存の変更が残っていれば、保存せずに警告を標準エラー出力に出す。
   - `--save`: 終了時に変更のあるドキュメントをすべて保存する。
   - `--save-as パス`: 最初のドキュメントを指定したパスに保存する (元のファイルは変えない)。
   - `--dry-run`: 保存を一切行わない (`doc.save()` は何もせず成功を返す)。変更の要約 (ドキュメントごとの変更バイト数) を標準エラー出力に出す。
5. 許可は AUTO-34 の 6 に従う。
6. `console.log` は標準出力、`console.warn` / `console.error` と `ui.message` は標準エラー出力に出す。`ui.prompt` などは AUTO-16 の 4 に従う。
7. `--timeout`: スクリプト全体の経過時間の上限 (秒)。超えると終了コード 7。
8. スクリプトの終了コードは `app.exit(コード)` で指定できる (0〜255。ただし 2〜10 は共通の意味 (AUTO-36) と重なるため、スクリプト独自の意味には 64 以上を使うようヘルプで案内する)。
9. C# スクリプトの実行にはコンポーネント (AUTO-03) が必要。ない場合は終了コード 3 と、追加のしかたを出す。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: GUI と同じ一括処理 API を使える。進捗は標準エラー出力 (端末の場合)。

**エラー**: 構文エラー・実行時の例外は終了コード 4 (標準エラー出力にファイル名・行・メッセージ)。

**受け入れ基準**:

- [ ] `hexed run xor.js a.bin --arg key=5A --save` で、a.bin が XOR されて保存される。
- [ ] `--dry-run` でファイルが変わらず、変更の要約が出る。
- [ ] 信頼されていないスクリプトが `--trust` なしで終了コード 5 になる。
- [ ] 例外を投げるスクリプトで終了コード 4 と行番号が出る。
- [ ] `app.exit(70)` で終了コード 70 になる。

### AUTO-42 テンプレートの適用と JSON 出力 (template)

| 項目 | 内容 |

**仕様**:

1. 書式: `hexed template パス [--template 名前またはパス | --auto] [--offset 式] [--format json|csv|text] [--depth 深さ] [--fields パス,...]`
2. `--auto`: 自動適用 (07) と同じ判定でテンプレートを選ぶ。合うものがなければ終了コード 1。
3. 出力:
   - `json`: AUTO-13 の `toJSON()` と同じ構造 (名前・型・開始・長さ・値・表示値・子)。
   - `csv`: 1 行 1 フィールド (パス・型・開始・長さ・値)。
   - `text`: インデント付きのツリー。
4. `--fields`: 出力するフィールドをパスで絞る (例: `--fields header.e_lfanew,sections[*].name`)。
5. `--depth`: 出力するツリーの深さの上限。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: テンプレートの上限 (07) に従う。出力はストリームで書く。

**エラー**: テンプレートのエラーは終了コード 4 (行・列を含む)。

**受け入れ基準**:

- [ ] PE ファイルに `--template pe` を適用した JSON が、GUI のテンプレートパネルの内容と一致する。
- [ ] `--fields` で指定したフィールドだけが出力される。
- [ ] `--auto` で PNG ファイルに PNG のテンプレートが選ばれる。

### AUTO-43 パッチの適用 (patch)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F3-08 |
| 呼び出し | `hexed patch ...` |

**概要**: パッチファイル (IPS・IPS32・UPS・BPS・独自形式 `.hexpatch`。03 の EDIT-42・EDIT-43 と 11 の TOOL-12) をファイルに適用する。

**仕様**:

1. 書式: `hexed patch 対象 パッチ (-o 出力パス | --in-place) [--format auto|ips|ips32|ups|bps|hexpatch] [--verify-before ハッシュ] [--verify-after ハッシュ] [--dry-run]`
   - `--format auto` (既定) はパッチのヘッダで形式を判別する (EDIT-43 の 1 と同じ規則)。UPS・BPS・`.hexpatch` は、パッチに記録された変換前の識別情報 (CRC-32 など) の確認も EDIT-43 と同じく行い、合わなければ適用せず終了コード 1。
2. 出力先は `-o` か `--in-place` のどちらかを必ず指定する (誤って元のファイルを変えないため)。どちらもない場合は終了コード 2。
3. `--in-place` は GUI の保存と同じ安全な方式 (一時ファイルに書いてから置き換える) で書く。
4. `--verify-before`: 適用前の対象のハッシュ (`アルゴリズム:値`、例: `sha256:ab12...`) を確認し、違えば適用せずに終了コード 1。`--verify-after`: 適用後のハッシュを確認し、違えば出力を書かずに終了コード 1。
5. `--dry-run`: 適用せずに、パッチのレコード数・変更されるバイト数・長さの変化を出力する。
6. パッチの形式の判定と適用の規則は 03 の EDIT-43 と 11 の TOOL-12 (IPS / IPS32 の形式) に従う。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: 適用はデータエンジンの操作で行い、保存はストリームで書く。

**エラー**: 壊れたパッチは終了コード 8 (どのレコードかを出す)。

**受け入れ基準**:

- [ ] IPS パッチを `-o` で適用した結果が、GUI で同じパッチを適用して保存した結果と一致する。
- [ ] `-o` も `--in-place` もない場合に終了コード 2 になる。
- [ ] `--verify-before` が合わない場合、出力ファイルが作られず終了コード 1 になる。

### AUTO-44 形式の変換と検索 (convert, find)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 3 提案) |
| 呼び出し | `hexed convert ...`、`hexed find ...` |

**概要**: インポート・エクスポート形式 (11) の変換と、ファイルの検索をコマンドラインから行う。

**仕様**:

1. `hexed convert 入力 出力 [--from 形式] [--to 形式] [形式ごとのオプション]`
   - 形式は 11 のインポート・エクスポート形式の ID (例: `bin`、`ihex`、`srec`、`base64`、`uu`、`hextext`、`c`)。省略時は拡張子と内容から判定する。
   - 形式ごとのオプションは 11 のダイアログの項目と同じ名前にする (例: `--record-length 32`、`--fill FF`、`--address-mode linear`)。
   - Intel HEX・S-record のチェックサムの誤りは終了コード 8。`--ignore-checksum` で無視する。
2. `hexed find パス... (--hex パターン | --text 文字列 | --regex 式) [--encoding 文字コード] [--case-sensitive] [--range 範囲] [--max 件数] [--format text|json]`
   - 一致ごとに `パス  オフセット  長さ` を出力する。ワイルドカードは 00 の 6.3 に従う。
   - 一致があれば終了コード 0、なければ 1。

**画面**: 該当なし。

**巨大ファイル・長時間処理**: どちらもストリーム処理。`find` の速度は 04 と同じ。

**エラー**: 1 のとおり。その他は AUTO-36。

**受け入れ基準**:

- [ ] `hexed convert fw.hex fw.bin` の結果が、GUI でインポートして保存した結果と一致する。
- [ ] `hexed convert fw.bin fw.hex --to ihex` の出力を再び `convert` で戻すと、元と一致する。
- [ ] `hexed find a.bin --hex "DE AD ?? EF"` がワイルドカードで一致する位置を出す。

## 外部からの自動操作

### AUTO-45 名前付きパイプによる JSON-RPC

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | 設定「設定 > スクリプト > 外部からの自動操作」(既定: 無効) |

**概要**: 他のプログラム (PowerShell、Python、テストツールなど) から、実行中のアプリを操作できるようにする。名前付きパイプ上の JSON-RPC 2.0 で、スクリプトと同じ API を公開する。

**仕様**:

1. **方式の決定 (COM ではなく JSON-RPC を採用する理由)**:

   | 観点 | JSON-RPC (名前付きパイプ) | COM (アウトプロセスサーバー) |
   | --- | --- | --- |
   | 3 種類の配布形態 | どれも同じ実装で動く (登録不要) | レジストリへのクラス登録が必要。ポータブル版では登録の後始末が問題になり、MSIX 版ではマニフェストでの宣言が別に必要 |
   | 呼び出し元の言語 | ソケットとパイプを扱える言語なら何でもよい (Python、PowerShell、Node.js、Go など) | VBScript・VBA・PowerShell からは簡単。Python などは追加ライブラリが必要 |
   | API の定義 | AUTO-04 の型定義から自動生成できる | 型ライブラリを別に保守する必要がある |
   | アクセス制御 | パイプの ACL で同じ利用者に限定できる | DCOM の設定が複雑 |

   VBA などから使いたい場合は、JSON-RPC を呼ぶ PowerShell モジュール (`HexEditor.Automation`、配布物に同梱) を経由する。
2. パイプ名: `\\.\pipe\HexEditor.<ユーザーの SID>.rpc`。ACL で現在の利用者だけに接続を許し、`PIPE_REJECT_REMOTE_CLIENTS` でネットワーク経由の接続を拒否する。
3. 有効にするには設定で明示的にオンにする (既定はオフ)。オンの間は、ステータスバーに「外部からの自動操作: 有効」のアイコンを表示する。
4. 接続してきたプロセスの実行ファイルのパスを `GetNamedPipeClientProcessId` で調べ、初めての実行ファイルなら信頼の確認 (AUTO-34 と同じ形式、許可の種類も同じ) を出す。許可した実行ファイルは設定に記録し、取り消せる。
5. メソッドは AUTO-04 の API を `オブジェクト.メソッド` の名前で公開する (例: `document.readBytes`、`app.open`)。ドキュメントは `id` で指定する。バイト列は Base64 の文字列で渡す。イベント (AUTO-06) は JSON-RPC の通知として送る (購読したものだけ)。
6. 1 回の要求・応答の上限は 64 MB。大きなデータは `exportRange` や `app.open` でファイルを介して扱う。
7. 外部からの操作による編集も、スクリプトと同じく Undo できる。操作中のドキュメントには InfoBar「外部から操作されています: プログラム名」を出す。
8. JSON-RPC の仕様書 (メソッド一覧と例) は AUTO-04 の型定義から生成して配布する。

**画面**: 設定画面の「外部からの自動操作」(オン / オフ、許可した実行ファイルの一覧)、ステータスバーのアイコン、接続の確認ダイアログ。

**巨大ファイル・長時間処理**: 一括処理のメソッドは非同期で、進捗を通知として送る。クライアントは `$/cancel` 通知でキャンセルできる。

**エラー**: JSON-RPC のエラー応答で返す。エラーコードは AUTO-04 の 9 の例外の種類に対応させる (`PermissionError` は -32001 など、一覧は仕様書に載せる)。

**受け入れ基準**:

- [ ] 設定がオフの間はパイプが存在しない。
- [ ] Python から接続し、`app.open` と `document.readBytes` が動く。
- [ ] 別の利用者のプロセスからは接続できない。
- [ ] 初めての実行ファイルからの接続で確認ダイアログが出て、拒否すると接続が切られる。
- [ ] 同梱の PowerShell モジュールで、開いているドキュメントの一覧を取得できる。

# 機能仕様書: 検索・置換

この文書は、検索バー、各種の検索 (Hex・テキスト・数値・正規表現)、すべて検索、置換、複数ファイル検索、文字列の抽出、YARA スキャンの振る舞いを定める。共通の書式・用語・入力式・ショートカットは [00-overview.md](00-overview.md) に従う。

対象とするロードマップの ID: F0-11、F1-07、F1-08、F1-09、F1-10、F2-07、F2-08、F2-17、F4-05。ロードマップにない機能は、調査 ([../research/feature-survey.md](../research/feature-survey.md) の 2.5 節) をもとに「追加」として含める。

## 1. 検索エンジンの共通仕様

この章の機能は、2 章以降のすべての検索 (検索バー、すべて検索、置換、複数ファイル検索、文字列の抽出、YARA) が共通で使う。

### FIND-01 チャンク単位の検索と境界の重なり

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 |
| 呼び出し | なし (すべての検索が内部で使う) |

**概要**: ドキュメント全体をメモリに読み込まず、一定サイズのチャンクごとに読み込んで検索する。チャンクの境界にまたがる一致を取りこぼさないよう、境界を重ねて読む。

**仕様**:

1. 検索は `IByteSource` ではなく、データエンジンのスナップショット (FIND-03) を対象にする。編集中の未保存の変更も検索対象に含む。変換ビュー (EDIT-45) が有効なタブでは、表示されている変換後のデータを対象にし、変換ビューが無効なら元のデータを対象にする (EDIT-45 の 11)。
2. チャンクの既定サイズは 4 MiB。設定で 256 KiB〜64 MiB の範囲で変更できる。
3. 前のチャンクの末尾 `重なり幅` バイトを次のチャンクの先頭に含めて読む。重なり幅は次のとおり。
   - 長さが固定のパターン (Hex、テキスト、数値): `パターンの最大長 - 1` バイト。
   - 長さが変わるパターン (正規表現、ワイルドカードを含む可変長の指定): 「一致の最大長」 (既定 4,096 バイト、設定で 1〜1,048,576 バイト) `- 1` バイト。一致の最大長を超える一致は見つからない。この制限は検索バーの正規表現オプションの説明文に表示する。
   - 正規表現は、さらに「文脈」(一致の最大長と 1,024 バイトの小さい方。以下 C) を重ねる (重なり幅は「一致の最大長 + C − 1」)。正規表現はチャンクを 256 KiB ごとの区間 (ドキュメントの位置で決まる区切り) に分けて復号・照合し、区間の前の C バイトと後ろの「一致の最大長 + C」バイトを文脈として読む。後読み・先読み・`\b`・`^`・`$` は、一致の前後 C バイトまでのデータで判定する (範囲の端・読めない範囲の境界は入力の端として扱う)。一致の最大長を超える一致は報告せず、その一致の末尾の後ろから探し続ける。このため、一致の最大長より長い繰り返し (例: 長い `00` の並びに対する `\x00+`) の中では、報告される一致の位置が区間の区切りによって変わることがある。メモリ使用量は区間 1 つ分 (並列数あたり数 MiB) で、ファイルサイズに比例しない。
4. 重なり部分で見つかった一致は、一致の開始位置で重複を取り除き、1 回だけ報告する。
5. リテラルのバイト列 (ワイルドカードなし、大文字・小文字を区別する) の検索には `Span.IndexOf` と `SearchValues<byte>` を使い、SIMD 命令で処理する。
6. 先頭バイトの候補を `SearchValues` で絞り込み、候補の位置だけを詳しく照合する方式を、ワイルドカード、大文字・小文字を区別しないテキスト、数値検索で使う。
7. すべて検索 (FIND-20) と複数ファイル検索 (FIND-30) は、チャンクを複数のスレッドで並列に処理する。並列数の既定は「論理プロセッサ数 - 1 (最小 1、最大 8)」。次 / 前を検索 (FIND-09) は 1 スレッドで照合し、別の 1 スレッドで次のチャンクを先読みする。
8. 後方検索では、チャンクを末尾側から先頭側へ順に読み、チャンク内では最後の一致から報告する。
9. 物理ディスクなどセクタ境界での読み込みが必要なデータソースでは、チャンクの開始位置と長さをセクタサイズの倍数に揃える。揃えるのはデバイスへの読み込みで、データソース (01 の ENG-29 の仕様 6) とブロックキャッシュ (ブロックの大きさはセクタサイズの倍数) が行う。検索の照合の範囲 (チャンクの論理的な区切り) はセクタの途中でもよい。

**画面**: なし。

**巨大ファイル・長時間処理**: メモリ使用量は `チャンクサイズ × (並列数 + 1) + 重なり幅` 程度に収め、ファイルサイズに比例させない。性能の目標は次のとおり (NVMe SSD、データが OS のキャッシュにない状態で測る)。速度はストレージと CPU に依存するため、「読み込み速度」は、同じ計測機で、同じストレージ上の同じファイルを 4 MiB 単位で先頭から順に読んだときの速度 (検索なしの読み込みだけの速度) とし、目標はこれとの比で判定する (00-overview.md 11.1)。リテラル以外の種類は CPU の処理が律速になりやすいため、「下表の値」と「読み込み速度の 80%」のうち小さい方を目標とする。下表の値は、性能テスト用の固定の計測機 (読み込み 2 GiB/s 以上の NVMe SSD) での値である。

| 検索の種類 | 目標 |
| --- | --- |
| リテラルのバイト列 | 読み込み速度の 80% 以上 (読み込み 1.25 GiB/s 以上のストレージで 1 GiB/s 以上) |
| ワイルドカード、大文字・小文字を区別しないテキスト | 500 MiB/s 以上 (読み込み速度の 80% がこれより遅い場合はその値) |
| 整数・浮動小数点 (許容誤差・範囲を含む) | 300 MiB/s 以上 (同上) |
| 正規表現 (後戻りしない方式) | 100 MiB/s 以上 (同上) |

**エラー**: 読み込みエラー (不良セクタ、デバイスの取り外しなど) が起きた場合は、読めなかった範囲 (データソースが範囲を特定できない場合は、その読み込み全体) を飛ばして検索を続けるか中止するかを InfoBar で選ばせる。読めなかったバイトを含む一致は報告しない (読めない部分は 0 で埋めて返るが、`00` として照合しない)。同じバイトについて尋ねるのは 1 回の検索につき 1 回だけとする (チャンクの重なり部分を読み直しても尋ね直さない)。「飛ばす」を選んだ場合は、その検索の残りの読めない範囲も尋ねずに飛ばす (1 回の検索で尋ねるのは最初の 1 回だけ)。InfoBar を答えずに閉じた場合は「飛ばす」とする。件数の数え上げ (FIND-12) とインクリメンタルサーチ (FIND-27) は利用者が明示的に始めた検索ではないため尋ねずに飛ばす (設定が「中止する」なら中止する)。既定の動作は設定で「確認する / 飛ばす / 中止する」から選べる (既定は「確認する」)。飛ばした範囲は結果一覧の「読み込めなかった範囲」に記録する。

**受け入れ基準**:

- [ ] チャンクの境界 (4 MiB の倍数の位置) をまたぐ 16 バイトのパターンが見つかる。
- [ ] 同じ一致が重なり部分で 2 回報告されない。
- [ ] 100 GiB のファイルの検索中、プロセスのメモリ使用量 (プライベートバイト) が 300 MiB を超えない (既定設定)。
- [ ] NVMe SSD 上の 10 GiB のファイルで、末尾にしかないリテラル 8 バイトの検索の速度 (10 GiB ÷ 検索の時間) が、同じ計測機で測った読み込み速度 (上記) の 80% 以上になる。性能テスト用の固定の計測機 (読み込み 2 GiB/s 以上) では 10 秒以内に終わる。リテラル以外の種類も上表の目標を満たす。
- [ ] チャンクサイズを 256 KiB と 64 MiB に変えても、同じ結果になる。

### FIND-02 進捗表示とキャンセル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 (基盤は F0-13) |
| 呼び出し | 検索バーのキャンセルボタン、処理センターのキャンセルボタン、検索バー内で Esc |

**概要**: 検索はすべてバックグラウンドで実行し、時間がかかる場合は進捗とキャンセルを提供する。

**仕様**:

1. 検索の開始から 0.5 秒たっても終わらない場合、検索バーに進捗バー (処理済みバイト数 / 対象バイト数) とキャンセルボタンを表示し、処理センターに登録する。
2. 処理センターには、進捗率、処理速度 (MB/s)、残り時間、これまでの一致件数を表示する。表示の更新は 250 ms ごと。
3. キャンセルの要求から 200 ms 以内に検索を止める。すべて検索でキャンセルした場合、それまでに見つかった結果は一覧に残し、一覧の見出しに「中断」と表示する。
4. 検索中も編集・スクロール・別の検索バー操作ができる。同じドキュメントで新しい検索を始めると、実行中の検索バーの検索 (次 / 前を検索) はキャンセルする。すべて検索・複数ファイル検索・文字列の抽出・YARA は、明示的にキャンセルするまで並行して続ける。
5. 検索が終わったとき、検索バーにフォーカスがなければ、ステータスバーに結果 (「12 件見つかりました」「見つかりませんでした」など) を 5 秒間表示する。

**画面**: 検索バーの右端に進捗バーとキャンセルボタン。ステータスバーの進捗表示から処理センターを開ける。

**巨大ファイル・長時間処理**: この機能自体が長時間処理の扱いを定める。

**エラー**: キャンセルは失敗しない。キャンセル後の結果は不完全であることを見出しで示す。

**受け入れ基準**:

- [ ] 10 GB のファイルの検索中に、進捗率・速度・残り時間が表示される。
- [ ] キャンセルボタンを押してから 200 ms 以内に、ディスクの読み込みが止まる。
- [ ] 検索中にカーソル移動とスクロールが 60 fps を保つ。
- [ ] すべて検索を途中でキャンセルすると、それまでの結果が一覧に残る。

### FIND-03 編集中のスナップショットに対する検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 |
| 呼び出し | なし (すべての検索が内部で使う) |

**概要**: 検索の開始時点のドキュメントの状態 (不変のスナップショット) を対象に検索し、検索中に編集しても結果が壊れないようにする。

**仕様**:

1. 検索の開始時に、データエンジンの現在のルート (不変のピースツリー) を取得し、検索が終わるまでそれだけを読む。検索中の編集は検索結果に影響しない。
2. 各一致は、検索したスナップショットの版を持つ (1 回の検索の結果のまとまりが、検索したスナップショットへの参照を持つ。スナップショットは不変なので、これが版番号の代わりになる)。
3. 結果を表示・ジャンプ・選択するときに、スナップショット以後の編集 (挿入・削除) に合わせて一致の位置をずらす。
   - 一致より前への挿入・削除: 位置をずらす。
   - 一致の範囲内が変更・削除された: 結果一覧でその行に「変更あり」の印を付ける。範囲がすべて削除された場合は「削除済み」とし、ジャンプは削除された位置に移動する。
4. Undo / Redo で状態がスナップショットの版に戻った場合、印を外す。
5. 置換 (FIND-22、FIND-23) は、置換の時点の最新の状態で一致を確認し直してから書き換える。一致しなくなっていた箇所は置換しない。

**画面**: 結果一覧の「状態」列に「変更あり」「削除済み」を文字とアイコンで表示する (色だけで示さない)。

**巨大ファイル・長時間処理**: スナップショットの取得はルートへの参照を保持するだけで、データをコピーしない (O(1))。

**エラー**: 外部変更の検知 (ENG-19) で元ファイルが再読み込みされた場合、その前のスナップショットの結果はすべて「古い結果」と表示し、再検索ボタンを出す。

**受け入れ基準**:

- [ ] すべて検索の実行中に、先頭に 100 バイト挿入しても、検索結果の件数が挿入前の状態と同じになる。
- [ ] 検索完了後に先頭へ 100 バイト挿入すると、結果一覧のジャンプ先が 100 バイト後ろにずれる。
- [ ] 一致の範囲を書き換えると、その行に「変更あり」が表示され、Undo で消える。

## 2. 検索バーと基本の検索

### FIND-04 検索バー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 |
| 呼び出し | 検索 > 検索、Ctrl+F、コマンドパレット「検索」 |

**概要**: エディタ上部に重ねて表示する非モーダルの検索バー。検索語の入力、検索の種類とオプションの選択、次 / 前を検索、すべて検索を 1 か所で行う。

**仕様**:

1. Ctrl+F で検索バーを開き、検索欄にフォーカスを移す。すでに開いている場合は検索欄の文字列を全選択する。
2. 開いたときに選択範囲があり、長さが 1〜256 バイトの場合は、その内容を検索欄に入れる。検索の種類が Hex のときは Hex 文字列、テキストのときは現在の文字コードで復号した文字列にする (復号できない場合は Hex に切り替える)。選択範囲が 257 バイト以上の場合は検索欄を変えず、検索範囲 (FIND-11) を「選択範囲」にする。
3. 検索の種類はドロップダウンで選ぶ: 「Hex」「テキスト」「整数」「浮動小数点」「正規表現 (テキスト)」「正規表現 (バイト列)」。既定は前回使った種類 (初回は Hex 列にカーソルがあれば Hex、テキスト列にあればテキスト)。機械語の命令のパターンで探す検索は検索バーには含めず、ANA-28 (命令パターン検索) が定める。
4. オプションは種類に応じて切り替えて表示する (各機能の項を参照)。共通のオプションは、方向 (FIND-09)、折り返し (FIND-09)、検索範囲 (FIND-11)、アラインメント条件 (FIND-17)。
5. 検索欄の中で次のキーを使う。これらは検索バーの有効範囲 (検索バー・置換バーにフォーカスがあるとき。00-overview.md 8.4) だけで有効で、グローバル・エディタの割り当てより優先する。
   - Enter: 次を検索。Shift+Enter: 前を検索。
   - Alt+Enter: すべて検索 (FIND-20)。
   - ↑ / ↓: 検索履歴 (FIND-28) をたどる。
   - Esc: 実行中の検索があれば取り消す (FIND-02)。実行中でなければ検索バーを閉じてエディタにフォーカスを戻す。したがって検索中は 1 回目の Esc で検索を取り消し、2 回目の Esc で閉じる。
6. 入力中の検索語はリアルタイムに検証する。不正な入力 (奇数桁の Hex、範囲外の数値、正規表現の構文エラーなど) は赤枠と説明文で示し、検索ボタンを無効にする。説明文には誤りの位置 (何文字目か) を含める。
7. 検索欄の横に、検索語を変換したバイト列の先頭 32 バイトを Hex で表示する (例: テキスト「AB」を UTF-16LE で検索する場合は `41 00 42 00`)。32 バイトを超える場合は末尾に「…(全 N バイト)」を付ける。
8. 検索が一致したら、一致した範囲を選択し、カーソルを一致の先頭に移動し、その位置が画面の中央付近に来るようにスクロールする。ジャンプ履歴 (VIEW-31) に記録する。
9. 表示中の範囲にある一致は、すべて強調表示する (設定で無効にできる)。強調表示は背景色と枠線で示し、ハイコントラストテーマではシステムの強調色の枠線を使う。強調表示の計算は画面に見えている範囲 (前後 1 画面分を含む) に限る。
10. 検索バーの状態 (種類、オプション、検索語) はドキュメントごとではなく、ウィンドウごとに保持する。タブを切り替えても検索語は変わらない。
11. 検索バーを閉じても、F3 / Shift+F3 で最後の条件の次 / 前を検索できる。
12. IME の変換中の文字は確定するまで検索に使わない (インクリメンタルサーチ (FIND-27) を含む)。
13. 変換ビュー (EDIT-45) が有効なタブで検索するときは、検索バーに「変換ビュー: XOR 5A」のような表示を出し、変換後のデータを検索していることを示す (FIND-01 の 1)。

**画面**: エディタ上部に重ねて表示する帯。1 行目: 種類のドロップダウン、検索欄、変換結果の表示、前を検索・次を検索・すべて検索のボタン、オプションの開閉ボタン、閉じるボタン。オプションを開くと 2 行目にオプションを並べる。置換時は検索欄の下に置換欄の行を加える (FIND-22)。幅が足りない場合はオプションを折り返す。右から左に書く言語では検索バーの並びを左右反転するが、検索欄と変換結果の Hex 表示は左から右にする。

**巨大ファイル・長時間処理**: 検索は FIND-01〜03 に従う。強調表示の計算は表示範囲だけを対象にし、スクロールのたびに再計算する (1 画面あたり 4 ms 以内)。

**エラー**: 一致しない場合、検索欄の枠を警告色にし、「見つかりませんでした」を検索欄の下に表示する (スクリーンリーダーにも通知する)。ダイアログは出さない。

**受け入れ基準**:

- [ ] Ctrl+F で検索バーが開き、検索欄にフォーカスがある。Esc で閉じるとエディタにフォーカスが戻る。
- [ ] 4 バイトを選択して Ctrl+F を押すと、その 4 バイトが Hex 文字列で検索欄に入る。
- [ ] `DE AD B` と入力すると赤枠と説明文が出て、検索ボタンが無効になる。
- [ ] 検索バーが開いていても、エディタをクリックして編集を続けられる。
- [ ] ナレーターで、検索結果 (見つかった位置、または見つからなかったこと) が読み上げられる。
- [ ] 日本語 IME で変換中の文字列が、確定前に検索されない。

### FIND-05 Hex バイト列の検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 |
| 呼び出し | 検索バーの種類「Hex」 |

**概要**: Hex 文字列で指定したバイト列を検索する。

**仕様**:

1. 入力は 00-overview.md の 6.3 節に従う。空白、カンマ、`0x`、`\x`、改行は区切りとして扱う。
2. 奇数桁の場合はエラーにする。ワイルドカードを使う場合は FIND-06 に従う。
3. 検索語の長さは 1 バイト〜1 MiB (1,048,576 バイト。Hex 文字列の文字数ではなく、変換後のバイト数で数える)。
4. 検索欄に、変換後のバイト数が 1 MiB を超える Hex 文字列を貼り付けた場合は、エラー「検索語は 1 MiB までです」を表示し、検索ボタンを無効にする。

**画面**: FIND-04 の検索バー。

**巨大ファイル・長時間処理**: FIND-01 に従う。

**エラー**: 不正な文字 (`G` など) は、その位置を示して「Hex として解釈できない文字があります (5 文字目: G)」と表示する。

**受け入れ基準**:

- [ ] `DEADBEEF`、`DE AD BE EF`、`0xDE,0xAD,0xBE,0xEF`、`\xDE\xAD\xBE\xEF` で同じ結果になる。
- [ ] `ABC` は奇数桁としてエラーになる。
- [ ] 1 MiB (1,048,576 バイト) ちょうどの検索語で検索でき、1,048,577 バイトではエラーになる。

### FIND-06 Hex のワイルドカード (バイト・ニブル)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-10 |
| 呼び出し | 検索バーの種類「Hex」で `??` または `?` を含める |

**概要**: Hex の検索語の中で、任意の 1 バイトや任意の 1 ニブルを指定して検索する。

**仕様**:

1. `??` は任意の 1 バイト、`?` は任意の 1 ニブル (4 bit) を表す。`A?` は上位ニブルが A のバイト、`?5` は下位ニブルが 5 のバイトに一致する。
2. `?` の数を含めて桁数が奇数の場合はエラーにする。
3. 可変長のワイルドカード `*` (0〜N バイトの任意の並び) を使える。`*` の最大長は「一致の最大長」(FIND-01、既定 4,096 バイト) まで。`*{0,16}` のように範囲を指定できる。`*` は最短一致とする。
4. 検索語の先頭と末尾をワイルドカードだけにはできない (先頭の `??` は一致の位置を不定にするため)。先頭または末尾が `??` / `*` の場合は警告「先頭と末尾のワイルドカードは無視されます」を表示し、取り除いて検索する。ただし一致の範囲にはその分を含める。
5. ワイルドカードだけの検索語はエラーにする。
6. 置換 (FIND-22) の置換語で `??` を指定した位置は、元のバイトをそのまま残す。

**画面**: FIND-04 の検索バー。ワイルドカードを含む場合、変換結果の表示ではワイルドカードの位置を `??` / `?` のまま表示する。

**巨大ファイル・長時間処理**: FIND-01 に従う。ワイルドカードでない最も長い連続部分を使って候補を絞り込み、候補の位置だけを照合する。

**エラー**: `?` の位置が不正な場合 (`???` など桁数が合わない) は、位置を示してエラーを表示する。

**受け入れ基準**:

- [ ] `4D 5A ?? ?? 50 45` が `4D 5A 90 00 50 45` に一致する。
- [ ] `A?` が `A0`〜`AF` のすべてに一致し、`B0` に一致しない。
- [ ] `4D 5A * 50 45` が、`4D 5A` と `50 45` の間に 0〜4,096 バイトある並びに一致し、間が 4,097 バイトの並びに一致しない。
- [ ] ワイルドカードを含む 10 GiB のファイルの検索が、FIND-01 の目標速度 (500 MiB/s と、同じ計測機で測った読み込み速度の 80% のうち小さい方) を満たす。

### FIND-07 テキストの検索 (文字コードの指定)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 |
| 呼び出し | 検索バーの種類「テキスト」 |

**概要**: 入力した文字列を指定の文字コードでバイト列に変換し、検索する。

**仕様**:

1. 文字コードは、表示の文字コード (F1-06 で対応するすべてのコードページ) から選ぶ。既定は「表示中の文字コードに合わせる」。少なくとも ASCII、ANSI (システムのコードページ)、OEM、EBCDIC、UTF-8、UTF-16LE、UTF-16BE、UTF-32LE、UTF-32BE、Shift_JIS、EUC-JP、GB18030、Big5、EUC-KR を選べる。
2. 入力した文字列を選んだ文字コードで符号化してから検索する。BOM は付けない。
3. 選んだ文字コードで表せない文字が含まれる場合は、その文字を示してエラーにする (置換文字 `?` に置き換えて検索しない)。
4. エスケープ表記 (オプション「エスケープ文字を使う」、既定オフ): `\n` `\r` `\t` `\0` `\\` `\xHH` (1 バイト)、`\uHHHH` (Unicode 文字) を使える。`\xHH` は符号化後のバイト列にそのまま入れる。
5. UTF-16 / UTF-32 では、オプション「文字の境界に揃える」(既定オフ) をオンにすると、一致の開始オフセットが 2 / 4 の倍数の位置だけを報告する。
6. 正規化 (NFC / NFD) は行わない。入力した文字列のコードポイントをそのまま符号化する。
7. 大文字・小文字を区別しない検索と単語単位の検索は FIND-10 に従う。

**画面**: 検索バーの 2 行目に文字コードのドロップダウン (検索できる一覧) と「エスケープ文字を使う」「文字の境界に揃える」のチェックボックス。

**巨大ファイル・長時間処理**: FIND-01 に従う。大文字・小文字を区別する場合はリテラルのバイト列検索と同じ速度。

**エラー**: 符号化できない文字は「この文字は Shift_JIS で表せません: 'ß' (3 文字目)」のように示す。

**受け入れ基準**:

- [ ] 「AB」を UTF-16LE で検索すると `41 00 42 00` に一致する。UTF-16BE では `00 41 00 42` に一致する。
- [ ] 「日本」を Shift_JIS で検索すると `93 FA 96 7B` に一致する。
- [ ] 「文字の境界に揃える」をオンにすると、奇数オフセットから始まる UTF-16 の一致が報告されない。
- [ ] `\x00` を含む検索語が、エスケープ文字オンで 0x00 を含むバイト列に一致する。

### FIND-08 複数の文字コードでの同時検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 検索バーの種類「テキスト」で文字コードに「複数」を選ぶ |

**概要**: 同じ文字列を複数の文字コードで一度に検索する。文字コードが分からないデータで使う。

**仕様**:

1. 文字コードのドロップダウンで「複数」を選ぶと、チェックボックス付きの一覧が開き、最大 8 種類を選べる。
2. 既定の組み合わせは「ASCII / UTF-8、UTF-16LE、UTF-16BE」。組み合わせは名前を付けて保存できる。
3. 各文字コードで符号化したバイト列を同時に検索する (FIND-26 の複数語検索と同じ方式)。符号化の結果が同じになる文字コード (英数字だけの文字列での ASCII と UTF-8 など) は 1 つにまとめ、結果には「ASCII / UTF-8」のように両方の名前を示す。
4. 次を検索では、どの文字コードでも最も近い一致に移動する。ステータスバーと検索バーに一致した文字コードを表示する。
5. すべて検索の結果一覧には「文字コード」列を加える。
6. 文字列を符号化できない文字コードは、その文字コードだけ除外し、警告を表示して残りで検索する。

**画面**: 文字コードのドロップダウンの「複数」項目、チェックボックス付きの一覧。

**巨大ファイル・長時間処理**: 1 回の読み込みですべての文字コードを照合する。文字コードの数に比例して読み込み回数を増やさない。

**エラー**: 選んだすべての文字コードで符号化できない場合はエラーにする。

**受け入れ基準**:

- [ ] 「Test」を ASCII / UTF-16LE / UTF-16BE で検索すると、3 種類の符号化それぞれの位置が 1 回の検索で見つかり、結果一覧に文字コードが表示される。
- [ ] 8 種類を選んでも、ファイルの読み込みは 1 回だけ行われる (読み込みバイト数がファイルサイズ + 重なり分以下)。

### FIND-09 次 / 前を検索、検索方向、折り返し

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 |
| 呼び出し | 検索 > 次を検索 (F3)、検索 > 前を検索 (Shift+F3)、検索バーの Enter / Shift+Enter とボタン |

**概要**: 現在の位置から前方または後方に向けて、次の一致を探す。末尾に達したら先頭に戻って続けられる。

**仕様**:

1. 検索の開始位置は次のとおり。
   - 次を検索: 現在の選択範囲が直前の検索の一致と同じなら「一致の開始 + 1」、そうでなければカーソル位置。
   - 前を検索: 現在の選択範囲が直前の検索の一致と同じなら「一致の開始 - 1」から後方に、そうでなければカーソル位置 - 1 から後方に探す。
2. 検索バーのオプション「方向」(前方 / 後方、既定は前方) は、Enter と「検索」ボタンの方向を決める。F3 は常に前方、Shift+F3 は常に後方。
3. 重なる一致: 次を検索は一致の開始 + 1 から探すため、重なる一致 (`AAAA` の中の `AA` など) も順に見つかる。
4. 折り返し (オプション「折り返す」、既定オン): 検索範囲の末尾 (後方では先頭) まで一致がなければ、範囲の反対側から開始位置まで続ける。折り返したときは、検索バーとステータスバーに「先頭に戻って検索しました」を表示し、スクリーンリーダーにも通知する。
5. 折り返しがオフで一致がない場合は「末尾まで見つかりませんでした」と表示する。
6. 開始位置から範囲全体を一周しても一致がない場合は「見つかりませんでした」と表示する。
7. 検索バーを閉じていても、F3 / Shift+F3 は最後に使った条件で検索する。一度も検索していない場合は検索バーを開く。

**画面**: 検索バーの前を検索・次を検索ボタン、オプション「方向」「折り返す」。

**巨大ファイル・長時間処理**: FIND-01、FIND-02 に従う。後方検索も前方と同じ速度の目標を満たす。

**エラー**: FIND-04 に従う。

**受け入れ基準**:

- [ ] `AAAA` に対して `AA` を次を検索で 3 回探すと、オフセット 0、1、2 に順に移動する。
- [ ] 末尾付近から次を検索すると、先頭側の一致に移動し、「先頭に戻って検索しました」が表示される。
- [ ] 折り返しをオフにすると、末尾で止まり「末尾まで見つかりませんでした」が表示される。
- [ ] Shift+F3 で、カーソルより前にある最も近い一致に移動する。

### FIND-10 大文字・小文字の区別、単語単位

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 (大文字・小文字)、追加 (フェーズ 1 提案) (単語単位) |
| 呼び出し | 検索バーのオプション「大文字と小文字を区別する」「単語単位で探す」 |

**概要**: テキスト検索で大文字・小文字を区別しない検索と、単語として一致する箇所だけを探す検索を行う。

**仕様**:

1. 「大文字と小文字を区別する」の既定はオフ。
2. 区別しない場合、検索語の各文字について Unicode の単純な大文字・小文字の対応 (1 文字対 1 文字、地域設定に依存しない Invariant の対応) で変種を作り、変種を選んだ文字コードで符号化したバイト列のどれかに一致する並びを探す。
   - トルコ語の `İ` `ı` などの地域固有の対応は使わない。`i` と `I` は対応し、`İ` (U+0130) と `ı` (U+0131) はそれぞれ自分自身とだけ一致する。
   - 1 文字が複数文字に対応するもの (`ß` と `SS` など) は対応させない。
   - 全角英字 (`Ａ` と `ａ`) は対応させる。全角と半角、ひらがなとカタカナは区別する。
3. 区別しない検索は、テキスト、正規表現 (テキスト)、複数語検索、文字列の抽出の絞り込みで使える。Hex と数値の検索には表示しない。
4. 「単語単位で探す」(既定オフ) をオンにすると、一致の直前と直後の文字が単語を作る文字でない場合だけを一致とする。
   - 単語を作る文字: Unicode の文字 (L)、数字 (Nd)、結合文字 (M)、`_`。
   - 直前・直後の文字は、選んだ文字コードで前後のバイトを復号して判定する。検索範囲の端、復号できないバイトは単語の境界とみなす。
5. CJK の文字は単語を作る文字として扱う (単語の区切りを辞書で判定しない)。

**画面**: 検索バーの 2 行目のチェックボックス 2 つ。

**巨大ファイル・長時間処理**: FIND-01 に従う。

**エラー**: なし。

**受け入れ基準**:

- [ ] 区別しない検索で「file」が `FILE`、`File`、`fIlE` に一致する。
- [ ] 区別しない検索で、OS の地域設定をトルコ語にしても「file」が `FILE` に一致する。
- [ ] 区別しない検索で「ａｂ」(全角) が `ＡＢ` に一致し、`AB` (半角) に一致しない。
- [ ] 単語単位で「cat」が `a cat.` に一致し、`concat` と `cats` に一致しない。
- [ ] UTF-16LE の区別しない検索が正しく動く (「ab」が `41 00 42 00` に一致する)。

### FIND-11 検索範囲

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 (全体・選択範囲)、追加 (フェーズ 1 提案) (オフセット範囲・開いているすべてのドキュメント) |
| 呼び出し | 検索バーのオプション「範囲」 |

**概要**: 検索の対象を、ドキュメント全体、選択範囲、指定したオフセット範囲、開いているすべてのドキュメントから選ぶ。

**仕様**:

1. 範囲の選択肢と既定値:
   - 「ドキュメント全体」(既定)。
   - 「選択範囲」: 検索バーを開いたときの選択範囲に固定する。検索中にカーソルを動かしても範囲は変わらない。マルチ選択 (EDIT-07) の場合は、すべての範囲を対象にする。選択範囲がない場合は選べない。
   - 「オフセット範囲」: 開始と終了 (または長さ) を入力式 (00-overview.md の 6 章) で指定する。終了は範囲に含まれる最後のバイトの位置 (このバイトを含む) とし、範囲を選択範囲から入れる場合は `sel.last` に当たる (EDIT-04 と同じ)。例: `0x1000`〜`end-0x100`。
   - 「開いているすべてのドキュメント」: すべてのタブのドキュメントを順に検索する。次を検索では、現在のドキュメントの末尾に達したら次のタブのドキュメントへ進み、該当するタブに切り替える。すべて検索では結果一覧をドキュメントごとにまとめる。
2. 一致は範囲の中に完全に収まるものだけを報告する。範囲の端をまたぐ一致は報告しない。
3. 範囲を「選択範囲」にしている間は、エディタ上でその範囲を薄い枠で示す (ハイコントラストでは点線の枠)。
4. 折り返し (FIND-09) は範囲の中で行う。

**画面**: 検索バーの 2 行目に範囲のドロップダウン。「オフセット範囲」を選ぶと、開始と「終了 (このバイトを含む)」の入力欄 (00-overview.md の 9 章の入力欄) を表示する。

**巨大ファイル・長時間処理**: 範囲の外は読まない。

**エラー**: 開始が終了より後、または範囲がドキュメントの外にある場合は、入力欄を赤枠にして検索ボタンを無効にする。

**受け入れ基準**:

- [ ] 範囲を「選択範囲」にすると、選択範囲の外にある一致が見つからない。
- [ ] 範囲の終端をまたぐ一致が報告されない。
- [ ] 「開いているすべてのドキュメント」で、3 つのタブのうち 2 つ目にだけある一致に、次を検索でタブが切り替わって移動する。
- [ ] `0x100` 〜 `end-0x10` のように入力式で範囲を指定できる。

### FIND-12 一致の強調とナビゲーションの補助

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F0-11 |
| 呼び出し | 検索バーが開いている間、自動 |

**概要**: 検索バーに一致の件数と現在の一致の番号を表示し、表示中の一致を強調する。

**仕様**:

1. 検索語を確定する (Enter を押す、またはインクリメンタルサーチで入力が止まる) と、バックグラウンドで範囲全体の一致件数を数え、検索バーに「3 / 125」(現在の一致の番号 / 全件数) と表示する。
2. 件数の数え上げは、範囲が 1 GiB (1,073,741,824 バイト) 以下の場合だけ自動で行う。1 GiB を超える場合は「件数を数える」ボタンを表示し、押したときに実行する。数え上げ中は「3 / 数えています…」と表示する。
3. 件数が 100 万件を超えた場合は数え上げを止め、「100 万件以上」と表示する。
4. 強調表示 (FIND-04 の 9) の色は、選択範囲・変更されたバイトの強調と区別できる色にする (色の重ね順は VIEW-17 に従う)。
5. 件数と番号は、次を検索 (FIND-09 の仕様 3) と合わせるため、重なる一致も 1 件ずつ数える (すべて検索の「重なる一致を含める」(FIND-20 の仕様 5) の設定に関係しない)。例えば `AAAA` の中の `AA` は 3 件。

**画面**: 検索欄の右に件数表示。

**巨大ファイル・長時間処理**: 数え上げは長時間処理として扱い、検索語が変わったら前の数え上げをキャンセルする。

**エラー**: なし。

**受け入れ基準**:

- [ ] 1 MiB のファイルで検索すると「1 / N」と件数が表示され、次を検索で番号が増える。
- [ ] 2 GiB のファイルでは件数が自動で数えられず、「件数を数える」ボタンで数えられる。ちょうど 1 GiB のファイルでは自動で数えられる。

### FIND-13 整数の検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-09 |
| 呼び出し | 検索バーの種類「整数」 |

**概要**: 整数の値を、サイズ・符号・エンディアンを指定してバイト列に変換して検索する。

**仕様**:

1. 値は入力式 (00-overview.md の 6 章) で入力する。負の値は先頭の `-` で表す (例: `-1`、`-0x80`)。
2. サイズ: 8 / 16 / 24 / 32 / 48 / 64 bit。既定は 32 bit。
3. 符号: 「符号あり」「符号なし」「どちらでも」。既定は「どちらでも」。
   - 「どちらでも」の場合、値がそのサイズの符号あり・符号なしのどちらかの範囲に入っていれば、その表現で検索する (例: 8 bit の `-1` と `255` はどちらも `FF` を探す)。
   - 値がどちらの範囲にも入らない場合はエラーにする (8 bit で `256`、`-129` など)。
4. エンディアン: 「リトルエンディアン」「ビッグエンディアン」「両方」。既定は表示中のエンディアン (ステータスバーの表示) に合わせる (ドキュメントのエンディアンは VIEW-11 で、フェーズ 2。それまでは VIEW-11 の既定のリトルエンディアンを既定とする)。利用者が選んだエンディアンは、そのウィンドウの検索バーで保つ。「両方」の場合は両方のバイト列を同時に検索する (値が左右対称で同じバイト列になる場合は 1 つにまとめる)。結果にはどちらで一致したかを示す。
5. 値の範囲を指定する検索は FIND-15、ビットマスクは FIND-16 に従う。
6. アラインメント条件 (FIND-17) を併用できる。既定はアラインメントなし (すべてのオフセット)。
7. 置換 (FIND-22) では、置換の値も同じサイズ・エンディアンの整数として入力する。

**画面**: 検索バーの 2 行目にサイズ、符号、エンディアンのドロップダウン。検索欄の横に変換結果のバイト列を表示する (例: `= 78 56 34 12 (LE)`)。

**巨大ファイル・長時間処理**: 値が 1 つの場合はバイト列のリテラル検索になり、FIND-01 の目標を満たす。

**エラー**: 範囲外の値は「32 bit の符号なし整数の範囲 (0〜4,294,967,295) を超えています」のように範囲を示す。範囲の数値は地域設定に従って書式化する。

**受け入れ基準**:

- [ ] 32 bit、リトルエンディアンで `0x12345678` を検索すると `78 56 34 12` に一致する。
- [ ] 16 bit、「両方」で `0x1234` を検索すると `34 12` と `12 34` の両方に一致し、結果にエンディアンが表示される。
- [ ] 8 bit、「どちらでも」で `-1` と `255` が同じ結果になる。
- [ ] 24 bit と 48 bit の値を検索できる。
- [ ] 8 bit で `256` を入力するとエラーになる。

### FIND-14 浮動小数点の検索 (許容誤差)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-09 |
| 呼び出し | 検索バーの種類「浮動小数点」 |

**概要**: float や double の値を、許容誤差を指定して検索する。誤差のある計算結果や、10 進で正確に表せない値を探すときに使う。

**仕様**:

1. 形式: half (16 bit)、float (32 bit)、double (64 bit)。既定は float。
2. 値の入力は小数点 `.` のみ (地域設定に依存しない)。指数表記 (`1.5e-3`)、`inf`、`-inf`、`nan` を受け付ける。
3. 許容誤差の種類と既定値:
   - 「なし」(既定): 値を指定の形式に丸めたものとビット単位で同じものだけに一致する。ただし `0` は `+0` と `-0` の両方に一致する。
   - 「絶対誤差」: `|x - 値| <= 誤差` を満たす x に一致する。
   - 「相対誤差」: `|x - 値| <= 誤差 × |値|` を満たす x に一致する。誤差は % ではなく比率で入力する (例: `0.001`)。
   - 「ULP」: 指定の形式で隣り合う値の個数 (0〜1,000,000) 以内の差のものに一致する。
4. `nan` を指定した場合は、すべての NaN (符号・ペイロードを問わない) に一致する。許容誤差は無視する。NaN は他のどの値にも一致しない。
5. `inf` / `-inf` は同じ符号の無限大だけに一致する。
6. 非正規化数 (サブノーマル) も通常の値として比較する。
7. エンディアン: リトル / ビッグ / 両方 (FIND-13 と同じ)。
8. 許容誤差が「なし」の場合はバイト列のリテラル検索 (`+0`/`-0` の 2 種類) で探す。それ以外は、各オフセット (アラインメント条件があればその位置だけ) で値を復号して比較する。
9. 値の範囲の検索は FIND-15 に従う。

**画面**: 検索バーの 2 行目に形式、エンディアン、許容誤差の種類のドロップダウンと誤差の入力欄。検索欄の横に「float として格納される値: 0.100000001490116」のように、丸めたあとの値を表示する。

**巨大ファイル・長時間処理**: FIND-01 の目標 (300 MiB/s 以上) を満たす。各オフセットの比較はベクトル化する。

**エラー**: 値が形式の範囲を超える場合 (half で `70000` など) は、無限大になることを示して確認を求めず、エラーにする。誤差に負の値は入力できない。

**受け入れ基準**:

- [ ] float、誤差なしで `0.1` を検索すると `CD CC CC 3D` (LE) に一致する。
- [ ] double、絶対誤差 `0.001` で `3.14159` を検索すると、`3.1415926535` を表す double に一致する。
- [ ] `0` で検索すると `+0` と `-0` の両方に一致する。
- [ ] `nan` で検索すると、異なるペイロードの NaN にすべて一致する。
- [ ] ULP `1` で検索すると、隣り合う値に一致し、2 つ離れた値に一致しない。

### FIND-15 値の範囲の検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 検索バーの種類「整数」「浮動小数点」で検索欄に範囲を入力する |

**概要**: 値が指定の範囲に入るデータを検索する。例: 1000〜2000 の範囲の 32 bit 整数。

**仕様**:

1. 検索欄に `最小..最大` の形で入力すると範囲検索になる。両端を含む。`..最大` (最小は型の最小値)、`最小..` (最大は型の最大値) も受け付ける。例: `1000..2000`、`-5..5`、`0x7F00_0000..`。
2. 最小が最大より大きい場合はエラーにする。
3. 符号「どちらでも」の範囲検索は、符号ありと符号なしのどちらかで範囲に入れば一致とする。結果にはどちらで一致したかを示す。
4. 浮動小数点の範囲検索では NaN は一致しない。
5. 「除外」オプション (既定オフ) をオンにすると、範囲に入らない値に一致する。
6. 範囲検索ではアラインメント条件 (FIND-17) を既定でサイズの倍数にする (32 bit なら 4 の倍数)。利用者は変更できる。全オフセットで探すと一致が非常に多くなるため。

**画面**: 検索欄に入力するだけ。検索欄の横に「範囲: 1,000〜2,000 (32 bit 符号あり, LE)」と表示する。

**巨大ファイル・長時間処理**: 各オフセットで値を復号して比較する。FIND-01 の目標 (300 MiB/s 以上) を満たす。

**エラー**: 範囲の端が型の範囲外の場合はエラーにする。

**受け入れ基準**:

- [ ] 16 bit 符号なしで `100..200` を検索すると、150 (`96 00`) に一致し、201 に一致しない。
- [ ] `..0` で検索すると、符号ありの負の値と 0 に一致する。
- [ ] 範囲検索の既定のアラインメントがサイズの倍数になっている。

### FIND-16 ビットマスク検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 検索バーの種類「Hex」でオプション「ビットマスク」をオンにする |

**概要**: 指定したビットだけを比較し、他のビットを無視して検索する。ビットフィールドやフラグの値を探すときに使う。

**仕様**:

1. 入力方法は 2 種類。
   - 値とマスク: 値 `V` とマスク `M` を Hex で入力する (同じ長さ)。各バイトで `(データ & M) == (V & M)` のとき一致とする。
   - ビットパターン: `0`、`1`、`x` (無視) を 8 文字で 1 バイトとして並べる。空白は区切り。例: `1xx0 0001 xxxx xx11`。
2. マスクの長さは 1〜256 バイト。
3. マスクがすべて 0 の場合はエラーにする。
4. ビットパターンでは、ビットの並びは上位ビットから下位ビットの順に書く。
5. ニブル単位のワイルドカード (FIND-06) は、マスクが `F0` / `0F` の特別な場合として内部で同じ処理に変換する。

**画面**: オプションをオンにすると、検索欄の下 (検索バーの 2 行目のオプションの並びの中、「ビットマスク」のチェックボックスの隣) に「マスク」の入力欄を加える。入力方法 (値とマスク / ビットパターン) を切り替えるボタンを置く。

**巨大ファイル・長時間処理**: 先頭バイトのマスク結果で候補を絞り込む。FIND-01 のワイルドカードの目標 (500 MiB/s 以上) を満たす。

**エラー**: 値とマスクの長さが違う場合、ビットパターンの文字数が 8 の倍数でない場合はエラーにする。

**受け入れ基準**:

- [ ] 値 `80`、マスク `80` で、最上位ビットが 1 のバイトすべてに一致する。
- [ ] ビットパターン `xxxx 0001` が `01`、`11`、`F1` に一致し、`02` に一致しない。
- [ ] マスク `00` はエラーになる。

### FIND-17 アラインメント条件 (オフセット mod x = y)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 検索バーのオプション「位置の条件」 |

**概要**: 一致の開始位置が「オフセット mod x = y」を満たすものだけを報告する。セクタの先頭やレコードの先頭にある値だけを探すときに使う。

**仕様**:

1. x (周期) は 1〜2^32 の整数、y (余り) は 0〜x-1。入力式で入力できる (`sector`、`0x200` など)。既定は「条件なし」(x = 1)。
2. 基準: 「ドキュメントのオフセット」(既定) または「表示上のアドレス」(ベースアドレスを設定している場合) を選べる。
3. すべての検索の種類 (Hex、テキスト、数値、正規表現、複数語、一致しない箇所) で使える。正規表現では、一致の開始位置が条件を満たすものだけを報告する。
4. 条件を設定している間は、検索バーに「位置: mod 512 = 0」のように表示する。
5. よく使う値をボタンで選べる: 「2 の倍数」「4 の倍数」「8 の倍数」「16 の倍数」「セクタの先頭」。

**画面**: 検索バーの 2 行目に「位置の条件」のドロップダウン。「指定する」を選ぶと x と y の入力欄を表示する。

**巨大ファイル・長時間処理**: 数値検索では、条件を満たす位置だけを復号する (x が大きいほど速くなる)。

**エラー**: y が x 以上の場合はエラーにする。

**受け入れ基準**:

- [ ] `mod 512 = 0` で Hex `EB` を検索すると、オフセット 0、512、1024… の位置の `EB` だけが見つかる。
- [ ] 基準を「表示上のアドレス」にしてベースアドレスを 0x100 にすると、アドレスで条件を判定する。
- [ ] y に x 以上の値を入力するとエラーになる。

## 4. 正規表現

### FIND-18 正規表現によるテキスト検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-07 |
| 呼び出し | 検索バーの種類「正規表現 (テキスト)」 |

**概要**: 指定の文字コードで復号したテキストに対して、正規表現で検索する。

**仕様**:

1. 構文は ECMAScript (JavaScript) の正規表現に準じる。文字クラス、量指定子 (最長・最短)、グループ、名前付きグループ `(?<name>...)`、先読み・後読み、`\b`、`\d` `\w` `\s`、Unicode プロパティ `\p{L}` を使える。照合は .NET の正規表現で行うため、テキストの正規表現では `\d` `\w` `\b` は Unicode の数字・文字で判定する (ECMAScript と違い、全角数字 `１` も `\d` に一致する)。ASCII だけにしたい場合は `[0-9]` `[A-Za-z0-9_]` と書く。バイト列の正規表現は FIND-19 の仕様 4 のとおり ASCII だけで判定する。
2. フラグ: `i` (大文字・小文字を区別しない、FIND-10 と同じ Invariant の対応)、`m` (`^` `$` を行頭・行末に一致させる)、`s` (`.` を改行に一致させる)。検索バーのチェックボックスで切り替える。既定はすべてオフ。
3. 文字コードは FIND-07 と同じ一覧から選ぶ。データを文字コードに従って復号し、文字の位置とバイトの位置の対応を保ちながら照合する。結果はバイトのオフセットと長さで返す。UTF-16 / UTF-32 では、FIND-07 の仕様 5 の「文字の境界に揃える」(既定オフ) がオフならすべての位相 (偶数・奇数のオフセットから始めた復号) で照合し、オンなら 2 / 4 の倍数の位置から始めた復号だけで照合する。
4. 復号できないバイトは U+FFFD (置換文字) 1 文字として扱う。U+FFFD は `.` や `[^a]` に一致する。
5. 一致の最大長は FIND-01 の「一致の最大長」(既定 4,096 バイト) まで。
6. 照合方式:
   - 後方参照と先読み・後読みを使わない場合は、後戻りしない方式 (.NET の `RegexOptions.NonBacktracking`) で照合し、時間がデータ長に比例するようにする。
   - 使う場合は後戻りする方式で照合し、チャンクごとに時間の上限 (既定 2 秒、設定で 0.1〜60 秒) を設ける。
7. 長さ 0 の一致 (`^`、`a*` など) は報告しない。
8. 置換 (FIND-22) では `$1`、`$<name>`、`$&` (一致全体)、`$$` (`$` 自体) を置換語に使える。置換語は同じ文字コードで符号化する。

**画面**: 検索バーの 2 行目にフラグのチェックボックス、文字コードのドロップダウン、「一致の最大長」の表示 (変更は設定画面へのリンク)。

**巨大ファイル・長時間処理**: FIND-01 に従い、重なり幅は一致の最大長にする。後戻りしない方式で 100 MiB/s 以上 (FIND-01 の表の正規表現の目標) を目標にする。

**エラー**:

- 構文エラーは位置と理由を示す (「12 文字目: 閉じ括弧がありません」)。
- 時間の上限に達した場合は、そのチャンクを飛ばして続けるか中止するかを InfoBar で選ばせる。飛ばした範囲は結果一覧に記録する。

**受け入れ基準**:

- [ ] `[A-Z]{3}\d{2}` が UTF-8 のテキスト `ABC12` に一致する。
- [ ] UTF-16LE で `\w+@\w+\.com` を検索すると、メールアドレスのバイト範囲 (長さは文字数 × 2) が返る。
- [ ] `a` が 40 個続くデータで、`(a+)+b` は後戻りしない方式で照合され、すぐに「見つかりませんでした」で終わる。先読みを含むため後戻りする方式になる `(a+)+(?=b)` では、破滅的な後戻りが起きても UI が固まらず、時間の上限 (既定 2 秒) で止まって InfoBar が出る (仕様 6)。
- [ ] 置換語 `$2-$1` でグループの順序を入れ替えられる。

### FIND-19 正規表現によるバイト列の検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-07 |
| 呼び出し | 検索バーの種類「正規表現 (バイト列)」 |

**概要**: バイト列に対して正規表現で検索する。各バイトを 1 文字 (U+0000〜U+00FF) とみなして照合する。

**仕様**:

1. 構文は FIND-18 と同じ。バイトは `\xHH` で書く。文字クラスにバイトの範囲を書ける (`[\x00-\x1F]`)。
2. 英数字などの印字可能な文字はそのバイト値 (ASCII) を表す。`A` は `41` に一致する。
3. `.` は既定で任意のバイト (`0A` を含む) に一致する (`s` フラグを既定でオンにする)。
4. `\d` `\w` `\s` `\b` は ASCII の範囲だけで判定する。`i` フラグは ASCII の英字だけを対応させる。
5. Unicode プロパティ (`\p{...}`) と `\u` は使えない (エラーにする)。
6. 一致の最大長、照合方式、時間の上限は FIND-18 と同じ。
7. 置換語は Hex 表記と `$1` などのグループ参照を組み合わせて書く (例: `$2 00 $1`)。

**画面**: FIND-18 と同じ。文字コードのドロップダウンは表示しない。

**巨大ファイル・長時間処理**: FIND-18 と同じ。

**エラー**: FIND-18 と同じ。`\p{...}` は「バイト列の正規表現では Unicode プロパティは使えません」と表示する。

**受け入れ基準**:

- [ ] `MZ.{58}` が DOS ヘッダの先頭 60 バイトに一致する。
- [ ] `\x89PNG\r\n\x1A\n` が PNG のシグネチャに一致する。
- [ ] `[\x80-\xFF]{4,}` が、0x80 以上のバイトが 4 つ以上続く範囲に一致する。

1. 検索バーの現在の条件 (種類、オプション、範囲、位置の条件) ですべての一致を探す。
2. 結果は一致の開始オフセットの昇順に一覧に追加していく (ストリーミング)。並列で検索する場合 (FIND-01 の 7) も、各チャンクの結果は、それより前のすべてのチャンクの結果を追加し終えてから追加する。チャンクの境界の重なり部分の一致は FIND-01 の 4 のとおり 1 回だけ報告し、重複も取りこぼしもない。検索の完了を待たずに一覧を操作できる。
3. 一覧は下のパネル「検索結果」に表示する。検索のたびに新しいタブを作るか、前の結果を置き換えるかを選べる (設定 `search.results.newTab`。既定は置き換え。タブの「固定」ボタンで固定したものは置き換えず、新しいタブを作る)。タブが 2 つ以上あるときは一覧の上にタブの並び (見出し「Hex: AB CD (100)」と閉じるボタン) を出す。裏のタブのすべて検索は止めずに続ける。
4. 一覧の列: 番号、オフセット (表示中の基数)、長さ、一致したデータ (Hex、先頭 32 バイト)、一致したデータ (テキスト、表示中の文字コード、先頭 32 文字)、前後のデータ (前後 16 バイト)、状態 (FIND-03)。条件に応じて、文字コード (FIND-08)、エンディアン (FIND-13)、値 (数値検索)、検索語 (FIND-26)、ドキュメント (FIND-11) の列を加える。
5. 重なる一致: オプション「重なる一致を含める」(既定オフ)。オフの場合は、一致の末尾の次から探す。
6. 件数の上限は既定 1,000,000 件 (設定で 1,000〜100,000,000 件)。上限に達したら検索を止め、一覧の見出しに「上限 (1,000,000 件) に達したため停止しました」と表示し、「続ける」ボタンを出す。停止時の一覧は、開始オフセットの小さい順に上限の件数ちょうど (並列数に関係なく同じ結果) になる。続けると上限を 2 倍にして、一覧の最後の一致の続きから探す (重複も取りこぼしもない)。
7. メモリ上に置く結果は 1,000,000 件までとし、それを超える分は一時ファイルに書き出す (結果 1 件あたり 32 バイト程度)。
8. 一覧の行をクリック (またはキーボードで選択して Enter) すると、その一致に移動して選択する。↑ / ↓ で行を移動すると、プレビューとしてエディタをその位置にスクロールする (設定で無効にできる)。
9. 一覧の並べ替え・絞り込みは 00-overview.md の 9 章の結果一覧に従う。検索中に並べ替えた場合、新しい結果は並び順の正しい位置に入る。
10. エディタ上では、すべての一致を強調表示する (FIND-04 の 9)。一覧を閉じると強調を消す。
11. 一覧に結果があるとき、F3 / Shift+F3 は一覧の次 / 前の結果に移動する (設定で「検索をやり直す」に変更できる)。

**画面**: 下パネル「検索結果」。見出しに条件の要約 (例: 「Hex: DE AD BE EF — 1,234 件 (完了)」)、件数、状態 (検索中 / 完了 / 中断 / 上限で停止)、キャンセルボタン、固定ボタン、エクスポートボタン、変換ボタン (FIND-21)。

**巨大ファイル・長時間処理**: FIND-01〜03 に従い並列で検索する。一覧は仮想化し、100 万件以上を表示してもスクロールが 60 fps を保つ。

**エラー**: 一時ファイルの作成に失敗した場合は、メモリ上の 1,000,000 件で止め、理由を見出しに表示する。

**受け入れ基準**:

- [ ] 検索バーで Alt+Enter を押すと、すべての一致が一覧に表示される。
- [ ] 10 GB のファイルで検索中に、すでに見つかった結果をクリックしてジャンプできる。
- [ ] 1,000,000 件で停止し、「続ける」で続きから検索できる。停止時の結果は開始オフセットの小さい順の 1,000,000 件で、続けた後の結果と合わせて重複も取りこぼしもない。
- [ ] 100 万件の結果をスクロールしても 60 fps を保つ。
- [ ] 一覧の行を選んで Enter を押すと、その位置に移動して一致が選択される。
- [ ] 「重なる一致を含める」をオンにすると、`AAAA` の中の `AA` が 3 件になる。オフでは 2 件になる。

### FIND-21 結果の変換とエクスポート

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-07 (エクスポート)、F2-12 (マルチ選択への変換) |
| 呼び出し | 結果一覧の「変換」ボタン、結果一覧の右クリックメニュー、コマンドパレット「検索結果を選択範囲に変換」「検索結果をブックマークに変換」「検索結果をエクスポート」 |

**概要**: すべて検索の結果を、マルチ選択・ブックマーク・ファイルに変換する。

**仕様**:

1. 対象は「選択した行」または「すべての行 (絞り込み後)」から選ぶ。既定は選択した行が 2 行以上あれば選択した行、そうでなければすべての行。
2. マルチ選択に変換: 各一致の範囲を選択範囲にする。上限は 1,000,000 範囲。超える場合は先頭から 1,000,000 件だけ変換し、InfoBar で知らせる。変換後はコピー・塗りつぶし・データ演算などをまとめて実行できる (03-editing.md)。
3. ブックマークに変換: 各一致をブックマーク (05-inspector-and-annotations.md の INSP-23) にする。名前は「検索: <検索語の要約> #番号」、グループは「検索結果 <日時>」。10,000 件を超える場合は確認ダイアログを出す (件数と、ブックマーク一覧が重くなる可能性を書く。ボタンは「ブックマークにする」「やめる」)。
4. エクスポート: CSV (UTF-8、BOM 付き、区切りはカンマ) と JSON。列は一覧の表示列。オフセットは 10 進と 16 進の両方の列を出す。日時は ISO 8601 (UTC)。
5. 一致したデータのコピー: 選択した行の一致データを、Hex 文字列 (1 行 1 件) またはテキストとしてクリップボードにコピーする。

**画面**: 結果一覧の見出しの「変換」ドロップダウンボタン (選択範囲に / ブックマークに / エクスポート…)。エクスポートはファイル保存ダイアログを開く。

**巨大ファイル・長時間処理**: 100 万件のエクスポートは長時間処理として扱う (進捗とキャンセル)。前後のデータの列を含める場合はドキュメントを読むため、読み込みも同じ処理に含める。

**エラー**: 書き込みに失敗した場合は、理由 (容量不足、アクセス拒否など) を InfoBar に表示する。

**受け入れ基準**:

- [ ] 100 件の結果をマルチ選択に変換すると、100 個の選択範囲になる。
- [ ] 結果をブックマークに変換すると、ブックマーク一覧に「検索結果 <日時>」のグループで表示される。
- [ ] CSV をエクスポートして Excel で開くと、日本語のテキストが文字化けしない。
- [ ] JSON のエクスポートに、オフセット・長さ・一致データの Hex が含まれる。

## 6. 置換

### FIND-22 置換 (1 件ずつ)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-08 |
| 呼び出し | 検索 > 置換 (Ctrl+H)、コマンドパレット「置換」 |

**概要**: 検索バーに置換欄を加え、一致を 1 件ずつ確認しながら置き換える。

**仕様**:

1. Ctrl+H で検索バーを置換の形で開く (検索欄の下に置換欄を加える)。検索欄の初期値は FIND-04 の 2 と同じ。
2. 置換語の書き方は検索の種類に合わせる。
   - Hex: Hex 文字列。`??` の位置は元のバイトを残す (FIND-06)。
   - テキスト: 同じ文字コードで符号化する。エスケープ文字のオプションも同じ。
   - 整数・浮動小数点: 同じサイズ・形式・エンディアンで符号化する。エンディアン「両方」の場合は、一致したエンディアンで符号化する。
   - 正規表現: FIND-18、FIND-19 のグループ参照を使える。
3. 「置換」ボタン: 現在の一致 (選択範囲が一致と同じ場合) を置換し、次の一致に移動する。現在の選択範囲が一致でない場合は、置換せずに次の一致に移動する。
4. 「スキップ」ボタン: 置換せずに次の一致に移動する。
5. 1 回の置換は 1 回の Undo で戻せる。
6. 読み取り専用のドキュメント (EDIT-16) では置換欄を無効にし、理由を表示する。
7. 長さが違う置換は FIND-24 に従う。
8. 置換語が空の場合は、一致を削除する (長さを変えられるドキュメントのみ。FIND-24)。

**画面**: 検索バーの置換欄の行。置換欄、「置換」「スキップ」「すべて置換」ボタン、長さが違う場合の扱いのドロップダウン。置換欄の横にも変換結果の Hex を表示する。

**巨大ファイル・長時間処理**: 1 件の置換はデータエンジンの操作として 100 ms 以内に終わる。

**エラー**: 置換語が不正な場合は検索欄と同じく赤枠と説明文で示し、置換ボタンを無効にする。

**受け入れ基準**:

- [ ] Ctrl+H で置換欄付きの検索バーが開く。
- [ ] 「置換」で現在の一致が置き換わり、次の一致が選択される。
- [ ] 1 回の置換が Ctrl+Z 1 回で元に戻る。
- [ ] Hex の置換語 `?? 00` で、1 バイト目が元のまま残る。
- [ ] 読み取り専用のドキュメントでは置換ボタンが押せない。

### FIND-23 すべて置換

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-08 |
| 呼び出し | 検索バーの「すべて置換」ボタン、コマンドパレット「すべて置換」 |

**概要**: 検索範囲のすべての一致を一度に置換する。

**仕様**:

1. 検索範囲 (FIND-11) のすべての一致を置換する。一致は重ならないように前から順に選ぶ (重なる一致を含めるオプションは無視する)。
2. 置換はバックグラウンドで一致を探し、最後にまとめてデータエンジンに適用する。適用中はそのドキュメントの編集を一時的に止め、ステータスバーに「置換を適用しています」と表示する (他のドキュメントは操作できる)。
3. すべての置換は 1 回の Undo で戻せる。
4. 完了後、InfoBar に「1,234 件置換しました」と「元に戻す」ボタンを表示する。
5. 一致の件数が 1,000,000 件を超える場合は、検索の完了後、適用の前に確認ダイアログを出す (件数、Undo の情報にメモリまたは一時ファイルの容量が必要になること。ボタンは「置換する」「やめる」)。
6. 検索中にキャンセルした場合は何も置換しない。
7. 範囲が「開いているすべてのドキュメント」の場合は、ドキュメントごとに 1 回の Undo になる。

**画面**: 検索バーの「すべて置換」ボタン、InfoBar。

**巨大ファイル・長時間処理**: 長さが同じ置換は、データエンジン上で置換箇所ごとのピースになる。ピースの数は置換件数に比例するが、メモリの上限 (00-overview.md の 11.2) を超える分は一時ファイルに退避する。100 万件の同じ長さの置換の適用は 5 秒以内を目標にする。

**エラー**: 適用中にメモリ・一時ファイルの容量が足りなくなった場合は、適用を取り消して元の状態に戻し、理由を表示する。

**受け入れ基準**:

- [ ] 1 MB のファイルで 1,000 件のすべて置換が 1 秒以内に終わり、Ctrl+Z 1 回ですべて元に戻る。
- [ ] 検索中にキャンセルすると、ファイルが変わらない。
- [ ] 100 万件を超える置換の前に確認ダイアログが出る。
- [ ] 完了の InfoBar の「元に戻す」で元に戻る。

### FIND-24 長さの違う置換と埋め方

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-08 |
| 呼び出し | 置換欄の「長さが違う場合」のドロップダウン |

**概要**: 置換語と一致の長さが違う場合の扱いを選ぶ。ファイルの長さを変えるか、埋めて長さを保つか。

**仕様**:

1. 選択肢:
   - 「長さを変える」: 一致を置換語に置き換え、ファイルの長さが変わる (挿入・削除)。
   - 「埋めて長さを保つ」: 置換語が短い場合、残りを埋め草で埋める。置換語が長い場合はエラーにする。
   - 「後ろを上書きする」: 置換語が長い場合、一致の後ろのバイトを上書きする。短い場合は残りのバイトをそのまま残す。
2. 既定値: 長さを変えられるドキュメント (ファイル) では「長さを変える」。長さが固定のドキュメント (ディスク、プロセスメモリ) では「埋めて長さを保つ」で、「長さを変える」は選べない。
3. 埋め草: `00` (既定)、`FF`、空白 (テキスト検索では選んだ文字コードの空白、それ以外は `20`)、指定バイト (Hex で 1〜16 バイトのパターンを繰り返す)。
4. 置換語と一致の長さが同じ場合は、どの選択肢でも上書きになる。
5. 「後ろを上書きする」で置換語がドキュメントの末尾を超える場合は、超える分を書かない (長さが固定のドキュメント) か、末尾に追加する (ファイル) かを、置換の前に確認ダイアログで選ばせる。
6. 正規表現など一致ごとに長さが変わる場合も、一致ごとに上の規則を適用する。

**画面**: 置換欄の行の「長さが違う場合」のドロップダウン。「埋めて長さを保つ」を選ぶと埋め草の選択を表示する。置換語と検索語の長さが違うときだけ強調して表示する。

**巨大ファイル・長時間処理**: 「長さを変える」でも、データエンジンの挿入・削除は 1 件あたり O(log n) で、ファイルサイズに比例しない。

**エラー**: 「埋めて長さを保つ」で置換語が長い場合は、「置換語 (6 バイト) が一致 (4 バイト) より長いため、長さを保てません」と表示し、置換ボタンを無効にする。

**受け入れ基準**:

- [ ] 「長さを変える」で 4 バイトを 6 バイトに置換すると、ファイルが 2 バイト長くなる。
- [ ] 「埋めて長さを保つ」で 4 バイトを 2 バイトに置換すると、残り 2 バイトが `00` になり、長さは変わらない。
- [ ] 物理ディスクのドキュメントでは「長さを変える」が選べない。
- [ ] 埋め草に `CC` を指定すると、残りが `CC` で埋まる。

## 7. 高度な検索

### FIND-25 一致しない箇所の検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 検索バーのオプション「一致しない箇所を探す」(種類が Hex のとき)、コマンドパレット「一致しない箇所を検索」 |

**概要**: 指定したパターンの繰り返しから外れる位置を探す。`00` や `FF` で埋まった領域を飛ばして、次のデータの始まりを探すときに使う。

**仕様**:

1. 検索語 P (Hex、1〜256 バイト、ワイルドカード可) を指定する。検索の開始位置から P を繰り返したものとデータを比べ、最初に違うバイトの位置を一致として報告する。
2. P の繰り返しの起点は検索の開始位置にする。オプション「起点を P の長さの倍数のオフセットに揃える」(既定オン) をオンにすると、`オフセット mod P の長さ = 0` の位置を起点にする。
3. 後方検索では、開始位置から先頭に向かって最初に違うバイトを探す。
4. すべて検索では、P の繰り返しで「ない」範囲を一覧にする。各結果は、違う範囲の開始と長さ (次に P の繰り返しが P の長さ × N バイト以上続く位置まで) で表す。N (最小の繰り返し回数) の既定は 16 (設定で 1〜65,536)。
5. 選択されるのは違う範囲の最初の 1 バイト (次を検索) または違う範囲全体 (すべて検索の結果を選んだとき)。

**画面**: 検索バーの 2 行目のチェックボックス。オンのときは検索欄の見出しを「繰り返しのパターン」に変える。

**巨大ファイル・長時間処理**: P が 1 バイトの場合は `IndexOfAnyExcept` (SIMD) を使い、FIND-01 のリテラルの目標を満たす。

**エラー**: P が空の場合はエラーにする。

**受け入れ基準**:

- [ ] 先頭 1 MB が `00` で、その後に `12` があるファイルで、`00` の一致しない箇所を検索すると、オフセット 0x100000 に移動する。
- [ ] P を `DE AD` にすると、`DE AD DE AD BE EF` でオフセット 4 に移動する。
- [ ] すべて検索で、`00` で埋まっていない範囲の一覧が得られる。

### FIND-26 複数の語の同時検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 検索バーの検索欄の右にある「複数語」ボタン、コマンドパレット「複数の語を検索」 |

**概要**: 複数の検索語 (種類・文字コードが違ってもよい) を 1 回の読み込みで同時に検索する。

**仕様**:

1. 「複数語」ボタンを押すと、検索欄が複数行の一覧に変わる。各行に、種類 (Hex / テキスト / 整数 / 浮動小数点)、検索語、文字コードやサイズなどのオプション、有効 / 無効のチェックを設定する。
2. 語の数は最大 10,000。テキストファイル (1 行に 1 語、UTF-8) から読み込める。読み込むときの種類は一括で指定する。
3. 大文字・小文字の区別、単語単位、範囲、位置の条件は、全体で共通のオプションにする。正規表現は複数語検索に入れられない。
4. リテラルの語 (ワイルドカード・許容誤差なし) は Aho-Corasick 法でまとめて照合し、それ以外の語は候補の絞り込み (FIND-01 の 6) で照合する。
5. 同じ位置で複数の語が一致した場合は、それぞれ別の結果として報告する。
6. 次を検索では、どの語でも最も近い一致に移動し、一致した語を検索バーに表示する。
7. すべて検索の結果一覧には「検索語」列を加え、語ごとの件数を見出しに表示する (「語ごとの件数」を開くと一覧で見られる)。
8. 語の一覧は名前を付けて保存・読み込みできる (JSON)。

**画面**: 検索欄が複数行の表に変わる。行の追加・削除・並べ替えのボタン、「ファイルから読み込み」「保存」ボタン。

### FIND-27 インクリメンタルサーチ

- [ ] `D`、`DE`、`DEA`、`DEAD` と入力するとき、`DE` と `DEAD` の時点で一致に移動し、`DEA` (奇数桁) では移動しない。

### FIND-30 複数ファイル検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-17 |
| 呼び出し | 検索 > 複数ファイル検索 (Ctrl+Shift+F)、コマンドパレット「複数ファイル検索」、Explorer からフォルダをドロップ (UI-34 の仕様 4 の InfoBar の「複数ファイル検索」ボタンで、ドロップしたフォルダを対象にして開く) |

**概要**: 指定したフォルダ内のファイルを対象に検索し、ファイルごとの一致を一覧にする。

**仕様**:

1. 「複数ファイル検索」パネルで、検索条件 (検索バーと同じ種類・オプション) と対象を指定する。パターンは検索バーと同じ作り方で作る。「検索バーの条件を使う」で検索バーの今の条件 (複数の文字コード・複数の語を含む) を取り込める。一致しない箇所 (FIND-25) と複数の語 (FIND-26) は検索だけで、置換はできない。
2. 対象の指定:
   - フォルダ: 複数指定できる。既定は現在のドキュメントのフォルダ。
   - 「サブフォルダを含める」: 既定オン。深さの上限 (既定なし)。

   - シンボリックリンク・ジャンクションをたどる: 既定オフ (ループを防ぐため。オンでもたどったフォルダは 1 回だけ訪れる)。
   - NTFS 代替データストリーム (ADS) を含める: 既定オフ。オンにすると各ファイルの名前付きストリームも検索する (F4-09 の実装後に有効)。
   - 開いているドキュメントを含める: 既定オン。開いているファイルは、編集中の未保存の状態を検索する。
3. ファイルの列挙と検索は並行して行う。並列に検索するファイルの数は既定 4 (設定で 1〜16)。HDD では 1 にすることを推奨する説明を設定に書く。
4. ファイルは読み取りで開き、共有モードは読み取り・書き込み・削除をすべて許可する (他のアプリが使っていても読めるようにする)。
5. 結果は「複数ファイル検索」パネルの下部の一覧に、ファイルごとにまとめて表示する (ファイルの行の下に一致の行を並べる。置換モードのチェックボックス (FIND-31 の仕様 2) を付けるため、下パネル「検索結果」ではなくパネルの中に置く)。ファイルの行: ファイルのパス、件数、ファイルサイズ、更新日時。一致の行: オフセット、長さ、一致データ (Hex / テキスト)。
6. 結果をダブルクリック (Enter) すると、そのファイルをタブで開き、一致の位置に移動して選択する。すでに開いている場合はそのタブに切り替える。
7. 一致がなかったファイルの数、読めなかったファイルの一覧 (理由付き) を見出しの「スキップしたファイル」に表示する。読めなかったファイルは「一致がなかったファイル」に数えない。正規表現の時間の上限 (FIND-18 の仕様 6) で飛ばした範囲があるファイルも、範囲付きでこの一覧に記録する。
8. 件数の上限は FIND-20 と同じ (全体で既定 1,000,000 件。設定 `search.findAll.limit`。上限ちょうどで止め、メモリ上に置くのは 1,000,000 件までで超える分は一時ファイルに書く (FIND-20 の仕様 6・7))。上限で止めたら「続ける」で上限を 2 倍にし、途中まで記録したファイルの続きとまだ探していないファイルを探す (重複も取りこぼしもない)。1 ファイルあたりの上限 (既定 10,000 件) も設け、その上限で止めたファイルはファイルの行にその旨を表示する。結果の一覧は仮想化し、見えている行だけを作る。
9. 対象の指定は名前を付けて保存できる。

**画面**: 「複数ファイル検索」パネル (既定は左パネル)。上部に検索条件、その下に対象の指定 (フォルダの一覧と追加ボタン、マスク、オプション)、「検索」「キャンセル」ボタン。結果はパネルの下部の一覧 (仕様 5)。

**巨大ファイル・長時間処理**: 長時間処理として扱い、処理センターに、処理済みのファイル数 / 見つかったファイル数、処理済みのバイト数、現在のファイル名を表示する。各ファイルは FIND-01 のチャンク検索で読み、ファイルの大きさに関係なくメモリ使用量を一定に保つ。

**エラー**: アクセス拒否・使用中・パスが長すぎるなどで読めないファイルは、スキップして一覧に記録し、検索は続ける。指定したフォルダが存在しない場合は、検索の前にエラーを表示する。

**受け入れ基準**:

- [ ] 1,000 ファイルのフォルダで検索すると、一致したファイルごとに結果がまとまって表示される。
- [ ] 除外マスク `*.log` で `.log` ファイルが検索されない。
- [ ] 他のアプリが書き込みで開いているファイルも検索できる。
- [ ] 読めなかったファイルが理由付きで一覧に出る。
- [ ] 結果をダブルクリックすると、ファイルが開いて一致が選択される。
- [ ] 260 文字を超えるパスのファイルを検索できる。
- [ ] シンボリックリンクのループがあるフォルダで、検索が終わる。

## 9. 文字列の抽出とスキャン

### FIND-32 文字列の抽出

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-08 |
| 呼び出し | 検索 > 文字列の抽出、コマンドパレット「文字列の抽出」 |

**概要**: ドキュメントの中から、指定の文字コードで読める文字が一定数以上続く箇所を探し、一覧にする (`strings` コマンドに相当)。

**仕様**:

1. 設定項目と既定値:
   - 最小の長さ: 4 文字 (1〜1,024)。
   - 最大の長さ: 4,096 文字 (これを超える文字列は分割せず、最初の 4,096 文字を表示し、長さは全体を示す)。
   - 文字コード: ASCII、UTF-8、UTF-16LE、UTF-16BE、ANSI (表示中のコードページ)、その他 F1-06 の文字コード。複数選べる。既定は ASCII と UTF-16LE。
   - 文字の種類: 「印字可能な文字」(既定。ASCII では 0x20〜0x7E とタブ)、「印字可能な文字と改行」(CR と LF を含める)。UTF-8 / UTF-16 などでは、Unicode の制御文字 (Cc)・未割り当て (Cn)・サロゲートの片方だけ・私用領域 (Co) を除く文字を印字可能とする。
   - 「NUL で終わるものだけ」: 既定オフ。オンにすると、直後が NUL 文字 (その文字コードでの 0) の文字列だけを報告する。
   - 範囲: ドキュメント全体 (既定)、選択範囲、オフセット範囲。
2. 同じ範囲が複数の文字コードで文字列になる場合 (ASCII と UTF-8 など) は、より長い方 (文字数。同じならバイト数) を報告し、長さが同じ場合は一覧で先に選んだ文字コードを報告する。UTF-16 / UTF-32 はすべての位相で読む。「NUL で終わるものだけ」は、重なる候補からこの規則で選んだ後に除く (NUL で終わらない長い文字列に重なる、別の位相の短い候補は報告しない)。
3. 結果は共通の結果一覧に表示する。列: オフセット、長さ (バイト)、文字数、文字コード、文字列。
4. 一覧の絞り込みで、文字列に含まれる語 (大文字・小文字を区別しない、FIND-10)、または正規表現で絞り込める。正規表現は絞り込み欄に `/…/` で囲んで書く (大文字・小文字を区別しない)。
5. 結果は FIND-21 と同じくマルチ選択・ブックマークに変換、CSV / JSON / テキスト (1 行 1 文字列) にエクスポートできる。

**画面**: 「文字列の抽出」パネル (下パネル)。上部に設定項目と「抽出」ボタン、下に結果一覧。

**巨大ファイル・長時間処理**: 長時間処理として扱う。FIND-01 のチャンク検索で処理し、チャンクの境界では最大の長さ分を重ねる。100 GB のファイルでもメモリ使用量は結果の件数分だけ増える。件数の上限は FIND-20 と同じ。

**エラー**: FIND-01 の読み込みエラーの扱いに従う。

**受け入れ基準**:

- [ ] 最小の長さ 4 で、`Hello` (5 文字) が報告され、`Hi` が報告されない。
- [ ] UTF-16LE の「ファイル」が文字列として報告され、文字数 4、長さ 8 バイトになる。
- [ ] 「NUL で終わるものだけ」で、後ろに `00` がない文字列が除かれる。
- [ ] 1 GB のファイルの抽出中に、結果がストリーミングで表示され、キャンセルできる。

### FIND-33 YARA スキャン

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-05 |
| 呼び出し | 検索 > YARA、コマンドパレット「YARA スキャン」 |

**概要**: YARA ルールでドキュメントをスキャンし、一致したルールと文字列の位置を一覧・強調表示する。

**仕様**:

1. ルールの読み込み: `.yar` / `.yara` (ソース) と、コンパイル済みのルールファイルを読み込める。複数のファイル・フォルダを指定できる。`include` は相対パスで解決する。
2. ルールセットは名前を付けて保存でき、スキャンのたびに選べる。ルールはアプリに同梱しない (利用者が用意する)。
3. スキャン範囲: ドキュメント全体 (既定)、選択範囲。複数ファイル検索 (FIND-30) と同じ対象指定で、フォルダ内のファイルもスキャンできる。
4. 未保存の編集を含む現在の状態 (FIND-03 のスナップショット) をスキャンする。
5. 使えるモジュール: `pe`、`elf`、`math`、`hash`、`time`、`string`、`console`。`cuckoo` などの外部のデータが必要なモジュールは使えない。外部変数 (`-d` 相当) をルールセットごとに設定できる。
6. スキャンはデータを 64 MB (設定で 16〜1,024 MB) のブロックに分けて YARA に渡す。ブロックは前のブロックの末尾 64 KB と重ね、重なり部分の一致は重複を取り除く。
   - 制限: 重なり幅を超える長さの文字列の一致や、ブロックをまたぐ条件は、ドキュメントが 1 ブロックに収まらない場合に見つからないことがある。この制限はスキャンの画面に常に表示する。
   - `filesize` はドキュメントの長さ (範囲指定時は範囲の長さ) を返す。`pe` / `elf` モジュールは先頭のブロックで解析する。
7. スキャンの時間の上限は既定 600 秒 (設定で 1〜86,400 秒)。
8. 結果は共通の結果一覧に表示する。列: ルール名、名前空間、タグ、メタ情報 (一覧の行を開くと全項目を表示)、文字列の識別子 (`$a` など)、オフセット、長さ、一致データ。文字列を含まないルール (条件だけのルール) は、オフセットなしの行として表示する。
9. 一致した範囲は、注釈 (05-inspector-and-annotations.md の INSP-32) としてエディタ上に強調表示し、ツールチップでルール名と文字列の識別子を表示する。
10. 結果は FIND-21 と同じく変換・エクスポートできる。

**画面**: 「YARA」パネル (下パネル)。ルールセットの選択、ルールファイルの追加・削除、外部変数の設定、範囲、「スキャン」ボタン、結果一覧。

**巨大ファイル・長時間処理**: 長時間処理として扱う (進捗はブロック単位)。メモリ使用量はブロックサイズ × 2 程度に抑える。

**エラー**:

- ルールのコンパイルエラーは、ファイル名・行番号・メッセージを一覧で表示し、スキャンを始めない。
- 時間の上限に達した場合は、それまでの結果を残して「時間の上限に達しました」と表示する。
- YARA の内部エラー (メモリ不足など) は、エラーコードと説明を表示する。

**受け入れ基準**:

- [ ] `rule mz { strings: $a = "MZ" condition: $a at 0 }` で EXE ファイルをスキャンすると、オフセット 0 の一致が表示される。
- [ ] 構文エラーのあるルールで、行番号付きのエラーが表示され、スキャンが始まらない。
- [ ] 1 ブロック (64 MB) を超えるファイルで、ブロックの境界をまたぐ 32 バイトの文字列が見つかり、重複して報告されない。
- [ ] 一致した範囲がエディタ上で強調され、ツールチップにルール名が出る。
- [ ] 未保存の編集で追加した文字列が、スキャンで見つかる。

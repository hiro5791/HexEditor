# 機能仕様書: 解析 (比較・統計・ハッシュ・逆アセンブル)

この文書は「解析」メニューに属する機能のうち、構造体テンプレート (07) を除くものを定める。ファイル比較、統計、ファイル形式の判定、ハッシュ・チェックサム、逆アセンブル、デマングルを扱う。

- 対象のロードマップ ID: F1-17 (ハッシュ・チェックサム)、F2-01 (ファイル比較)、F2-04 (統計)、F2-14 (ハッシュの拡充)、F4-01 (逆アセンブル)、F6-01 (構造を理解した比較)、F6-02 (ファイルマップ)。
- ロードマップにない調査結果 ([../research/feature-survey.md](../research/feature-survey.md) の 2.1、2.8〜2.10、2.13、2.15) の機能も「追加」として含める。
- 書式・用語・入力式・ショートカット・共通 UI 部品は [00-overview.md](00-overview.md) に従う。

関連する他の文書:

- ミニマップ (02、F2-03) は ANA-13 のエントロピー計算の結果を共有する。
- データインスペクタの「1 命令ぶんの逆アセンブル」(05) は ANA-23 の逆アセンブルエンジンを使う。
- コマンドラインからのハッシュ計算・比較 (08、F3-08) は ANA-18 と ANA-01 の処理を呼ぶ。スクリプト API (08) からも同じ処理を呼べる。
- 圧縮データの展開 (03、F4-04) は ANA-16 の検出結果から呼べる。
- 構造を理解した比較 (ANA-31・ANA-32) は、構造体テンプレート (07) の評価器と結果ツリーの部品を使う。
- ファイルマップ (ANA-33・ANA-34) は、ANA-16・ANA-17・カービングのシグネチャ (12 の FOR-18)・テンプレートの自動適用 (07 の TPL-30) を組み合わせ、テンプレートの推定 (07 の TPL-38) を呼べる。

## 0. この文書の共通事項

### 0.1 対象範囲の指定

統計・ハッシュ・パターン統計・逆アセンブルなど、データの範囲を対象にする機能は、共通の「対象範囲」選択欄を持つ。

| 選択肢 | 意味 | 既定になる条件 |
| --- | --- | --- |
| 選択範囲 | 現在の選択範囲 1 つ | 選択範囲が 1 バイト以上あるとき |
| マルチ選択 | マルチ選択のすべての範囲 (EDIT-07) | マルチ選択が 2 つ以上の範囲を持つとき |
| ドキュメント全体 | オフセット 0 から末尾まで | 選択範囲がないとき |
| 範囲を指定 | 開始と長さ (または「終了 (このバイトを含む)」) を入力式 (00 の 6 章) で指定。終了は `sel.last` と同じく最後のバイトの位置 (EDIT-04 と同じ) | — |

- マルチ選択は、オフセットの小さい順に連結したものとして扱う。範囲が重なる場合、重なった部分は 1 回だけ数える。
- 対象範囲の横に、実際の開始・終了 (このバイトを含む)・長さを常に表示する (例: `0x1000〜0x1FFF (4,096 バイト)`)。

#### 0.1.1 変換ビューとの関係

変換ビュー (EDIT-45) が有効なタブでは、統計・ハッシュ・ファイル形式の判定・逆アセンブルなど、この文書の機能のうちドキュメントのデータを読むものは、表示されている変換後のデータを対象にする。変換ビューが無効なら元のデータを対象にする (EDIT-45 の 11)。変換後のデータを対象にした結果には、パネルの見出しと結果のエクスポートに「変換ビュー: …」の表示を付ける。比較 (1 章) も、各側のタブの表示どおりのデータを比べる。

### 0.2 計算時点のデータ

1. 計算は、計算を開始した時点のドキュメントの内容 (未保存の編集を含む) に対して行う。
2. データエンジンのピースツリーは不変なので、開始時点のルートを保持して計算する。計算中に利用者が編集しても、計算結果は開始時点の内容のものになる。
3. 計算後にドキュメントが編集された場合、結果の表示に「結果は編集前の内容のものです」と表示し、「再計算」ボタンを出す。

### 0.3 長時間処理

- 0.5 秒以上かかりうる計算は、処理センター (00 の 9 章) に登録し、進捗率・処理速度・残り時間・キャンセルを提供する。
- 途中経過を出せる計算 (統計、エントロピーグラフ、比較) は、0.5 秒ごとに途中結果を画面に反映する。
- キャンセルした場合、途中結果を「途中で中止 (xx% まで)」と明示して残すか破棄するかを、機能ごとに定める。

### 0.4 グラフのアクセシビリティ

- すべてのグラフは、同じ内容を表として表示する切り替えボタン (「表で表示」) を持つ。
- グラフ領域にはスクリーンリーダー向けの名前と要約 (例: 「エントロピーグラフ、ブロック 4,096 個、最大 7.99 ビット、オフセット 0x3F000」) を設定する。
- 色だけで区別しない。系列は線の種類・マーカー・模様でも区別する。ハイコントラストテーマではシステム色で描画する。
- 数値の表示 (件数、割合、平均など) は地域設定に従って書式化する。16 進の値 (オフセット、ハッシュ値) は地域設定に依存しない。

## 1. ファイル比較

### ANA-01 比較の開始と比較対象の指定

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-01 |
| 呼び出し | 解析 > 比較 > ファイルを比較...、コマンドパレット「比較: ファイルを比較」、タブの右クリックメニュー「比較の左側に選択」「選択した左側と比較」、ショートカットは既定なし |

**概要**: 2 つのデータを指定して比較を始める。比較対象ごとに開始オフセットと長さを独立に指定できる。

**仕様**:

1. 比較対象 (左・右) には次のいずれかを指定する。
   - 開いているドキュメント (タブの一覧から選ぶ)
   - ディスク上のファイル (ファイル選択ダイアログ、またはパスの入力)
   - 開いているドキュメントの、ディスク上に保存されている内容 (ANA-08)
   - プロセスメモリのスナップショット (ANA-09)
   - 物理ディスク・ボリューム (F2-09 で開いているもの)
2. 左右それぞれに「開始オフセット」と「長さ」を入力式で指定する。既定は開始 0、長さは末尾まで。開始オフセットは左右で異なってよい (例: 左 `0x200`、右 `0x0`)。
3. 比較方式を選ぶ。
   - 単純比較 (ANA-02): 既定。
   - 挿入・削除を考慮した比較 (ANA-03)。
4. 方式ごとのオプション (ANA-02、ANA-03 に記載) を指定する。前回の指定を記憶し、次回の既定値にする。
5. 「比較」ボタンで比較を開始し、比較ビュー (ANA-04) を新しいタブで開く。タブ名は `左の名前 ↔ 右の名前`。
6. 同じ組み合わせ (同じ 2 つのドキュメント、同じ範囲) の比較タブがすでにある場合は、そのタブに切り替えて再比較する。
7. 比較中も左右のドキュメントは編集できる。比較は開始時点の内容で行う (0.2)。
8. 比較の設定 (対象、範囲、方式、オプション) は比較タブに保存し、「再比較」で同じ条件でやり直せる。
9. 片方の対象だけを選んで実行した場合は、右側のファイル選択ダイアログを開く。
10. 2 つのファイルを Explorer から同時にドラッグ & ドロップするとき、Shift キーを押しながらドロップすると、その 2 つで比較ダイアログを開く。

**画面**: 「ファイルを比較」ダイアログ。左右 2 列に「対象」コンボボックス (ドキュメント一覧と「ファイルを選択...」「保存済みの内容」「スナップショット...」)、開始オフセット欄、長さ欄 (00 の 9 章の入力欄)。下に比較方式のラジオボタンと、方式ごとのオプションを展開表示する Expander。ボタンは「比較」「キャンセル」。左右を入れ替えるボタン (アイコンと名前「左右を入れ替え」) を中央に置く。

**巨大ファイル・長時間処理**: 比較の実行は ANA-02 / ANA-03 に従う。ダイアログ自体はサイズに依存しない。

**エラー**:

- 対象のファイルを開けない (アクセス拒否、ロック、存在しない): ダイアログ内の対象欄の下に理由を表示し、「比較」ボタンを無効にする。
- 開始オフセットが対象の長さを超える、長さが残りを超える: 入力欄を赤枠にし、「開始オフセットが長さ (0x1000) を超えています」のように表示する。
- 左右に同じドキュメントの同じ範囲を指定した: 「同じ範囲どうしの比較です」と警告を表示するが、実行は許可する。

**受け入れ基準**:

- [ ] 開いている 2 つのタブを選んで比較タブが開く。
- [ ] 左の開始オフセット `0x200`、右の開始オフセット `0` を指定すると、左の 0x200 と右の 0x0 が並んで比較される。
- [ ] 長さに `0x1000` を指定すると、0x1000 バイトを超えた部分は比較されない。
- [ ] 「左右を入れ替え」で対象・開始・長さがまとめて入れ替わる。
- [ ] 前回の比較方式とオプションが次回の既定になる。
- [ ] 存在しないパスを入力すると「比較」ボタンが無効になり、理由が表示される。

### ANA-02 単純比較 (バイトごと)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-01 |
| 呼び出し | ANA-01 のダイアログで「単純比較」を選ぶ。比較タブのツールバーの方式切り替え |

**概要**: 左右の開始オフセットから同じ相対位置にあるバイトどうしを比べ、異なるバイトの範囲を差分として求める。

**仕様**:

1. 相対位置 `i` (0 ≤ i < min(左の長さ, 右の長さ)) について、左[開始+i] と右[開始+i] を比べる。
2. 異なるバイトが連続する範囲を 1 つの差分 (種類「変更」) にまとめる。
3. オプション「近い差分をまとめる」: 2 つの差分の間にある一致バイトが N 個以下なら 1 つの差分にまとめる。N の既定は 0 (まとめない)、範囲は 0〜65,536。
4. 長さが異なる場合、短い方の末尾より後ろの部分を 1 つの差分 (種類「左のみ」または「右のみ」) にする。
5. オプション「比較の単位」: 1 / 2 / 4 / 8 バイト。単位が 2 以上の場合、単位内の 1 バイトでも異なれば単位全体を差分にする。既定は 1。
6. 結果として、差分の数、異なるバイトの総数、一致率 (一致バイト数 / 比較したバイト数、小数第 2 位まで) を求める。
7. 差分の位置は、左右それぞれのオフセット (開始オフセットを足した絶対オフセット) で記録する。

**画面**: 比較ビュー (ANA-04)。進捗は比較タブ上部の進捗バーと処理センターに表示する。

**巨大ファイル・長時間処理**:

- 1 MB 単位で左右を並行して読み、SIMD (`Span<byte>.SequenceEqual` 相当、`Vector` による不一致位置の探索) で比べる。速度の目標は、遅い方のストレージの読み込み速度の 80% 以上。
- 差分の一覧はメモリに 100 万件まで保持し、それを超えた分は一時ファイルに書き出す。件数に上限は設けない。
- 比較中も、すでに見つかった差分は一覧と比較ビューに表示する。
- キャンセルした場合、比較済みの範囲までの結果を残し、「0x3A000000 まで比較して中止」と表示する。

**エラー**:

- 読み込みエラー (不良セクタ、プロセスメモリの読めない領域): その範囲を種類「読み込み不可」の差分として記録して続行する。読み込み不可の範囲の数を結果の要約に表示する。
- 一時ファイルの書き込みに失敗 (容量不足): 比較を中止し、InfoBar に「一時フォルダの空き容量が不足しています」と表示する。それまでの結果は残す。

**受け入れ基準**:

- [ ] 1 バイトだけ異なる 2 つの 1 GB ファイルで、差分 1 件、異なるバイト 1 個が報告される。
- [ ] 長さ 100 と 120 のファイル (先頭 100 バイトは同じ) で、右のオフセット 100〜119 が「右のみ」の差分 1 件になる。
- [ ] 「近い差分をまとめる」を 4 にすると、間に 3 バイトの一致を挟む 2 つの差分が 1 件になる。
- [ ] NVMe SSD 上の 10 GB のファイル 2 つの比較が、読み込み速度の 80% 以上で終わる。
- [ ] 1,000 万件の差分が出る比較でも、メモリ使用量が 1 GB を超えない。
- [ ] 比較の途中でキャンセルすると、中止した位置までの結果が残る。

### ANA-03 挿入・削除を考慮した比較

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-01 |
| 呼び出し | ANA-01 のダイアログで「挿入・削除を考慮した比較」を選ぶ。比較タブのツールバーの方式切り替え |

**概要**: 一方にバイトが挿入・削除されていても、その後ろの一致部分を正しく対応付けて比較する。Myers の差分アルゴリズム (LCS) を、再同期の窓で区切って使う。

**仕様**:

1. 結果は「一致」「変更」「挿入 (右のみ)」「削除 (左のみ)」の 4 種類の区間の列になる。変更は、同じ位置での削除と挿入の組で、長さが左右で異なってよい。
2. 処理の手順は次のとおり。
   1. 左右の先頭から、一致が続く限り「一致」として進める。
   2. 不一致が見つかったら、その位置から「再同期ウィンドウ」の範囲 (左右それぞれ W バイト) を対象に、Myers の O(ND) アルゴリズム (線形空間版) で最短編集手順を求める。
   3. 長さが「最小一致長」M バイト以上の一致区間だけを再同期点として採用する。M 未満の一致は変更の一部として扱う。
   4. 再同期点が見つかった場合、その点から 1. に戻る。
   5. ウィンドウ内に再同期点がない場合、ウィンドウ全体を「変更」とし、ウィンドウの末尾から 1. に戻る。
3. ウィンドウ内での探索の前に、ローリングハッシュ (M バイト単位) で左右の共通ブロックを探し、候補の位置から Myers を適用する。これにより、W より長い挿入・削除でも、M バイト以上の一致が W 以内にあれば再同期できる。
4. オプションと既定値:

   | オプション | 既定値 | 範囲 |
   | --- | --- | --- |
   | 再同期ウィンドウ (W) | 64 KB | 256 バイト〜16 MB |
   | 最小一致長 (M) | 8 バイト | 1〜4,096 バイト |
   | 比較の単位 | 1 バイト | 1 / 2 / 4 / 8 バイト |
   | 近い差分をまとめる | 0 バイト | 0〜65,536 バイト |

5. 結果は最短の編集手順であることを保証しない (ウィンドウで区切るため)。たとえば W より長い挿入では、再同期点の手前が「挿入」1 件にならず、「挿入」と短い「変更」の組になることがある。比較タブの要約に「挿入・削除を考慮 (近似)」と表示する。
6. 左右のどちらかが長さを変えられないデータソース (ディスク、プロセスメモリ) でも比較はできる。マージ (ANA-07) で挿入・削除を反映できないだけである。

**画面**: 比較ビュー (ANA-04)。挿入・削除の位置で左右の行がずれないよう、カーソルのある行を基準に、対応する位置を左右同じ高さに表示する (同期スクロール。ANA-04 の仕様 4)。相手側の挿入・削除の位置には「揃えるための空白」の印 (斜線の模様の細い帯) を描く。相手側に空白の行そのものを挟んで表示する方式は、Hex ビューに行の挿入の仕組み (並列表示 VIEW-39 と共通) ができてから行う (フェーズ 3)。

**巨大ファイル・長時間処理**:

- メモリ使用量はウィンドウの大きさに比例し、ファイルサイズには比例しない。W = 16 MB でも作業用メモリは 256 MB 以内に収める。
- 巨大なデータでの手順 (実装の方針。HexEditor.Core の InsertDeleteComparer):
  1. 一致の続く間は単純比較と同じく 1 MiB 単位で読んで進める (差分の少ないファイルでは単純比較とほぼ同じ速さ)。
  2. ウィンドウ内の Myers は編集距離に上限 (4,096 要素) を設け、超えたら打ち切る (全く異なるデータで時間が W の 2 乗にならないように)。W がデータより長く編集距離が上限以内なら、最小一致長 1 で最短の編集手順になる。
  3. Myers で M バイト以上の一致がなければ、M バイト単位のローリングハッシュで再同期点を探す (仕様 3)。片側のウィンドウのブロックを索引 (最大 2^18 項目。ウィンドウが大きい場合は一定の間隔で間引く) にし、もう片側をウィンドウの 4 倍 (最大 4 MiB) 先まで流し読みして、左右の位置の和が最小の共通ブロックを再同期点にする。両側から探し、近い方を使う。
  4. どちらでも見つからなければ、ウィンドウ全体を「変更」にして進む (仕様 2.5)。
  5. 作業用メモリはウィンドウ 2 つ・索引・読み込みの塊だけで、W = 16 MB で約 50 MB。
- 差分の少ないファイルどうし (違いが全体の 1% 以下) では、単純比較 (ANA-02) の 50% 以上の速度を保つ。
- 1 つのウィンドウで 5 秒以上かかった場合は、そのウィンドウを「変更」として打ち切り、要約に「打ち切ったウィンドウ: n 個」と表示する。
- 進捗・キャンセルは ANA-02 と同じ。

**エラー**:

- 読み込みエラー: ANA-02 と同じく「読み込み不可」の区間として記録し、その直後から再同期を試みる。
- ウィンドウの指定が範囲外: ダイアログの入力欄で拒否する。

**受け入れ基準**:

- [ ] 1 GB のファイルの中央に 1 バイト挿入したファイルとの比較で、差分は「挿入」1 件だけになる。
- [ ] 中央から 1,000 バイト削除したファイルとの比較で、差分は「削除」1 件 (1,000 バイト) だけになる。
- [ ] 100 KB の挿入 (W = 64 KB、M = 8) でも、挿入の後ろが「一致」として再同期される。挿入の部分は、「挿入」1 件、または「挿入」と、再同期点の直前の短い「変更」の組として報告されてよい (ウィンドウで区切るため。5 を参照)。
- [ ] 一致が 7 バイトしかない区間は、M = 8 のとき再同期点にならない。
- [ ] W = 16 MB で全く異なる 2 つの 1 GB ファイルを比較しても、メモリ使用量が 1 GB を超えない。
- [ ] 要約に「(近似)」と表示される。

### ANA-04 比較ビューと同期スクロール

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-01 |
| 呼び出し | ANA-01 で比較を実行すると開く。表示 > 比較のレイアウト (左右 / 上下)。比較タブのツールバー「同期スクロール」トグル |

**概要**: 比較の左右を並べて表示し、差分を種類ごとに強調する。スクロールとカーソル移動を左右で同期する。

**仕様**:

1. 比較タブは 2 つの Hex ビュー (02 の Hex ビューと同じ部品) を左右または上下に並べる。既定は左右。表示 > 比較のレイアウトで切り替える。
2. 各ビューは対応するドキュメントそのものを表示する。表示設定 (1 行のバイト数、グループ化、文字コード) は左右で共通にする。
3. 差分の強調は次のとおり。色は `ThemeResource` で定義し、ハイコントラストでも区別できるよう色以外の印も付ける。差分は VIEW-17 の色の重ね順の「差分」の層に描き、他の強調 (選択、検索の一致、変更されたバイト、ブックマーク、テンプレートなど) との重なりは VIEW-17 に従う。下線は変更されたバイトの印 (VIEW-17) に使うため、差分の印には使わない。

   | 種類 | 色 (既定) | 色以外の印 |
   | --- | --- | --- |
   | 変更 | 赤系の背景 | 点線の枠 (点の模様) |
   | 挿入 (右のみ) | 緑系の背景 | セルの左端の縦線 |
   | 削除 (左のみ) | 青系の背景 | 取り消し線 |
   | 読み込み不可 | グレーの斜線 | `??` 表示 |
   | 揃えるための空白 (ANA-03) | 斜線の模様 | 相手側の挿入・削除の位置に斜線の模様の細い帯 (空白の行を挟む表示はフェーズ 3。ANA-03 の「画面」) |

   文字の太さは変えない (行の文字は 1 つの TextBlock の Run で描くため、太字は文字の幅とセルの位置がずれる)。

4. 同期スクロール (既定でオン):
   - 単純比較では、左右の相対位置が同じ行を同じ高さに表示する。
   - 挿入・削除を考慮した比較では、対応付け (区間の列) に従って、対応する位置を同じ高さに表示する。カーソルを動かしたときはカーソルの行を基準に、スクロールだけのときは同じ行数だけ動かして、対応を保つ。
   - 一方のカーソルを動かすと、もう一方のカーソルも対応する位置に動く。対応する位置がない (挿入・削除区間の中) 場合は、区間の先頭に置く。
   - オフにすると、左右は独立してスクロールする。オンに戻すと、フォーカスのある側に合わせる。
5. 各ビューの右端に「差分マップ」(縦の帯) を置き、全体のうち差分のある位置を種類ごとの色の線で示す。クリックするとその位置へ移動する。帯の 1 ピクセルに複数の差分が入る場合は、最も多い種類で描く。
6. ステータスバーに「差分 12 / 340」(現在の差分の番号 / 総数)、異なるバイト数、一致率を表示する。
7. 比較タブでの編集はそれぞれのドキュメントに対して行い、通常のタブと同じく Undo できる。編集すると、比較タブ上部に InfoBar「内容が変更されました。比較結果は古くなっています。」と「再比較」ボタンを出す。
8. スクリーンリーダーは、カーソル位置のバイトについて「オフセット、値、差分の種類 (変更 / 挿入 / 削除 / 一致)、相手側の値」を読み上げる。
9. 右から左に書く言語でも、左右の配置は「左 = 比較の左側」のまま反転しない (Hex 表示部分は常に左から右、00 の 5.4)。

**画面**: 比較タブ。上部にツールバー (再比較、方式、前の差分、次の差分、同期スクロール、レイアウト、マージ操作、オプション)。中央に 2 つの Hex ビューと各ビューの差分マップ。下に差分の一覧パネル (ANA-06、既定で表示)。

**巨大ファイル・長時間処理**: 描画は見えている行だけを対象にし、差分の検索は差分一覧の索引 (オフセットで二分探索) を使う。100 GB のファイルどうしの比較でも、スクロールは 60 fps を保つ。差分マップはバックグラウンドで描き、描き終わるまで薄い色で仮表示する。

**エラー**:

- 比較の途中で一方のドキュメントが閉じられた: 比較を中止し、比較タブに「左側のドキュメントが閉じられたため比較を中止しました」と表示する。
- 一方のファイルが外部で変更された (ENG-19): 通常のタブと同じ通知を出し、比較タブにも「再比較」を出す。

**受け入れ基準**:

- [ ] 変更・挿入・削除がそれぞれ別の色と、別の色以外の印で表示される。ハイコントラストテーマで区別できる。
- [ ] 同期スクロールがオンのとき、片方をスクロールするともう片方が対応する位置にスクロールする。
- [ ] 挿入・削除を考慮した比較で、挿入区間の後ろの一致部分が左右同じ高さに表示される。
- [ ] 差分マップをクリックすると、その位置に移動する。
- [ ] 比較タブで編集すると「再比較」の InfoBar が出る。Ctrl+Z で編集を取り消せる。
- [ ] ナレーターで差分の種類と相手側の値が読み上げられる。

### ANA-05 次 / 前の差分へ移動

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-01 |
| 呼び出し | 移動 > 次の差分 (Alt+F5) / 前の差分 (Shift+Alt+F5)、比較タブのツールバー、コマンドパレット「比較: 次の差分」「比較: 前の差分」。ショートカットは 00-overview.md 8.2 (グローバル) |

**概要**: カーソル位置から見て次 (または前) の差分の先頭へ移動し、その差分を選択する。

**仕様**:

1. 「次の差分」は、フォーカスのある側のカーソルより後ろで最初に始まる差分の先頭へ移動し、差分の範囲を選択する。相手側も対応する差分を選択する。
2. 「前の差分」は、カーソルより前で始まる最後の差分へ移動する。カーソルが差分の中にある場合は、その差分の先頭へ移動する。
3. 末尾の差分から「次の差分」を実行すると、先頭の差分へ戻り、ステータスバーに「先頭の差分に戻りました」と 3 秒表示する。先頭から「前の差分」も同様。
4. 差分がない場合は、ステータスバーに「差分はありません」と表示し、移動しない。
5. 移動はジャンプ履歴 (VIEW-31) に記録する。
6. 比較タブ以外 (通常のタブ) でも、そのドキュメントを含む比較タブが開いていれば、その比較結果を使って移動できる。複数ある場合は最後に使った比較タブの結果を使う。
7. 比較の途中でも、それまでに見つかった差分の間を移動できる。

**画面**: 比較タブのツールバーのボタン (上向き・下向き矢印のアイコンと名前「前の差分」「次の差分」)。

**巨大ファイル・長時間処理**: 差分一覧の索引を二分探索するので、差分の件数に関係なく 100 ms 以内に移動する。

**エラー**: 比較結果がない状態で実行した: ステータスバーに「比較結果がありません」と表示する。メニュー項目は無効にする。

**受け入れ基準**:

- [ ] Alt+F5 で次の差分、Shift+Alt+F5 で前の差分へ移動する。
- [ ] 「次の差分」で次の差分の範囲が左右とも選択される。
- [ ] 最後の差分で「次の差分」を実行すると、先頭の差分に戻り、その旨が表示される。
- [ ] 1,000 万件の差分があっても、移動が 100 ms 以内に終わる。
- [ ] 移動後に Alt+← で移動前の位置に戻れる。

### ANA-06 差分の一覧とグラフ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-01 |
| 呼び出し | 比較タブの下部パネル「差分」、表示 > パネルの表示切り替え > 差分、コマンドパレット「比較: 差分の一覧を表示」 |

**概要**: 差分を共通の結果一覧 (00 の 9 章) で表示し、差分の分布をグラフで示す。

**仕様**:

1. 一覧の列: 番号、種類、左オフセット、左の長さ、右オフセット、右の長さ、左のバイト (先頭 16 バイト)、右のバイト (先頭 16 バイト)。
2. 行を選ぶと、比較ビューでその差分へ移動する。
3. 種類で絞り込める (変更 / 挿入 / 削除 / 読み込み不可)。長さで絞り込める (例: 4 バイト以上)。
4. 並べ替え: 番号 (= オフセット順)、長さ。
5. 共通の結果一覧の機能 (CSV / JSON へのエクスポート、選択した行のマルチ選択・ブックマークへの変換) を使える。マルチ選択・ブックマークへの変換は、左右どちらのドキュメントに作るかを選ぶ。
6. 要約欄: 比較方式、比較したバイト数 (左右)、差分の件数 (種類別)、異なるバイト数、一致率、比較にかかった時間、打ち切ったウィンドウの数 (ANA-03)。
7. グラフ「差分の分布」: 横軸を左側のオフセット (比較範囲全体)、縦軸を区間ごとの異なるバイトの割合 (0〜100%) とする棒グラフ。区間の数は既定 512、64〜4,096 で変更できる。棒をクリックすると、その区間の最初の差分へ移動する。
8. 比較結果をテキストのレポートとして保存できる (「レポートを保存...」)。内容は要約と、全差分の一覧 (種類、左オフセット、右オフセット、長さ、左右の先頭 16 バイトの Hex)。文字コードは UTF-8 (BOM なし)。

**画面**: 下部パネル。左に結果一覧、右にグラフと要約 (幅が 800 px 未満のときは上下に並べる)。グラフには「表で表示」ボタン (0.4)。

**巨大ファイル・長時間処理**: 一覧は仮想化し、1,000 万件以上でも表示できる。並べ替え (長さ順) は 100 万件を超える場合バックグラウンドで行い、処理中は一覧の上に進捗を出す。エクスポートは長時間処理として扱う。

**エラー**: エクスポート先に書き込めない: InfoBar に理由 (アクセス拒否、容量不足) を表示する。

**受け入れ基準**:

- [ ] 一覧の行を選ぶと、比較ビューがその差分へ移動する。
- [ ] 種類「挿入」で絞り込むと、挿入の差分だけが表示される。
- [ ] 選択した差分を左側ドキュメントのマルチ選択に変換できる。
- [ ] グラフの棒をクリックすると、その区間の最初の差分へ移動する。
- [ ] グラフを「表で表示」に切り替えると、区間ごとの割合が表で表示される。
- [ ] 100 万件の差分を CSV に出力でき、出力中も UI が固まらない (判定はテスト仕様書の方針 ([../test/00-test-strategy.md](../test/00-test-strategy.md)) の 7.3)。

### ANA-07 差分のマージ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-01 |
| 呼び出し | 比較タブのツールバー「右へコピー」「左へコピー」、差分の一覧の右クリックメニュー、コマンドパレット「比較: 差分を右へコピー」「比較: 差分を左へコピー」「比較: すべての差分を右へコピー」「比較: すべての差分を左へコピー」、ショートカットは既定なし |

**概要**: 差分の内容を一方からもう一方へコピーして、2 つのデータを揃える。

**仕様**:

1. 対象は次のいずれか。
   - 現在の差分 (カーソルのある差分)
   - 差分の一覧で選んだ差分 (複数可)
   - すべての差分
2. 「右へコピー」は、左側の内容で右側の該当区間を置き換える。種類ごとの動作:
   - 変更: 右の区間を左の区間の内容で置き換える (長さが異なる場合は右の長さが変わる)。
   - 削除 (左のみ): 左の区間の内容を右の対応位置に挿入する。
   - 挿入 (右のみ): 右の区間を削除する。
   - 「左へコピー」はこの逆。
3. 長さを変えられないデータソース (ディスク、プロセスメモリ、上書きモードに固定された読み取り専用でないドキュメントを含む) が書き込み先の場合、長さが変わる差分は対象外にする。対象外の件数を InfoBar で知らせる。
4. 1 回の操作 (複数の差分をまとめてコピーした場合も) を、書き込み先ドキュメントの Undo 1 回分として記録する。
5. コピーした差分は一覧から消え、比較ビューの対応付けを更新する (再比較はしない)。
6. 書き込み先が読み取り専用 (EDIT-16) の場合は実行できない。
7. マージは書き込み先ドキュメントを変更済みにするだけで、自動で保存しない。

**画面**: 比較タブのツールバーのボタン (矢印のアイコンと名前)。差分の一覧の右クリックメニュー。

**巨大ファイル・長時間処理**: データエンジンの操作として行うので、コピーするデータ量に関係なく 1 件あたり 100 ms 以内。差分が 1 万件を超える「すべての差分」は長時間処理として扱い、キャンセルした場合はそれまでの変更をすべて取り消す (中途半端な状態を残さない)。

**エラー**:

- 書き込み先が読み取り専用: メニュー項目を無効にし、ツールチップに「右側は読み取り専用です」と表示する。
- 長さが変わる差分を長さ固定のデータソースへコピーしようとした: 該当する差分を飛ばし、InfoBar に「長さが変わる差分 3 件はコピーしませんでした」と表示する。

**受け入れ基準**:

- [ ] 「変更」の差分を右へコピーすると、その区間が一致になる。
- [ ] 「削除」の差分を右へコピーすると、右に同じバイト列が挿入される。
- [ ] すべての差分を右へコピーした後で再比較すると、差分が 0 件になる。
- [ ] 複数の差分のコピーが Ctrl+Z 1 回で取り消せる。
- [ ] 書き込み先がディスクのとき、長さが変わる差分は飛ばされ、件数が通知される。

### ANA-08 保存済みの内容との比較

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-01 (関連: F1-18) |
| 呼び出し | 解析 > 比較 > 保存済みの内容と比較、タブの右クリックメニュー「保存済みの内容と比較」、外部変更の通知 (01) の「比較」ボタン、コマンドパレット「比較: 保存済みの内容と比較」 |

**概要**: 編集中のドキュメントと、ディスク上にある同じファイルの現在の内容を比較する。外部変更の通知 (ENG-19) の「比較」ボタンはこの機能を呼ぶ。外部変更の検知と通知の画面は ENG-19 が主担当で、この項目は比較の実行を定める (00-overview.md 1.1)。

**仕様**:

1. 左にディスク上の内容 (読み取り専用で開く)、右に編集中のドキュメントを置いて比較タブを開く。
2. ディスク上のファイルが、ドキュメントを開いた (または最後に保存した) 後に変更されていない場合は、データエンジンのピースツリーから直接差分を求める (元データを指すピースはすべて一致、それ以外が差分)。この場合の結果は正確で、ファイルの読み込みはしない。
3. ディスク上のファイルが外部で変更されている場合 (ENG-19 から呼ばれた場合を含む) は、比較方式の既定を「挿入・削除を考慮した比較」にして ANA-03 で比較する。ファイルが置き換えられた場合の元の内容の読み方は ENG-19 に従う。
4. 2 の方式では、変更・挿入・削除の区別はピースの種類から求める (挿入したピース → 挿入、削除した範囲 → 削除、上書きした範囲 → 変更)。
5. 未保存の編集がない場合は、ステータスバーに「保存済みの内容と同じです」と表示し、比較タブは開かない (外部変更がある場合を除く)。
6. 新規作成で一度も保存していないドキュメントでは実行できない。

**画面**: 比較ビュー (ANA-04)。左側のタブ名は `名前 (保存済み)`。

**巨大ファイル・長時間処理**: 2 の方式は、ピースの数に比例する時間で終わる (ファイルサイズには依存しない)。3 の方式は ANA-03 に従う。

**エラー**: ディスク上のファイルが削除されている・開けない: InfoBar に「保存済みのファイルを開けません: 理由」と表示する。

**受け入れ基準**:

- [ ] 100 GB のファイルで 3 か所を編集して実行すると、1 秒以内に 3 件の差分が表示される。
- [ ] 挿入した箇所は「挿入」、上書きした箇所は「変更」、削除した箇所は「削除」として表示される。
- [ ] 外部でファイルが変更されている場合、挿入・削除を考慮した比較が行われる。
- [ ] 未保存の編集がない場合は「保存済みの内容と同じです」と表示される。

### ANA-09 プロセスメモリのスナップショットと比較

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) (関連: F2-10) |
| 呼び出し | 解析 > 比較 > プロセスのスナップショットを作成...、解析 > 比較 > スナップショットを比較...、プロセスメモリのタブの右クリックメニュー「スナップショットを作成」、コマンドパレット「比較: スナップショットを作成」「比較: スナップショットを比較」 |

**概要**: プロセスメモリのスナップショットを、別の時点のスナップショットや現在のメモリと比較する。スナップショットの作成・保存 (対象の選び方、`.hexsnap` 形式、取得中の一時停止) は ENG-35 が主担当で、この項目は比較を定める (00-overview.md 1.1)。

**仕様**:

1. 「スナップショットを作成」は ENG-35 の作成の処理 (対象の選択、一時停止の選択を含む) を呼ぶ。この入口から作る場合は保存先を選ばず、一時フォルダに `.hexsnap` (ENG-35 の 3) として保存する。後から「名前を付けて保存」で任意の場所に保存できる。
2. スナップショットが持つ情報 (領域ごとの開始アドレス・サイズ・保護属性・種類・モジュール名、読めなかったページ) は ENG-35 の 3 に従う。
3. 保存済みの `.hexsnap` を開いたドキュメント (ENG-35 の 4) も比較の対象にできる。比較のダイアログの「スナップショット...」は `.hexsnap` を選ぶ。「ファイルを選択...」で `.hexsnap` を選んだ場合も、生のバイト列ではなくスナップショットとして領域ごとに比べる。
4. スナップショットには名前 (既定は `プロセス名 時刻`) を付け、比較の対象一覧 (ANA-01) に表示する。
5. 比較は、ベースアドレスが同じ領域どうしで行う (単純比較、ANA-02)。片方にしかない領域は「領域の追加」「領域の削除」として一覧に出す。サイズが変わった領域は、短い方の長さまで比較し、残りを「左のみ」「右のみ」にする。
6. 比較対象の組み合わせ: スナップショットどうし、スナップショットと現在のメモリ。
7. 差分の一覧 (ANA-06) には、オフセットの代わりに仮想アドレスと領域名 (モジュール名 + オフセット、または `private 0x...`) を表示する。
8. スナップショットで読めなかったページ (ENG-35 の 3) は、比較の結果で「読み込み不可」として表示し、差分には数えない (ステータスバーの「差分 n / N」の n・N に含めない。要約の種類別の件数の「読み込み不可」には出す)。
9. この機能の入口から一時フォルダに作ったスナップショットは、アプリの終了時に削除する (「名前を付けて保存」したものは残す)。

**画面**: 「スナップショットを作成」ダイアログは ENG-35 の保存のダイアログから保存先の欄を除いたもの (名前の欄を加える)。

**フェーズの区分**: ENG-35 (対象の選択、取得中の一時停止、ミニダンプ) はフェーズ 4 で実装した。フェーズ 3 の「スナップショットを作成」は、今のタブのプロセスの読めるすべての領域 (ENG-35 の仕様 1 の既定) を一時停止せずに取得し、ダイアログでは名前だけを決めていた。フェーズ 4 からは「画面」のとおり、名前・対象・一時停止を決める。対象のプロセスは、作成するときに選んでいるプロセスメモリのタブ (プロセスメモリのタブでないときはコマンドを使えない)。比較は比較タブ (ANA-04)。左右の Hex ビューは、領域を切り替えるコンボボックスを上部に持つ。

**巨大ファイル・長時間処理**: スナップショットの作成は ENG-35 の長時間処理に従う (空き容量の確認を含む)。比較は ANA-02 に従う。

**エラー**:

- 作成時のエラー (プロセスの終了、読めない領域、空き容量不足) は ENG-35 に従う。
- 権限不足でプロセスを読めない (どのページも権限不足で読めない): 01 のプロセスを開くときと同じく、昇格した補助プロセスでの再試行を提案する。補助プロセスを使えない配布形態では、管理者として実行する案内を出す。

**受け入れ基準**:

- [ ] プロセスのスナップショットを 2 回作り、比較すると、変化したアドレスが領域名付きで一覧に出る。
- [ ] スナップショットと現在のメモリを比較できる。
- [ ] 片方にしかない領域が「領域の追加」「領域の削除」として表示される。
- [ ] `.hexsnap` に保存したスナップショットを再起動後に開いて比較できる。
- [ ] 一時フォルダのスナップショットがアプリの終了時に削除される。

## 2. 統計

### ANA-10 統計パネルとヒストグラム

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-04 |
| 呼び出し | 解析 > 統計、表示 > パネルの表示切り替え > 統計、コマンドパレット「解析: 統計を表示」、選択範囲の右クリックメニュー「統計」、ショートカットは既定なし |

**概要**: 対象範囲の値の出現回数をヒストグラムと表で表示する。要素の型はバイト以外 (16〜64 bit 整数、浮動小数点) も選べる。

**仕様**:

1. 対象範囲は 0.1 の選択欄で指定する。
2. 要素の型: `u8` (既定)、`s8`、`u16`、`s16`、`u32`、`s32`、`u64`、`s64`、`f32`、`f64`。2 バイト以上の型ではエンディアン (既定はドキュメントのエンディアン設定) と、要素の間隔 (ストライド、既定は型のサイズ、1〜65,536) を指定する。対象の末尾で要素に満たないバイトは数えず、その数を「端数: 3 バイト」と表示する。
3. ビン (区間):
   - `u8` / `s8`: 256 個のビン (値ごと) に固定。
   - その他の型: ビンの数 (既定 256、2〜65,536) と範囲 (既定は「自動」= 最小値〜最大値。手入力も可) を指定する。範囲外の値は「範囲より小さい」「範囲より大きい」の 2 つの欄で数える。
   - `u16` / `s16` は「値ごと (65,536 個)」も選べる。
4. 浮動小数点の NaN、+∞、−∞ はビンに入れず、別の欄で数える。
5. ヒストグラムの表示: 縦軸は件数または割合 (%)。縦軸の目盛りは線形または対数を選べる (既定は線形)。
6. 表の列: 値 (またはビンの範囲)、件数、割合、累積割合。`u8` では文字 (現在の文字コードでの表示) の列も出す。件数・値で並べ替えられる。
7. `u8` の場合、次の分類ごとの割合も表示する: `0x00`、`0xFF`、印字可能な ASCII (`0x20`〜`0x7E`)、空白類 (`0x09`、`0x0A`、`0x0D`)、その他の制御文字、`0x80`〜`0xFF`。
8. ヒストグラムの棒または表の行をダブルクリックすると、その値 (ビン) の次の出現位置へ移動する (末尾まで見つからなければ先頭から探し直す)。右クリックメニュー「この値をすべて検索」で 04 のすべて検索を実行する。「この値をすべて検索」は値 1 つのビン (u8・s8、u16・s16 の「値ごと」) だけで使え、範囲のビンでは無効にする (値の範囲の検索 FIND-15 から呼ぶ形は後で加える)。
9. パネルの「自動で再計算」(既定でオン) がオンのとき、対象範囲が変わると 300 ms 待ってから再計算する。ただし対象が 64 MB を超える場合は自動で再計算せず、「再計算」ボタンを強調表示する。
10. 結果は CSV / JSON にエクスポートでき、表をクリップボードにタブ区切りでコピーできる。

**画面**: 統計パネル (既定は下部)。上部に対象範囲の選択欄、型、エンディアン、ストライド、ビンの設定。中央にタブ「ヒストグラム」「記述統計 (ANA-11)」「エントロピー (ANA-12、ANA-13)」「ダイグラム (ANA-14)」「パターン (ANA-15)」「分類 (ANA-16)」。各タブのグラフに「表で表示」ボタン (0.4)。

**巨大ファイル・長時間処理**: 1 回の順次読み込みで計算する。速度の目標はストレージの読み込み速度の 80% 以上 (`u8` の場合)。0.5 秒ごとに途中結果を描き直す。キャンセルした場合は、そこまでの結果を「途中で中止 (xx% まで)」と表示して残す。「自動」範囲のビンは、最小値・最大値を求める 1 回目の読み込みと、数える 2 回目の読み込みが必要なので、64 bit 型では処理時間が 2 倍になることを設定欄の説明に書く。

**エラー**:

- 対象範囲が型のサイズより短い: 「要素が 1 つもありません」と表示する。
- 読み込みエラー: 読めなかった範囲を除いて計算を続け、「読み込めなかった範囲: 2 か所、8,192 バイト」と表示する。

**受け入れ基準**:

- [ ] すべて `0x41` の 1 MB の範囲で、`0x41` の件数が 1,048,576、割合 100% になる。
- [ ] `u16` LE で `01 00 01 00 02 00` を対象にすると、1 が 2 件、2 が 1 件になる。
- [ ] ストライド 4 の `u16` で、4 バイトごとの先頭 2 バイトだけが数えられる。
- [ ] `f32` で NaN が別の欄で数えられる。
- [ ] 棒をダブルクリックすると、その値の次の出現位置へ移動する。
- [ ] 10 GB のファイル全体のバイトヒストグラムが、読み込み速度の 80% 以上で求まる。
- [ ] 「表で表示」でグラフと同じ値の表が表示される。

### ANA-11 記述統計

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-04 |
| 呼び出し | 統計パネルの「記述統計」タブ、コマンドパレット「解析: 記述統計」 |

**概要**: 対象範囲の要素の平均・分散・中央値などの記述統計量を求める。

**仕様**:

1. 要素の型・エンディアン・ストライドは ANA-10 の設定を共有する。
2. 求める値:

   | 項目 | 定義 |
   | --- | --- |
   | 要素数 | 数えた要素の数 (NaN・∞ を除く) |
   | 合計 | 要素の合計 (整数型は 128 bit 整数で正確に、浮動小数点は補正付き加算 (Kahan) で計算) |
   | 最小値 / 最大値 / 範囲 | 範囲 = 最大値 − 最小値 |
   | 平均 | 合計 / 要素数 |
   | 分散 | 母分散と標本分散 (不偏分散) の両方。Welford の方法で計算 |
   | 標準偏差 | 母標準偏差と標本標準偏差 |
   | 中央値 | 要素数が偶数の場合は中央 2 つの平均 |
   | 第 1 / 第 3 四分位数 | 線形補間 (Excel の `QUARTILE.INC` と同じ方法) |
   | 最頻値 | 最も多く現れる値。同数の値が複数ある場合は小さい順に最大 5 個まで表示し、「ほか n 個」と書く |
   | 歪度 | 標本歪度 (調整済み Fisher-Pearson 係数) |
   | 尖度 | 超過尖度 (正規分布で 0) |
   | カイ二乗値 | `u8` のみ。一様分布を仮定した値と p 値 |
   | 系列相関係数 | 隣り合う要素の相関係数 (−1〜1) |
   | 算術平均の π 推定 | `u8` のみ。6 バイトを 1 組の座標とするモンテカルロ法での π の推定値と誤差 (%)。乱数性の目安 |

3. 中央値・四分位数・最頻値は、`u8`・`s8`・`u16`・`s16` ではヒストグラムから正確に求める。それ以外の型では、要素数が 1,600 万以下なら全要素を並べ替えて正確に求める。1,600 万を超える場合は中央値・四分位数を近似 (t-digest) で求めて値の前に `≈` を付け、最頻値は「—」(ツールチップ「要素数が多すぎるため求めていません」) にする。
4. 値は型に応じて表示する。整数型の最小値・最大値・最頻値は 10 進と 16 進を並べる。小数は有効数字 10 桁。
5. 「値をコピー」で 1 項目を、「すべてコピー」で全項目を `項目名<TAB>値` の形でコピーする。

**画面**: 統計パネルの「記述統計」タブ。2 列の表 (項目、値)。各項目名にツールチップで定義を表示する。

**巨大ファイル・長時間処理**: ANA-10 と同じ読み込みで同時に計算する (追加の読み込みはしない。ただし 3 の正確な中央値のための並べ替えは、要素を一時的に最大 128 MB のメモリに保持する)。

**エラー**: 要素数が 0 または 1: 分散・歪度・尖度など計算できない項目は「—」とし、ツールチップに理由を出す。

**受け入れ基準**:

- [ ] `u8` の値 1, 2, 3, 4 の 4 バイトで、平均 2.5、母分散 1.25、標本分散 1.666666667 (有効数字 10 桁の表示。4 を参照)、中央値 2.5 になる。
- [ ] 歪度・尖度が、同じデータでの NumPy / SciPy (`scipy.stats.skew(bias=False)`、`kurtosis(bias=False)`) の値と小数第 6 位まで一致する。
- [ ] 1 億要素の `u32` で中央値に `≈` が付き、最頻値が「—」になる。
- [ ] 一様乱数 1 MB のカイ二乗の p 値が 0.01〜0.99 に入る。
- [ ] 整数の合計が 64 bit を超えても正しく表示される。

### ANA-12 エントロピー・冗長度・圧縮率の推定

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-04 |
| 呼び出し | 統計パネルの「エントロピー」タブ、コマンドパレット「解析: エントロピー」 |

**概要**: 対象範囲のシャノンエントロピー、冗長度、圧縮したときのおおよその大きさを求める。

**仕様**:

1. エントロピー H は、ANA-10 のヒストグラム (ビン) の出現確率 p から `H = −Σ p log2 p` で求める。単位は「ビット / 要素」。
2. 表示する値:

   | 項目 | 定義 |
   | --- | --- |
   | エントロピー | H (ビット / 要素)。`u8` では 0〜8 ビット / バイト |
   | エントロピー (%) | H / log2(ビンの数) × 100 |
   | 冗長度 | 1 − H / log2(ビンの数) (%) |
   | 理論上の最小サイズ | H × 要素数 / 8 バイト (0 次のエントロピー符号化の下限) |
   | 圧縮率の推定 | 下記 3 の試し圧縮での圧縮後サイズ / 元のサイズ (%) |

3. 試し圧縮: 対象から 64 KB のブロックを均等な間隔で最大 1,024 個 (合計 64 MB) 取り出し、Deflate (圧縮レベル 6、.NET 標準) で圧縮して比率を求める。対象が 64 MB 以下なら全体を圧縮する。結果には「標本: 64 MB / 10 GB」のように標本の大きさを表示する。
4. 判定の目安を文章で表示する (色だけにしない):
   - H < 1: 「ほぼ同じ値の繰り返し」
   - 1 ≤ H < 5: 「テキストや構造化データの可能性」
   - 5 ≤ H < 7.2: 「一般的なバイナリ (実行形式など) の可能性」
   - 7.2 ≤ H: 「圧縮または暗号化されたデータの可能性」(詳しい判定は ANA-16)
   - この目安は `u8` の場合だけ表示する。
5. 試し圧縮は「圧縮率を推定する」チェックボックス (既定でオン) で無効にできる。

**画面**: 統計パネルの「エントロピー」タブ上部に値の表。下部にエントロピーグラフ (ANA-13)。

**巨大ファイル・長時間処理**: エントロピーは ANA-10 のヒストグラムから求めるので追加の読み込みはない。試し圧縮は別の長時間処理として並行して行い、最大 64 MB だけ読む。

**エラー**: 試し圧縮の失敗 (メモリ不足など): 圧縮率の推定を「—」にし、ツールチップに理由を出す。他の値は表示する。

**受け入れ基準**:

- [ ] すべて同じ値の範囲で、エントロピー 0、冗長度 100% になる。
- [ ] `00`〜`FF` が 1 回ずつ並んだ 256 バイトで、エントロピー 8、エントロピー 100% になる。
- [ ] 暗号論的乱数 10 MB でエントロピーが 7.99 以上、目安が「圧縮または暗号化されたデータの可能性」になる。
- [ ] 100 GB のファイルで試し圧縮の標本が 64 MB 以下で、標本の大きさが表示される。

### ANA-13 エントロピーグラフ

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-04 (関連: F2-03) |
| 呼び出し | 統計パネルの「エントロピー」タブ、コマンドパレット「解析: エントロピーグラフ」 |

**概要**: 対象範囲を一定の大きさのブロックに分け、ブロックごとのエントロピーを折れ線グラフで表示する。

**仕様**:

1. ブロックの大きさ: 「自動」(既定) または 256 バイト〜64 MB の 2 の累乗。「自動」は、対象の長さ / 1,024 以上で最小の 2 の累乗 (最小 256 バイト)。ブロック数は最大 1,048,576 個とし、指定の大きさで超える場合は超えない最小の 2 の累乗に上げる (メモリをブロック数で抑えるため)。
2. ブロックごとのエントロピー (`u8`、0〜8 ビット / バイト) を計算し、横軸をオフセット、縦軸をエントロピーとして描く。
3. 補助の系列を追加できる (既定はオフ): ブロックごとの `0x00` の割合、印字可能な ASCII の割合。系列は線の種類で区別する。
4. 横方向に拡大・縮小できる (Ctrl + マウスホイール、または拡大・縮小ボタン)。拡大して 1 ブロックが 4 ピクセル以上になると、表示範囲だけを細かいブロックで計算し直す (最小 256 バイト)。
5. グラフをクリックすると、そのブロックの先頭へ移動する。ドラッグすると、その範囲を選択する。
6. Hex ビューのカーソル位置を、グラフ上に縦線で示す。
7. しきい値の線 (既定 7.2 ビット) を描く。しきい値を超えるブロックが続く区間は、背景に模様を付ける。しきい値は 0〜8 の範囲で変更できる。
8. ミニマップ (02、F2-03) のエントロピー表示は、ここで計算したブロックごとのエントロピーをキャッシュとして共有する。同じドキュメント・同じブロックの大きさであれば再計算しない。キャッシュはドキュメントの編集で、編集された範囲を含むブロックだけ無効にする。
9. グラフの値を CSV (ブロックの開始オフセット, エントロピー) にエクスポートできる。

**画面**: 統計パネルの「エントロピー」タブ下部。グラフの上にブロックの大きさ、補助の系列、しきい値の設定。グラフに「表で表示」ボタン (0.4)。キーボードでは、グラフにフォーカスがあるとき ← / → でブロックを 1 つずつ移動し、Enter でそのブロックへジャンプする。

**巨大ファイル・長時間処理**: 1 回の順次読み込みで全ブロックを計算する。計算中は、計算済みのブロックから順に描く。100 GB のファイルでもブロック数は最大 1,024 前後 (「自動」の場合) なので、描画の負荷はサイズに依存しない。キャンセルした場合は、計算済みのブロックだけを表示する。

**エラー**: 読み込めなかったブロック: グラフの線を途切れさせ、その範囲にグレーの斜線を描く。表では「読み込み不可」と表示する。

**受け入れ基準**:

- [ ] 前半がゼロ、後半が乱数の 2 GB のファイルで、前半 0、後半ほぼ 8 のグラフになる。
- [ ] グラフをクリックすると、そのブロックの先頭へ移動する。ドラッグでその範囲が選択される。
- [ ] 拡大すると、表示範囲が細かいブロックで再計算される。
- [ ] ミニマップのエントロピー表示が、統計パネルで計算済みの場合に再計算されない。
- [ ] キーボードだけでブロックを移動し、ジャンプできる。

### ANA-14 ダイグラムとバイト分布の図

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 統計パネルの「ダイグラム」タブ、コマンドパレット「解析: ダイグラム」「解析: 位置ごとのバイト分布」 |

**概要**: 連続する 2 バイトの組 (ダイグラム) の出現頻度を 256 × 256 の図で表示する。あわせて、オフセットとバイト値の関係を示す「位置ごとのバイト分布」図を表示する。

**仕様**:

1. ダイグラム: 対象範囲の各位置 i について (b[i], b[i+1]) を数え、横軸を b[i]、縦軸を b[i+1] とする 256 × 256 のヒートマップで表示する。濃さは件数の対数に比例させる。
2. 位置ごとのバイト分布: 横軸をオフセット (対象範囲を 512 区間に分ける)、縦軸をバイト値 (0〜255) とし、区間ごとの各バイト値の件数を濃さで表すヒートマップ。
3. 図の上にマウスを置くと、値 (例: `0x4D 0x5A`)、件数、割合をツールチップで表示する。
4. ダイグラムのセルをダブルクリックすると、その 2 バイト列を検索バー (04) に入れて次を検索する。位置ごとのバイト分布のセルをクリックすると、その区間の先頭へ移動する。
5. 色は ThemeResource の単色の濃淡で描く。ハイコントラストテーマではシステム色の濃淡 (段階を 8 段階に減らし、段階ごとに模様を変える) で描く。
6. 表で表示する場合は、件数の多い組の上位 1,000 件を件数順に並べる。

**画面**: 統計パネルの「ダイグラム」タブ。2 つの図をタブ (「ダイグラム」「位置ごとの分布」) で切り替える。図は正方形を保って拡大・縮小する。

**巨大ファイル・長時間処理**: カウンタは 65,536 個 (ダイグラム) と 512 × 256 個 (位置ごと) で、メモリは対象の大きさに依存しない。1 回の順次読み込みで計算し、ANA-10 と同じ読み込みに相乗りできる場合は相乗りする。

**エラー**: 対象が 2 バイト未満: ダイグラムに「2 バイト以上の範囲を指定してください」と表示する。

**受け入れ基準**:

- [ ] `41 42 41 42` で、(0x41, 0x42) が 2 件、(0x42, 0x41) が 1 件になる。
- [ ] セルの上で値と件数のツールチップが出る。
- [ ] セルをダブルクリックすると、その 2 バイトが検索される。
- [ ] 10 GB のファイルでもメモリ使用量が増えない。

### ANA-15 パターン統計

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 統計パネルの「パターン」タブ、コマンドパレット「解析: よく現れるバイト列」 |

**概要**: 対象範囲で多く現れる n バイトの列 (n-gram) と、データの繰り返しの周期を求める。

**仕様**:

1. よく現れるバイト列:
   - 長さ n: 2〜16 (既定 4)。
   - 上位 K 件: 10〜10,000 (既定 100)。
   - 最小件数: 2 以上 (既定 2)。
   - 位置の条件 (任意): 「オフセット mod a = b」のアラインメントに一致する位置だけを数える (既定は条件なし)。
   - 「すべて 0x00」「すべて 0xFF」の列を除く (既定でオン)。
2. 結果の列: 順位、バイト列 (Hex)、テキスト表示、件数、割合、最初の出現位置。行のダブルクリックで最初の出現位置へ、右クリックメニュー「すべて検索」で 04 のすべて検索を実行する。
3. 繰り返しの周期の推定:
   - 対象範囲の自己相関 (位置を k だけずらしたときに一致するバイトの割合) を k = 1〜4,096 について求め、割合の高い k を上位 10 件表示する。割合がほぼ同じ (差が 0.5 ポイント以内) なら、その約数の k を先にする (64 と 128 なら 64)。
   - 結果の行から「この長さでレコード表示」(02、F2-16) を実行できる。
   - 結果の行から「この長さでテンプレートを推定」(07 の TPL-38、フェーズ 6) を実行できる。
   - 自己相関の計算は対象の先頭 64 MB だけを使う。先頭 64 MB の中に均等に置いた 8 か所 × 256 KB の標本で比べる (対象が約 2 MB 以下なら全体)。
4. 件数は常に正確な値を表示する (大きな対象でも、下記「巨大ファイル・長時間処理」の 2 段階方式で数え直す)。

**画面**: 統計パネルの「パターン」タブ。上に設定、下に結果一覧 (共通の結果一覧) を 2 つ (「よく現れるバイト列」「周期」) タブで切り替える。

**巨大ファイル・長時間処理**:

- 対象が 256 MB 以下の場合は、すべての n-gram をハッシュ表で正確に数える。256 MB を超える場合は、1 回目の読み込みで Count-Min スケッチと上位候補 (Space-Saving 法、候補数 = K × 10) を求め、2 回目の読み込みで候補の件数を正確に数え直す。作業用メモリは 256 MB 以内とする。
- 長時間処理として扱い、キャンセルした場合は結果を破棄する (部分的な上位一覧は誤解を招くため)。

**エラー**: 作業用メモリの上限に達した (256 MB 以下でも種類が非常に多い場合): 自動で上記の 2 段階方式に切り替えて続行する。

**受け入れ基準**:

- [ ] `DE AD BE EF` を 1,000 回含むファイルで、n = 4 の 1 位が `DE AD BE EF` (1,000 件) になる。
- [ ] 1 GB のファイルでも、作業用メモリが 256 MB を超えず、上位の件数が正確 (別の方法で数えた値と一致) である。
- [ ] 64 バイトの固定長レコードが並ぶファイルで、周期の 1 位が 64 になる。
- [ ] 周期の結果からレコード表示を実行できる。

### ANA-16 暗号化・圧縮データの検出

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) |
| 呼び出し | 統計パネルの「分類」タブ、解析 > 暗号化・圧縮データの検出、コマンドパレット「解析: 暗号化・圧縮データを検出」 |

**概要**: 対象範囲をブロックごとに調べ、ゼロ埋め・テキスト・バイナリ・圧縮・暗号化 (または乱数) のどれに近いかを分類する。既知の圧縮形式のヘッダも探す。

**仕様**:

1. ブロックの大きさは 4 KB (既定)。512 バイト〜1 MB の 2 の累乗から選べる。
2. ブロックごとに、エントロピー H、カイ二乗の p 値、印字可能 ASCII の割合、最頻値の割合を求め、次の順に判定する。

   | 分類 | 条件 (既定値) |
   | --- | --- |
   | 定数 | 最頻値の割合 ≥ 99% (`0x00` の場合は「ゼロ埋め」と表示) |
   | テキスト | 印字可能 ASCII と空白類の割合 ≥ 95%、または UTF-8 / UTF-16 として妥当な割合 ≥ 95% |
   | 暗号化・乱数 | H ≥ 7.9 かつ 0.01 ≤ p ≤ 0.99 |
   | 圧縮 | H ≥ 7.2 で、上の条件に当たらない |
   | バイナリ | 上のどれにも当たらない |

3. 同じ分類のブロックが続く部分を 1 つの区間にまとめ、一覧に出す。列: 開始オフセット、長さ、分類、平均エントロピー、判定の確度 (高 / 中 / 低。しきい値からの離れ具合で決める)。統計のゆらぎによる細切れはならす: 末尾のブロックの大きさの半分に満たないブロックは前のブロックと同じ分類にし、2 ブロック以下の「暗号化・乱数」「圧縮」の区間が、もう一方の高エントロピーの分類のより長い区間と隣り合う場合はその分類にまとめる (乱数のブロックの約 2% は p 値の条件を外れるため)。
4. 既知の圧縮・暗号化形式のシグネチャを探し、見つかった位置を一覧に追加する。zlib と gzip は展開できることも確かめ (展開できないものは偶然の一致として除く)、展開できたストリームの範囲 (512 バイト単位) の高エントロピーのブロックは「圧縮」とする (統計だけでは圧縮と暗号化を区別しにくいため)。対象: zlib (`78 01` / `78 5E` / `78 9C` / `78 DA`、ヘッダのチェック値が正しいものだけ)、gzip (`1F 8B 08`)、zstd (`28 B5 2F FD`)、xz (`FD 37 7A 58 5A 00`)、bzip2 (`42 5A 68` + `31`〜`39`)、LZ4 フレーム (`04 22 4D 18`)、7z (`37 7A BC AF 27 1C`)、ZIP のローカルヘッダ (`50 4B 03 04`)、Brotli は判定不能のため対象外、OpenSSL の `Salted__`、PGP のパケットヘッダ (確度 低)。
   - 実装の注記 (フェーズ 6 の監査): 見つかった位置の一覧は最大 1,048,576 件 (2^20) まで持ち、それより後ろのシグネチャは加えない (シグネチャだけを敷き詰めたデータで、一覧がデータの長さに比例して増えないため)。
5. 圧縮形式のシグネチャの行の右クリックメニューに「ここから展開...」を置き、03 の展開機能 (F4-04) を、開始オフセットと形式を指定した状態で開く。フェーズ 2 では項目を出して無効にし、展開機能 (フェーズ 4) ができてからつなぐ。
6. 判定のしきい値は詳細設定で変更できる。
7. 結果をミニマップ (02) に「分類」レイヤとして重ねて表示できる。レイヤはミニマップの印の 1 つとして ON / OFF を選べる (既定は ON。VIEW-35 の仕様 6)。
8. この判定は推定である。パネルに「統計に基づく推定で、誤判定がありえます」と常に表示する。

**画面**: 統計パネルの「分類」タブ。上部に区間の割合を示す横長の帯 (分類ごとに色と模様を変える、凡例付き)、下に結果一覧。

**巨大ファイル・長時間処理**: 1 回の順次読み込みで、ブロックの分類とシグネチャの探索を同時に行う。メモリはブロック数に比例する (100 GB / 4 KB = 約 2,600 万ブロックの場合、分類は 1 ブロック 1 バイトで保持し、約 26 MB)。キャンセルした場合は、処理済みの範囲の結果を残す。

**エラー**: 読み込めなかったブロック: 分類「読み込み不可」とする。

**受け入れ基準**:

- [ ] ゼロ埋め・英文テキスト・gzip で圧縮したデータ・AES で暗号化したデータを連結したファイルで、4 つの区間がそれぞれ正しく分類される。
- [ ] 埋め込まれた zlib ストリームの位置が一覧に出て、「ここから展開...」で展開画面が開く。展開画面が開くことは、03 の展開機能 (F4-04、フェーズ 4) ができてから確認する。それまでは一覧に出ることだけを確認する。
- [ ] 凡例と模様で、色が見えなくても分類を区別できる。
- [ ] 100 GB のファイルで、メモリ使用量が 1 GB を超えない。

## 3. ファイル形式の判定

### ANA-17 ファイル形式の判定

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 2 提案) (関連: F3-02) |
| 呼び出し | 解析 > ファイル形式の判定、ステータスバーの形式表示をクリック、コマンドパレット「解析: ファイル形式を判定」「解析: 埋め込まれた形式を探す」、選択範囲の右クリックメニュー「ここからの形式を判定」 |

**概要**: マジックナンバーなどから、ドキュメント (または指定位置から始まるデータ) のファイル形式と MIME タイプを判定する。

**仕様**:

1. 内蔵のシグネチャデータベースを使う。データベースは本プロジェクトが自前で作成・保守するシグネチャの一覧で、リポジトリ内のデータファイル (JSON) として管理し、アプリに同梱する。第三者のマジックナンバーのデータベースは使わない。各項目は、形式名、MIME タイプ、拡張子、判定条件 (オフセットとバイト列 (ワイルドカード `??` 可)、文字列、数値の比較、複数条件の AND / OR、入れ子の条件)、優先度を持つ。内蔵のデータベースは拡張できる。利用者は同じ形式 (JSON) の追加のデータベースを設定フォルダの `magic/` に置ける。プラグインは拡張ポイント `IFileTypeDetector` (08 の AUTO-31) で判定を追加できる。追加のデータベースとプラグインの判定結果は、内蔵の項目と同じように候補の一覧に加える。
2. 収録する形式は、少なくとも標準テンプレート集 (07 の TPL-34) にある全形式と、主要な画像・音声・動画・文書・アーカイブ・実行形式・ディスクイメージ・データベースの形式 (合計 300 形式以上) とする。
3. 判定の結果: 候補の一覧 (形式名、MIME、拡張子、確度 (%)、一致した条件の位置)。確度の高い順に並べる。
4. ドキュメントを開いたとき、先頭から 64 KB と末尾 64 KB を使って自動で判定し、最も確度の高い形式名をステータスバーに表示する (設定でオフにできる)。判定はバックグラウンドで行い、ファイルを開く時間 (1 秒以内) に影響させない。
5. 「ここからの形式を判定」は、カーソル (または選択範囲の先頭) をオフセット 0 とみなして判定する。
6. 「埋め込まれた形式を探す」は、対象範囲の全オフセットでシグネチャを探し、見つかった位置を共通の結果一覧に出す (フェーズ 2 では「ファイル形式」パネルの中の一覧に出す。共通の結果一覧 (FIND-20) が検索以外の結果を受け付けるようになったら移す)。対象範囲の先頭は、先頭の固定バイト列の短い形式 (PE の `MZ` など) も含めてすべての項目で判定する。列: オフセット、形式名、MIME、確度。誤検出を減らすため、先頭の固定バイト列が 4 バイト以上ある条件だけを使う。ファイルの切り出し (カービング) はフォレンジック (12、F5-05) で行い、ここでは行わない。
7. 判定結果はテンプレートの自動適用 (07 の TPL-30) と統計の分類 (ANA-16) に渡す。分類では、ドキュメントの先頭から始まる対象で、最も確度の高い形式が圧縮されたデータの形式 (ZIP・gzip・7z・xz・zstd・PNG・JPEG・MP4 など) なら、高エントロピーのブロックを「暗号化・乱数」ではなく「圧縮」(確度 中) とし、使った形式名をパネルに表示する。
8. 拡張子と判定結果が食い違う場合 (例: 拡張子 `.jpg` で中身が PNG) は、判定結果の欄に「拡張子と内容が一致しません」と表示する。

**画面**: 「ファイル形式」パネル (既定は右)。判定結果の候補一覧と、選んだ候補の詳細 (一致した条件、その位置へ移動するリンク)。ステータスバーの形式表示 (例: `PNG image`) は、クリックでこのパネルを開く。

**巨大ファイル・長時間処理**: 4 の自動判定は最大 128 KB しか読まない。6 の全体走査は長時間処理として扱い、多数のパターンを同時に探す (Aho-Corasick 法) ことで、速度の目標をストレージの読み込み速度の 50% 以上とする。

**エラー**:

- どの形式にも当たらない: 「不明な形式 (データ)」と表示する。テキストとして妥当な場合は「テキスト (UTF-8)」などと表示する。
- 利用者のデータベースの構文エラー: 起動時にそのファイルを読み飛ばし、InfoBar に「magic/xxx.json を読み込めません: 12 行目」と表示する。

**受け入れ基準**:

- [ ] PNG・JPEG・PDF・ZIP・PE・ELF のファイルで、それぞれ正しい形式名と MIME が表示される。MIME は順に `image/png`、`image/jpeg`、`application/pdf`、`application/zip`、`application/vnd.microsoft.portable-executable`、`application/x-elf` とする。
- [ ] 拡張子を `.jpg` に変えた PNG ファイルで「拡張子と内容が一致しません」と表示される。
- [ ] 100 GB のファイルを開いても、先頭の表示が 1 秒以内で、形式名はその後に表示される。
- [ ] PNG 画像を埋め込んだ実行ファイルで「埋め込まれた形式を探す」を実行すると、PNG の位置が一覧に出る。
- [ ] `magic/` に置いた利用者の定義で判定できる。

## 4. ハッシュ・チェックサム

### ANA-18 ハッシュパネル (計算対象と同時計算)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-17 (マルチ選択と除外範囲は F2-14) |
| 呼び出し | 解析 > ハッシュ、表示 > パネルの表示切り替え > ハッシュ、コマンドパレット「解析: ハッシュを計算」、選択範囲の右クリックメニュー「ハッシュを計算」、ショートカットは既定なし |

**概要**: 対象範囲のハッシュ値・チェックサムを、選んだ複数のアルゴリズムで 1 回の読み込みで同時に計算する。

**仕様**:

1. 対象範囲は 0.1 の選択欄で指定する。マルチ選択の場合は、計算方法を次から選ぶ。
   - 連結して 1 つの値を求める (既定。オフセットの小さい順に連結)
   - 範囲ごとに値を求める (結果の表が範囲ごとの行になる)
2. 除外範囲: 計算から外す範囲を複数指定できる (開始と長さの入力式、または「選択範囲を追加」)。除外の方法を選ぶ。
   - 飛ばす (既定): 除外範囲のバイトを入力に含めない。
   - 置き換える: 除外範囲のバイトを指定した値 (既定 `0x00`) とみなして計算する (例: チェックサム欄自体を 0 として計算する PE のチェックサム)。
3. アルゴリズムは ANA-19 の一覧からチェックボックスで複数選ぶ。選んだ組み合わせを「セット」として名前を付けて保存できる。最初から用意するセット:
   - よく使う (既定): CRC-32、MD5、SHA-1、SHA-256
   - 暗号学的ハッシュ: MD5、SHA-1、SHA-256、SHA-512、SHA3-256、BLAKE3
   - チェックサム: 加算 8 / 16 / 32 bit、XOR 8 bit、CRC-16/ARC、CRC-32、Adler-32
4. 選んだアルゴリズムはすべて同じ読み込みデータを受け取り、並列に計算する (読み込みは 1 回)。
5. 結果の表: アルゴリズム名、値、ビット数。値の表示形式を選べる: Hex 大文字 (既定)、Hex 小文字、Base64、10 進 (64 bit 以下のアルゴリズムのみ)。
6. 64 bit 以下のチェックサム・CRC は、値のバイト順を選べる: ビッグエンディアン表記 (既定、数値としての表記) / リトルエンディアンのバイト列表記。
7. 「自動で再計算」(既定でオン): 対象範囲が変わると 300 ms 待って再計算する。対象が 64 MB を超える場合は自動で計算せず、「計算」ボタンを強調表示する。
8. パラメータを持つアルゴリズム (シード、鍵、出力長) は、表の行の「設定」ボタンでパラメータを入力する (ANA-19 の表を参照)。パラメータは結果の行に表示する (例: `xxHash64 (seed=0x1234)`)。
9. 計算した結果は、パネルを閉じるまで履歴として保持し、「前回の結果」と比べて変わった値に印 (アイコンと「変更」の文字) を付ける。

**フェーズの区分**: ロードマップの行のとおり、1 のマルチ選択と 2 の除外範囲は F2-14 (フェーズ 2)。「エラー」の「読めない範囲を除外範囲に追加するボタン」も除外範囲とともに加える。3 のセットは、フェーズ 2 のアルゴリズム (SHA3-256、BLAKE3 など) を含むものも、使えるアルゴリズムだけを選ぶ。8 のパラメータは、フェーズ 1 のアルゴリズムでは加算チェックサムの「結果の補数」だけ (シード・鍵・出力長はフェーズ 2 のアルゴリズムとともに加える)。

**画面**: ハッシュパネル (既定は右)。上から: 対象範囲の選択欄、除外範囲の一覧 (Expander、既定で閉じる)、アルゴリズムの選択 (セットのコンボボックスと、検索付きのチェックボックス一覧)、「計算」ボタンと進捗、結果の表 (アルゴリズム、値、操作ボタン)。値は等幅フォントで表示し、長い値は折り返す。

**巨大ファイル・長時間処理**:

- 長時間処理として扱い、処理速度 (MB/s) を表示する。
- 速度の目標: CRC-32 / xxHash / BLAKE3 のみの場合はストレージの読み込み速度の 80% 以上。SHA-256 はハードウェア支援 (SHA 拡張命令) がある CPU で 1 GB/s 以上。
- 遅いアルゴリズム (MD2、Whirlpool など) が含まれる場合は、全体の速度がそのアルゴリズムで決まることを、そのアルゴリズムの行の注記に表示する。
- キャンセルした場合、結果は破棄する (途中までのハッシュ値は意味がないため)。

**エラー**:

- 読み込みエラー: 計算を中止し、「オフセット 0x... を読み込めないため計算できません」と表示する。読めない範囲を除外範囲に追加するボタンを出す。
- 除外範囲が対象範囲の外にある: 除外範囲の行に警告アイコンと「対象範囲の外です」を表示し、計算では無視する。
- パラメータが不正 (鍵の長さが違うなど): その行を赤枠にし、その行だけ計算しない。

**受け入れ基準**:

- [ ] 4 つのアルゴリズムを選んで計算すると、ファイルの読み込みが 1 回だけ行われる (読み込んだバイト数がファイルサイズと同じ)。
- [ ] `123456789` (ASCII) の 9 バイトを選択すると、CRC-32 が `CBF43926`、MD5 が `25F9E794323B453885F5181F1B624D0B` になる。
- [ ] 除外範囲を「置き換える (0x00)」で指定すると、その範囲を 0 にしたファイルと同じ値になる。
- [ ] マルチ選択で「範囲ごと」を選ぶと、範囲ごとの行が表示される。
- [ ] 64 MB を超える選択では自動で再計算されない。
- [ ] 10 GB のファイルの SHA-256 計算中もスクロールや編集が固まらず (判定はテスト仕様書の方針 ([../test/00-test-strategy.md](../test/00-test-strategy.md)) の 7.3)、キャンセルできる。

### ANA-19 対応アルゴリズム

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-17 (表の「フェーズ」列が 1 のもの)、F2-14 (同 2 のもの) |
| 呼び出し | ハッシュパネル (ANA-18) のアルゴリズム一覧 |

**概要**: ハッシュパネルで選べるアルゴリズムの一覧と、それぞれの定義を定める。

**仕様**:

1. 加算チェックサム・XOR (フェーズ 1 は 8 / 16 / 32 bit の加算と 8 bit の XOR、それ以外はフェーズ 2):

   | 名前 | 定義 | パラメータ |
   | --- | --- | --- |
   | 加算 8 / 16 / 32 / 64 bit (バイト単位) | 各バイトを符号なしで足し、結果を 8 / 16 / 32 / 64 bit で切り捨てる | 結果の補数 |
   | 加算 16 / 32 / 64 bit (ワード単位) | 16 / 32 / 64 bit の要素として足す。要素のエンディアン (LE / BE) と符号 (符号あり / なし) を選ぶ。端数のバイトは 0 で埋める | エンディアン、符号、結果の補数 |
   | インターネットチェックサム | RFC 1071 (16 bit ワードの 1 の補数和の 1 の補数) | エンディアン (既定 BE) |
   | XOR 8 / 16 / 32 / 64 bit | 要素 (バイトまたはワード) の排他的論理和 | エンディアン (ワードの場合) |

   - 「結果の補数」: なし (既定) / 1 の補数 (全ビット反転) / 2 の補数 (符号反転。合計に足すと 0 になる値)。
   - 符号ありの場合、結果は符号付き 10 進でも表示する。

2. CRC (フェーズ 1 は CRC-16/ARC、CRC-16/CCITT-FALSE、CRC-32、CRC-32C、それ以外はフェーズ 2):
   - パラメータは CRC カタログ (Greg Cook の「Catalogue of parametrised CRC algorithms」) の名前と定義 (width, poly, init, refin, refout, xorout, check) に従う。
   - プリセット (別名はカッコ内):

   | 幅 | プリセット |
   | --- | --- |
   | 8 | CRC-8 (SMBUS)、CRC-8/AUTOSAR、CRC-8/BLUETOOTH、CRC-8/CDMA2000、CRC-8/DARC、CRC-8/DVB-S2、CRC-8/GSM-A、CRC-8/I-CODE、CRC-8/I-432-1 (ITU)、CRC-8/MAXIM-DOW (MAXIM、DOW-CRC)、CRC-8/NRSC-5、CRC-8/ROHC、CRC-8/SAE-J1850、CRC-8/WCDMA |
   | 16 | CRC-16/ARC (CRC-16、IBM)、CRC-16/IBM-3740 (CCITT-FALSE)、CRC-16/XMODEM (ACORN、LTE)、CRC-16/KERMIT (CCITT)、CRC-16/MODBUS、CRC-16/USB、CRC-16/IBM-SDLC (X-25)、CRC-16/DNP、CRC-16/MAXIM-DOW、CRC-16/GENIBUS、CRC-16/SPI-FUJITSU (AUG-CCITT)、CRC-16/UMTS (BUYPASS)、CRC-16/DECT-X、CRC-16/EN-13757、CRC-16/T10-DIF、CRC-16/TELEDISK、CRC-16/CDMA2000、CRC-16/MCRF4XX |
   | 24 | CRC-24/OPENPGP、CRC-24/BLE、CRC-24/FLEXRAY-A |
   | 32 | CRC-32 (ISO-HDLC)、CRC-32C (ISCSI、Castagnoli)、CRC-32/BZIP2、CRC-32/MPEG-2、CRC-32/CKSUM (POSIX)、CRC-32/JAMCRC、CRC-32/XFER、CRC-32/AUTOSAR、CRC-32/AIXM (CRC-32Q)、CRC-32/BASE91-D (CRC-32D) |
   | 64 | CRC-64/ECMA-182、CRC-64/XZ (GO-ECMA)、CRC-64/GO-ISO、CRC-64/WE、CRC-64/REDIS、CRC-64/NVME |

   - CRC-32/CKSUM は、POSIX の `cksum` と同じく末尾にデータ長を加える方式も「cksum (長さ付き)」として選べる。
   - 独自のパラメータは ANA-20 で定義する。

3. 非暗号学的ハッシュ (Adler-32 はフェーズ 1、それ以外はフェーズ 2):

   | 名前 | 出力 | パラメータ |
   | --- | --- | --- |
   | Adler-32 | 32 bit | — |
   | Fletcher-16 / 32 / 64 | 16 / 32 / 64 bit | ワードのエンディアン (32 / 64 の場合) |
   | FNV-1 / FNV-1a | 32 / 64 / 128 bit | — |
   | xxHash32 / xxHash64 | 32 / 64 bit | シード (既定 0。xxHash32 は 32 bit、xxHash64 は 64 bit) |
   | XXH3-64 / XXH3-128 | 64 / 128 bit | シード (既定 0。64 bit) |
   | MurmurHash3 x86_32 / x86_128 / x64_128 | 32 / 128 / 128 bit | シード (既定 0。32 bit) |
   | MurmurHash2 / MurmurHash64A | 32 / 64 bit | シード (既定 0。MurmurHash2 は 32 bit、MurmurHash64A は 64 bit) |
   | SipHash-2-4 / SipHash-1-3 | 64 bit (128 bit 版も選べる) | 鍵 128 bit (既定はすべて 0) |

   - シードの幅は参照実装の API に合わせる。シードが 32 bit のアルゴリズムに 0xFFFFFFFF を超える値を指定した場合は、黙って切り詰めず、ANA-18 の「パラメータが不正」として扱う。
   - 値のバイト列: 64 bit 以下の値は数値のビッグエンディアン (ANA-18 の仕様 6 でバイト順を選べる)。128 bit の値は参照実装の正規の出力に合わせる (FNV-128 は数値のビッグエンディアン、XXH3-128 は canonical 形式、MurmurHash3 の 128 bit 版と SipHash の 128 bit 版は参照実装が出力するバイト列)。128 bit の値は数値として扱わない (バイト順の選択と 10 進表示はしない)。

4. 暗号学的ハッシュ (MD5、SHA-1、SHA-256、SHA-384、SHA-512 はフェーズ 1、それ以外はフェーズ 2):

   | 名前 | 出力 | パラメータ・注記 |
   | --- | --- | --- |
   | MD2 / MD4 / MD5 | 128 bit | 安全でないことを行の注記に表示 |
   | SHA-1 | 160 bit | 安全でないことを行の注記に表示 |
   | SHA-224 / SHA-256 / SHA-384 / SHA-512 | 224〜512 bit | — |
   | SHA-512/224 / SHA-512/256 | 224 / 256 bit | — |
   | SHA3-224 / SHA3-256 / SHA3-384 / SHA3-512 | 224〜512 bit | — |
   | SHAKE128 / SHAKE256 | 可変 (既定 256 / 512 bit) | 出力長 (8〜8,192 bit、8 の倍数) |
   | Keccak-256 | 256 bit | パディングが SHA3 と異なる版 (Ethereum などで使う) |
   | RIPEMD-128 / 160 / 256 / 320 | 128〜320 bit | — |
   | Tiger / Tiger2 | 192 bit | 128 / 160 bit に切り詰めた表示も選べる |
   | Whirlpool | 512 bit | — |
   | BLAKE2s | 8〜256 bit (既定 256) | 出力長、鍵 (0〜32 バイト) |
   | BLAKE2b | 8〜512 bit (既定 512) | 出力長、鍵 (0〜64 バイト) |
   | BLAKE3 | 可変 (既定 256 bit) | 出力長、鍵付きモード (32 バイトの鍵) |
   | TTH (Tiger Tree Hash) | 192 bit | 1,024 バイトの葉。Base32 表示を既定にする |
   | ed2k | 128 bit | 9,728,000 バイトごとの MD4。データ長がちょうどこの倍数のときの扱いを「旧方式 (red) / 新方式 (blue)」から選ぶ (既定は新方式) |

5. 実装の方針: .NET 標準 (`System.Security.Cryptography`) にあるものはそれを使う。CRC・チェックサム・xxHash など標準にないものは、パッケージを増やさず Core に実装する (`System.IO.Hashing` は .NET の標準ライブラリではなく別のパッケージのため使わない)。SHA-3 は OS が対応していない環境 (Windows 10 など) があるため、標準の実装が使えない場合は同じ結果を出す別の実装に切り替える。標準にないアルゴリズムのライブラリ (BouncyCastle などの候補) は未決定。
6. プラグイン (08、F3-07) でアルゴリズムを追加できる。追加したアルゴリズムは一覧の「プラグイン」グループに出る。
7. すべてのアルゴリズムについて、テストベクタ (公式の値、CRC はカタログの check 値) を単体テストで確認する。

**画面**: ハッシュパネルのアルゴリズム一覧。グループ (チェックサム、CRC、非暗号学的ハッシュ、暗号学的ハッシュ、プラグイン) ごとに折りたためる。名前・別名で絞り込める (大文字・小文字を区別しない序数比較)。

**巨大ファイル・長時間処理**: ANA-18 に従う。

**エラー**: OS やライブラリでアルゴリズムが使えない: 一覧で無効にし、ツールチップに理由を出す (例: 「この環境では利用できません」)。

**受け入れ基準**:

- [ ] すべての CRC プリセットで、`123456789` の値がカタログの check 値と一致する。
- [ ] 空のデータと `abc` について、MD5、SHA 系、SHA-3、RIPEMD、Whirlpool、Tiger、BLAKE2、BLAKE3 の値が公式のテストベクタと一致する。
- [ ] 加算 8 bit の「2 の補数」を有効にすると、データの全バイトとその値を足した合計が 0 (mod 256) になる。
- [ ] xxHash64 のシードを変えると値が変わり、行にシードが表示される。
- [ ] Windows 10 でも SHA3-256 が計算できる。

### ANA-20 カスタム CRC

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F2-14 |
| 呼び出し | ハッシュパネルのアルゴリズム一覧「カスタム CRC を追加...」、コマンドパレット「解析: カスタム CRC を定義」 |

**概要**: CRC のパラメータを利用者が指定して、独自の CRC を定義する。

**仕様**:

1. 入力するパラメータ:

   | パラメータ | 内容 | 範囲・既定値 |
   | --- | --- | --- |
   | 名前 | 一覧に表示する名前 | 必須。既存の名前と重複不可 |
   | 幅 (width) | ビット数 | 1〜64 |
   | 多項式 (poly) | 最上位ビットを省いた通常表記 | 幅に収まる値 |
   | 初期値 (init) | | 既定 0 |
   | 入力の反転 (refin) | 各バイトのビット順を反転するか | 既定 しない |
   | 出力の反転 (refout) | 結果のビット順を反転するか | 既定 しない |
   | 最終 XOR (xorout) | | 既定 0 |

2. 数値は 00 の 6 章の入力式で入力する。
3. 入力中に、`123456789` に対する値 (check) と剰余 (residue) をその場で表示する。
4. 既存のプリセットを選んで「複製して編集」できる。
5. 定義したカスタム CRC は設定に保存し、全ドキュメントで使える。JSON ファイルにエクスポート・インポートできる。JSON の形式は CRC カタログの項目名 (`width`、`poly`、`init`、`refin`、`refout`、`xorout`、`check`、`name`) を使う。
6. 内部実装は、幅 8 以上ではテーブル方式 (スライス 8)、幅 8 未満ではビット単位の計算とする。

**画面**: 「カスタム CRC」ダイアログ。パラメータの入力欄、check と residue の表示、「保存」「キャンセル」。

**巨大ファイル・長時間処理**: 計算は ANA-18 に従う。テーブル方式の CRC-32 相当で 1 GB/s 以上。

**エラー**:

- 多項式が幅に収まらない: 入力欄を赤枠にし、「多項式は 16 bit 以内で指定してください」のように表示する。
- インポートする JSON の形式が不正: 「n 件目の項目を読み込めません: 理由」と表示し、正しい項目だけ取り込む。

**受け入れ基準**:

- [ ] width=16、poly=0x8005、init=0、refin/refout=true、xorout=0 を入力すると、check が `BB3D` (CRC-16/ARC と同じ) と表示される。
- [ ] 定義したカスタム CRC が再起動後も一覧にある。
- [ ] エクスポートした JSON を別の環境でインポートすると同じ値が計算される。
- [ ] 幅 5 の CRC (CRC-5/USB 相当) が計算でき、check が `19` になる。

### ANA-21 期待値との照合

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-17 (「一致するアルゴリズムを探す」は F2-14) |
| 呼び出し | ハッシュパネルの「照合」欄、コマンドパレット「解析: ハッシュ値を照合」「解析: 一致するアルゴリズムを探す」「解析: チェックサムファイルで検証」 |

**概要**: 計算したハッシュ値を、利用者が入力した期待値やチェックサムファイルの値と照合する。値だけ分かっていてアルゴリズムが分からない場合に、一致するアルゴリズムを探す。

**仕様**:

1. 期待値の入力欄に値を貼り付けると、計算済みの全結果と比べ、一致した行に「一致」のアイコンと文字を付ける。
2. 期待値の書式は次を受け付ける。
   - Hex (大文字・小文字、空白・`:`・`-` 区切り、`0x` 接頭辞)
   - Base64
   - チェックサムファイルの 1 行 (`<値> *<ファイル名>`、`<値>  <ファイル名>`、`SHA256 (<ファイル名>) = <値>`)
3. 比較は、値のバイト列として行う (表記の大文字・小文字や区切りを無視)。64 bit 以下の値は、バイト順を逆にした値とも比べ、逆順で一致した場合は「一致 (バイト順が逆)」と表示する。
4. 「チェックサムファイルで検証」: `.md5`、`.sha1`、`.sha256`、`.sha512`、`.sfv` (CRC-32) のファイルを選ぶと、ドキュメントのファイル名に対応する行を探して照合する。アルゴリズムはファイルの拡張子と値の長さから決める。
5. 「一致するアルゴリズムを探す」: 期待値の長さ (ビット数) に合うすべてのアルゴリズム (全 CRC プリセット、利用者のカスタム CRC、全チェックサムの全オプションの組み合わせを含む) で計算し、一致したものを一覧に出す。幅が 8 の倍数でない CRC (CRC-5 など) は、値のバイト数 (幅を 8 の倍数に切り上げた長さ) で長さを比べる。「符号あり」は表示だけが変わり値のビット列は同じなので、組み合わせに含めない。対象範囲が 1 MiB を超える場合は確認ダイアログで所要時間の目安を示す。
6. 結果は「一致」「不一致」をアイコンと文字の両方で示す。スクリーンリーダーには「SHA-256、一致」と読み上げさせる。

**フェーズの区分**: ロードマップの行のとおり、5 の「一致するアルゴリズムを探す」(ボタンとコマンドパレットの項目を含む) は F2-14 (フェーズ 2)。

**画面**: ハッシュパネル下部の「照合」欄 (期待値の入力欄、「チェックサムファイルで検証...」「一致するアルゴリズムを探す」ボタン、結果の表示)。

**巨大ファイル・長時間処理**: 1 は計算済みの結果との比較なのですぐ終わる。5 は対象を 1 回読み込み、全アルゴリズムを同時に計算する (ANA-18 と同じ方式)。長時間処理として扱う。

**エラー**:

- 期待値として解釈できない: 入力欄を赤枠にし、「16 進または Base64 の値を入力してください」と表示する。
- チェックサムファイルにドキュメントのファイル名がない: 「このファイルの行が見つかりません」と表示し、ファイル内の行を選べる一覧を出す。
- 一致するアルゴリズムがない: 「一致するアルゴリズムはありません (n 種類を試しました)」と表示する。

**受け入れ基準**:

- [ ] SHA-256 の期待値を小文字で貼り付けても「一致」になる。
- [ ] CRC-32 の値をバイト順を逆にして貼り付けると「一致 (バイト順が逆)」になる。
- [ ] `sha256sum` で作った `.sha256` ファイルで検証できる。
- [ ] `123456789` と `0x29B1` で「一致するアルゴリズムを探す」を実行すると、CRC-16/IBM-3740 (CCITT-FALSE) が見つかる。
- [ ] 一致・不一致が色以外 (アイコンと文字) でも区別できる。

### ANA-22 結果のコピーと書き込み

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F1-17 (ドキュメントへの書き込みは F2-14) |
| 呼び出し | ハッシュパネルの結果の行の「コピー」ボタンと右クリックメニュー、コマンドパレット「解析: ハッシュ値をコピー」「解析: ハッシュ値をカーソル位置に書き込む」 |

**概要**: 計算結果をクリップボードやファイルに出力する。チェックサムをドキュメントの指定位置に書き込む。

**仕様**:

1. コピーの形式:
   - 値のみ (行の表示形式のまま)
   - `アルゴリズム名: 値` (選んだ行、またはすべての行)
   - チェックサムファイル形式 (`<値> *<ファイル名>`)
   - JSON (`[{"algorithm": "SHA-256", "value": "…", "parameters": {…}, "range": {"start": 0, "length": 1024}}]`)
   - CSV (アルゴリズム, 値, 開始, 長さ)
2. 「チェックサムファイルとして保存...」で、選んだアルゴリズムのチェックサムファイル (`.sha256` など、UTF-8、改行は LF) を保存する。
3. 「カーソル位置に書き込む」: 値のバイト列をカーソル位置 (または選択範囲の先頭) に上書きで書き込む。バイト順 (BE / LE) を選ぶ確認欄を出す (64 bit 以下の値の場合)。書き込みは Undo 1 回分として記録する。上書きモード・挿入モードに関係なく上書きする。
4. 「カーソル位置に書き込む」で、書き込み先が計算の対象範囲に含まれる場合は警告を出す (書き込むと値が変わるため)。除外範囲 (ANA-18 の 2) に書き込み先が含まれていれば警告しない。

**フェーズの区分**: ロードマップの行のとおり、3・4 の「カーソル位置に書き込む」(右クリックメニューとコマンドパレットの項目を含む) は F2-14 (フェーズ 2)。コマンドパレットの「解析: ハッシュ値をコピー」は、結果が 1 行なら値のみ、複数行なら `アルゴリズム名: 値` をすべての行についてコピーする。

**画面**: 結果の表の各行のボタン (コピー) と右クリックメニュー (各形式でコピー、カーソル位置に書き込む)。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**:

- 読み取り専用のドキュメントに書き込もうとした: メニュー項目を無効にする。
- 書き込みがドキュメントの末尾を超える: 「末尾を超えるため書き込めません (残り 2 バイト、必要 4 バイト)」と表示する。

**受け入れ基準**:

- [ ] すべての行を JSON でコピーすると、範囲とパラメータを含む JSON が得られる。
- [ ] 保存したチェックサムファイルを `sha256sum -c` で検証できる。
- [ ] CRC-32 を LE でカーソル位置に書き込むと、値の下位バイトから書き込まれ、Ctrl+Z で元に戻る。
- [ ] 書き込み先が対象範囲に含まれるときだけ警告が出る。

## 5. 逆アセンブル

### ANA-23 逆アセンブルビュー

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-01 |
| 呼び出し | 解析 > 逆アセンブル、表示 > パネルの表示切り替え > 逆アセンブル、コマンドパレット「解析: 逆アセンブル」「解析: カーソル位置から逆アセンブル」、選択範囲の右クリックメニュー「逆アセンブル」、ショートカットは既定なし |

**概要**: ドキュメントのバイト列を機械語として解釈し、命令の一覧 (リスティング) として表示する。Capstone などの逆アセンブラを使い、多くのアーキテクチャに対応する (使い分けは仕様 1 の「エンジン」)。逆アセンブラ (対応アーキテクチャ・構文・表示設定) はこの項目と ANA-24〜26 が主担当で、データインスペクタの 1 命令の表示 (INSP-16) は同じ逆アセンブラと設定を使う (00-overview.md 1.1)。

**仕様**:

1. 対応するアーキテクチャとモード:

   | アーキテクチャ | モード | エンジン |
   | --- | --- | --- |
   | x86 | 16 bit、32 bit、64 bit | Iced |
   | ARM | ARM、Thumb (Thumb-2 を含む)、ARMv8 (AArch32)、Cortex-M | Capstone |
   | ARM64 (AArch64) | — | Capstone |
   | MIPS | MIPS32、MIPS64、microMIPS、MIPS32R6 | Capstone |
   | PowerPC | 32 bit、64 bit、QPX | Capstone |
   | SPARC | SPARC、SPARC V9 | Capstone |
   | SystemZ | — | Capstone |
   | XCore | — | Capstone |
   | 68K | 68000〜68060 | Capstone |
   | RISC-V | RV32、RV64、圧縮命令 (C 拡張。モード RV32C / RV64C) | 本体 |
   | 6502 (MOS65XX) | 6502、65C02、W65C02、65816 | 本体 |
   | TMS320C64x | — | Capstone |
   | BPF | 従来の BPF、eBPF | 本体 |
   | WebAssembly | — | 本体 |

   - エンジン: x86 は Iced (.NET のライブラリ、MIT ライセンス。ANA-29 のアセンブラと同じ)。Capstone は NuGet で x64 と ARM64 の Windows 向けのネイティブライブラリを入手できる版 (4.0) を使う。Capstone 4 にない RISC-V・6502 系・BPF・WebAssembly は本体の自前の逆アセンブラで解釈する (表記は Capstone 5 に合わせる)。
   - ほかに Capstone 4 が対応するもの (M680X、EVM) と、プラグインの逆アセンブラ (08 の AUTO-31 の `IDisassembler`) を、一覧の「その他」に出す。Capstone 4 にない SH、TriCore は対象外 (未決定: Capstone 5 のネイティブライブラリを NuGet で入手できるようになったら加える)。
   - エンディアンを持つアーキテクチャ (ARM、MIPS、PowerPC など) では、リトル / ビッグを選ぶ。
   - 65816 の即値の長さは 8 bit (フラグ M = 1、X = 1) とみなす。
2. 開始位置: カーソル位置 (既定)、選択範囲の先頭、指定したオフセット、仮想アドレス (ANA-24)。
3. ベースアドレス: 表示上のアドレス = オフセット − 開始セクションのファイル位置 + ベースアドレス。既定は、実行形式の場合 ANA-24 で決まる値、それ以外は 0。手入力できる。
4. リスティングの列: アドレス、バイト列 (既定 8 バイトまで、超える分は `…`)、ニーモニック、オペランド、コメント (シンボル名、分岐先の名前、文字列の参照)。
5. 線形スイープ (先頭から順に解釈) で表示する。解釈できないバイトは `db 0xNN` (1 バイト) として表示し、次のバイトから解釈を続ける。
6. Hex ビューとの連動:
   - リスティングで行を選ぶと、その命令のバイト列を Hex ビューで選択する。
   - Hex ビューでカーソルを動かすと、そのバイトを含む命令の行をリスティングで選ぶ (「カーソルに追従」トグル、既定でオン)。
   - 現在の命令の範囲は Hex ビューで枠線 (色以外の印) で示す。色の重ね順 (VIEW-17) では、インスペクタの対象の強調 (層 3) と同じ層として描く。
7. 命令の上にマウスを置くと、詳細 (命令の長さ、オペランドの種類と読み書き、使うレジスタ、命令グループ) をツールチップで表示する。
8. 選んだ行をコピーできる (テキストとして、列をタブ区切りで)。範囲を「アセンブリとしてエクスポート...」でテキストファイルに保存できる。
9. ドキュメントを編集すると、編集された範囲以降の表示を作り直す。
10. 逆アセンブルエンジンはデータインスペクタ (05) の「1 命令ぶんの逆アセンブル」とスクリプト API (08) でも使う。

**画面**: 逆アセンブルパネル (既定は右。幅を広げるときは下部に移せる)。「逆アセンブル」表示モード (Hex ビューの右に並べて表示) は、パネルを右に置いた状態と同じなので別に設けない。上部のツールバーに、アーキテクチャ、モード、エンディアン、開始位置、ベースアドレス、構文 (ANA-26)、「カーソルに追従」。リスティングは仮想化した一覧で、等幅フォント、左から右固定 (右から左の言語でも反転しない)。

**巨大ファイル・長時間処理**:

- 表示に必要な範囲だけを解釈する。下方向のスクロールは表示範囲の直後から解釈する。
- 上方向のスクロールや任意位置へのジャンプでは、可変長命令のアーキテクチャ (x86、68K など) で命令境界が分からないため、4 KB ごとに解釈を始める「チェックポイント」を置く。セクションの先頭 (ANA-24) かチェックポイントから解釈して表示位置に合わせる。チェックポイントの命令境界は、解釈した結果を記憶して再利用する。
- スクロールバーはバイトのオフセットに比例させる (命令数は数えない)。
- どの位置へのジャンプも 100 ms 以内に表示する。

**エラー**:

- Capstone のネイティブライブラリを読み込めない: パネルに「逆アセンブルエンジンを読み込めません」と理由を表示する。

**実装の注記 (ANA-23)**: 仕様 10 のスクリプト API は、08 に逆アセンブルの API が定められていない。ロードマップの最後のフェーズ (フェーズ 5) までに含めていないため、未決定とする (08 と合わせて定める) (本体の逆アセンブラは Core の `Disassembler` として、インスペクタ (INSP-16) とテンプレートのビジュアライザ (07 の TPL-16) から使える)。固定長の命令のアーキテクチャで解釈できない語は、語の各バイトを `db` にし (1 バイトずつ)、次の命令は語の境界から解釈する。ラベルの自動生成 (ANA-25 の仕様 6) のため、実行可能なセクション (合計 64 MB まで) をバックグラウンドで先に解釈して分岐先を集める。

- 選んだアーキテクチャでほとんど解釈できない (表示範囲の 50% 以上が `db`): パネル上部に「このアーキテクチャのコードではない可能性があります」と表示する。

**受け入れ基準**:

- [ ] x64 の PE ファイルのエントリポイントで、`dumpbin /disasm` と同じ命令列が表示される (構文の差を除く)。
- [ ] 1 の表のすべてのアーキテクチャで、テスト用のバイト列が期待どおりに解釈される。
- [ ] リスティングの行を選ぶと、Hex ビューでその命令のバイトが選択される。逆も同じ。
- [ ] 100 GB のファイルの末尾付近へジャンプしても、100 ms 以内にリスティングが表示される。
- [ ] 解釈できないバイトが `db` として表示され、次のバイトから解釈が続く。
- [ ] 右から左の言語の UI でもリスティングは左から右で表示される。

### ANA-24 実行形式のセクションとシンボルの解釈

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-01 |
| 呼び出し | 逆アセンブルパネルの「セクション」「シンボル」一覧、コマンドパレット「解析: 仮想アドレスへ移動」「解析: エントリポイントへ移動」、ショートカットは既定なし |

**概要**: PE、ELF、Mach-O の形式を解釈し、セクション、仮想アドレス、エントリポイント、シンボル (エクスポート・インポート・シンボル表) を逆アセンブルに使う。

**仕様**:

1. 対応形式:
   - PE: PE32、PE32+ (x86、x64、ARM、ARM64、ARM64EC / ARM64X)。
   - ELF: 32 / 64 bit、リトル / ビッグエンディアン。
   - Mach-O: 32 / 64 bit。ユニバーサル (fat) バイナリは、含まれるアーキテクチャの一覧から選ぶ。
2. ドキュメントを逆アセンブルするとき、先頭が対応形式であれば、ヘッダからアーキテクチャ・モード・エンディアン・イメージベースを自動で設定する。自動設定は利用者が上書きできる。
3. セクションの一覧: 名前、仮想アドレス、仮想サイズ、ファイル位置、ファイル上のサイズ、属性 (実行 / 読み / 書き)。行を選ぶとそのセクションの先頭を逆アセンブルする。
4. オフセットと仮想アドレスの変換: リスティングのアドレス列は仮想アドレスで表示する。ファイル上に対応するバイトがない範囲 (`.bss` など仮想サイズ > ファイル上のサイズの部分) は表示しない。
5. 「仮想アドレスへ移動」: 入力式 (00 の 6 章) で仮想アドレスを入力し、対応するオフセットへ移動する。入力欄の横に、対応するオフセットとセクション名を表示する。
6. シンボルの取得元:
   - PE: エクスポート表、インポート表 (IAT の各項目に `DLL名!関数名`)、遅延読み込みインポート、例外表 (関数の範囲)。PDB は読み込まない (未決定: 将来の拡張として検討)。
   - ELF: `.symtab`、`.dynsym`、PLT の項目 (`関数名@plt`)。
   - Mach-O: シンボル表 (`LC_SYMTAB`)、遅延バインドのスタブ (`__stubs` と間接シンボル表)。エントリポイントは `LC_MAIN` から求める (`LC_UNIXTHREAD` だけの古い形式ではエントリポイントを求めない)。
7. シンボルの一覧: 名前 (デマングル済み、ANA-30)、仮想アドレス、種類 (関数 / データ / インポート / エクスポート)。名前で絞り込める。行を選ぶとその位置を逆アセンブルする。
8. リスティングのコメント列に、命令が参照するアドレスのシンボル名 (`call qword ptr [rip+0x1234]` → `; KERNEL32!CreateFileW`) と、参照先が文字列 (ASCII / UTF-16 で 4 文字以上) の場合はその文字列を表示する。
9. エントリポイントと、シンボルの開始位置には、リスティングに見出し行 (例: `main:`) を入れる。
10. .NET の PE (CLI ヘッダを持つ) の場合は、MSIL の逆アセンブル (ANA-27) を案内する InfoBar を出す。

**画面**: 逆アセンブルパネルの左側に「セクション」「シンボル」のタブ付き一覧 (パネルの幅が 600 px 未満では上下に並べる)。

**巨大ファイル・長時間処理**: ヘッダとシンボル表の解析はバックグラウンドで行う。シンボルが 100 万個を超える場合は、一覧を仮想化し、名前の索引作りを長時間処理として扱う。解析が終わるまで、リスティングはシンボルなしで表示する。

**エラー**:

- ヘッダが壊れている (セクション表がファイルの範囲外など): 解釈できた部分だけを使い、パネル上部に「ヘッダの一部を解釈できません: 理由」と表示する。
- 仮想アドレスがどのセクションにも含まれない: 入力欄に「どのセクションにも含まれないアドレスです」と表示する。

**受け入れ基準**:

- [ ] Windows の `notepad.exe` (x64 と ARM64) で、アーキテクチャが自動で設定され、エントリポイントが表示される。
- [ ] Linux の ELF 実行ファイルで、`main` などのシンボルが一覧に出る。
- [ ] Mach-O のユニバーサルバイナリで、アーキテクチャを選んで逆アセンブルできる。
- [ ] 仮想アドレスを入力すると、対応するオフセットへ移動する。
- [ ] インポート関数の呼び出しの行に `DLL名!関数名` のコメントが付く。

### ANA-25 分岐先への移動と相互参照

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-01 |
| 呼び出し | F12 (分岐先へ移動。00-overview.md 8.2)、リスティングの行で Enter (パネルの有効範囲。00-overview.md 8.6) またはダブルクリック、右クリックメニュー「分岐先へ移動」「このアドレスへの参照を探す」、コマンドパレット「逆アセンブル: 分岐先へ移動」「逆アセンブル: 参照を探す」。「参照を探す」のショートカットは既定なし |

**概要**: call / jmp / 条件分岐などの分岐先をたどる。あるアドレスを参照している命令を探す (相互参照)。

**仕様**:

1. 分岐先へ移動: 選んだ命令が、即値の分岐先を持つ分岐命令 (call、jmp、jcc、b、bl、beq など)、または RIP 相対 / PC 相対のメモリ参照を持つ命令の場合、その先の仮想アドレスへ移動する (リスティングと Hex ビューの両方)。
2. 分岐先がインポートの項目 (IAT、PLT) の場合は、移動せずにステータスバーに「外部関数: KERNEL32!CreateFileW」と表示する。
3. 移動はジャンプ履歴 (VIEW-31) に記録し、Alt+← で戻れる。
4. F12 は、逆アセンブルパネルにフォーカスがあるときは選んだ行の命令の分岐先へ移動する。Hex ビューにフォーカスがあるときは、テンプレートの適用があれば定義へ移動 (TPL-24 の 3) を優先し、適用がなく逆アセンブルパネルが開いていればカーソル位置を含む命令 (ANA-23 の 6) の分岐先へ移動する。テンプレートの結果ツリーにフォーカスがあるときの F12 は定義へ移動 (TPL-24) になる。
5. 分岐命令の行には、分岐の方向 (前方 / 後方) を示す矢印をアドレス列の左に描く。表示範囲内に分岐先がある場合は、分岐元と分岐先を結ぶ線を描く (既定でオン、設定でオフにできる)。
6. ラベルの自動生成: シンボルのない分岐先には、`sub_<アドレス>` (call の先)、`loc_<アドレス>` (jmp・条件分岐の先) の名前を付けて見出し行を入れる。
7. 相互参照: 「このアドレスへの参照を探す」で、実行可能なセクション全体を線形スイープで解釈し、選んだアドレス (またはシンボル) を分岐先・参照先に持つ命令を共通の結果一覧に出す。列: 参照元のアドレス、命令、種類 (call / jmp / データ参照)。
8. 相互参照の結果は、同じドキュメントを編集するまで記憶する。

**画面**: リスティング (ANA-23)。相互参照の結果は下部の結果一覧パネル。

**巨大ファイル・長時間処理**: 相互参照の探索は長時間処理として扱う。対象は実行可能なセクションだけ (実行形式でない場合は対象範囲 0.1 を指定させる)。キャンセルした場合は、見つかった分だけ残す。

**エラー**:

- 分岐先がファイルの範囲外 (セクションに含まれない): ステータスバーに「分岐先 0x... はファイルに含まれていません」と表示し、移動しない。
- 間接分岐 (`jmp rax` など) で分岐先が決まらない: メニュー項目を無効にする。

**受け入れ基準**:

- [ ] `call` の行で Enter または F12 を押すと分岐先へ移動し、Alt+← で戻れる。
- [ ] インポート関数の呼び出しで Enter を押すと、関数名がステータスバーに表示される。
- [ ] シンボルのない関数の先頭に `sub_` で始まる見出しが付く。
- [ ] 関数の先頭アドレスへの参照を探すと、その関数を呼んでいる `call` の行が一覧に出る。

### ANA-26 逆アセンブルの表示設定

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F4-01 |
| 呼び出し | 逆アセンブルパネルのツールバー「構文」と「表示オプション」、設定 > 逆アセンブル |

**概要**: 命令の構文や数値の書式など、リスティングの表示を変える。

**仕様**:

1. 構文 (x86): Intel (既定)、AT&T、MASM。x86 の逆アセンブラ (Iced) の書式に対応させる (Intel はメモリのオペランドにサイズを付け、`+` の前後に空白を入れる Capstone と同じ形)。
2. 数値の書式: `0x` 接頭辞 (既定) または `h` 接尾辞、16 進の大文字・小文字 (既定は小文字)、負の即値を符号付きで表示するか (既定は符号なし。x86 だけ。ほかのアーキテクチャはエンジンの表記のまま)。
3. ニーモニックとレジスタ名の大文字・小文字 (既定は小文字)。
4. ARM のレジスタ名: 番号 (`r13`) または別名 (`sp`、既定)。
5. バイト列の列: 表示するかどうか (既定で表示)、最大バイト数 (4〜16、既定 8)。
6. アドレス列: 仮想アドレス (既定、実行形式の場合) / オフセット / 両方。
7. 分岐の線 (ANA-25 の 4) とコメント列の表示の有無。
8. 設定はアーキテクチャごとではなく全体で共有する。ただし構文は x86 にだけ適用する。
9. 設定の変更はその場でリスティングに反映する。

**画面**: ツールバーの「構文」コンボボックスと、「表示オプション」のフライアウト (チェックボックスとコンボボックス)。設定画面 (09) の「逆アセンブル」の項目にも同じものを置く。

**巨大ファイル・長時間処理**: 該当なし (表示範囲だけを作り直す)。

**エラー**: 該当なし。

**受け入れ基準**:

- [ ] AT&T に切り替えると、x64 の `48 89 E5` (Intel 構文の `mov rbp, rsp`) が、オペランドのサイズの接尾辞を付けた `movq %rsp, %rbp` の形で表示される。
- [ ] `h` 接尾辞を選ぶと即値が `10h` の形で表示される。
- [ ] 設定の変更が再起動後も保たれる。

### ANA-27 MSIL の逆アセンブル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | 逆アセンブルパネルのアーキテクチャ「MSIL (.NET)」、コマンドパレット「解析: .NET のメソッドを逆アセンブル」 |

**概要**: .NET アセンブリ (CLI ヘッダを持つ PE) のメソッドの IL コードを逆アセンブルする。

**仕様**:

1. メタデータを `System.Reflection.Metadata` で読み、名前空間 → 型 → メソッドの木を表示する。
2. メソッドを選ぶと、メソッド本体 (ヘッダ、ローカル変数のシグネチャ、IL、例外処理の節) を逆アセンブルして表示する。
3. オペランドのトークンは名前に解決して表示する (例: `call void [System.Console]System.Console::WriteLine(string)`、`ldstr "Hello"`)。
4. リスティングの各行はファイル上のオフセットに対応させ、ANA-23 の 6 と同じく Hex ビューと連動させる。
5. 分岐命令 (`br`、`brtrue` など) は ANA-25 と同じく分岐先へ移動できる。`call` で同じアセンブリ内のメソッドを呼ぶ場合は、そのメソッドへ移動できる。
6. ReadyToRun のネイティブコードがある場合は、そのメソッドの x64 / ARM64 のコードを ANA-23 で表示する切り替えを出す。
7. 難読化などでメタデータを読めない場合は、IL を読める範囲で表示し、トークンは `token 0x06000001` のまま表示する。

**画面**: 逆アセンブルパネルの左側の一覧が、MSIL のときは「型とメソッド」の木になる。

**巨大ファイル・長時間処理**: メタデータの読み込みはバックグラウンドで行う。型・メソッドの木は仮想化し、10 万メソッドでも表示できる。

**エラー**: メタデータが壊れている: 読めた範囲の木を表示し、「メタデータの一部を読めません」と表示する。

**受け入れ基準**:

- [ ] .NET の Hello World の `Main` メソッドで、`ldstr` と `call` がトークンを名前に解決して表示される。
- [ ] IL の行を選ぶと、Hex ビューで対応するバイトが選択される。
- [ ] 分岐命令から分岐先へ移動できる。

実装の注記 (ANA-27): フェーズ 4 の監査: メタデータは信頼できない入力として扱う: 入れ子の型・型の参照の解決範囲・TypeSpec の入れ子は 64 段で打ち切る (輪になっていても止まる)。1 KB を超えるシグネチャは解釈せず `token 0x…` で示す (System.Reflection.Metadata のシグネチャの解釈は入れ子ごとに再帰し、深さの上限を持たないため)。1 つのメソッドで逆アセンブルする IL は 1 MiB まで (超える分は行を作らず、その旨の行を出す)。

### ANA-28 命令パターン検索

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | 逆アセンブルパネルの「命令を検索」、コマンドパレット「逆アセンブル: 命令パターンを検索」 |

**概要**: アセンブリの表記 (ワイルドカード付き) で命令の並びを検索する。命令パターン検索はこの項目が主担当で、04 (検索) は参照するだけである (00-overview.md 1.1)。バイト列の検索・すべて検索 (04) とは別の機能で、結果は共通の結果一覧に出す。

**仕様**:

1. パターンは 1 行に 1 命令、または `;` 区切りで複数の連続する命令を書く。例: `push rbp; mov rbp, rsp`、`call *`、`mov e?x, [rip+*]`。
2. ワイルドカード: `*` は任意の文字列 (オペランドの一部または全体)、`?` は任意の 1 文字。`{n}` を命令の位置に書くと、任意の命令 n 個を表す (例: `cmp *; {0-3}; jz *`)。
3. 比較は、ANA-26 の現在の構文で表示した文字列に対して、大文字・小文字を区別せずに行う (序数比較)。空白の数の違いは無視する。
4. オプション「正規表現」を選ぶと、1 命令ごとの文字列に対する .NET の正規表現として解釈する。
5. 対象: 実行可能なセクション全体 (実行形式の場合の既定) または対象範囲 (0.1)。線形スイープで解釈した命令列を探す。
6. 結果の列: アドレス、オフセット、一致した命令列。行を選ぶとリスティングと Hex ビューがその位置へ移動する。マルチ選択・ブックマークへの変換は共通の結果一覧の機能を使う。

**画面**: 逆アセンブルパネル上部の検索欄 (検索バーと同じ見た目で、パネル内に表示)。検索欄でのキー (Enter / Shift+Enter、Alt+Enter、↑ / ↓、Esc) は検索バーの有効範囲 (00-overview.md 8.4) と同じに扱う。結果は下部の結果一覧パネル。

**巨大ファイル・長時間処理**: 長時間処理として扱う。逆アセンブルの速度 (x64 で 50 MB/s 程度) で決まるため、対象が 100 MB を超える場合は実行前に所要時間の目安を表示する。キャンセルした場合は、見つかった分を残す。

**エラー**: パターンの構文エラー (括弧の対応、`{n}` の範囲が不正): 検索欄を赤枠にし、位置と理由を表示する。

**受け入れ基準**:

- [ ] x64 の実行ファイルで `push rbp; mov rbp, rsp` を検索すると、関数の先頭が一覧に出る。
- [ ] `call *` ですべての `call` 命令が見つかる。
- [ ] 大文字で入力しても一致する。

### ANA-29 インプレースアセンブル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | リスティングの行の右クリックメニュー「アセンブル...」、コマンドパレット「逆アセンブル: 命令を書き換える」 |

**概要**: リスティング上で命令をアセンブリの表記で入力し、その機械語でドキュメントを書き換える。

**仕様**:

1. 選んだ行の命令を編集欄に表示し、利用者が新しい命令 (`;` 区切りで複数可) を入力する。
2. 入力に合わせて、生成される機械語のバイト列と長さをその場で表示する。アドレスはその行の仮想アドレスを使う (相対分岐の計算のため)。
3. 新しい命令が元の命令より短い場合、残りを埋める方法を選ぶ: NOP (`0x90`) で埋める (既定) / そのまま残す。
4. 長い場合は、後ろの命令を上書きすることを、上書きされる命令の一覧とともに警告する。挿入モードでも上書きで書き込む (命令の位置をずらさない)。
5. 書き込みは Undo 1 回分として記録する。
6. アセンブラは Iced (.NET のライブラリ、MIT ライセンス) を使い、対応するアーキテクチャは x86 (16 / 32 bit) と x64 とする。それ以外のアーキテクチャ (ARM、ARM64、MIPS など) ではインプレースアセンブルを提供せず、リスティングの右クリックメニューにこの機能を表示しない。コマンドパレットはすべてのコマンドを並べる決まり (09 の UI-17) なので、使えない理由 (「x86 と x64 だけで使えます」) とともに無効にする。
7. 生成する機械語は Iced のエンコーダの出力とする。同じ命令に正しい符号化が複数ある場合 (例: `xor eax, eax` の `31 C0` と `33 C0`、相対分岐の短い形 `EB rel8` と長い形 `E9 rel32`) にどれを選ぶかは Iced に従い、最短の符号化であることは保証しない。受け入れ基準では、同じ命令として逆アセンブルし直せて、相対分岐では分岐先が一致する符号化であれば、どれでも合格とする。

**画面**: 行の位置に開く小さな編集欄 (フライアウト)。入力欄、生成されるバイト列、警告、「書き込む」「キャンセル」。

**巨大ファイル・長時間処理**: 該当なし。

**エラー**:

- アセンブルできない (構文エラー、そのアーキテクチャにない命令): 入力欄の下に理由を表示し、「書き込む」を無効にする。
- 読み取り専用のドキュメント: メニュー項目を無効にする。

**受け入れ基準**:

- [ ] x64 で `mov eax, 1` を `xor eax, eax` に書き換えると、2 バイトの機械語 (`31 C0` または `33 C0`) が書き込まれ、余った 3 バイトが NOP で埋められる。
- [ ] 相対分岐 `jmp 0x401000` を入力すると、行のアドレスから正しいオフセットが計算される (短い形・長い形のどちらで符号化してもよく、逆アセンブルし直した分岐先が 0x401000 になる)。
- [ ] 書き換えを Ctrl+Z で元に戻せる。

### ANA-30 シンボル名のデマングル

| 項目 | 内容 |
| --- | --- |
| ロードマップ | 追加 (フェーズ 4 提案) |
| 呼び出し | 解析 > デマングル...、テキスト列の選択範囲の右クリックメニュー「デマングル」、コマンドパレット「解析: シンボル名をデマングル」 |

**概要**: C++ や Rust のコンパイラが生成した装飾済みのシンボル名 (マングル名) を、人が読める名前に戻す。

**仕様**:

1. 対応する方式:

   | 方式 | 例 |
   | --- | --- |
   | Itanium C++ ABI (GCC、Clang) | `_ZN3foo3barEi` → `foo::bar(int)` |
   | Microsoft Visual C++ | `?bar@foo@@QEAAXH@Z` → `public: void __cdecl foo::bar(int)` |
   | Rust (旧方式) | `_ZN4core3ptr13drop_in_place17h0123456789abcdefE` → `core::ptr::drop_in_place` |
   | Rust (v0) | `_RNvCs1234_7mycrate3foo` → `mycrate::foo` |
   | D | `_D3foo3barFiZv` → `void foo.bar(int)` |

   - Swift、Objective-C などは対象外 (未決定)。
2. 方式は名前の先頭の文字列から自動で判定する。判定できない場合は入力をそのまま表示する。
3. 「デマングル」のページ: 入力欄 (複数行、1 行に 1 つ) と結果欄。入力に合わせてその場で変換する。
4. 選択範囲から実行した場合は、選択範囲を現在の文字コードで文字列として読み (NUL は改行として区切る)、デマングルした結果をページに表示する。
5. 表示オプション: 型情報 (引数・戻り値の型) を省いた短い名前 / 完全な名前 (既定)。Rust の旧方式ではハッシュ部分 (`17h...E`) を表示しない (既定)。
6. 結果をコピーできる。
7. 逆アセンブル (ANA-24 のシンボル一覧、ANA-23 のコメント列) とテンプレートの標準ライブラリ (07 の TPL-18) は、この機能を使ってシンボル名を表示する。
8. 実装は本体の自作のデマングラとし、出力の形は LLVM のデマングラ (`llvm-cxxfilt`・`llvm-undname`) に合わせる (`char const*`、`void (*)(int)`、`std::vector<int, std::allocator<int>>`)。Itanium の式 (テンプレート引数の `X…E`) はリテラル・テンプレートの仮引数・sizeof・単項と二項の演算子だけを解釈し、それ以外は「デマングルできません」とする。Microsoft の局所の名前 (`?1??func@@…`) は解釈しない。D は属性 (pure など) を表示しない。

**画面**: 「デマングル」のページ (ツールのタブで開く。モードレス)。上に入力欄、下に結果欄、オプションのチェックボックス、「コピー」ボタン。

**巨大ファイル・長時間処理**: 1 つの名前の長さは 64 KB まで (超える部分は変換しない)。入力が 1 万行を超える場合は、バックグラウンドで変換する。

**エラー**: 不正なマングル名: その行の結果に「デマングルできません」と表示し、元の文字列をそのまま出す。

**受け入れ基準**:

- [ ] 1 の表の例がすべて期待どおりに変換される。
- [ ] 複数行の入力を一度に変換できる。
- [ ] 逆アセンブルのシンボル一覧で C++ の関数名がデマングルされて表示される。
- [ ] 不正な名前を入力してもアプリが落ちず、「デマングルできません」と表示される。

### ANA-31 構造を理解した比較 (フィールドの対応付け)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F6-01 |
| 呼び出し | 比較タブのツールバー「構造で比較」(トグル)、解析 > 比較 > 構造で比較、ファイルを比較ダイアログ (ANA-01) のチェックボックス「構造でも比較する」、コマンドパレット「比較: 構造で比較」「比較: 構造の比較に使うテンプレートを選ぶ」、ショートカットは既定なし |

**概要**: 比較の左右に同じ構造体テンプレート (07) を当てはめ、違いを「どのフィールドがどう変わったか」として求める (例: `nt.FileHeader.TimeDateStamp` が `0x5F5E1000` から `0x60000000` に変わった、tEXt のチャンクが 1 つ増えた)。配列の要素は、チャンクの種類や名前などのキーで対応付け、追加・削除・移動を見分ける。バイトの比較 (ANA-02 / ANA-03) はそのまま行い、構造の比較はその横に並べて出す。

**仕様**:

1. 使える対象と既定:
   - 比較の左右が、ANA-01 の 1 の「開いているドキュメント」「ディスク上のファイル」「保存済みの内容」「物理ディスク・ボリューム」のどれかのときに使える。プロセスメモリのスナップショット (ANA-09) では使えない (メニュー項目を無効にし、ツールチップで理由を出す)。
   - 「構造でも比較する」の既定はオン (設定 `compare.structure.enabled`)。テンプレートが決まらない場合はエラーにせず、バイトの比較だけを行い、構造の差分パネル (ANA-32) に理由と「テンプレートを選ぶ...」ボタンを出す。
2. テンプレートの決め方。上から順に調べ、最初に決まったものを使う。
   1. 利用者が「構造の比較に使うテンプレートを選ぶ」で選んだテンプレート。左右で 1 つ。開始オフセットは左右別に指定でき、既定は ANA-01 の左右の開始オフセット。
   2. 左右のドキュメントの両方に、同じテンプレートファイルの固定の適用 (TPL-20、TPL-26) があり、その開始オフセットから比較の開始オフセットを引いた値が左右で同じとき: そのテンプレートと開始オフセット。該当する適用が複数あれば、比較の開始オフセットに最も近いもの。
   3. 左右それぞれの比較の開始オフセットで自動適用の判定 (TPL-30 の 1、2) を行い、両方の最上位の候補が同じテンプレートで、どちらの一致も `magic` (または `magic_all`) を含むとき: そのテンプレートを比較の開始オフセットから。拡張子・MIME だけの一致では選ばない。
   - 左右で別のテンプレートを使うことはできない (対象外)。
   - 決めたテンプレートと開始オフセットと理由を、構造の差分パネルの見出しに出す (例: 「テンプレート: PE executable (pe.hxt)、左 0x0 / 右 0x0。両方のマジックが一致したため」)。
3. 評価:
   - 左右それぞれ、比較を始めた時点の内容 (0.2) に対してテンプレートを新しく評価する。タブの結果ツリー (TPL-21) の適用とは別の評価で、タブの結果ツリーと色分けは変えない。
   - 評価は TPL-28 (遅延評価・上限・キャンセル) に従い、テンプレートの上限 (`limit.*`、TPL-17 の 4) も通常の適用と同じにする。
   - テンプレートはデータの末尾まで読める。比較の範囲 (ANA-01 の 2 の長さ) は構造の比較には使わず、範囲の外のフィールドの差分には「範囲外」の印を付ける。
4. 比べる単位 (フィールド):
   - 葉のパターン: 整数、浮動小数点、`bool`、文字、列挙型、フラグ型、ビットフィールドの要素、日時などの表示用の型 (TPL-03 の 4)、文字列 (`string`、`wstring`、`pstring`)、`u8` と `char` と `char16` の配列 (1 つの値として比べる。TPL-07 の 6)、埋め草 (`padding`)、`[[sealed]]` のパターン (中身を 1 つの値として比べる)。
   - 入れ物のパターン: 構造体、共用体、配列、ポインタ、セクション。入れ物は子を比べる。
   - 比べないもの: `export(false)` のパターン、計算値 (`[[show]]` のローカル変数)。`hidden` のパターンは既定では比べない (設定 `compare.structure.includeHidden`、既定オフ)。
   - 葉は、パターンの範囲のバイト列で比べる。ビットフィールドの要素はビットの値で、`read` 変換 (TPL-14) のあるパターンは変換後の値で比べる。範囲のバイト列が同じなら、オフセットが違っても「一致」とする (前に追加があってずれただけのフィールドは差分にしない)。
5. 対応付け (左右のどのパターンどうしを比べるか)。結果ツリーの根から順に、次の規則で対応付ける。
   1. 構造体・共用体の子: 名前 (識別子) で対応付ける。`if` や `switch` の中で宣言したかどうかは問わない。ループで宣言して添字の付いた同じ名前のパターン (`section[1]` など、TPL-11) は、配列の要素と同じ規則で対応付ける。片方にしかない名前は「追加」(右だけにある) または「削除」(左だけにある) にする。
   2. 同じ名前で型名が違う: 「型の変更」とし、その下は比べない。
   3. 配列の要素: 次の 3 つの方法の 1 つで対応付ける。既定は「自動」。

      | 方法 | 対応付け |
      | --- | --- |
      | キー | 要素の型の、指定した葉のフィールド (キーフィールド) の値と、同じ値の中での出現の順で対応付ける (左の 2 番目の `IDAT` と右の 2 番目の `IDAT`) |
      | 内容 | 要素の範囲のバイト列のハッシュの並びを、Myers の差分 (ANA-03 と同じ部品) で対応付ける。一致しない要素の連続のうち、左右で同じ位置にあるものを順に組にして「変更」として中身を比べ、余りを追加・削除にする |
      | 位置 | 添字で対応付ける (`[i]` と `[i]`)。長さが違えば、余りを追加・削除にする |

      - 「自動」の決め方: (a) テンプレートで、配列のパターンまたは要素の型に属性 `[[diff_key("フィールド名")]]` (TPL-13) があれば、そのフィールドをキーにする。(b) なければ、要素が構造体で、その直接の子に文字列・文字の配列 (64 バイト以下)・列挙型・GUID / UUID の葉があれば、宣言の順で最初のものをキーにする。ただし、そのフィールドの値が左右のどちらかですべての要素で同じなら、次の候補にする。(c) どれもなければ、要素が構造体なら「内容」、葉なら「位置」にする。
      - 使った方法とキーを配列の行に出す (「キー: type」「内容」「位置」)。構造の差分パネル (ANA-32) の配列の行の右クリックメニュー「対応付けの方法...」で、配列ごとに方法とキーを変えられる。キーには要素の型の直接の子の葉だけを選べる。変えた設定は、テンプレートと配列のパス (添字を除いた形。例: `chunks`、`sections`) ごとに記録し、次からの比較でも使う (設定 `compare.structure.arrayRules`)。
   4. 移動: 「キー」で対応付けた要素のうち、左右で並び順が違うもの (左の順に並べたときの右の添字の並びの、最も長い増加部分列に入らない要素) を「移動」とする。「内容」では、削除と追加になった要素のうち、バイト列が同じものの組を「移動」とする。移動した要素も中身を比べ、違いがあれば「移動・変更」とする。
   5. ポインタ: ポインタの値は葉として比べ、指す先のパターンは子として比べる。指す先がすでに比べたパターンと同じ (TPL-08 の「既出」) なら、指す先は比べない。
   6. セクション (TPL-15): セクションの中のパターンも比べる。差分のバイトの範囲は、セクションを作った元の範囲 (展開の元のデータなど) を指す。
   7. 対応付けは 64 段の深さまで。それより深い部分は比べず、「深すぎるため比べていません」の行を 1 つ出す。
6. 差分の種類は「変更」「追加」「削除」「移動」「移動・変更」「型の変更」「解析できない」の 7 つ。
   - 「解析できない」: 片方または両方で、そのパターンまたはその親でテンプレートのエラー (TPL-27) が起きたもの。エラーより後ろのパターンは、相手側にあっても「削除」「追加」にせず、「解析できない (右: エラーの理由)」の行 1 つにまとめる。
   - 上限 (`limit.array` など) で打ち切った配列の、打ち切りより後ろも同じく比べず、「上限のため比べていません」の行にする。
   - 埋め草 (`padding`) の違いも「変更」として求め、行に「埋め草」の印を付ける (構造の差分パネルの既定の絞り込みでは表示しない。ANA-32 の 3)。
7. 差分 1 件の情報: 種類、表示用のパス、左のパス、右のパス、型、左右の値の表示 (結果ツリーの値の列と同じ表示。長い値は先頭 64 文字)、左右の開始オフセットとサイズ (ドキュメントの先頭からのオフセット)、対応付けの方法、範囲外かどうか。
   - 表示用のパスは左のパス (追加では右のパス) で、キーで対応付けた配列の要素にはキーの値を付ける (例: `chunks[3] (type = "tEXt")`)。
   - 追加の行の左のオフセットには、左でその要素が入るはずの位置 (同じ親の中で、直前に対応付いた兄弟の終わり。兄弟がなければ親の始まり) を入れ、サイズは 0 にする。削除の行の右も同じ。
8. 構造の外の差分: バイトの比較 (ANA-02 / ANA-03) の差分のうち、どの葉のパターンの範囲とも重ならない部分 (テンプレートが解釈しない部分) の件数とバイト数を求め、構造の差分の一覧の最後に「構造の外の差分」の行 1 つとして出す。
9. 再比較 (ANA-01 の 8) で、構造の比較もやり直す。使っているテンプレートのファイルを保存すると、構造の比較を自動でやり直す (TPL-20 の 6 と同じ)。
10. 要約: テンプレート、左右の開始オフセット、比べたフィールドの数 (左右)、種類ごとの件数、構造の外の差分の件数とバイト数、テンプレートのエラー・警告の件数 (左右)、かかった時間、上限・キャンセルで途中までかどうか。

**画面**: 比較タブのツールバーに「構造で比較」のトグル (アイコンと名前) と、使っているテンプレートの名前のボタン (押すと「構造の比較に使うテンプレートを選ぶ」を開く)。テンプレートの選択は TPL-20 の選択画面に、左右の開始オフセットの欄を加えたものを使う。結果は構造の差分パネル (ANA-32)。

**巨大ファイル・長時間処理**:

- 構造の比較は、バイトの比較と並行して、別の長時間処理 (処理センターの「構造の比較」) として行う。進捗は「比べたフィールドの数」と「左の評価位置 / 左の長さ」。見つかった差分は 0.5 秒ごとに一覧に加える。
- 比べるフィールドの数の上限は、左右それぞれ 1,000,000 個 (設定 `compare.structure.maxFields`、10,000〜10,000,000)。上限に達したら止め、それまでの差分を残して、パネルに「フィールドの数が上限 (1,000,000) に達したため、途中まで比べました」と「上限を上げて再比較」ボタン (設定の最大値まで) を出す。
- 速くするための方針 (実装の方針):
  - 葉の要素の固定長の配列 (`u32 a[n]` など) は、要素を 1 つずつ評価せず、左右の範囲のバイト列を 1 MiB 単位で比べ、違う要素の連続を 1 件の差分 (「`a[10 … 25]` 変更」) にまとめる。比べたフィールドの数には、差分の件数だけを数える。
  - 型の定義から、ポインタ・セクション・`$` への代入を含まない固定長の型 (TPL-28 の 1) と分かる部分木は、左右のバイト列が同じなら子を評価せずに一致とする。
  - 「内容」の対応付けで Myers を使うのは、要素の数が左右とも 100,000 以下の配列だけにする。超える場合は「位置」にし、配列の行に「要素が多いため位置で対応付けました」と出す。「キー」の対応付けはハッシュ表で行い (要素の数に比例する時間)、キーの値は 1 要素につき先頭 64 バイトまで持つ。
- 作業用のメモリは、評価のメモリ (左右それぞれ `limit.memory` まで、TPL-28 の 2) のほかに 256 MB 以内とする。差分の件数の上限は `compare.structure.maxFields` と同じ。
- キャンセルは 100 ms 以内に効く (TPL-28 の 4)。キャンセルした場合も、それまでの差分を残し、要約に「途中で中止」と出す。
- バイトの比較の読み込みと Hex ビューの表示の読み込みを、構造の比較の読み込みより優先する。

**エラー**:

- テンプレートの構文エラー: 構造の比較を行わず、パネルに理由と「テンプレートを選ぶ...」「テンプレートを編集」ボタンを出す。バイトの比較は続ける。
- 片方の評価だけでエラーが起きた: 6 の「解析できない」で示す。
- 再比較のときにテンプレートのファイルが見つからない: パネルにその旨と「テンプレートを選ぶ...」を出す。

**受け入れ基準**:

- [ ] `nt.FileHeader.TimeDateStamp` だけが違う 2 つの PE ファイルを比較すると、構造の差分が「変更」の 1 件だけになり、パスと左右の値と左右のオフセットが表示される。
- [ ] 左右のドキュメントにテンプレートの適用がなくても、2 つの PNG ファイルの比較で PNG のテンプレートが選ばれ、選んだ理由が表示される。拡張子だけが一致する場合はテンプレートが選ばれない。
- [ ] TD-ANA-STRUCT-PNG-A と TD-ANA-STRUCT-PNG-B の比較で、IHDR の幅と CRC、tEXt (Author) の長さ・文字列・CRC の「変更」、tEXt (Comment) の「追加」、tIME の「削除」だけが報告され、位置がずれた IDAT と IEND は差分にならない。
- [ ] tEXt のチャンクを後ろへ移した PNG との比較で、そのチャンクが「移動」の 1 件だけになる。
- [ ] キーのない構造体の配列で、要素 1 つの削除・1 つの挿入・1 つの値の変更が、それぞれ「削除」「追加」「変更」の 1 件ずつになる。対応付けの方法でキーに `id` を選ぶと同じ結果になり、次の比較でもその設定が使われる。
- [ ] `[[diff_key("id")]]` を付けた配列が、`id` をキーにして対応付けられる。
- [ ] 右のファイルの途中が壊れていて解析エラーになると、エラーより後ろは「削除」にならず、「解析できない」の 1 行になる。
- [ ] テンプレートが解釈しない部分のバイトの差分が、「構造の外の差分」の行と要約の件数・バイト数に出る。
- [ ] 1 億要素の葉の配列 (`u64 a[eof]`) を持つ 2 つのデータの比較で、違う要素の連続が範囲の差分にまとめられ、メモリ使用量が 1 GB を超えない。
- [ ] フィールドの数が上限に達すると、途中までの結果と「上限を上げて再比較」が表示される。比較中のキャンセルが 100 ms 以内に効き、それまでの差分が残る。
- [ ] テンプレートが決まらない 2 つのファイルでは、バイトの比較だけが行われ、構造の差分パネルに理由と「テンプレートを選ぶ...」が表示される。

### ANA-32 構造の差分パネル (表示・移動・絞り込み・エクスポート)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F6-01 |
| 呼び出し | 比較タブの下部パネル「構造の差分」、表示 > パネルの表示切り替え > 構造の差分、コマンドパレット「比較: 構造の差分を表示」「比較: 次の構造の差分」「比較: 前の構造の差分」「比較: 構造の差分をエクスポート」。Alt+F5 / Shift+Alt+F5 (ANA-05) は、このパネルにフォーカスがあるとき、または比較タブの「移動の対象」が「構造」のとき、構造の差分の間を移動する |

**概要**: 構造の比較 (ANA-31) の結果を、フィールドの木の形で一覧にする。行を選ぶと、左右の Hex ビューでそれぞれのフィールドの範囲を選ぶ。種類で絞り込み、JSON・CSV・テキストのレポートに書き出せる。

**仕様**:

1. 表示には、結果ツリー (TPL-21) と同じツリー表の部品を使う。差分のある葉と、その祖先 (入れ物) だけを表示する。祖先の行には子孫の差分の件数を種類ごとに出す (例: `chunks — 変更 5、追加 1、削除 1`)。差分が 1,000 件以下ならすべて開いた状態で、超える場合は最上位だけを開いた状態で表示する。
2. 列: 名前 (表示用のパスの最後の要素。ANA-31 の 7)、種類、左の値、右の値、型、左オフセット、右オフセット、サイズ (左右で違えば `16 → 24`)、対応付け (配列の行だけ)。オフセットとサイズの基数は Hex ビューの設定に従う。
   - 種類はアイコンと文字の両方で示し、色だけにしない。変更・追加・削除の色と模様は ANA-04 の 3 の表と同じものを使い、移動は矢印のアイコン、型の変更と解析できないは警告のアイコンにする。
3. 絞り込み:
   - 種類のチェックボックス (変更 / 追加 / 削除 / 移動 / 型の変更 / 解析できない)。既定はすべてオン。「移動・変更」は「移動」と「変更」のどちらがオンでも表示する。
   - 「埋め草を含める」(既定オフ)。
   - 名前・パス・値の文字列での絞り込み欄 (部分一致。大文字・小文字を区別しない序数比較、00 の 5.4)。
   - 「一致したフィールドも表示」(既定オフ)。オンにすると、比べたすべてのフィールドを表示する。
4. 行を選ぶ (クリックまたは Enter): 左の Hex ビューで左の範囲を、右の Hex ビューで右の範囲を選んで表示する。追加の行では、左は ANA-31 の 7 の入るはずの位置にカーソルを置き (選択はしない)、削除の行の右も同じにする。
   - 同期スクロール (ANA-04 の 4) は、この移動の後は「左右の今の位置の差を保つ」動きで続ける。バイトの差分へ移動するか再比較すると、元の動きに戻る。
   - 移動はジャンプ履歴 (VIEW-31) に記録する。
5. 次 / 前の構造の差分: 表示中 (絞り込みの後) の葉の行の順に、次・前の行を選び、4 の動作をする。末尾・先頭で折り返す動作と表示は ANA-05 の 3、4 と同じ (「先頭の構造の差分に戻りました」「構造の差分はありません」)。比較タブのツールバーに「移動の対象: バイト / 構造」の切り替えを置く (既定は「バイト」)。構造の差分パネルにフォーカスがあるときは、切り替えによらず構造を対象にする。
6. 右クリックメニュー: 「左のデータへ移動」「右のデータへ移動」「パスをコピー」「行をコピー」(タブ区切り)、「左右の値をコピー」、「左にブックマークを追加」「右にブックマークを追加」(パスと種類をコメントにしたブックマーク。05)、「対応付けの方法...」(配列の行だけ。ANA-31 の 5 の 3)、「左の結果ツリーで表示」「右の結果ツリーで表示」。
   - 「左の結果ツリーで表示」: 左のドキュメントに同じテンプレート・同じ開始オフセットの適用があれば、その結果ツリーで対応するノードを選ぶ。なければ、その適用を固定の適用として左のドキュメントに加えてから選ぶ。右も同じ。
7. エクスポート (「エクスポート...」): JSON・CSV・テキストのレポートに書き出す。対象は表示中 (絞り込みの後) の行 (既定) か、すべての差分。
   - JSON: `template`、`left` と `right` (ドキュメントの名前・パス・開始オフセット・評価の状態)、`summary` (ANA-31 の 10)、`diffs` (配列)。`diffs` の各要素は `kind` (`changed` / `added` / `removed` / `moved` / `movedChanged` / `typeChanged` / `unparsed`)、`path`、`leftPath`、`rightPath`、`type`、`left` と `right` (`offset`、`size`、`value`、`display`。片方にないときは `null`)、`match` (`key:<フィールド名>` / `content` / `index`)、`padding`、`outsideRange`。数値の書き方は TPL-25 の 2 と同じ (64 bit を超える整数とバイト列は文字列)。
   - CSV: 1 行に 1 差分。列は `kind,path,leftPath,rightPath,type,leftOffset,leftSize,leftValue,rightOffset,rightSize,rightValue,match`。文字コード・改行・引用は TPL-25 の 3 と同じ (BOM 付きの UTF-8、CRLF、RFC 4180)。
   - テキストのレポート: 要約と、1 行に 1 差分 (例: `変更  nt.FileHeader.TimeDateStamp  0x5F5E1000 → 0x60000000  (左 0x88、右 0x88)`)。種類の語は表示言語で書く。文字コードは UTF-8 (BOM なし)。
   - JSON・CSV の `kind` は表示言語によらない英語の語にする。オフセットの書式は 10 進 (既定。JSON では数値) か 16 進の文字列を選べる (TPL-25 の 4 と同じ)。
8. パネルの上部に、ANA-31 の 10 の要約と、比較中の状態 (「比較中: 12,345 フィールド」) を出す。エラー・警告の件数をクリックすると、その側のテンプレートの出力 (TPL-27) を開く。
9. スクリーンリーダー: 葉の行は「種類、パス、左の値、右の値、左オフセット、右オフセット」を読み上げる (例: 「変更、nt.FileHeader.TimeDateStamp、左 0x5F5E1000、右 0x60000000、左 0x88、右 0x88」)。祖先の行は「名前、差分の件数、開閉の状態」を読み上げる。
10. キーボード: 行の移動・開閉・Enter は TPL-21 の 7 と同じ。Ctrl+C で「行をコピー」。右クリックメニューは Shift+F10 またはアプリケーションキー。
11. 画面の文字列はすべてリソースにし、英語と日本語を書く (00 の 5.3)。テンプレート由来の名前と値は翻訳しない。

**画面**: 比較タブの下部パネルに、差分の一覧 (ANA-06) と並ぶタブ「構造の差分」を置く。上部に要約とツールバー (種類の絞り込み、文字列の絞り込み、一致も表示、前の構造の差分、次の構造の差分、エクスポート、テンプレートの選択)、その下にツリー表。幅が 800 px 未満のときは要約を折りたためる。

**巨大ファイル・長時間処理**: ツリー表は仮想化し、100 万行でも 60 fps でスクロールできる (TPL-21 の 4)。絞り込みは 100 万件で 500 ms 以内に終える。それ以上かかる場合はバックグラウンドで行い、一覧の上に進捗を出す。エクスポートは長時間処理として、ストリームで書き出す。キャンセルすると書きかけのファイルを消す。

**エラー**:

- エクスポート先に書き込めない: InfoBar に理由 (アクセス拒否、容量不足) を出し、書きかけのファイルを消す。
- 「左の結果ツリーで表示」で、適用の数が上限 (TPL-20 の 3 の 32 個) に達している: 適用を加えず、InfoBar で知らせる。

**受け入れ基準**:

- [ ] 構造の差分パネルに、差分のある葉とその祖先だけが表示され、祖先の行に子孫の差分の件数が種類ごとに出る。
- [ ] 行を選ぶと、左右の Hex ビューでそれぞれのフィールドの範囲が選ばれる。追加の行では、左のカーソルが入るはずの位置に移る。

### ANA-33 ファイルマップの作成 (領域の判定)

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F6-02 |
| 呼び出し | 解析 > ファイルマップ、コマンドパレット「解析: ファイルマップを作成」「解析: ファイルマップを作り直す」、ミニマップの右クリックメニュー「ファイルマップを作成」、ショートカットは既定なし |

**概要**: ドキュメント全体を 1 回の操作で調べ、どこに何があるか (既知の形式の構造、埋め込まれたファイル、圧縮・暗号化されたデータ、テキスト、ゼロ・埋め草、繰り返しのレコード) を領域の一覧にする。まず標本で数秒のうちに概観を出し、続けて全体を読んで細かくする。どの大きさのドキュメントでも、メモリの使用量は一定の上限に収める。

**仕様**:

1. 対象: ドキュメント全体 (既定) または対象範囲 (0.1)。対象範囲は 1 つの連続した範囲にする (マルチ選択の場合は、最初の範囲の先頭から最後の範囲の終わりまで)。画面 (メニュー・コマンドパレット・パネル・ミニマップ) から作るときは、選択範囲があってもドキュメント全体を対象にする (ファイルマップはドキュメント全体の見取り図のため。一部だけの見取り図は、範囲を新しいタブで開いて (ENG-39) そのタブで作る)。対象範囲は Core の作成の指定で渡せる。変換ビュー (EDIT-45) が有効なタブでは、変換後のデータを対象にする (0.1.1)。ファイル・ディスク・ボリューム・プロセスメモリ・リモートのどのデータソースでも使える。プロセスメモリでは読めない領域を「読み込み不可」にする。
2. 次の 3 つの段階で作る。各段階の結果は、できたところから画面 (ANA-34) に出す。
   1. 概観 (標本): 対象を 4,096 個の区間 (区間の長さは「対象の長さ / 4,096」以上で最小の 2 の累乗。最小 4 KiB) に分け、各区間の中央の 4 KiB を読んで ANA-16 の 2 の規則で分類する。あわせて、対象の先頭でファイル形式の判定 (ANA-17 の 4) を行う。読む量は最大 16 MiB と判定の 128 KiB。この段階の領域は「標本による推定」とし、確度は最大で「中」にする。
   2. 全体の走査: 対象を先頭から 1 回だけ順に読み、次を同時に行う。走査が済んだ範囲から、概観の結果を置き換える。
      - (a) ブロックごとの ANA-16 の分類。ブロックの大きさは 4 KiB。対象が 64 GiB を超える場合は、ブロックの数が 2^24 以下になる最小の 2 の累乗にする。
      - (b) 埋め込まれた形式のシグネチャの探索。ANA-17 の 6 と同じ条件 (先頭の固定バイト列が 4 バイト以上の項目) と、カービングの組み込みの定義 (FOR-18 の 3) のヘッダを使う。どちらも先頭の固定バイト列が 4 バイト以上のものを 1 つの表 (Aho-Corasick 法) で同時に探し、見つかった位置で項目の条件 (データベース) とヘッダの全体 (カービング) を確かめる。対象の先頭は先頭の形式 (3 の (a)) なので候補にしない。
      - (c) 圧縮形式のシグネチャの探索と展開の確認 (ANA-16 の 4)。
      - (d) ゼロ・定数のバイトの 512 バイト以上の連続の、境目のバイト単位での確定。
   3. 構造の解析:
      - (a) 対象の先頭の形式に、自動適用の候補 (TPL-30 の 1、2。`magic` を含む一致) のテンプレートがあれば、それを評価し、最上位のパターン (例: PE の `header`、`nt`、`sections`) と、属性 `[[bookmark]]` (TPL-13) の付いたパターンを「形式の構造」の領域にする。
      - (b) 走査で見つけた埋め込まれた形式のうち、その位置で自動適用の候補になるテンプレートがあるものは、その位置から評価し、最上位のパターンの最後の終わりまでを「埋め込まれたファイル」(確度 高) にする。評価がエラーになったもの、テンプレートのない形式は、カービングの定義の長さの決め方 (FOR-19 の 3 の構造の検証・サイズの取得・フッター) で長さを決め (確度 中)、それでも決まらなければ次の領域 (内容のレーンで、その位置を含む領域の次の領域、または次の候補) の始まりまでを「終わりが不明」(確度 低) とする。テンプレートは、その位置を先頭 (オフセット 0) とするデータとして評価し、カービングの定義で長さが決まる場合はその長さまでのデータにする (ZIP のように末尾から構造を探す形式でも、後ろに続くデータに影響されない)。前に決めた埋め込まれたファイル (確度 中以上) の中にある候補 (ZIP の 2 つ目以降のローカルヘッダなど) は、そのファイルの一部とみなして領域にしない。
      - (c) 圧縮形式のシグネチャで展開を確かめたストリーム (ANA-16 の 4) は、その範囲を「圧縮」(ラベルは形式名、確度 高) にする。範囲の終わりは DEFLATE の最後のブロックの終わりと末尾のチェック値 (zlib は Adler-32、gzip は CRC-32 と ISIZE) でバイト単位に決め、チェック値が合わないものは偶然の一致として除く。ブロックの大きさより短いストリーム (PNG の IDAT の中の短い zlib など) は領域にしない (細切れを避けるため。シグネチャは ANA-16 の一覧に残る)。
      - (d) 分類が「バイナリ」で 16 KiB 以上の領域 (長い順に最大 64 個) について、領域の先頭 256 KiB で ANA-15 の 3 の自己相関を求める。最も割合の高いずらし k (8〜4,096) の一致の割合が 20% 以上で、ずらし 1〜(k − 1) の一致の割合の平均の 2 倍以上なら、その領域を「繰り返しのレコード (k バイト)」にする (確度は割合が 50% 以上で高、それ以外は中)。
      - 構造の解析のテンプレートの評価の上限: 先頭の形式は時間 5 秒 (TPL-30 と同じ)、埋め込まれた形式は 1 つにつき時間 2 秒・パターン 100,000 個。埋め込まれた形式を評価するのは全体で 256 個まで (それを超えた分は、確度 中・低の方法で長さを決める)。
3. 領域の種類 (凡例の項目) と、帯 (ANA-34) のどのレーンに置くか:

   | 種類 | 決め方 | レーン |
   | --- | --- | --- |
   | 形式の構造 | 2 の 3 の (a)。ラベルはパターンのパス (例: `sections[0]`) と、`name` 属性または文字列のメンバーの値 (例: `.text`) | 構造 |
   | 埋め込まれたファイル | 2 の 3 の (b)。ラベルは形式名 (例: `PNG image`) | 構造 |
   | 圧縮 | ANA-16 の「圧縮」と 2 の 3 の (c) | 内容 |
   | 暗号化・乱数 | ANA-16 の「暗号化・乱数」 | 内容 |
   | テキスト | ANA-16 の「テキスト」。ラベルに文字コード (ASCII / UTF-8 / UTF-16) を付ける | 内容 |
   | ゼロ・埋め草 | ANA-16 の「定数」。ラベルは `ゼロ` または `定数 0xFF` の形 | 内容 |
   | 繰り返しのレコード | 2 の 3 の (d) | 内容 |
   | バイナリ | ANA-16 の「バイナリ」 | 内容 |
   | 読み込み不可 | 読めなかった範囲 | 内容 |

   - 構造のレーンの領域は 2 段まで入れ子にできる (埋め込まれたファイルの中に、そのテンプレートの最上位のパターン)。内容のレーンの領域は重ならない (どのバイトも 1 つの種類に入る)。構造のレーンに領域のないバイトもある。
4. 各領域が持つ情報: 開始オフセット、長さ、種類、ラベル、確度 (高 / 中 / 低)、根拠、どの段階の結果か (標本 / 走査 / 構造)、使ったテンプレート、入れ子の親。
   - 根拠は文章で、数値を含める (例: 「0x50000 に PNG のシグネチャ。テンプレート "PNG image" で 0x50000〜0x5045F (1,120 バイト) を解析できました」「エントロピー 7.99 ビット / バイト、カイ二乗の p 値 0.41」「ずらし 64 バイトで 31% が一致 (ずらし 1〜63 の平均は 2%)」「区間の中央の 4 KiB の標本による推定」)。文は文単位のリソースにし、数値は地域設定で書式化する (00 の 5.4)。
5. 結果の共有: 全体の走査で求めた分類は、同じドキュメント・同じ範囲・同じブロックの大きさの ANA-16 の結果として登録する。統計パネルの「分類」タブとミニマップの分類の印 (VIEW-35 の 6) は、データを読み直さずにそれを使う。逆に、条件の合う ANA-16 の結果がすでにあれば、走査の (a) を省く。
6. 編集との関係: 0.2 に従う。作った後に編集すると、パネルに「結果は編集前の内容のものです」と「作り直す」ボタンを出す。「作り直す」はすべての段階をやり直す (編集した部分だけの作り直しは行わない)。
7. ファイルマップはドキュメントを閉じるまで持ち、ドキュメントに付随するデータ (00 の 10 章) には保存しない (残したいときはエクスポートする。ANA-34 の 9)。
8. ファイルマップは自動では作らない (利用者の決定 2026-10-21)。作るのは、ファイルマップを作成する操作 (解析 > ファイルマップ、コマンドパレット、ミニマップの右クリックメニュー、パネルの「作成」) をしたときだけにする。開いたときに自動で作る設定は設けない。
9. この解析は推定である。パネルに「シグネチャと統計に基づく推定で、誤りがありえます」と常に出す (ANA-16 の 8 と同じ)。

**画面**: ファイルマップのパネル (ANA-34)。進捗は処理センターとパネルの状態の行に出す。

**巨大ファイル・長時間処理**:

- 3 つの段階を 1 つの長時間処理として処理センターに出す (段階の名前、進捗率、残り時間、キャンセル)。
- 概観は、100 GB のファイルでも 5 秒以内 (ローカルの SSD) に出す。全体の走査の速さの目標は、ストレージの読み込み速度の 50% 以上 (ANA-17 の 6 と同じ)。
- メモリ: ブロックの分類はブロック 1 つにつき 1 バイト (最大 2^24 ブロックで 16 MiB。根拠の文のためのエントロピー・p 値・確度を合わせて 1 ブロック 5 バイト、最大 80 MiB)。領域は最大 1,048,576 個 (2^20)、埋め込まれた形式の候補は最大 100,000 個まで持ち、超えた分は件数だけを数えて「ほか n 件」と出す。テンプレートの評価のメモリを除き、128 MB 以内とする。
- 実装の注記 (フェーズ 6 の監査): シグネチャだけを敷き詰めたデータでも走査と構造の解析が終わるように、2 の 2 の (b) で項目の条件 (データベース) を確かめるために読む量は全体で「対象の長さ」(最小 64 MiB) まで、2 の 3 の (b) でカービングの定義の長さを決めるための読み取りは全体で「対象の長さの 4 倍」(最小 256 MiB) までとする。超えた後の一致は候補にせず「ほか n 件」に数え、長さは確度の低い方法 (次の領域まで) で決める。
- キャンセルは 100 ms 以内に効く。済んだ段階・済んだ範囲の結果は残し、走査していない範囲は概観の結果 (「標本による推定」) のまま残す。
- Hex ビューの表示の読み込みを優先し、ファイルマップを作っている間も Hex ビューのスクロールは 60 fps を保つ。

**エラー**:

- 読み込みエラー: その範囲を「読み込み不可」にして続ける (ANA-16 と同じ)。
- テンプレートの評価のエラー: その領域の長さを確度の低い方法で決め、根拠に「テンプレート "…" の解析に失敗しました (HXT2xxx)」と書く。ファイルマップ全体はエラーにしない。

**受け入れ基準**:

- [ ] TD-ANA-MAP-MIX で、PE の構造、ゼロ、テキスト、埋め込まれた PNG、zlib の圧縮、暗号化・乱数、64 バイトの繰り返しのレコード、埋め込まれた ZIP の各領域が、テストデータの定義の位置 (内容のレーンはブロック 1 つ以内の誤差、埋め込まれたファイルと圧縮のストリームは正確なオフセット) と種類で一覧に出る。
- [ ] 埋め込まれた PNG の領域の長さが、PNG のテンプレートで解析した長さ (IEND のチャンクの終わりまで) と一致し、確度が「高」になる。
- [ ] 100 GB のファイルで、5 秒以内に概観が表示され、全体の走査の間も Hex ビューのスクロールが 60 fps を保つ。
- [ ] 100 GB のファイルの全体の走査で、メモリ使用量が 1 GB を超えない。
- [ ] 走査の途中でキャンセルすると 100 ms 以内に止まり、走査した範囲は走査の結果、残りは「標本による推定」として残る。
- [ ] 変換ビュー (XOR 0x5A) を設定した TD-ANA-MAP-XOR で、TD-ANA-MAP-MIX と同じ領域が出る。
- [ ] ファイルマップを作った後、統計パネルの「分類」タブとミニマップの分類が、データを読み直さずに表示される。
- [ ] 作った後に編集すると、「結果は編集前の内容のものです」と「作り直す」が表示される。
- [ ] すべての領域に確度と、数値を含む根拠の文がある。
- [ ] 読み込みエラーになる範囲を含むデータで、その範囲が「読み込み不可」になり、ファイルマップは最後まで作られる。

### ANA-34 ファイルマップの表示と操作

| 項目 | 内容 |
| --- | --- |
| ロードマップ | F6-02 |
| 呼び出し | ANA-33 の実行で自動で開く。表示 > パネルの表示切り替え > ファイルマップ、コマンドパレット「解析: ファイルマップを表示」「解析: ファイルマップをエクスポート」「解析: 見つかったファイルにテンプレートを適用」、ミニマップのファイルマップの印のクリック |

**概要**: ファイルマップを、ドキュメント全体を表す横長の帯と領域の一覧で表示する。クリックでその場所へ移動でき、領域ごとに、テンプレートの適用、新しいタブで開く、展開、テンプレートの推定などをその場で始められる。

**仕様**:

1. パネル「ファイルマップ」(既定は下部、00 の 9 章のパネル)。上から順に、状態の行 (段階、進捗、キャンセル、「作り直す」、推定である旨)、帯 (構造と内容の 2 本のレーン)、オフセットの目盛り、凡例、領域の一覧 (共通の結果一覧)、選んだ領域の詳細 (根拠と操作のボタン) を置く。
2. 帯:
   - 横軸はオフセットで、左が先頭。右から左に書く言語でも反転しない (Hex 表示部分と同じ扱い。00 の 5.4)。
   - Ctrl + マウスホイール、ツールバーの拡大・縮小ボタン、キーボード (帯にフォーカスがあるときの `+` / `-`) で横に拡大・縮小する。最大の拡大は 1 ブロックが 8 ピクセル。
   - 標本による推定の部分は薄い色と点の模様で描き、走査が済んだ部分と区別する (凡例に「標本による推定」の項目を置く)。
   - Hex ビューの表示中の範囲を枠で、カーソルの位置を縦線で示す。
   - 1 ピクセルに複数の領域が入る場合は、内容のレーンはその中で最も長い種類で描き、構造のレーンはどれかの領域があれば描く。
3. 色と模様: 種類ごとの色は ThemeResource で定め、色に加えて種類ごとに違う模様 (斜線、点、横線、格子など) を付ける。ハイコントラストテーマではシステム色と模様だけで描く。凡例には、種類の名前と模様と、その種類のバイト数と割合を出す。
4. 帯の操作:
   - クリック: その位置へカーソルを移す (VIEW-34。ジャンプ履歴に記録)。
   - ダブルクリック: その位置の領域を選択範囲にする。
   - マウスを合わせる: ツールチップに種類、ラベル、範囲 (例: `0x50000〜0x5045F (1,120 バイト)`)、確度、根拠の最初の文を出す。
   - キーボード: 帯は Tab でフォーカスを受け取り、そのときはカーソル位置を含む内容のレーンの領域を選ぶ。← / → で前 / 次の領域へ帯の中の選択を移し、↑ / ↓ でレーンを切り替え、Enter で選んだ領域の先頭へ移動してその範囲を選ぶ。Shift+F10 またはアプリケーションキーで右クリックメニューを開く。
5. 領域の一覧: 列は開始オフセット、終了 (このバイトを含む)、長さ、種類、ラベル、確度、段階。並べ替え・絞り込み・CSV / JSON へのエクスポート・選んだ行のブックマークやマルチ選択への変換は、共通の結果一覧 (00 の 9 章) の機能を使う。一覧の行を選ぶと帯の選択も移り、帯で選ぶと一覧の行も移る。
6. 領域の右クリックメニュー (帯と一覧で同じ) と詳細のボタン。その種類の領域で使えるものだけを出す (使いやすさの原則 3)。

   | 項目 | 出す領域 | 動作 |
   | --- | --- | --- |
   | 範囲を選択 | すべて | 領域を選択範囲にする |
   | ブックマークに追加 | すべて | ラベルを名前、種類と根拠をコメントにしたブックマーク (05) を作る |
   | テンプレート "…" を適用 | 形式の構造と埋め込まれたファイルで、テンプレートが決まっているもの | 領域の開始オフセットで、そのテンプレートの固定の適用 (TPL-20) を、適用の設定画面を出さずに作る |
   | 新しいタブで開く | 埋め込まれたファイル、圧縮、テキスト、繰り返しのレコード | ENG-39 で範囲を新しいタブで開く (新しいタブでは TPL-30 の自動適用の判定が行われる) |
   | ここから展開... | 圧縮 (形式が分かっているもの) | 展開 (03 の EDIT-41) を、開始オフセットと形式を入れた状態で開く (展開した結果は派生ドキュメント (EDIT-46) として開ける) |
   | テンプレートを推定... | 繰り返しのレコード | テンプレートの推定 (07 の TPL-38) を、範囲とレコード長 (ずらし k) を入れた状態で開く |
   | 文字列を抽出... | テキスト | 文字列の抽出 (04) を、範囲を指定した状態で開く |
   | ファイルとして保存... | 埋め込まれたファイル | 範囲の切り出しと保存 (11 の TOOL-16) を、範囲と拡張子を入れた状態で開く |

7. 埋め込まれたファイルへのテンプレートの適用:
   - 「見つかったファイルにテンプレートを適用」は、テンプレートの決まっている埋め込まれたファイルに、一覧の順で固定の適用を作る。適用の数の上限 (TPL-20 の 3 の 32 個) に達したら止め、適用しなかった件数を InfoBar で知らせる。
   - 設定 `fileMap.applyTemplatesToEmbedded`: 「提案する」(既定)、「しない」。埋め込まれたファイルのテンプレートは提案するだけで、自動では適用しない (利用者の決定 2026-10-21)。「提案する」では、ファイルマップの構造の解析が終わったときに、テンプレートの決まった埋め込まれたファイルがあれば、InfoBar「埋め込まれたファイルが 3 個見つかりました。テンプレートを適用しますか?」と「適用」「一覧を表示」ボタンを出す。InfoBar は編集を妨げない。
8. ミニマップ: VIEW-35 の 6 の印に「ファイルマップ」を加える。ファイルマップの内容のレーンを、帯と同じ色と模様で、印の帯の左に幅 6 epx で描く。ファイルマップがあるときは、分類の印の代わりにこれを描く。クリックするとファイルマップのパネルを開き、その位置の領域を選ぶ。
9. エクスポート (「エクスポート...」): JSON・CSV・テキストのレポートに書き出す。
   - JSON: `document` (名前、パス、長さ、変換ビュー)、`createdUtc`、`complete` (すべての段階が済んだか)、`stages` (段階ごとの状態)、`regions` (配列)、`legend` (種類ごとのバイト数)。`regions` の各要素は `offset`、`length`、`kind` (`structure` / `embedded` / `compressed` / `encrypted` / `text` / `zero` / `constant` / `records` / `binary` / `unreadable`)、`lane` (`structure` / `content`)、`label`、`confidence` (`high` / `medium` / `low`)、`evidence`、`stage` (`sample` / `scan` / `structure`)、`template`、`parent` (入れ子の親の番号。なければ `null`)。
   - CSV: 1 行に 1 領域。列は `offset,length,kind,lane,label,confidence,stage,template,evidence`。文字コード・改行・引用は TPL-25 の 3 と同じ。
   - テキストのレポート: 先頭に推定である旨 (ANA-33 の 9)、ドキュメントの情報、種類ごとのバイト数と割合、領域の一覧 (1 行に 1 領域)。UTF-8 (BOM なし)。
   - `kind`・`confidence` などの語は表示言語によらない英語の語にする。`label` と `evidence` は表示言語で書く。
10. アクセシビリティ: 帯の各領域を UI オートメーションの要素にし (表示中の範囲の領域だけを作る)、名前に「種類、ラベル、開始オフセット、長さ、確度」を入れる。ナレーターは、帯の中で ← / → で移ったときに領域を読み上げる。帯には「表で表示」ボタン (0.4) を付け、押すと領域の一覧にフォーカスを移す。
11. 画面の文字列はすべてリソースにし、英語と日本語を書く (00 の 5.3)。形式名はシグネチャデータベース (ANA-17) とテンプレートの表示名 (TPL-17 の `name.<言語タグ>`) に従う。

**画面**: 1 のとおり。幅が 800 px 未満のときは、詳細を一覧の下に置く。

**巨大ファイル・長時間処理**: 帯は、表示中のピクセルの範囲に入る領域だけを区間の索引で探して描く。領域が 100 万個でも、拡大・縮小とスクロールは 60 fps を保つ。エクスポートは長時間処理として、ストリームで書き出す。

**エラー**:

- エクスポート先に書き込めない: InfoBar に理由を出し、書きかけのファイルを消す。
- 適用の数の上限: 6 と 7 のとおり InfoBar で知らせる。
- 適用したテンプレートのエラー: TPL-27 に従う (ファイルマップの内容は変えない)。

**受け入れ基準**:

- [ ] 帯をクリックするとその位置へカーソルが移り、Alt+← で元の位置に戻れる。ダブルクリックでその領域が選択範囲になる。
- [ ] キーボードだけで、帯の領域を順に選び、レーンを切り替え、領域へ移動し、右クリックメニューを開ける。

- [ ] 「見つかったファイルにテンプレートを適用」で、テンプレートの決まった埋め込まれたファイルに適用ができる。33 個以上ある場合は 32 個で止まり、適用しなかった件数が知らされる。

# メモリダンプ

他のツールで取ったメモリダンプを開き、物理アドレスや仮想アドレスで読みます。

## メモリダンプを開く {#open}

1. コマンドパレットで **ファイル: メモリダンプを開く** を実行します。**ファイル > 詳細を指定して開く...** で形式 **メモリダンプ** を選んでもかまいません。
2. ダンプのファイルを選びます。

HexEditor はファイルの先頭で形式を見分けます。

- **物理メモリのイメージ** (raw。WinPmem の `.raw`・`.mem`・`.bin` など): オフセットが物理アドレスです。
- **Windows のクラッシュダンプ** (`MEMORY.DMP`。完全メモリダンプ・カーネルメモリダンプ): ドキュメントは物理アドレス空間になります。ダンプに入っていないページは、未割り当てとして示します。
- **ミニダンプ** (HexEditor がプロセスから保存したミニダンプを含む): ドキュメントは同じアドレスのプロセスの仮想アドレス空間になり、**メモリマップ** のパネルに領域とモジュールの一覧が出ます。

見分けられないファイルは、物理メモリのイメージとして開きます。

メモリダンプは常に読み取り専用で開きます。開くと、ダンプの種類と取得日時が通知に出ます。タブのツールチップにも出ます。

開くときに読むのはヘッダと範囲の一覧だけなので、64 GB のダンプもすぐに開きます。

ダンプが壊れている場合や、HexEditor が読めない種類 (圧縮された休止状態のファイルなど) の場合は、raw として開くかを尋ねます。**raw として開く** を選ぶと、ファイルのバイトを見られます。

## 動いているメモリを読む {#live-memory}

HexEditor は、動いているコンピューターの物理メモリを読めません。Windows でこれを読むには署名されたカーネルドライバが必要で、HexEditor はドライバを入れないためです。他のツールでダンプを取り、そのダンプを HexEditor で開いてください。1 つのプロセスのメモリを読むには、**ファイル > プロセスを開く...** を使います。

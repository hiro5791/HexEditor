# コマンドライン (hexed)

このページでは、コマンドラインから HexEditor を使う方法を説明します。ファイルを指定して開く、ハッシュを計算する、2 つのファイルを比べる、スクリプトを画面なしで動かす、といったことができます。バッチファイルや PowerShell、ビルドの手順から呼び出すのに便利です。

## コマンドラインからファイルを開く {#open-from-the-command-line}

HexEditor には、実行ファイルが 2 つあります。

- `HexEditor.exe`: 画面のあるアプリ本体です。ファイルを開く用途の引数だけを受け付けます。
- `hexed.exe`: コンソール用の小さな実行ファイルです。すべてのコマンドを受け付けます。結果は画面 (標準出力) に出ます。

どちらでも、ファイルを開けます。

```text
hexed data.bin
hexed open data.bin --offset 0x1000
```

`hexed ファイル名` は、`hexed open ファイル名` と同じです。HexEditor がすでに起動しているときは、そのウィンドウにタブとして開きます。相対パスは、コマンドを実行したフォルダを基準に解決されます。

### hexed の呼びかた {#how-to-call-hexed}

版によって、`hexed` の呼びかたが違います。

| 版 | 呼びかた |
| --- | --- |
| Microsoft Store | どのフォルダからでも `hexed` で呼べます |
| インストーラ | インストール時に、ユーザーの PATH にアプリのフォルダが追加されます。`hexed` で呼べます。設定で外すこともできます |
| ポータブル | PATH は変わりません。展開したフォルダの `hexed.exe` をフルパスで呼ぶか、自分で PATH に追加します |

### 開くときのオプション {#open-options}

| オプション | 内容 |
| --- | --- |
| `--offset 位置`、`-g 位置` | カーソルをその位置に置く (例: `0x1000`、`end-16`) |
| `--select 範囲` | その範囲を選択する (`開始:長さ` または `開始..終了`) |
| `--readonly`、`-r` | 読み取り専用で開く |
| `--disk 番号またはパス` | 物理ディスクを開く (例: `--disk 0`、`--disk \\.\PhysicalDrive1`) |
| `--volume ドライブ` | ボリュームを開く (例: `--volume C:`) |
| `--process PID または名前` | プロセスのメモリを開く |
| `--encoding 文字コード` | テキスト列の文字コード |
| `--template 名前またはパス` | 開いたあとにテンプレートを適用する |
| `--compare パス1 パス2` | 2 つのファイルを比較の画面で開く |
| `--run スクリプト` | 開いたあとにスクリプトを実行する |
| `--new-window` | 新しいウィンドウで開く |
| `--new-document` | 空の新しいドキュメントを開く |
| `--open-disk` | 「ディスクを開く」のダイアログを出す |
| `--new-instance` | 起動中のものに渡さず、別のプロセスとして起動する |
| `--wait`、`-w` | 開いたドキュメントがすべて閉じられるまで、コマンドを終わらせない (`hexed` のみ) |
| `--safe-mode` | セーフモードで起動する ([セーフモード](plugins.md#safe-mode)) |
| `--write-block` | アプリ全体の書き込み保護を有効にして起動する |
| `--ui-lang 言語` | 表示言語を指定して起動する (例: `--ui-lang ja`) |

ディスクとプロセスは、コマンドラインからは読み取り専用で開きます。書き込みが必要なときは、開いたあとで書き込みを許可します。管理者の権限が必要なときは、通常と同じ手順で確認が出ます。[管理者の権限](opening-files.md#administrator)を参照してください。

`--wait` は、外部のツールから HexEditor を「編集用のエディタ」として呼ぶときに使えます。タブを閉じるまで、`hexed` は終わりません。

存在しないパスを指定すると、`hexed` は終了コード 3 で終わります。`--offset` の式が正しくないときは 2 です。

## hexed コマンド {#hexed}

`hexed` の書式は次のとおりです。

```text
hexed <コマンド> [引数] [オプション]
```

コマンドは次のとおりです。

| コマンド | 内容 |
| --- | --- |
| `open` | 画面のあるアプリで開く |
| `hash` | ハッシュとチェックサムの計算、検証 |
| `dump` | Hex ダンプの出力 |
| `compare` | 2 つのファイルの比較 |
| `run` | スクリプトを画面なしで実行 |
| `template` | 構造体テンプレートを適用して結果を出力 |
| `patch` | パッチの適用 |
| `convert` | 形式の変換 |
| `find` | 検索して一致の位置を出力 |

`open` 以外のコマンドは、画面を出さずに、そのコマンドの中だけで完結します。HexEditor が起動していなくても使えます。巨大なファイルでも、少しずつ処理するので、メモリは増え続けません。

### 共通のオプション {#common-options}

| オプション | 内容 |
| --- | --- |
| `--help`、`-h` | 使いかたを表示する (`hexed <コマンド> --help` で、そのコマンドの説明) |
| `--version` | バージョンを表示する |
| `--quiet`、`-q` | 結果だけを出す |
| `--format text` または `json` | 出力の形式 (既定は `text`) |
| `--output パス`、`-o パス` | 結果を画面の代わりにファイルへ出す |
| `--lang 言語` | メッセージの言語 (例: `ja`) |
| `--no-color` | 色を使わない |
| `--unregister` | この PC に登録したもの (右クリックメニュー、ファイルの関連付け、ジャンプリスト、PATH、一時フォルダ) を消す |

`patch` では、`-o` は出力するファイルを意味します。`--format` も、`patch` ではパッチの種類を意味します。

### 位置と範囲の書きかた {#expressions}

オフセット、長さ、範囲を取るオプションには、`0x1F00` のような 16 進、10 進、`end-16` のような式を書けます。接頭辞のない数は、10 進として扱われます。

範囲は、`開始:長さ` か `開始..終了` で書きます。`開始..終了` の終了は、範囲に含まれません。`end` は、ファイルの長さです。たとえば、末尾の 32 バイトは `end-32:32` です。

PowerShell では、`$` が変数として扱われます。`$` を含む値は、シングルクォートで囲んでください (例: `'$1F00'`)。

### 出力のしかた {#output}

- 結果 (ハッシュ値、ダンプ、JSON など) は標準出力に、UTF-8 で出ます。進捗、警告、エラーは標準エラー出力に出ます。そのため、`> out.txt` でリダイレクトしても、結果だけがファイルに入ります。
- メッセージは表示言語に合わせて訳されます。結果の書式と JSON のキーは訳されません。機械で読むためです。
- `--format json` の出力には、`"schema": "hexeditor.コマンド名/1"` が入ります。
- 端末で実行しているときは、長い処理の進捗が 1 行で出ます。
- <kbd>Ctrl</kbd>+<kbd>C</kbd> で中止できます。終了コード 6 で終わり、書きかけの出力ファイルは消えます。

## ハッシュと比較 {#hash-and-compare}

### ハッシュを計算する {#hash}

```text
hexed hash file.bin
hexed hash file.bin -a sha256,md5
hexed hash *.bin --format gnu
hexed hash image.iso --range 0:1048576
```

- `-a` または `--algorithm` で、アルゴリズムの ID をカンマで区切って指定します。既定は `sha256` です。`--algorithm list` で、使える ID の一覧が出ます。複数を指定しても、ファイルは 1 回しか読みません。
- パスには、`*.bin` のようなワイルドカードとフォルダを指定できます。フォルダの中まで含めるには `--recurse` (または `-r`) を付けます。`-` を指定すると、標準入力を読みます。
- `--range` で、ファイルの一部だけを対象にできます。
- `--format` で、出力の形を選べます。

| 形式 | 出力 |
| --- | --- |
| `text` (既定) | `アルゴリズム  値  パス` |
| `gnu` | `値  パス` (`sha256sum` と同じ。そのままチェックサムのファイルになります) |
| `bsd` | `SHA256 (パス) = 値` |
| `json` | ファイルごとのオブジェクトの配列 |

### チェックサムのファイルで検証する {#hash-check}

```text
hexed hash --check SHA256SUMS
```

チェックサムのファイル (`.sha256`、`.md5`、`SHA256SUMS`、`.sfv` など) を読み、各ファイルを調べて、`OK`、`FAILED`、`MISSING` を出します。形式は自動で見分けます。1 つでも合わないものがあると、終了コードは 1 です。

### 2 つのファイルを比べる {#compare}

```text
hexed compare a.bin b.bin
hexed compare a.bin b.bin --brief
hexed compare a.bin b.bin --mode resync --format json
```

- 既定 (`--mode byte`) は、同じ位置のバイトどうしを比べます。`--mode resync` は、途中の挿入や削除を考えて比べます。
- 差分は、範囲ごとに、種類 (変更、挿入、削除)、両方のオフセット、長さが出ます。短い差分 (16 バイト以下) は、両方の Hex の値も出ます。最後に、差分の件数と合計のバイト数が出ます。
- `--brief` は、一致か不一致かを 1 行で出し、最初の差分で止まります。巨大なファイルを素早く確かめたいときに使います。
- `--range1` と `--range2` で、それぞれのファイルの比べる範囲を指定できます。
- `--max` で出力する差分の数を制限できます (既定は 1,000)。超えた分は、数だけ数えます。

終了コードは、同じなら 0、違いがあれば 1 です。

## Hex ダンプ {#dump}

```text
hexed dump file.bin
hexed dump file.bin --range 0x100:0x80 --width 16
hexed dump file.bin --style xxd
hexed dump file.bin --range end-32:32
```

ファイル (または範囲) の Hex ダンプを出力します。巨大なファイルでも、メモリは一定です。

| オプション | 内容 |
| --- | --- |
| `--range 範囲` | 出力する範囲 (既定はファイル全体) |
| `--width n` | 1 行のバイト数 (既定 16) |
| `--group n` | グループのバイト数 (0 でグループなし) |
| `--encoding 文字コード` | テキスト列の文字コード (既定は ASCII) |
| `--base-address 式` | 最初のバイトに付けるアドレス (既定 0) |
| `--style 形式` | 出力の形式 |
| `--squeeze` | 前の行と同じ内容の行を `*` 1 行にまとめる |

`--style` には、`default`、`xxd` (xxd と互換)、`hexdump-c` (`hexdump -C` と互換)、`plain` (Hex だけ)、`base64`、そして `c`、`csharp`、`python` などのソースコードの形式を指定できます。範囲がファイルの外にあるときは、終了コード 2 になります。

## テンプレートと JSON の出力 {#templates-and-json}

```text
hexed template image.png --template png --format json
hexed template unknown.bin --auto
hexed template app.exe --template pe --fields header.e_lfanew,sections[*].name
```

ファイルに[構造体テンプレート](templates.md)を適用して、結果を出力します。

- `--template 名前またはパス` で、使うテンプレートを指定します。`--auto` は、アプリでファイルを開いたときの[自動適用](templates.md#auto-apply)と同じ判定で、テンプレートを選びます。合うものがなければ、終了コード 1 です。
- `--offset 式` (または `-g`) で、構造体を読み始める位置を指定します (既定は 0)。
- `--format` は、`json`、`csv`、`text` から選びます (既定は `text`。インデント付きのツリーです)。`json` の構造は、画面の[結果のエクスポート](templates.md#export-results)と同じです。
- `--fields パス,...` で、出力するフィールドを絞れます。
- `--depth n` で、出力するツリーの深さを制限できます。

テンプレートにエラーがあるときは、行と列つきのメッセージが出て、終了コードは 4 です。

## 変換と検索 {#convert-and-search}

### 形式を変換する {#convert}

```text
hexed convert firmware.hex firmware.bin
hexed convert firmware.bin firmware.hex --to ihex --record-length 32
```

インポート・エクスポートの形式を変換します。入力と出力の形式は、拡張子と中身から自動で判定されます。`--from` と `--to` で指定することもできます。

- 形式は、`bin`、`ihex`、`srec`、`base64`、`base32`、`ascii85`、`uu`、`qp`、`url`、`hextext`、`dectext`、`c`、`cpp`、`csharp`、`java`、`js`、`python`、`rust`、`go`、`pascal`、`vbnet` などです。
- Intel HEX と S-record のチェックサムが合わないと、終了コード 8 で終わります。`--ignore-checksum` を付けると、無視して読みます。
- `--fill 値` で、すき間を埋めるバイトを指定します (既定 `FF`)。`--address-mode` で、アドレスの方式を指定します。
- 形式ごとのオプションは、[インポートとエクスポート](import-export.md)の画面の項目と同じ名前を、小文字とハイフンで書きます (例: `--record-length 32`、`--bytes-per-line 16`)。

### 検索する {#find}

```text
hexed find a.bin --hex "DE AD ?? EF"
hexed find *.log --text error --case-sensitive
hexed find data.bin --regex "ID[0-9]+" --format json
```

ファイルを検索して、一致ごとに `パス  オフセット  長さ` を出力します。

- `--hex` はバイト列です。`??` は任意の 1 バイトです。
- `--text` は文字列、`--regex` は正規表現です。`--encoding` で文字コードを指定します (既定は UTF-8)。
- `--case-sensitive` で、大文字と小文字を区別します。
- `--range` で範囲を絞り、`--max` で見つける数を制限します。フォルダを指定したときは、`--recurse` で中まで探します。

一致があれば終了コード 0、なければ 1 です。

### パッチを適用する {#patch}

```text
hexed patch app.bin fix.ips -o app-fixed.bin
hexed patch app.bin fix.ips --in-place --verify-before sha256:ab12...
```

パッチのファイルをファイルに適用します。この版で適用できるのは、IPS と IPS32 です。

- 出力先は、`-o パス` (元のファイルは変えない) か `--in-place` (元のファイルを書き換える) のどちらかを必ず指定します。どちらもないと、終了コード 2 です。
- `--in-place` は、アプリでの保存と同じように、一時ファイルに書いてから置き換えます。
- `--verify-before アルゴリズム:値` で、適用の前に対象のハッシュを確かめます。違うときは、何も書かずに終了コード 1 で終わります。`--verify-after` は、適用後のハッシュを確かめます。
- `--dry-run` は、何も適用せずに、パッチのレコード数と変更されるバイト数を出力します。

壊れたパッチは、終了コード 8 です。

## スクリプトの実行 {#run-scripts}

```text
hexed run xor.js a.bin --arg key=5A --save
hexed run check.js a.bin b.bin --dry-run
```

[スクリプト](scripting.md)を、画面を出さずに実行します。ファイルを指定すると、開いた状態でスクリプトが始まります。最初のファイルが、アクティブなドキュメントです。

| オプション | 内容 |
| --- | --- |
| `--arg 名前=値` | パラメータの値を渡す (繰り返せます)。スクリプトの `script.args` に入ります |
| `--trust` | 信頼していないスクリプトを、確認なしで実行する |
| `--allow 許可,...` | 与える許可 (例: `file-read`) |
| `--save` | 終了時に、変更のあるドキュメントをすべて保存する |
| `--save-as パス` | 最初のドキュメントを、そのパスに保存する (元のファイルは変えない) |
| `--dry-run` | 何も保存しない。変更の要約だけを出す |
| `--timeout 秒` | スクリプト全体の実行時間の上限 |
| `--readonly`、`-r` | ファイルを読み取り専用で開く |

保存の既定は、スクリプトが `doc.save()` を呼んだドキュメントだけを保存する、というものです。終了時に保存されていない変更があると、警告が出ます。

画面がないため、信頼の確認のダイアログは出せません。次のどちらかのときだけ、スクリプトが実行されます。

- アプリの画面で、そのスクリプトに **常に許可する** を選んだことがある。
- `--trust` と、必要な `--allow` をコマンドで指定した。

どちらもないと、終了コード 5 で終わります。

`console.log` は標準出力に、`console.warn`、`console.error`、`ui.message` は標準エラー出力に出ます。

スクリプトの終了コードは、スクリプトの中で `app.exit(コード)` を呼んで決められます (0〜255)。2〜10 は、このページの終了コードの意味と重なります。独自の意味には、64 以上を使ってください。

C# のスクリプトを実行するには、[C# スクリプト コンポーネント](scripting.md#csharp-component)が必要です。ない場合は、終了コード 3 になります。

## 終了コード {#exit-codes}

すべてのコマンドで、終了コードの意味は共通です。

| コード | 意味 |
| --- | --- |
| 0 | 成功 (`compare`: 一致、`find`: 見つかった、`hash --check`: すべて一致) |
| 1 | 処理は成功したが、結果は「否」 (`compare`: 違いがある、`find`: 見つからない、`hash --check`: 合わないものがある、`patch`: 確認に失敗、`template --auto`: 合うものがない) |
| 2 | 引数の誤り (知らないオプション、式の誤りなど) |
| 3 | 入出力のエラー (ファイルがない、読めない、書けない、空き容量が足りない) |
| 4 | スクリプトやテンプレートのエラー (構文エラー、実行時の例外) |
| 5 | 許可がない (信頼されていないスクリプト、アクセス拒否、管理者の権限が必要) |
| 6 | 中止された (<kbd>Ctrl</kbd>+<kbd>C</kbd>) |
| 7 | 上限を超えた (スクリプトの実行時間やメモリ、`--timeout`) |
| 8 | 形式のエラー (Intel HEX のチェックサムの誤り、壊れたパッチなど) |
| 10 | 内部エラー (想定外の問題。詳細は、メッセージに出るログのファイルにあります) |

バッチファイルなら `%ERRORLEVEL%`、PowerShell なら `$LASTEXITCODE` で、終了コードを調べられます。

```text
hexed compare a.bin b.bin --brief
if %ERRORLEVEL% == 0 echo same
```

# ファイルシステム

NTFS・FAT12・FAT16・FAT32・exFAT・ext2/3/4・HFS+・APFS・ISO 9660・UDF のボリュームのファイルを、Windows にマウントさせずに見る方法を説明します。削除されたファイルの探し方、クラスタを使っているファイルの調べ方、ファイル・空き領域・スラックの書き出し方も説明します。

ファイルシステムは読むだけです。ファイルの作成・削除・名前の変更・削除の取り消しはしません。

## ファイルシステムのブラウザを開く {#browser}

1. ボリューム、パーティションのタブ、またはボリュームのイメージを開きます。ディスクの場合は、先にパーティションの中にカーソルを置くか、**パーティション** パネルの **ファイルシステムを表示** を使います。
2. **フォレンジック > ファイルシステム > ブラウザを表示** を選びます。

先頭のセクタから種類を判定します。判定できないときは種類を尋ねます。暗号化された (BitLocker の) ボリュームは開きません。

**ファイルシステム** パネルには次のものがあります。

- 種類、ボリューム名、シリアル番号、クラスタサイズと、警告 (予備のブートセクタが一致しないなど)
- フォルダのツリー: ルートと、**$メタデータ**、**削除されたファイル**、**孤立したファイル**、**未割り当て領域**、**ボリュームスラック** のフォルダ
- ファイル一覧と、絞り込みの欄 (名前の一部、またはワイルドカード `*` と `?`)、ボリューム全体を探す **ファイルを検索** の欄
- 選んだ項目の詳細と、その断片

フォルダは開いたときに読み、一覧は読みながら増えていくので、100 万個のファイルがあるフォルダでもウィンドウは止まりません。**列** で列の表示・非表示を切り替えます。日時は UTC で出ます。FAT の日時はタイムゾーンを持たないため、`~` を付けて出します。

ファイルを選んでいないときは、概要 (種類、ボリューム名、シリアル番号、クラスタサイズ、総クラスタ数、空きクラスタ数、ブートセクタのすべての項目) が出ます。

## ファイルを操作する {#file-actions}

- ファイルをダブルクリックするか Enter キーを押すと、先頭のバイトへ移動し、すべての断片を選択します。
- ファイルを右クリックすると、次の操作ができます。
  - **ファイルを別タブで開く**: ファイルの内容 (断片をつなぎ、スパースの部分は 0、NTFS の圧縮は展開したもの) を読み取り専用のタブで開きます。そのタブのステータスバーに、カーソル位置のディスク上のオフセットが出ます。
  - **ファイルを書き出す**: 選んだファイルとフォルダを、選んだフォルダに書き出します。[ファイルを書き出す](#export) を参照してください。
  - **メタデータの位置へ移動**: MFT レコードやディレクトリエントリへ移動します。
  - **ファイルのクラスタを表示**: すべての断片を強調します。[クラスタ](#clusters) を参照してください。
  - **MFT レコードを表示**・**INDX を表示**・**$LogFile を表示** (NTFS)、**ディレクトリエントリを表示**・**クラスタチェーンを表示** (FAT・exFAT): 構造をテンプレートや **フォレンジックの結果一覧** パネルで表示します。
  - **パスをコピー**、**一覧を CSV / JSON にエクスポート**

NTFS の代替データストリームは `file.txt:ストリーム名` として出ます。`Zone.Identifier` のような小さいストリームは、詳細に内容がテキストで出ます。設定でストリームを隠せます。

メタデータが壊れた項目 (フィックスアップが合わない MFT レコード、循環する FAT のチェーンなど) には破損の印が付き、詳細に理由が出ます。ボリュームのほかの部分は読み続けます。

NTFS で $STANDARD_INFORMATION の日時が $FILE_NAME の日時より前のファイルには **日時の不一致** の印が付きます。日時が書き換えられた手がかりになります。

FAT32 で 2 つの FAT が食い違っているときは、違いのあるエントリの数が出て、使う FAT を選べます。

## 削除されたファイル {#deleted}

**削除されたファイル** のフォルダを開くか、**フォレンジック > ファイルシステム > 削除されたファイルを探す** を選びます。すべての MFT レコード、インデックススラック、ディレクトリエントリを読み、見つかった順に一覧に加えます。

**復元の見込み** の列に、内容を取り戻せる見込みが出ます。

- **良好**: クラスタがすべて空きのままです。
- **一部上書き**: クラスタの一部を、今は他のファイルが使っています。
- **上書き済み**: クラスタのすべてを、今は他のファイルが使っています。
- **位置不明**: データの位置が分かりません。
- **常駐**: データが MFT レコードの中にあります。

FAT と exFAT では、削除されたファイルのクラスタのチェーンが消えているため、先頭のクラスタから連続したクラスタとして読みます。詳細にそのことが出ます。削除されたファイルも、ほかのファイルと同じように開いたり書き出したりできます。上書き済みのファイルを書き出す前に、内容が他のファイルのものである可能性を知らせます。

## ファイルを書き出す {#export}

1. ファイルやフォルダを選びます (複数可)。
2. 右クリックして **ファイルを書き出す** を選びます。
3. オプション (ディレクトリ構造を保つ、代替データストリーム、スラック、削除されたファイル) と書き出し先のフォルダを選びます。

ファイルごとの元のパス、ファイル ID、サイズ、日時 (UTC)、MD5、SHA-256、書き出し先、復元の見込みを `export-manifest.csv` に書きます。書き出したファイルの日時は元の日時に合わせません。書き出し先の空き容量が足りないときは何も書きません。読めなかった部分は 0 で埋め、マニフェストに範囲を書きます。

## クラスタ {#clusters}

- ステータスバーに、LBA、クラスタ番号、クラスタ内の位置、そのクラスタの持ち主が出ます。ステータスバーの **調べる** を選ぶと、クラスタの逆引き表を作ります。表は保存され、同じボリュームを次に開いたときにも使います。
- **フォレンジック > ファイルシステム > クラスタへ移動** でクラスタへ移動します。FAT のクラスタは 2 から始まります。この欄では `cluster` が現在のクラスタ番号を表すので、`cluster+1` は次のクラスタです。
- **この位置を使っているファイル**: カーソル位置や選択範囲のクラスタを使っているファイル (削除されたファイルを含む) を一覧にします。
- **ファイルのクラスタを表示**: 選んだファイルのすべての断片を強調し、**断片一覧** パネルに出します。行を選ぶとその断片へ移動します。**移動 > 次の断片**・**移動 > 前の断片** で断片の間を移動します。

## 空き領域とスラック {#slack}

**表示 > フォレンジックの強調** を選ぶと、メタデータ、未割り当てのクラスタ、RAM スラック (ファイルの末尾からそのセクタの終わりまで)、ドライブスラック (クラスタの終わりまで)、ボリュームスラック、パーティションの隙間に印を付けます。種類ごとに模様と行の先頭の文字が違うので、色がなくても区別できます。Hex ビューの右上に凡例が出ます。初めてのときは、スラックを出す前に、すべてのファイルの末尾のクラスタを調べます。

- **未割り当て領域を書き出す** はすべての空きクラスタを 1 つのファイルにつなぎ、**スラックを書き出す** はすべてのファイルのスラックをつなぎます。どちらも、各部分のディスク上のオフセットを示す対応表 (`.map.csv`) を作れます。
- **未割り当て領域を別タブで開く** は、空きクラスタを 1 つのドキュメントとして表示します。ステータスバーに、カーソル位置のディスク上のオフセットが出ます。
- **未割り当て領域を選択**・**スラックを選択** でこれらの範囲を選択すると、検索バーの **選択範囲** で、その範囲だけを検索できます。

## ext2・ext3・ext4 {#ext}

ext2・ext3・ext4 のボリュームを読みます。スーパーブロック、グループ記述子 (`64bit` 機能の 64 バイトのものと `flex_bg` を含む)、inode、エクステントツリー、直接・間接ブロック、インラインデータ、htree のディレクトリに対応します。概要には、`compat`・`incompat`・`ro_compat` の機能を含むスーパーブロックの項目が出ます。`metadata_csum` があるときは、スーパーブロック・グループ記述子・inode のチェックサムを確かめ、合わないものを警告やファイルの破損の印で示します。

- ファイルを右クリックして **inode を表示** を選ぶと、inode を構造体テンプレートで色分けし、その位置へ移動します。番号で移動するには、**フォレンジック > ファイルシステム > inode へ移動** を選んで番号を入力します。
- **削除されたファイル** には、ディレクトリエントリの使われていない部分 (`rec_len` の余り) に残った名前と、削除日時のある inode が出ます。ext3 と ext4 は削除のときにブロックの位置を消すことが多く、そのファイルには **位置不明** の印が付きます。
- ジャーナル (**$メタデータ** の `$Journal`) は一覧にするだけです。右クリックして **ジャーナルを表示** を選ぶと、記述子・コミット・取り消しのブロックが出ます。ジャーナルを再生することはありません。
- fscrypt で暗号化されたファイルには暗号化の印が付き、名前と内容は記録されたまま出ます。
- 空き領域はブロックビットマップで判定します。ext・HFS+・APFS はブロックで数えるため、**クラスタへ移動** は **ブロックへ移動** と出ます。

## HFS+ と APFS {#apple}

**HFS+・HFSX**: 概要にボリュームヘッダーと、ボリュームの末尾の予備のボリュームヘッダーが一致するかが出ます。ファイルとフォルダはカタログ B 木から、9 個目以降の断片はエクステントオーバーフロー B 木から読みます。リソースフォークは `名前/..namedfork/rsrc` として出て、ほかのファイルと同じように開けます。ハードリンクは `iNode` のファイルをたどって読みます。圧縮されたファイル (decmpfs) には圧縮の印が付き、展開せずに出ます。ジャーナルは表示するだけで、再生しません。空き領域は割り当てファイルで判定します。

**APFS**: コンテナのチェックポイントのうち、チェックサムが正しい最新のものを使います。最新のものが壊れているときは、古いものを使っていることを警告で知らせます。ボリュームはツリーの最上位のフォルダです。ボリュームには名前、役割、暗号化されているかが出ます。スナップショットはボリュームの **$Snapshots** フォルダに一覧で出ますが、中身は見られません。暗号化されたボリューム (FileVault を含む) は検出するだけで、暗号化の印が付き、ファイル一覧は出ません。空き領域は空き領域マネージャで判定し、読めないときは空き領域の強調を使えません。

HFS+ と APFS では削除されたファイルは探しません。

## ISO 9660 と UDF {#optical}

ディスクのイメージは 2,048 バイトのセクタのものを読みます (2,352 バイトの生のセクタのイメージには対応していません)。

**ISO 9660**: Joliet の名前があればその名前を、なければ Rock Ridge の名前を、どちらもなければ ISO 9660 の基本の名前を出します。ファイル一覧の上の **名前の種類** で切り替えられます。Rock Ridge の名前のときは、**属性** の列に POSIX のモードが出ます。起動できるディスクでは、El Torito のブートカタログのエントリ (プラットフォーム、エミュレーションの種類、開始セクタ、セクタ数) が概要に、ブートイメージが **$メタデータ** に `$BootImage1` などとして出ます。ファイルと同じように書き出せます。複数セッションのディスクでは最後のセッションを出します。**セッション** でほかのセッションを選べます。

**UDF**: 1.02〜2.60 を読みます。UDF 2.50 以降のメタデータパーティションにも対応します。概要に UDF の版が出ます。タグのチェックサムや CRC が合わない記述子は警告にして、読み続けます。仮想パーティション (VAT) とスペアリングテーブルには対応していません。UDF と ISO 9660 の両方があるディスクでは UDF を出し、**形式** で切り替えられます。未割り当て領域のビットマップがあれば、空き領域をそれで判定します。ISO 9660 と UDF では削除されたファイルは探しません。

# パッチ

パッチは、2 つの版のデータの違いを記録したものです。自分の変更からパッチを作り、元のファイルに当てられます (HexEditor でも、ほかのツールでも)。このページでは、パッチを作る、当てる、配る方法を説明します。

## パッチを作る {#create}

1. **データ > パッチ > パッチを作成...** を選びます。
2. **差分の取り方** で、何と何を比べるかを選びます。
3. **形式** で、パッチの形式を選びます。
4. **出力ファイル** を選びます。
5. レコード数と推定サイズを確かめて、**作成** を選びます。

| 差分の取り方 | 意味 |
| --- | --- |
| **保存されている内容と現在の内容** | 保存していない変更です。既定です。変更した場所だけを見るので、すぐに終わります |
| **2 つのファイル (タブ)** | 別に開いているタブ (変換前) からこのタブへ |
| **履歴の 2 時点** | 元に戻すの履歴のある時点から別の時点へ |

履歴パネル (**この 2 時点からパッチを作成...**) と、比較 (比較のツールバーの **比較からパッチを作成...**) からも作れます。

| 形式 | 説明 |
| --- | --- |
| **自動 (IPS または IPS32)** | 使えれば IPS、16 MiB 以上の位置の変更があれば IPS32 を使います |
| **IPS** | 多くのツールが対応しています。変更は 16 MiB 未満の位置に限ります。挿入・削除は、それより後ろのすべてのバイトの変更として書きます |
| **IPS32** | IPS と同じで、4 GiB 未満の位置まで使えます |
| **UPS** | 大きさの上限はありません。変換前と変換後の CRC-32 を記録し、逆向きにも当てられます |
| **BPS** | 大きさの上限はありません。CRC-32 を記録し、挿入・削除を効率よく表します |
| **独自形式 (.hexpatch)** | 大きさの上限はありません。挿入・削除と、変換前のファイルの識別情報を記録し、逆向きにも当てられます |
| **自己適用型 (EXE)** | パッチを自分で当てるプログラムです (下記) |

変更を表せない形式は選べず、理由が出ます。挿入・削除があって、その形式では効率よく表せない場合は、BPS か独自形式を勧める警告が出ます。

UPS と BPS は、CRC-32 のために変換前と変換後のデータ全体を読むため、大きなファイルでは時間がかかります。パッチの作成は、進捗を示しながらバックグラウンドで行います。

## パッチを当てる {#apply}

1. **データ > パッチ > パッチを適用...** を選んで、パッチのファイルを選びます。形式はファイルから判別します。
2. 形式、レコード数、変更するバイト数、適用後の長さを確かめます。
3. **変換前の確認** を確かめます。
   - **一致**: このデータ用に作られたパッチです。
   - **不一致**: 別のファイル用のパッチの可能性があります。ボタンは **適用する** になり、既定のボタンは **キャンセル** です。
   - **確認できません**: IPS と IPS32 のパッチは、変換前の内容を記録していません。
4. **適用** を選びます。

パッチは 1 回の編集として当たるので、<kbd>Ctrl</kbd>+<kbd>Z</kbd> 1 回で元に戻せます。保存するまで、ファイルには書きません。UPS と BPS の確認は、ドキュメント全体を読みます。大きなファイルでは **確認を省略して適用** を選べます。UPS・BPS・独自形式のパッチを当てたあとは、結果をパッチと照らし合わせ、一致しなければ適用を取り消します。

すでにファイルに当てたパッチを戻すには、**逆適用** をオンにします。UPS と独自形式で使えます。

長さが変わるパッチは、ディスクのように長さが決まっているデータには当てられません。

[変換ビュー](transform-view.md) が有効なときも、パッチの確認と適用は、表示されているデータではなく元のデータに対して行います。長さが変わるパッチは、変換ビューを解除するまで当てられません。

## 自己適用型パッチ {#self-applying}

自己適用型パッチは、パッチを中に持った小さなプログラムです。HexEditor を持っていない人でも、実行するだけで自分のファイルにパッチを当てられます。

1. パッチを作るときに、形式 **自己適用型 (EXE)** を選びます。
2. 必要なら **既定の対象ファイル名** と **表示するメッセージ** を入れます。
3. **適用プログラム** で、実行する PC に合わせて **x64** か **ARM64** を選びます。
4. ファイルを作ります。

このプログラムにはコード署名がないため、実行すると Windows の SmartScreen の警告が出ます。実行すると、次の順に進みます。

1. メッセージを出して、パッチを当てるファイルを選ばせます。
2. そのファイルがパッチを作った元のファイルかを確かめ、違えば警告します。
3. バックアップ (`名前.bak`) を作るかを尋ねます。既定は作ります。
4. 結果を一時ファイルに書き、確かめてから、ファイルを置き換えます。途中で失敗しても、ファイルは変わりません。
5. 結果を表示します。

プログラムの表示は、訳があれば Windows の表示言語で、なければ英語です。

# スクリプト

このページでは、JavaScript と C# のスクリプトで HexEditor を自動化する方法を説明します。スクリプトを使うと、同じ編集の繰り返し、ファイルの一括処理、独自の解析を、ボタン 1 つで実行できます。

操作を記録して再生するだけなら、スクリプトを書かなくても [マクロ](macros.md)で足ります。

## JavaScript と C# {#languages}

スクリプトは 2 種類の言語で書けます。ファイルの拡張子で言語が決まります。

| 言語 | 拡張子 | 特徴 |
| --- | --- | --- |
| JavaScript | `.js`、`.mjs` | そのまま使えます。許可された機能だけを使える安全な環境で動き、実行時間とメモリに上限があります。 |
| C# | `.csx` | 最初に C# スクリプト コンポーネントの追加が必要です。速く動きますが、PC 上で何でもできるコードです。 |

どちらの言語でも、使える機能 (API) は同じです。名前の付け方だけが違います。JavaScript は `doc.readBytes`、C# は `Doc.ReadBytes` のようになります。

最初は JavaScript をおすすめします。C# は、速度が必要なとき、または .NET のライブラリを使いたいときに選んでください。

## スクリプトを実行する {#run-a-script}

### サンプルから始める {#samples}

**ツール > スクリプト > サンプル** から、付属のサンプルを選べます。XOR デコード、PE ヘッダの要約、フォルダのハッシュ一覧、高エントロピー領域の一覧などがあります。サンプルは、コピーを編集用に開いて、自由に書き換えられます。

### ファイルを選んで実行する {#run-a-file}

1. 対象のドキュメントをアクティブにします。
2. **ツール > スクリプト > スクリプトを実行** を選び、スクリプトのファイルを選びます。

一度実行したあとは、<kbd>F5</kbd> (または **ツール > スクリプト > 直前のスクリプトを再実行**) で、同じスクリプトをもう一度実行できます。スクリプトエディタにフォーカスがあるときは、<kbd>F5</kbd> でそのエディタのスクリプトを実行します。

スクリプト一覧からも実行できます。[スクリプト一覧](#script-list)を参照してください。

### パラメータ {#parameters}

スクリプトがパラメータを宣言しているときは、実行の前に入力ダイアログが出ます。前回入力した値が、次の既定値になります。

### 実行中の動き {#while-running}

- スクリプトは専用のスレッドで動きます。画面は固まらず、ほかのドキュメントは編集できます。
- スクリプトが書き込んでいるドキュメントは、実行が終わるまで編集できません。上に「スクリプト「名前」を実行中です」と出て、**停止** のボタンがあります。
- 進捗と経過時間は、処理センターに出ます。
- 同時に実行できるスクリプトは、既定で 4 本までです。多い分は待ちます。**設定 > 自動化** の **同時に実行できるスクリプトの数** で変えられます。
- スクリプトによる編集は、1 回の実行で 1 つの [元に戻す](editing.md#undo-redo)の単位になります。<kbd>Ctrl</kbd>+<kbd>Z</kbd> を 1 回押すと、スクリプトの変更がまとめて戻ります。エラーで終わったスクリプトも、それまでの変更は残り、同じように取り消せます。

### 止める {#stop}

処理センターの **停止**、またはドキュメント上部の **停止** のボタンで止めます。**ツール > スクリプト > すべてのスクリプトを停止** で、実行中のスクリプトをすべて止められます。JavaScript は、止めてから 3 秒たっても終わらないと、強制的に中断されます。

C# のスクリプトは強制的には中断できません。スクリプトが停止の合図を確かめない繰り返しに入ると、止まらなくなることがあります。そのときは、HexEditor を再起動してください。未保存の編集は、復旧用のデータに書き出されます。

### 上限 {#limits}

JavaScript には、暴走したスクリプトがアプリを巻き込まないように、次の上限があります。

| 上限 | 既定値 | 変えられる範囲 |
| --- | --- | --- |
| 実行時間 | 60 秒 | 1 秒〜無制限 (0) |
| メモリ | 512 MB | 16 MB〜4 GB |
| 再帰の深さ | 1,000 | 100〜10,000 |

実行時間には、一括処理の完了待ちと、利用者の入力待ちは数えません。上限に達すると、スクリプトは一時停止して **続ける (さらに 60 秒)** と **停止** が出ます。上限は **設定 > 自動化** で変えられます。

## スクリプトエディタ {#script-editor}

スクリプトを書くには、スクリプトエディタを使います。ドキュメントと同じ並びのタブで開きます。

- 新しく作る: **ツール > スクリプト > 新しいスクリプト** (JavaScript) または **新しい C# スクリプト**。
- 既存のものを直す: [スクリプト一覧](#script-list)で **編集** を選びます。

### エディタの機能 {#editor-features}

- 構文の色分け。テーマに合わせた色になります。
- 補完。`doc.` のように入力すると、使えるメソッドが説明つきで出ます。C# の補完を使うには、C# スクリプト コンポーネントが必要です。
- エラーの表示。入力が止まると構文を調べ、エラーに波線を引きます。下の **問題** にも一覧が出て、選ぶとその行へ移動します。
- 行へ移動 (<kbd>Ctrl</kbd>+<kbd>G</kbd>)。
- 折りたたみ、括弧の対応の表示、コメントの切り替え (<kbd>Ctrl</kbd>+<kbd>/</kbd>)、書式の整形 (<kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>F</kbd>)、検索と置換。
- 保存は <kbd>Ctrl</kbd>+<kbd>S</kbd>。

WebView2 ランタイムが入っていない PC では、色分けや補完のない基本のエディタで開き、上のバーで知らせます。スクリプトの編集と実行はできます。

ツールバーには、**実行**、**デバッグ実行**、**停止**、**一時停止** と、**対象のドキュメント** の選択があります。**対象のドキュメント** で、スクリプトが操作するドキュメントを選べます。未保存の内容でも、<kbd>F5</kbd> でエディタの内容のまま実行されます。

スクリプトのファイルが 10 MB を超えるときは、エディタで開けません。外部のエディタで編集してください。

### スクリプト一覧 {#script-list}

**ツール > スクリプト > スクリプト一覧** (または **表示 > パネルの表示切り替え > スクリプト一覧**) で、スクリプトの一覧パネルが開きます。

一覧には、**スクリプト**、**マクロ**、**サンプル** が出ます。追加したフォルダの中身も出ます。上の欄で絞り込めます。

| 操作 | 内容 |
| --- | --- |
| **実行** | <kbd>Enter</kbd> かダブルクリックでも実行できます |
| **編集** | スクリプトエディタで開きます。サンプルは **コピーを編集用に開く** になります |
| **新規作成** | JavaScript か C# の新しいスクリプトを作ります |
| **名前の変更**、**削除 (ごみ箱へ移動)**、**フォルダで表示** | ファイルの管理 |
| **ショートカットの割り当て** | スクリプトにキーを割り当てます |
| **自動実行の設定** | [イベントで実行する](#event-scripts)スクリプトに登録します |

スクリプトは、コマンドパレットにも **スクリプト: 名前** で出ます。ショートカットを割り当てれば、キーで実行できます。

スクリプトのフォルダを足すには、**設定 > 自動化** の **スクリプトを追加するフォルダ** を使います。チームで共有するフォルダを足すと便利です。フォルダを開くには、**ツール > スクリプト > スクリプトのフォルダを開く** を使います。フォルダにファイルを置くと、一覧は自動で更新されます。

### メタデータ {#metadata}

スクリプトの先頭にコメントで書くと、名前、説明、パラメータなどを宣言できます。

```javascript
// ==HexEditorScript==
// @name         XOR decode
// @name:ja      XOR デコード
// @description  Selection XOR with a key
// @param        key hex "5A" Key
// @param        whole checkbox false Whole file
// @permission   file-read
// ==/HexEditorScript==
```

- `@name` と `@description`: 一覧に出る名前と説明。`@name:ja` のように言語を付けると、表示言語に合わせて選ばれます。
- `@param 名前 型 既定値 ラベル`: パラメータ。宣言すると、実行時に入力ダイアログが自動で出ます。値は `script.args` に入ります。
- `@permission`: 必要な許可。[信頼と許可](#permissions)を参照してください。
- `@on`: 自動実行の候補。登録は利用者が自分で行います。

メタデータのないスクリプトも実行できます。

### 出力パネル {#output-panel}

`console.log` などの出力と、エラーは、**出力** パネルに出ます。**表示 > パネルの表示切り替え > 出力** で開きます。スクリプトが出力したときに自動で開く設定もあります (**設定 > 自動化**)。

- 上の **出力元** で、スクリプトやプラグインごとに切り替えます。
- 各行に、時刻、種類 (情報・警告・エラー)、本文が出ます。警告とエラーは、色に加えてアイコンでも区別されます。
- エラーの行番号を選ぶと、スクリプトエディタのその行が開きます。
- **クリア**、**すべてコピー**、**ファイルに保存**、**行の折り返し**、絞り込みが使えます。

## スクリプトの API {#script-api}

スクリプトからは、次のようなオブジェクトを使います。

| オブジェクト | できること |
| --- | --- |
| `app` | 開いているドキュメントの一覧、ファイルを開く、アプリのコマンドの実行、イベントの受信 |
| `doc` | アクティブなドキュメント。読み書き、検索、保存、カーソルと選択範囲、ブックマーク、元に戻す |
| `ui` | メッセージ、入力ダイアログ、進捗の表示、出力 |
| `hash` | ハッシュの計算 |
| `clipboard` | クリップボードの読み書き |
| `app.templates` | テンプレートの適用と結果の取得 |
| `settings`、`script` | 設定の読み書き、スクリプト専用の保存領域、パラメータ (`script.args`) |
| `fs`、`net`、`process` | ファイル、ネットワーク、外部プログラム (許可が必要) |

すべてのオブジェクトとメソッドは、[自動化 API リファレンス](api-reference.md)にあります。**ヘルプ > スクリプトの API リファレンス** でも開けます。

簡単な例です。選択範囲の先頭 16 バイトを、出力パネルに出します。

```javascript
const doc = app.activeDocument;
const bytes = doc.readBytes(doc.selection.start, 16);
console.log(bytes);
```

### 大きなデータを扱うコツ {#bulk}

1 バイトずつの繰り返しは、巨大なファイルでは遅くなります。範囲の XOR、検索、ハッシュ、コピーのように、データ量に比例する処理は、API の一括処理を使ってください。一括処理は、ファイルの大きさに関係なく少しずつ処理し、進捗とキャンセルに対応します。

- 少量の読み書き (1 回 16 MB 以下) は、すぐに結果が返ります。
- 時間のかかる処理は `await` で待ちます。例: `await doc.transform(range, "xor", key)`。
- 16 MB を超える範囲を一度に読むことはできません。分けて読みます。

### アプリのコマンドを呼ぶ {#commands}

`app.commands.execute("edit.selectAll")` のように、メニューやコマンドパレットのコマンドを ID で実行できます。ID は表示言語によらず固定なので、言語を変えてもスクリプトは動きます。

### イベント {#events}

`app.on("afterSave", handler)` のように、イベントを受け取れます。イベントは、`documentOpened`、`documentClosed`、`activeDocumentChanged`、`beforeSave`、`afterSave`、`selectionChanged` です。`beforeSave` では、保存を中止できます。

イベントを受け取るスクリプトは、止めるまで常駐します。常駐中のスクリプトは、スクリプト一覧に **常駐** と出ます。

## 信頼と許可 {#permissions}

スクリプトは、使い方によっては大切なファイルを壊したり、情報を送り出したりできます。そのため、初めて実行するスクリプトの前に、確認のダイアログが出ます。

確認が出るのは、次の場合です。

- 初めて実行するスクリプト
- 前回の確認から内容が変わったスクリプト

アプリに付属のサンプル、スクリプトエディタで自分で保存したスクリプト、自分で記録したマクロ、コンソールの入力には出ません。外部のエディタで書き換えたスクリプトは、書き換えるたびに確認が出ます。

ダイアログには、名前、作者、そして次のような説明が出ます。

- **JavaScript**: 「このスクリプトは開いているドキュメントを読み書きできます」と、それ以外に求めている許可の一覧。
- **C#**: 「このコードはあなたの PC 上で、あなたと同じ権限で何でも実行できます」という警告。C# のスクリプトは、サンドボックスの中では動きません。
- インターネットから取得したファイルのときは、その旨の警告。

ボタンは次のとおりです。

- **1 回だけ実行する**: 今回だけ実行します。次回も確認が出ます。
- **常に許可する**: 以後、同じ内容のスクリプトは確認なしで実行します。
- **実行しない**。

信頼できる作者のものだけを実行してください。

### JavaScript の許可の種類 {#permission-kinds}

JavaScript のスクリプトは、何も許可しなくても、開いているドキュメントの読み書きができます。次のことをするには、許可が必要です。

| 許可 | できること |
| --- | --- |
| `file-read` | 任意のファイルの読み取り |
| `file-write` | 任意のファイルの作成・書き込み・削除 |
| `network` | ネットワーク通信 |
| `process` | 外部プログラムの実行 |
| `disk` | ディスク、ボリューム、プロセスメモリを開く |
| `clipboard-read` | クリップボードの読み取り |
| `settings` | アプリの設定の変更 |

スクリプトが `@permission` で宣言していない許可の必要な機能を呼ぶと、その場で **許可する** / **許可しない** の確認が出ます。

HexEditor を管理者として実行しているときは、「常に許可する」を選んだスクリプトでも、実行のたびに確認が出ます。管理者の権限は、PC 全体に影響するためです。

組織が設定ファイルでスクリプトを無効にしている場合、スクリプトのメニューは使えません。

### 「常に許可する」を確認して取り消す {#revoke-trust}

「常に許可する」を選んだスクリプトは、**設定 > 自動化** の **信頼と許可** に一覧で出ます。名前、許可の内容、許可した日が分かります。

1. **設定 > 自動化** を開き、**信頼と許可** を探します。
2. 取り消したいスクリプトの **取り消す** を選びます。

取り消したスクリプトは、次に実行するときに、また確認のダイアログが出ます。一覧にスクリプトがないときは、「常に許可しているスクリプトはありません。」と出ます。

組織がスクリプトの方針を決めているときは、その方針が **信頼と許可** に読み取り専用で出ます。この方針は、ここでは変えられません。プラグインの信頼は、この一覧ではなく、プラグインマネージャで管理します ([プラグインの許可と信頼](plugins.md#plugin-permissions))。

## スクリプトコンソール {#console}

スクリプトのファイルを作らずに、1 行ずつ試せるのが **コンソール** です。**ツール > スクリプト > コンソール** (または **表示 > パネルの表示切り替え > コンソール**) で開きます。

1. 上の **言語** で、JavaScript か C# を選びます。
2. 下の入力欄に式や文を入力して、<kbd>Enter</kbd> を押します。複数行にするには <kbd>Shift</kbd>+<kbd>Enter</kbd> で改行します。
3. 結果が履歴に出ます。バイト列は Hex ダンプの形で出ます。

使い方のヒントです。

- `doc` は、そのときアクティブなドキュメントを指します。
- JavaScript では、入力した変数が次の入力にも残ります。**リセット** で新しいセッションにできます。C# では、変数は次の入力へ持ち越せません。
- <kbd>↑</kbd> と <kbd>↓</kbd> で、前の入力をたどれます。履歴は再起動後も残ります。
- コンソールからの書き込みは、入力 1 回が 1 つの [元に戻す](editing.md#undo-redo)の単位です。
- 長くかかる入力は、処理センターから止められます。

## イベントで実行するスクリプト {#event-scripts}

HexEditor の起動時や、ファイルを開いたとき、保存の前後などに、スクリプトを自動で実行できます。

**設定 > 自動化** の **自動実行 (フック)** で登録します。スクリプト一覧のスクリプトを右クリックして **自動実行の設定** を選んでも開けます。ここに追加したスクリプトだけが実行されます。スクリプトが自分で登録することはできません。

| タイミング | 実行される時 | 制限時間の既定 |
| --- | --- | --- |
| 起動時 | 最初のウィンドウが操作できるようになった後 | 60 秒 |
| ファイルを開いたとき | ドキュメントの先頭が表示された後 | 10 秒 |
| 保存の前 | 保存の直前 | 5 秒 |
| 保存の後 | 保存の完了後 | 10 秒 |
| 閉じる前 | ドキュメントを閉じる直前 | 5 秒 |

- 1 つのタイミングに、複数のスクリプトを登録できます。並べた順に実行します。
- **条件** で、**拡張子**、**パスのパターン**、**先頭のバイト列**、**データソース** を指定すると、条件に合うファイルだけで実行します。
- 保存の前のスクリプトは、`script.args.event.cancel(理由)` を呼んで保存を中止できます。
- 制限時間を超えたスクリプトやエラーになったスクリプトは止められ、上に通知が出ます。保存の前のスクリプトが失敗したときは、**保存する** か **保存しない** を選べます。
- 同じタイミングで 3 回続けて失敗したスクリプトは、自動で無効になります。
- セーフモードでは、自動実行はすべて止まります。[プラグイン](plugins.md#safe-mode)を参照してください。

## C# スクリプト コンポーネントの追加 {#csharp-component}

C# のスクリプトは、Roslyn というコンパイラを使います。Roslyn は大きいため、HexEditor には含まれていません。C# のスクリプトを初めて使うときに、追加のコンポーネントとして入れます。

1. **ツール > スクリプト > C# スクリプト コンポーネントを追加** を選びます。`.csx` のスクリプトを初めて実行したときにも、追加をすすめるダイアログが出ます。
2. サイズ (約 20 MB)、保存先、通信先の確認が出ます。確認して、追加します。
3. 追加が終わると、`.csx` のスクリプトが実行できます。

コンポーネントのバージョンは、アプリのバージョンと対になっています。アプリを更新したときは、コンポーネントも合わせて更新します。

オフラインの PC など、ダウンロードできない環境では、手動で入れられます。

1. 別の PC で、リリースのページからコンポーネントの zip をダウンロードします。
2. HexEditor のデータフォルダの `components\csharp\<バージョン>\` に、zip の中身を展開します。

設定でネットワークを使わない状態 (**設定 > プライバシー**) にしているときは、ダウンロードされません。この手動の方法を使ってください。

### コンポーネントを管理する {#csharp-component-manage}

追加したコンポーネントの状態の確認と管理は、**設定 > 自動化** の **C# スクリプト コンポーネント** でします。

- 入っているときは、「インストール済みのバージョン」が出ます。この版の HexEditor と違うバージョンのときは、その旨が出ます。この版用のコンポーネントを追加してください。
- 入っていないときは、「入っていません。C# スクリプトを使うにはこのコンポーネントが必要です。」と出ます。
- **追加...** で、コンポーネントを追加します。**ツール > スクリプト > C# スクリプト コンポーネントを追加** と同じです。
- **削除** で、コンポーネントを削除します。C# のスクリプトは、もう一度追加するまで実行できません。
- **コンパイル結果のキャッシュを削除** で、C# のスクリプトのコンパイル結果を消します。次に実行するときに、もう一度コンパイルします。

## JavaScript のデバッグ {#debugging-javascript}

JavaScript のスクリプトは、スクリプトエディタの中でステップ実行できます。

1. スクリプトエディタで、止めたい行の左の余白をクリックするか、<kbd>F9</kbd> を押して、ブレークポイントを置きます。
2. ツールバーの **デバッグ実行** を選びます。ブレークポイントがなくても、<kbd>F10</kbd> か <kbd>F11</kbd> を押すと、最初の行で止まる状態で始まります。
3. ブレークポイントで止まります。

止まっている間は、**デバッグ** タブに、**呼び出し履歴**、**変数**、**ウォッチ** が出ます。変数は、ローカル、クロージャ、グローバルなどに分かれて出て、オブジェクトは展開できます。**ウォッチ式を追加** で式を足すと、止まるたびに値を調べます。止まっている位置で式を試したいときは、[コンソール](#console)に入力します。

| 操作 | キー |
| --- | --- |
| 続行 | <kbd>F5</kbd> |
| 停止 | <kbd>Shift</kbd>+<kbd>F5</kbd> |
| ブレークポイントの設定 / 解除 | <kbd>F9</kbd> |
| ステップオーバー | <kbd>F10</kbd> |
| ステップイン | <kbd>F11</kbd> |
| ステップアウト | <kbd>Shift</kbd>+<kbd>F11</kbd> |

これらのキーは、スクリプトエディタにフォーカスがあるときに使えます。<kbd>F11</kbd> は、全画面表示ではなくステップインになります。ツールバーやコマンドパレットからも実行できます。

ブレークポイントには、条件 (式が真のときだけ止まる) とヒット回数を付けられます。無効にしたブレークポイントは白抜きの丸で、条件付きのものは中に「=」が付いた丸で表します。

例外で止まる条件は、**設定 > 自動化** の **デバッグ中に例外で止まる** で選びます。止まっている時間は、実行時間の上限に数えません。止まっている間も、スクリプトが書き込み中のドキュメントは編集できません。

ブレークポイントは、スクリプトごとに記憶されます。

## C# スクリプトのデバッグ {#debugging-csharp-scripts}

C# スクリプトは、アプリ内でステップ実行できません。C# スクリプトのエディタでは、<kbd>F9</kbd>、<kbd>F10</kbd>、<kbd>F11</kbd>、<kbd>Shift</kbd>+<kbd>F11</kbd> は何もしません。<kbd>F5</kbd> で実行し、<kbd>Shift</kbd>+<kbd>F5</kbd> で止めます。

C# スクリプトをデバッグするには、外部のデバッガを HexEditor にアタッチします。

1. スクリプトをスクリプトエディタで開きます。
2. ツールバーの **デバッグ実行** を選びます。HexEditor はデバッグ情報付きでスクリプトをコンパイルし、プロセス ID を表示します。
3. Visual Studio または Visual Studio Code (C# 拡張) で、そのプロセス ID のプロセスにアタッチします。
4. `.csx` ファイルにブレークポイントを置きます。決まった場所で止めるには、スクリプトの中で `System.Diagnostics.Debugger.Break()` を呼びます。
5. デバッガがアタッチされると、スクリプトの実行が始まります。デバッガなしで始めるには、**アタッチせずに実行** を選びます。

`Console.WriteLine` と `Ui.Output` の出力は、出力パネルに出ます。例外のスタックトレースには、`.csx` ファイルの行番号が出ます。

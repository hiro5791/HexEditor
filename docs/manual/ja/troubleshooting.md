# トラブルシューティング

このページでは、うまく動かないときの原因の探し方と、直し方を説明します。困ったときは、まずここを見てください。

## データの保存先 {#data-folder}

設定、ログ、復旧用データなど、HexEditor が作るデータは、ひとつのデータフォルダにまとまっています。場所は、配布形態によって違います。

| 配布形態 | データフォルダ |
| --- | --- |
| Microsoft Store 版 | `%LocalAppData%\Packages\<パッケージ名>\LocalState\` |
| インストーラ版 | `%LocalAppData%\HexEditorData\` |
| ポータブル版 | `HexEditor.exe` の隣の `Data` フォルダ |

フォルダは、**ツール > 設定 > 詳細** の **データフォルダを開く**、またはコマンドパレットの **設定: データフォルダを開く** で開けます。**ヘルプ > バージョン情報** にも、フォルダを開くボタンがあります。

中には、次のものがあります。

| 名前 | 内容 |
| --- | --- |
| `settings.json`、`keybindings.json` | 設定とショートカット |
| `recovery\` | 異常終了のための復旧用データ |
| `crash\` | 異常終了したときの情報 |
| `logs\` | ログ |
| `documents\` | ドキュメントごとの表示の設定、ブックマークなど |

ポータブル版を、書き込めない場所 (読み取り専用のメディアなど) で動かすと、設定を保存できません。その場合は、画面上部のバーで知らせます。書き込める場所にコピーして使ってください。

編集の途中のデータは、一時ファイルとして、データフォルダ (ポータブル版では Windows の一時フォルダ) に置かれます。ファイルが大きくなる編集をすると、一時ファイルも大きくなります。空き容量が 1 GB を下回ると、バーで知らせます。一時データのフォルダは、設定の **一時データのフォルダ** で、別のドライブに変えられます。

## 異常終了した後 {#crash-recovery}

HexEditor が異常終了しても、保存していなかった変更は、多くの場合、取り戻せます。変更のあるドキュメントは、1 分ごとに復旧用データとして保存されているからです。

1. HexEditor を、もう一度起動します。
2. **未保存の編集内容の復旧** の画面が出たら、取り戻したいドキュメントを選んで、**復旧する** を選びます。
3. 復旧したドキュメントを確認して、**ファイル > 名前を付けて保存** などで保存します。

**破棄** を選ぶと、復旧用データは消えます。**あとで** を選ぶと、次の起動でもう一度出ます。

- 復旧したドキュメントでは、元に戻す履歴は使えません。
- 元のファイルが、その間に変更されていたときは、読み取り専用で開きます。内容を確かめてください。
- プロセスのメモリは復旧できません。
- 保存が途中で止まっていたときは、**保存前に戻す** が出ます。
- 30 日より古い復旧用データは、自動で消えます。

起動したときに「前回、HexEditor が異常終了しました」というバーが出たときは、**クラッシュ情報を開く** で、`crash\` フォルダのファイルを見られます。ファイルには、版、配布形態、例外の内容、直近のログが入っています。開いていたファイルの内容は入っていません。**問題を報告** を選ぶと、そのまま報告できます ([問題を報告する](#report-a-problem))。

保存先と復旧のしくみは、[バックアップと復旧](opening-files.md#backups-and-recovery) も見てください。

### セーフモード

起動するときに <kbd>Shift</kbd> キーを押したままにすると、セーフモードで起動します。プラグインと自動で動くスクリプトを読み込みません。タイトルに **(セーフモード)** と出ます。これらが原因で起動できなくなったときに、使います。バーの **通常どおり再起動** で、元に戻ります。

## ファイルやディスクを開けない {#cannot-open}

| メッセージや症状 | 原因と対処 |
| --- | --- |
| ファイルが見つかりません | ファイルが移動または削除されています。最近使ったファイルから開いたときは、一覧から削除できます |
| このファイルを開く権限がありません | ファイルの権限を確かめてください。読み取り専用でも開けない場合は、タブを作りません |
| ほかのアプリが使用中のため開けません | 使っているアプリの名前が出ます。そのアプリを閉じてから、もう一度開いてください |
| フォルダは開けません | ファイルを選んでください。フォルダの中のファイルをまとめて探すには、[複数のファイルの検索](search-replace.md#multiple-files) を使います |
| デバイスのパス (`\\.\` で始まるもの) | ファイルとしては開けません。**ファイル > ディスクを開く** を使います |
| ディスクやプロセスを開くとき、管理者権限が必要と出る | [管理者権限](opening-files.md#administrator) を見てください |
| このボリュームは BitLocker でロックされています | ロックを解除してから、開いてください |
| メディアが入っていません | 光学ドライブやカードリーダーに、メディアを入れてください |
| プロセスが開けない | Windows に保護されたプロセスは、管理者権限でも開けません |

ほかにも、次のことを確かめてください。

- Explorer からドラッグ & ドロップで開けないときは、HexEditor を管理者として実行していないか確かめます。管理者として実行している間は、Windows の制限で、ドロップできません。<kbd>Ctrl</kbd>+<kbd>O</kbd> で開いてください。
- 21 個以上のファイルをまとめてドロップすると、開くかどうかを確認します。フォルダは開けません。
- 拡張子が `.hex` や `.s19` のファイルが、テキストではなくデコードされて開くのは、仕様です。テキストのまま見たいときは、**詳細を指定して開く** の **形式** を **バイナリのまま** にします。

## ファイルを保存できない {#cannot-save}

保存に失敗しても、元のファイルは変わっていません。メッセージに理由が出ます。

| 理由 | 対処 |
| --- | --- |
| 保存先の空き容量が足りない | 空き容量を作るか、**別の場所に保存** を選びます。**その場でずらしながら保存** は、途中で止まると、ファイルが壊れる危険があります |
| 書き込む権限がない | **名前を付けて保存** で、書ける場所に保存します |
| 他のアプリが使用中のため、保存できない | 「他のアプリ (名前) が使用中のため、ファイル名 を保存できません。」と出ます。使っているアプリを閉じてから、**再試行** を選びます |
| このドライブのファイルシステムの上限を超える | FAT32 では、4 GB を超えるファイルを書けません。別のドライブに保存します |
| 書き込み中のエラー | 理由が出ます。USB メモリの接続やネットワークを確かめてください |
| 読み込めない範囲を含む | 不良セクタなどを含むデータは、保存できません。範囲の一覧が出ます |
| 読み取り専用のドキュメント | **保存** は使えません。**編集を許可する** か、**名前を付けて保存** を使います |
| 別のタブで開いているファイルへの保存 | 先にそのタブを閉じます |

- 保存が終わるまで、そのドキュメントは編集できません。進み具合は、ステータスバーと処理センターに出ます。
- 外部で変更されたファイルへ保存しようとすると、上書きの確認が出ます ([ファイルが外部で変更されたとき](opening-files.md#external-changes))。
- ディスクへの書き込みで、ボリュームをロックできないときは、ディスマウントするかどうかを聞かれます。システムのボリュームには、書き込めません。

## 動作が遅い {#slow}

HexEditor は、巨大なファイルでも速く動くように作られています。遅いと感じたら、次のことを確かめてください。

- **進行中の処理**: 検索、保存、ハッシュの計算は、バックグラウンドで動きます。ステータスバーの処理の表示を選ぶと、処理センターが開き、進み具合と残り時間を見られ、キャンセルもできます。
- **ネットワークやリムーバブルのドライブ**: ネットワーク上のファイルや、USB メモリは、読み込みの速度が遅いです。ファイルを開くとき、先頭だけを読みますが、検索や保存は、ドライブの速度に左右されます。
- **クラウドだけにあるファイル**: OneDrive などにあるファイルは、読むときに Windows がダウンロードします。
- **一致が多すぎる検索**: すべて検索は、結果が多いと時間がかかります。範囲を絞るか、条件を厳しくします。
- **正規表現**: 後方参照や先読みを使った正規表現は、時間がかかることがあります。
- **ミニマップの正確な計算**: **正確に計算** がオンだと、巨大なファイルで時間がかかります。オフにします。
- **変更が非常に多い**: 編集の数が多いと、メモリを使います。保存すると、使うメモリが減ります。
- **ハードディスクでの複数ファイル検索**: 同時に調べるファイルの数を減らすと、速くなることがあります。

HexEditor は、ファイルの大きさに比例したメモリを使いません。ファイルを開くときに、全体を読み込むことはありません。

## ログファイル {#logs}

ログは、データフォルダの `logs\` に保存されます。ログは、このパソコンの中にだけ残り、外には送られません。ファイルの内容は書かれません。

- 既定は **通常** の詳しさです。原因を調べるときは、**ツール > 設定** の **ログの詳しさ** を **デバッグ** にします。デバッグでは、ファイルのパスも書かれるので、報告に貼るときは注意してください。
- 管理者権限の補助のプログラムが実行した操作 (ディスクを開くなど) も、種類と対象と結果だけが記録されます。読み書きしたデータの内容は記録されません。
- 異常終了したときの情報は、`crash\` に残ります。最新の 10 件が残ります。

## 問題を報告する {#report-a-problem}

不具合を見つけたときは、GitHub に報告してもらえると助かります。

1. **ヘルプ > 問題を報告** を選びます。
2. 既定のブラウザで、GitHub の報告の画面が開きます。版、配布形態、OS の情報が、本文に入っています。
3. 何をしたら、何が起きたかを書いて、送ります。

開いていたファイルの名前や内容は、本文に入りません。報告には、次のことを書くと、原因を探しやすくなります。

- 何をしたか (手順)
- 期待した結果と、実際の結果
- ファイルの種類と大きさ (ファイルの内容は書かないでください)
- 異常終了のときは、`crash\` のファイルの内容

**ヘルプ > バージョン情報** の **情報をコピー** で、版などの情報をコピーできます。報告に貼ってください。オフラインモードのときは、ブラウザを開く前にアドレスが表示されます。

## 翻訳の誤りを報告する {#report-a-translation}

画面の文章が不自然なときや、間違っているときは、報告できます。

1. **ヘルプ > 翻訳の誤りを報告** を選びます。
2. 報告したい文字列を、一覧から選びます。表示している文章、英語の原文、リソースのキーのどれでも検索できます。
3. **報告** を選びます。ブラウザで、翻訳の報告の画面が開きます。表示言語、文字列のキー、今の訳が入力済みです。
4. 正しいと思う訳を書いて、送ります。

一覧から選ばずに報告するときは、**選ばずに報告** を選びます。英語表示のときも、同じ画面で、原文の誤りを報告できます。

文字列のキーを知りたいときは、設定の **ツールチップにリソースキーを表示する** をオンにします。画面の文字にマウスを合わせると、キーが出ます。

訳を自分で直したい人は、リソースのファイル (`.resw`) を直す Pull Request でも送れます。手順は、報告の画面の説明にあります。

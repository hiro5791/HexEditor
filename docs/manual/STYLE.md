# マニュアルの書き方 (STYLE.md)

利用者向けマニュアル (`docs/manual`) の原稿を書く人のための決まり。仕様は [../spec/09-ui-and-settings.md](../spec/09-ui-and-settings.md) の UI-59。

このファイルはマニュアルのページではない (HTML にしない)。

## 1. ファイルの構成

```text
docs/manual/
  manual.json        言語の一覧、ページの順序、画面の部品 (サイドバーなど) の文言
  STYLE.md           この文書
  en/<ページ>.md      英語 (原文。すべてのページを書く)
  ja/<ページ>.md      日本語
  <言語>/images/      画面の写真などの画像
```

- ページの ID はファイル名 (`.md` を除いたもの)。小文字の英字・数字・`-` だけを使う。どの言語でも同じファイル名にする。
- ページは言語のフォルダの直下に置く (サブフォルダは使わない)。
- ページを足すときは、英語と日本語の両方を書き、`manual.json` の `pages` の適切な位置に ID を足す。`index.md` (目次のページ) にもリンクを足す。
- ほかの言語は、翻訳を始めるときにフォルダを作り、`manual.json` の `languages` に足す。その言語にないページは英語のページを出す (「まだ翻訳されていない」旨が付く)。

## 2. 作り方と確かめ方

```powershell
dotnet run --project tools/ManualBuilder -c Release -- build    # artifacts/manual に HTML を作る
dotnet run --project tools/ManualBuilder -c Release -- check    # 検査だけ
```

- 壊れたリンク・見出し・画像、使えない HTML があると、ファイルと行を示して失敗する。アプリのビルドと CI も失敗する。
- `artifacts/manual/<言語>/index.html` をブラウザで開いて見た目を確かめる。ライト / ダーク、Windows のコントラスト テーマでも確かめる。

## 3. ページの形

- 1 行目は見出し 1 (`# ページの題`)。見出し 1 はページに 1 つだけ。
- 見出しは段を飛ばさない (`##` の次に `####` を使わない)。
- 見出し 2 には、言語によらない ID を付ける: `## 元に戻すとやり直し {#undo-redo}`。英語と日本語で同じ ID にする。見出し 3 も、ほかのページからリンクするなら ID を付ける。
- ID は小文字の英字・数字・`-` で、英語の見出しから作る (例: `Undo and redo` → `undo-redo`)。いったん公開した ID は変えない (アプリやほかのページがリンクしているため)。
- アプリから開く見出し (Core の `src/HexEditor.Core/Help/ManualLinks.cs` の `ManualTopic`) の ID を変えると、テスト (TC-UI-59-07) が失敗する。変えるときはコードも直す。
- ページの最初に、そのページで分かることを 1〜2 文で書く。
- 手順は番号付きの一覧 (`1.`) で書く。1 つの手順に 1 つの操作。
- 書きかけの節は `> TODO` の引用で示す。

## 4. 文章

### 4.1 共通

- 利用者が何をしたいかから書く (機能の名前からではなく)。
- 1 文に 1 つのことを書く。短い文にする。
- 仕様書の ID (UI-40 など)、テストケースの ID、内部の名前 (クラス名、設定のキー以外のコードの名前) は書かない。
- 設定のキー (`network.offline` など) は、設定ファイルを直接編集する説明でだけ書く。ふつうは設定画面の項目名で書く。
- 将来の予定は書かない。今の版でできることだけを書く。

### 4.2 英語

- Plain English. Use the second person ("you") and the present tense.
- Use sentence case for headings ("Open a file", not "Open A File").
- Use "select" for menu items and buttons, "press" for keys, "type" for text.

### 4.3 日本語

- です・ます調。短い文にする。
- 用語は [../i18n/glossary.csv](../i18n/glossary.csv) の `ja` の列に合わせる (例: ドキュメント、オフセット、カーソル、選択範囲、Hex 列、テキスト列、上書きモード、挿入モード、ブックマーク、テンプレート、インスペクタ、パネル、タブ、コマンドパレット)。
- 画面の文言は、アプリの日本語の表示 (`src/HexEditor.App/Strings/ja/Resources.resw`) と同じにする。
- 英数字と日本語の間には半角の空白を入れる (アプリの文言と同じ)。括弧は半角の `()` を使い、前に半角の空白を入れる。
- 「〜することができます」ではなく「〜できます」。「〜して下さい」ではなく「〜してください」。

## 5. 画面の要素・メニュー・キーの書き方

| 対象 | 書き方 | 例 (英語) | 例 (日本語) |
| --- | --- | --- | --- |
| メニュー | 太字。`>` で区切る。アクセスキー `(O)` と `...` は書かない | **File > Open** | **ファイル > 開く** |
| ボタン・項目・パネルの名前 | 太字 | **Run without attaching** | **アタッチせずに実行** |
| キー | `<kbd>` で 1 キーずつ囲み、`+` でつなぐ | <kbd>Ctrl</kbd>+<kbd>G</kbd> | <kbd>Ctrl</kbd>+<kbd>G</kbd> |
| コマンドパレットのコマンド | 太字で、パレットの表示名 | **Help: Documentation** | **ヘルプ: ドキュメント** |
| 入力する値・ファイル名・コード | コード (`` ` ``) | `0x1F00` | `0x1F00` |

- キーの名前は英語の表記にそろえる: <kbd>Ctrl</kbd>、<kbd>Shift</kbd>、<kbd>Alt</kbd>、<kbd>Enter</kbd>、<kbd>Tab</kbd>、<kbd>Insert</kbd>、<kbd>Page Up</kbd>、<kbd>F5</kbd>。
- ショートカットは既定のキー配置のものを書く。メニューやコマンドパレットからの操作も合わせて書く (キーを変えた利用者のため)。
- 使える HTML は `<kbd>` だけ。ほかの HTML は検査で失敗する。

## 6. リンク

- マニュアルのほかのページへは、同じ言語のフォルダの中の相対パスで書く: `[編集](editing.md)`、`[元に戻す](editing.md#undo-redo)`。HTML にするときに `.html` に直る。
- 見出しへのリンクは、`{#id}` で付けた ID を使う (自動で付く ID は言語ごとに違うため)。
- 仕様書・テストケースなど、マニュアルの外の文書にはリンクしない (利用者向けではなく、同梱の HTML から開けないため)。どうしても必要なら `https://` の完全な URL にする (例: GitHub のリリースのページ)。`http://` は使わない。
- リンクの文字列は、リンク先のページや見出しの題にする (「ここ」にしない)。

## 7. 画像

当面は文字だけで書く。画面の写真を足すときは次のようにする。

- `docs/manual/<言語>/images/<ページ>-<内容>.png` に置く (例: `en/images/hex-view-columns.png`)。その言語の画像がなければ英語の画像を使う。
- ページからは `![代替テキスト](images/hex-view-columns.png)` で参照する。代替テキストは必須 (画像の内容を 1 文で)。
- 画像は 100% の表示倍率、ライトテーマ、1024 × 768 に収まる大きさのウィンドウで撮る。PNG にする。個人の情報 (ファイルのパス、利用者名) を写さない。
- 画像だけで説明しない。画像がなくても分かる文章を書く。

## 8. 機能を変えるとき

機能を作る・変える Pull Request では、マニュアルの英語と日本語のページも直す (CLAUDE.md の「作業時の注意」)。

- 画面の文言・メニュー・既定のキーを変えたら、マニュアルの書き方もそろえる。
- 新しい機能は、該当するページの節に足す。合うページがなければページを足す (1 章)。
